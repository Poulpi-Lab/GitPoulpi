# AI アシスタント

GitPoulpi はアカウントを一切必要とせず、**AI は既定でオフ**です。AI をオンにすると、commit メッセージや stash メッセージの作成、変更内容の説明、pull request の説明文の作成、merge 競合の解決案の提案、作業中の変更の複数 commit への分割ができます。モデルは自分で用意したものを使います。自分で持っている API キー、ローカルサーバー、またはすでにインストール済みのエージェント CLI（`claude -p` など）です。

AI のコントロールにはすべて紫色の `✦` が付きます。AI がオフの間は次のとおりです。

- どこにも何も送信されません。
- AI のコントロールは一切表示されません。`✦` ボタン、`AI:` のパレットコマンド、AI のメニュー項目、AI のキーヒントはありません。AI のキーは何も実行しません。
- リポジトリの AI ページには「AI はオフです（設定 > AI）」とだけ表示されます。
- MCP サーバーは `ai_*` ツールを一覧に出しません。`gitpoulpi ai ...` の CLI コマンドは同じメッセージで拒否されます。

**AI を有効化**はすぐに反映されます。再起動は不要です。

GitPoulpi で AI を使う方法は 2 つあります。

| | 組み込み AI（このページ） | 外部エージェント |
|---|---|---|
| 内容 | GitPoulpi がモデルに、commit メッセージや説明などを作ってもらう | Claude Code、Cursor、Codex... が GitPoulpi をツールとして操作する |
| 設定場所 | 設定 > AI（`[ai]`） | エージェントの MCP 設定、制限は `[mcp]` |
| ガイド | 以下 | [MCP とエージェント](mcp-and-agents.md) |

## AI を設定する

1. `Ctrl+,` > **AI** > **AI を有効化**にチェックを入れます。
2. プロファイルは**プロファイル（接続）**タブのリストで、ページ左側にあります（狭いターミナルでは上に積み重ねて表示されます）。1 つ選ぶと、右側でそのプロファイルを編集できます（`Enter` でその行へ移動します。パレットの **AI: プロファイルを編集...** でリストへ移動できます）。*Default* という名前のプロファイルは常に存在します。**+ 追加**で別のプロファイルを作り、**複製**で選択中のプロファイルをキーなしでコピーし、**削除**は先に確認します。**プロバイダー**を選び、そのフィールドを入力します。

   | プロバイダー | フィールド | 既定値 |
   |---|---|---|
   | **ローカルエージェント**（キー不要、独自のアカウントも不要） | **エージェントの種類**（どのエージェントか）、**コマンド**（実行するプログラムそのもの。`PATH` 上のもの、エイリアスやラッパースクリプト、またはフルパス）、非対話にするための**引数**、任意の**環境変数**。プロンプトは標準入力に渡され、回答は標準出力から読み取られます。 | Claude Code：`claude`、`-p --model haiku` |
   | **Anthropic** | **API キー**、任意の**モデル**と**ベース URL** | `claude-sonnet-5`、`https://api.anthropic.com/v1` |
   | **OpenAI** | **API キー**、モデル、ベース URL | `gpt-5`、`https://api.openai.com/v1` |
   | **OpenRouter** | **API キー**、モデル、ベース URL | `openai/gpt-5`、`https://openrouter.ai/api/v1` |
   | **OpenAI 互換**（Ollama、LM Studio、vLLM、社内ゲートウェイ） | **ベース URL**（`.../v1`）、**モデル**、任意のキー | `http://localhost:11434/v1`（Ollama。LM Studio は `http://localhost:1234/v1`）、`llama3` |

   **プリセット**（別の値をいつでも入力できます）：

   ![ローカルエージェントのプロファイルにあるエージェントの種類ドロップダウン。Claude Code、OpenAI Codex CLI、Gemini CLI、opencode など各種エージェント CLI が並ぶ](../images/settings-ai-presets.png)

   - **ローカルエージェント > エージェントの種類**は、よく使われるエージェント CLI のドロップダウンです。利用の多いものが先頭にあります。Claude Code、OpenAI Codex CLI、Gemini CLI、opencode、Cursor Agent、GitHub Copilot CLI、Pi、Qwen Code、Aider、Goose、Crush、Amp、そして*その他（候補なし）*です。種類は**コマンドとは別のもの**で、表示される候補を決めるだけです。種類を選ぶと、**コマンド**（前の種類の既定値のままの場合）と**引数**に、ヘッドレス実行用の呼び出し（`claude -p`、`codex exec -`、`gemini -p ...` など）が入力されます。**コマンド**は自由なテキストです。`/opt/bin/work-claude`、ラッパースクリプト、エイリアスの実体を書いても、種類とそのオプション、モデル一覧、変数はそのまま残ります。**エージェントの種類**が空のときは、GitPoulpi がコマンドから推測します。
   - **引数オプション**は、GitPoulpi の単発利用に合ったオプションを追加または削除します。それぞれ 1 行の理由が付いています。ツールなし、会話を保存しない、プレーンテキストで回答、推論を少なく、読み取り専用、許可を求めて止まらない、更新確認なし・利用統計なし、などです。エージェントごとに違いがあるため、一覧もエージェントごとに異なります（コマンドラインでツールを無効にできるのは一部だけで、opencode では環境変数を使います）。**モデル**はそのエージェントのモデルを一覧にし、正しいフラグを書き込みます（Claude Code は `--model haiku`、Codex は `-m gpt-6-luna`、opencode は `--model provider/model`）。*（既定 - フラグなし）*でフラグを削除します。Amp にはモデルフラグがありません。`aider` はプロンプトを `/dev/stdin` から読むため、Linux と macOS でのみ動作します。
   - **環境変数**は、そのエージェントのプロセスにだけ設定され、GitPoulpi や他のプロファイルには設定されません。**環境変数を追加**では、そのエージェントにとって重要な、文書化済みの変数が、それぞれの役割（利用統計や更新確認の無効化、努力レベル、設定ディレクトリ、API キー、ベース URL やローカルホストなど）とともに候補に出ます。`NAME` や `NAME=値` を直接入力することもできます。追加した変数には、それぞれ専用の **Env NAME** 行ができます。値がボタンとして表示され（押すと新しい値を入力でき、フィールドを離れると保存されます）、**[x]** ボタンでその変数を削除できます。値には `${env:NAME}` を指定して、GitPoulpi 自身の環境変数を借りられます（API キーに便利で、`config.toml` に書き込まれずに済みます）。秘密に見える値（`_KEY`、`_TOKEN`、`_SECRET` などで終わる名前、または既知のキーのプレフィックス）は黒丸で表示され、最初から入力し直す必要があります。値がログに記録されることはありません。
   - **HTTP プロバイダー > プロバイダーのプリセット**は、ベース URL とモデルを入力します。対象は OpenAI、Anthropic、OpenRouter、Google Gemini、xAI、DeepSeek、Mistral、Groq、Together、Fireworks、Cerebras、Perplexity、Moonshot、Qwen（DashScope）、Zhipu（GLM）と、ローカルサーバーの Ollama、LM Studio、llama.cpp、vLLM、Jan、LocalAI です。**モデル**はそのプロバイダーのモデルのドロップダウンで、自由入力もできます。

3. **接続テスト**を押します。*前回のテスト*に `接続できました：モデルが応答しました` または `失敗：<理由>` と表示されます。
4. プロファイルが複数あるときは、下部で**既定のプロファイル**を選びます。各操作に個別のプロファイルを指定することもできます。

![ローカルエージェント用の AI ページのプロファイルブロック：エージェントの種類（Claude Code）、コマンド、引数、モデル、2 つの Env 行、環境変数の追加と削除、接続テスト、既定のプロファイル](../images/settings-ai-agent.png)

**API キー**は、**API キー**行で `Enter` を押して入力し、システムの認証情報ヘルパー（Git Credential Manager、libsecret / `pass`、Keychain）に `ai:<プロファイル ID>` という名前で保存されます。`config.toml` には保存されません。ヘルパーがない場合、GitPoulpi は保存したふりをせず、その旨を表示します。*設定 > SSH と認証情報 > すべてのユーザー名とパスワードを削除*でキーも削除されます。

`config.toml` での同じ設定（それ以外はすべて[設定リファレンス](config-reference.md#ai組み込み-ai既定ではオフ)にあります）：

```toml
[ai]
enabled = true
default_profile = "claude-code"

[[ai.profiles]]
id = "claude-code"
name = "Claude Code"
kind = "local_agent"      # open_ai | anthropic | open_router | open_ai_compatible | local_agent
command = "claude"        # free: an alias, a wrapper script, an absolute path
harness = "claude"        # which agent it is; empty = inferred from `command`
args = ["-p", "--model", "haiku"]

[ai.profiles.env]         # this agent's process only; ${env:NAME} borrows ours
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC = "1"
ANTHROPIC_API_KEY = "${env:ANTHROPIC_API_KEY}"
```

## 実行モード：ヘッドレスか仮想ターミナルか

ローカルエージェントのプロファイルは、**実行モード**で選んだ 2 通りのどちらかでエージェントを実行します
（Claude Code、OpenAI Codex CLI、Gemini CLI で表示されます）。

- **ヘッドレス（非対話）**（既定）：エージェントの単発モード（`claude -p`）で、プロンプトは stdin、答えは stdout です。
- **対話型（仮想ターミナル）**：GitPoulpi がエージェント自身の画面を非表示のターミナルで起動し、
  人間のようにリクエストを入力して、答えを待ち、エージェントを閉じます。エージェントによっては、
  ヘッドレスモードと対話モードで課金や制限が異なります。どちらが当てはまるか、また各モードについて
  プロバイダーの条件がどうなっているかはプロバイダー次第なので、プロバイダーの条件を確認してください。

各モードはそれぞれ**引数**、**引数オプション**、**モデル**を持ちます。モードを切り替えても何も失われず、
対話モードでは、ヘッドレス用フラグなしで意味のあるオプションだけが表示されます。さらに 2 つの行が両方のモードに共通です。

- **作業フォルダー**：*専用フォルダー*は GitPoulpi が所有する空のフォルダーで、エージェントからは
  プロジェクトが見えず、信頼の確認は 1 回だけです。*現在のリポジトリ*はエージェントにプロジェクト自身の
  コンテキスト（たとえば `CLAUDE.md`）を渡し、信頼の確認はリポジトリごとに 1 回です。*既定*は、対話型では
  専用フォルダー、ヘッドレスでは従来どおり GitPoulpi が動いているフォルダーです。
- **タイムアウト（秒）**：GitPoulpi が諦めてエージェントを停止するまでに、エージェントにかけてよい時間です。
  空の場合、ヘッドレスは 120 秒、対話型は 180 秒です。

**初回起動時の質問には、あなたが答えます。** フォルダーで一度も実行されたことのないエージェントは、
最初に何かを尋ねます（このフォルダーを信頼するか、サインイン、テーマの選択）。GitPoulpi が代わりに答えることは
ありません。リクエストはメッセージとともに止まり、**エージェントを開く...**（プロファイル上、またはコマンドパレットの
*AI: エージェントを開く...*）で、エージェントが使う作業フォルダーの見えるターミナルでエージェントを 1 回開きます。
質問に答えてエージェントを閉じ、もう一度試してください。答えはエージェントが覚えています。

答えは、Claude Code ではエージェントのセッショントランスクリプト（正確なテキストで、後で削除されます）から、
Codex と Gemini ではリクエストが求める 2 本のマーカー行の間の画面から読み取ります。仮想ターミナルの
実行は同時に最大 2 つで、リクエスト中に Esc を押すとエージェントを停止します。

```toml
[[ai.profiles]]
id = "claude-terminal"
kind = "local_agent"
command = "claude"
harness = "claude"
args = ["-p"]                       # the headless set, kept
run_mode = "terminal"               # headless (default) | terminal
terminal_args = ["--effort", "low"] # the interactive set
workdir = "dedicated"               # default | dedicated | repository
timeout_secs = 180                  # 0 or absent: 120 headless, 180 terminal
```

## 指示

モデルに伝える内容に追加するテキストです。各操作の組み込みプロンプト（回答の形式を固定するもの）は常に最初に置かれ、編集できません。その後に、一般的なものから具体的なものへ 4 つのレベルが、空でないものだけ次の順で続きます。

1. **全体の指示**（すべての操作）。エディターの*クイック挿入*のチップで定型文を挿入できます：*`<言語>`で応答*、*簡潔に応答*、*命令形を使う*、*技術的な口調*、*カジュアルな口調*。
2. **ワークスペースの指示**（すべての操作、[ワークスペース](workspaces.md#ワークスペースの-ai-の指示)のすべてのリポジトリ）：すべての操作向けと、必要なら操作ごと。ワークスペースの編集フォームで編集します。
3. **リポジトリの指示**（すべての操作、このリポジトリのみ）と、*全体と組み合わせる*：**全体に追加**（全体の指示の後に付ける）または**全体を置き換え**（全体の指示の代わりにする）。
4. **操作ごとの指示**（*commit メッセージの生成*、*変更の説明*、*stash メッセージの生成*、*pull request*、*commit コンポーザー*、*競合の解決*、*コードレビュー*、*commit の分割*）。各ブロックのエディターに専用のチップ（例：*Conventional Commits 形式*、*50 文字まで*）と専用の**プロファイル**ドロップダウンがあります（`既定（<名前>）`は既定のプロファイルに従います）。

*カスタム指示*の行で `Enter` を押すと複数行エディターが開きます（`Ctrl+S` で保存、`Esc` でキャンセル）。テキストの上にある*クイック挿入*の行には、そのセクションのチップが並びます。チップをクリックすると、その文がキャレット位置に挿入されます。キーボードでは、`Tab` でその行に移動し、`Left`/`Right` でチップを選び、`Enter` または `Space` で挿入してテキストに戻ります（`Tab` または `Esc` なら挿入せずに戻ります）。その文がすでに指示に入っているチップは暗く表示され、もう一度挿入しても何も起こりません。テキスト部分はフル機能のエディターです。クリックでキャレットを置き、ドラッグまたは `Shift`+矢印キーで範囲を選択し、`Ctrl+A` で全選択、`Ctrl+C` / `Ctrl+X` で選択範囲をコピー/切り取り、`Ctrl`+矢印キーで単語単位に移動し、`Home` / `End`、`PageUp` / `PageDown`、マウスホイールで長いテキストを移動できます。ページ自体には、各指示のプレビューだけが表示されます。

![AI ページ：全体の指示、続いてプロファイルのドロップダウンとカスタム指示を備えた commit メッセージの生成と変更の説明のブロック](../images/settings-ai.png)

**リポジトリごと**：*設定 > リポジトリ別の設定 > AI*（リポジトリを開いている間）には、リポジトリの指示と、操作ごとに全体の設定を上書きするプロファイルと指示があります。空のフィールドは全体の設定を使います（そこではグレーで表示されます）。**全体にリセット**で上書きを削除します。リポジトリの `.gitpoulpi/repo-state.toml` に保存され、CLI にも反映されます。

![リポジトリの AI ページ：全体と組み合わせるドロップダウン付きのリポジトリの指示、続いて操作ごとのプロファイルと指示](../images/settings-repo-ai.png)

### レベルの組み合わせ方

送信される順序は、組み込みプロンプト、**全体**、**ワークスペース**、**リポジトリ**、そして操作ごとの指示です。レベルのモードによって、それより上のレベルがどうなるかが決まります。

- **追加**（既定）：そのレベルのテキストが、より一般的なレベルの後ろに追加されます。
- **置き換え**：そのレベルのテキストが、より一般的なすべてのレベル（全体、そしてリポジトリが置き換える場合はワークスペース）の*代わりに*使われます。テキストのないレベルは何も置き換えません。

操作ごとの指示も同じ考え方です。その操作の全体の指示、続いてその操作のワークスペースの指示（その後ろに追加、または置き換え）があり、リポジトリのその操作に対する上書きは、どちらよりも優先されます。使われるワークスペースは、ウィンドウのアクティブなワークスペースがそのリポジトリを含んでいればそれ、なければそのリポジトリを含む最初のワークスペースです。コマンドラインでは `GITPOULPI_WORKSPACE` のもの、なければ最初のものです。

送信される内容をレベルごとに正確に見るには、`gitpoulpi ai prompt --action <action> --repo .` を実行します（`base`、`global`、`workspace`、`repository`、`task`、そして最終的な `system_prompt`）。モデルは呼び出さず、AI がオフでも動作します。ワークスペースの指示をスクリプトから設定するには、`gitpoulpi workspace set-ai-instructions <id> [--action <a>] [--mode append|replace] --text ...`（または `--clear`）を使います。

### プロンプト変数

すべての指示テキスト（全体、ワークスペース、リポジトリ、操作ごと）には `${name}` 形式の変数を含められます。変数はプロンプトの送信直前に値へ置き換えられます（保存されるテキストは `${...}` のままです）。表にない名前は書かれたまま送信され、エディターが警告します。リテラルの `${` を書くには `$${` と書きます。

| 変数 | 展開される内容 | 例 |
|---|---|---|
| `${uilang}` | UI の言語（英語名） | `French` |
| `${repo}` | リポジトリのフォルダー名 | `gitpoulpi` |
| `${branch}` | 現在のブランチ | `main` |
| `${ref}` / `${commit}` | 操作の対象の commit（*説明*）の短い sha。なければ HEAD | `4c0443d` |
| `${commit_subject}` | その commit の件名 | `feat: add search` |
| `${date}` | ローカルの日付（ISO 形式） | `2026-10-03` |
| `${time}` | ローカルの時刻（`HH:MM`） | `14:05` |
| `${datetime}` | ローカルの日付と時刻 | `2026-10-03 14:05` |
| `${user}` / `${email}` | `git config user.name` / `user.email` | `Ada Lovelace` |
| `${remote}` | 既定のリモート（`origin`、なければ最初のもの） | `origin` |
| `${host}` | `github`、`gitlab`、`other`（別のホスト）、`none` | `github` |
| `${files}` | 操作の diff に含まれるファイル数 | `3` |
| `${action}` | 実行中の操作 | `commit_message` |

指示エディターでは、`${` と入力すると一致する変数をポップアップが一覧表示します（`Up`/`Down` で選択、`Enter` または `Tab` で挿入、`Esc` で閉じる）。または左下の**変数**ドロップダウン（`Ctrl+T`、またはコマンドパレットの *AI: プロンプト変数を挿入*）を使うと、カーソル位置に挿入されます。各項目には説明があり、ホバーまたはハイライトしている間、ドロップダウンとボタンの上の行に表示されます。

## できること

| 操作 | ウィンドウでの方法 | CLI |
|---|---|---|
| **commit メッセージ** | 変更をステージし、概要フィールド右の `✦` を押す、`Ctrl+G i`、またはパレットの `AI: Commitメッセージを生成`。概要と説明が入力され、編集できます。commit はされません。 | `ai commit-message`（出力のみ）、`commit --ai`（commit まで実行） |
| **変更の説明** | 作業中の変更ペイン右上の `✦`（`Ctrl+G w`：選択中の commit、なければ作業中の変更）、または commit のメニューの*変更を説明（AI）*。ポップアップ：矢印でスクロール、`c` でコピー、`Esc` で閉じる。 | `ai explain [rev] [--wip]` |
| **stash メッセージ** | `Ctrl+G m` で stash のダイアログを開き、その **AI メッセージ**ボタン（ダイアログ内の `Ctrl+G`）でモデルに依頼します。パレットの `AI: Stashメッセージを生成` は両方を行います。 | `stash push --ai` |
| **pull request のタイトルと説明** | pull request 作成フォームの*タイトルと説明を生成*（ブランチの commit と diff はローカルで読み取られます）。 | |
| **merge 競合の解決** | merge 競合エディターで、ツールバーの `✦ 提案` ボタン、競合の右クリックメニュー*✦ 解決案を提案（AI）*、`Alt+I`、またはパレットの `AI: merge競合の解決案を提案`。提案は出力の*現在の競合*の範囲を 1 回の編集として置き換えます（編集済みとして印が付き、元に戻す操作は 1 ステップ）。保存するまで、何も保存もステージもされません。 | `ai resolve-conflict <path> [--conflict N]`（出力のみ） |
| **コードレビュー** | [pull request / merge request のレビュー](review.md#-ai-によるレビューのドラフト)で、`✦ ドラフトを作成...` ボタン、`s`、またはパレットの `レビュー: ✦ レビューのドラフトを作成...`（レビューオプションが開き、`Enter` で実行）。モデルはリクエストの差分、説明、既存のコメント（既定ではプロジェクトの `CLAUDE.md` と `AGENTS.md` も。[レビューのコンテキスト](#レビューのコンテキスト)を参照）を読み、コメントを提案します。それぞれを採用、編集、却下できます。レビューを送信するまで、ホストには何も届きません。 | `hosting review suggest <n>`（JSON を出力し、何も投稿しません）、`ai review-context`（既定値） |
| **commit の分割** | commit のメニューの*commit を分割（AI）...*、またはパレットの `AI: 選択中のCommitを分割...`。モデルによるグループ分けが入力済みの分割エディターが開きます。下を参照。 | `ai split-plan <rev>`（出力のみ） |
| **履歴書き換えスクリプト** | [履歴書き換えワークベンチ](history-rewrite.md#ai-でスクリプトを作成する)で、スクリプトエディターの `✦ AI で作成...` ボタン、またはパレットの `書き換え: AI でスクリプトを作成...`。ダイアログに送信される内容がそのまま表示されます。スクリプトは印付きでエディターに入り、自動で実行も適用もされません。 | `ai rewrite-script "<instruction>" [--sample N]`（出力のみ） |
| **履歴書き換えルール** | [履歴書き換えワークベンチ](history-rewrite.md#ai-でルールを作成する)で、`✦ AI でルールを作成...` ボタン、`Alt+I`、またはパレットの `書き換え: AI でルールを作成...`。複数行のダイアログに送信される内容がそのまま表示されます。ルールと設定はワークベンチに入り、自動でプレビューも適用もされません。 | `ai rewrite-rules "<description>" [--context]`（出力のみ） |
| **commit コンポーザー** | WIP 行のメニューの*commit を構成（AI）...*、`Ctrl+G C`、パレットの `AI: 作業中の変更からCommitを構成...` | |

`Esc` で実行中のリクエストをキャンセルできます（ローカルエージェントのプロセスは終了されます）。

### merge 競合の解決

モデルに渡されるのは、ファイルのパスと言語、エディターに表示されるラベル付きの競合のベース、現在（A）、受け入れ側（B）の各ブロック、その前後それぞれ最大 20 行の merge 済みテキスト、そして自分で書いた指示（全体、リポジトリ、設定 > AI の*競合の解決*のもの）です。モデルは、その 1 つの競合の解決後のテキストをコードブロックで返します。コードではなく競合マーカーや雑談を含む回答は 1 回だけ差し戻され、それでも駄目なら拒否されます。40 KB（`ai.limits.conflict_bytes`、*設定 > AI > 上限*）を超える競合は、サイズと上限を示す警告の裏に保留され、*そのまま送信*（このリクエストのみ。プライバシーのチェックは引き続き適用）、*設定を開く*、*キャンセル*を選べます。この上限は GitPoulpi 独自の安全策なので、モデルに余裕があるときは引き上げてください。AI がオフの間はコントロールが非表示で、提案が何かを保存、ステージ、解決することはありません。出力を確認し、編集して、いつもどおり保存してください。

### commit コンポーザー

モデルは作業中の変更を複数の commit に分割します（変更されたすべてのファイルがちょうど 1 つの commit に入ります。無効なプランは 1 回だけ差し戻され、それでも駄目なら拒否されます）。ファイルにまだ競合がある間は何も依頼されません。コンポーザーは競合のないツリーを必要とするため、ダイアログが競合のあるファイルを一覧し、競合解決ビューを開きます。何かが commit される前に、プランを確認します。

![コンポーザーのレビュー：ファイル付きの 4 つの提案 commit と、リセット、キャンセル、commit 4 件を作成のボタン](../images/composer.png)

| キー | マウス | 動作 |
|---|---|---|
| `Up` / `Down`（`k` / `j`） | 行をクリック | commit とファイルの間を移動 |
| `Alt+Up` / `Alt+Down`（`K` / `J`）、`m` | 矢印、ドラッグ＆ドロップ | commit を移動。ファイルを別の commit へ移動 |
| `Right` / `Left`、`*` | 行の矢印 | commit の展開 / 折りたたみ、すべて展開 / 折りたたみ（`ui.composer_files` で初期状態を設定） |
| `e` / `Enter` | 鉛筆 | メッセージを編集 |
| `d` / `Delete` | `drop` / `復元` | commit を除外（そのファイルは commit されないまま残る） |
| `n` | `+ 単独のcommit` | ファイルを単独の commit に移す |
| `r` | `リセット` | モデルのプランに戻す |
| `Ctrl+S` / `a` | `commit N 件を作成` | 順番に commit を作成 |
| `Esc` | `キャンセル` | 何もせずに終了 |

作成時には、各 commit のファイルをステージして commit する処理を順に行います。作業ツリーには一切触れません。一部だけステージされたファイルは、丸ごと commit されます。途中で失敗すると、そこで止まり、いくつの commit が作成されたかが表示されます。

### commit の分割

モデルは commit の変更を、[分割エディター](log-and-history.md#commit-を分割する)と同じ番号付けで読み取り、メッセージ付きの複数の commit を提案します。ハンク単位でも、1 行単位でもグループ化できます。変更を取りこぼした答え、同じ変更を 2 回割り当てた答え、存在しないものを指した答えは拒否されます。いずれの場合も分割エディターが開き、提案が入力済みの状態か、モデルが失敗したときは理由がメモとして表示された状態で開くため、手動で分割できます。**分割**（`Ctrl+S`）を押すまで、何も分割されません。グループ分けが合わなければ、先に変更を移動したり、commit の名前を変えたり、commit を追加したりしてください。プロファイルと指示は、設定 > AI の*commit の分割*のものです。

### 履歴書き換えスクリプト

書き換えでやりたいこと（「夜間に作成したすべての commit を翌朝に移す」「古いメールアドレスを新しいものに置き換える（2024 年より前のみ）」など）を伝えると、モデルがスクリプトルール用の [Lua スクリプト](history-rewrite.md#lua-スクリプト)を書きます。ヘッダー、`rewrite_commit(c, ctx)`、サンドボックスのヘルパーが含まれます。デーモンが返ってきた答えをコンパイルし、コンパイルできなければ、エラーを一度だけモデルに返します。最終的に残ったものがエディターに表示されるので、内容を読み、テストしてから、プレビューしてください。詳細とダイアログについては[履歴の書き換え](history-rewrite.md#ai-でスクリプトを作成する)を参照してください。プロファイルと指示は、設定 > AI の*履歴書き換えスクリプト*のものです。

### 履歴書き換えルール

履歴をどう書き換えたいかを自分の言葉で説明すると（「古いメールアドレス a@b.org を c@d.org に置き換える」「secrets.txt を全履歴から削除する」など）、モデルが対象範囲、いくつかの設定、そしてワークベンチの語彙で書かれた[書き換えルール](history-rewrite.md#ai-でルールを作成する)の一覧を提案します。**準備するだけです**：答えはワークベンチに入り、プレビューも適用もされません。使えない項目は理由付きで一覧され、有効な項目は残ります。この方法でスクリプトルールが作られることはありません。任意で、対象範囲、ブランチと tag の名前、最新の commit の作成者も一緒に送れます（既定ではオフのボックスで、「送信される内容」のペインに表示されます）。プロファイルと指示は、設定 > AI の*履歴書き換えルール*のものです。

## キーの送り先

API キー（OpenAI、Anthropic、OpenRouter、OpenAI 互換サーバー）は、保存時のアドレス、つまりプロファイルのベース URL のオリジンに結び付けられます。これはユーザー専用のプライベートデータフォルダーの `trust.toml` に記録されます。あとでベース URL が別の場所を指すようになると、何かを送る前にリクエストが拒否され、キーはそのまま残ります。意図して新しいアドレスにキーを移すには、`gitpoulpi ai trust <profile> --accept-origin <url>` を実行します（アプリ内で承認することもできます）。

- 平文の `http://` は、このマシン上（`localhost` の Ollama や LM Studio）では許可されます。それ以外では `gitpoulpi ai trust <profile> --allow-insecure-http on` が必要です。
- 証明書が既知の認証局につながらないセルフホストサーバーは、`--accept-certificate <sha256>` でピン留めした鍵のフィンガープリントに限って受け入れられます。TLS ハンドシェイクで、サーバーがその鍵を持っていることは引き続き確認されます。
- このチェックができる前からキーを持っていたプロファイルは、最初に使われたときに、現在のベース URL でそのまま記録されます。
- ローカルエージェント（`claude -p` など）にはキーも HTTP もないため、結び付けるものがありません。

## レビューのコンテキスト

コードレビューのドラフト（`✦`、または `hosting review suggest`）は、リクエストの差分、タイトル、説明、既存のコメントを読みます。
プロジェクト自身の規約も、差分の前に置かれる**プロジェクトの規約**ブロックとして渡すことができ、ローカルエージェントにリポジトリ内で
作業させることもできます。既定値は次のとおりです。

| 設定 | 既定 | 意味 |
|---|---|---|
| `run_in_repository` | `profile` | `profile`：AI プロファイルの*作業フォルダー*に従う。`yes`：プロファイルの設定に関係なく、レビューのためにローカルエージェントをリポジトリ内で実行する。`no`：そこでは実行しない（*リポジトリ*に設定されたプロファイルは、代わりに専用フォルダーを使う）。HTTP プロファイルには作業フォルダーがないため、影響しません。 |
| `include_claude_md` | オン | リポジトリの `CLAUDE.md` をモデルに渡す。 |
| `include_agents_md` | オン | リポジトリの `AGENTS.md` をモデルに渡す。 |
| `extra_file` | なし | 追加ファイル1つ：リポジトリルートからの相対パス、絶対パス、またはリンク。 |

これらは指示と同じように重ねて適用され、フィールドごとに最も具体的なものが優先されます：全体の `[ai.review]` テーブル、
次にリポジトリ固有の値（未設定のフィールドは継承）、最後に1回の実行での選択です。クローンしていないリポジトリは、
レビューのドラフトと並んで `remote-reviews.toml` に `host/project` ごとに固有の値を保存します。

リポジトリは、全体の追加ファイルを**オフ**にすることもできます。そのリポジトリの `no_extra_file = true`（*リポジトリ固有の設定 > AI* の**追加ファイルなし**チェックボックス、✦ レビューのオプションのダイアログ、`ai review-context` の `--no-extra-file` フラグ）は、`[ai.review]` が何を指定していても「このリポジトリでは追加ファイルなし」を意味します。**空**の**追加ファイル**フィールドは同じ意味ではなく、全体のファイルを継承します。リポジトリのファイルとこのスイッチは互いに排他的で（一方を設定すると他方が解除されます）、手で編集したファイルに両方がある場合はスイッチが優先されます。リポジトリの古い `extra_file = ""` は引き続き「なし」を意味します。

ファイルの取得元：

- `CLAUDE.md`、`AGENTS.md`、相対パスの追加ファイルは、リクエストが対象とするブランチのリポジトリの**ルート**から読み取られ、
  作業ツリー（別のブランチだったり、ローカルの編集があったりする）から読まれることはありません。クローンがある場合はリクエストの
  ベースコミットから、ない場合はホストの API から読み取ります。
- 絶対パスは、このマシンから読み取られます。
- コードホスト上のファイルへのリンク（GitHub の `.../blob/<branch>/<path>`、GitLab の `.../-/blob/<branch>/<path>`、
  Gitea と Forgejo の `.../src/branch/<branch>/<path>`、または raw リンク）は、ホストが一致する連携プロファイル経由で読み取られるため、
  すでに設定したトークンでプライベートリポジトリも使えます。どのプロファイルにも一致しないリンクや、それ以外のアドレスは、匿名で取得されます。
  スラッシュを含むブランチ名はリンクから読み取れません：パスを使うか、スラッシュのないブランチのリンクを使ってください。
- `CLAUDE.md` や `AGENTS.md` がなくても何も表示せずスキップされますが、追加ファイルがない場合は報告されます
  （CLI の JSON の `context.problems`）。
- 各ファイルは **8 KB**、全ファイルの合計は **16 KB** で切り詰められ、モデルが読む内容に
  `[CLAUDE.md cut: showing ... of ... bytes]` という目に見える注記が付きます。

ローカルエージェントがリポジトリ内で実行される場合、チェックアウトされているファイルはリクエストの head と一致しないことがあり、
差分が正であることがプロンプトで伝えられます。

レビュー画面では、`s` で **✦ レビューオプション**ダイアログが開き、リポジトリの値（なければ全体の値）が入力済みです。
今回の実行に限って変更するか、*このリポジトリの既定値として保存*にチェックして保持します
（[レビューオプション](review.md#レビューオプション)を参照）。既定値は*設定 > AI*（*コードレビュー*のブロック、4 行）と、
*リポジトリ固有の設定 > AI* でも編集できます。後者では各行を*全体を使用*にでき、*全体にリセット*ボタンでリポジトリ固有の値が
破棄されます。設定の検索でも見つかります（`CLAUDE.md を含める`、`追加ファイル`）。モデルに渡せなかったもの（存在しない追加ファイル）や
収まるよう切り詰められたものは、ドラフトのカードに表示されます。

コマンドラインから：

```sh
gitpoulpi ai review-context                      # 全体の既定値と、レビューで実際に使われる内容
gitpoulpi ai review-context --agents-md off      # 全体の既定値を保存
gitpoulpi --repo ~/work/app ai review-context --claude-md off --context-file docs/REVIEW.md
gitpoulpi ai review-context --project github.com/acme/app --context-file https://github.com/acme/rules/blob/main/review.md
gitpoulpi ai review-context --repo ~/work/app --reset   # 再び全体の既定値に従う
gitpoulpi hosting review suggest 12 --claude-md off --context-file docs/REVIEW.md --run-in-repo no
```

`ai review-context` はモデルが不要で、AI をオフにしていても使えます。`ai prompt --action code_review` は有効なコンテキストを
`review_context` として出力します。同じ 4 つの設定は `config.toml` の `ai.review.*` です
（[リファレンス](config-reference.md#ai組み込み-ai既定ではオフ)）。

## 入力の上限

GitPoulpi がリクエストに入れるすべての入力には、`[ai.limits]`（*設定 > AI > 上限*）の設定としてサイズの上限があります。
この上限は GitPoulpi 独自の安全策です（モデルのコンテキストウィンドウはモデルごとに異なります）。
モデルに余裕があるときは引き上げ、リクエストを小さく保ちたいときは下げてください。

| 設定（`ai.limits.`） | 既定値 | 上限の対象 |
|---|---|---|
| `conflict_bytes` | 40000 | 1 つの merge 競合のベース、現在、受け入れ側のブロック |
| `diff_bytes` | 60000 | commit メッセージ、説明、stash の名前、pull request の説明、commit プラン、commit の分割の diff、およびコードレビュー全体の diff |
| `review_file_bytes` | 12000 | コードレビューでの 1 ファイルの diff |
| `review_text_bytes` | 4000 | レビュー対象の pull request の説明 |
| `review_threads_bytes` | 6000 | すでにあるレビューコメント |
| `review_context_file_bytes` | 8192 | レビューの 1 つのプロジェクトコンテキストファイル（`CLAUDE.md`、`AGENTS.md`、追加ファイル） |
| `review_context_bytes` | 16384 | レビューのすべてのコンテキストファイルの合計 |

**黙って切り詰められることはありません。**入力が上限を超えると、リクエストは待機し、*AI の上限を超えています*が
超えているものを一覧します。どの部分か（diff、ファイル、説明、コンテキストファイル）、そのサイズ、上限、設定です。
レビューでは、超えているすべての部分が 1 つのダイアログに並びます。ボタンとそのキーは次のとおりです。

- *すべて送信*（`S`）：このリクエストのみ、何も切り詰めません。プライバシーのチェック（シークレットの置き換え、
  機密ファイルの除外）と、オンのときは次に表示される*送信される内容*ペインは、引き続き通ります。
- *切り詰めて送信*（`K`）：上限を超えた部分が、従来どおり切り詰められます。ダイアログの各行に、
  何が除外されるか（diff の末尾、最後のハンク、収まらないファイル）が示されます。
- *設定を開く*（`O`）：リクエストをキャンセルし、最初に挙げられた上限の*設定 > AI > 上限*を開きます。
  フォーカスはここから始まり、Enter で送信されることはありません。
- *キャンセル*（`C`、`Esc`、閉じる ✕、または外側のクリック）：何も送信しません。

競合は例外で、切り詰められることはありません。*そのまま送信*（`S`）が全体を 1 回だけ送信します。

AI のリクエストが自動で始まることはないため、確認できるバックグラウンドの実行はありません。
すべてのリクエストは、あなたが始めたものです。確認できない実行（CLI と MCP）は従来どおり切り詰め、
その旨を伝えます。下記を参照してください。

**コマンドラインでは**ダイアログに答えられないため、上限を超えた入力は従来どおり切り詰められ、
応答に切り詰めた内容が示されます：
`truncated: [{part, detail?, bytes, limit, setting}]`（何かを切り詰めたときだけ含まれます。`part` は `diff`、`split_hunks`、
`review_diff`、`review_file`、`review_text`、`review_threads`、`context_file`、`context_total` のいずれかです）。
`--send-all`（別名 `--no-truncate`）は代わりにすべてを全体のまま送信します：`ai`（すべてのコマンド。上限を超えた競合が
そうでなければ拒否される `ai resolve-conflict` を含む）、`commit --ai`、`stash push --ai`、`hosting review suggest` で使えます。
MCP のツールにも同じ `send_all` 引数と同じ `truncated` フィールドがあります。

## プライバシー

- ボタンを押すかコマンドを実行するまで、何も送信されません。バックグラウンドでの AI、利用統計、GitPoulpi のアカウントはありません。
- 送信されるもの：プロンプト（組み込みのもの、続いて自分で書いた指示）と、依頼した diff。pull request の場合は、ブランチの commit の件名も送信されます。60 KB（`ai.limits.diff_bytes`）を超える diff が黙って切り詰められることはありません。[入力の上限](#入力の上限)を参照してください。
- 履歴書き換えスクリプトの依頼では、あなたの指示と、固定のスクリプト仕様（スクリプトサンドボックスの API）が送信されます。最大 20 件の commit の作成者、日付、件名が送られるのは、ダイアログで*サンプルを送る*にチェックを入れた場合**だけ**です（既定はオフで、CLI では `--sample N` が必要です）。ファイルの内容とシークレットの値は送信されません。
- 送信先は、その操作に選んだプロファイルのみです。その API ホスト、またはローカルエージェントのコマンドの標準入力（以降はそのエージェントの動作に従います）です。
- API キーは `gitpoulpi` プロセス自身が使用し、デーモン、ウィンドウの他のクライアント、MCP クライアントには渡りません。
- 生成されたテキストが、自動で commit、push、適用されることはありません。

### リクエストから取り除かれるもの

どのアクションが送るか、どのプロバイダー（ホスト型 API かローカルエージェント）が受け取るかにかかわらず、すべてのリクエストは、最初に同じクリーニング処理を通ります。

- **シークレットは伏せられます**（`[ai.privacy] redact_secrets`、既定でオン）。既知のプレフィックスを持つトークン、秘密鍵のブロック、JWT、URL 内のパスワード、値がランダムに見える `password = value` の行は、`[REDACTED:<rule>]` に置き換えられます。網羅的ではなく、よくある形を見つけます（`rewrite scan-secrets` と同じスキャナーです）。
- **機密ファイルは除外されます**（`[ai.privacy] exclude_sensitive_files`、既定でオン）。`[privacy] sensitive_patterns`（`.env` と `.env.*`（`.example`、`.sample`、`.template` を除く）、`*.pem`、`*.key`、SSH 秘密鍵、`*.p12`、`*.pfx`、`*.jks`、`*.keystore`、`*.crt`、`*.cer`、`*.der`、`*.kdbx`）に一致するファイルの diff は、リクエストに含まれません。そのようなファイルを挙げる分割パートやコンポーザーのファイル一覧も同じように切り落とされるため、そのファイルの計画は不完全として拒否されることがあります。そのファイルは自分でステージまたは分割してください。

どちらかをオフにするのは自分の選択であり、オフの間、設定 > AI には、その下に赤い行が表示されます。

**送信する前に、送信内容を確認します。** リクエストが外に出る前に、TUI は**送信する内容の確認**ダイアログを表示します。クリーニング後の指示とリクエスト（履歴書き換えのダイアログと同じペインで、スクロールでき、`Alt+W` で表示と非表示を切り替えます）、置き換えられたシークレットの数と除外されたファイル（ルールと `ghp_****abcd` のようなマスクしたプレビュー。値そのものは表示しません）、**<アクション>では今後表示しない**ボックス、**送信**と**キャンセル**が表示されます（`Esc`、閉じる ✕、外側のクリックでキャンセル。送信するまで何も外に出ません）。このボックスは `[ai.sent_preview] <action> = false` を書き込みます。設定 > AI の*送信前に内容を表示...*にはアクションごとのスイッチと**すべて再表示**があります。2 つの履歴書き換えダイアログはすでにリクエストを表示しているため、スイッチはありません。

**コマンドラインでは**、すべての `ai ...` の応答（と `hosting review suggest`）に `privacy: {redactions: N, excluded_files: [...]}` が含まれ、`--print-sent` はクリーニング後の system テキストと user テキストを `{sent: [{system, user}], privacy, dry_run: true}` として、モデルを呼ばずに出力します（`ai.enabled = true` が必要で、キーもネットワークも不要です）。

**制限。**作業フォルダーがリポジトリであるローカルエージェント（`workdir = repository`、またはレビューの*リポジトリ内でエージェントを実行*）は、ファイルを自分で読めます。クリーニングの対象は GitPoulpi が送るものであり、エージェントが自分で開くものではありません。エージェントをリポジトリに近づけないようにするには、`dedicated` の作業フォルダーを使ってください。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| どこにも `✦` がない | AI がオフです：*設定 > AI > AI を有効化*。 |
| `✦` がグレー | 何もステージされていません（commit メッセージの場合）。 |
| *接続テスト*：コマンドが見つからない | ローカルエージェントの**コマンド**が、GitPoulpi から見える `PATH` にありません。`claude --version` が動く環境で GitPoulpi を起動するか、フルパスを指定してください。 |
| ローカルエージェントが止まる、または対話画面が表示される | *ヘッドレス*の実行モードでは、**引数**にヘッドレス用のフラグ（Claude Code なら `-p`）を追加するか、**エージェントの種類**を選び直してヘッドレス用の呼び出しを復元してください。対話画面は、*対話型（仮想ターミナル）*の実行モードのためのものです。 |
| "Use "Open the agent"..." | エージェントが初回起動時の質問（フォルダーの信頼、サインイン）をしています。プロファイルの**エージェントを開く...**を使って答え、エージェントを閉じてから、もう一度試してください。 |
| 仮想ターミナルのリクエストがタイムアウトする | メッセージの末尾にエージェントの画面の最後の数行が付きます。権限の確認、ログイン、更新の質問がそこに表示されます。**エージェントを開く...**で答えるか、**タイムアウト**を延ばしてください。 |
| `失敗：` 401 | キーが間違っているか、別のプロバイダーのキーです：入力し直してください。 |
| `失敗：` 404 | その**モデル**は存在しません：空にして既定を使ってください。 |
| `失敗：` 接続エラー（Ollama、LM Studio） | サーバーが起動していないか、**ベース URL** のポートが違う、または `/v1` がありません。 |
| キーを入力したのに `（未設定）` と表示される | 認証情報ヘルパーがありません：設定してから（`git config --global credential.helper ...`）、もう一度入力してください。 |
| *AI の上限を超えています* | リクエストの入力が `[ai.limits]` の上限を超えています：*すべて送信*、*切り詰めて送信*、*設定を開く*、*キャンセル*から選んでください（[入力の上限](#入力の上限)を参照）。 |
| 「この競合は上限より大きいです」 | 競合が `ai.limits.conflict_bytes`（既定 40000）を超えています。*そのまま送信*で 1 回だけ送信でき、*設定を開く*で 設定 > AI > 上限の該当の上限へ移動します。 |
| 言語やスタイルが違う | 指示を追加してください。エディターのクイック挿入のチップを使うと簡単です。 |
| コンポーザーが「プランが無効」と言う | モデルがファイルを飛ばした、または重複させました：もう一度試すか、より強力なモデルを使ってください。 |

## 古い設定ファイル

`[[ai.presets]]` と `[ai.defaults]` を含む古い `config.toml` も、引き続き読み込まれます。

- 各操作の既定のプリセットは、その操作の `[ai.actions.<action>]` になります（`system_prompt` は `instructions` になります）。
- 古いプリセットはすべて `[[ai.legacy_presets]]` に保持されます。設定 > AI では、*古いプリセット*の下に、*アーカイブを削除*とともに表示されます。
- リポジトリの古い `[preferences.ai_presets]` は、リポジトリの上書き設定になります。

組み込みプロンプトは常に最初に置かれるようになりました。古いプロンプトが組み込みプロンプトをコピーしていた場合は、コピーした部分を削除し、追加したい内容だけを残してください。
