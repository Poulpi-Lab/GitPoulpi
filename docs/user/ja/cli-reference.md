# CLI リファレンス

サブコマンドなしの `gitpoulpi` はウィンドウを開きます。サブコマンドを付けると、スクリプトから使える git クライアントになります。どのコマンドもウィンドウと同じバックグラウンドデーモンを経由するため、スクリプトで行った変更は、開いている GitPoulpi にリアルタイムで反映されます。エージェントが使う MCP ツールは、これらと同じコマンドから生成されます（[MCP とエージェント](mcp-and-agents.md)）。すべてのフラグは `gitpoulpi <command> --help` で確認できます。

## グローバルフラグ

| フラグ | 効果 |
|---|---|
| `--json` | 結果を JSON で出力します。エラーも JSON です：標準出力に `{"error": "..."}` が出力され、終了コードは 1 です。 失敗した git 操作には `"detail": {"operation", "command", "exit_code", "stderr"}` が加わります（実行された git コマンド（秘密情報はマスク済み）、その終了コード、stderr の末尾。内蔵の git ライブラリの場合は `"git2": {"class", "code", "message"}`）。MCP ツールも同じオブジェクトを返します。`--json` なしでは、これらの行は stderr に出力されます。 |
| `--repo <path>` | 操作対象のリポジトリ（既定：git と同様に、カレントディレクトリを含むリポジトリ）。 |
| `-s, --session <name>` | 通信先のセッション（デーモン）。既定：リポジトリのルートから決まるため、1 つのリポジトリ内で開いたものはすべて 1 つのデーモンを共有し、2 つのリポジトリには 2 つのデーモンが対応します。 |
| `--backend git2\|system` | このコマンドが起動するデーモンのバックエンド（すでに動いているデーモンは自分のものを維持します）。 |
| `--cwd-file <file>` | ウィンドウが終了するときに、アクティブなタブのフォルダーを書き込む先（`shell-init` が使います）。 |
| `-a, --add [path]`、`--no-raise` | すでに起動中の GitPoulpi に、別のものを起動する代わりにフォルダーを新しいタブとして開きます。[開いているウィンドウにフォルダーを追加する](#開いているウィンドウにフォルダーを追加する)を参照してください。サブコマンドは受け付けません。 |
| `-l, --lang <lang>` | `--help` のテキストのみの言語：`en`、`fr`、`es`、`pt-BR`、`pt-PT`、`it`、`de`、`zh-CN`、`ja`、`ko`、`ru`、`uk`、`pl`、`cs`、`nl`、`sv`、`tr`。[ヘルプの翻訳](#ヘルプの翻訳)を参照してください。 |

### 開いているウィンドウにフォルダーを追加する

`gitpoulpi --add [path]`（`-a`。`gp -a` と `gpa` のコマンドエイリアスも同じコードを実行します）は、`path`（既定は現在のディレクトリで、それを含むリポジトリに解決されます）を、すでに起動中の GitPoulpi の新しいタブとして開きます。ターミナルで `cd` したフォルダーのために 2 つ目のウィンドウが起動することはありません。

- *起動中のセッション*とは、デーモンが応答し、GitPoulpi のウィンドウが接続されているものです。**AI エージェントによるビューの操作を許可する**をオフにしているウィンドウは自分を知らせないため、見つかりません（`gitpoulpi launch` と同じ制限です）。
- 起動中のセッションが 1 つ：そのセッションがタブを受け取ります（そのリポジトリがすでに開いていればそのタブを表示します）。デスクトップが許せばウィンドウが前面に出ます（Windows、WezTerm、Hyprland。`--no-raise` で省略できます）。どのセッションが受け取ったかは 1 行で表示されます。
- 複数：タブ数とリポジトリ名とともに番号付きで一覧表示されます。番号を入力して Enter を押してください（空行、または Esc のあと Enter でキャンセルし、終了コードは 130）。標準入力がターミナルでない場合、コマンドは失敗し、`--session NAME` を指定するよう案内します。`-s NAME` を指定すると質問は省略されます。
- なし（または `-s NAME` が起動していないセッションを指す場合）：そのフォルダーで、`gp [path]` とまったく同じように、このターミナルで GitPoulpi を通常どおり起動します。
- ウィンドウはユーザー自身の操作として即座に適用します（確認のチップもエージェントの印もありません）。ただし、ウィンドウ側でフォームに入力中の場合は、ウィンドウがステータスバーのチップでタブを提示し、終了コードは 3 です。リポジトリの外にあるフォルダーは拒否されます（終了コード 1）。

`--json` は 1 つのオブジェクトを出力します：`{"action": "joined", "session", "repo", "already_open", "raised", "outcome": {...}}`（`outcome` は `ui show` と同じく、ウィンドウからの応答です）、または `{"action": "cancelled"}`。エラーは `{"error": "..."}` です。終了コード：0 はタブが開いた、3 はチップで提示した、1 は拒否または失敗、130 はキャンセル。MCP ツールはありません。ユーザーにリポジトリを見せたいエージェントは `ui show tab` を使います。

### ヘルプの翻訳

`gitpoulpi --help` は英語です。`-l` を付けると、別の言語で説明を読めます：`gitpoulpi -l fr --help`、`gitpoulpi -l de commit --help`。翻訳されるのは、説明とセクション見出しだけです。コマンド名、フラグ、値の名前、指定できる値は変わらないため、スクリプトやエージェントからは同じインターフェースに見えます。ヘルプの言語は環境変数からは読み取られません。`-l` を指定したときだけ出力が変わります。MCP ツールの説明は常に英語です。

リビジョンには git が受け付けるものなら何でも指定できます（`HEAD~2`、ブランチ、tag、短い sha）。ハンクと行は、`gitpoulpi --json diff` の番号付けに従います。

## コマンド

**確認**

| コマンド | 内容 |
|---|---|
| `status` | ステージ済み、未ステージ、未追跡、競合中のファイル。 |
| `log [--graph] [--limit N] [--skip N] [--path P] [--count]` | 履歴。`--skip` と `--limit` でページ送りし、`--path` でファイルの履歴になります。`--count` は `{"total": N}` だけを出力します。走査が保持している commit の数で（`--limit` / `--skip` は無視）、TUI のステータスバーのスラッシュの後の数字（`500 / 2500 commits`）です。 |
| `log --format mermaid [--detail structure\|refs\|subjects\|full] [--orientation lr\|tb] [--fence] [--range A..B] [--limit N] [--subject-width N]` | commit を Mermaid の `gitGraph` スクリプトとして出力します。ログの[Mermaid gitGraph としてコピー](log-and-history.md#commit-を-mermaid-gitgraph-としてコピーする)ポップアップが作るものと同じです。`--range A..B` は `git log A..B` と同じです（`A` だけなら `A..HEAD`）。指定しない場合は最初の `--limit` 件の commit（既定は 30）です。詳細度、方向、フェンスの既定は `ui.mermaid_*` です。`--json` を付けると `{format, detail, commits, text}`。通常の出力はスクリプトそのものです。 |
| `diff [--staged] [--path P] [--name-only]` | 作業ツリー（またはステージ済み）の diff をハンクと行で返します。`--name-only` は変更されたファイルとその状態だけを一覧にします。 |
| `diff --from <rev> [--to <rev\|worktree>] [--name-only]` | 2 つのリビジョン、またはリビジョンと作業ツリーを比較します（`--to` の既定は `worktree`：追跡対象ファイルのステージ済みと未ステージの変更）。ログの[比較](log-and-history.md#commit-を比較する)と同じ一覧です。 |
| `show <path> [--at REV \| --staged \| --worktree] [--raw [--output FILE]]` | リビジョン時点、インデックス、またはディスク上のファイルの内容。画像は `--json` で `image: {format, width, height}` を持ちます（ヘッダーから読み取ります）。`--raw` は正確なバイト列を標準出力、または `--output FILE` に書き出します（LFS ポインターの場合はローカルのオブジェクト）。MCP では使えません。 |
| `blame <path> [--at REV]` | 各行を誰が変更したか。ファイル全体の名前変更を追跡します。各行には commit、作成者とコミッターの時刻、`orig_path`（その commit でのファイル名）、`previous`（`[親, パス]`: その commit より前の行を見るために blame をやり直す場所。ルート commit で生まれた行や、親にファイルがない commit の行にはありません）が付きます。 |
| `file-history <path> [--at REV] [--skip N] [--limit N]` | ファイルを変更した commit を新しい順に、**名前変更を追跡して**（`git log --follow`）返します。各エントリには commit、親、作成者、作成者とコミッターの時刻、要約、その commit でのファイルの `path`、`change`（`Added`、`Modified`、`Deleted`、`{Renamed: {from}}`）、行数 `added`/`removed`（バイナリは null）があります。`--limit` の既定値は 100 で、`more` は古いエントリがあるかを示し、`--skip` + `--limit` でページングします。マージはすべての親と異なる場合のみ列挙され、数値は最初の親との差です。`log --path` と違い、名前変更で履歴は終わりません。 |
| `conflicts list [--names-only]` | 競合中のファイルと、3 つの側のテキスト。`--names-only` は軽量な一覧です（パス、種類、ステージ oid）。 |
| `conflicts show <path> [--conflict N]` | 競合中の 1 ファイル：ペインのラベル、3 つの側、番号付きの A/B の競合領域（`--json` は完全なドキュメント）。 |
| `conflicts resolve <path> --side ours\|theirs\|base` | 片側でファイルを解決します（`--ours` / `--theirs` は短縮形）。 |
| `conflicts resolve <path> --both [--theirs-first]` | すべての競合の両側を残します（A の次に B、または B の次に A）。 |
| `conflicts resolve <path> --pick 1=a,2=ba [--default a\|b]` | 競合ごとの選択：`a` は ours、`b` は theirs、`ab`、`ba`、`none`。すべての競合に選択があるか `--default` を指定しない限り、`pick_incomplete` で拒否されます。 |
| `conflicts resolve <path> --content-file F\|- [--encoding L]` | 指定された最終テキストを書き込みます（UTF-8、または `L` でエンコード）。 |
| `conflicts resolve <path> --delete` | 削除を受け入れます（削除／変更の競合）：`git rm`。 |
| `conflicts resolve ... [--no-stage] [--expect base,ours,theirs]` | `--no-stage` は解決済みの印を付けずに保存します。`--expect` は古い情報に対するガードです（ステージ oid、なしは `-`）。 |
| `conflicts unresolve <path>` | この操作の間に解決したファイルを、競合中の状態に戻します。 |
| `conflicts check` | HEAD を派生元のブランチへ merge すると競合するか？ `{"status": "conflicts"\|"clean"\|"no-base"\|"disabled", "head", "base_ref", "base", "base_source": "globs"\|"pull-request", "files": [...]}`。メモリ上の merge です（作業ツリー、インデックス、ref は変わりません。システムバックエンドでは git 2.38 以降、それ以外は `disabled`）。読み取り専用で、MCP ツール `conflicts_check` でもあります。[merge の競合を解決する](merge-conflicts.md#競合の予防)を参照してください。 |
| `conflicts state` | 進行中の merge、rebase、cherry-pick、revert（なければ `null`）。 |
| `conflicts abort` | その操作を中止します（破壊的：それまでの解決は失われます）。 |
| `conflicts skip` | 進行中の cherry-pick または revert（または rebase が止まっている commit）をスキップします：HEAD、インデックス、作業ツリーが HEAD に戻ります。空のものから抜け出す方法です。merge にはスキップするものがありません（破壊的、元に戻せません）。 |
| `conflicts am-continue` | パッチのファイルを解決してステージした後、進行中の `git am` を続行します（`{"outcome":"Completed"}` または `"Stopped"`）。 |
| `conflicts am-skip` | `git am` が止まったパッチをスキップします。 |
| `conflicts am-abort` | `git am` を中止します（破壊的：ブランチは `am` の前の状態に戻ります）。 |
| `job list` | デーモンのバックグラウンドジョブを古い順に表示します：fetch、push、pull、clone、LFS 転送は、受け付けた時点からそれぞれ 1 件のジョブです（待機中、実行中、または直近 30 秒以内に終了したもの）。JSON：id、kind、state、phase、progress、`not_cancellable`、`error`。 |
| `job cancel <id>` | ジョブを止めます。安全に止められない段階を過ぎていると拒否されます（終了コード 1、何も変わりません）。ジョブを開始したコマンドで Ctrl+C を押すと、そのジョブがキャンセルされます。 |
| `job wait <id> [--timeout S]` | ジョブが終わるまで待ち、最終状態を出力します。`Done` なら終了コード 0、失敗、キャンセル、タイムアウトなら 1 です。 |
| `index-lock show` | リポジトリの `index.lock`（なければ `null`）：パス、経過秒数、`stale`（10 秒より古い）。 |
| `index-lock remove` | 古い `index.lock` を削除します。10 秒未満のもの、または存在しない場合は拒否されます。 |
| `rebase-plan [<upstream>] [--root]` | インタラクティブ rebase が再適用する commit を、古い順に表示します。 |

| `ai rewrite-script <instruction> [--sample N]` | 指示をもとに AI が履歴書き換え用に書いた Lua スクリプトを、`{script, check, retried, sample, applied: false}` として出力します。`check` は `rewrite script check` がそのスクリプトについて返す内容です（コンパイルできないときはモデルにもう一度だけ尋ね、それでもだめなら終了コード 2）。送信するのは指示だけで、`--sample` を付けると、最新 `N` 件（最大 50）の commit の作成者、日付、件名も送ります。ファイルの内容は送りません。何も実行しません。`ai.enabled = true` が必要です。 |
| `ai rewrite-rules <description> [--context]` | 説明をもとに AI が提案する履歴書き換えのルールと設定を、`{recipe, problems, notes, retried, context, applied: false}` として出力します。`recipe` は `rewrite preview --recipe-json` が読む内容で、`problems` は除外した項目とその理由です（1 つでもあれば終了コード 2。有効なルールは残ります）。送信するのは説明だけで、`--context` を付けると、現在のブランチ、ブランチと tag の名前、最新 200 件の commit の作成者も送ります。ファイルの内容は送りません。プレビューも適用もしません。`ai.enabled = true` が必要です。 |
| `ai resolve-conflict <path> [--conflict N]` | 競合中のファイルの 1 つの競合に対して AI が提案する解決案を出力します（`N` は 1 始まり。ファイルに競合が 1 つだけなら省略可）。出力のみで、何も書き込みもステージもされません（結果の適用は `conflicts resolve`）。 |
| `ai prompt --action <a>` | このリポジトリで AI の操作が送信するシステムプロンプトを、レベルごと（`base`、`global`、`workspace`、`repository`、`task`）と、最終的な `system_prompt` として出力します。モデルは呼び出さず、AI がオフでも動作します。ワークスペースは、`GITPOULPI_WORKSPACE` のものがリポジトリを含む場合はそれ、なければ含む最初のものです。 `code_review` では `review_context` のエントリ（レイヤーではなく、差分の前でリクエストに加わる）が、差分以外にレビューへ渡されるものを有効な値とともに示します。 |
| `ai review-context [--repo PATH \| --project HOST/PROJECT] [--run-in-repo profile\|yes\|no] [--claude-md on\|off] [--agents-md on\|off] [--context-file PATH\|URL] [--no-context-file] [--no-extra-file [on\|off]] [--reset]` | コードレビューのドラフトに差分以外に何を渡すかを表示または設定します（`[ai.review]`。[AI > レビューのコンテキスト](ai.md#レビューのコンテキスト)を参照）。`--repo` も `--project` も指定しなければ全体の既定値です。`--repo`（グローバルフラグ）は1つのクローン固有の値、`--project github.com/owner/name` はクローンしていないリポジトリの値です（`remote-reviews.toml`）。設定フラグがなければ表示するだけで、あれば保存して表示します。JSON：`scope`（`global`、`repository`、`project`）、`target`、`global`、`own`（リポジトリまたはプロジェクトが設定したフィールドのみ）、`effective`（レビューで実際に使われる値）、`changed`。`--reset` はリポジトリまたはプロジェクト固有の値を破棄します。`--run-in-repo` は `--project` には適用されません。`--no-extra-file`（単独、または `on`）は、全体の設定にかかわらずリポジトリまたはプロジェクトに追加ファイルを渡さず、`off` は再び全体のファイルに従わせます。`--repo` または `--project` が必要で、`--context-file` とは同時に使えず、`own` には `"no_extra_file": true` が表示されます。モデルは不要で、AI がオフでも動作します。 |

加えて `commit --ai` と `stash push --ai` があります。モデルは `gitpoulpi` プロセスから呼び出されるため、API キーがデーモンや MCP クライアントに渡ることはありません。

### ワークスペースと検索

**ワークスペース**は、リポジトリに名前を付けたグループで、既定の commit プロファイルを持たせることもできます。
`config.toml` の隣の `workspaces.toml` に保存され、すべてのセッションとウィンドウで共有されるため、`workspace` コマンドはデーモンを起動しません
（`add` と `create --add` だけが、各リポジトリの `origin` URL を得るためにデーモンに問い合わせます）。リポジトリは複数のワークスペースに入れることができます。
パスの比較は、お気に入りや最近の一覧と同じ方法で行われます。

| コマンド | 内容 |
|---|---|
| `workspace list`、`workspace show <id>` | `{workspaces: [...]}` / `{workspace}`：`id`（スラッグ。名前を変えても変わりません）、`name`、`color`、`description`、`profile`、`profile_exists`、`repos: [{path, exists, remote}]`（`remote` はリポジトリの追加時に記録された `origin` の URL で、認証情報は除かれます）。 |
| `workspace create <name> [--add PATH]... [--profile ID] [--color C] [--description T]` | ワークスペースを作成して表示します。同じ名前のワークスペースは 2 つ作れません。`--add` は複数指定でき、コマンドを実行するリポジトリを選ぶ `--repo` とは別です。 |
| `workspace rename <id> <name>`、`workspace delete <id>` | 名前を変更しても id は変わりません。削除してもリポジトリには一切触れません。 |
| `workspace add <id> <path>...`、`workspace remove <id> <path>...` | `add` は各リポジトリのルートと `origin` の URL を記録します（存在しないパス、またはリポジトリの内側でないパスは、メッセージとともに拒否され、何も保存されません。あとで消えたリポジトリだけが、見つからない印付きで一覧に残ります）。`remove` は、ディスクから消えたリポジトリのパスも受け付けます。 |
| `workspace set-profile <id> <profile>` / `--none` | ワークスペースのリポジトリで commit に使う `[[profiles]]` の id です。どのプロファイルにも当たらない id は保存されます（`profile_exists: false`）が、適用されません。 |
| `workspace set-ai-instructions <id> [--action <a>] [--mode append\|replace] (--text T \| --clear)` | ワークスペースの AI の指示で、すべての操作向け、または 1 つの操作向け（`commit_message`、`code_review` など）です。`append` は全体の指示の後に追加し、`replace` は代わりに使います。ワークスペースのすべてのリポジトリに、リポジトリ自身の指示の前に適用されます。`workspace show` は `ai_instructions` として出力します。 |
| `commit -m M [--workspace ID]` | リポジトリがワークスペースに属し、プロファイルが存在するときは、そのワークスペースのプロファイルで commit します。それ以外は `general.active_profile`、さらにリポジトリ自身の ID です。`--workspace`（または `GITPOULPI_WORKSPACE`）がなければ何も変わりません：リポジトリは複数のワークスペースに入れられるため、commit が所属からワークスペースを推測することはありません。未知の id はエラーです。 |
| `search <query> [--workspace ID] [--kind K]... [--limit N]` | 現在のリポジトリ、またはワークスペースの全リポジトリ（`GITPOULPI_WORKSPACE` がフラグの代わりになります）の、ブランチ（ローカルとリモート）、tag、worktree、stash、commit メッセージ、ホスティングのキャッシュにある pull/merge request と Issue をあいまい検索します。ウィンドウ側の機能は[検索](search.md)です。 |

`search` は `{query, workspace, hits, partial, repos}` を返します。各ヒットは `{kind, label, detail, target, score, positions, repo}` です。
`kind` は `branch`、`tag`、`commit`、`stash`、`worktree`、`repo`、`pull_request`、`issue` のいずれか、`positions` は強調表示する `label` の一致文字、
`target` は移動先を示します（完全な参照名を持つ `{type: "ref", name}`、`{type: "commit", id}`、`{type: "stash", index, id}`、`{type: "worktree", path}`、
`{type: "repo", path}`、`{type: "pull_request", number}`、`{type: "issue", number}`）。ヒットはリポジトリをまたいで `score` で統合され、一致度の高いものが先頭です。
一致の判定はコマンドパレットと同じです：クエリそのまま、次にそのままどこかに含まれるもの、最後に文字が順序どおりに含まれるもの（早く短いほうが優先）。
commit の本文は、件名が一致せず、クエリが 3 文字以上のときだけ検索されます。プレフィックスは検索を絞り込み、テキストの一部にはなりません：
`b:` ブランチ、`t:` tag、`c:` commit、`s:` stash、`w:` worktree、`r:` リポジトリ（ワークスペースのみ）、`pr:`（または `mr:`）pull/merge request、`i:` Issue、
`#` はその両方です。`--kind`（複数指定可。名前は同じ）でも絞り込めます。
`partial` は、リポジトリの commit が [`search.commit_limit`](config-reference.md#searchワークスペース検索)で打ち切られたときに true になります。`repos` は、
各リポジトリを検索したかどうかを示します（検索しなかった場合は `reason` が付きます。ディスクから消えたパスは報告されるだけで、致命的ではありません）。
単発のコマンドは、先に各リポジトリのインデックスを作成します。同じセッションでウィンドウが開いていれば、デーモンがすでに温めています。
pull/merge request と Issue は、各リポジトリのホスティングのキャッシュ（ウィンドウが `.gitpoulpi/hosting-cache.json` に保持するファイル）から読まれ、
ホストに問い合わせることは決してありません。ウィンドウで一度も読み込まれていないリポジトリには見つかるものがなく、キャッシュがない、または書き込みが途中のときは、単にヒットなしになります。

**開いているウィンドウに表示する**（`ui`。すべてのコマンドが `--viewer <id>` と `--launch` も受け付けます）

| コマンド | 内容 |
|---|---|
| `ui viewers [--all-sessions]`、`ui state [--text]` | 開いているウィンドウと、その表示内容。 |
| `ui show commit <rev> [--also R] [--files] [--focus refs\|log\|status]`、`ui show ref <name>`、`ui show pr <n>`、`ui show issue <n>`、`ui show wip [path] [--staged] [--composer]` | 何かを選択します。 |
| `ui show diff <path> [--rev R \| --unstaged \| --staged] [--line N] [--side old\|new] [--split \| --inline] [--whole-file \| --hunks] [--highlight A-B]` | 指定した行で diff を開きます。 |
| `ui show file <path> [--rev R \| --worktree \| --index] [--blame \| --history] [--line N] [--column C] [--highlight A-B]` | ファイル、その blame、または履歴を開きます。 |
| `ui show tab [path]`、`ui show home [--filter F]`、`ui show search <query>`、`ui show palette [query]`、`ui show keys [topic]`、`ui show settings [page] [--setting KEY]` | タブ、ホーム、検索バー、パレット、ヘルプ、設定ページへ移動します。`gitpoulpi ui show settings --help` でページ名の一覧が出ます。 |
| `ui highlight <A[:C]-B[:C]> [--no-scroll]`、`ui notify <message>`、`ui back` | 行に色を付けます。トースト通知。直前の表示変更を元に戻します。 |
| `ui show conflict <path> [--conflict N]` | 競合中のファイルの競合 N で、merge エディターを開きます（何も選択も保存もされません）。 |
| `ui propose reword <rev> -m M`、`ui propose commit-message <summary> [--body B]`、`ui propose branch <name> [--start-point R]`、`ui propose tag <name> [--target R] [-m M]` | 自分で確定する、入力済みのダイアログを開きます（`[mcp] allow_ui_propose = true` が必要）。 |
| `ui propose split <rev> --plan <file\|->` | commit の上に分割エディターを開き、計画（`split-commit --plan` の JSON）を入力済みにします。確認、編集、適用はユーザーが行い、それまで何も分割されません。他の提案と同じ制限があります。 |
| `ui propose rewrite --recipe <file\|->` | レシピ（`rewrite preview --recipe` と同じ TOML または JSON）をあらかじめ入れた状態で、履歴書き換えワークベンチを開きます。プレビューと適用はあなたが行い、あなたが操作するまで、書き換え、消去、push は行われません。提案に含められるのは、最大 50 件のルール、スクリプトなし（スクリプトはプレビューで実行されてしまうため）、シークレット値なしです。ほかの提案と同じゲートです。 |
| `ui propose resolution <path> (--pick 1=a,2=ba,... [--default a\|b] \| --content-file F)` | 解決案があらかじめ選択された状態（またはファイル全体のテキスト）で merge エディターを開き、確認してもらいます。確定は、ユーザー自身の「保存して解決済みにする」だけです。他の提案と同じ制限が適用されます。 |

終了コード：0 は適用済み、3 はユーザーに委ねた、1 はそれ以外。詳細と、ウィンドウが従うルールは [MCP とエージェント](mcp-and-agents.md#ユーザーに表示する)にあります。

## 補足

- **セッション。** `gitpoulpi session list` は各セッションを `live` / `stale` 付きで表示します（そのポートへの接続で判定）。導出される名前は `<フォルダー>-<パスのハッシュ>` です。
- **対話的な確認はありません。** 質問されることはありません。危険な操作は、フラグ（`--yes`、`--force-with-lease`）が必要か、理由付きで拒否されます。
- **CLI にないもの**：`checkout --file`（1 ファイルの復元）はウィンドウだけにあります。
