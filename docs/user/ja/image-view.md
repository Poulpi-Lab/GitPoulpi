# Diff ビューとファイルビューの画像

画像であるバイナリファイルは、「（no textual changes - binary content...）」という通知ではなく、画像として表示されます。
Diff ビューでは**変更前**と**変更後**を表示し、ファイルビューではファイルの現在の状態を表示し、
merge エディターでは競合した画像の各側を表示します。ここにあるものはすべて読み取り専用です。
画像を見ても、リポジトリは変更されないので、元に戻すものは何もありません。

**設定 > 画像 > 画像をプレビュー**（`ui.image_view`）でオフにできます。
通常のバイナリ通知に戻ります。`image-view` 機能なしのカスタムビルドにはビューアーがまったくなく、
画像ページにはエディターの一覧だけが残ります
（[カスタムビルド](custom-builds.md)を参照）。

## 対象のファイル

PNG と JPEG は常に対象です。GIF、WebP（最初のフレーム）、BMP、ICO/CUR は、
ビルドに `image-view` がある場合に対象です。TIFF、AVIF、HEIC、PSD、RAW は認識されますが
デコードされません。形式、サイズ、寸法を示す情報カードが表示されます。SVG はテキストなので、
テキストの diff のままです。**プレビューの最大サイズ**（既定は 32 MiB）を超える画像や
64 メガピクセルを超える画像は、代わりに情報カードを表示します。Git LFS で保存されたファイルは、
そのオブジェクトがローカルのストアにある場合に表示されます。ない場合、カードは先に
`LFS > Pull` するよう案内します。透明部分は市松模様の上に描かれます。

## 描画の仕組み

画像プロトコルのあるターミナル（Kitty と Ghostty、WezTerm と iTerm2、
Rio、mintty）では、画像は本物の画像になります。それ以外（素の Windows Terminal、
tmux、GitPoulpi が知らないターミナル）では、色付きの半ブロック文字で描画されます。
縦の解像度は半分ですが、どこでも読み取れます。**画像プロトコルがない場合**は*情報カードのみ*に設定できます。
**ログとグラフ**ページの**画像プロトコル**で、特定のプロトコルを強制できます。

## Diff ビュー

画像ファイルの diff（commit のもの、WIP の未ステージまたはステージ済みの側）を開きます。
ヘッダーには両方のファイルが名前付きで表示され（`PNG 512x512 . 34 KiB -> PNG 640x480 . 41 KiB`）、
続いてズームのボタン、**合わせる**、**1:1**、**編集に使う**があります。

- ヘッダーの右側の**分割 | インライン**、または `m`：左右に並べるか、1 枚ずつ表示します。
  インラインビューでは、**Tab**、または*変更前 | 変更後*のクリックで、もう一方が表示されます。
  2 つのペインには狭すぎる分割は、設定（`ui.diff_layout`）を変えずにインラインで描画されます。
- 分割の**仕切り**は、ドラッグするか、`Alt+Right` /
  `Alt+Left`（変更前ペインが広がる/狭まる）で動かせ、ダブルクリックか `Alt+0` で中央に戻ります。
  この割合はセッション中は記憶されます。
- 新しいファイルは*新規ファイル*という見出しの 1 つのペイン、削除されたファイルは*削除されたファイル*を表示します。
  どちらも切り替えは非表示になります。作業中の変更で選択した未追跡の画像は、新しいファイルとしてプレビューされます。
- 変更前の側は、親 commit（commit の diff）、`HEAD`（ステージ済み）、またはインデックス（未ステージ）です。
  変更後の側は、その commit、インデックス、またはディスク上のファイルです。diff を開いている間に
  ディスク上のファイルが変わると（エディターから保存した、ツールが書き換えた）、画像は約 0.5 秒以内に追従します。

## ファイルビュー

ファイルのメニューまたは diff バーの**ファイルビュー**から画像を開きます。1 つのペインに、
そのリビジョンのファイル（作業中の変更ではディスク上のファイル）が表示されます。

## ズームとスクロール

| | |
|---|---|
| `+` / `-`（または `=`） | ペインの中心を基準にズームイン / ズームアウト |
| `0` | **合わせる**（既定）：画像全体を表示し、ウィンドウや仕切りのサイズを変えても合わせたままになります |
| `1` | 実寸（1:1） |
| 矢印キー、`h j k l` | ペインの 10 分の 1 ずつスクロール。`Shift` を押すとペイン 1 枚分。`PageUp`/`PageDown`、`Home`/`End` |
| ホイール | 縦にスクロール。`Shift`+ホイールで横に、`Ctrl`+ホイールでポインターを基準にズーム |
| ドラッグ | 画像をつかんで動かします。両側のスクロールバーはほかの場所と同じように使えます |

ズームしたビューは、ペインのサイズを変えても倍率と中心の点を保ちます。合わせるは合わせるのままです。
Diff ビューでは、2 つのペインが 1 つのズームと 1 つのスクロール位置を共有します
（**前後のズームとスクロールを同期**、既定でオン）。そのため、両方の画像の同じ部分が表示されます。
サイズが異なる場合、ズームはそれぞれに対して相対的に保たれます。**ピクセル表示にする倍率**（既定は 2x）以上では、
画像は滑らかにせず正方形のピクセルとして拡大され、アイコンやドット絵に向いています。

## 編集に使う

ヘッダーの**編集に使う**ボタンは、このマシンで見つかった画像エディター（GIMP、Krita、Inkscape、Photoshop、
Paint.NET、プレビューなど、そしてシステムの既定のアプリ）を一覧表示します。`o` で既定のものを実行し、
`Shift+O` で一覧を開きます。ファイル一覧の画像の右クリックメニューや、
コマンドパレット（*画像: 編集に使う...*）にもあります。一覧と既定は
**設定 > 画像**で設定します。[開く場所](open-in.md)と同じ仕組みです。

ディスク上のファイル（作業中の変更の側）の編集は直接です。エディターがその場で保存し、画像が更新されます。
それ以外のバージョン（commit のもの、インデックス、削除されたファイル）は**読み取り専用の一時コピー**に書き出され、
ステータスバーに通知が出るので、エディターがリポジトリを変更することはありません。

システムが画像の種類に登録しているアプリ（その「アプリで開く」リスト）は、リスト内の自分のエディターの後に並び、すでにあるプログラムは繰り返されません。画像以外のバイナリファイルにも同じリストがあります。[開く場所](open-in.md)を参照してください。

## merge エディター内

競合した画像は、カードの枠の中に **A**、**B**、（ある場合は）**ベース**の画像を左右に並べて表示します。
それぞれ枠に合わせて表示され、読み取り専用です（ここではズームできません。画像は選択を助けるだけです）。
ボタンとキーは変わりません：**A を残す**（`a`）、**B を採用**（`b`）、**ベースを採用**（`o`）、
**mergeツールで開く**（`m`）。プレビューには十分な幅のウィンドウ（約 70
列）といくらかの空き行が必要です。それより狭いと、カードは通常のテキストのものになります。
[merge 競合の解決](merge-conflicts.md)を参照してください。

## キーと設定

キーは[キーバインド](keybindings.md#画像ビュー)にあります。どれも
再割り当てでき、パレット（`Ctrl+P`、*画像*と入力）から呼び出せます。オプションは
[設定](settings.md#画像)の**画像**ページと
[設定リファレンス](config-reference.md)（`ui.image_view*`、`ui.image_editors`）にあります。
