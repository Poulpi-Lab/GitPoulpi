# merge 競合の解決

merge、cherry-pick、revert、rebase が競合で止まると、ログにバナー（*Mergeの途中 · feature を main へ · 競合 2 ファイル*）が表示され、競合したファイルは Status ペインに赤い `!` 付きで並びます。そのうちの 1 つを **mergeエディター**で開きます。A（現在の側）と B（取り込む側）が左右に並び、その下に、書き込み先のファイルである**出力**が表示されます。このページは簡易版です。キーの完全な一覧は[キーバインド](keybindings.md)にあります。

## 開き方

- Status ペインの `!` の行で Enter キーを押すか、ダブルクリックします。右クリックメニューの先頭は **mergeエディターで開く** です。
- バナーの **競合を解決...** ボタン（最初の競合ファイルを開きます）。
- 競合したファイルの Diff ビューにある **mergeエディター** ボタン（`Shift+E`）。
- パレット：**競合: mergeエディターを開く**。

自動で開くことはありません。止まった操作では、バナーと `!` の行が表示されるだけです。

![merge の競合で止まったリポジトリのログ：Resolve conflicts と Abort merge のあるバナー、赤い ! が付いた 2 つの競合ファイル](../images/conflict-banner.png)

エディターはウィンドウの全幅を使います。開いている間は Refs サイドバーと右パネルが隠れ、閉じると戻ります（その間は `F9` で表示と非表示を切り替えられます）。エディターの幅が `merge.side_by_side_min_width` 桁以上（既定は 100。設定 > diffとエディター。`0` は常に左右表示）なら、A と B は左右に並びます。それより狭いと、タブの後ろに 1 度に 1 つの側だけが表示されます。長い行は A と B が一緒に横へスクロールし（`Shift+←` / `Shift+→`、Shift+ホイール、または横ホイール）、折り返されることはありません。

![mergeエディター：出力の上に A（現在）と B（取り込み）が左右に並び、競合 1 は A から、競合 2 は B から採用済みで、競合 3 はまだ選択待ち](../images/merge-editor.png)

## 選択する

各競合は A と B の中で枠で囲まれたブロックになっており、ヘッダーにチェックボックスが、各行の先頭に `+` / `✓` が付きます。

| やりたいこと | キー | マウス |
|---|---|---|
| カーソル位置の行を採用する（フォーカス中の側） | `Space` | 行をクリック |
| フォーカス中の側のチャンク全体を採用する | `Enter` | ヘッダーの `[ ]` をクリック |
| この競合で A のみ / B のみを採用する | `a` / `b` | チャンクを右クリック |
| 両方を採用する（A、次に B / B、次に A） | `c` / `Shift+C` | チャンクを右クリック |
| 何も採用しない | `x` | チャンクを右クリック |
| 採用した 2 つの側の順序を入れ替える | `s` | `1st` / `2nd` のバッジをクリック |
| A をすべて採用 / B をすべて採用する（全競合） | `Shift+A` / `Shift+B` | ツールバー |
| この競合の選択を解除する（未解決に戻す） | A / B 内で `u`、どこでも `Alt+U` | チャンクを右クリックして **選択を解除（未解決に戻す）** |
| ファイル全体を元の競合状態に戻す（出力に入力していた場合は先に確認します。`Ctrl+Z` で元に戻せます） | A / B 内で `Shift+U`、どこでも `Alt+R` | すべて採用の横の **リセット** |
| 次 / 前の競合 | `F7` / `Shift+F7`、`Alt+Down` / `Alt+Up`（A / B 内では `n` / `Shift+N`） | `▼` / `▲`、またはスクロールバーのマークをクリック |
| 数字を付けると移動を繰り返す | `3j`、`2k`、`2n`、`3N`（A / B 内） | |
| 次 / 前の競合ファイル | `Alt+PageDown` / `Alt+PageUp` | ヘッダーの `›` / `‹` |
| ベース（共通の祖先）ペインを表示 / 非表示にする | `Alt+D`（A / B 内では `d`） | `ベース` |
| A と B にファイル全体を表示する（**全体**） | `Alt+F`（A / B 内では `f`） | `全体` |
| A または B の幅を広げる / 同じ幅に戻す | `Alt+Right` / `Alt+Left`、`Alt+0` | 区切りをドラッグ。区切りをダブルクリック |
| A / B / ベースを横にスクロールする | `Shift+←` / `Shift+→`（`Shift+H` / `Shift+L`） | Shift+ホイール、横ホイール |
| Refs と Status のパネルを表示 / 非表示にする | `F9` | |
| A、B、出力にフォーカスする | `F6` / `Shift+F6` | クリック |
| 今いる競合のままペインへ移動する | `Alt+1` で A、`Alt+2` で B、`Alt+3` で出力、`Alt+4` でベース。または `Ctrl+N` に続けて `1` / `2` / `3` | |
| 隣のペイン（A、ベース、B、出力）へ、同じ競合のまま移動する | A / B 内で `h` / `l` または `←` / `→` | |
| 出力の高さを切り替える | `z` | タイトルをドラッグ |
| 元に戻す / やり直す（選択と入力は 1 つのスタック） | `Ctrl+Z` / `Ctrl+Y` | |
| ファイルを書き込み、競合状態のままにする | `Alt+S` | **保存** |
| ファイルを書き込み、解決済みにする | `Ctrl+S` | **保存して解決済みにする** |
| 閉じる | `Esc` | `✕` |

すべてのスクロールバー（A / B / ベース、および出力）には、競合ごとに 1 つのマークが付きます。まだ選択が必要なものはオレンジ、処理済みは緑、現在の競合は青です。マークをクリックするとその競合へジャンプします（スクロールバーのつまみの下にあるマークはすでに画面内にあるため、そこでのクリックはつまみのドラッグになります）。

**全体** は、競合だけでなくすべての diff を色付けして、A と B にファイル全体を表示します。

![全体モード：A と B にファイル全体が表示され、変更が色付けされている](../images/merge-editor-full-file.png)

出力は本物のエディターです。クリックして入力し、選択、切り取り、貼り付けができ、`Ctrl+F` で検索できます。手で編集した競合に対して選択を行うと、その編集は置き換えられます（`Ctrl+Z` で元に戻せます）。何も選択されていない競合があるまま、またはまだ競合マーカーに見える行が残ったまま保存しようとすると、先に確認が表示されます。

### ✦ 解決案を提案（AI）

AI をオンにしている場合（設定 > AI。[AI アシスタント](ai.md)を参照）、ツールバーに **✦ 提案** ボタンが表示されます。競合の右クリックメニューには *✦ 解決案を提案（AI）* があり、`Alt+I` とパレット（`AI: merge競合の解決案を提案`）でも同じことができます。対象は現在の競合だけで、実行するのはユーザーが求めたときだけです。回答は、その競合に対応する出力の部分を 1 回の編集として置き換え、編集済み（`✎`）の印が付くので、`Ctrl+Z` でその競合を元の状態に戻せます。保存やステージが自動で行われることはありません。実行中はヒント行に経過時間が表示され、`Esc` でキャンセルでき、失敗した場合もそこに表示されます。AI がオフの場合、これらの操作は存在しません。

**保存して解決済みにする** を実行すると、そのファイルはステージされ、競合ファイルの一覧に戻ります。次のファイルは自分で開いてください。`Ctrl+Z`（または「元に戻す」ボタン）で、直前の「解決済みにする」を取り消せます。ファイルが残っていなければ、バナーに **Mergeをcommit**（cherry-pick、revert、rebase の場合は **続行**）と **Mergeを中止** が表示されます。後者は先に確認を求め、HEAD、インデックス、作業ツリーを元の状態に戻します。

結果が HEAD と同じになる merge（すべてで自分たちの側を採用した場合）では、ステージされたものも変更されたファイルもありませんが、それでも完了できます。**Mergeをcommit** で merge メッセージ付きの commit 入力が開き、その commit は 2 つの親を持ちます。同様に、merge が止まっている間は、何もステージされていなくても、コンポーザーの Commit ボタンが有効になります。

空の cherry-pick や revert（変更がすでに適用済み）は commit できません。git が拒否するため、**続行** はその旨を伝え、**スキップ** を案内します。**スキップ**（バナーのボタン、パレットの項目 *Git: Cherry-pick、リバートをスキップ*、CLI の `conflicts skip`）は先に確認を求め、その操作について何も記録せずに終了します。HEAD、インデックス、作業ツリーは HEAD に戻ります。スキップは元に戻せません（意図して手放したもの以外は何も失われません）。merge にはスキップするものがありません。

## テキストではない競合

バイナリファイル、Git LFS ポインター、8 MiB を超えるファイル、片側で削除されたファイル、名前変更の残り、シンボリックリンク、モードの変更、サブモジュールには、選択できる行がありません。エディターには、各側の内容を示す**カード**と、選択肢ごとのボタンが表示されます。選択すると、そのファイルはすぐに解決され、ステージされます。

| カード | 選択肢 |
|---|---|
| バイナリファイル、LFS ポインター、大きすぎるファイル | **A を残す**（`a`）、**B を採用**（`b`）、**ベースを採用**（`o`。ある場合）、**mergeツールで開く**（`m`） |
| 片側で削除、もう一方で変更 | **ファイルを残す**（`k`）、**削除を受け入れる**（`Shift+D`） |
| 名前変更の残り（パスが片側にしか存在しない） | **ファイルを残す**（`k`）、**ファイルを削除**（`Shift+D`） |
| シンボリックリンク、サブモジュール、ファイルモード | **A を残す**、**B を採用**、**ベースを採用** |

ファイルが画像（PNG、JPEG、GIF、WebP、BMP、ICO）の場合、ボックスには A、B、ベースの画像も、収まるように調整された読み取り専用の状態で、十分な幅のウィンドウに表示されます。[画像](image-view.md#merge-エディター内)を参照してください。

![バイナリの競合のカード：A、B、ベースの内容と、Keep A、Take B、Take Base、Open in merge tool のボタン](../images/merge-editor-card.png)

`Esc` を押すと、選択せずにカードを閉じます。外部 merge ツールは、設定 > diffとエディターの `general.external_merge_tool` です（`{base}`、`{local}` = A、`{remote}` = B、`{merged}`。空の場合は `git mergetool`）。ツールが正常終了すると、そのファイルはステージされます。

## 競合の予防

GitPoulpi は merge の*前に*知らせることができます。今いるブランチが、派生元のブランチ（その**ベース**）と競合しそうなとき、ログの上端の枠の行に帯が現れます：**origin/main と 2 個のファイルで競合**と、**ファイルを表示**ボタンです。帯は、進行中の操作のバナーの次に空いている枠の行に入るため、バナーが表示されている間は空きができるまで待つことがあります。何も merge されません。デーモンが 2 つの commit をメモリ上で merge するだけなので（libgit2、または git 2.38 以降なら `git merge-tree --write-tree`。それより古い git では、ログに 1 行残してこの機能がオフになります）、ファイル、インデックス、ref には触れません。

- **ベース**は、GitPoulpi がすでに知っていればブランチの pull request のターゲットブランチです（Pull requests セクションが保持するキャッシュを使うので、そのためのネットワーク呼び出しはありません）。知らない場合は、**ベースブランチ**のパターン（設定 > 競合の予防）に一致するブランチのうち、分岐してからの commit が最も少ないものです。同数なら先端が分岐点に近いほう、次にローカルよりリモート追跡ブランチ、最後に名前順で決まります。そのブランチ自身と、そのリモートのコピーがベースになることはありません。
- **ポップアップ**（帯をクリックするか、パレットの**競合: 予測された競合を表示**。キーボードから使えます）には、ファイルの一覧と、**merge のプレビューを開く**、**ベースに rebase** があります。これらはベースブランチ自身のメニュー行（*<base> を <branch> に merge*、*<branch> を <base> に rebase*）を代わりに実行するもので、履歴に記録されるので `Ctrl+Z` で戻せます。実際に競合する merge は、ほかの merge と同じく merge エディターで止まります。左右キーでボタンを移動し、Enter で押し、Esc で閉じます。
- **実行されるとき**：リポジトリが静かになってから約 2 秒後にバックグラウンドで実行されます（commit、checkout、ブランチを動かした fetch、rebase のあと）。`(HEAD, ベース)` の組ごとに 1 回です。HEAD が動くと帯はすぐに隠れ、新しい結果に応じて再び現れるか、現れないままになります。HEAD が切り離されている場合は確認しません。
- **オフにする**：設定 > 一般の**競合の事前検出を有効化**、または 1 つのリポジトリについては、その**競合の予防**ページ。スクリプトからは、`gitpoulpi conflicts check` が同じ結果を JSON で出力します（[CLI リファレンス](cli-reference.md)）。

## エージェント

エージェントは、競合をユーザーに見せる（`gitpoulpi ui show conflict <path> [--conflict
N]`：エディターがその競合で開き、何も選択されません）ことも、解決を**提案**する（`gitpoulpi ui propose resolution <path> --pick 1=a,2=ba` または `--content-file F`。*AI エージェントの変更提案を確認できるようにする* が必要）こともできます。提案を受けると、選択内容（またはテキスト全体）がすでに出力に入った状態でエディターが開き、紫色の *✦ claude-code からの提案* バナーが表示されます。内容を確認し、必要なところを変更して **Ctrl+S** を押してください。何かが書き込まれたりステージされたりするのは、その操作だけです。エディターを閉じると、提案は却下されます。[MCP とエージェント](mcp-and-agents.md)を参照してください。

スクリプトからは、同じ操作を `gitpoulpi conflicts list | show | resolve |
unresolve | state | abort` で実行できます（[CLI リファレンス](cli-reference.md)）。`conflicts check` は、merge の前に競合を予測します。
