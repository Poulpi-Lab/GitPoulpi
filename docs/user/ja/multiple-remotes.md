# 1 つのブランチに複数のリモート

多くのリポジトリは複数のホストにまたがっています：メインのホスト（`origin`）、別のホストのミラー、バックアップなどです。GitPoulpi では、ブランチをワンクリックでそのすべてに push でき、必要なら複数のリモートから pull もできます。素の git の動作は何も変わりません。アカウントは不要で、すべてリポジトリ自身の `.git/config` に保存されるので、素の git やほかのツールもそのまま使えます。

## push 先と pull 元

- **アップストリーム**は git 本来の概念（`branch.<name>.remote` と `merge`）です。ブランチの*主*リモートで、GitPoulpi はその動作を一切変えません。
- **push 先**は、ブランチが追加で push するリモートです。Pushボタンは、ブランチをアップストリームとすべての push 先に送ります。
- **pull 元**は、pull が追加で commit を取り込むリモートです。オンにしない限りオフです（**Pull も**チェックボックス）：選んでいない 2 つのリモートを merge するのは、誰も望まない既定だからです。

push 先では、そのリモート上で別のブランチ名を使えます（`backup` には `feat-x` を送る、など）。

## リモートのダイアログ

ブランチを右クリックして **<ブランチ名> のリモート...** を選びます（Push のドロップダウン、パレットの `Git: ブランチのリモート...`、Refs セクションのそのブランチの行にある `⇉3` バッジのクリックからも開けます）。リポジトリのすべてのリモートが一覧に出ます：

| 列 | 意味 |
|---|---|
| リモート、ブランチ | リモートと、そこでのブランチ名。**リモート上の名前を変更...** は、選択した行のその名前を変えます。 |
| Push | チェックすると、そのリモートがこのブランチの push 先になります。 |
| Pull も | チェックすると、pull がそのリモートも取り込みます。アップストリームは常に pull されます。 |
| 状態 | ブランチがそのリモートに対してどの位置にあるか：同期済み、先行、遅れ、新規、無関係。 |

「リモートなし」と表示された行は、ブランチがまだ記録しているのにリポジトリにはもう存在しないリモートです。**削除**でそれを忘れます。同じダイアログでアップストリームも設定でき（**アップストリーム**リスト）、**アップストリーム解除**で外せます。**適用**は、すべてを元に戻せる 1 つの変更として書き込みます。

リポジトリは、すべての新しいブランチに同じ追加の push 先を与えることもできます：**設定 > Git とエンコード**（リポジトリ別のページ）の「新しいブランチの追加push先」（リモートごとに 1 つのチェックボックス）です。ブランチが最初にアップストリームを持つときにブランチへコピーされ、既存のブランチは変更されません。

## push する

- 追加の push 先があるブランチでの **Pushボタン**：そのすべてに push します。どのリモートも新しい commit をそのまま受け取れるなら、すぐに実行され、進行状況の表示で各リモートにチェックマークが付いていきます。判断が必要な場合（リモートに自分にはない commit がある）は、代わりに計画のダイアログが開きます。
- **Push ▾**（ボタンの横の矢印。設定で **Pushボタン**を **ask** にしているときはボタン自体も）：
  - `すべてにPush（origin, gitlab, backup）`
  - `<リモート> のみにPush`：ブランチのリモートごとに 1 つ
  - `選択したリモートにPush...`：どのブランチにも常にあります（リモートが 1 つだけのブランチでも）
  - `<ブランチ名> のリモート...`
- ブランチの右クリックメニューとパレット（`Git: すべてのPush先にPush`、`Git: リモートへPush...`、`Git: 選択したリモートにPush...`）にも、同じ名前で同じ操作があります。

**選択したリモートにPush...** は、リポジトリのすべてのリモートの一覧を開き、ブランチのアップストリームと push 先にチェックが入っています。今回の push だけに有効です。**このブランチに記憶**にチェックを入れると、その選択がブランチの push 先として保存されます。

### 計画

グループの push の前に、GitPoulpi はすべてのリモートを調べます（簡単な問い合わせと、差がある場合のみそのリモートからのダウンロード）。3 番目のリモートの問題も、最初の push が始まる前に分かります。ダイアログには各リモートについて、ブランチの位置と実行する内容が一覧で出ます：

| 状況 | 既定の操作 | ほかに選べる操作 |
|---|---|---|
| リモートにブランチがない、または一部の commit が足りない | Push | スキップ |
| リモートのほうが進んでいる（そのリモートに送る新しいものがない） | そのリモートから早送り | スキップ |
| push 済みのものを rebase または amend したため、リモートと異なる | 強制push（リース） | Merge、Rebase、スキップ |
| リモートに他の人の commit がある | そのリモートから Merge（**Pullボタン**が rebase のときは Rebase） | Rebase、強制push（リース）、スキップ |
| 履歴が自分のものと何も共有していない | スキップ | 強制push（リース） |
| ホストがブランチを拒否した（保護されている） | スキップ | なし：強制しても拒否される |

各行の操作は変更できるリストです（左右キーで切り替え、Enter で開き、`s` でその行をスキップ）。merge は、競合するかどうかと、どのファイルで競合するかを表示します。**強制push**は必ず確認があり、リモートと置き換えられる commit の数を示し、必ずリース付きで（素の force は使いません）、元に戻せません：結果には、置き換えられた commit と、それを元に戻すコマンドが表示されます。**問題をスキップ**は、問題のあるすべての行をスキップにします。**実行**（Ctrl+Enter）で開始します。

merge、早送り、rebase が先に一覧の順で実行されるので、ブランチは最終状態に一度で到達します。そのあと push が 1 リモートずつ、アップストリームから順に送られます。リモート間の「全部成功か全部失敗か」というアトミックな動作はありません：各リモートがそれぞれの結果で終わり、1 つの失敗（ネットワーク、フック）がほかを止めることはありません。**失敗分を再試行**（または `Git: 失敗したPushを再試行`）でそれらをもう一度試します。進行状況の表示を閉じても実行は止まりません。`Git: グループPushを表示` で呼び戻せます。

### 競合と続行

実行中の merge または rebase が競合で止まると、ダイアログが閉じ、通常の merge バナーと競合エディターに切り替わります。ログの上に `グループPushを一時停止中（gitlab）：競合を解決して完了し、続行してください。` というストリップが出て、**続行**と**グループを中止**のボタンが付きます。

- 競合を解決し、merge または rebase を完了します（GitPoulpi でも素の git でも）。
- **続行**は、それが終わるまでグレーのままで、**勝手に押されることはありません**：何も自動では続きません。押す（または `Git: グループPushを続行` を実行する）と、実行は新しい先端からすべてのリモートに再び push します。rebase のあと、まだ古い commit を持つリモートは、黙って強制されるのではなく、計画のダイアログに戻ります（強制push が必要になったため）。
- **グループを中止**（確認あり。`Git: グループPushを中止`）は、実行が開始した merge または rebase を破棄し、その実行を忘れます。完了済みの push はそのまま残ります。

ストリップは GitPoulpi を再起動しても残り、CLI からも同じ保存済みの実行が見えます。

## pull する

- **Pull** ボタンは、ブランチに pull 元がなければこれまでどおりアップストリームを pull します。pull 元があれば、アップストリームとすべての pull 元を順に、設定の **Pullボタン**のモード（merge、fast-forward only、rebase）で pull します。早送りできない pull 元は、アップストリームと同じように merge（または rebase）されます。fast-forward only のときは、それ以上が必要な pull 元について先に確認します。
- **Pull ▾** には、pull 元があるときに `すべてのソースからPull（origin + gitlab）` が、ブランチの各リモートについて `<リモート> のみからPull` が加わります：チェックボックスにかかわらず、そのリモートのブランチを 1 回だけ pull します。
- パレットには `Git: すべてのソースからPull` と `Git: 1つのリモートからPull...` があります。
- 競合で止まった pull も、グループの pull であることを示す同じストリップを残します。

## 設定

4 つとも **設定 > Git とエンコード**にあります。

| 設定 | 既定 | 意味 |
|---|---|---|
| **Pushボタン** | direct | direct はすぐに push し、ask は先に Push メニューを開きます。 |
| **Pullボタン** | merge | Pullボタンのモード（merge、fast-forward only、rebase）。pull 元にも適用されます。 |
| **pushの前にすべてのリモートを確認** | オン | グループの push の前にすべてのリモートを調べます（CLI もこれに従います。`--no-preflight` で 1 回だけオフにできます）。 |
| **新しいブランチの追加push先**（リポジトリ別） | なし | 新しいブランチが追加で push するリモート。 |

## コマンドラインから

```
gitpoulpi branch upstream add gitlab --pull      # pull 元でもある push 先
gitpoulpi branch upstream list                    # ブランチの設定内容
gitpoulpi push --all-targets                      # アップストリームとすべての push 先
gitpoulpi push --to gitlab --to backup:feat-x     # 今回はこれらだけ
gitpoulpi pull --all-sources                      # アップストリームとすべての pull 元
gitpoulpi remote-group plan                       # グループの push の内容。何も変更しない
gitpoulpi remote-group continue                   # 停止を解決して完了したあと
```

リモートが判断を必要とするときは、コマンドが計画を返し（終了コード 3）、何も変更しません。`--resolve gitlab=merge` で答えます。すべてのフラグは [CLI リファレンス](cli-reference.md)を参照してください。MCP サーバーにも同じツールがあります。

## 素の git で

push 先は単なる設定キーなので、スクリプトやエイリアスから GitPoulpi なしで使えます：

```
git config --get-all branch.feature.gitpoulpi-push-to     # 1 行に 1 つの値：remote または remote:branch

# 現在のブランチをアップストリームとすべての push 先に push する
git config alias.pushall '!b=$(git symbolic-ref --short HEAD); git push; for t in $(git config --get-all branch.$b.gitpoulpi-push-to); do r=${t%%:*}; d=${t#*:}; [ "$d" = "$t" ] && d=$b; git push "$r" "$b:$d"; done'
```

値は `<remote>`（同じブランチ名）または `<remote>:<branch>` で、`d=${t#*:}` の行がそれを振り分けています。この素のエイリアスは、先にリモートを調べず、merge も提案せず、競合のあとに続行することもできません：それがダイアログの役目です。

## 知っておくと便利なこと

- 同じアドレスを指す 2 つのリモートは検出されます（「gitlab と mirror は同じ URL にpushします」）。2 つ目は既定でスキップされます。
- 保護されたブランチを持つホストは強制push を拒否します：その行にそう表示され、選べるのはスキップだけです。
