# pull request / merge request のレビュー

pull request（GitHub、Gitea、Forgejo）、merge request（GitLab）、Gerrit のチェンジ（[Gerrit](#gerrit)を参照）を、
**リポジトリのウィンドウを離れずに**レビューできます。レビュー画面には、説明、会話、コメントのスレッドが行の下に並んだ変更ファイル、
commit が表示され、コメント、承認、変更の要求といったレビューの内容もここで書きます。これらのホストのいずれかのプロファイル
（[ホスティングと Issue トラッカーの連携](hosting-integration.md)を参照）と、それにリンクされたリポジトリが必要です。
それ以外のプロバイダーはレビューに対応していません。ホストの制約は守られます。GitLab には**変更を要求**の判定がなく、
1 つのコメントに付けられる行は 1 行だけです。このページでは、これらすべてを*リクエスト*と呼びます。

## レビューを開く

どの入口から入っても、同じ画面が開きます。

- サイドバーの **PULL REQUESTS** の一覧：行を選んで **Enter** を押すか、右クリックして**レビュー...**を選びます。
- **Radar**：行のメニューの**レビュー...**、または `e` キー（リポジトリが開き、続けてレビューが開きます。クローンしていない
  リポジトリのリクエストでは、クローンするか API 経由でレビューするかを尋ねられます。
  [クローンなしのレビュー](#クローンなしのレビュー)を参照）。
- **ワークスペース検索**（`Ctrl+Alt+F`）：pull request または merge request を選んで **`Alt+R`** を押します。
- パレット：**ホスティング: リクエストをレビュー...** で、選べるリクエストの一覧が表示されます。

画面はリポジトリの上でウィンドウ全体に広がります（別ウィンドウではなく、リポジトリのタブのモードです）。
**`Esc`** または右上の `✕` で閉じます。開いている間、バックグラウンドでホストからリクエストを読み取り、そのコードを git で
取得します。少し時間がかかるときはスピナーが表示されます。

## ヘッダー

常に表示されるのは、番号とタイトル、状態（Open、Draft、Merged、Closed）、ブランチ（`main ← feature/moons`）、作成者、
チェック（`✓ チェック合格`、`✗ チェック失敗`、`● チェック実行中`）、きれいにマージできるか競合するか、サイズ、
そしてコメントを書いた場合の **`保留中のコメント 3 件`** です。

4 つのメタデータのボタン、**担当者**、**レビュアー**、**ラベル**、**マイルストーン**は、サイドバーと同じピッカーを開きます
（[担当者、レビュアー、ラベル、マイルストーン](hosting-integration.md#担当者レビュアーラベルマイルストーン)を参照）。
ホストが受け付けるとすぐに、ヘッダーに結果が反映されます。操作のボタンは、**チェックアウト**（リクエストのブランチの
通常のチェックアウトで、画面も閉じます）、**ブラウザーで開く**、**更新**（**`F5`**）、**レビューを完了**です。

## 3 つのページ

上の枠にあるセグメントコントロールでページを切り替えます。**概要**、**ファイル**、**Commits**
（**`Alt+1`**、**`Alt+2`**、**`Alt+3`**、またはクリック）です。

### 概要

概要は**リクエストの会話**です。Issue にあるのと同じタイムラインと同じコメントボックスです（[会話](hosting-integration.md#5c-会話)）。最初に説明（*がこれを作成しました*）、続いてコメント、差分の抜粋付きのコードへのスレッド、判定付きの送信済みレビュー（`承認`、`変更を要求`、`コメント`、`却下`。GitLab では判定は承認です）、イベントが古い順に並び、最新のウィンドウが表示されて、その上端に**古いものを読み込む**があります。コメントボックスはタイムラインの下に固定されています（**新規コメント**）：**編集**、**プレビュー**、**分割**、**キャンセル**、**送信**。**ここで書いたコメントはすぐにホストへ送られます**（保留中のものはありません。保留中のコメントはコードへのコメントで、レビューと一緒に送られます）。一覧にはすぐ追加され、ホストが応答すると正式な位置に収まります。ホストが拒否した場合は、ボックスがあなたのテキストと理由つきで再び開きます。

キーは会話ビューと同じです：**`Up`** / **`Down`**（と `Ctrl+J` / `Ctrl+K`）で項目間を移動し、**`r`** は選択した項目のスレッドへの返信、**`Q`** は引用して新規コメント、**`c`** は新規コメント、**`e`** / **`d`** は自分のコメントの編集と削除（削除の前には確認があります）、**`l`** または `Enter` は項目のリンク、**`g`** はその図、**`y`** はそのアドレスのコピー、**`o`** はブラウザーで開く、**`n`** は次の新着項目、**`v`** はイベントの表示／非表示、**`m`** は古い項目の読み込み、`Tab` はタイムラインとボックスの間の移動、**内部メモ**（`Alt+I`）はそのようなメモのあるホストにあります。選択した項目のボタン（**返信**、**引用**、**編集**、**削除**、**リンク**）も同じ動作で、パレットには*レビュー: ...* の行と並んで*会話: ...* の行があります。リンクは、レビューのほかの場所と同じく、開く前に確認されます。

コードのスレッドは `path:line` をリンク（下線付きの実際のボタン）として表示します。それをクリックするか、選択したスレッドで **`G`** を押すか、パレットの*会話: スレッドのコードを開く*を使うと、**ファイル**ページに切り替わり、そのファイルが開いて、コメントされた行（書かれたとおりに旧側または新側）にカーソルが置かれ、その下にスレッドが開きます（折りたたまれていれば展開されます）。**Esc**、ページタブの左にある**概要へ戻る**ボタン、または*レビュー: 概要のコメントに戻る*で、概要の同じ項目に戻ります。行が差分からなくなったスレッド（古いもの）は、最も近い行でファイルが開き、ステータス行でそう伝えます。リクエストがもう変更していないファイルのスレッドは、そのファイルが差分に含まれていないと伝えます。同じリクエストの Issue や Radar のビューには開けるコードがなく、`G` はレビューにあると答えます。

会話のキーとレビューのキーが重なるときは、このページでは会話の文字が優先されます：`l`（ラベル）、`m`（マイルストーン）、`Q`（Gerrit の abandon）、`e` / `d`、`r` です。ラベル、マイルストーン、abandon はヘッダーのボタンとパレットに残り、`a`（担当者）、`p`（レビュアー）、`f`（**レビューを完了**）、`b`（**チェックアウト**）、`P`、`D`、`U`、`Alt+1` / `Alt+2` / `Alt+3` はここでも意味が変わりません。ボックスにキーボードがあるあいだは、`Alt+1` / `Alt+2` / `Alt+3` を除くすべてのキーがボックスのものになり、`Esc` でキーボードがタイムラインに戻り、もう一度 `Esc` を押すとレビューが閉じます。

別のウィンドウや CLI で書かれたコメントは、ここに自動で表示されます。GitPoulpi のすべての書き込み（このウィンドウのものを含む）がセッションに知らされ、同じリクエストを表示しているウィンドウがそれを読み直します。

コメントボックスは[会話ビュー](hosting-integration.md#書き込み)と共通の Markdown エディターです（スレッドへの返信、行へのコメント、**レビューを完了**の要約のボックスも同じ）。`Ctrl+Enter`（`Ctrl+S`、`Alt+Enter` も可）で送信し、AI がオンなら `Alt+E` で**AI で作成**を開きます（[AI の章](ai.md#ホストでの作成補助)）。プレビューには、参照（`#7`、`!12`、`ABC-12`、commit ID）を含め、ホストでの見た目どおりにテキストが表示されます。送信していないテキストはリクエストごとに保持されます。

### ファイル

左に変更ファイルが並び（状態の文字、`+追加 -削除`、未解決のスレッド数 `●n`、保留中のコメント数 `✎n`）、
右に選択したファイルの差分が表示されます。差分は git から得られます。リクエストの head は `refs/gitpoulpi/pr/<n>` に取得され
（ブランチにはならず、何もチェックアウトされません）、マージベースと比較されるため、余白の行番号はコメントが使う行番号と
完全に一致します。

- **ファイルの前の `[ ]`**：*閲覧済み*にします（クリック、または一覧で **`v`** / `Space`）。タイトルに件数が表示されます。
  閲覧済みの印はリポジトリごとに保存され、再起動後も残ります。
- **スレッド**は該当する行のすぐ下に表示されます：最初のコメント、返信、そして**返信**と**解決** / **再開**のボタンです。
  解決済みのスレッドは 1 行に折りたたまれます。**`z`**（またはそのスレッドで `Enter`、`▾` のクリック）で、
  どのスレッドも折りたたみ／展開できます。
- **古いスレッド**と、差分に表示されない行のスレッドは、ハンクの後ろの*表示中の行の外にあるコメント*に一覧表示され、
  コードが変わった場合は `古い` のバッジが付きます。
- **`c`** はカーソルのある行にコメントします（行頭の小さな `+` もマウスで同じ操作ができます）。
  **`Shift+Up` / `Shift+Down`**（または行の上でのドラッグ）で先に複数行を選ぶと、コメントはその範囲に付きます。
  GitLab は 1 つのコメントに 1 行しか付けられないため、ビューは行を選択せずにそう伝えます。
- **`r`** はカーソル位置のスレッドに返信し、**`x`** は解決または再開します。どちらも**すぐに**ホストへ送信されます。
- キー：`Up` / `Down` / `PgUp` / `PgDn` / `Home` / `End` で移動します。ファイル一覧から差分へは `Tab`、`Right`、`Enter`、
  差分から戻るには `Left` と `Tab` を使います。`]` と `[` で次のファイルと前のファイルへ移動します。

### 差分の表示オプション

**ファイル**と **Commits** の差分ペインは、[Diff ビュー](staging-and-committing.md)そのものです。最初の行に同じバーがあり、
選んだ内容も同じように記憶されます（設定は共通で、ここで選んだものが Diff ビューの開き方になり、その逆も同様です）。

- **インライン / 分割**：1 列で表示するか、変更前と変更後を左右に並べます。分割表示では、スレッド、保留中のコメント、提案は
  それが属する側の下に表示されます。削除された行へのコメントは左側の下、追加された行や変更のない行へのコメントは右側の下です。
  削除と追加が並ぶ行で **`c`** を押す前に、対象にしたい側をクリックしてください。キーボードでは新しい側にコメントします。
- **ハンク**：変更とその前後の文脈だけを表示するか、変更を所定の位置に置いたままファイル全体を表示します。ファイル全体の表示では、
  変更の外にある行のスレッドは、*表示中の行の外にあるコメント*ではなく、その行の下に表示されます。
  ファイルのテキストはバックグラウンドで読み込まれ、届くまでハンクはその旨の 1 行とともに画面に残ります
  （Commits ページでは、commit のうち最大 40 ファイルがこの方法で読み込まれます）。
- **WS**：空白のみの違いの変更を表示または無視します。
- **折返**：長い行を折り返します。
- **上下の矢印**：前のハンクと次のハンク。
- **Map**（**`M`**）：スクロールバーの横のミニマップで、設定は Diff ビューと共通です。クリックまたはドラッグでスクロールします。
- **自動**（**`E`**、または*レビュー: 文字コードを選択...*）：ファイルを読み込む文字コードで、Diff ビューと同じです。
  自動検出、または一覧にある文字コードのいずれかを、ペインが表示しているファイル（Commits ページではカーソル位置のファイル）に対して
  選びます。ファイルの両側がその文字コードでバックグラウンドで読み込み直され、同じパスについての選択は Diff ビューと共有されます。
  その方法で読み込めないファイルは、差分の上にその理由が表示されます。
- **`⋯`**：ペインが狭くてすべてのボタンが入らない場合、収まらないものはバーの端の `⋯` の中にまとめられます。
  その一覧から、クリックしたときと同じように実行できます。キーとパレットの行は従来どおり使えます。

スクロールバーのルーラーには、変更（ファイル全体表示のみで、Diff ビューと同じ）、スレッド・保留中のコメント・提案ごとの
ドット `●`、そしてカーソルの位置が示されます。

長い行はペインの端で切れます（全体を見るには**折返**をオンにします）。横にもスクロールできます：差分上の **`Right`** と
**`Left`**（左端での `Left` はファイル一覧に戻ります）、横方向のホイールまたは `Shift` とホイール、下の枠に沿ったスクロールバー、
または*レビュー: 差分を左／右にスクロール*です。

### テキストと行の選択

ドラッグを始めた場所によって、選択されるものが変わります。**コード上**で始めたドラッグはテキストを選択します（Diff ビューと同じで、
ダブルクリックで単語を選択）。**`Ctrl+C`**（または*レビュー: 選択したテキストまたは行をコピー*）は、行番号やマーカーなしで
その文字だけをコピーし、テキストを選択していないときはカーソル位置の行をコピーします。**ガター**（行番号、マーカー、`+`）で始めた
ドラッグは行を選択し、従来どおりその行にコメントできます。ガターでのダブルクリックも、その行へのコメントの開始です。

Diff ビューのキー `n`、`p`、`m`、`w`、`s` はレビュー自身のキーとして使われるため、レビューでの切り替えは大文字です：
**`V`** レイアウト、**`H`** ハンクまたはファイル全体、**`S`** 空白、**`W`** 折り返し、**`J`** / **`K`** 次と前のハンク、
**`E`** 文字コード、**`M`** ミニマップ。すべてにパレットの行があります（*レビュー: レイアウトを切り替え（インライン／分割）*など）。

### Commits

リクエストの commit のみ（その背後の履歴ではありません）が新しい順に並び、選択した commit の差分（その親に対する変更）が
すべてのファイルを上下に並べて表示されます。表示オプションは同じです。

## レビューを書く

コードへのコメントは**保留中**になります。コメントはユーザーのマシン上（リポジトリの状態ファイルの中）に保存されるため、
再起動後も残り、ヘッダーに件数が表示されます。レビューを完了するまで、何も送信されません。保留中のコメントは、行の下に
`保留中 - 12 行目` のバッジと 2 つのボタン、**`e`**（編集）と **`d`**（削除）で表示されます。

**レビューを完了**（**`f`**、ボタン、またはパレット）は小さなフォームを開きます：要約（省略可）と **判定** の一覧
（*コメント*、*承認*、*変更を要求*）です。ホストが許可するものだけが一覧に出ます。GitLab には*変更を要求*がありません。
**レビューを送信**（`Ctrl+S`）は、要約、判定、保留中のすべてのコメントを一度に送信します。**レビューを破棄...**は、確認の後に
保留中のコメントを捨てます。

レビューを待たずにすぐ送信されるのは、返信、解決と再開、そして会話へのコメントです。コメントのボックスに、どちらの種類かが
表示されます（*このコメントはすぐに投稿されます*、または*このコメントは、レビューを完了するまで保留中のレビューに追加されます*）。
ホストが返信を拒否した場合、ボックスは入力した内容のまま再び開きます。

保留中のコメントを書いた後でリクエストに新しい commit が加わった場合、その行が移動しているかもしれないと画面が警告します
（GitHub と GitLab は、読んだ commit にコメントを付けます。古い head に対するレビューは拒否されます）。

## Gerrit

Gerrit サーバーは、ほかのホストと同じように接続し（[ホスティングと Issue トラッカーの連携](hosting-integration.md)を参照：
サーバーの URL、ユーザー名、HTTP パスワード）、**PULL REQUESTS** で*プロジェクト*にリンクします。そのチェンジは pull request
として一覧表示され（`#7`、チップ `GR`）、同じ画面でレビューされます。Gerrit ならではの違いは次のとおりです。

- **パッチセット**：チェンジには番号付きのパッチセットがあります（commit をアップロードするたびに 1 つ増えます）。ヘッダーの
  上の枠、ページのタブの隣に **`パッチセット N`** のコンボボックスがあります（**`P`**、またはパレットの*レビュー: パッチセットを
  選択...*）。最新のものが選ばれた状態で開き、別のものを選ぶとそのパッチセットのファイルとコードを読み込み、ほかのパッチセットに
  書かれたスレッドは*古い*ものとして一覧表示されます。完了するレビューは、表示中のパッチセットに対して送信されます。
- **別のパッチセットと比較する。**その左にある 2 つ目のコンボボックス **`比較：ベース`**（**`D`**、またはパレットの*レビュー: パッチセットを比較...*）には、ベースと、表示中のものより古いすべてのパッチセットが並びます。パッチセット 3 を表示中にパッチセット 1 を選ぶと、ファイルページには、パッチセット 1 以降にパッチセット 3 で変わったものだけが一覧され、diff も表示されます（サーバー自身の差分なので、新しいターゲットへのリベースは変更として現れません）。commit ページにはその 1 つの差分が表示されます。両方のパッチセットは `refs/gitpoulpi/pr/<n>` と `refs/gitpoulpi/pr/<n>-ps<k>` に取得されます。表示中のもの以外のパッチセットに書かれたスレッドは*古い*ものになります。比較中のものより古いパッチセットを読み取り用に選ぶと、比較はベースに戻ります。CLI の対応は `review show|fetch --compare-with K` です。
- **サブミットと放棄。**サーバーがチェンジをサブミットできると示している場合（必要な投票とチェックがそろっている）、ヘッダーのボタンに **サブミット** ボタンが加わります。チェンジを放棄できる間は **放棄** ボタンがあります。どちらも（キーは **`U`** と **`Q`**、パレットは*レビュー: チェンジをサブミット...* / *レビュー: チェンジを放棄...*）まず確認のポップアップを表示し、操作はサーバー上で行われ **GitPoulpi からは元に戻せない**ことを伝えます（マージされたチェンジはマージされたままで、放棄したチェンジは Gerrit の Web インターフェースで復元できます）。キャンセルすると何も送信されず、成功するとビューはチェンジを読み直します。CLI の対応は `gitpoulpi hosting review submit-change <n>` と `hosting review abandon <n> [--message M]` です。
- **判定の代わりに投票**：**レビューを完了**には、投票できるラベルごとにコンボボックスが 1 つ表示されます。`Code-Review`（-2 から +2）と、
  プロジェクトにあれば `Verified` で、**このチェンジとユーザー本人**にサーバーが許可する値だけが並びます（権限のない開発者は +2 を
  選べません）。現在の投票が選ばれた状態で始まり、変更した投票だけが送信されます。要約と保留中のコメントは同じ呼び出しで送られます。
  Gerrit の Web インターフェースで保存した下書きは、レビューと一緒に公開されます。
- **スレッド**は Gerrit のコメントチェーンです。最新のコメントが `unresolved: false` となっているスレッドは解決済みです。
  **解決**は `Done` という返信を投稿してそうし、**再開**は `Reopened` という返信を投稿します。返信と解決は、ほかのホストと同様に
  すぐにサーバーへ送られます。
- **レビュー用の push**：Gerrit は `refs/for/<branch>` に push するとチェンジを作成します。PULL REQUESTS セクションが Gerrit の
  プロジェクトにリンクされていれば、セクションの **`+`** ボタンとパレットの行 **ホスティング: レビュー用にPush...** が
  ターゲットブランチを尋ね、`HEAD` を `refs/for/<branch>` に push します（トピックはコマンドラインで指定できます）。この push は
  GitPoulpi からは元に戻せません（Gerrit でチェンジを abandon してください）。メッセージにもそう表示されます。CLI での対応コマンドは
  `gitpoulpi hosting review push` です。
- メタデータのボタンは Gerrit では読み取り専用で（レビュアーは表示されます）、*変更を要求*の判定はありません（-1 または -2 の投票が
  同じ意味です）。チェックのチップは `Verified` ラベルです。

## ✦ AI によるレビューのドラフト

![ファイルページの行の下に表示された 2 つの ✦ の提案。それぞれに採用、編集、却下があり、既存のスレッドと並んでいる](../images/review-ai.png)

AI をオンにすると（*設定 > AI*、[AI](ai.md)を参照）、ヘッダーに **`✦ ドラフトを作成...`** のボタンが表示されます（**`s`** や、
パレットの行*レビュー: ✦ レビューのドラフトを作成...*でも実行できます）。ボタンは[レビューオプション](#レビューオプション)を開き、
そこで **`Enter`** を押すとモデルに問い合わせます。モデルに問い合わせるのはこれだけで、レビューを開いただけでは
問い合わせません。モデルはリクエストのタイトルと説明、すでにあるコメント（繰り返さないようにするため）、そして差分を読み、
**レビューのドラフト**を返します：送信する本文、推奨する判定（承認、変更を要求、コメントのいずれか）、全体の要約、
提案するコメントの一覧です。長い差分はモデルに渡す際に、ファイルごと、また全体で短縮され、概要ページには
短縮されたファイルや除外されたファイルの数が表示されます。処理中は、少し経つとステータスバーにスピナーが表示され、**`Esc`**
（または同じボタン）でキャンセルできます。[4 つのレベル](ai.md#指示)の*コードレビュー*の指示が適用されるため、チームや
ワークスペースで、よいレビューとは何かを指定できます。

### レビューオプション

`s` は **✦ レビューオプション**のダイアログを開きます。リポジトリの既定値（リポジトリに設定がなければ全体の既定値）が入力済みです。
`Enter`（または**実行**ボタン）で、ダイアログに表示されている内容で実行を開始します。`Esc`、**キャンセル**、または×で閉じ、
何も問い合わせません。

| コントロール | 動作 |
|---|---|
| **エージェントをリポジトリ内で実行** | *プロファイルの設定*（AI プロファイルの作業フォルダーに従う）、*はい*、*いいえ*。HTTP プロファイル（作業フォルダーがない）の場合や、クローンなしで API 経由でレビューしている場合は、理由が下に表示されてグレー表示になります。 |
| **CLAUDE.md**、**AGENTS.md** | リクエストの対象ブランチで読み取ったリポジトリのそのファイルをモデルに渡します。エージェントがリポジトリ内で実行される場合は自分で読み込むため、ダイアログにそう表示されます。 |
| **追加ファイル** | 追加ファイル1つ：リポジトリ内のパス、絶対パス、またはコードホスト上のファイルへのリンク。**参照...**（`Ctrl+B`、またはボタン上で `Enter`）はファイルピッカーを開きます。ピッカーはリポジトリのルート（すでに指定されたファイルがあればその隣）から始まり、リポジトリ内のファイルはルートからの相対パス、外のファイルは絶対パスで書き込まれます。フィールドへの入力はこれまでどおり使えます。 |
| **追加ファイルなし** | 今回の実行では、全体の設定やリポジトリが追加ファイルを指定していても、追加ファイルを渡しません。ファイルを入力するか **参照...** で選ぶとチェックが外れます。**このリポジトリの既定値として保存**と併用すると、リポジトリの*追加ファイルなし*スイッチになります。ダイアログは実行が継承する値から始まるため、ここでは空のフィールドは「なし」として扱われます。 |
| **このリポジトリの既定値として保存** | 次回以降のレビューのために値も保存します：リポジトリの状態ファイルに、クローンしていないリポジトリでは `remote-reviews.toml` に保存されます。全体の値と異なる値だけが保存されるため、残りは引き続き*設定 > AI* に従います。 |

すべて `Tab` で移動でき、`Space` でチェックボックスを切り替え、パスのフィールドは通常のテキストフィールドです。同じ 4 つの設定は
*設定 > AI*（*コードレビュー*）と*リポジトリ固有の設定 > AI* にもあります。[レビューのコンテキスト](ai.md#レビューのコンテキスト)を
参照してください。モデルに渡せなかったもの（存在しない、または読み取れない追加ファイル）や、上限に収まるよう短縮されたファイルは、
ドラフトのカードに一覧表示されます。

提案は**コメントではありません**。2 か所に表示されます。

- **ファイルページの該当行の下**：`✦` の付いたゴーストコメントとして、重要度（`情報`、`警告`、`問題`）と、3 つのボタン
  **採用**、**編集**、**却下**が付きます。差分に表示されない行についての提案は、捨てられずに保持されます。ハンクの後ろの
  *ファイル全体についての AI の提案*に一覧表示され、採用すると、ファイルの最初の変更行に*（N 行目付近）*という言葉を先頭に付けて置かれます。
- **概要ページ**の会話の上のブロック（実行後のみ）：要約と、同じボタンと **すべて採用** / **すべて却下** を備えた一覧です。

**採用**（`y`）は、提案を通常の**保留中のコメント**に変えます（その後も編集や削除ができます）。**編集**（`w`）はモデルの文面を
先頭にしてコメントのボックスを開き、残した内容を採用します。**却下**（`n`）は提案を捨てます。**すべて採用**（`A`）も、
保留中の一覧に追加するだけです。ファイルページではキーはカーソル位置の提案に、概要ページでは一覧の先頭に作用します（一覧が空になると、`y` と `n` は会話の*リンクをコピー*と*次の新着*に戻ります）。
**AI の要約を使用**（`i`、またはレビューを完了するフォームのボタン）は、モデルの要約をレビューの本文に入れます。自動では挿入されません。
**レビューを送信するまで、ホストには何も送信されません。**

概要ページには、そのブロックの先頭の提案の上に、ドラフトがカードとして表示されます：判定のチップ、レビューの本文、3 つのボタンです。

- **✦ ドラフトを使用...**（`u`）は、未処理の提案をすべて保留中のコメントとして採用し、ドラフトの本文と判定が入力済みの
  *レビューを完了*を開きます。内容を読み、変更し、送信するのはあなた自身です。フォームをキャンセルしてもドラフトは残ります。
  ホストの制限は守られます：GitLab には*変更を要求*がないため、フォームがそう表示して*コメント*に切り替えます。Gerrit では、
  サーバーがあなたにその値を許可している場合に限り、判定は +1 または -1 の Code-Review 投票になります（許可されていなければ
  投票は設定されず、フォームがそう表示します）。
- **本文を編集...**（`t`）は、使う前にドラフトのレビュー本文を変更します。
- **ドラフトを破棄**（`N`）は、本文、判定、残りの提案をすべて捨てます。

ドラフトはリクエストごとに保持されるため、レビューを閉じて開き直しても残っています。モデルが書いた後でリクエストの
head が動いた場合、カードに*このドラフトの作成後にリクエストが変更されました。*と表示されます。レビューを送信すると、ドラフトは使用済みになります。

## クローンなしのレビュー

マシン上にないリポジトリのリクエストでも、レビューできます。Radar でその行の**レビュー**（`e`）を押すと方法を尋ねられ
（[Radar](radar.md#リクエストのレビュー)を参照）、**API 経由でレビュー**を選ぶと、この同じ画面がホームウィンドウの
Radar の上に開きます。このページの内容はすべて同じように使えますが、次の違いがあります。

- コード（変更されたファイル、各ファイルの差分、リクエストの Commits、コミットの差分、ファイル全体）はホストの API から
  読み取られるため、大きなリクエストを最初に開くときは少し時間がかかります。ホストが差分を送らないファイル（バイナリや非常に大きいもの）
  は、差分の代わりにその旨が表示されます。
- 保留中のコメントは、リポジトリ自身の状態ではなく、設定フォルダーの `remote-reviews.toml` に、ホストとプロジェクト（`host/project`）
  ごとに保存されます。レビューを閉じて開き直しても残っており、レビューを送信すると使用済みになります。
- 文字コードの選択はできず（*クローンがないと利用できません*）、**チェックアウト**もありません（先にリポジトリをクローンするよう表示されます）。
- `Esc` または隅の `✕` で画面を離れ、Radar に戻ります。パレット（`Ctrl+P`）は、リポジトリのタブと同じようにこの画面の行に作用します。

クローンを残したい場合は、**クローンしてからレビュー**（またはパレットの *Radar: クローンしてレビュー...*）を選びます。
クローンのダイアログがリクエストの接続済みアカウントで開いてリポジトリが選択され、クローンが完了すると、新しいリポジトリのタブでレビューが開きます。

## コマンドラインとエージェントから

同じレビューを `gitpoulpi hosting review show|threads|comment|reply|resolve|submit|fetch|suggest`
（およびそこから作られる MCP ツール）で実行できます。[CLI リファレンス](cli-reference.md)を参照してください。`threads` は
送信済みの判定（`reviews`）も一覧表示します。`suggest <n>` はモデル（AI オン）に問い合わせ、何も投稿せずに `verdict`、`body`、要約、提案を JSON で
出力するため、スクリプトやエージェントが `submit --comment` に渡すコメントを選べます。

どれもクローンは不要です：`--project owner/name`（複数の連携が設定されている場合は `--id` も）を付けると、`show`、`threads`、
`comment`、`reply`、`resolve`、`submit`、`suggest` を、カレントディレクトリが何も知らないプロジェクトに対して実行します。
`hosting review diff <n>` はハンク付きの diff を出力し（`--api` を付けるとクローン内でもホストから読み取ります）、
`hosting file <path> --project P [--ref R]` は指定リビジョンのファイル、たとえばプロジェクトの `CLAUDE.md` を読み取ります。
どちらもホストの API を読み取ります：GitHub、GitLab、Gitea、Forgejo、Gerrit。
