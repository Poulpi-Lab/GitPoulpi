# 検索

`Ctrl+Alt+F`（または `Ctrl+P` の後に `検索: ワークスペース...`）で、**作業中のすべてのリポジトリ**を対象とするあいまい検索が開きます。
対象は、[ワークスペース](workspaces.md)が有効ならそのワークスペースのリポジトリ、そうでなければ開いているタブです。**全体検索**ボタン（タイトルバーの歯車のすぐ左にある虫眼鏡とラベル）でも開きます。検索できるものは次のとおりです。

- **リポジトリ**（名前、次にパスで）
- **ブランチ**（ローカルとリモート追跡）と **tag**
- **worktree**（フォルダー、次にパスとブランチで）
- **stash**（メッセージで）
- **commit**（件名で。commit の本文は、件名が一致せず、3 文字以上を入力したときだけ検索されます）
- **pull request または merge request** と **Issue**（タイトル、`#番号`、作成者、ブランチで）

![開いている 2 つのリポジトリの上に表示された検索ポップアップ：「main」に一致するブランチ、stash、commit が並び、それぞれ右側にリポジトリ名が表示されている](../images/workspace-search.png)

結果は種類ごとにグループ化され、各グループの中では一致度の高いものが先頭に並びます。各行には、種類のアイコン、
強調表示された一致文字、淡色の詳細（ブランチのアップストリーム、リクエストの作成者とブランチ、stash の位置）、
そして右側にリポジトリ名が表示されるので、`main` ブランチを持つ 2 つのリポジトリが混同されることはありません。
リポジトリがまだ commit のインデックスを作成中のとき（大きなリポジトリでの最初の検索は少し時間がかかることがあります）は、
タイトルにスピナーが表示されます。ほかの種類はすぐに表示され、commit は準備ができ次第加わります。

## 移動する

| キー | 動作 |
|---|---|
| `Up` / `Down`、`Ctrl+P` / `Ctrl+N`、`PageUp` / `PageDown`、`Home` / `End` | 結果の間を移動します（グループの見出しは飛ばされます）。 |
| `Enter` | 結果へ移動します。リポジトリのタブが開き（または切り替わり）、その結果が表示されます。 |
| `Esc` | 検索を閉じます。 |
| `Alt+1` から `Alt+8` | 種類のオン / オフを切り替えます（一覧の上のチップ。その順序のとおり）。`Alt+0` ですべてオンになります。 |

「移動する」の意味は次のとおりです。

| 結果 | Enter の動作 |
|---|---|
| ブランチまたは tag | Refs ペインでそれを選択し、ログでその commit を選択します。 |
| commit | ログでそれを選択します。読み込み済みの範囲より古い場合は、先にログをさらに読み込みます。 |
| stash | STASHES セクションの該当行を選択します。 |
| worktree | タブとして開きます。 |
| pull request / merge request、Issue | サイドバーの該当行を選択します（そのリポジトリのタブで）。 |
| リポジトリ | そのタブに切り替えます（開いていなければ開きます）。 |

`Ctrl+N Backspace`（またはパレットの `戻る`）で、エージェントによるビューの変更と同じように、元の場所に戻れます。
どこかに移動しても、チェックアウト、merge、変更は一切行われません。

マウスでは、行のクリックで選択、ダブルクリックで移動、チップのクリックでその種類のオン / オフ、ホイールでスクロール、
ポップアップの外側のクリックで閉じます。

## プレフィックスで絞り込む

クエリの先頭にプレフィックスを付けると、チップの状態に関係なく、その種類だけが検索されます。

| プレフィックス | 種類 |
|---|---|
| `r:` | リポジトリ |
| `b:` | ブランチ |
| `t:` | tag |
| `w:` | worktree |
| `s:` | stash |
| `c:` | commit |
| `pr:`（または `mr:`、`p:`） | pull request または merge request |
| `i:` | Issue |
| `#` | pull request / merge request と Issue（`#12` で番号 12 が見つかります） |

`fix: login` は通常のクエリであり、プレフィックスではありません。プレフィックスとして扱われるのは、1 文字だけ
（または `pr:` / `mr:`）の後にコロンが続くもの、または先頭の `#` だけです。

## 一致のしかた

コマンドパレットと同じ 3 つの段階です。入力した文字列そのまま、次にそのままどこかに含まれるもの、最後に文字が順序どおりに
（離れていても）含まれるものです。一致位置が先頭に近いほど、また文字列が短いほど優先されます。大文字と小文字は区別されません。

## pull request と Issue

これらは、GitPoulpi が各リポジトリについてすでに読み込んだもの（サイドバーの PULL REQUESTS と ISSUES セクションの一覧）から取られ、
リポジトリの `.gitpoulpi/` フォルダー内の小さなキャッシュファイルに保存されています。検索が **GitHub や GitLab に問い合わせることは一切ありません**。
ウィンドウでリクエストを一度も読み込んだことのないリポジトリには、見つかるものがなく、表示される内容はサイドバーの最後の更新と同じ新しさです。
リンクされたアカウントがなければ、見つかるものはなく、設定するものもありません。

## コマンドラインから

`gitpoulpi search <query> [--workspace ID] [--kind K]... [--limit N]` は同じ検索を行い、JSON を出力します
（[CLI リファレンス](cli-reference.md#ワークスペースと検索)を参照）。MCP サーバーには `search` ツールがあり、エージェントもユーザーと同じものを探せます。
[設定](config-reference.md#searchワークスペース検索)の `search.commit_limit` は、各リポジトリでインデックスに入れる commit の数を制限します
（`0` で commit 検索がオフになります）。

## キーを変更する

`検索: ワークスペース...` はパレットのコマンドで、キーは `global.workspace_search` アクションです。設定 > キーボードとマウスで再割り当てするか、
`[keybindings.global]` テーブル（`workspace_search = "Ctrl+Alt+F"`）で変更できます。
