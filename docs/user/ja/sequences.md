**シーケンス**は、順に実行されるコマンドの名前付きの一覧です。たとえば
*すべての変更をステージ*、*AI: commit メッセージを生成*、*Commit*、*Push* を、
**バックアップ**という 1 つのキーにまとめられます。各ステップは
[コマンドパレット](keybindings.md)のコマンドです。シーケンスはそれ自身がパレットの行
（`シーケンス: <name>`）になり、キーに割り当てられ、**設定 > シーケンス**
または `config.toml` で編集します。

## シーケンスのページ

**設定 > シーケンス**は[リストページ](settings.md#リスト)です：左にシーケンス、右に選択中のシーケンスの行が並びます。
すべての変更はすぐに反映されて書き込まれ、パレットとキーマップは再起動なしで追従します。

```
 Sequences
+- Sequences -------------+  Editing sequence 1/2
| This installation       |  Name         Backup
| > Backup        Alt+B   |  Id           backup
|   Worktree and agent    |  Description  Stage everything, ...
| This repository         |  Scope        This installation
|   Release               |  Shortcut     [ Alt+B ] [ Clear ]
+-------------------------+  Steps        Stage all > AI: ... > Commit > Push
| [+ Add v] [Dup] [Remove]|              [ Edit steps (4) ] [ Run now ]
| [Up] [Down]             |
+-------------------------+
```

* **+ 追加**は、**空のシーケンス**と 3 つのプリセット、**プリセットから ▸ バックアップ**、
  **分割して push**、**Worktree とエージェント**を提示します。プリセットは出発点です：
  追加するまでは何も有効にならず、追加したものは編集できるコピーです。プリセットは、追加するときに
  インターフェース言語の名前になります。
* **複製**、**削除**（先に確認します）、**上へ** / **下へ**、またはドラッグで一覧を並べ替えます
  （`Insert`、`Ctrl+D`、`Delete`、`Alt+Up`、`Alt+Down`）。一覧の順序は `config.toml` での順序です。
* 問題のある行は赤で示され、理由が表示されます（ステップがない、このバージョンが知らないステップ、
  必要なオプションのない「しない」の一時停止）。問題のあるシーケンスも**保存できます**（将来のバージョンの未知のステップは
  そのまま保たれます）が、パレットの行は修正されるまで灰色のままです。

### シーケンスの行

| 行 | 内容 |
|---|---|
| **名前** | パレットに表示されるもの：`シーケンス: <name>`。 |
| **ID** | `config.toml`、コマンドライン、およびショートカットのキーに使う短い名前です（`a-z`、`0-9`、`_`、`-`）。名前を変えると、ショートカットも同じ書き込みで一緒に移ります。 |
| **説明** | 任意。自分用のメモです。 |
| **適用範囲** | 下を参照してください。 |
| **ショートカット** | キーを表示するボタンです。`Enter` またはクリックで、**キーボードとマウス**と同じキーの取得が開きます：競合とターミナルの警告は押している間に表示され、ほかの操作が使っているキーは同じように拒否されます。**解除**で外します。キーは `[keybindings.sequence] <id>` として保存されます。 |
| **ステップ** | 順に並んだステップです。**ステップを編集**で開きます。 |
| **今すぐ実行** | 現在のウィンドウでシーケンスを実行します。 |

### 適用範囲

各シーケンスには適用範囲があり、シーケンスとともに保存されます：

| 適用範囲 | 保存先 | 見える人 |
|---|---|---|
| **このインストール**（既定） | `config.toml` の `[[sequences]]`。このインストールが所有者になります | この GitPoulpi のインストールだけ。 |
| **このコンピューター上のすべてのインストール** | `config.toml` の `[[sequences]]`。所有者なし | そのファイルを共有するすべてのインストール。 |
| **このリポジトリのみ** | 現在のリポジトリの `.gitpoulpi/sequences.toml` | リポジトリを持つ全員。信頼した後にのみ有効になります（下を参照）。 |

適用範囲を変えると、定義が移動します：**このリポジトリのみ**を選ぶとリポジトリのファイルに書き込まれ、
`config.toml` から取り除かれます。逆も同じです。リポジトリの適用範囲には、リポジトリが開いている必要があります。

### リポジトリのシーケンスと信頼

`.gitpoulpi/sequences.toml` はコミットできるので、他人から来ることがあり、シーケンスはあなたのマシン上でコマンドを実行します。
そのため、リポジトリのシーケンスは、コミットされたワークフローファイルのコマンドと同じように、**信頼するまで提示されません**。

まだ誰も信頼していないそのようなファイルがリポジトリにあると、Log の上に通知が現れます：
*このリポジトリは 2 個のシーケンスを定義しています*。**確認**、**信頼**、**無視**が付きます。何かを妨げることはありません。

- **確認**は、すべてのシーケンスを、各ステップ、一時停止、オプションとともに読み取り専用で一覧します。
  そこでの**信頼**は、一覧されたものを信頼します。**閉じる**（または `Esc`）は何も信頼しません。一覧がウィンドウより長い場合、
  そこでは信頼を選べません（ウィンドウを大きくしてください）：読めなかったものを信頼することはありません。
- **信頼**（ボタン、またはパレットの*シーケンス: このリポジトリのシーケンスを信頼*）は、ファイルを現在の状態のまま信頼します。
- **無視**は、ファイルが変わるまで通知を隠します。
- キーボードからは：パレットに*シーケンス: このリポジトリのシーケンスを確認 / 信頼 / 無視*があります。

記録されるのは、id、コマンド、一時停止、オプションのダイジェストで、リポジトリのローカルの状態に保たれます（リポジトリ自身には入りません）。
たとえば pull の後などにこれらのどれかが変わると、通知は*このリポジトリのシーケンスが変更されました*として戻り、
再び信頼するまで、シーケンスはパレットとキーから消えます。シーケンスの名前の変更や説明の編集では何も変わりません。
設定で自分で書いたシーケンスは、編集前にファイルがすでに信頼されていた（または空だった）場合は信頼されたままです。

信頼されると、リポジトリのシーケンスはあなた自身のものと同じようにパレットに `シーケンス: <name>` として現れ、
設定でショートカットを付けられます。自分のシーケンスと同じ id のものは衝突で、自分のものが優先され、もう一方は重複として報告されます。

コマンドラインからは：`gitpoulpi sequence list` がファイルのシーケンスを `trusted` と `repo_trust` の状態
（`untrusted`、`changed`、`trusted`）とともに表示します。`gitpoulpi sequence trust`（と `untrust`、別のリポジトリには
`--repo PATH`）は、人が `sequence show` を読んだ後に実行するものです。`sequence run` は信頼されていないリポジトリのシーケンスを拒否します。
AI エージェントは信頼できません：そのための MCP ツールはありません。

## ステップ

**ステップを編集**は、一覧をシーケンスのステップ（タイトルは **{name} のステップ**）に、行を選択中のステップのものに置き換えます。
**戻る**（行の上端の ×）または `Esc` でシーケンスに戻ります。

* **+ 追加**は**ステップを追加**を開きます：シーケンスが実行できるすべてのコマンドが、パレットでの名前で
  （AI のものにはスパークル付き）並び、入力に応じて、パレットと同じ一致方法で絞り込まれます。このバージョンが実行できないステップは
  理由付きで灰色になります。`Enter` またはクリックで末尾に追加し、`Esc` または × でポップアップを閉じます。
* **複製**、**削除**、**上へ** / **下へ**、ドラッグは、シーケンスの場合と同じように動作します。
* 破壊的なコマンド（ブランチの削除、変更の破棄など）は提示されません：シーケンスはそれらを実行できません。

### 一時停止

各ステップには**一時停止**があります：

| 一時停止 | 意味 |
|---|---|
| **既定** | ステップは、答えが必要なときだけ、通常のダイアログで停止します（ブランチ名、まだ空の commit メッセージなど）。 |
| **常に** | このステップの前で停止し、続行するか確認します。 |
| **しない** | 停止しません。ステップのオプションで必要なものをすべて与える必要があるので、名前を尋ねるステップには**名前**オプションの入力が必要です。 |

実行前に必ず確認するステップ（強制 push）には**しない**は提示されず、行がその理由を示します。
AI メッセージのステップでの**しない**は、明示的な選択として許可されています。

### オプション

**一時停止**の下の行はステップのオプションです：**名前**や**メッセージ**のテキスト、**ブランチ**、
**新しいタブで開く**のようなチェックボックス、または設定から埋められるドロップダウン（**リモート**、**AI プロファイル**、
**開く場所**の項目）。テキストには変数 `${branch}`、`${date}`、`${time}`、`${n}`（名前を一意にする番号）が使えます。
テキストを消すと、そのオプションは取り除かれます。

## AI で作成・編集する

[AI をオンにする](ai.md#シーケンスの下書き)（設定 > AI）と、2 つの項目が現れます：
**追加 > AI で作成...**（パレットの行 `シーケンス: AI で作成...` も同じで、このページで設定をダイアログ付きで開きます）と、
選択中のシーケンスの**今すぐ実行**の隣の **AI で編集...** です。AI がオフの間は、どちらも存在しません。

```
+- Create a sequence with AI ------------------------------- x -+
| Describe the sequence you want                                |
| +-----------------------------------------------------------+ |
| | stage everything, write the commit message with the AI,   | |
| | commit, then push                                         | |
| +-----------------------------------------------------------+ |
| Enter adds a line. Ctrl+Enter sends. Esc closes.              |
| [ ] Send context (remote names, AI profiles, Open in labels)  |
|    Off: only your description is sent.                        |
| The AI only proposes. Nothing is saved before you accept...   |
| [ Send ] [ Cancel ]                                           |
+---------------------------------------------------------------+
```

作りたいものを自分の言葉で書きます。**送信**（または `Ctrl+Enter`、`Ctrl+S`）は、ほかのすべての AI の操作と同じプロファイル、
ジョブの表示、`Esc` で（そして同じ「送信される内容」の確認とともに）モデルに尋ねます。答えは、何かが起きる前に読む**提案**です：

* 名前、id、説明、そしてステップと、その一時停止とオプション。
* **AI で編集**では、現在のシーケンスとの差分：`+` は追加されたステップ、`-` は取り除かれたステップ、`~` は一時停止やオプションが変わったステップ、
  フィールドでは `~ Name: "a" -> "b"`。
* **除外されたもの**：モデルが提案した、許可されないステップ（不明、破壊的、シーケンスの中のシーケンス、不可能な一時停止）が理由付きで並びます。
  有効なステップは残ります。
* モデルの**メモ**と、表示されるだけの**提案されたショートカット**（そのキーがすでに使われているかどうかも）。割り当てられることはありません：
  あとで**ショートカット**ボタンを使ってください。

```
+- Proposed change ----------------------------------------- x -+
| + added   - removed   ~ changed                               |
| ~ Name: "Daily" -> "Daily 2"                                  |
| Steps (3)                                                     |
| + 1. Git: Fetch All Remotes                                   |
|   2. Git: Stage All Changes                                   |
| - Git: Commit...                                              |
| ~ 3. Git: Push: defaults -> Pause: Always                     |
| Left out                                                      |
| step 4 `reset_hard`: destructive steps are not allowed        |
| [ Accept ] [ Edit before saving ] [ Reject ] [ Back ]         |
+---------------------------------------------------------------+
```

* **承諾**は 1 回の保存で書き込み（新しいシーケンス、または編集対象の置き換えで、id、適用範囲、キーは保たれます）、一覧でそれを選択します。
* **保存前に編集**は同じことをして、ステップを開き、行を調整できるようにします（このページはすべての編集をすぐに保存するので、
  シーケンスはすでに保存されています）。
* **却下**は何も書き込みません。**戻る**は、もう一度送るために説明に戻ります。
* 承諾するものがないときは、**承諾**は使えません：使えるステップがない、ページが問題と示すもの、または何も変更しない編集です。

**承諾**の前に何かが書き込まれることはなく、ここからシーケンスが実行されることもありません。
ダイアログを閉じる（×、`Esc`、外側のクリック）と、説明が入力されているか提案が開いている間は「変更を破棄しますか？」と尋ねます。
設定を閉じるときも同様です。

## config.toml

```toml
[[sequences]]
id = "backup"
name = "Backup"
scope = "installation"
owner = "<this installation's id>"

[[sequences.steps]]
run = "stage_all"

[[sequences.steps]]
run = "ai_generate_commit_message"
pause = "always"

[[sequences.steps]]
run = "commit"

[[sequences.steps]]
run = "push"

[keybindings.sequence]
backup = "Alt+B"
```

このバージョンが知らないキーとステップは、ページが保存するときも保たれます。

## シーケンスの実行

シーケンスは、ステップの名前付きの一覧で、各ステップはパレットのコマンドです（すべてステージ、AI で commit メッセージを書く、commit、push など）。
パレット（`シーケンス: <name>`）から、設定 > キーボードとマウスで割り当てたキー（`tui.toml` の `[keybindings.sequence]`）で、
またはコマンドライン（`gitpoulpi sequence run`）から実行します。

実行中は、Log の上端のストリップに `<name> k/n`、ステップ、待っている内容が表示されます。実行はジョブパネルにも
`シーケンス <name> k/n：<step>` として表示されます。同時に実行できるシーケンスは 1 つで、2 つ目を始めようとすると、実行中のものが示されます。

**確認のために止まる場所。** 各ステップには `pause` の設定（`default`、`always`、`never`）があります：

| ステップ | 既定 | `pause = "never"` |
|---|---|---|
| AI の commit メッセージ | メッセージがメッセージ欄に入り、ストリップに「メッセージを確認して、続行してください」と表示されます | すぐに進みます |
| Commit | 空のメッセージでは必ず停止します：欄にキーボードが移り、自分の commit（または続行）で進みます | commit するメッセージがないときは使えません |
| AI で commit を構成 | レビューが開き、適用で進み、閉じるとキャンセルになります | 提案をそのまま適用します |
| worktree を作成 | 名前が入力済みのダイアログが開きます | ダイアログなしで `options.name` から作成します |
| Push | `git.push_behavior = ask` のとき「Push 先...」の選択が開きます | `options.remote` へ push します |
| リース付き強制 push、秘密に見えるファイルのステージ | 必ず確認します | 使えません |

どのステップでも `pause = "always"` にすると、実行前に「次：<step>」が**続行**と**キャンセル**とともに表示されます。ブランチが分岐していて push が拒否された場合は、
通常のダイアログが開き、ストリップに「Push が拒否されました：ダイアログで選んでください」と表示されます。pull してから push する
（またはリース付き強制 push をする）と実行は続き、ダイアログを閉じるとキャンセルになります。

**続行**は、ストリップのボタン、パレットの `シーケンス: 続行`、または `sequence.continue` に割り当てたキーです。**キャンセル**は、
ストリップの閉じる ×、`シーケンス: キャンセル`（`sequence.cancel`）、ジョブパネル、またはほかに受け取るものがないときの `Esc`
（開いているダイアログが先に閉じ、それもキャンセルになります）です。キャンセルしても、すでに実行されたステップは保たれ、そのことが表示されます：
「<name> はステップ k/n（<step>）の後でキャンセルされました。それ以前のステップはそのまま残ります」。

**ステップが失敗したとき**、実行はそこで止まります：ステータスバーにシーケンス、ステップ、エラーが表示され、ストリップは赤くなって
**詳細**（ステップのオプションを一覧するアクティビティログの項目）と閉じる × が付き、それ以前のステップは完了したままです。

**Worktree。** `open_tab = true` の worktree 作成ステップは、実行を新しい worktree のタブに移します：次のステップ
（`tab_dir_terminal`、`tab_open_agent_here`、`tab_open_in`）はそこで動作します。別のタブが表示されているときは、ストリップに「タブ <name> を待機中」と
**移動**が表示されます。そのタブを閉じると実行はキャンセルされます。実行は GitPoulpi を終了すると引き継がれません。

### エージェントによる実行の提案

*AI エージェントが確認用の変更を提案できるようにする*がオンのとき（`[mcp] allow_ui_propose`）、エージェントはあなたのウィンドウにシーケンスの実行を依頼できます
（`gitpoulpi ui sequence run <id>`、MCP の `ui_sequence_run`）。バナーが現れます：
*✦ <agent> からの提案：シーケンス <name> を実行*。**実行**と**却下**が付きます。
実行を押す（クリック、または `Ctrl+N` の後に `Enter`）まで何も実行されません。
却下、`Esc`（ほかに受け取るものがないとき）、またはパレットの*エージェント: 保留中のビューを破棄*で取り下げます。
その後の実行は、自分で始めた場合とまったく同じで、シーケンスが指定した箇所で一時停止します。
シーケンスが存在しない、無効、または信頼していないリポジトリのシーケンスの場合、提案は拒否されます。

## 実行を元に戻す

リポジトリを変更するすべてのステップ（ステージ、commit、tag、ブランチ、stash、worktree など）は、実行の印が付いた**独自の通常の元に戻す項目**を残します。
そのため `Ctrl+Z` はこれまでどおり 1 ステップずつ元に戻し、[元に戻す履歴](undo-redo.md#元に戻す履歴)にはそれらに `⟳ <name>` が表示されます。
実行全体を取り消すには**シーケンス全体を元に戻す**があります：元に戻す履歴のボタン（`x`）、パレットの行 `編集: シーケンス全体を元に戻す`、
または `gitpoulpi undo --sequence` です。実行の項目を新しいものから順に、それぞれ独自のチェックと質問付きで元に戻し
（すでに push された commit は先に確認します）、最初の拒否でステップを示して停止し、より古いものはジャーナルに残します。
AI のメッセージと push は項目を残しません：push は取り消されません。触れるのは現在のリポジトリのジャーナルだけで、worktree で行ったステップは
そのリポジトリから元に戻します。やり直しは項目ごとのままです。詳細：[シーケンスの実行](undo-redo.md#シーケンスの実行)。
