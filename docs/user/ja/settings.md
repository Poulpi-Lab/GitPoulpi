# 設定

設定は `Ctrl+,`、`Ctrl+N` に続けて `,`、タイトルバーの × の左にある歯車、または `Ctrl+P` > *設定* で開きます。設定画面は、開いている間ウィンドウ全体を置き換えます。右上の `✕`、`Esc`、または `q` で閉じます。閉じると何かが失われる場合にだけ、先に確認されます（[設定を閉じる](#設定を閉じる)を参照）。

変更はすぐに `config.toml` に保存されます。各キー、その既定値、環境変数については[設定リファレンス](config-reference.md)を参照してください。このページでは設定画面そのものを説明します。

![設定画面：左に検索ボックスとページの一覧、右に「一般」ページ](../images/settings.png)

## 設定画面の使い方

| 操作 | 方法 |
|---|---|
| ページの一覧とオプションの間を移動する | `Tab` / `Shift+Tab`、またはクリック。 |
| 移動する | `j` / `k` または矢印キー。 |
| オプションを変更する | `Enter` または `Space`、または値をクリック。下記を参照してください。 |
| 閉じる | `✕` をクリック、または `Esc` か `q`。フィールド、ドロップダウン、確認が開いている間は、`Esc` はそれだけを閉じます。 |

`Enter` または `Space` の動作は行によって異なります。

- チェックボックスは切り替わります。
- ドロップダウンは開きます。矢印キーで選び、`Enter` で確定します。
- テキストまたは数値のフィールドは編集を始めます。矢印キー、`Home`、`End`、`Backspace`、`Delete` が使え、クリックでキャレットを置けます。`Enter`、`Tab`、`Up`、`Down`、または別の場所のクリックで値を保存します。`Esc` で取り消します。拒否された値は赤色のままフィールドに残り、ステータスバーに理由が表示されます。
- ボタンの行（**作成**、**削除**、**テスト**など）には、今使えるボタンだけが表示されます。`Left` / `Right` で 1 つ選んで `Enter` で押すか、クリックします。何かを削除するボタンは、先に確認します。

どのページでも、値は同じ列から始まるため、ラベルは左に、フィールドは右にそろいます。テキストや数値は色付きの帯、選択肢は `▾` で終わる帯、チェックボックスは `[x]` で表示されます。長いラベルは切らずに折り返され、狭いウィンドウでは値がラベルの下に移ります。

グレーアウトした行には、無効な理由が表示されます。たとえば、**グラフのレーン背景**が**オフ**の間は、**行の色付けの強さ**がグレーアウトします。

### リスト

同じ種類の項目を複数編集するページ（プロファイル、AI、ワークフロー、開く場所、画像）では、**左にリスト、右に選択中の項目のフィールド**が表示されます。狭いウィンドウでは、リストがフィールドの上に置かれます。リストはどこでも同じ形です。

- 行の印は状態を表します。`●` は有効なプロファイル、`★` は既定のエントリ、`⚠` は未完成の項目（メールアドレスのないプロファイルなど）で、詳細が出る場所に理由が表示されます。
- リストの下には **+ 追加**、**複製**、**削除**、`↑`、`↓` があります。今は使えないボタン（先頭行の `↑` など）は暗く表示されます。ページにプリセットや種類の選択肢がある場合、**+ 追加 ▾** でドロップダウンが開きます。
- **削除**は、追加した直後でまだ編集していない項目を除いて、先に確認します。
- 行をドラッグして移動します。落とす位置にバーが表示され、`Esc` でドラッグを取り消せます。ダブルクリックすると、その項目のフィールドへ移動します。

| キー | 動作 |
|---|---|
| `Up` / `Down`、`Home` / `End`、`PageUp` / `PageDown` | 項目を選ぶ。 |
| `Insert` | 項目を追加する（ドロップダウンがある場合は開く）。 |
| `Ctrl+D` | 項目を複製する。 |
| `Delete` | 確認のうえ、項目を削除する。 |
| `Alt+Up` / `Alt+Down` | 項目を上または下へ移動する。 |
| `Enter` または `Right` | 項目のフィールドへ移動する。 |
| `Left` | ページの一覧へ戻る。 |
| `Alt+Left` / `Alt+Right` | 「一般」タブとリストのタブを切り替える（ページのどこでも）。 |

これらのページにはそれぞれ、タイトルの下に2つの**サブタブ**があります。ページ全体の設定が、選択した項目のプロパティと取り違えられないようにするためです。**一般** はページ自体の設定（有効なプロファイル、既定のエントリ、AIの各アクションが受け取る指示、ワークフローのテンプレートなど）、もう1つは項目の名前を冠したタブ（**プロファイル**、**プロファイル（接続）**、**項目**、**エディター**、**ルール**）で、リストと選択した項目のフィールドが入っています。ページは **一般** で開き、各ページで最後に開いていたタブはアプリを終了するまで記憶されます。各ページ（およびタブ）のスクロール位置と選択中の行も同様に記憶されます。タブをクリックするか、`Alt+Left` / `Alt+Right` を押します。検索ボックス、コマンドパレットの設定行、「設定で指定してください」というリンクは、その設定があるタブを開きます。
[キーボードとマウス](#キーボードとマウス)にも同じ 2 つのタブ（**一般**、**キー割り当て**）があります。

キーは**キーボードとマウス**で変更できます（コンテキストは *preferences*。[キーバインド](keybindings.md)を参照）。

### 複数行エディター

複数行を保持する設定（スパースチェックアウトのパス、commit テンプレートの説明、競合防止のベースブランチ、ワークフローのフックなど）は、`Enter` またはクリックで小さなエディターが開きます。`Ctrl+S` でテキストを確定し、`Esc` で破棄します。マウスは一般的なテキストボックスと同じように使えます。

- クリックすると、クリックした位置にキャレットが置かれます。
- ドラッグするとテキストを選択でき、ホイールでスクロールします。
- ダブルクリックすると、ポインターの下の単語を選択します。
- `Shift` + クリックで、キャレットからポインターまで選択範囲を広げます。

キーボードでも同じことができます。`Shift` + 矢印キーで選択、`Ctrl` + 矢印キーで単語単位の移動、`Ctrl+A` ですべて選択、`Ctrl+C` と `Ctrl+X` でコピーと切り取りです。

### 設定を閉じる

`✕`、`Esc`、`q` は同じ動作です。設定は変更のたびにすぐ適用されるので、ほとんどの場合はそのまま閉じます。何かが失われるときだけ、**設定を閉じますか？**と確認されます。

- **ワークフロー**ページに未保存の変更がある。
- commit メッセージのテンプレートに未保存の変更がある。
- 作成者のメールアドレスがないプロファイルがある（そのプロファイルによる commit を、あなたのものとして記録できません）。

ボックスには、**その項目へ移動**（そのページを開く）、**破棄して閉じる**、**このまま閉じる**、**キャンセル**があります。設定の中の小さなエディター（AI の指示のテキスト、ワークフローのフック、スパースチェックアウトのパス）には、それぞれ独自の `✕` があり、テキストを編集したときだけ**変更を破棄しますか？**と確認されます。

### 設定の上に開くポップアップ

タイトル行には、メインウィンドウと同じようにアプリケーションのタコのアイコンと名前が表示されます。タコをクリックすると About が開きます。

ウィンドウ全体に関わる一部のポップアップは設定の上に開き、閉じると設定を元のままに戻します（ページ、スクロール位置、未保存のワークフローやテンプレートの変更はそのまま残ります）。

- コマンドパレット（`Ctrl+P`）
- テーマピッカー（`Ctrl+N y`、**アプリ: テーマを変更...**）。設定画面そのものに各テーマをプレビューし、`Esc` で前のテーマに戻します。
- 言語とグラフの色のピッカー（`Ctrl+N` に続けて、メインウィンドウと同じ文字）
- ワークスペース検索（`Ctrl+Alt+F`）
- About（`Ctrl+N a`、タコのアイコン、または **ヘルプ: GitPoulpi について**）とヘルプオーバーレイ（`?`）

それぞれ `Esc`、そのポップアップ自身の `✕`、または外側のクリックで閉じます。設定が対象とするもの（タブ、ブランチ、diff など）に作用するコマンドは、パレットには表示されますが、「先に設定を閉じてください」と表示されてグレーアウトされます。それらの `Ctrl+N` コードも、設定の下の枠線に同じ文言を表示します。設定を閉じてから実行してください。

`Ctrl+N` を押すと、ページの各コントロールにバッジが表示されます。検索ボックス、ページの一覧（現在のページに 1 つ）、サブタブ、リストとそのボタン、画面上の各フィールド、閉じる `✕` です。バッジの文字を押すと、そのコントロールをクリックしたのと同じ動作になります。テキストフィールドは編集状態で開き、チェックボックスは切り替わり、ドロップダウンは開き、ボタンは実行されます。`Esc` で取り消します。画面外にスクロールされたフィールドにはバッジが付きません。フィールドに入力している間や、ドロップダウン、エディター、検索が開いている間は、`Ctrl+N` は本来の意味のままです。[バッジ](keybindings.md#バッジ)を参照してください。

### 検索ボックス

ページの一覧の上にあるボックスは、すべてのページのすべてのオプションの名前と説明を検索します。クリックするか、`/` または `Ctrl+F` を押して入力してください。一致した項目の一覧が開き、各項目にはオプションとそのページが表示されます。`Up` / `Down` で選び、`Enter` でそのオプションへ移動し、`Esc` で一覧を閉じます。

![設定で「diff」を検索：ログとグラフ、diffとエディター、Git のページから一致するオプション](../images/settings-search.png)

## コマンドパレットから設定する

ほとんどの設定は、この画面を開かずに変更できます。コマンドパレット（`Ctrl+P`）に `設定:` または `Settings:` と入力してください。行は各ページのフィールドから生成されるため、新しい設定は両方に現れます。

- チェックボックスは **設定: ... を切り替え** です。すぐに切り替わり、行には `[x]` または `[ ]` が表示されます。
- ドロップダウンは **設定: ...** です。`Enter` でパレットがその値に絞り込まれ、現在の値には `現在` と付きます。値の上で `Enter` を押すと選択されます。
- 数値やテキストは、現在の値が入力済みのプロンプトを開きます。ページが拒否する値（数値でない、範囲外）は同じように拒否され、プロンプトは開いたままです。
- ページが必要な設定（リスト、実行時に選択肢が決まるコンボ）は、その場所で設定を開きます。

![Settings: で絞り込んだコマンドパレット：設定ごとに 1 行で、右側に現在の値が表示される](../images/palette-settings.png)

値は `config.toml` に保存され、ページとまったく同じように適用されます。設定キーの英語の語（`remember tabs`）で、どの言語でもその行が見つかります。

## ページ

ページの一覧には 2 つのグループがあります。

- **設定**：グローバルな設定。
- **リポジトリ別の設定**：アクティブなタブのリポジトリに対する設定。リポジトリが開いている間だけ表示されます。

### 一般

![「一般」ページの「言語」ドロップダウン：自動と 17 の言語、検索フィールド付き](../images/settings-language.png)

| オプション | 働き |
|---|---|
| **言語** | インターフェースの言語：**自動**（システムの言語、なければ英語）、English、Français、Español、Português （Brasil）、Português （Portugal）、Italiano、Deutsch、简体中文、日本語、한국어、Русский、Українська、Polski、Čeština、Nederlands、Svenska、Türkçe。再起動なしですぐに反映されます。ログの月名と日付も連動します。環境変数 `GITPOULPI_LANG`（例：`GITPOULPI_LANG=fr`）はこの選択より優先されます。CLI と MCP の出力は英語のままです。 |
| **git 用語を翻訳** | 既定ではオフ：commit、push、pull、stash、tag などの git 用語は、どの言語でも英語のままです。オン：その言語の git 用語を使います（日本語では*コミット*、*プッシュ*、*スタッシュ*、*タグ*）。すぐに反映されます。 |
| **git 用語を英語で表示** | 日本語、韓国語、中国語のみ：*stage*、*unstage*、*staged* を音訳ではなく英語で表示します。**git 用語を翻訳**がオンの間は効果がありません。 |
| **タブを記憶** | 起動時に、前回のセッションのタブを開き直します。オフの場合、リポジトリの中で起動するとそのリポジトリだけを開き、リポジトリの外で起動するとリポジトリのタブなしでホームから始まります。再起動が必要です。 |
| **Radar を有効化** | 既定でオン（`general.radar_enabled`）。オフにすると、Radar のタブ、そのパレットコマンド、`Alt+R` が隠れ、バックグラウンドでの取得も行われません。すぐに反映されます。[Radar](radar.md#タブを閉じるまたは-radar-をオフにする)を参照。Radar のないビルドでは表示されません。 |
| **リポジトリ内で起動したときのタブ** | 起動したフォルダーがリポジトリの中にあるときに、最初に開くタブ（`general.startup_tab_in_repo`）：**現在のリポジトリ**（既定。そのリポジトリのタブ。なければ開きます）、**最後のタブ**（前回終了時にアクティブだったタブ）、**ホーム**、**Radar**。`--repo` で指定したリポジトリは常に自分のタブを開きます。**最後のタブ** は、**タブを記憶** がオフ、または記憶されたタブがなければホームになります。**Radar** は、Radar が無効またはビルドに含まれないときホームになります。起動時に一度だけ読み込まれ、反映には再起動が必要です。 |
| **リポジトリ外で起動したときのタブ** | 起動したフォルダーがリポジトリではないとき（たとえばユーザーフォルダー）に、最初に開くタブ（`general.startup_tab_outside_repo`）：**ホーム**（既定）、**最後のタブ**、**Radar**。**最後のタブ** は、**タブを記憶** がオフ、または記憶されたタブがなければホームになります。**Radar** は、Radar が無効またはビルドに含まれないときホームになります。起動時に一度だけ読み込まれ、反映には再起動が必要です。 |
| **ランチャーから起動したときのタブ** | GitPoulpi が作成したデスクトップまたはスタートメニューのショートカット（`--launcher` を渡します）から起動したときに、フォルダーに関係なく最初に開くタブ（`general.startup_tab_launcher`）：**最後のタブ**（既定）、**ホーム**、**Radar**。上の 2 つの設定より優先されます。**最後のタブ** は、**タブを記憶** がオフ、または記憶されたタブがなければホームになります。**Radar** は、Radar が無効またはビルドに含まれないときホームになります。古いバージョンが作成したショートカットは、次回起動時にこのオプションが付きます。起動時に一度だけ読み込まれ、反映には再起動が必要です。Windows では、タスクバーにピン留めしたコピーも次回起動時に書き換えられ、シェルを介さない起動（ダブルクリック、ピン留めした exe 自体）はランチャーからの起動として扱われます。 |
| **worktree のタブをまとめる** | 既定でオン（`general.group_worktree_tabs`）。リポジトリにリンクされた worktree のタブは、そのリポジトリのタブのすぐ後ろに並び、ドラッグして離したタブも元の位置に戻ります。オフにすると、置いた場所のままになります。オンにすると、開いているタブがまとめ直されます。 |
| **既定のクローン先フォルダー** | Clone ダイアログが開始する場所です。空の場合：Windows では `%USERPROFILE%\source\repos`、それ以外では `~/src`。 |
| **既定の参照フォルダー** | Browse が開く場所です。空の場合：最後に使ったフォルダー、なければホームフォルダー。 |
| **リポジトリデータの保存場所** | GitPoulpi がリポジトリごとのデータを置く場所です（`session.per_repo_state_dir`）。**.git の中**（既定：作業ツリーには何も現れず、すべての worktree で共有されます）、**作業ツリーの中**（`.gitpoulpi` フォルダー。チームで共有する `workflow.toml` を commit するのに必要です）、**自分のユーザーデータフォルダー**（リポジトリの外）から選びます。古いバージョンが残した `.gitpoulpi` フォルダーは、初めて必要になったときに新しい場所へ移され、空になると削除されます。git が追跡しているファイル（commit 済みの `workflow.toml`）は移動も削除もされず、そのまま読めます。 |
| **既定のブランチ名** | Init で作成するリポジトリの最初のブランチです。空の場合：git に任せます。既存のブランチの名前は変更しません。 |
| **競合の事前検出を有効化** | 既定でオン（`general.conflict_detection`）。現在のブランチを元のブランチへ merge すると競合する場合に、試す前にログで警告します。リポジトリごとに、**競合の予防**ページでオフにできます。[merge の競合を解決する](merge-conflicts.md#競合の予防)を参照してください。設定を閉じたときに反映されます。 |
| **ログレベル**、**ログファイルの保存期間**、**ログファイルの最大サイズ** | アクティビティログの元になるアプリケーションログ：記録する最も詳細なレベル（`log.level`）、ファイルを保存する期間（整数と単位（日、週間、か月、年）を 1 行で指定します。数値をクリックして入力し、Up と Down で増減し、Tab で単位へ移動して Enter でその一覧を開きます。最長 10 年、既定は 1 週間、`log.retention_days` と `log.retention_unit`）、1 日分のファイルをローテーションするサイズ（数値と MiB または GiB、1 MiB から 1 GiB、`log.max_file_mb` と `log.max_file_unit`）。 |
| **操作の所要時間を表示**、**拡張ログ** | アクティビティログの「Git 操作」タブ：各操作の所要時間（`log.timings`、既定でオン）と、バックグラウンドの処理（更新と自動 fetch）（`log.extended`、既定でオフ）。[何かが失敗したとき](troubleshooting.md#アクティビティログ)を参照してください。 |
| **元に戻す機能を有効化**、**元に戻す履歴の深さ**、**GitPoulpi の外での変更を記録** | **元に戻す履歴**のグループです。元に戻す機能のオン／オフと、保持する操作の数を設定します（既定は 100、`0` は無制限）。元に戻す機能をオフにすると、確認のうえで元に戻す履歴が消去されます。最後の項目は、シェルやエージェントがブランチ、tag、stash、HEAD に対して行った操作も記録します。[元に戻す・やり直す](undo-redo.md)を参照してください。 |

#### ランチャー（デスクトップ統合）

「一般」ページの最後のグループである **ランチャー** では、OS のランチャーから、選んだターミナルで GitPoulpi を起動するショートカットを作成します。

| 行 | 内容 |
|---|---|
| **ショートカット用のターミナル** | `ui.launch_terminal`：**自動**、**OS の既定**、またはこのマシンで見つかったターミナルのいずれかです（**開く場所** と同じ検出方法）。自動の場合、Windows では Windows Terminal（なければ WezTerm、Alacritty、通常のコンソール）、Linux では `xdg-terminal-exec`（Omarchy。なければ最初に見つかったターミナル）、macOS では iTerm2、Ghostty、WezTerm、kitty のいずれもインストールされていなければ Terminal を使います。 |
| **ダブルクリック時にそのターミナルで開き直す** | Windows のみ（`ui.relaunch_in_terminal`）。exe をダブルクリックすると既定のコンソールが開きますが、このコンソールは画像をうまく描画できません。そのため GitPoulpi は選んだターミナルで開き直し、最初のウィンドウを閉じます。ターミナルから起動した場合は開き直しません。 |
| **クリック時に開いているウィンドウを表示** | `ui.reuse_window` (既定でオン). GitPoulpi のショートカット（`gitpoulpi launch`）をクリックすると、新しく起動せず、すでに開いている GitPoulpi のウィンドウを表示します。 新しいターミナルを起動するのは、開いているものがない場合、この設定がオフの場合、またはウィンドウを前面に出せない場合だけです。前面に出せるのは Windows、WezTerm、Hyprland で、ほかの Linux デスクトップでは従来どおり新しいウィンドウが起動します。macOS では使いません（Dock がすでに同じ動作をします）。 意図的に別のウィンドウを開くには、クリック時に **Shift** を押し続ける（Windows）か、ランチャーの**新しいウィンドウ**アクション（Linux）を使います。スクリプトからは `gitpoulpi launch --new-window` で同じことができます。 |
| **コマンドのエイリアス** | `ui.command_alias`：**なし** と `gp` を選べるドロップダウンで、好きな名前も入力できます（英数字と `-`、`_`、`.`。スペースやパスの区切り文字は不可）。行内の**作成**ボタンで、その名前から GitPoulpi を起動できるようになります（エイリアスができると**削除**に変わり、GitPoulpi が作成したエイリアスをすべて削除します）。その名前が PATH 上ですでに別のものを実行する場合、Windows では PowerShell にその名前の組み込みエイリアスがある場合（そこでは `gp` が `Get-ItemProperty` で、どのファイルよりも優先されます）、行の下に警告が表示されます。シェルのエイリアスや関数はここからは見えません。oh-my-zsh は `gp` を自分で定義していて、こちらより優先されます。 |
| **新規タブのエイリアス** | `ui.command_alias_add`：2つ目のコマンド（例：`gpa`）で、新しい GitPoulpi を起動する代わりに、すでに起動中の GitPoulpi に現在のフォルダーを新しいタブとして開きます（`gitpoulpi --add`）。起動中のものがなければ通常どおり GitPoulpi を起動し、複数あればどれに参加するかを尋ねます。**なし**、`gpa`、エイリアス名の末尾に `a` を付けたものを選べるドロップダウンで、好きな名前も入力できます（規則は上と同じ）。**作成**ボタン 1 つで両方のコマンドが作られ、**削除**は GitPoulpi が作成したコマンドをすべて削除します。それぞれに状態の行があります。Linux と macOS では 2 行のスクリプト、Windows では `.cmd` です。[CLI リファレンス](cli-reference.md#開いているウィンドウにフォルダーを追加する)を参照してください。 |
| **GitPoulpi を PATH に追加** | GitPoulpi の実行元フォルダーとエイリアス用フォルダーを、新しいターミナル向けに PATH へ追加します。行のボタンは**追加**または**削除**で、**削除**は追加したものだけを取り除きます。すでに PATH にあるフォルダーには触れません（その場合、行には**すでに PATH にあります**と表示されます）。 |
| **アプリランチャー**（Linux） | `~/.local/share/applications/gitpoulpi.desktop`（`XDG_DATA_HOME` に従います）と、`~/.local/share/icons/hicolor/256x256/apps` にアイコンを書き込みます。Omarchy では `omarchy-tui-install` が作るものと同じエントリ（`xdg-terminal-exec --app-id=TUI.tile -e <exe>`）になり、ほかのターミナルではそれぞれに合ったコマンド（`kitty`、`wezterm start --`、`alacritty -e`、`ghostty -e`、`foot` など）になります。 |
| **デスクトップ**（Linux） | 同じエントリをデスクトップフォルダーに置きます（フォルダーがある場合）。 |
| **スタートメニュー**（Windows） | `%APPDATA%\Microsoft\Windows\Start Menu\Programs` に `GitPoulpi.lnk` を作成します。タスクバーにピン留めしたコピーは、アイコンや色の変更に自動で追従します。アイコンが古いままの場合は、ピン留めを外してもう一度ピン留めしてください（スタートメニューの項目を右クリックして **タスクバーにピン留めする**）。 |
| **デスクトップ**（Windows） | デスクトップに `GitPoulpi.lnk` を作成します。 |
| **アプリケーションフォルダー**（macOS） | `~/Applications/GitPoulpi.app` を作成します。GitPoulpi を実行するターミナルを開く小さなバンドルです。 |

各行には状態が表示されます：**未作成**、**作成済み**、**古い**（exe が移動したか、別のターミナルが選ばれています。GitPoulpi が 1 秒以内に自分で書き直すので、目にすることはほとんどありません）、**GitPoulpi 以外のファイルがあります**（同じ名前のファイルがありますが GitPoulpi が作成したものではないため、一切変更しません）。**削除** は GitPoulpi が作成したファイル（`X-GitPoulpi=1` のマーカー付き）だけを削除します。アイコンはロゴの色のタコです（GitPoulpi について > 色）。Linux では色ごとに別のアイコン名が付くので、アイコンをキャッシュするランチャーでも新しい色が表示されます。作成したショートカットは自動で最新に保たれます：色を変えたとき、ターミナルや exe が移動したときに、GitPoulpi は自分が作成したショートカットを（作成していないものには触れず、新しく作ることもなく）起動時と実行中に書き直します。更新ボタンはありません。あるのは **作成**（まだ存在しないショートカット用）と **削除** だけです。

**タスクバーと Dock でのグループ化。** GitPoulpi はターミナルのウィンドウ内で動くため、タスクバーでは通常ターミナルのアイコンの下に表示され、ピン留めした GitPoulpi アイコンの下に「実行中」の点が付きません。Windows：ショートカットには AppUserModelID `GitPoulpi.GitPoulpi` が付いており、そこから起動した GitPoulpi は自分のターミナルウィンドウに同じ ID と自分のアイコンを設定します（ウィンドウは、しばらく固有のタイトルを付けて見つけ、その後タイトルを元に戻します）。そのためウィンドウはピン留めした GitPoulpi アイコンの下に入ります。複数のタブを持つターミナルウィンドウは全体として扱われ、GitPoulpi が動いている間はすべてのタブが GitPoulpi のアイコンの下にまとまります。以前に作成したショートカットとタスクバーのピン留めは、同じ同期で書き換えられます。ピン留めがまだターミナルのアイコンのままなら、いったん外してもう一度ピン留めしてください。Linux：kitty、foot、Alacritty、WezTerm、Ghostty はウィンドウクラス `gitpoulpi` で起動し、`.desktop` エントリがそれを指定する（`StartupWMClass`）ので、Dock はランチャーのアイコンの下にウィンドウをまとめます。ほかのターミナルは自分のアイコンのままです。macOS：何もする必要はありません。Dock はアプリ単位でまとめます。

![ランチャーグループまでスクロールした 設定 > 一般：ショートカット用のターミナルとアプリランチャーの行](../images/settings-launcher.png)

##### コマンドのエイリアスと PATH（システム別）

| システム | エイリアス | PATH |
|---|---|---|
| Linux、macOS | `~/.local/bin/<name>` から `gitpoulpi-tui` へのシンボリックリンク。リンクにはマーカーを持たせられないため、リンク先が `gitpoulpi-tui` という名前のファイルである場合に GitPoulpi のものとみなします。通常のファイル、または別のものへのリンクは**自分のものではない**扱いで、置き換えも削除もされません。 | `~/.bashrc` と `~/.zshrc`（存在するほう。どちらもなければ macOS では `~/.zshrc`、それ以外では `~/.bashrc`）の `# >>> GitPoulpi PATH (X-GitPoulpi=1) >>>` と `# <<< GitPoulpi PATH <<<` の間のブロック。fish を使っている場合は `~/.config/fish/conf.d/gitpoulpi-path.fish`。削除はこのブロック（または fish のファイル）だけを取り除きます。 |
| Windows | `%LOCALAPPDATA%\Programs\GitPoulpi\bin\<name>.cmd`。`REM X-GitPoulpi=1` を含む 2 行のシムです。 | `HKCU\Environment` のユーザー PATH。PowerShell 経由で書き込み、その後 `WM_SETTINGCHANGE` をブロードキャストして新しいプログラムに反映させます。値 `GitPoulpiPathAdded` に追加した内容を記録し、削除ではそれだけを取り除きます。 |

PATH の変更が見えるのは新しいターミナルで、すでに開いているものには反映されません。どちらの操作も履歴には記録されず、元に戻す機能の対象ではありません。戻すには**削除**を使います。

パレットにも同じアクションがあります（**ランチャー: ショートカットを作成**、**ランチャー: デスクトップのショートカットを作成**、**ランチャー: ショートカットを削除**、**ランチャー: コマンドのエイリアスを作成**、**ランチャー: コマンドのエイリアスを削除**、**ランチャー: PATH に追加**、**ランチャー: PATH から削除**）。スクリプトからは `gitpoulpi desktop shortcut status|install|remove [--where launcher|desktop|startmenu]` で同じことができます。

パレットのコマンド **アプリ: 言語を変更...**（`Ctrl+N g`）でも同じ言語の一覧が開きます。そこではハイライトした言語がライブでプレビューされ、`Enter` で確定、`Esc` で前の言語に戻します。

### 同期

GitPoulpi がリポジトリをリモートと同じ状態に保つ方法と、その間にローカルの変更をどう扱うかを設定します。

![「同期」ページ：自動フェッチの間隔が数値と単位（分）で 1 行に並び、その下に他のオプションが続く](../images/settings-quantity.png)

| オプション | 働き |
|---|---|
| **自動fetchの間隔** | この間隔で、すべてのリモートをバックグラウンドで fetch します。数値と単位（分または時間）を 1 行で指定します。既定は 5 分、最大 60 分（1 時間）、`0` でオフになります。`general.auto_fetch_interval_minutes` は分のままで、`general.auto_fetch_interval_unit` は表示のされ方を記録するだけです。再起動が必要です。 |
| **タブを開いたときにfetch** | リポジトリのタブを開いたときに、バックグラウンドで Fetch All を実行します。既定でオンです。直近 60 秒以内に fetch したリポジトリは、再度 fetch されません。 |
| **自動プルーン** | fetch 時に、リモートにもう存在しないリモート追跡ブランチも削除します。既定ではオフです。 |
| **tagの自動プルーン** | fetch 時に、リモートで削除された tag をローカルからも削除します。対象はリモートにあったことのある tag だけで、一度も push していない tag は残ります。既定ではオフで、git と同じです。git 2.41 以降が必要です。CLI：`gitpoulpi fetch --prune-tags`、設定キーは `general.auto_prune_tags`。[ブランチ、tag、Refs サイドバー](log-and-history.md#ブランチtagrefs-サイドバー)を参照してください。 |
| **サブモジュールを最新に保つ** | checkout または pull の後に、サブモジュールをリポジトリが記録している commit に更新します。[サブモジュール](submodules.md)を参照してください。 |
| **merge後に「.orig」ファイルを削除** | merge が完了した後に、バックアップの `*.orig` ファイルを削除します。既定ではオフです。 |
| **checkout・pull・merge・rebase前に自動stash** | ローカルの変更がこれらの操作を妨げるときの動作：**確認**（変更を stash し、操作を実行して、stash を戻すかをダイアログで尋ねます）、**常に**（尋ねずに実行）、**しない**（拒否）。 |
| **自動stashに未追跡ファイルを含める** | 自動 stash で、未追跡ファイルも対象にします。 |

このページには、**更新**のグループもあります。

| オプション | 働き |
|---|---|
| **更新の確認** | ドロップダウン（`updates.mode`）：**通知**（既定）は 1 日に 1 回バックグラウンドで確認し、タイトルバーに `vX.Y.Z が利用可能` と表示します。**自動**は、GitPoulpi をリリースアーカイブからインストールした場合に、更新のダウンロードもバックグラウンドで行います（再起動のタイミングは自分で選びます）。**オフ**はリクエストを一切送りません。すぐに反映されます。[更新](installation.md#更新)を参照してください。 |
| **更新チャンネル** | ドロップダウン（`updates.channel`）：**安定版**（既定）または**プレリリース版**（リリース候補も対象）。すぐに反映されます。 |

このページには、**履歴の書き換え**のグループもあり、外部スクリプトの制限時間を設定します（[履歴の書き換え](history-rewrite.md)を参照）。

| オプション | 働き |
|---|---|
| **スクリプトの応答時間の上限** | 外部スクリプトが 1 件の commit に答えるのにかけられる時間です。数値と単位（ミリ秒または秒）を 1 行で指定します。既定は 5 秒、1 ミリ秒から 10 分まで（`rewrite.script_timeout_ms`、`rewrite.script_timeout_unit`）。超過するとプロセス全体が停止し、何も移動しないまま書き換えが失敗します。 |
| **スクリプトの 1 回あたりの実行時間の上限** | 外部スクリプトが全体を 1 回処理するのにかけられる時間です。数値と単位（秒、分、時間）で指定します。既定は 1 時間、最大 24 時間（`rewrite.script_total_timeout_s`、`rewrite.script_total_timeout_unit`）。 |

### プロファイル

![「プロファイル」ページ](../images/settings-profiles.png)

commit の ID プロファイルです。GitPoulpi から行う commit に使う名前とメールアドレスを設定します。**一般**タブに**有効なプロファイル**のドロップダウンがあり、**プロファイル**タブは[リスト](#リスト)（追加、複製、削除、並べ替え）と選択中のプロファイルのフィールドです。各プロファイルには、**プロファイル ID**、**プロファイル名**、**作成者名**、**作成者のメールアドレス**があります。メールアドレスのないプロファイルには、リストに `⚠` が付きます。有効なプロファイルがない場合、または名前かメールアドレスが空のプロファイルの場合は、git 自身の `user.name` と `user.email` が使われます。

プロファイルが 2 つ以上あると、ツールバーの右端にプロファイルのコンボボックスが表示されます。これはアクティブなリポジトリだけのプロファイルを設定します。選ぶと、その ID をそのリポジトリの git config にも書き込むかを尋ねるダイアログが表示されます。パレットのコマンドは **リポジトリ: プロファイルを変更...** です。

これらのプロファイルは、「連携」ページのホスティングのプロファイルでも、「AI」ページの AI のプロファイルでもありません。

### SSH と認証情報

![「SSH と認証情報」ページ](../images/settings-ssh.png)

SSH はシステムの `ssh` を使うため、ssh-agent と ssh の設定はそのまま使えます。GitPoulpi が鍵の内容を読むことはありません。

| オプション | 働き |
|---|---|
| **秘密鍵のパス** | 設定すると、fetch、pull、push、clone は `GIT_SSH_COMMAND=ssh -i "<key>" -o IdentitiesOnly=yes` を付けて git を実行するため、ssh はその鍵だけを提示します。空の場合：エージェントと ssh の設定がそのまま適用されます。 |
| **公開鍵のパス** | 秘密鍵のパスが空のときだけ使われます。ssh が、ssh-agent（またはハードウェアキー）が保持する対応する鍵を選びます。 |
| **鍵の種類** | **鍵ペアを生成**が作る種類：`ed25519`、`rsa`（4096 ビット）、`ecdsa`（NIST P-256）。 |
| **HTTPS 認証情報** | HTTPS 経由の fetch、pull、push、clone の認証方法：**credential_helper**（git 自身のヘルパー、既定）、**prompt**（ヘルパーを無視し、git がターミナルで尋ねます）、**none**（認証情報なし、公開リモートのみ）。 |
| **すべてのユーザー名とパスワードを削除** | GitPoulpi が認証情報ヘルパーに保存したトークンをすべて削除します。先に確認されます。 |
| **鍵ペアを生成** | **鍵の種類**の鍵ペアを、パスフレーズなしで `~/.ssh/gitpoulpi_<type>` に作成し、2 つのパスを記録します。既存のファイルを上書きすることはありません。 |

鍵のパスは次の転送から有効になります。先頭の `~/` はホームフォルダーを意味します。

他の場所で行った設定は、常にこれらのパスより優先されます。優先順位は高い方から次のとおりです。

1. GitPoulpi が動作している環境の `GIT_SSH_COMMAND` または `GIT_SSH`。
2. リポジトリの git config、またはグローバルの git config にある `core.sshCommand`。タブメニューの *SSH key...* が、1 つのリポジトリに対してこれを書き込みます。
3. このページの 2 つの鍵のパス。
4. ssh 自身の既定値とエージェント。

鍵はホスティングのアカウントに属させることもできます。[ホスティングと Issue トラッカー](hosting-integration.md)を参照してください。

### 連携

![「連携」ページ：左にプロバイダー、GitHub の接続ボタン](../images/settings-integrations.png)

アカウントを接続します。**ホスティング**のグループには、GitHub、GitHub Enterprise、GitLab、GitLab Self-Managed、Azure DevOps、Azure DevOps Server、Bitbucket、Bitbucket Data Center、Gitea、Forgejo、Gerrit があります。**Issue トラッカー**のグループには、Jira Cloud、Jira Data Center、Trello、Linear、YouTrack、Redmine、Local Markdown があります。各プロバイダーには、**接続**、トークンのフィールド、トークンに必要なスコープ、ホストのトークンページへのリンクがあります。このページには専用のガイドがあります：[ホスティングと Issue トラッカー](hosting-integration.md)。

プロバイダーの上に 2 つのオプションがあります。最初のプロバイダーで `Up` を押すと移動できます。

| オプション | 働き |
|---|---|
| **pull request と Issue の更新間隔** | サイドバーの一覧とツールバーのチップを更新する間隔です。数値と単位（分または時間）で指定します。既定は 5 分、最大 2 時間、`0` でタイマーがオフになります（`general.hosting_refresh_minutes`、`general.hosting_refresh_unit`）。 |
| **レビュー依頼の用語** | ホスト上のレビューに使う用語：**自動（ホストごと）**、**Pull Request**、**Merge Request**。 |
| **Pull Request が閉じられた、または merge 済みのときはチップを隠す** | 既定でオン（`ui.hide_finished_pr_chip`。GitLab では「merge request」と表示されます）。ツールバーのチップには、チェックアウト中のブランチの最新のリクエストが表示されます。オンにすると、そのリクエストが閉じられるか merge 済みになった時点でチップが隠れ、ブランチにリクエストがないときと同じく、薄い **+ PR** チップ（新しいリクエストを開始）が表示されます。オフの場合は、状態にかかわらず常に最新のリクエストを表示します。すぐに反映されます。 |

### AI

### エージェントと MCP

AI エージェントがこのウィンドウで行えることと、MCP サーバーを動かしてよいかどうかを設定します。2 つの MCP の行は、サーバーを含むビルドでのみ表示されます。[MCP とエージェント](mcp-and-agents.md)を参照してください。

| オプション | 働き |
|---|---|
| **MCP サーバー** | オン（既定）：エージェントがサーバー（`gitpoulpi mcp serve`）を起動できます。オフ：起動を拒否します。`mcp.enabled` として保存されます。変更は、次にエージェントがサーバーを起動するときに反映されます。すでに起動中のサーバーは、起動時の設定のままです。 |
| **MCP サーバーのポート** | アドレスを指定しないときに `--http` が待ち受けるポートで、1 から 65535（既定は 8808）。`mcp.bind` のポート部分に保存され、ホスト部分は維持されます（空のときは `127.0.0.1`）。次にエージェントがサーバーを起動するときに反映されます。 |
| **AI エージェントによる表示の操作を許可** | エージェントが、このウィンドウに commit、ファイル、通知を表示できるようにします（`ui show`）。オフの場合、どのエージェントもウィンドウに届きません。 |
| **AI エージェントの変更提案を確認できるようにする** | エージェントが、ユーザーが確定する入力済みの Reword、commit、ブランチ、tag のダイアログを開けるようにします。既定ではオフです。[MCP とエージェント](mcp-and-agents.md)を参照してください。 |
| **エージェント用ウィンドウを開く**、**起動コマンド（custom）** | GitPoulpi のウィンドウが開いていないときに、エージェントがウィンドウを開いてよいか、またどのターミナルやマルチプレクサで開くかを設定します。既定ではオフです。 |

### ログとグラフ

commit グラフの描き方と、ログが読み込む commit 数を設定します。グラフの色は**外観**ページにあります。

| オプション | 働き |
|---|---|
| **グラフの描画方式** | **auto** は、ターミナルが対応していれば画像で、そうでなければ文字で描画します。**image** は画像を強制し、**text** は文字を強制します。再起動が必要です。 |
| **画像プロトコル** | 画像をターミナルへ送る方法：**auto**、**kitty**、**iterm2**、**sixel**、**none**。再起動が必要です。 |
| **グラフにstashを表示** | ログに stash ごとの行を表示します。オフの場合：stash はサイドバーにだけ表示されます。 |
| **ホバー中のcommitに、ブランチの仮表示を出す** | 既定でオン（`ui.graph_ghost_ref`）。Ref 列に余裕があれば、自分の ref を持たないホバー中の commit に、履歴から推定した所属ブランチ（なければリモートブランチ）の名前を淡いピルで表示します。merge の後に削除されたブランチも、merge commit の件名にある名前で、取り消し線付きで表示されます（`Merge branch 'x'`、`Merge pull request #N from owner/x` など）。squash merge、rebase、fast-forward ではそのような痕跡は残りません。tag が仮表示されることはありません。ピルにホバーすると種類が表示されます。クリックしても特別なことは起きません。ブランチの作成はパレットのコマンド `Git: 選択中のcommitにブランチを作成...` で行います。 |
| **参照とcommitの接続線** | 参照のラベルからその commit の点へ細い線を引きます。 |
| **列のサイズ変更** | `ui.column_resize`。Log、Radar、diff・ファイル・Blame の各ビューの commit 列にすぐ反映されます。**線**（既定）：各列の境界は 1 セル幅の隙間で、ヘッダーに小さな目印があり、ポインターが境界にある間は表全体にアクセント色の細い線が描かれ、線に沿ってどこからでもドラッグしてサイズを変えられます。**ヘッダー**：目印はなく、境界の次のヘッダーセルの最初の文字が光り、そこだけがドラッグの起点です。サイズ変更のキー（Log は `Shift+C`、Radar は `C`、commit 列は `Tab`）は、どちらでも同じ動作です。 |
| **変更列が非表示のとき、メッセージに WIP の変更数を表示** | WIP 行のメッセージに変更数（`✎ 3  + 2  − 1`）を表示します。変更列が表示されているときは、その列に数が入ります。 |
| **ブランチのフォルダーツリー** | サイドバーで、`/` を含むブランチ名とタグ名をフォルダーにまとめます。Refs ペインの `y` で切り替わります。 |
| **左ペインのセクション** | 左ペインの表示 / 非表示のセクションを、誰の設定にするか：**リポジトリ別**（既定。各リポジトリが独自の設定を持ち、グローバルの設定が出発点になります）または**グローバル**（すべてのリポジトリで共通）。切り替えても、どちらの設定も残ります。[マウスとジェスチャー](mouse-and-gestures.md)を参照してください。（`ui.sidebar_sections_scope`） |
| **参照をクリックしてグラフに表示** | Refs ペインで参照を 1 回クリックすると、ログがその指す位置までスクロールして行が点滅します（commit の選択と右側のパネルは変わりません）。オフの場合：クリックはサイドバーの行を選択するだけです。**グラフで表示**はどちらの設定でも使えます。 |
| **コンポーザーの提案** | AI commit コンポーザーが、各提案のファイルを**展開**または**折りたたみ**で開くかどうかを設定します。 |
| **グラフの初期commit数** | リポジトリを開いたときに、ログが読み込む commit 数です。既定は 5000、最小は 500。値を大きくすると、大規模なリポジトリが遅くなります。 |
| **グラフのcommitを遅延読み込み** | オン：読み込み済みの最も古い commit までスクロールすると、バックグラウンドでさらに commit を読み込みます。オフ：ログは最初の commit で止まります。 |
| **遅延読み込み 1 回あたりのcommit数** | バックグラウンドの 1 回の読み込みで取得する commit 数です。 |
| **グラフの最大commit数** | 遅延読み込みがこの数で止まります。`0` は無制限です。commit 1 件につき約 300 バイトのメモリを使います。 |
| **commitの総数の数え方** | ステータスバーの `読み込み済み / 総数` の総数を求める方法です（`log.commit_count`、ドロップダウン、すぐに反映されます）。**System git** は `git rev-list --count` のプロセスを 1 つ実行します（既定。通常は最速）。**libgit2** は GitPoulpi の内部で数え、プロセスを起動しません。ウイルス対策ソフトがすべてのコマンドをスキャンして git の呼び出しが毎回遅くなるマシン向けです。**オフ**は数えず、読み込み済みの commit だけを表示します。 |
| **作成者を .mailmap 経由で表示** | Log、blame、ファイル履歴で、各作成者をリポジトリの `.mailmap` が指定する名前で表示します（`log.use_mailmap`。スイッチで、既定はオン。すぐに反映されます）。保存済みの commit は変更されません。オフにすると、commit されたときの名前が表示されます。`history-rewrite.md` の*名義タブ*を参照してください。 |

### 開く場所

![「開く場所」ページの「項目」タブ：エントリのリスト、編集中のエントリ（ラベルとコマンド）、「+ 追加」ボタン](../images/settings-open-in.png)

タイトルバーの**開く場所**ボタンの一覧を編集します。**一般**タブには**終了して cd** のフォルダーボタン、**既定のエントリ**、**検出された既定値を復元**があります。**項目**タブは[リスト](#リスト)（それぞれラベルとコマンド）で、**+ 追加 ▾** からプリセットと**カスタム**を追加でき、既定のエントリには `★` が付きます。選択中のエントリのフィールドには**テスト**ボタンがあります。[開く場所](open-in.md)を参照してください。

最初の行 **アクティブなタブのフォルダーに追従** には 2 つの値があります。

- **ボタン**（`buttons`、既定）：アクティブなタブが GitPoulpi を起動したフォルダーでないとき、タブバーに**終了して cd** を表示します。
- **auto**：ボタンなし。終了のたびにシェルのフォルダーがアクティブなタブに変わり、新しいタブを開くと既定の「開く場所」のエントリを実行します。

### 画像

画像ファイルの表示方法と、**編集に使う**が使うプログラムを設定します。[画像](image-view.md)を参照してください。**一般**タブには下の表示オプション、**既定のエントリ**、**検出された既定値を復元**があり、**エディター**タブは画像エディターのリストです。画像プレビューのないビルドには表示オプションがありません。

| オプション | 働き |
|---|---|
| **画像をプレビュー** | 画像ファイルを、Diff ビューとファイルビューで画像として表示します。オフの場合：ふつうのバイナリの通知。既定でオンです。 |
| **画像プロトコルがない場合** | インライン画像のプロトコルがないターミナルで：**半ブロックの色**（既定）または**情報カードのみ**。 |
| **プレビューの最大サイズ** | これより大きい画像はデコードされず、代わりに情報カードが表示されます。数値と MiB または GiB で指定します。既定は 32 MiB、最大 1 GiB（`ui.image_view_max_mib`、`ui.image_view_max_unit`）。 |
| **ピクセル表示にする倍率** | `1x`、`2x`（既定）、`never`：この倍率から、滑らかにせず四角いピクセルで表示します。 |
| **前後のズームとスクロールを同期** | 画像の diff の 2 つのペインが、ズームとスクロール位置を共有します。既定でオンです。 |

**エディター**タブは、[開く場所](open-in.md)と同じ[リスト](#リスト)です。エディターごとに**ラベル**、**コマンド**、変数のチップ `${file}` `${dir}` `${name}` `${repo}`、**サンプル画像でテスト**があります。**+ 追加 ▾** でプリセットと**カスタム**を追加でき、**検出された既定値を復元**でリストをリセットします。編集するまでは、このマシンにインストールされているエディターとシステムの既定アプリが一覧に入っています。変更はすべてすぐに反映されます。

### キーボードとマウス

![「キーボードとマウス」ページ：コンテキストごとのすべてのアクションとそのキー、検索ボックス、フィルター](../images/settings-keyboard.png)

**設定 > キーボードとマウス**には 2 つのタブがあります（クリック、または `Alt+Left` / `Alt+Right`）。**一般** にはキーボードプロトコルとマウスの設定があり、**キー割り当て** には、すべてのショートカットがコンテキストごとに、検索ボックス（`/`）とフィルター付きで一覧表示されます。行では次の操作ができます。

| キー | 操作 |
|---|---|
| `Enter` またはダブルクリック | 新しいキーを取り込みます。押している間に、競合とターミナルの警告が表示されます。 |
| `a` | 別のキーを追加します。 |
| `u` | アクションの割り当てを解除します。 |
| `r` | 行を既定に戻します。 |

| `c`、または行の `!` をクリック | その操作と、キーが競合するすべての操作を表示します。`Esc` で全件表示に戻ります。他の操作と競合するキーは赤、キー単独の警告（ターミナルが送れないなど）はオレンジで表示されます。 |

### リポジトリ別：スパースチェックアウト

スパースチェックアウトのダイアログ（`リポジトリ: スパースチェックアウト...`）と同じ操作を、このリポジトリの設定のページとして表示します（`gitpoulpi ui show settings sparse-checkout`）。

| オプション | 働き |
|---|---|
| **状態** | この作業ツリーがスパースチェックアウトかどうか。 |
| **残すディレクトリ** | リポジトリのルートからの相対パスで、1 行に 1 ディレクトリ。`Enter`（またはクリック）で複数行のエディターが開きます：`Ctrl+S` でテキストを確定、`Esc` で破棄します。スパースチェックアウトがオンの間は、現在のディレクトリが表示されます。git のコーンモードはディレクトリしか扱えず（パターンや単独のファイルは不可）、ルート直下のファイルは常にチェックアウトされ、空の一覧は拒否されます。 |
| **スパースチェックアウトを開始** | 一覧にあるディレクトリだけをチェックアウトします。スパースチェックアウトがオンになると、同じボタンが**ディレクトリ一覧を適用**に変わり、編集した一覧を適用します：一覧から外したディレクトリは作業ディレクトリから削除されます。一覧が空の間は押せません。 |
| **スパースチェックアウトを終了** | 通常のチェックアウトに戻します：すべてのファイルが戻ります（確認あり）。スパースチェックアウトがオフの間は押せません。 |
| **スパースチェックアウトを更新** | 現在の一覧をもう一度適用します（たとえば、スクリプトや別のツールが一覧の外のファイルをチェックアウトしたあとなど）。送られるのは現在のディレクトリで、入力欄の未送信のテキストではありません。スパースチェックアウトがオフの間は押せません。 |

ボタンはふつうのバックグラウンド操作として実行されます（実行中はページに「スパースチェックアウトを適用しています...」と表示されます）。ダイアログと同じく元に戻す履歴の対象ではありませんが、失われるものはなく、**スパースチェックアウトを終了**ですべてのファイルが戻ります。

### リポジトリ別：LFS

このリポジトリの LFS の状態です（`gitpoulpi ui show settings lfs`。LFS のないビルドにはありません）。

- **初期化されていない場合：**「`<repository>` では Git LFS がセットアップされていません」と **ここで LFS をセットアップ** ボタンが表示されます。このボタンは `git lfs install --local` を実行します（このリポジトリのフィルターとフックだけで、グローバル設定には触れません。`git-lfs` が必要です）。リポジトリの `.gitattributes` がすでにファイルを LFS 経由にしているのにフックがない場合は、ページにその旨が表示されます。
- **初期化されている場合：**「`<repository>` では Git LFS がセットアップ済みです」と、`.gitattributes` で追跡しているパターン（`filter=lfs`）が表示されます。

このリポジトリに独自の LFS フック（`git lfs install --local` が書き込む `pre-push` または `post-checkout` フック）があれば、LFS は**初期化済み**とみなされます。フィルターだけでは判定しません：ユーザーレベルの `git lfs install` はすべてのリポジトリにフィルターを設定するため、どのリポジトリも初期化済みに見えてしまうからです。

ツールバーの **`LFS ▾`** ボタンも同じ状態に従います。LFS が初期化されているか、`.gitattributes` がすでに LFS を使っているリポジトリでだけ表示され、ふつうのリポジトリでは隠れたままです（リポジトリで最初の LFS の読み取りが済むまでも隠れているため、リポジトリを開いてから少し遅れて現れることがあります）。このページで初期化すると表示されます。`LFS:` のパレットコマンドは、**LFS: このリポジトリで初期化**も含めて、どこでも使えます。

### リポジトリ別：commit

このリポジトリでの commit の動作を設定します（`gitpoulpi ui show settings commit`）。2 つのスイッチはどちらも既定で**オフ**で、このリポジトリにだけ保存されます（[`repo-state.toml`](config-reference.md) の `[preferences]`）。

| 設定 | 働き |
|---|---|
| **commitのたびにpush** | commit に成功したら、チェックアウト中のブランチをアップストリームへふつうの push として push します（進捗を追跡できる転送で、実行中の表示は「commit してから push しています...」）。アップストリームのないブランチは commit だけが行われ、push はされません。その旨が通知されます：新しいブランチの最初の push は、アップストリームを設定する **Push** ボタンの役目のままです。push が拒否された場合は、いつもの push 拒否のカードが開き、commit は残ります。 |
| **commitのたびに git フックを既定でバイパス** | commit フォームの**フックをスキップ**チェックボックス（**直前の commit を修正（Amend）**の隣。Status ペインでは `Shift+H`、パレットでは **Commit: フックのスキップを切り替え**）が最初からオンになり、`pre-commit` と `commit-msg` のフックが実行されません（`git commit --no-verify`）。これは commit ごとの選択のままで、commit のあとはこの既定値に戻ります。 |

既定のままなら、GitPoulpi がどのバックエンドを使っていても、リポジトリの commit フックは commit のたびに実行されます（commit フックのあるリポジトリは、libgit2 がフックを一切実行しないため、システムの `git` 経由で commit されます）。フックが失敗すると、その出力はアクティビティログの項目に表示され（ステータスバーには commit に失敗したと表示されます）、何も commit されません。

### リポジトリ別：merge オプション

スイッチは 1 つ、**Squash**（既定ではオフ）です。オンにすると、ローカルブランチの merge（ブランチのメニュー、ドラッグ＆ドロップ、パレットの `Merge`）は、merge commit を作らずにそのブランチの変更をステージします（`git merge --squash`）：commit は自分で行うことになります。commit フォームは、squash ごとに 1 回、git の squash メッセージ（`SQUASH_MSG`、コメント行は除去）が入った状態で開きます。その後は進行中の操作が何もないため（`MERGE_HEAD` なし）、**中止**は使えません。取りやめるには、ステージした変更を破棄してください。squash が競合で止まった場合は、競合した merge と同じく、競合が Status ペインに残ります。ステージされた変更は元に戻す履歴の項目になりません（動いた ref がなく、復元するものがないため）。CLI の `gitpoulpi merge <branch> --squash` は、この設定にかかわらず同じことを行います。

### リポジトリ別：メッセージテンプレート

commit フォームの初期メッセージを設定します（`gitpoulpi ui show settings commit-template`）。

- **空のCommitパネルにテンプレートを事前入力**：*空の* commit フォームに、commit ごとに 1 回テンプレートが入ります（手で消した場合は、次の commit まで尊重されます）。
- **commitの作成時にコメント行を削除**：commit するとき、`#`（またはリポジトリの `core.commentChar`）で始まる行がメッセージから除かれます。`git commit --cleanup=strip` と同じです。GitPoulpi は git が整形しない `-m` で commit するため、自分でこの処理を行います。スイッチがオフなら、`#` の行は commit に残ります。
- **概要**（ラベルには、72 桁までの残りと超過した桁数が表示されます）と、複数行の**説明**（`Enter` またはクリックでエディターが開き、`Ctrl+S` で確定）。
- **テンプレートを保存**は、テンプレートをリポジトリのデータフォルダー（`session.per_repo_state_dir` を参照）の `commit-template.txt` に書き込み、このリポジトリの `commit.template` をそのファイルに設定します。これにより、コマンドラインの `git commit` やほかのツールでも使われます。`commit.template` がすでに別のファイルを指している場合、ページにはそのファイルのパスが表示され、設定には触れずに*そのファイル*を編集します。

### リポジトリ別：競合の予防

`gitpoulpi ui show settings conflict-prevention`。このリポジトリの競合の事前検出のページです（[merge の競合を解決する](merge-conflicts.md#競合の予防)を参照）。

- **競合の事前検出を有効化**（ターゲットブランチとの）：既定でオン。オフにすると、このリポジトリだけ検出が無効になります。全体のスイッチは、「一般」ページの**競合の事前検出を有効化**です。検出にはどちらもオンである必要があります。
- **ベースブランチ**（既定は `**`）：現在のブランチの派生元になりうるブランチを、1 行に 1 パターンで指定します（`Enter` またはクリックでエディターが開き、`Ctrl+S` で確定）。その下のパターン表が一覧の見本です。

  | パターン | 一致するもの |
  |---|---|
  | `origin/main` | そのブランチのみ |
  | `origin/**` | リモート `origin` のすべてのブランチ |
  | `origin/feature/**` | `origin` の `feature/` で始まるブランチ |
  | `!origin/abc` | そのブランチを除外 |

  ローカルブランチは名前そのまま（`main`）、リモート追跡ブランチは先頭にリモート名を付けます（`origin/main`）。`*` と `?` は 1 つのパスセグメント内にとどまり、`**` はセグメントをまたぎます。空行と `#` のコメントは無視されます。除外だけの一覧は「これらを除くすべてのブランチ」の意味になります。値は `repo-state.toml` に保存され、設定を閉じたときに読み直されます。

### リポジトリ別：AI

![リポジトリの「AI」ページ：リポジトリの指示（全体に追加または全体を置き換え）と、アクションごとのプロファイルと指示](../images/settings-repo-ai.png)

このリポジトリの AI プロファイルとアクションごとの指示、およびこのリポジトリのすべてのアクションに適用される*リポジトリの指示*です。空のフィールドは、全体の AI 設定を使います。[AI アシスタント](ai.md#指示)を参照してください。*コードレビュー*ブロックには、レビューのコンテキストの 4 つの行が繰り返されます：各選択は*全体を使用（値）*から始まって全体の値を表示し、空の**追加ファイル**には全体の値がグレーで表示されます（同じ **参照...** ボタンがあり、ピッカーはリポジトリのルートから始まります。リポジトリ内のファイルはルートからの相対パスで保存されます）。**追加ファイルなし**のスイッチは、このリポジトリでは全体の追加ファイルをオフにします。空のフィールドは引き続き全体の値に従います。**全体にリセット**（リポジトリ固有の値ができると表示されます）は、すべてを元に戻します。これらはこのリポジトリの `repo-state.toml` に保存されます。

### リポジトリ別：ワークフロー

`gitpoulpi ui show settings workflow`。このリポジトリのブランチワークフロー（テンプレート、検出、基点ブランチ）には専用のガイドがあります：[ブランチワークフロー](branching-workflows.md#設定--ワークフロー)。**一般**タブには、ルール以外のもの（テンプレート、検出、フック、Issue フロー、保存先）があり、**ルール**タブはグループ分けされた[リスト](#リスト)（**ベースブランチ**、**トピックの種類**、**完了ルール**）で、**+ 追加 ▾** で種類を選び、項目はグループ内で移動します。ほかのページと違って下書きを保持します（バーは両方のタブにあります）。ページの下部に固定されたバーに **● 未保存**（または**変更なし**）と、**保存先：.gitpoulpi/workflow.toml（共有）**、**自分だけに保存**、**変更を破棄**が表示され、未保存の下書きがある状態で設定を閉じようとすると、先に確認されます。

## ファイル、環境変数、CLI
