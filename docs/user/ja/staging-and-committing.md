# ステージと commit

何を変更したかを確認し、commit に入れるものを正確に選び、commit を書き、ファイルをさらに詳しく見る（blame、履歴、組み込みエディター）方法を説明します。*WIP 行* や *ハンク* といった用語は、[インターフェースツアー](interface-tour.md)で説明しています。

## 作業中の変更

未 commit の作業は **ログの最初の行**です（破線の円、`// WIP`、変更ファイル数 `✎ n` と追加ファイル数 `+ n` のカウンター付き）。選択すると、右ペインに作業中の変更が表示されます。

![作業中の変更：右に未ステージとステージ済みのファイル、その下に commit フォーム](../images/hero.png)

- **未ステージのファイル**：編集、追加（未追跡）、削除されたファイルのうち、次の commit にまだ入っていないものです。
- **ステージ済みのファイル**：次の commit に含まれるものです。
- **競合したファイル**（赤い `!`。merge、rebase、cherry-pick、revert が止まっている間）：`Enter` で merge エディターが開きます。[merge 競合の解決](merge-conflicts.md)を参照してください。
- **名前変更または移動されたファイル**は、どちらの一覧でも `新 <- 旧` の 1 行になります（ディスク上で削除されたファイルと、内容が 50% 以上同じ新しいファイルは、ステージする前でも移動とみなされます）。ステージ、ステージ解除、破棄は両方の名前に作用します。ステージすると削除と新しいファイルがステージされ、git からは 1 回の名前変更に見え、取り消しも 1 ステップです（`Undo Stage rename 旧 -> 新`）。その行を開くと旧名との内容の diff が表示され、先頭は `旧 -> 新（N% 類似）` です。編集のない移動では**内容の変更なし**と表示されます。commit のファイルも同様で、`gitpoulpi status` と `gitpoulpi diff` は `renamed_from` を報告します。
- **パス**または**ツリー**（`m`）で、ファイルを一覧表示するかフォルダーごとに表示するかを切り替えます。**すべて折りたたむ**（`z`）でフォルダーを折りたたみます。**すべてのファイルを表示**（`a`）は、変更されたファイルだけでなくツリー全体を表示します。一覧の空白部分を右クリックすると **すべて展開** / **すべて折りたたむ**、フォルダーの行では **すべてのサブフォルダーを展開** / **すべてのサブフォルダーを折りたたむ** が使えます。キーは `=`、`-`、`*`、`_` です（[マウスとジェスチャー](mouse-and-gestures.md)を参照）。折りたたまれたフォルダーには、名前の後ろに、サブフォルダーを含む中のファイル数が小さな薄い数字で表示されます（`src/ (12)`）。開いているフォルダーには表示されません。幅の狭いペインでは、数が見えるように先に名前が短縮されます。Git LFS で保存されたファイルのあるリポジトリでは、**LFS のみ**チェックボックス（`o`、または **ファイル: LFS のみ表示を切り替え**）が、すべてのファイル一覧（Unstaged、Staged、**すべてのファイルを表示**、commit のファイル）をそれらのファイルだけに絞り込みます。フォルダーの数もそれに従い、LFS を使うファイルがないときは表示されません。
- タイトルには、どのブランチで何ファイルが変更されたかが表示されます。

### ステージ、ステージ解除、破棄

| やりたいこと | 操作 |
|---|---|
| ファイルをステージする | 行にカーソルを合わせて**ファイルをステージ**をクリックするか、選択して `Ctrl+Space` を押す、または `Ctrl+G s` |
| フォルダーをステージする | フォルダー行の**フォルダーをステージ** |
| すべてをステージする | セクションタイトルの**すべての変更をステージ**、または `Ctrl+G a` |
| ステージ解除する | ステージ済みセクションにある同じボタンとキー（`Ctrl+G u`） |
| ファイルの変更を破棄する | ファイルを右クリックして**変更を破棄...**（先に確認します。`Ctrl+Z` で変更を元に戻せます） |

### 機密ファイル

ファイル、フォルダー、またはすべてをステージするときは、先にそれによって何が追加されるかを確認します。名前が `[privacy] sensitive_patterns` に一致するファイル（`.env` と `.env.*`（`.example`、`.sample`、`.template` を除く）、`*.pem`、`*.key`、SSH 秘密鍵、`*.p12`、`*.pfx`、`*.jks`、`*.keystore`、`*.crt`、`*.cer`、`*.der`、`*.kdbx`）や、スキャナーが認識するシークレットを本文に含むファイルは、ステージされません。**機密ファイル**の確認では、各ファイルと理由（パターン、またはシークレットの種類とマスクしたプレビュー。値そのものは表示しません）が一覧表示され、**1. それでもステージ**か **2. キャンセル（何もステージしない）**を選べます。矢印キーか数字キーを押すまでどの回答も強調表示されないので、うっかり Enter を押しても何も回答したことになりません。`Esc`、閉じる ✕、外側のクリックはキャンセルです。ファイル内で見つかったシークレットには、その行が示されます（`config/app.env:12`）。決める前に確認するには、検出項目をクリックし（または `Tab` / `Shift+Tab`、`Ctrl+J` / `Ctrl+K` で移動し）、**ファイル内で表示**ボタン、`S`、またはパレットの**機密ファイル: ファイル内で表示**を押します。ファイルがファイルビューで開いてその行までスクロールされ、行が強調表示されます。ファイルビューを閉じる（`Esc`）と、確認は手つかずのまま戻ります。確認しても何もステージされません。キーボード、ボタン、メニュー、パレット、ドラッグ＆ドロップのどれから行っても同じ確認が出ます。すべて同じリクエストを送るためです。キャンセルすると、同じステージに含まれる通常のファイルも含めて、何もステージされません。

テキストファイルは 1 つあたり 1 MiB まで、合計 32 MiB まで読み取ります。それより大きいファイルとバイナリファイルは、名前だけで判断されます。`[privacy] staging_guard = false` でこのチェックをオフにできます。1 つのハンクや一部の行のステージはチェックされません。すでにそのファイルを作業中だからです。

ファイルを右クリックするとメニューが開きます。ステージまたはステージ解除、破棄、パスのコピー、ファイルの履歴と blame、外部エディター・diff ツール・ファイルマネージャーで開く（[設定 > diffとエディター](settings.md#diffとエディター)で設定します）などがあります。

## ファイルの無視と、バイナリ／テキストとしての扱い

ファイルを右クリック > **無視** でそのファイルまたは拡張子を無視し、フォルダー行では **フォルダー内のすべてのファイルを無視** を選びます。GitPoulpi はまず、ルールをどのファイルに書くかを尋ねます。リポジトリのルートの `.gitignore`（既定）、ファイルのフォルダーまでの各フォルダーの `.gitignore`、または `.git/info/exclude`（このクローンのみ、commit されません）です。まだ存在しないファイルには「新規」と表示され、確定すると作成されます。行は選んだファイルからの相対パスで書かれ、`src/a/b.txt` は `src/.gitignore` では `/a/b.txt` になります。矢印キーで移動し、入力で一覧を絞り込み、`Enter` で書き込み、`Esc` でキャンセルします。`.gitignore` への書き込みは `Ctrl+Z` で元に戻せます。`.git/info/exclude` は作業ツリーの外にあるため元に戻せません。

![無視ルールの書き込み先を尋ねる一覧：リポジトリの .gitignore、ファイルのフォルダーの .gitignore、または .git/info/exclude。それぞれ書き込まれる行つき](../images/ignore-picker.png)

ファイルを右クリック > **バイナリとして扱う**（git がすでにバイナリとして扱っている場合は **テキストとして扱う**）で、`.gitattributes` のルール（`binary` または `text diff`）を書き込みます。ファイル自体か同じ拡張子のすべてのファイルを選び、次に上と同じ一覧で書き込む `.gitattributes` を選びます（このクローンのみなら `.git/info/attributes`）。同じパターンに対して既に書かれたルールは、矛盾させずに置き換えられます。ファイルの diff はすぐに更新され、ステータスバーには何をどこに書いたかが表示されます（別のルールが優先される場合は警告も出ます）。フォルダー行には **フォルダー内のファイルの扱い** > **バイナリ** / **テキスト** があります。コマンドパレット（**作業中の変更: 選択中のファイルをバイナリとして扱う...**）とコマンドライン（`gitpoulpi treat binary|text <パス>`）でも同じことができます。ファイルビューもこのルールに従います。テキストとして扱うファイルは、NUL バイトを含んでいても行を表示し、git が binary として diff するファイルはバイナリの通知を表示します。

## ファイル一覧のメニュー、複数選択、変換

右ペインのファイル一覧（Unstaged、Staged、commit の変更ファイル、**すべてのファイルを表示**）は同じメニューと操作を共有します。ファイル、フォルダー行、一覧の空白部分を右クリックするか、フォーカスのある行で `.`（`Shift+F10`、メニューキー）を押すか、パレットで **ファイル: 行または選択範囲のメニューを開く** を実行します。

- **commit のファイル**（および**すべてのファイルを表示**のファイル）：**Diffを開く**、**ファイルを開く**、**ファイル履歴**、**ファイル Blame**、エディター・既定のプログラム・**アプリで開く...** で開く、**フォルダーで表示**、**ファイルを編集**、**ファイルパスをコピー**、**ファイルのフルパスをコピー**、**無視**、**バイナリとして扱う** または **テキストとして扱う**、**変換**、**このcommitからファイルを復元**（先に確認します。`git checkout <commit> -- <ファイル>` と同様にファイルもステージされ、`Ctrl+Z` で以前のファイルに戻ります）、**ファイルを削除...**。作業コピーに関する行は、ファイルが作業ツリーにないとき、理由付きでグレー表示になります。**作業ツリーとのDiff**は、commit のバージョンとディスク上のファイルの差分を開きます。**ファイルの変更からパッチを作成...** は、そのファイルの commit 内の変更のパッチを書き出します（選択範囲とフォルダー行にもあります。作業中の変更の**すべてのファイルを表示**では、ファイルの作業ツリーの変更をパッチにします）。
- **フォルダー行**: **フォルダーを開く**、**ファイルパスをコピー**、**フォルダー内のすべてのファイルを無視**、**フォルダー内のファイルの扱い**、**変換**、**このフォルダーにファイルを作成**。
- **一覧の空白部分**: **ファイルを作成** と **リポジトリのフォルダーを開く**。Unstaged の一覧では **すべてステージ** と **すべての変更を破棄...** が、Staged の一覧では **すべてステージ解除** が加わります。

![commit のファイルを右クリックしたメニュー：diff、ファイル履歴、blame を開く、エディターや既定のプログラムで開く、パスのコピー、無視、変換、commit から復元、削除](../images/commit-file-menu.png)

### 複数のファイルを選択する

操作はログと同じです。**Ctrl+クリック**で行を選択に追加または除外します。**Shift+クリック**（Shift+クリックをターミナルが使う場合は **Alt+クリック**）で起点からの範囲を選びます。通常のクリックはやり直しで、従来どおり diff を開きます。`Esc` で選択を解除します。キーボードでは `Space` または `Insert` で、どのリストでも現在の行を切り替え（Unstaged と Staged では `Ctrl+Space` で選択範囲、または現在の行をステージします）、`Shift+Up` / `Shift+Down` で範囲を広げます。フォルダー行は、折りたたまれていても配下のすべてのファイルを選びます。選択された行は強調表示され、ステータスバーに数が表示されます。`Ctrl+A` はフォーカス中のリストのすべての行を選択します。

選択された行を右クリック（または `.`）すると、**N 個のファイル** という見出しの、選択全体のメニューが開きます：ステージ／ステージ解除、破棄、無視、バイナリ／テキストとして扱う、変換、パスのコピー、commit から復元、削除。ステージ、ステージ解除、復元はそれぞれ 1 回の操作です。破棄と削除は先に確認し、ファイル数を表示します。選択外の行を右クリックすると、その行で選択をやり直します。

![未ステージ一覧で 4 つのファイルを選択し、「4 個のファイル」の見出しのメニューを表示：ステージ、破棄、無視、バイナリまたはテキストとして扱う、変換、パスのコピー、削除](../images/file-pane-multiselect.png)

### エンコーディング、改行コード、インデントの変換

**変換** は、ファイル、フォルダー、選択のメニューにあります。コマンドラインでは `gitpoulpi convert` が同じことをします。

- **エンコーディング**: UTF-8、UTF-8 BOM、UTF-16 LE/BE、Windows-1252、ISO-8859-1、ISO-8859-15、Windows-1250、Windows-1251、KOI8-R、Shift_JIS、EUC-JP、GBK、Big5、EUC-KR。
- **改行コード**: LF、CRLF、CR。
- **インデント**: 行頭の空白をスペースまたはタブにします（タブ幅を指定）。

作業ツリーのファイルは、エディターのステータスバーと同じ関数でバックグラウンドで書き換えられます。有効な UTF-8 ではなくバイトオーダーマークもないファイルは、エディターと同様に Windows-1252 として読み込まれます。バイナリファイル、存在しないファイル、変換先のエンコーディングで表現できないファイルはスキップして報告され（*12 個のファイルを変換、3 個をスキップ（バイナリ 3）*）、壊れることはありません。書き込めないファイルがあると失敗の通知が出ます。バッチ全体が取り消しジャーナルの 1 件で、`Ctrl+Z` 1 回ですべてのファイルが元に戻ります。エディターで開いているファイルは、閉じるまで変換できません。

## diff を読む

ファイル名をクリックする（またはその上で `d` を押す）と、中央のログの代わりにそのファイルの diff が表示されます。`Esc` または `q` でログに戻ります。

![2 つのハンクがある diff。それぞれにハンクを破棄とハンクをステージのボタンがある](../images/diff.png)

上のバーで表示を切り替えます。

- **インライン**は 1 列の diff を表示し、**分割**は変更前と変更後を左右に並べます（`m` でレイアウトを順に切り替え）。
- **ハンク**（`Shift+H`）は、前後 1 行の文脈を付けて変更されたハンクだけを表示します。オフにするとファイル全体が見えます。
- **WS**（`s`）は、空白だけが異なる変更を隠します。
- **折返**（`w`）は、長い行を切り詰めずに折り返します。
- **Map**（`Shift+M`）は、スクロールバーの横にファイル全体のミニマップを表示します。クリックするとその位置へジャンプします。選択した単語の他の出現箇所には色が付き、スクロールバーにも印が付きます。
- `n` と `p`（またはバーの矢印）で、ハンク間を移動します。
- **自動**（最後のボタン、`Shift+C`）は、ファイルを読み込む文字コードです。クリックするか（`Shift+C` を押すか、パレットの*Diff: 文字コードを選択...*を実行して）、一覧から 1 つ選びます：先頭が**自動検出**、続いて UTF-8、UTF-8 BOM、UTF-16 LE と BE、Windows-1252、ISO-8859-1、ISO-8859-15、Windows-1250、Windows-1251、KOI8-R、Shift_JIS、EUC-JP、GBK、Big5、EUC-KR（入力で一覧を検索できます）。ファイルの両側がその文字コードで正確なバイト列として読み直されるため、Latin-1 のファイルではアクセントが、UTF-16 のファイル（git がバイナリと見なすもの）では行が表示されます。選択は、終了するまでそのファイルのパスについて記憶され、このビューと[レビュー](review.md)で共有されます。文字コードを選んでいる間、ハンクはこのビュー専用のものになるため、ステージと破棄は使えません（再びステージするには**自動検出**を選んでください）。読み込みに時間がかかると、少しした後にタイトルに*読み込み中...*と表示されます。

![同じ diff を分割レイアウトで表示したもの。変更前と変更後が左右に並ぶ](../images/diff-split.png)

テキストはマウスで選択でき（ドラッグ、または単語をダブルクリック）、`y` または `Ctrl+C` でコピーできます。コピーされるのはファイルのテキストだけで、行番号や `+`・`-` の記号は含まれません。

### ハンクまたは 1 行だけをステージする

作業ツリーの diff では、各ハンクのヘッダーに**ハンクをステージ**と**ハンクを破棄**があります（ステージ済み側では**ハンクをステージ解除**）。

- `Space` で、カーソル位置のハンクをステージします。
- 数行だけをステージするには、`v` で選択を開始し、`j`/`k` で移動して `Enter` を押します。対象になるのは*変更された*行だけです。
- `x` はハンクを、`Shift+X` は選択した行を破棄します。どちらも先に確認し、`Ctrl+Z` で変更を元に戻せます。
- ハンクを右クリック（または `.`）するとメニューが開きます。ステージ、ステージ解除、破棄、ファイルの履歴、blame、コピーがあります。

commit の diff は読み取り専用です。変更された画像は画像として表示されます。[画像](image-view.md)を参照してください。

## commit を書く

commit フォームは右ペインの下部にあり、その**概要**はログの作業中の変更の行にあるフィールドでもあります。どちらかに入力すると、もう一方にも反映されます。

![AI が書いたメッセージが入った commit フォーム：文字数カウンター付きの概要、説明、緑の commit ボタン](../images/ai-commit-message.png)

- **概要**（カウンターに 72 文字のうちの残りが表示されます）と**説明**。概要で `Enter` を押すと説明に移動し、説明で `Enter` を押すと改行されます。
- **{n} ファイルの変更をcommit**（緑のボタン）または `Ctrl+Enter` で、ステージ済みの変更を commit します。何もステージされていない場合、ボタンはその旨を表示し、何もしません。
- **直前のcommitを修正（Amend）**（`Shift+A`）は、ステージ済みの変更と新しいメッセージを最後の commit にまとめます。すでに push 済みの commit の場合は、その後に force push（with lease）が必要になります。
- **フックをスキップ**（`Shift+H`、またはパレットの **Commit: フックのスキップを切り替え**）は、リポジトリの `pre-commit` と `commit-msg` のフックを実行せずに commit します。commit ごとの選択で、**設定 > リポジトリ別の設定 > commit** で最初からオンにできます。**直前のcommitを修正（Amend）** のすぐ下に専用の行があり、完全なラベルで表示されます。ペインがとても狭いときだけラベルが**フック無し**に縮み、さらにチェックボックスだけになります（ツールチップに名前が出ます）。消えることはありません。フォームがとても低いときは、代わりに Amend の行を共有し、同じように縮みます。
- Status ペインの `c` で、キャレットがフォームに移動します。`Esc` で離れます。
- `Ctrl+G c` と `Ctrl+G Enter`（パレットの **Git: Commit...** と **Git: ステージ済みの変更を今すぐCommit**）は同じコマンドで、どこからでも使える commit ボタンです。フォームに概要があり、何かがステージされていれば、すぐに commit します。**直前のcommitを修正（Amend）** と **フックをスキップ** に従い、フォーカスは動かしません。そうでない場合は何も commit せず、キャレットをフォームの概要に移し（ペインが非表示または折りたたまれていれば表示します）、ステータス行にどのショートカットで commit できるかを表示します（既定は `Ctrl+Enter`）。何もステージされていないときは、その旨を伝えます。ステータス行に文字を入力することはありません。AI のリクエストがまだ実行中のときは何も commit せず、その旨を表示します（`Esc` でリクエストを中止します）。`Ctrl+Z` でほかの commit と同じように取り消せます。
- リポジトリごとに、[設定](settings.md#リポジトリ別commit)で **commit のたびに push** する、**commit テンプレート**でフォームを始める（メッセージから `#` のコメントも取り除く）、merge を **squash** にする、を選べます。squash にすると、フォームは git の squash メッセージが入った状態で開きます。
- ホスティング連携がリンクされていれば、フォームで `Alt+R` を押すと Issue の参照が挿入されます。[ホスティングと Issue トラッカー](hosting-integration.md)を参照してください。

[AI](ai.md) がオンの場合、概要の右にある **`✦`** ボタンが、ステージ済みの変更からメッセージを書きます（`Ctrl+G i`）。**AI でcommitを構成**は、作業内容を複数の commit に分割します（次の節）。テキストはフォームに入るので、自分で編集できます。commit ボタンを押すまで、何も commit されません。

**AI でcommitを構成**は Amend の行の右端にあり、右ペインが狭くなっても消えずに縮みます。完全なラベル、次に**AI で構成**、最後に **`✦`** だけになります。どの幅でもクリック、ツールチップ、キー（`Ctrl+G Shift+C`）はそのままです。

概要の行の右端にある **`✦`**（メッセージを生成）と **`#`**（Issue 参照を挿入）のボタンも同じように縮みます。ペインが狭いと余白がなくなり、次に 1 つの **`⋯`** ボタンにまとまってメニューに両方が並ぶので、どちらも消えることはありません。

## commit コンポーザー：変更を複数の commit に分ける

*（AI をオンにする必要があります。[AI アシスタント](ai.md)を参照。）* **AI でcommitを構成**を押します（または `Ctrl+G C`、あるいは作業中の変更の行を右クリック）。モデルが、ファイル付きの複数の commit を提案します。変更されたファイルはちょうど 1 つの commit に入り、無効な計画は 1 度だけモデルに差し戻されます。提案は、まだ何も commit されていない確認画面として開きます。

![commit コンポーザー：提案された 4 つの commit。それぞれファイルまで展開でき、上・下・編集・破棄のコントロールと、リセット、キャンセル、commit 4 件を作成のボタンがある](../images/composer.png)

| やりたいこと | 操作 |
|---|---|
| commit を展開または折りたたむ | `Left` / `Right`、または矢印をクリック。`*` ですべてを切り替え |
| commit を上または下へ移動する | 行の `▲` `▼`、または `Alt+Up` / `Alt+Down`（`K` / `J`） |
| ファイルを別の commit へ移動する | commit の上へドラッグする（一覧から、または右の作業中の変更の一覧から）。または、ファイルで `m` を押してドロップダウンから commit を選ぶ。あるいは、ファイルで `Alt+Up` / `Alt+Down` |
| ファイルを単独の commit にする | ファイルで `n`、または `+ 単独のcommit` ボタン |
| commit のメッセージを書き直す | 鉛筆、`e`、`Enter`、またはダブルクリック：メッセージを編集し、`Enter` で確定、`Esc` で破棄 |
| commit を除外する | `drop`（`d` または `Delete`）。そのファイルは未 commit のまま残ります。`復元` で戻せます |
| やり直す | **リセット**（`r`）でモデルの計画に戻ります |
| 作成する | **commit N 件を作成**（`Ctrl+S`、`Ctrl+Enter`、または `a`） |
| 終了する | **キャンセル**または `Esc`：何も行われません |

commit を作成すると、まずすべてがステージ解除され、その後 commit ごとにそのファイルをステージして commit するので、作業ツリーに触れることはありません。途中の手順が失敗すると、そこで止まり、いくつ commit が作られたかを表示します。ステージされるのはファイル全体です。一部だけステージされていたファイルも、全体が commit されます。コンポーザーが使うプロファイルと指示は、*設定 > AI* で選びます。[AI アシスタント](ai.md#commit-コンポーザー)を参照してください。

## ファイルビュー、Blame、ファイル履歴

ビューバーには**ファイルビュー**（ファイルの内容）、**Diff**、**Blame**、そして [Commit列](interface-tour.md#commit列)の `ファイル │ すべて` の切り替え（その `ファイル` の一覧がファイル履歴です）があり、ファイルの右クリックメニューにも同じものがあります。これらは、開いた元の commit の時点のファイルを表示します。作業中の変更から開いた場合は、未 commit（`@ WIP`）の状態を表示します。

- **Blame** と**ファイル履歴**は独立したビューです。*ログを使う* の [Blame](log-and-history.md#blame) と [ファイル履歴](log-and-history.md#ファイル履歴) を参照してください。Blame のハンクやファイル履歴の行で `Enter` を押すと、ログのその commit へ移動します。
- `y` または `Ctrl+C` で、選択したテキストをコピーします（Blame ではコードだけ）。
- `Shift+G` で最終行へジャンプします。`q` でビューを閉じます。

## 組み込みエディター

**編集**（`e`）は、ファイルの*作業ディレクトリ側のコピー*を、中央ペインの上に重なる小さなエディターで開きます。シンタックスカラー、行番号、元に戻す・やり直す、検索、ステータスバー（位置、改行コード、インデント、言語）があります。古い commit の diff から開いた場合でも、編集するのは常に作業コピーです。

![Rust ファイルをシンタックスハイライトと行番号付きで表示するエディター。ツールバーには保存、元に戻す、やり直す、検索がある](../images/editor.png)

| キー | 動作 |
|---|---|
| `Ctrl+S` | 保存（ファイルは一時ファイルに書き込んでからリネームされるので、中途半端な状態で書かれることはありません。改行コード、BOM、末尾の改行は保持されます） |
| `Ctrl+Z`、`Ctrl+Y` | 元に戻す、やり直す |
| `Ctrl+F`、`F3` | 検索、次を検索 |
| `Tab`、`Shift+Tab` | インデント、インデント解除（ファイル自体のスタイルに従います） |
| `Ctrl+A`、`Ctrl+C`、`Ctrl+X`、`Ctrl+V` | すべて選択、コピー、切り取り、貼り付け |
| `Esc` | 閉じる。未保存の変更がある場合は、**保存**（`s`）、**破棄**（`d`）、**キャンセル**（`c`）を確認します |

バイナリファイルは開けません。

**選択に追従**にチェックを入れると（エディターのバーのボックス。パレットの *エディター: 選択に追従を切り替え* や *設定 > diffとエディター* でも切り替えられます）、エディターを開いている間に右ペインで別のファイルを選ぶと、そのファイルの diff やファイルビューの代わりに、作業コピーがエディターで開きます。未保存の変更がある場合は、先に**保存**、**破棄**、**キャンセル**を尋ね、キャンセルすると現在のファイルにとどまります。編集できないファイル（バイナリ、大きすぎるファイル、削除されたファイル）は通常のビューで開き、ステータスバーにその理由が表示されます。エディターを閉じると、選択中のファイルのビューに移ります。既定でオンです。これは作業中の変更向けです。編集中に commit や比較のファイルを選ぶと、（未保存の編集があれば先に**保存**、**破棄**、**キャンセル**を尋ねたうえで）エディターを離れ、そのファイルの diff が開きます。エディターにはない Commit列も一緒に戻ります。

右側のステータスバーには、ファイルの**エンコード**、**改行コード**、**インデント**、続いてカーソル位置と構文が表示されます。
最初の 3 つはボタンで、それぞれドロップダウンを開きます（矢印キーまたはホイール、入力で絞り込み、`Enter` で選択、`Esc` で閉じる）。
パレット（`Ctrl+P`）からも同じメニューを開けます：*エディター: エンコードを変更*、*エディター: エンコードを指定して開き直す*、*エディター: エンコードに変換*、*エディター: 改行コードを変換*、*エディター: インデントを変更*。

![バーの UTF-8 チップの下に開いたエディターのエンコーディングメニュー：別のエンコーディングでファイルを開き直す、または変換する](../images/editor-encoding-menu.png)

![LF チップの下に開いたエディターの改行コードメニュー：ファイルを LF、CRLF、CR のいずれかに変換する](../images/editor-eol-menu.png)

- **エンコード。** ファイルは、自身が示すエンコード（BOM：UTF-8 または UTF-16）で開き、なければ UTF-8、それも違えば
  Windows-1252 で開きます。どれかはバーに表示されます。**エンコードを指定して開き直す**は、ファイルのバイト列を別の
  エンコードで読み直します（未保存の変更があるときは先に確認します）。判定が外れたときに使います。**エンコードに変換**は、
  テキストをそのままに、ファイルの保存エンコードを変えます（UTF-8、UTF-8 BOM、UTF-16 LE と BE、Windows-1252、
  ISO-8859-1 と -15、Windows-1250、Windows-1251、KOI8-R、Shift_JIS、EUC-JP、GBK、Big5、EUC-KR）。保存するまで何も
  書き込まれず、元に戻すで取り消せます。変換先で表せない文字があるときは、ステータスバーにその個数と最初の位置が表示され、
  変換はされません。保存も同じように拒否され、`?` が書き込まれることはありません。
- **改行コード。** `LF`、`CRLF`、`CR` を表示し、複数が混在していると `混在` と表示します。メニューは、ファイル内のすべての
  改行を LF、CRLF、CR のいずれかに、元に戻す 1 回分でまとめて変換します。新しく入力する行にはファイル自身の改行が使われます。
  選択した内容は *改行コード* 設定より優先されます。
- **インデント。** `スペース：4` または `タブ：4` を表示します。メニューでは、`Tab` と自動インデントが挿入するもの（スペースまたはタブ）、
  サイズ（1〜8：インデントの幅と、このファイルでのタブの幅）を選び、各行の先頭の空白をスペースまたはタブに、元に戻す 1 回分で変換できます。

## Stash、パッチ、Git LFS

- **Stash** と **Pop** はツールバーにあります。[ログを使う](log-and-history.md#ブランチtagrefs-サイドバー)を参照してください。
- **パッチを作成**と**パッチを適用**は、commit と参照のメニューにあります。CLI には `gitpoulpi patch` があります。
- Git LFS に保存された大きなファイルは、内容を pull するまで小さなポインターファイルとして表示されます。[Git LFS](lfs.md)を参照してください。

## コマンドラインから

このページのすべてはスクリプトから実行できます。

```
gitpoulpi --json status
gitpoulpi stage --file src/lib.rs
gitpoulpi stage --all --allow-sensitive   # after the refusal below
gitpoulpi --json diff
gitpoulpi commit -m "feat: add the helper"
gitpoulpi discard --file src/lib.rs --hunk 1
```

`gitpoulpi stage` も機密ファイルを同じように拒否します。何もステージされず、終了コードは 2 で、`--json` は `{error: "sensitive_files", files: [{path, reason}]}`（ルールとマスクしたプレビュー。値は含みません）を出力します。`--allow-sensitive` が再試行用です。MCP エージェントも同じ応答で拒否され、`[mcp] allow_sensitive_staging = true` でない限り `allow_sensitive` を渡せません。エージェントには、あなたに尋ねるよう伝えられます。

[CLI リファレンス](cli-reference.md)を参照してください。
