# トラブルシューティングと FAQ

まず下のクイックアンサーを見てください。より長い節では、Git LFS とグラフの描画を扱います。どれでも解決しない場合は、お使いの OS、ターミナル、`gitpoulpi --version` の結果、行った操作を添えて、GitHub リポジトリに Issue を作成してください。

## 何かが失敗したとき

失敗した操作は、ポップアップも枠つきのカードも出しません。**ステータスバー**が赤で、タイトルと理由を伝えます（*error: Fetch failed: The remote could not be reached.*）。別のメッセージに置き換わるまで、そこに残ります。右端のアクティビティボタンは、まだ見ていないエラーの数を数えます。赤いメッセージをクリックするか、パレットの `アクティビティログ: 直前のエラーを開く` を実行すると、その項目でアクティビティログが開きます。自分で起こしたあらゆる失敗が、git 操作に限らず同じ形で表示されます：

- **git 操作**：fetch、push、pull、checkout、merge、rebase、commit、stash など。
- **クローン**（と新しいリポジトリの作成）：「クローンに失敗しました」。
- **GitHub または GitLab への呼び出し**：ピッカーと「クローン」ダイアログのリポジトリ一覧、pull request や Issue の作成、「連携」ページでのトークンや SSH キーの確認：「ホスティングへのリクエストに失敗しました」。
- **外部プログラム**：エディター、diff や merge のツール、ファイルエクスプローラー、ブラウザー、ターミナル、ランチャー、画像エディター、設定の*試す*や*接続テスト*のボタンなど：「外部ツールが失敗しました」。
- **AI リクエスト**（commit メッセージ、説明、競合の提案など）：「AI リクエストに失敗しました」。
- **書き込めなかったファイル**：内蔵エディターの保存、merge エディター、保存できなかった設定：「保存に失敗しました」。

赤いメッセージは、どのビューが前面にあってもステータスバーに表示されます：リポジトリのタブ、Home、レーダー、ワークスペース、設定（画面の最下行）、アクティビティログやダイアログの下。ステータスバーが覆われている場所（Home、レーダー、ワークスペース、設定）では、エラーを確認するまで、メッセージが最下行に重ねて書かれます。メッセージはタブを移っても付いてきます。タブを切り替えたときにまだ実行中だった操作は追跡されません。結果はアクティビティログで確認してください。

更新できない PULL REQUESTS と ISSUES セクションの一覧は、代わりにセクション内に専用の 1 行を残します（自動で更新されるので、数秒ごとにメッセージが出てもノイズになるだけです）。まだ開いているダイアログ（クローン、Pull Request の作成など）も専用の 1 行メッセージを残すので、入力欄を直してやり直せます。

アクティビティログの項目には、以前ポップアップが示していたものがすべて入っています：

- **タイトルと理由。**「Fetch に失敗しました」に続いて、理由を平易な言葉で述べる 1 文、そして次に何をするか。認識されるもの：リモートに手元にない commit がある（*先に pull*）、認証情報が拒否された（*設定 > 連携か SSH キーを確認*）、競合で停止した、上書きされるローカルの変更がある（*commit、stash、または破棄*）、リモートに到達できない、別の git プロセスがリポジトリのロックを保持している。それ以外は git 自身の最初の 1 行が表示されます。認証情報の拒否やホストに到達できないなど、クローンやホストへの呼び出しが同じ形で失敗した場合も、同じ文面になります。それ以外の失敗には、何が失敗したかを述べる 1 文（「リポジトリをクローンできませんでした。」「プログラムを実行できませんでした。」）が付きます。
- **詳細**。項目を開いているとき（`Enter`、またはその項目を開いたクリック）に表示されます：操作、実行された git コマンド、その終了コード、出力の最後の数行（内蔵の git ライブラリの場合はエラーのクラスとコード）。認証情報、トークン、`Authorization` ヘッダーは、表示、ログ記録、コピーの前にマスクされます。
- **コピー**（ボタン、または `c`）は、説明してくれる人や AI とのチャットに貼り付けるためのテキストをクリップボードに入れます：GitPoulpi のバージョン、システム、ターミナル、バックエンド、失敗した操作とその詳細、git のバージョン。
- 次の一手がある場合は**そのためのボタン**。コピーの隣にあります（または `r`）：*先に Pull*（リモートが拒否する push）、*Stash してやり直す*（checkout、merge、rebase、pull の妨げになるローカルの変更）、*やり直す*（リモートに到達できなかった）、*連携を開く*（認証情報）。その手順を実行して、ウィンドウを閉じます。前面のタブ以外のリポジトリの失敗では *連携を開く* だけが表示されます。やり直しは別のリポジトリで実行されてしまうためです。
- マウスなしでは、コマンドパレットに `アクティビティログ: 直前のエラーを開く`、`アクティビティログ: 直前のエラーをコピー`、`アクティビティログ: 提案された操作を実行` があります（ステータスバーに表示されているエラーに対する、項目の対処ボタンです）。

リモートが先に進んでいたため拒否された push には、専用のダイアログ（先に pull、lease つきの force push、キャンセル）が引き続き使われます。事実はアクティビティログにも残ります。

### アクティビティログ

ステータスバーの右端の **アクティビティ** ボタン（数字は、まだ見ていないエラーの数）、`Ctrl+N` の後に `Shift+A`、パレットの `表示: アクティビティログ` でウィンドウが開きます。`Ctrl+N` を押すと、ウィンドウの各タブ、ボックス、フィールド、チェックボックス、ボタン（と一覧の最初の項目）にバッジが表示され、その文字を押すとクリックしたのと同じ動作をします。タブは **Git 操作** と **アプリケーション** の 2 つで、`Tab`、クリック、`g`（Git 操作）、`p`（アプリケーション）で切り替えます。その下の **対象範囲** ボックスは、両方のタブに適用されます（下を参照）。

- **アプリケーション**：プログラム自身のログ行で、ウィンドウとバックグラウンドのデーモンの両方の行が、新しいものから順に並びます。**レベル** ボックス（ドロップダウン：エラー、警告、情報、デバッグ、トレース。`l` で開く）で表示量を決めます。記録されている以上の詳細を求めると、記録レベルも上がります（`log.level` として保存されます）。その下の **表示** には、レベルごとのチェックボックス（エラー、警告、情報、デバッグ、トレース。それぞれの行数つき）があり、そのレベルの行を非表示または表示にできます（たとえばエラーだけを見るとき）。**すべて** / **なし** はすべてのボックスをオンまたはオフにします。`1` から `5` のキーがその順でレベルを切り替え、`a` がすべて、`n` がなしです。パレットには `アクティビティログ：「...」レベルの表示/非表示を切り替え`、`アクティビティログ：すべてのレベルを表示`、`アクティビティログ：どのレベルも表示しない` があります。レベルボックスの選択より上のレベルはグレーで表示されます（それらは記録されません。ポインターを合わせると理由が表示されます）。チェックの状態は終了するまで保持され、アプリケーションタブにだけあります。**フィルター**（`/`）は入力した文字を含む行だけを残します。**すべてコピー（絞り込み後）** は表示中の内容をコピーします（チェックとフィルターの両方が適用されます）。**ログフォルダーを開く** はファイルマネージャーでフォルダーを開きます。長い行が切り詰められることはありません。下の「長い行」を参照してください。
![アクティビティログのアプリケーションタブ：レベルボックス、すべてとなしつきのレベル別表示チェックボックス、フィルター、ログ行](../images/activity-log.png)

**ログを消去**（`x`、またはパレットのコマンド `アクティビティログ: アプリケーションログを消去`）は **アプリケーション** タブにあります。先に確認を求め、保持しているすべての日のログファイルと画面上の一覧を空にします。元に戻すことはできず、undo 履歴にも残りません。

- **Git 操作**（ウィンドウが最初に開くタブ）：操作が新しいものから順に並び、それぞれ実行した時刻と所要時間が付きます（`Push - 123 ms`）：リポジトリを開く、commit グラフの読み込み、fetch、pull、push、commit、checkout、merge、rebase、stash、clone。失敗、ステータスメッセージ、失敗したクローン、ワークスペースの Fetch all もここに一覧されます。`Enter` かクリックで 1 件を開き（理由、次の一手、コマンド、終了コード、出力）、`c` かそのコピーボタンでコピー、`r` かそのボタンで提案された手順を実行します。`Tab`（または `p`）でアプリケーションタブに切り替わります。`Left` / `Right` で長い行を横にスクロールします。
![アクティビティログの Git 操作タブ：各操作の時刻と所要時間、失敗した fetch は赤](../images/activity-log-repository.png)

- **どの操作がエラーを起こしたか。** すべての失敗には、何が起こしたかが示されます。項目にも、アプリケーションログにも、コピーしたレポートにも入ります。操作は人が呼ぶ名前で示され（`Remove remote`、`Fetch all remotes`、`Hosting request: create pull request`、`Token command`）、主な引数が付きます（`remote=cm6`、ブランチ、パス。メッセージ本文は含まれず、URL とトークンはほかと同じようにマスクされます）。続いてリポジトリ、要求元（`TUI`、`CLI`、`MCP`）、そして操作 ID、つまりデーモンがそのリクエストに付けた番号（fetch、push、pull ではジョブ番号も）が示されます。Git 操作タブでは、項目の見出しは `Remove remote failed (remote=cm6) - ... [CLI #12]` のようになり、詳細は `操作:`、`リポジトリ:`、`要求元:`、`操作 ID:` で始まります。独自のタイトルがない操作には、その操作の名前でタイトルが付きます（`Remove remote failed`）。アプリケーションタブでは、失敗の行が同じ言葉とタグで始まります：`Remove remote failed (remote=cm6) [op #12, CLI, repo name]: backend error: no such remote: cm6`。このような行はその操作を開きます：クリックするか、選択して `Enter` を押します（パレットの `アクティビティログ: この行の操作を表示`）。`]` と `[` は次と前の失敗の行を選択します（`アクティビティログ: 次の失敗した操作` / `アクティビティログ: 前の失敗した操作`）。行を選択している間は、矢印キーはスクロールではなく選択を動かします。開く項目は、そのウィンドウが操作を実行したときはウィンドウ自身のものです。同じセッションに対する CLI やエージェントの失敗では、ウィンドウがその行から項目を作ります。コピーしたエラーレポートには `operation:`、`arguments:`、`repository:`、`requested by:`、`operation id:` の行が入り、単独で貼り付けられます（この行は英語のままです）。スクリプトからは、失敗したコマンドの `--json` エラーは変わりません。失敗したリクエストに対するデーモンの応答には、追加の `context` フィールドに同じ情報が入ります。

- **長い行**（両方のタブ）：ウィンドウより幅の広い見出しや詳細の行が切り詰められることはありません。一覧の下に横スクロールバーが現れます。`Left` / `Right`（`activity_log.scroll_left` / `activity_log.scroll_right` として再割り当てできます）、`Shift` + ホイールまたは横ホイール、パレットの `アクティビティログ: 左へスクロール` / `アクティビティログ: 右へスクロール`、またはバー（つまみをドラッグするか、トラックを押してつまみをポインターの下へ移動）で横にスクロールします。`Home` で先頭に戻り、タブを切り替えると、もう一方のタブは左端から始まります。折り返されるテキスト（要約、提案された手順）は折り返されたままです。

- **対象範囲**（タブの下のドロップダウン。`s` で開く、またはパレットの `アクティビティログ: 対象範囲を選択`）：両方のタブが何についてのものかを決めます。選択肢は、**このリポジトリ（名前）**（ログを開いたタブのリポジトリ。リポジトリのない Home からは表示されません）、**すべてのリポジトリ**、各**ワークスペース**、ウィンドウが知っている各リポジトリです。リポジトリのタブから開くと *このリポジトリ* で、Home（アクティビティボタン、`Ctrl+N` の後に `Shift+A`）から開くと *すべてのリポジトリ* で開きます。`Ctrl+N` の後に `Shift+G` とパレットの `表示: グローバルアクティビティログ` は、常に *すべてのリポジトリ* で開き、前面のタブ以外のリポジトリの失敗（たとえば失敗したクローン）の赤いエラーをクリックしたときも同様です。最後の選択はセッション中保持され、2 通りの開き方で別々に記憶されます。アプリケーションタブでは、プログラムがリポジトリについて書いた行（失敗した push、操作の時間）がそのリポジトリのものとして扱われ、*すべてのリポジトリ* では、そのような行に持ち主が表示されます（`[name]`）。リポジトリに関係しない行（起動、設定、デーモン自身）と、どれにも属さない項目（保存の失敗）は**アプリ全体**です。どの対象範囲でも表示され、対象範囲が *すべてのリポジトリ* より狭いときは `[アプリ全体]` と示されるため、フィルターが失敗を隠すことはありません。パレットには、タブを開く `アクティビティログ: Git 操作` と `アクティビティログ: アプリケーションログ` もあります。

- **診断情報をコピー**（両方のタブにあるボタン、`d`。対象範囲にかかわらず常にログ全体で、パレットの `表示: 診断情報をコピー`）は、バージョン、システム、ターミナル、バックエンド、直近の失敗とその詳細、選んだレベルの直近 200 行のログをコピーします。何かおかしいときに AI へ渡すためのブロックです。

所要時間はウィンドウが計測するもの（リクエストからデーモンの応答まで、往復を含む）なので、CLI や MCP が行う処理は計測されません。`log.timings`（既定でオン）で所要時間をオフにでき、`log.extended`（既定でオフ）はバックグラウンドの処理、つまり定期更新と自動 fetch も一覧します。どちらも 設定 > 全般 の、ほかのログ設定の隣にあります。なお、すべての操作は常にアプリケーションログへ書き込まれます（頼んだ操作は `info`、バックグラウンドは `debug`）。

ログファイルは `gitpoulpi-YYYY-MM-DD.log` で、既定では 1 週間分、最長で 10 年間保存され（`log.retention_days`、1〜3650）、GitPoulpi の起動時に削除され、`log.max_file_mb`（5 MiB）でローテーションされます。保存場所：[設定リファレンス](config-reference.md#logアプリケーションログ)。スクリプトからは、失敗したコマンドの `--json` エラーが同じ情報を `detail` に含みます。[CLI リファレンス](cli-reference.md)を参照してください。

赤いメッセージをクリックすると、その項目を開いた状態で、すべてのリポジトリを対象にログが開きます。Git 操作の一覧はセッション中のものです。アプリケーションタブは、再起動をまたいでプログラムのログを保持します。

**バックグラウンドジョブ。** fetch、push、pull、クローン、LFS 転送、ワークスペースの Fetch all / Pull all / Clone missing、AI リクエスト、送信中のプルリクエストや Issue はジョブです。ステータスバーの右端に実行中のジョブと取り消しの `[x]` が表示され、ラベルをクリック（または `Ctrl+N` に続けて `Shift+J`、パレットの `Jobs: Show background jobs`）すると、ジョブごとのキャンセルボタンがあるパネルが開きます（`c` や `Del` も可）。クローンはバックグラウンドで動き、AI リクエストとワークスペースの巡回はタブを切り替えても続きます。安全に止められる地点を過ぎたジョブは理由付きでグレー表示になり、キャンセルしたジョブはリポジトリを元のままにします。

## クイックアンサー

**ツールバーとサイドバーのアイコンが、四角や疑問符で表示されます。**
ターミナルで Nerd Font、または絵文字に対応した任意のフォントを使ってください。それらがなくても、グラフとテキストは動作します。

**commit グラフが画像ではなく文字で描かれます。** これは自動的なフォールバックです。画像を使うには、kitty グラフィックスプロトコル（kitty、Ghostty、kitty グラフィックスをオンにした herdr）または iTerm2 プロトコル（WezTerm、Rio、mintty）、または sixel（Windows Terminal、foot、Tabby、Konsole、背後のターミナルが sixel に対応している tmux）に対応したターミナルが必要です。Windows コンソール、zellij、screen では文字になります。どちらかを強制する方法は、下のグラフの節、[ターミナルの選び方](terminals.md)、[マルチプレクサ](multiplexers.md)を参照してください。

**マウスが反応しない、またはマウスでテキストを選択できません。**
GitPoulpi はクリックを受け取るためにマウスをキャプチャします。ターミナル自身でテキストを選択するには、ドラッグ中に `Shift` を押し続けます（ほとんどのターミナルで有効です）。diff の中での選択もできます（ドラッグしてから `y`）。マウスのキャプチャをオフにするには、*設定 > キーボードとマウス > マウスを有効化*を使います（再起動が必要です）。キーボードですべてのコマンドを実行できます。

**ショートカットが動きません。** ターミナル、tmux、AutoHotkey のスクリプトなどが、GitPoulpi より先にそのキーを受け取っている可能性があります（Linux や macOS のターミナルでは、`Ctrl+,` が単なる `,` として届くことがよくあります。`Ctrl+Shift+N` は `Ctrl+N` に見えます）。代わりのキーを使うか（`Ctrl+N` の次に `,` で設定が開きます。`Ctrl+P` ですべてのコマンドに届きます）、コードを割り当て直してください。[設定](settings.md#キーボードとマウス)を参照してください。

**`Ctrl+Tab` でタブが切り替わりません。** kitty、WezTerm、Ghostty、Windows Terminal は `Ctrl+Tab` と `Ctrl+Shift+Tab` を自分のタブ用に使うため、このキーは GitPoulpi に届きません。`Ctrl+PageDown` / `Ctrl+PageUp` は常に使えます。この 2 つを GitPoulpi に渡すには、ターミナルの設定で解除し、ターミナルを再起動（または設定を再読み込み）してください。

- kitty：`kitty.conf` に書きます（アクションのない `map` は既定の割り当てを解除します。`--when-focus-on` とウィンドウ条件（`title:...` など）を併用すると、一致するウィンドウにフォーカスがあるときだけ解除することもできます。kitty のマッピングのドキュメントを参照してください）。

  ```
  map ctrl+tab
  map ctrl+shift+tab
  ```

- WezTerm：`wezterm.lua` に書きます。

  ```lua
  config.keys = {
    { key = 'Tab', mods = 'CTRL', action = wezterm.action.DisableDefaultAssignment },
    { key = 'Tab', mods = 'CTRL|SHIFT', action = wezterm.action.DisableDefaultAssignment },
  }
  ```

- Ghostty：設定ファイルに書きます。

  ```
  keybind = ctrl+tab=unbind
  keybind = ctrl+shift+tab=unbind
  ```

- Windows Terminal：`settings.json` に書きます（`"id": null` で既定の割り当てを解除します）。

  ```json
  "keybindings": [
    { "id": null, "keys": "ctrl+tab" },
    { "id": null, "keys": "ctrl+shift+tab" }
  ]
  ```

  （古い設定ファイルでは、`actions` に `nextTab` / `prevTab` がこれらのキーで並んでいます。その場合はそこからキーを削除してください。）

これでターミナル自身の `Ctrl+Tab` によるタブ切り替えは使えなくなります。このキーを kitty キーボードプロトコル経由でしか送れないターミナルでは、プロトコルをオンにしておく必要があります（既定でオンです。[キーバインド](keybindings.md#ターミナルが送れないキーと-kitty-キーボードプロトコル)を参照）。

**ショートカットを思い出せません。** `Ctrl+P` を押して、したいことを入力してください。各結果にショートカットが表示されます。`?` ですべてが一覧できます。

**設定の項目がグレーになっています。** ほかの項目に依存しています。その行に、どの項目か表示されます（たとえば、*行の色付けの強さ*は、*グラフのレーン背景*が*行の色付け*のときに有効になります）。

**ログの上に「自動 stash が保留中」と表示されます。** GitPoulpi が操作を実行するために変更を stash しましたが、元に戻せませんでした。バナーの **Pop now**、**Show stash**、**やり直す**（操作を取り消して変更を戻す）、**Drop** を使ってください。[自動 stash](log-and-history.md#自動-stash)を参照してください。

**エージェントが `no_viewer` または `deferred` と言っています。** `no_viewer`: そのリポジトリの GitPoulpi ウィンドウが開いていません（または*AI エージェントによる表示の操作を許可*がオフです）。`deferred`: ウィンドウにチップが表示されています。`Ctrl+N Enter` で承認します。[MCP とエージェント](mcp-and-agents.md#ユーザーに表示する)を参照してください。

**GitPoulpi を開くと、空のウィンドウ、または `ログのエラー：backend error` が表示されます。**
Git リポジトリの中で起動したか確認してください（そうでない場合は、ホームタブが表示されます。**参照**、**クローン**、**初期化**を使ってください）。次に `gitpoulpi daemon status` を実行します。`gitpoulpi daemon restart` で、このリポジトリのバックグラウンドプロセスを再起動します。`r` を押して更新してください。

**同じリポジトリで 2 つのウィンドウを開くと、動作がおかしくなります。** これらは意図的に、リポジトリごとに 1 つのデーモンを共有しているため、一方の変更がもう一方に反映されます。デーモンが固まったように見える場合は、`gitpoulpi daemon stop --all` ですべてのセッションのデーモンを停止します。次のウィンドウが新しいデーモンを起動します。

**commit、pull、push でパスワードを求められる、または認証に失敗します。**
GitPoulpi はネットワーク通信に、お使いの `git` 自身の認証情報ヘルパーと ssh-agent を使います。まず、通常のターミナルで `git fetch` が動くことを確認してください。pull request 用の GitHub/GitLab のトークンは別のもので、任意です。[ホスティングと Issue トラッカー](hosting-integration.md)を参照してください。

**fetch、pull、push が「The configured credential helper failed」「The SSH host key of the remote is not known yet」または拒否されたサインインで失敗し、アクティビティログの項目に「SSH と認証情報...」ボタンがあります。**
このリポジトリのサインイン方法が原因の失敗です。ボタンを押すと 設定 > SSH と認証情報 が開き、このリポジトリの別の認証元を選べます：リポジトリのヘルパーを無視した git 自身のヘルパー、連携アカウント、鍵ファイル（known hosts ファイル付き）、または独自のヘルパーやトークンコマンド。そのあと**接続テスト**ですべてのリモートを確認します。実行できなかったヘルパーは、`git config --show-origin --get-all credential.helper` で設定場所を確認できます。

**「GitPoulpi did not send the account token to ...」。** リポジトリのリモートが、選んだアカウントに結び付けられたアドレスではないサーバーを指しているため（多くはリポジトリ自身の設定にある `url.<x>.insteadOf` の書き換えが原因）、トークンは送られませんでした。リモートを直すか、ページで別の認証元を選んでください。

**「This repository's token command failed」「... changed since you confirmed it」「This repository's sign-in cannot be used」。**
ページの選択を実行できません：トークンコマンドがトークンを出力しなかった（最後のエラー行が、秘密を除いて引用されます）、実行するスクリプトが確認後に変更された（ページでコマンドをもう一度確認してください）、または選択した鍵ファイルやアカウントがもうありません。どの場合も **SSH と認証情報...** ボタンが表示されます。

**OpenSSH が鍵ファイルについて「bad permissions」と言います。** ほかのアカウントがその鍵を読み取れます。設定 > SSH と認証情報 の**秘密鍵ファイル**の行に警告と**自分のアカウントに限定**が表示されます。

**ステータスバーに「ステージ中...」が残ります。** バックグラウンドの更新がまだ実行中です。ファイル一覧が更新されると消えます。`r` で更新を強制できます。

**非常に大きなリポジトリが遅いです。** 設定 > ログとグラフの*グラフの初期 commit 数*を減らしてください（*グラフの commit を遅延読み込み*がオンなら、スクロールに合わせてログがさらに読み込みます）。ログの*変更*列を非表示にし、アバターをオフにします。元に戻す機能が不要なら*元に戻す機能を有効化*をオフにします（ステージと commit で一切の記録処理がなくなります）。`GITPOULPI_TIMING=1` を設定すると、リクエストごとの所要時間が一時フォルダーの `gitpoulpi-timing.log` に書き込まれます。パフォーマンスの報告に添付すると役立ちます。

**AI のボタンが表示されない、またはグレーです。** AI は既定でオフです。[AI アシスタント](ai.md#トラブルシューティング)を参照してください。

**GitPoulpi が勝手に終了しました。** 終了はすべて記録されています。設定ディレクトリで `gitpoulpi-tui-exit.log`（クラッシュ後は `gitpoulpi-tui-panic.txt` も）を探してください（`gitpoulpi config path` が表示する設定ファイルはそこにあります）。それを Issue に添付してください。

**設定はどこにありますか？** `gitpoulpi config path` で分かります。リポジトリごとの状態は、リポジトリ内の `.gitpoulpi/repo-state.toml` にあります。

**GitPoulpi はどこかにデータを送信しますか？** ユーザーが求めたことだけです。リモートへの git 操作、アカウントを接続した後のホスティングへのリクエスト、AI ボタンを押した後の AI へのリクエスト、そしてアバターをオンにした場合の、作成者のメールアドレスのハッシュの Gravatar への送信です。テレメトリはありません。[AI アシスタント](ai.md#プライバシー)を参照してください。

## すべての書き込みが失敗する："Unable to create index.lock"

git コマンドが異常終了した場合（クラッシュ、強制終了されたターミナルなど）、`.git/index.lock` が残ることがあり、その後はリポジトリへのすべての変更が失敗します。このファイルが作成から 10 秒以上たつと、GitPoulpi はログの上に帯を表示します。**index.lock を削除**です（パレット：*リポジトリ: 古い index.lock を削除*。CLI: `gitpoulpi index-lock remove`）。先に確認し、そのファイルだけを削除します。ほかの git プログラムがまだ動いているかどうかを、GitPoulpi は確実には判断できません。確定する前に、動いていないこと（IDE、別のターミナルなど）を確認してください。リンクされた worktree では、ロックはその worktree 自身のもので、`.git/worktrees/<名前>` にあります。

## "git am" が停止し、Rebase の中止が効かない

`am`（メールボックスからのパッチの適用）は rebase ではありません。停止した `git am` には専用の帯、**パッチを適用中（git am）**があり、競合を解決、続行、スキップ、中止が使えます（パレット：*git am: 続行 / このパッチをスキップ / 中止*。CLI: `conflicts am-continue|am-skip|am-abort`）。中止は先に確認し、ここまでに適用したパッチを破棄して、ブランチを元の位置に戻します。これらは、rebase のボタンと同じく、元に戻せません。

## 元に戻すがグレーで「... を元に戻せません」と表示される（ブロックされた項目）

最新のジャーナルの項目が詰まっています。GitPoulpi の外でリポジトリが先に進んだか、その項目が中断されたためです。元に戻すにカーソルを合わせると理由が表示されます。完全に詰まったままの場合、ツールチップは**編集: ブロックされた元に戻す項目を履歴から外す**（パレット）または `gitpoulpi undo-forget` を案内します。先に確認し、ジャーナルから項目を取り除くだけで、リポジトリには手を加えません。[元に戻す/やり直す](undo-redo.md)を参照してください。

## 大きなファイルが 3 行のテキストとして表示される（「LFS ファイルがポインターとして表示される」）

画像、モデル、大きなバイナリのはずのファイルに `version https://git-lfs.github.com/spec/v1` と `oid sha256:...` の行が入っている場合、それは Git LFS の**ポインター**で、実際の内容がダウンロードされていません（または LFS フィルターがインストールされていません）。

- ステータスペインを見てください。LFS を使うリポジトリで `git-lfs` が見つからないと、琥珀色のバナーが表示されます。プログラムをインストールして（https://git-lfs.com。Windows: Git for Windows に同梱、または `winget install GitHub.GitLFS`。Debian/Ubuntu: `apt install git-lfs`。macOS: `brew install git-lfs`）、開き直すか `r` を押してください。
- `gitpoulpi lfs status` は、プログラムがインストールされているか、フィルターとフックが設定されているか、どのパターンが追跡されているかを示します。`gitpoulpi lfs files` は、ポインターのファイルと、そのうち `local` のものを一覧表示します。
- `git-lfs` がインストールされていれば、パレットの **`LFS: オブジェクトをPull`** を実行します（または `gitpoulpi lfs pull`）。オブジェクトをダウンロードして、ポインターを置き換えます。このリポジトリに LFS フィルターがなければ、先にインストールします。
- ダウンロードが失敗した場合、メッセージに理由が示されます（リモートの認証情報、サーバーにオブジェクトがもうない、など）。GitPoulpi 自身のアカウントは不要です。LFS はリモートの通常の認証情報（認証情報ヘルパーまたは ssh-agent）を使います。
- LFS リポジトリのクローンが LFS が原因で失敗することはありません。ダウンロード手順を実行できなかった場合は、ポインターのままクローンが作成され、あとから `LFS: オブジェクトをPull` で完了できます。`gitpoulpi clone --no-lfs` は、意図的にダウンロードを省略します。
- 設定 > Git とエンコード > Git LFS で、LFS に関するすべてをオフにできます（または `[git] lfs_enabled = false`）。

## "git-lfs not found" / "Git LFS is not installed"

メッセージ `Git LFS がインストールされていません。このリポジトリは大きなファイルを Git LFS で保存しており、...`（または*インストールページを開く*ボタン付きのダイアログ、あるいは git 自身の `git-lfs: command not found` / `'lfs' is not a git command`）は、そのリポジトリが LFS 用に設定されていて - その `.gitattributes`、`.git/config` のフィルター、または `pre-push` フックが `git-lfs` を呼び出していて - GitPoulpi から見える `PATH` にそのプログラムがないことを意味します。インストールしてください（上のリンクを参照）。Windows では、プログラムは Git for Windows に同梱されています。ターミナルで `git lfs version` が動くのに GitPoulpi が見つからないと言う場合は、同じ `PATH` が見えるターミナルから GitPoulpi を起動してください。git 自身の動作はそのままに、GitPoulpi から LFS を隠すには、`git.lfs_enabled` をオフにします。

## グラフが画像ではなく文字で描かれる（herdr、tmux、そのほかのターミナル）

GitPoulpi は、ターミナルが確実に表示できる場合に限って、Graph 列と作成者のアバターをピクセルで描きます。素の WezTerm、Rio、mintty、および 3.7.7 より古い iTerm2 では iTerm2 のインライン画像、kitty、Ghostty、iTerm2 3.7.7 以降では Kitty グラフィックスプロトコル、そして **herdr 自身の設定で `kitty_graphics = true`** になっていて（`[terminal]`、古い herdr では `[experimental]`）、かつ herdr が WezTerm、kitty、Ghostty の中で動いている場合の herdr です。sixel の画像は Windows Terminal、foot、Tabby、Konsole、mlterm（と、背後のターミナルが sixel に対応している tmux）で使われます。それ以外では文字で描きます。これは常に正しい表示です。

- herdr で Kitty グラフィックスがオンなのに、GitPoulpi が設定を見つけられない（または herdr の既定に頼っている）場合は、`ui.image_protocol = "kitty"` を設定して（設定 > ログとグラフ > 画像プロトコル）再起動してください。
- グラフの場所に四角や文字化けが表示されるターミナルでは、`ui.image_protocol = "none"` または `ui.graph_renderer = "text"` を設定してください。
- `GITPOULPI_TERMINAL_IMAGE=off` は、設定に関係なく画像をオフにします。

**herdr リモート（`herdr --remote <host>`、または `ssh` してから `herdr`）: 文字のグラフが既定です。** SSH 越しでは、GitPoulpi はリモートホスト上で動き、リモートの環境と herdr の `config.toml` しか読めません。Kitty の画像が表示されるかどうかは、*ローカル*の herdr クライアント（そのクライアント自身の `kitty_graphics` 設定とターミナル）が決めますが、GitPoulpi にはそれが見えません。クライアントが画像を描かない場合、セルは空白のままです。そのため GitPoulpi は、SSH 越しの herdr を検出すると（`SSH_CONNECTION` / `SSH_CLIENT` / `SSH_TTY`）、必ず文字のグラフを描きます。ローカルの herdr が `kitty_graphics = true` で、Kitty の画像を描けるターミナル（kitty、Ghostty）を使っている場合は、リモート側で `ui.graph_renderer = "image"`（または `ui.image_protocol = "kitty"`）を設定して有効にしてください。画像はインライン（`t=d`）で送られるため、どんなバイトストリームでも動作します。列が空の場合は、`ui.graph_renderer = "text"` を設定してください。

**レーンの背後に、明るい長方形が出る。** 何も描かれていない部分では、画像は透明です（ストレートアルファの RGBA PNG）。そのため、ターミナルの背景と選択の帯が透けて見えます。Kitty プロトコルのターミナル、**WezTerm**、**Rio** はそのアルファを合成します。この場合、GitPoulpi は画像の下に通常の空白セルを確保し、その後ろに画像を送ります。それ以外の iTerm2 プロトコルのターミナル（古い iTerm2、mintty）は、PNG のアルファをブレンドすることが知られていないため、画像にテーマの色の不透明な背景が付きます。背景色がそれと異なるターミナルでは、長方形として見えることがあります。`ui.graph_renderer = "text"` で消えます。`ui.graph_lane_background = "off"` にすると、透明な描画経路では、レーンの背後に何も描かれません。

**Windows：グラフ列が空白、違う行にある、または画面が乱れる（WezTerm 20240203、Rio、mintty）。** これらのターミナルの背後にある疑似コンソールが、画像のシーケンスを落としたり位置をずらしたりします（[ターミナルの選び方](terminals.md#windows)）。`ui.graph_renderer = "text"` を設定するか、Windows Terminal を使ってください。

tmux、zellij、screen、herdr の中では、何が通るかと追加する設定について[マルチプレクサ](multiplexers.md)を参照してください。

[設定リファレンス](config-reference.md)の `ui.graph_renderer` と `ui.image_protocol` を参照してください。
