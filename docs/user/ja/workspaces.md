# ワークスペース

**ワークスペース**は、リポジトリに名前を付けたグループです。フロントエンドとその API、ドキュメントのように、
一緒に作業するリポジトリをまとめます。ワークスペースは、どのリポジトリがタブとして開いているかを記憶し、
**既定の commit プロファイル**を持たせることもできます。そのため、これらのリポジトリでの commit は、
手動で切り替えなくても正しい ID で行われます。リポジトリは複数のワークスペースに入れることができ、
どれにも入っていなくても問題ありません。「ワークスペースなし」は、従来どおりの通常のタブ一覧です。

ワークスペースは `config.toml` の隣の `workspaces.toml` に保存され、すべてのセッション、ウィンドウ、CLI、MCP
（`gitpoulpi workspace ...`。[CLI リファレンス](cli-reference.md)を参照）で共有されます。ワークスペースを閉じたり
削除したりしても、ディスク上のリポジトリには影響しません。シェルや `gitpoulpi workspace ...` から追加、名前変更、削除されたワークスペースは、ウィンドウが開いている間、キーを押さなくても 1 秒ほどで自動的に反映されます（ワークスペースのタブ、タブバーのチップとその一覧）。ワークスペースの編集はお気に入りやプロファイルと同じく設定であり、
[元に戻す・やり直す](undo-redo.md)の対象ではありません。削除の前には確認が表示されます。

## ワークスペースのチップ

ワークスペースが 1 つでもあると、タブバーの `⌂` のすぐ右にチップが表示されます。色付きのドットと有効なワークスペースの名前、
または（淡色で）「ワークスペースなし」です。バーが狭いときはドットだけになり、とても狭いときは消えます。

![タブバーの上のワークスペースのドロップダウン：ワークスペースなし、Orbit（チェック付き）、Side projects、Archive、ワークスペースを管理...が並び、ツールバーには Orbit のチップと、そのプロファイル「Work - ワークスペース Orbit 由来」が表示されている](../images/workspace-switch.png)

- **クリック**するか、`Alt+W` を押すか、パレットから `ワークスペース: 切り替え...` を実行すると、ドロップダウンが開きます。
  ワークスペースの一覧、「ワークスペースなし」、「ワークスペースを管理...」（ワークスペースのタブを開きます）が並びます。
- **切り替えるとタブが入れ替わります。**離れるワークスペースで開いていたタブは保持され、移動先のタブが戻ります
  （初回は、存在するリポジトリが開きます）。元に戻せば、すべてそのままです。タブの切り替えと同じようにウィンドウが再起動しますが、
  デーモンは動き続けます。
- **ワークスペースは記憶されます。**次回の起動時も、そのワークスペースで開きます。
- ワークスペースの**最後のタブを閉じる**と、ワークスペースは有効なままホームタブが表示されます。
- **ワークスペースが有効なときの `+`（新しいタブ）**は、選んだリポジトリをタブ一覧に追加するだけで、何も尋ねません。
  ワークスペース自体に入れるには、タブの右クリックメニューの「ワークスペースに追加」（またはパレットの `ワークスペース: タブをワークスペースに追加`）を使います。
  「ワークスペースから除外」は、タブを開いたまま、ワークスペースから外します。

ワークスペースがまだないときは、チップは表示されません。先にワークスペースのタブかパレットから作成してください。

## ワークスペースのタブ

`+` メニュー、`Alt+J`、またはパレットの `ワークスペース: 管理...` から開きます。`x`（または `Ctrl+W`）で閉じ、閉じるまでは再起動後も開いたままです。各ワークスペースは 1 行で、色のドット、名前、リポジトリの数（見つからないものの数も）、
既定のプロファイル、そしてウィンドウがそのワークスペースにいるときは「有効」が表示されます。`Right`、`Space`、またはクリックで、
その行がリポジトリまで展開されます。

![ワークスペースのタブ：Orbit が 2 つのリポジトリまで展開され、Side projects と、「1 個が見つかりません」と表示された Archive が並んでいる](../images/workspaces.png)

| ワークスペースごとの操作 | キー | |
|---|---|---|
| 開く | `Enter` | 有効にして、そのタブを開きます。 |
| 編集... | `e` | 下記のフォームです。 |
| 削除... | `x` | 先に確認します。リポジトリには影響しません。 |
| すべてFetch | `Shift+F` | 1 つずつ順に実行し、進捗をステータスバーに表示し、失敗は最後に一覧します。 |
| すべてPull | `Shift+P` | 同じく順に実行しますが、早送りのみです。merge で止まることはありません。 |
| 見つからないものをクローン | `m` | 記録されたリモートがある、見つからないリポジトリをすべてクローンします。 |
| 新しいワークスペース... | `n` | |
| 開いているタブから... | `a` | 開いているタブにチェックを付けた、新しいワークスペースを作ります。 |

**見つからない**リポジトリ（フォルダーが消えたもの）は、印を付けて一覧に残り、**場所を指定...**（`l` または `Enter`：現在の場所を選びます）、
**クローン**（追加時に `origin` の URL が記録されている場合）、**除外**（`x`）が使えます。どの行にも `⋮` メニュー（右クリック、`.`、`Shift+F10`）があり、
同じ操作が並びます。すべての操作は、パレットの `ワークスペース:` にもあります。

## 新規 / 編集フォーム

![ワークスペースの編集フォーム：名前、色、説明、既定のプロファイル、リポジトリのチェックリスト](../images/workspace-edit.png)

- **名前**：必須で、重複できません。
- **色**：テーマの色のドロップダウンです。チップと行のドットの色になります。
- **説明**：自由なテキストです。
- **プロファイル**：`[[profiles]]` のドロップダウン、または「なし」です。任意です。
- **✦ AI の指示**：AI がオンのときのみ。[下](#ワークスペースの-ai-の指示)を参照してください。
- **リポジトリ**：GitPoulpi が把握しているすべてのリポジトリ（開いているタブ、お気に入り、最近のもの、ワークスペース自身のもの、見つからないものを含む）のチェックリストです。
  `Space` で行にチェックを付けます。**フォルダーを追加...**（`Ctrl+B`）で、ディスク上のリポジトリを選べます。
  新しいリポジトリの origin URL は、リポジトリから読み取られて（認証情報は除いて）記録されます。後でクローンが使うのはこの URL です。

## ワークスペースの AI の指示

AI をオンにすると（*設定 > AI*）、フォームに**編集...**ボタン付きの **✦ AI の指示**の行が表示されます（行で `Enter`）。**ワークスペースのすべてのリポジトリ**で AI に伝える内容を編集する小さなエディターが開きます。**対象**のリストで*すべての AI 操作*または 1 つの操作（commit メッセージ、説明、stash メッセージ、pull request、commit コンポーザー、競合の解決、コードレビュー）を選び、**全体と組み合わせる**で*全体に追加*（全体の指示の後に送信）または*全体を置き換え*（全体の指示の代わりに送信）を選んで、テキストを書きます。**適用**は全体のセットを保持し、フォームの**保存**がワークスペースと一緒に `workspaces.toml` に書き込みます。**キャンセル**は入力した内容を破棄します。AI がオフの間、この行は非表示で、ワークスペースの指示はそのまま残ります。

ワークスペースの内容は、全体の指示とリポジトリ自身の指示の間に入ります（順序と*置き換え*の動作は [AI の指示](ai.md#指示)を参照）。複数のワークスペースに属するリポジトリでは、ウィンドウのアクティブなワークスペースがそのリポジトリを含んでいればそれ、なければ含む最初のものが使われます。スクリプトからは：`gitpoulpi workspace set-ai-instructions <id> [--action <a>] [--mode append|replace] (--text ... | --clear)`。`workspace show` は `ai_instructions` として出力します。

```toml
[[workspace]]
id = "acme"
name = "Acme"
repos = ["/home/u/src/acme-api"]

[workspace.ai_instructions]       # every AI action in this workspace
text = "Use the Acme glossary."
mode = "add"                       # or "replace"

[workspace.ai_overrides.code_review]   # one action
text = "Flag missing tests."
mode = "add"
```

## 既定のプロファイル

commit には、次のうち最初に当てはまるプロファイルが使われます。

1. そのリポジトリに対して**手動で**選んだプロファイル（ツールバーのプロファイルのフィールド）。
2. リポジトリがメンバーである場合の、**有効なワークスペース**のプロファイル。
3. `general.active_profile`。

ツールバーのプロファイルのフィールドには、その由来が表示されます：「Work - ワークスペース Acme 由来」。
プロファイルが 1 つしかない場合でも、ワークスペースの既定が効いている間は、このフィールドが表示されます。
プロファイルがもう存在しないワークスペースは、単に適用されなくなります。CLI では、`commit --workspace <id>`
（または `GITPOULPI_WORKSPACE`）が同じ順序で決定します。

## キー

| キー | 操作 |
|---|---|
| `Alt+W` | ワークスペースのドロップダウンを開く |
| `Alt+J` | ワークスペースのタブを開く |
| `n`、`a` | 新しいワークスペース、開いているタブから新規作成 |
| `e` | ワークスペースを編集 |
| `Shift+F`、`Shift+P`、`m`、`l` | すべてFetch、すべてPull、見つからないものをクローン、場所を指定 |

どれも設定 > キーボードとマウスで再割り当てできます。完全な一覧は[キーバインド](keybindings.md)にあります。
