# AI 지원

GitPoulpi는 계정이 필요 없으며 **AI는 기본적으로 꺼져 있습니다**. AI를 켜면 commit과 stash 메시지를 작성하고, 변경 사항을 설명하고, pull request 설명을 작성하고, merge 충돌 해결 방법을 제안하고, 작업 중인 변경 사항을 여러 commit으로 나눌 수 있습니다. 모델은 사용자가 정합니다. 직접 가진 API 키, 로컬 서버, 또는 이미 설치된 에이전트 CLI(`claude -p` 등) 중에서 고릅니다.

모든 AI 컨트롤에는 보라색 `✦`가 표시됩니다. AI가 꺼져 있는 동안에는 다음과 같습니다.

- 어디로도 아무것도 전송되지 않습니다.
- AI 컨트롤이 표시되지 않습니다. `✦` 버튼, `AI:` 팔레트 명령, AI 메뉴 행, AI 키 힌트가 모두 없으며 AI 키는 아무 동작도 하지 않습니다.
- 저장소 AI 페이지에는 "AI가 꺼져 있습니다 (설정 > AI)"만 표시됩니다.
- MCP 서버는 `ai_*` 도구를 나열하지 않습니다. `gitpoulpi ai ...` CLI 명령은 같은 메시지로 거부합니다.

**AI 사용**은 즉시 적용됩니다. 재시작할 필요가 없습니다.

GitPoulpi에서 AI를 사용하는 방법은 두 가지입니다.

| | 내장 AI (이 페이지) | 외부 에이전트 |
|---|---|---|
| 내용 | GitPoulpi가 모델에게 commit 메시지, 설명 등을 요청합니다 | Claude Code, Cursor, Codex... 가 GitPoulpi를 도구로 구동합니다 |
| 설정 위치 | 설정 > AI (`[ai]`) | 에이전트의 MCP 구성, 제한은 `[mcp]` |
| 안내 | 아래 | [MCP와 에이전트](mcp-and-agents.md) |

## AI 구성

1. `Ctrl+,` > **AI** > **AI 사용**에 체크합니다.
2. 프로필은 **프로필 (연결)** 탭의 목록이며 페이지 왼쪽에 있습니다(좁은 터미널에서는 위쪽에 쌓입니다). 하나를 고르면 오른쪽에서 편집할 수 있습니다(`Enter`로 그 행들로 이동하며, 팔레트의 **AI: 프로필 편집...**은 목록으로 이동합니다). *Default*라는 이름의 프로필은 항상 존재합니다. **+ 추가**는 프로필을 하나 더 만들고, **복제**는 선택한 프로필을 (키 없이) 복사하며, **제거**는 먼저 확인합니다. **제공자**를 고르고 해당 필드를 채웁니다.

   | 제공자 | 필드 | 기본값 |
   |---|---|---|
   | **로컬 에이전트** (키도 자체 계정도 없음) | **에이전트 종류**(어떤 에이전트인지), **명령**(정확한 프로그램: `PATH`에 있는 것, 별칭이나 래퍼 스크립트, 또는 전체 경로), 비대화형으로 만드는 **인자**, 선택 사항인 **환경 변수**. 프롬프트는 stdin으로 들어가고 응답은 stdout에서 읽습니다. | Claude Code: `claude`, `-p --model haiku` |
   | **Anthropic** | **API 키**, 선택 사항인 **모델**과 **기본 URL** | `claude-sonnet-5`, `https://api.anthropic.com/v1` |
   | **OpenAI** | **API 키**, 모델, 기본 URL | `gpt-5`, `https://api.openai.com/v1` |
   | **OpenRouter** | **API 키**, 모델, 기본 URL | `openai/gpt-5`, `https://openrouter.ai/api/v1` |
   | **OpenAI 호환** (Ollama, LM Studio, vLLM, 회사 게이트웨이) | **기본 URL**(`.../v1`), **모델**, 선택 사항인 키 | `http://localhost:11434/v1` (Ollama, LM Studio는 `http://localhost:1234/v1`), `llama3` |

   **프리셋**(다른 값도 언제든 직접 입력할 수 있습니다):

   ![로컬 에이전트 프로필의 에이전트 종류 드롭다운: Claude Code, OpenAI Codex CLI, Gemini CLI, opencode와 그 밖의 에이전트 CLI가 나열됨](../images/settings-ai-presets.png)

   - **로컬 에이전트 > 에이전트 종류**는 널리 쓰이는 에이전트 CLI의 드롭다운이며 가장 많이 쓰이는 것부터 나열됩니다. Claude Code, OpenAI Codex CLI, Gemini CLI, opencode, Cursor Agent, GitHub Copilot CLI, Pi, Qwen Code, Aider, Goose, Crush, Amp, 그리고 *기타(제안 없음)*입니다. 종류는 **명령과 별개**입니다. 어떤 제안을 받을지만 정합니다. 하나를 고르면 **명령**(아직 이전 종류의 기본값인 경우)과 **인자**가 헤드리스 호출(`claude -p`, `codex exec -`, `gemini -p ...` 등)로 미리 채워집니다. **명령**은 자유 텍스트입니다. `/opt/bin/work-claude`, 래퍼 스크립트, 별칭 대상을 쓰더라도 종류와 그 옵션, 모델 목록, 변수는 그대로 유지됩니다. **에이전트 종류**가 비어 있으면 GitPoulpi가 명령에서 추론합니다.
   - **인수 옵션**은 GitPoulpi의 일회성 사용에 맞는 옵션을 추가하거나 제거하며, 각각 한 줄 설명이 붙어 있습니다. 도구 없음, 저장된 세션 없음, 일반 텍스트 출력, 낮은 추론 수준, 읽기 전용 모드, 권한 프롬프트 없음, 업데이트 확인 및 사용 통계 없음입니다. 에이전트마다 다르기 때문에 목록도 에이전트별로 다릅니다(명령줄에서 도구를 끌 수 있는 에이전트는 일부뿐이며, opencode는 환경 변수를 사용합니다). **모델**은 해당 에이전트의 모델을 나열하고 올바른 플래그를 써 줍니다(Claude Code는 `--model haiku`, Codex는 `-m gpt-6-luna`, opencode는 `--model provider/model`). *(기본값 - 플래그 없음)*은 플래그를 제거합니다. Amp에는 모델 플래그가 없습니다. `aider`는 프롬프트를 `/dev/stdin`에서 읽으므로 Linux와 macOS에서만 동작합니다.
   - **환경 변수**는 해당 에이전트의 프로세스에만 설정되며 GitPoulpi나 다른 프로필에는 설정되지 않습니다. **환경 변수 추가**는 이 에이전트에 중요한 문서화된 변수를 각각의 기능 설명과 함께 제시합니다(원격 측정과 업데이트 확인 끄기, 추론 수준, 구성 디렉터리, API 키, 기본 URL 또는 로컬 호스트 등). `NAME` 또는 `NAME=value`를 직접 입력할 수도 있습니다. 이후 변수마다 **Env NAME** 행이 생기며, 값이 버튼으로 표시됩니다(누르면 새 값을 입력하고, 필드를 벗어날 때 저장됩니다). 옆의 **[x]** 버튼은 그 변수를 삭제합니다. 값에 `${env:NAME}`을 쓰면 GitPoulpi 자신의 변수를 빌려 올 수 있습니다(API 키를 `config.toml`에 기록하지 않으려 할 때 유용합니다). 비밀로 보이는 값(`_KEY`, `_TOKEN`, `_SECRET`... 로 끝나는 이름이나 잘 알려진 키 접두사)은 점으로 표시되며 처음부터 새로 입력합니다. 값은 절대 로그에 남기지 않습니다.
   - **HTTP 제공자 > 제공자 프리셋**은 OpenAI, Anthropic, OpenRouter, Google Gemini, xAI, DeepSeek, Mistral, Groq, Together, Fireworks, Cerebras, Perplexity, Moonshot, Qwen (DashScope), Zhipu (GLM)와 로컬 서버 Ollama, LM Studio, llama.cpp, vLLM, Jan, LocalAI의 기본 URL과 모델을 채워 줍니다. **모델**은 해당 제공자의 모델 드롭다운이며 자유 텍스트도 허용됩니다.

3. **연결 테스트**를 누릅니다. *마지막 테스트*에 `연결됨: 모델이 응답했습니다` 또는 `실패: <이유>`가 표시됩니다.
4. 프로필이 여러 개이면 맨 아래에서 **기본 프로필**을 고릅니다. 각 동작은 여전히 자체 프로필을 지정할 수 있습니다.

![로컬 에이전트용 AI 페이지 프로필 블록의 아래쪽: 실행 모드, 인자, 모델, 작업 폴더, 제한 시간, Env 행 두 개, 환경 변수 추가, 연결 테스트](../images/settings-ai-agent.png)

**API 키**는 **API 키** 행에서 `Enter`로 입력하며, `config.toml`이 아니라 시스템 자격 증명 도우미(Git Credential Manager, libsecret / `pass`, Keychain)에 `ai:<profile id>` 이름으로 저장됩니다. 도우미가 없으면 GitPoulpi는 보관하는 척하지 않고 그렇게 알려 줍니다. *설정 > SSH 및 자격 증명 > 모든 사용자 이름과 비밀번호 삭제*가 이를 제거합니다.

`config.toml`에서는 다음과 같습니다(나머지 모든 내용은 [설정 참조](config-reference.md#ai-내장-ai-기본적으로-꺼짐)에 있습니다).

```toml
[ai]
enabled = true
default_profile = "claude-code"

[[ai.profiles]]
id = "claude-code"
name = "Claude Code"
kind = "local_agent"      # open_ai | anthropic | open_router | open_ai_compatible | local_agent
command = "claude"        # free: an alias, a wrapper script, an absolute path
harness = "claude"        # which agent it is; empty = inferred from `command`
args = ["-p", "--model", "haiku"]

[ai.profiles.env]         # this agent's process only; ${env:NAME} borrows ours
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC = "1"
ANTHROPIC_API_KEY = "${env:ANTHROPIC_API_KEY}"
```

## 실행 모드: 헤드리스 또는 가상 터미널

로컬 에이전트 프로필은 **실행 모드**에서 고른 두 방식 중 하나로 에이전트를 실행합니다
(Claude Code, OpenAI Codex CLI, Gemini CLI에 표시됩니다).

- **헤드리스 (비대화형)**, 기본값: 에이전트의 단발성 모드(`claude -p`)입니다.
  프롬프트는 stdin으로 보내고 답변은 stdout으로 받습니다.
- **대화형 (가상 터미널)**: GitPoulpi가 숨겨진 터미널에서 에이전트 고유의 화면을
  시작하고, 사람이 하듯 요청을 입력한 뒤 답변을 기다렸다가 에이전트를 닫습니다.
  일부 에이전트는 헤드리스 모드와 대화형 모드의 요금 부과나 사용 제한이 다릅니다.
  어느 쪽이 적용되는지, 그리고 두 모드에 대한 제공자의 약관이 무엇인지는
  제공자에 따라 다르니 해당 제공자의 내용을 확인하세요.

각 모드는 자신의 **인자**, **인자 옵션**, **모델**을 따로 유지합니다. 모드를 바꿔도
잃는 것이 없으며, 대화형 모드는 헤드리스 플래그 없이도 의미 있는 옵션만
제공합니다. 두 모드 모두에 적용되는 행이 둘 더 있습니다.

- **작업 폴더**: *전용 폴더*는 GitPoulpi가 소유한 빈 폴더로, 에이전트에게 프로젝트가
  보이지 않으며 한 번 신뢰해 달라고 요청합니다. *현재 저장소*는 에이전트에 프로젝트
  자체의 컨텍스트(예: `CLAUDE.md`)를 제공하며, 저장소마다 한 번씩 신뢰 여부를
  묻습니다. *기본값*은 대화형 모드에서는 전용 폴더이고, 헤드리스 모드에서는 이전처럼
  GitPoulpi 자체가 실행 중인 폴더입니다.
- **제한 시간 (초)**: GitPoulpi가 포기하고 에이전트를 중지하기까지 에이전트에 주어지는
  시간입니다. 비워 두면 헤드리스 120초, 대화형 180초입니다.

**처음 실행할 때의 질문은 직접 답해야 합니다.** 폴더에서 한 번도 실행된 적 없는
에이전트는 먼저 무언가를 묻습니다(이 폴더를 신뢰할지, 로그인, 테마 선택).
GitPoulpi는 절대 대신 답하지 않습니다. 요청은 메시지와 함께 중단되며, 프로필의
**에이전트 열기...**(또는 명령 팔레트의 *AI: 에이전트 열기*)가 에이전트를 사용할
작업 폴더에서 눈에 보이는 터미널로 한 번 엽니다. 질문에 답하고, 에이전트를 닫고,
다시 시도하세요. 답은 에이전트가 기억합니다.

### 탭의 폴더에서 에이전트 열기

명령 팔레트의 `탭: 여기서 AI 에이전트 열기`(`palette.tab_open_agent_here`로 다시 바인딩 가능, 기본 키 없음)는
활성 탭의 폴더에서 터미널을 열고 로컬 에이전트 프로필의 에이전트를 실행하여, 그곳에서 직접 작업할 수 있게 합니다.
**여기서 터미널 열기**와 같은 터미널이고 **에이전트 열기...**와 같은 명령이지만, 프로필 자체의 작업 폴더 대신
탭의 폴더에서 실행됩니다. 로컬 에이전트 프로필이 하나면 바로 열리고, 여러 개면 탭 표시줄 아래의 목록이 어느 것인지
묻습니다. 프롬프트를 보내지 않고 AI 요청도 시작하지 않습니다: 에이전트를 여는 것이 동작이며, 그 안에서 입력하는
내용은 내 몫입니다.

이 행에는 AI 반짝이 표시가 붙고, AI가 꺼져 있으면(**설정 > AI**) 숨겨지며, 로컬 에이전트인 프로필이 없으면
("설정된 로컬 AI 에이전트가 없습니다") 회색으로 표시됩니다. 시퀀스에서는 `tab_open_agent_here` 단계가 `profile`
옵션으로 AI 프로필의 `id`를 받습니다(비워 두면 기본 프로필, 없으면 첫 번째 로컬 에이전트). 직접 만든 터미널
템플릿에는 에이전트의 명령을 넘길 수 없습니다: 터미널은 해당 폴더에서 열리고, 상태 표시줄이 실행할 명령을 알려 줍니다.

답변은 Claude Code의 경우 에이전트의 세션 기록(정확한 텍스트이며 이후 삭제됨)에서
읽고, Codex와 Gemini의 경우 요청이 요구하는 두 마커 줄 사이의 화면에서 읽습니다.
가상 터미널 실행은 동시에 최대 두 개까지이며, 요청 중에 Esc를 누르면 에이전트가
중지됩니다.

```toml
[[ai.profiles]]
id = "claude-terminal"
kind = "local_agent"
command = "claude"
harness = "claude"
args = ["-p"]                       # the headless set, kept
run_mode = "terminal"               # headless (default) | terminal
terminal_args = ["--effort", "low"] # the interactive set
workdir = "dedicated"               # default | dedicated | repository
timeout_secs = 180                  # 0 or absent: 120 headless, 180 terminal
```

## 지침

모델에게 전달되는 내용에 덧붙이는 텍스트입니다. 각 동작의 내장 프롬프트(응답 형식을 고정합니다)는 항상 맨 앞에 오며 편집할 수 없습니다. 그다음 가장 일반적인 것부터 가장 구체적인 것까지 네 단계가 이어지며, 각 단계는 비어 있지 않을 때만 쓰입니다.

1. **전역 지침**(모든 동작). 편집기의 *빠른 삽입* 칩이 자주 쓰는 문장을 삽입합니다. *<언어>로 응답*, *간결하게 응답*, *명령형 사용*, *기술적인 어조*, *친근한 어조*.
2. **워크스페이스 지침**(모든 동작, [워크스페이스](workspaces.md#워크스페이스의-ai-지침)의 모든 저장소): 모든 동작에 대해, 그리고 선택적으로 동작별로. 워크스페이스의 편집 양식에서 편집합니다.
3. **저장소 지침**(모든 동작, 이 저장소에만 적용), *전역과 결합* 포함: **전역에 추가**(전역 지침 뒤에) 또는 **전역 대체**(전역 지침 대신).
4. **동작별 지침**(*Commit 메시지 생성*, *변경 사항 설명*, *Stash 메시지 생성*, *Pull request*, *Commit 작성기*, *충돌 해결*, *코드 리뷰*, *Commit 분할*). 각 블록에는 편집기에 자체 칩(예: *Conventional commits 형식*, *50자 제한*)과 자체 **프로필** 드롭다운이 있습니다(`기본값 (<name>)`은 기본 프로필을 따릅니다).

*사용자 지정 지침* 행에서 `Enter`를 누르면 여러 줄 편집기가 열립니다(`Ctrl+S`로 저장, `Esc`로 취소). 텍스트 위의 *빠른 삽입* 행에 그 섹션의 칩이 있습니다. 칩을 클릭하면 캐럿 위치에 그 문장이 삽입됩니다. 키보드에서는 `Tab`으로 그 행으로 이동하고, `Left`/`Right`로 칩을 고르고, `Enter` 또는 `Space`로 삽입한 뒤 텍스트로 돌아갑니다(`Tab`이나 `Esc`는 삽입 없이 돌아갑니다). 문장이 이미 지침에 들어 있는 칩은 흐리게 표시되며 다시 삽입해도 아무 일도 일어나지 않습니다. 텍스트는 완전한 편집기입니다. 클릭하면 캐럿이 놓이고, 드래그나 `Shift`+화살표로 선택하며, `Ctrl+A`는 모두 선택, `Ctrl+C` / `Ctrl+X`는 선택 영역을 복사하고 잘라내며, `Ctrl`+화살표는 단어 단위로 이동하고, `Home` / `End`, `PageUp` / `PageDown`, 마우스 휠로 긴 텍스트를 이동합니다. 페이지 자체에는 각 지침의 미리보기만 표시됩니다.

![AI 페이지: 전역 지침, 이어서 프로필 드롭다운과 사용자 지정 지침이 있는 Commit 메시지 생성과 변경 사항 설명 블록](../images/settings-ai.png)

**저장소별**: *설정 > 저장소별 설정 > AI*(저장소가 열려 있는 동안)에는 저장소 지침과, 동작별로 전역 설정을 재정의하는 프로필과 지침이 있습니다. 비워 둔 필드는 전역 설정을 사용합니다(해당 필드에 회색으로 표시됩니다). **전역으로 초기화**는 재정의를 제거합니다. 저장소의 `.gitpoulpi/repo-state.toml`에 저장되며 CLI에서도 적용됩니다.

![저장소의 AI 페이지: 전역과 결합 드롭다운이 있는 저장소 지침, 이어서 각 동작의 프로필과 지침](../images/settings-repo-ai.png)

### 단계가 결합되는 방식

전송 순서는 내장 프롬프트, **전역**, **워크스페이스**, **저장소**, 그다음 동작 자체의 지침입니다. 단계의 모드가 그 위의 단계들에 어떤 일이 생기는지
정합니다:

- **추가**(기본값): 그 단계의 텍스트가 더 일반적인 단계들 뒤에 붙습니다.
- **대체**: 그 단계의 텍스트가 더 일반적인 모든 단계 *대신* 쓰입니다(전역, 그리고 저장소가 대체하면 워크스페이스). 텍스트가 없는 단계는 아무것도
  대체하지 않습니다.

동작 자체의 지침도 같은 방식입니다: 그 동작의 전역 지침, 그다음 그 동작의 워크스페이스 지침(그 뒤에 추가되거나 그것들을 대체), 그리고 저장소가 그 동작에
대해 가진 자체 재정의가 둘 모두보다 우선합니다. 사용되는 워크스페이스는 창의 활성 워크스페이스가 해당 저장소를 포함하면 그것이고, 아니면 해당 저장소를
포함하는 첫 번째 워크스페이스입니다. 명령줄에서는 `GITPOULPI_WORKSPACE`의 워크스페이스이고, 없으면 첫 번째입니다.

전송되는 내용을 단계별로 정확히 보려면 `gitpoulpi ai prompt --action <action> --repo .`를 실행하세요(`base`, `global`, `workspace`, `repository`, `task`,
그리고 최종 `system_prompt`). 모델을 호출하지 않으며 AI가 꺼져 있어도 동작합니다. 워크스페이스의 지침은 스크립트에서
`gitpoulpi workspace set-ai-instructions <id> [--action <a>] [--mode append|replace] --text ...`(또는 `--clear`)로 설정합니다.

### 프롬프트 변수

모든 지침 텍스트(전역, 워크스페이스, 저장소, 동작별)에는 `${name}` 변수를 쓸 수 있습니다. 변수는 프롬프트를 전송하기 직전에 값으로 치환됩니다(저장된 텍스트에는 `${...}`가 그대로 남습니다). 표에 없는 이름은 쓴 그대로 전송되며 편집기가 이를 경고합니다. 문자 그대로의 `${`는 `$${`로 씁니다.

| 변수 | 치환되는 값 | 예 |
|---|---|---|
| `${uilang}` | UI 언어, 영어 이름 | `French` |
| `${repo}` | 저장소의 폴더 이름 | `gitpoulpi` |
| `${branch}` | 현재 브랜치 | `main` |
| `${ref}` / `${commit}` | 동작 대상 commit(*설명*)의 짧은 sha, 없으면 HEAD | `4c0443d` |
| `${commit_subject}` | 해당 commit의 제목 줄 | `feat: add search` |
| `${date}` | 로컬 날짜, ISO | `2026-10-03` |
| `${time}` | 로컬 시간, `HH:MM` | `14:05` |
| `${datetime}` | 로컬 날짜와 시간 | `2026-10-03 14:05` |
| `${user}` / `${email}` | `git config user.name` / `user.email` | `Ada Lovelace` |
| `${remote}` | 기본 리모트(`origin`, 없으면 첫 번째) | `origin` |
| `${host}` | `github`, `gitlab`, `other`(다른 호스트) 또는 `none` | `github` |
| `${files}` | 동작의 diff에 포함된 파일 수 | `3` |
| `${action}` | 실행 중인 동작 | `commit_message` |

지침 편집기에서 `${`를 입력하면 일치하는 변수를 나열하는 팝업이 나타납니다(`Up`/`Down`으로 선택, `Enter` 또는 `Tab`으로 삽입, `Esc`로 닫기). 또는 왼쪽 아래의 **변수** 드롭다운(`Ctrl+T`, 또는 명령 팔레트의 *AI: 프롬프트 변수 삽입*)을 사용하면 캐럿 위치에 삽입됩니다. 각 항목에는 설명이 있으며, 마우스를 올리거나 강조 표시하는 동안 드롭다운과 버튼 위의 줄에 표시됩니다.

### Merge 충돌 해결

모델은 파일의 경로와 언어, 충돌의 base, 현재(A), 들어오는(B) 블록(편집기에 표시되는 레이블 포함), 그 앞뒤로 이미 merge된 텍스트 최대 20줄, 그리고 사용자의 지침(전역, 저장소, 설정 > AI의 *충돌 해결* 지침)을 받습니다. 모델은 해당 충돌 하나의 해결된 텍스트를 코드 블록으로 답합니다. 코드 대신 충돌 마커나 잡담이 담긴 응답은 한 번 되돌려 보낸 뒤 거부합니다. 40 KB(`ai.limits.conflict_bytes`, *설정 > AI > 한도*)를 넘는 충돌은 크기와 한도를 알려 주는 경고 뒤에서 보류되며, *그래도 보내기*(이번 요청에만, 개인정보 검사는 그대로 적용), *설정 열기*, *취소*를 고를 수 있습니다. 이 한도는 GitPoulpi 자체의 안전장치이므로 모델에 여유가 있으면 늘리세요. AI가 꺼져 있는 동안 컨트롤은 숨겨지며, 제안은 어떤 것도 저장하거나 스테이징하거나 해결하지 않습니다. 출력을 검토하고, 편집하고, 평소처럼 저장하세요.

### Commit 작성기

모델은 작업 중인 변경 사항을 여러 commit으로 나눕니다(변경된 모든 파일이 정확히 한 commit에 들어갑니다. 유효하지 않은 계획은 한 번 되돌려 보낸 뒤 거부합니다). 파일에 아직 충돌이 있는 동안에는 아무것도 요청하지 않습니다. 작성기에는 충돌 없는 트리가 필요하므로, 대화상자가 해당 파일을 나열하고 충돌 해결 보기를 엽니다. 아무것도 commit되기 전에 계획을 검토합니다.

![작성기 검토 화면: 파일이 딸린 제안된 commit 네 개, 그리고 초기화, 취소, commit 4개 만들기 버튼](../images/composer.png)

| 키 | 마우스 | 동작 |
|---|---|---|
| `Up` / `Down` (`k` / `j`) | 행 클릭 | commit과 파일 사이를 이동 |
| `Alt+Up` / `Alt+Down` (`K` / `J`), `m` | 화살표, 드래그 앤 드롭 | commit 이동, 파일을 다른 commit으로 이동 |
| `Right` / `Left`, `*` | 행의 화살표 | commit 펼치기 / 접기, 전체 펼치기 / 접기(`ui.composer_files`가 시작 상태를 정함) |
| `e` / `Enter` | 연필 | 메시지 편집 |
| `d` / `Delete` | `삭제` / `복원` | commit 제외(파일은 commit되지 않은 상태로 남음) |
| `n` | `+ 별도 commit` | 파일을 별도의 commit으로 이동 |
| `r` | `초기화` | 모델의 계획으로 되돌리기 |
| `Ctrl+S` / `a` | `commit N개 만들기` | 순서대로 생성 |
| `Esc` | `취소` | 아무것도 하지 않고 나가기 |

생성할 때는 각 commit의 파일을 스테이징하고 차례로 commit하며, 작업 트리는 건드리지 않습니다. 일부만 스테이징된 파일은 통째로 commit됩니다. 한 단계가 실패하면 중단하고 commit이 몇 개 만들어졌는지 알려 줍니다.

### Commit 분할

모델은 commit의 변경 사항을 [분할 편집기](log-and-history.md#commit-분할)와 같은 번호로 읽고, 메시지가 하나씩 달린 여러 commit을 제안합니다. hunk와 개별 줄도 묶을 수 있습니다. 변경을 빠뜨리거나, 같은 변경을 두 번 배정하거나, 존재하지 않는 것을 가리키는 응답은 거부됩니다. 어느 쪽이든 분할 편집기가 열립니다. 제안이 채워진 상태로 열리거나, 모델이 실패했다면 이유를 적은 안내와 함께 열리므로 직접 분할할 수 있습니다. **분할**(`Ctrl+S`)을 누르기 전에는 아무것도 분할되지 않으므로, 묶음이 맞지 않으면 먼저 변경을 옮기거나 commit 이름을 바꾸거나 commit을 추가하십시오. 프로필과 지침은 설정 > AI의 *Commit 분할* 항목입니다.

### 기록 다시 쓰기 스크립트

다시 쓰기가 해야 할 일을 설명하면("밤에 만든 commit을 모두 다음 날 아침으로 옮기기", "예전 이메일을 새 이메일로 바꾸기, 2024년 이전만") 모델이 스크립트 규칙에 쓸 [Lua 스크립트](history-rewrite.md#lua-스크립트)를 작성합니다. 머리말, `rewrite_commit(c, ctx)`, 샌드박스의 도우미가 포함됩니다. 데몬이 답을 컴파일하며, 컴파일되지 않으면 오류를 모델에게 한 번 돌려보냅니다. 남은 결과는 편집기에 표시되므로 읽어 보고, 테스트한 다음 미리보기하십시오. 자세한 내용과 대화상자는 [기록 다시 쓰기](history-rewrite.md#ai로-스크립트-작성)에 있습니다. 프로필과 지침은 설정 > AI의 *기록 다시 쓰기 스크립트* 항목입니다.

### 기록 다시 쓰기 규칙

기록을 어떻게 다시 써야 하는지 자기 말로 설명하면("내 예전 이메일 a@b.org를 c@d.org로 바꾸기", "전체 기록에서 secrets.txt 제거") 모델이 범위, 몇 가지 설정, [다시 쓰기 규칙](history-rewrite.md#ai로-규칙-만들기) 목록을 워크벤치의 어휘로 제안합니다. **준비만 합니다**: 답은 워크벤치를 채울 뿐 미리보기도 적용도 하지 않으며, 쓸 수 없는 항목은 이유와 함께 목록에 표시되고 유효한 항목은 유지됩니다. 이 방법으로 스크립트 규칙은 만들어지지 않습니다. 원하면 범위, 브랜치와 tag 이름, 최신 commit의 작성자도 함께 보낼 수 있습니다(기본값 꺼짐인 확인란이며, "전송되는 내용" 창에 표시됩니다). 프로필과 지침은 설정 > AI의 *기록 다시 쓰기 규칙* 항목입니다.

### 시퀀스 초안

동작 시퀀스를 자기 말로 설명하면("모두 스테이징하고, AI로 메시지를 작성하고, commit한 뒤 push", 또는 기존 시퀀스에 대해
"먼저 fetch 추가") 모델이 이름, ID, 단계, 원하면 단축키까지 제안합니다. **제안만 합니다**: 수락하기 전에는 아무것도
저장되지 않고 아무것도 실행되지 않습니다. 모델은 시퀀스에 들어갈 수 있는 명령만 알며(모델에 주는 목록은 시퀀스를 검증하는
표에서 생성되므로 어긋날 수 없습니다), 단계마다 따로 검사됩니다. 알 수 없거나, 위험하거나, 다른 시퀀스를 실행하거나,
불가능한 일시 중지를 요구하는 단계는 이유와 함께 목록에 표시되고 제외되며 유효한 단계는 유지됩니다. 선택적으로 리모트
이름, AI 프로필 ID, 열기 위치 레이블도 함께 보냅니다(기본값 꺼짐, CLI 플래그는 `--context`). 터미널에서
`gitpoulpi ai sequence-draft`는 제안을 JSON으로 출력하며(`gitpoulpi sequence add --file`이 읽는 `toml` 포함) 아무것도
저장하지 않습니다. 프로필과 지침은 설정 > AI의 *시퀀스 초안* 항목입니다.

터미널 UI에서는 같은 작업이 설정 > 시퀀스 > **추가**의 **AI로 만들기...** 항목(팔레트: `시퀀스: AI로 만들기...`)과
시퀀스의 **AI로 편집...** 버튼입니다. 원하는 내용을 쓰는 대화상자(기본값이 꺼진 컨텍스트 상자와 "전송되는 내용" 질문
포함)가 열리고, 이어서 **수락**, **저장 전에 편집**, **거부**하거나 **뒤로**로 다시 보낼 수 있는 제안이 나옵니다.
편집은 현재 시퀀스와의 차이를 보여 주고(`+` 추가, `-` 삭제, `~` 변경), 제안된 단축키는 내 키맵과 대조만 할 뿐
바인딩되지 않습니다. 수락하기 전에는 아무것도 저장되지 않습니다([시퀀스](sequences.md#ai로-만들기와-편집) 참조).

### 호스트에서 쓰기 도움

*호스트의 답글*은 댓글, 스레드의 답변, 코드 줄에 다는 댓글 또는 리뷰 요약의 초안을 쓰고, *이슈 설명*은 새 이슈의 설명 초안을 씁니다. **AI는 초안만 작성합니다.** 텍스트는 입력창에 들어가거나(CLI에서는 출력되어) 내가 읽고, 고치고, 직접 보냅니다. 이 기능에서 호스트에 쓰는 코드 경로는 없습니다: 게시, 편집, 해결, 삭제를 할 수 없고, CLI와 MCP의 응답에는 `"posted": false`가 들어 있으며, 로컬 에이전트는 읽기 전용으로 실행됩니다(아래). 텍스트는 입력창 자체의 **보내기**(`Ctrl+Enter`) 또는 댓글 버튼으로만 GitPoulpi를 떠납니다.

**Markdown 입력창에서.** AI가 켜져 있으면 호스트로 텍스트를 보내는 모든 입력창([대화 보기](conversations.md#대화)의 댓글, 답글 또는 편집, 리뷰 댓글, 리뷰 마치기 요약, 새 이슈 설명, pull request 설명)의 모드 표시줄 오른쪽 끝에 **AI로 쓰기** 버튼(`Alt+E`, 모두 같은 키)이 있습니다. 누르면 표시줄 아래에 패널이 열립니다.

- *이 답변에 담고 싶은 내용* 필드: 사용할 때 입력합니다(`Enter`로 초안 작성). 자리 표시자에 예시가 있습니다("동의하고, 실패하는 테스트를 요청"). **최근** 목록에 이전 지시문이 남습니다(클릭하거나 필드에서 `Up` / `Down`. `ai-hints.toml`에 보관).
- *내 초안 다듬기*: 상자에 이미 텍스트가 있으면 체크되어 있으며, AI가 새로 쓰지 않고 그 텍스트에서 시작합니다.
- *AI가 저장소를 읽도록 허용*: 기본값을 켜지 않았다면(아래 참고) **매번 체크 해제** 상태입니다.
- **초안**, **중지**(`Esc`도 가능), **닫기**, 그리고 진행 상황이나 오류를 보여 주는 한 줄.

평소의 "보내는 내용" 대화상자(`[ai.sent_preview] hosting_reply`, `issue_body`, `pull_request_description`)가 요청이 나가기 전에 내용을 보여 줍니다. 시스템 텍스트와 사용자 텍스트 외에, 저장소를 읽을 때는 **저장소 컨텍스트** 목록을 보여 줍니다: 각 부분의 크기, 한도 대비 합계(*48 KB 중 31.2 KB*), 맞추려고 잘라낸 것, 민감해서 제외한 것, 재사용되는 부분. 로컬 에이전트의 경우 에이전트가 읽기 전용 도구로 저장소를 직접 읽는다고 알리고, 도구 이름과 작업 폴더, 에이전트 세션이 새로 시작되었는지 이어지는지를 표시하며, 모든 대화상자는 *AI는 초안만 작성합니다. 직접 보내기 전에는 아무것도 게시되지 않습니다.*로 끝납니다. 초안은 한 번의 실행 취소 단계로 텍스트를 대체하고 입력창이 미리보기로 전환되어 보내기 전에 읽어 볼 수 있습니다. `Ctrl+Z`를 누르면 내 텍스트가 돌아옵니다. pull request 설명은 브랜치의 commit과 diff로 작성되며 같은 지시문을 받습니다. 거기서는 저장소 선택이 회색으로 표시됩니다("이 텍스트에는 해당 없음").

모델이 받는 것: 항목의 제목, 상태, 설명, 내가 답하는 스레드, 최근 댓글(최신 순, `ai.limits.hosting_reply_context_bytes` 이내, 기본값 49152), 호스트가 받는 마크업(그래서 Jira 답변은 GitPoulpi가 변환하는 Markdown으로 돌아옵니다), 이 답변에 담고 싶은 내용, 그리고 내 텍스트를 다듬을 때는 내 초안. 다른 사람이 쓴 모든 것은 요청에서 신뢰할 수 없는 데이터로 표시되므로 댓글에 숨은 지시문은 따르지 않습니다. 한도를 넘으면 몰래 자르지 않고 물어봅니다. 가장 오래된 댓글부터 빠집니다(내가 답하는 스레드는 예산의 절반까지 유지). CLI는 잘림을 `truncated`에 보고하며 `--send-all`이 이를 해제합니다.

**나만의 기본 프롬프트.** 두 동작이 출발점으로 삼는 지시문은 편집할 수 있습니다: *설정 > AI > 호스트의 답글 > 기본 프롬프트*(`ai.hosting_reply.base_prompt`). 비어 있으면 내장 프롬프트를 쓰며, 이 프롬프트는 텍스트만, 호스트의 마크업으로, 힌트가 달리 말하지 않는 한 대화의 언어로 달라고 요청합니다. 전역, 워크스페이스, 저장소 지시문은 그 뒤에 계속 이어지며, 거기에 무엇을 쓰든 다른 사람의 텍스트는 신뢰할 수 없는 것으로 표시됩니다. `ai prompt --action hosting_reply`가 각 단계를 출력합니다.

#### 저장소 접근

**기본값은 꺼짐이며 사용할 때마다 체크합니다.** 저장소를 읽으면 "이 충돌이 우리 코드에서 일어나는가?" 같은 질문에 훨씬 좋은 답이 나오지만 더 많이 보내므로, 매번 내가 고르는 선택입니다: *AI가 저장소를 읽도록 허용*은 모든 상자에서 체크 해제로 시작합니다. `ai.hosting_reply.read_repository`(*기본적으로 AI가 저장소를 읽도록 허용*, 꺼짐)는 상자가 체크된 채로 시작하게만 합니다. `--read-repo`는 CLI의 체크입니다. 이 선택은 세 경우에 회색으로 표시되며 활성화하면 이유가 나옵니다: 저장소가 **복제되어 있지 않음**(Radar에서 연 다른 저장소의 대화. 읽을 것이 없음), 선택한 로컬 에이전트에 GitPoulpi가 신뢰하는 **읽기 전용 모드가 없음**, 텍스트가 **저장소로 작성되지 않음**(pull request 설명). 내가 직접 체크하는 것 외에는 아무것도 이를 켜지 않습니다.

그다음은 프로필에 따라 다릅니다.

| 프로필 | 저장소를 읽는 주체 | 보내는 내용 |
|---|---|---|
| **API** (OpenAI 호환, Anthropic) | GitPoulpi, 데몬을 통해 읽기 전용 | GitPoulpi가 만들어 모델에 주는 컨텍스트: 저장소 맵(최상위 트리와 일치한 파일 주변 경로), 대화에 나온 파일(전체 파일, 또는 줄이나 심볼 주변 40줄), 대화에 나온 식별자와 오류 메시지의 검색 결과, pull request라면 그 diff. `ai.limits.hosting_reply_*` 이내(컨텍스트 49152, 파일 8192, 맵 6144, 검색어당 20건, 검색어 8개)이며, diff, 파일, 검색 결과, 맵 순으로 잘리고 보고됩니다. 민감해 보이는 파일은 제외되고 나머지의 비밀 정보는 먼저 가려집니다([개인정보](#개인정보) 참고). |
| **로컬 에이전트** (Claude Code, Codex), 헤드리스 | 에이전트 자신, 저장소 폴더에서 | 만드는 것은 없습니다: 에이전트가 **읽기 전용 도구**로 저장소에서 시작되어 필요한 것을 읽습니다. Claude Code는 `Read`, `Grep`, `Glob`을 받고 `Bash`, `Edit`, `Write`, `NotebookEdit`, `WebFetch`, `WebSearch`는 거부되며 MCP 서버는 로드되지 않습니다(프로젝트 자체의 서버가 게시할 수 있기 때문). Codex는 읽기 전용 샌드박스에서 실행됩니다. 환경의 호스팅 자격 증명(`GH_TOKEN`, `GITHUB_TOKEN`, `GITLAB_TOKEN`, Jira, Linear, Azure DevOps, Bitbucket 변수, `GIT_ASKPASS`, `SSH_AUTH_SOCK`)은 에이전트의 환경에서 제거되므로, 잘못 설정된 에이전트도 게시나 push를 할 수 없습니다. |

GitPoulpi가 읽기 전용 모드를 확인하지 못한 에이전트(그리고 대화형 터미널 실행 모드의 모든 에이전트)는 들어올 수 없습니다: 선택은 *이 에이전트에는 GitPoulpi가 신뢰하는 읽기 전용 모드가 없습니다.*와 함께 회색으로 유지됩니다.

**캐시와 컨텍스트 새로고침.** 모은 내용은 재사용되어 다음 답글이 빠르고 저렴합니다.

- API 프로필이 만든 컨텍스트는 저장소별로 `ai.hosting_reply.context_ttl_minutes`(*저장소 컨텍스트 유지 시간*, 기본 30분) 동안 보관됩니다. 키는 저장소, 그 `HEAD`, 선택, 한도이며 부분별로 따로 보관되므로, 같은 저장소의 다음 이슈는 공유하지 않는 부분만 다시 만듭니다. 창에서는 캐시가 메모리에 있고(최근 8개 컨텍스트), CLI는 비공개 상태 폴더의 파일에 보관하므로 두 번째 `ai hosting-reply --read-repo`가 첫 번째가 만든 것을 재사용합니다.
- 체크아웃된 브랜치의 새 commit(`HEAD`가 이동), 한도 변경, 또는 시간 제한이 되면 처음부터 다시 시작합니다. **컨텍스트 새로고침**(저장소를 읽을 때 패널의 버튼) 또는 CLI의 `--refresh-context`도 마찬가지입니다. 상자 아래 한 줄이 마지막 초안이 한 일을 알려 줍니다: *컨텍스트 생성: 5개 부분, 31.2 KB, HEAD a1b2c3d*, *컨텍스트 재사용 (5개 중 4개 부분, HEAD a1b2c3d)*, *제공자 캐시: 토큰 12k개 재사용*, *에이전트가 저장소를 읽었습니다 (HEAD a1b2c3d)*, *에이전트 세션 시작* 또는 *에이전트 세션 이어감*.
- **Anthropic 프롬프트 캐시.** Anthropic 프로필에는 기본 프롬프트와 지시문이 하나의 캐시 블록으로, 저장소 컨텍스트가 두 번째 블록으로, 그 뒤에 내 대화, 힌트, 초안이 담겨 요청이 나가므로, 같은 컨텍스트의 두 번째 답글은 제공자의 캐시에서 읽혀 비용이 일부에 그칩니다(후속 요청은 대화 메시지와 최신 초안도 캐시합니다. 아래 참고). 응답의 캐시 카운터가 *제공자 캐시: 토큰 N개 재사용*에 표시되는 값입니다. OpenAI 호환 서버에는 자동 접두사 캐싱에 도움이 되는 같은 안정적인 요청 순서가 적용되며, GitPoulpi는 추가로 보내는 것이 없습니다.
- **에이전트가 세션을 유지합니다.** **답글 사이에 에이전트 세션 유지**(`ai.hosting_reply.reuse_agent_session`, 기본 켜짐)가 켜져 있고 *AI가 저장소를 읽도록 허용*이 체크되어 있으면, 이를 지원하는 로컬 에이전트(현재는 Claude Code)는 세션 id로 시작된 뒤 그 id로 재개되므로, 저장소에서 읽은 내용이 에이전트 자신의 기록에 남아 다음 답글이 더 빨리 시작됩니다. 다른 에이전트는 한 번만 실행됩니다. 세션은 저장소, `HEAD`, 동작별이며, 새 commit이나 **컨텍스트 새로고침**이 새 세션을 시작합니다. 옵션이 꺼져 있거나 상자가 체크 해제되어 있으면 각 답글은 아무것도 남기지 않는 일회성 실행입니다. 세션은 에이전트 자체의 저장소에 있고, GitPoulpi는 그 id만 보관합니다(창에서는 메모리, CLI에서는 사용자 전용 파일).

**후속 요청: 더 짧게, 다른 지시.** 같은 입력창에서 다시 요청하는 것("더 짧게", "감사 인사 추가")은 하나의 교환입니다. 재개된 Claude Code 세션은 스스로 기억합니다. 그 밖의 모든 경우(API 프로필, Codex, 다른 모든 에이전트)에는 GitPoulpi가 그것을 돌려줍니다: 요청에 첫 요청의 대화 메시지가 담기고, 이어서 이전의 각 지시와 그에 답한 초안이 제대로 된 채팅 턴으로 담기며(문서 하나를 읽는 에이전트에게는 프롬프트 안의 대본으로), 마지막에 새로운 것만 담깁니다: 내 지시와, *내 초안 다듬기*가 체크되어 있으면 내가 직접 고친 내용이 반영된 상자의 현재 텍스트입니다. 그래서 후속 요청은 처음부터 다시 시작하는 일이 없고 저장소에서 아무것도 다시 읽지 않습니다. "전송되는 내용"에 모두 표시됩니다. 교환은 대화와 마찬가지로 `ai.limits.hosting_reply_context_bytes` 이내로 유지됩니다: 가장 오래된 후속 요청부터 빠지고, 대화 메시지와 내 최신 초안은 항상 남습니다(CLI 응답의 `context.history_omitted`가 그 수를 셉니다). 교환 안에서 저장소 컨텍스트는 첫 요청의 것으로 유지되므로 재사용되고 제공자의 캐시가 유지됩니다: Anthropic 프로필에서는 기본 프롬프트, 저장소 컨텍스트, 대화 메시지, 최신 초안이 캐시되는 부분이며, OpenAI 호환 서버는 접두사 캐싱을 위한 같은 메시지 순서를 받습니다. Codex는 `codex exec resume <id>`로 재개할 수 있지만, 세션 id를 스스로 고르고 JSON 이벤트 중에만 출력하며(`--last`는 내 세션을 집어 들 수 있습니다), 그래서 GitPoulpi는 한 번만 실행하는 방식을 유지하고 기록을 다시 제공합니다. 교환은 입력창과 함께 존재합니다: 입력창이 닫히거나 텍스트를 보내면 끝나고, **컨텍스트 새로고침**도 그것을 버립니다(다음 요청이 첫 요청이 됩니다). 답을 받은 요청만 교환에 합류하며, 실패하거나 중지된 요청은 합류하지 않습니다. pull request 설명은 diff로 작성되며 교환이 없습니다.

CLI에서는 각 호출이 별개이므로 `--continue`가 교환을 다시 이어 줍니다: 이 저장소에서 같은 대상(같은 `--item`, `--reply-to`, `--path`/`--line` 또는 `--issue-title`)에 대한 마지막 `ai hosting-reply`를 비공개 상태 폴더의 작은 파일에서 이어 갑니다. `--continue`가 없으면 새 교환이 시작되어 보관된 것을 대체합니다. 대상에 보관된 것이 없을 때 `--continue`는 오류입니다. 이전 턴이 함께 갔으면 응답의 `context`에 `history_turns`(와 `history_omitted`)가 들어 있습니다.

```
gitpoulpi ai hosting-reply --conversation conversation.json --hint "say I will look tomorrow"
gitpoulpi ai hosting-reply --conversation conversation.json --hint "shorter" --continue
gitpoulpi ai hosting-reply --conversation conversation.json --reply-to <thread id> --draft "thx will do"
gitpoulpi ai hosting-reply --conversation conversation.json --read-repo --hint "is this our bug?"
gitpoulpi ai hosting-reply --issue-title "Crash on empty config" --hint "steps to reproduce"
```

`--conversation`은 파일, 표준 입력용 `-`, 또는 JSON 자체를 받습니다: `hosting issue comments --json` 또는 `hosting review conversation --json`이 출력하는 JSON(`header`와 `entries`가 있는 이전 페이지도 받아들임)이므로 `gitpoulpi hosting issue comments 7 --json | gitpoulpi ai hosting-reply --conversation -`처럼 쓸 수 있습니다. `--item <ref>`는 대화를 직접 가져옵니다(`7` 또는 `#7`은 이슈, `!7`은 pull request). `--read-repo`와 함께 `--pr-base REV --pr-head REV`는 pull request의 diff를 컨텍스트에 넣습니다. 응답의 `context`가 어떤 부분을 읽었는지, 재사용되었는지, 제공자의 캐시 토큰, 에이전트 세션을 알려 줍니다. MCP 도구 `ai_hosting_reply`는 같은 명령이며 읽기 전용입니다.

## 키가 가는 곳

API 키(OpenAI, Anthropic, OpenRouter, OpenAI 호환 서버)는 저장된 주소에 묶입니다. 프로필 기본 URL의 origin이며, 사용자만 접근할 수 있는 비공개 데이터 폴더의 `trust.toml`에 기록됩니다. 나중에 기본 URL이 다른 곳을 가리키면 아무것도 전송되기 전에 요청이 거부되고 키는 그대로 남습니다. 키를 새 주소로 의도적으로 옮기려면 `gitpoulpi ai trust <profile> --accept-origin <url>`을 실행하세요(또는 앱에서 수락).

- 일반 `http://`는 이 컴퓨터(`localhost`의 Ollama, LM Studio)에서는 허용됩니다. 그 밖의 곳에서는 `gitpoulpi ai trust <profile> --allow-insecure-http on`이 필요합니다.
- 인증서가 알려진 기관으로 이어지지 않는 자체 호스팅 서버는 `--accept-certificate <sha256>`로 고정한 키 지문에 대해서만 수락됩니다. TLS 핸드셰이크는 서버가 그 키를 가지고 있음을 여전히 증명합니다.
- 이 검사가 생기기 전에 이미 키가 있던 프로필은 처음 사용할 때 현재 기본 URL을 기준으로 조용히 기록됩니다.
- 로컬 에이전트(`claude -p` 등)는 키도 HTTP도 없으므로 묶을 것이 없습니다.

## 리뷰 컨텍스트

코드 리뷰 초안(`✦` 또는 `hosting review suggest`)은 요청의 diff, 제목, 설명, 기존 댓글을 읽습니다. 프로젝트 고유의 규칙도 diff 앞에 놓이는 **Project conventions** 블록으로 전달할 수 있고, 로컬 에이전트가 저장소 안에서 작업하게 할 수도 있습니다. 기본값은 다음과 같습니다.

| 설정 | 기본값 | 의미 |
|---|---|---|
| `run_in_repository` | `profile` | `profile`: AI 프로필의 *작업 폴더*가 결정합니다. `yes`: 프로필 설정과 관계없이 리뷰 동안 로컬 에이전트가 저장소에서 실행됩니다. `no`: 저장소에서 실행하지 않습니다(*저장소*로 설정된 프로필은 전용 폴더를 대신 사용합니다). HTTP 프로필에는 작업 폴더가 없으므로 아무 영향이 없습니다. |
| `include_claude_md` | 켜짐 | 모델에 저장소의 `CLAUDE.md`를 전달합니다. |
| `include_agents_md` | 켜짐 | 모델에 저장소의 `AGENTS.md`를 전달합니다. |
| `extra_file` | 없음 | 추가 파일 하나: 저장소 루트 기준 경로, 절대 경로 또는 링크. |

지침처럼 계층으로 적용되며 더 구체적인 쪽이 필드별로 우선합니다. 전역 `[ai.review]` 테이블, 그다음 저장소 고유 값(설정하지 않은 필드는 상속), 그다음 한 번의 실행에서 고른 값입니다. 클론되지 않은 저장소의 고유 값은 `host/project`별로 `remote-reviews.toml`에, 리뷰 초안 옆에 보관됩니다.

저장소는 전역 추가 파일을 **끌** 수도 있습니다. 저장소의 `no_extra_file = true`(*저장소별 설정 > AI*의 **추가 파일 없음** 확인란, ✦ 리뷰 옵션 대화상자, `ai review-context`의 `--no-extra-file` 플래그)는 `[ai.review]`가 무엇을 지정하든 "이 저장소에는 추가 파일 없음"을 뜻합니다. **비어 있는** **추가 파일** 필드는 같은 것이 아니며, 전역 파일을 상속합니다. 저장소의 파일과 이 스위치는 서로를 배제하며(하나를 설정하면 다른 하나가 지워짐), 직접 편집한 파일에 둘 다 있으면 스위치가 우선합니다. 저장소의 예전 `extra_file = ""`는 여전히 없음을 뜻합니다.

파일을 가져오는 곳:

- `CLAUDE.md`, `AGENTS.md`, 상대 경로의 추가 파일은 요청이 대상으로 하는 브랜치에서 저장소 **루트**를 기준으로 읽으며, 작업 트리(다른 브랜치에 있거나 로컬 수정이 있을 수 있음)에서는 읽지 않습니다. 클론이 있으면 요청의 base commit에서, 없으면 호스트 API에서 읽습니다.
- 절대 경로는 이 컴퓨터에서 읽습니다.
- 코드 호스트 파일의 링크(GitHub `.../blob/<branch>/<path>`, GitLab `.../-/blob/<branch>/<path>`, Gitea와 Forgejo `.../src/branch/<branch>/<path>`, 또는 raw 링크)는 호스트가 일치하는 연동 프로필을 통해 읽으므로, 비공개 저장소도 이미 입력한 토큰으로 동작합니다. 어떤 프로필과도 일치하지 않는 링크나 그 밖의 주소는 익명으로 가져옵니다. 슬래시가 들어간 브랜치 이름은 링크로 읽을 수 없으니 경로를 쓰거나 슬래시 없는 브랜치의 링크를 쓰십시오.
- 없는 `CLAUDE.md`나 `AGENTS.md`는 조용히 건너뛰고, 없는 추가 파일은 보고됩니다(CLI JSON의 `context.problems`).
- 각 파일은 **8 KB**, 전체는 **16 KB**에서 잘리며, 모델이 읽는 내용에 `[CLAUDE.md cut: showing ... of ... bytes]` 표시가 보입니다.

로컬 에이전트가 저장소에서 실행될 때, 프롬프트는 체크아웃된 파일이 요청의 head와 다를 수 있으며 diff가 기준이라고 알려 줍니다.

리뷰 화면에서 `s`는 이 값들이 채워진 **✦ 리뷰 옵션** 대화상자를 엽니다(전역 값 위에 저장소의 값). 이번 실행에서만 바꾸거나, *이 저장소의 기본값으로 저장*을 선택해 유지하십시오([리뷰 옵션](review.md#리뷰-옵션) 참고). 기본값은 *설정 > AI*(*코드 리뷰* 블록, 네 행)와 *저장소별 설정 > AI*에서도 편집할 수 있으며, 저장소에서는 각 행에 *전역 사용*을 고를 수 있고 *전역으로 초기화* 버튼이 저장소 고유 값을 지웁니다. 설정 검색에서도 찾을 수 있습니다(`CLAUDE.md 포함`, `추가 파일`). 모델에 전달하지 못한 것(없는 추가 파일)이나 맞추려고 잘린 것은 초안 카드에 표시됩니다.

명령줄에서:

```sh
gitpoulpi ai review-context                      # the global defaults and what a review gets
gitpoulpi ai review-context --agents-md off      # save a global default
gitpoulpi --repo ~/work/app ai review-context --claude-md off --context-file docs/REVIEW.md
gitpoulpi ai review-context --project github.com/acme/app --context-file https://github.com/acme/rules/blob/main/review.md
gitpoulpi ai review-context --repo ~/work/app --reset   # follow the global defaults again
gitpoulpi hosting review suggest 12 --claude-md off --context-file docs/REVIEW.md --run-in-repo no
```

`ai review-context`는 모델이 필요 없으며 AI를 꺼도 동작합니다. `ai prompt --action code_review`는 실제 적용되는 컨텍스트를 `review_context`로 출력합니다. 같은 네 설정은 `config.toml`의 `ai.review.*`입니다([참조](config-reference.md#ai-내장-ai-기본적으로-꺼짐)).

## 입력 한도

GitPoulpi가 요청에 넣는 모든 입력에는 크기 한도가 있으며, 이는 `[ai.limits]` 아래의 설정입니다(*설정 > AI > 한도*). 이 한도는 GitPoulpi 자체의 안전장치입니다(모델의 컨텍스트 창은 모델마다 다릅니다). 모델에 여유가 있으면 늘리고, 요청을 작게 유지하려면 줄이세요.

| 설정 (`ai.limits.`) | 기본값 | 제한하는 대상 |
|---|---|---|
| `conflict_bytes` | 40000 | merge 충돌 하나의 base, 현재, 들어오는 블록 |
| `diff_bytes` | 60000 | commit 메시지, 설명, stash 이름, pull request 설명, commit 계획, 분할 요청의 diff. 코드 리뷰의 전체 diff |
| `review_file_bytes` | 12000 | 코드 리뷰에서 파일 하나의 diff |
| `review_text_bytes` | 4000 | 리뷰 대상 pull request의 설명 |
| `review_threads_bytes` | 6000 | 이미 있는 리뷰 댓글 |
| `review_context_file_bytes` | 8192 | 리뷰의 프로젝트 컨텍스트 파일 하나(`CLAUDE.md`, `AGENTS.md`, 추가 파일) |
| `review_context_bytes` | 16384 | 리뷰의 모든 컨텍스트 파일 합계 |
| `hosting_reply_context_bytes` | 49152 | 초안 답글에 주는 항목과 대화 |
| `hosting_reply_file_bytes` | 8192 | 초안 답글에 주는 저장소 파일 하나 (AI가 저장소를 읽을 때) |
| `hosting_reply_map_bytes` | 6144 | 초안 답글에 주는 저장소 맵 |
| `hosting_reply_hits_per_term` | 20 | 검색어마다 남기는 검색 결과 (1에서 200) |
| `hosting_reply_terms` | 8 | 찾아보는 검색어 (1에서 50) |

**조용히 잘리는 일은 없습니다.** 입력이 한도를 넘으면 요청이 대기하고 *AI 한도 초과* 대화상자가 넘은 항목을 나열합니다. 어느 부분(diff, 파일, 설명, 컨텍스트 파일)인지, 크기, 한도, 설정 이름을 보여 줍니다. 리뷰는 한도를 넘은 모든 부분을 한 대화상자에 나열합니다. 버튼과 각 키는 다음과 같습니다.

- *모두 보내기* (`A`): 이번 요청에만 적용되며 아무것도 자르지 않습니다. 개인정보 검사(비밀 값 대체, 민감한 파일 제외)와, 켜져 있다면 이어서 나오는 *전송되는 내용* 창은 그대로 거칩니다.
- *잘라서 보내기* (`T`): 한도를 넘은 부분을 이전처럼 자릅니다. 대화상자의 각 줄이 무엇이 빠지는지(diff의 끝, 마지막 hunk, 들어가지 않는 파일) 알려 줍니다.
- *설정 열기* (`O`): 요청을 취소하고 첫 번째로 나열된 한도에 해당하는 *설정 > AI > 한도*를 엽니다. 포커스가 여기서 시작하므로 Enter는 절대 전송하지 않습니다.
- *취소* (`C`, `Esc`, 닫기 표시 또는 바깥 클릭): 아무것도 보내지 않습니다.

충돌은 예외입니다. 충돌은 절대 잘리지 않으며 *그래도 보내기*가 한 번 통째로 보냅니다.

AI 요청을 스스로 시작하는 것은 없으므로 물어볼 백그라운드 실행도 없습니다. 모든 요청은 사용자가 시작한 것입니다. 물어볼 수 없는 실행(CLI와 MCP)은 이전처럼 자르고 그 사실을 알립니다. 아래를 참고하세요.

**명령줄에서는** 대화상자에 답할 수 없으므로 한도를 넘은 입력은 이전처럼 잘리고, 응답이 잘린 내용을 알려 줍니다. `truncated: [{part, detail?, bytes, limit, setting}]`이며 무언가 잘렸을 때만 나타납니다(`part`는 `diff`, `split_hunks`, `review_diff`, `review_file`, `review_text`, `review_threads`, `context_file`, `context_total` 중 하나). `--send-all`(별칭 `--no-truncate`)은 대신 모든 것을 통째로 보냅니다. `ai`(`ai resolve-conflict` 포함 모든 명령. 한도를 넘은 충돌은 그렇지 않으면 거부됩니다), `commit --ai`, `stash push --ai`, `hosting review suggest`에서 쓸 수 있습니다. MCP 도구에도 같은 `send_all` 인자와 같은 `truncated` 필드가 있습니다.

## 개인정보

- 버튼을 누르거나 명령을 실행하기 전에는 아무것도 전송되지 않습니다. 백그라운드 AI도, 원격 측정도, GitPoulpi 계정도 없습니다.
- 전송되는 것은 프롬프트(내장 프롬프트, 이어서 사용자의 지침)와 요청한 diff입니다. pull request의 경우 브랜치의 commit 제목도 포함됩니다. 60 KB(`ai.limits.diff_bytes`)를 넘는 diff는 조용히 잘리지 않습니다. [입력 한도](#입력-한도)를 참고하세요.
- 기록 다시 쓰기 스크립트 요청은 지시문과 고정된 스크립트 규약(스크립트 샌드박스의 API)을 전송합니다. 최대 20개 commit의 작성자, 날짜, 제목은 대화상자에서 *샘플 보내기*를 선택한 경우**에만** 함께 전송됩니다(기본값 꺼짐. CLI에서는 `--sample N`이 필요). 파일 내용과 비밀 값은 절대 전송되지 않습니다.
- 해당 동작에 선택된 프로필로만 전송됩니다. 즉 그 API 호스트, 또는 로컬 에이전트 명령의 stdin입니다(그 뒤에는 해당 에이전트가 하는 일을 합니다).
- API 키는 `gitpoulpi` 프로세스 자체가 사용하며 데몬, 창의 다른 클라이언트, MCP 클라이언트에는 전달되지 않습니다.
- 생성된 텍스트는 스스로 commit, push, 적용되지 않습니다.

### 요청에서 제거되는 것

어떤 동작이 보내든, 어떤 제공자(호스팅 API 또는 로컬 에이전트)가 받든, 모든 요청은 먼저 같은 정리 단계를 거칩니다.

- **비밀 정보를 가립니다**(`[ai.privacy] redact_secrets`, 기본값 켜짐). 알려진 접두사가 있는 토큰, 개인 키 블록, JWT, URL 안의 비밀번호, 값이 무작위로 보이는 `password = value` 줄은 `[REDACTED:<rule>]`로 대체됩니다. 모든 것을 찾아내지는 못하며 흔한 형태를 찾습니다(`rewrite scan-secrets`와 같은 스캐너).
- **민감한 파일을 제외합니다**(`[ai.privacy] exclude_sensitive_files`, 기본값 켜짐). `[privacy] sensitive_patterns`에 일치하는 파일(`.example`, `.sample`, `.template` 파일을 제외한 `.env`와 `.env.*`, `*.pem`, `*.key`, SSH 개인 키, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `*.crt`, `*.cer`, `*.der`, `*.kdbx`)의 diff는 요청에 포함되지 않습니다. 이런 파일을 지정하는 분할 조각이나 composer 파일 목록도 같은 방식으로 잘리므로, 그 계획이 불완전하다는 이유로 거부될 수 있습니다. 그런 파일은 직접 스테이징하거나 분할하세요.

둘 중 하나를 끄는 것은 선택이며, 설정 > AI는 꺼져 있는 동안 그 아래에 빨간 줄을 표시합니다.

**보내기 전에 보내는 내용 확인.** 요청이 나가기 전에 TUI가 **보내는 내용 검토** 대화상자를 표시합니다. 정리된 뒤의 지침과 요청(기록 다시 쓰기 대화상자와 같은 창이며 스크롤할 수 있고 `Alt+W`로 표시하거나 숨김), 대체된 비밀 정보의 개수와 제외된 파일(규칙과 `ghp_****abcd` 같은 가려진 미리 보기이며 값은 절대 표시하지 않음), **<동작>에 대해 다시 표시하지 않기** 체크박스, **보내기** / **취소**(`Esc`, 닫기 표시, 바깥 클릭은 취소이며 보내기 전에는 아무것도 나가지 않음)가 들어 있습니다. 이 체크박스는 `[ai.sent_preview] <action> = false`를 기록합니다. 설정 > AI > *보내기 전에 전송 내용 표시...*에는 동작마다 스위치 하나와 **모두 다시 표시**가 있습니다. 기록 다시 쓰기 대화상자 두 개는 이미 요청을 보여 주므로 스위치가 없습니다.

**명령줄에서는** 모든 `ai ...` 응답(그리고 `hosting review suggest`)에 `privacy: {redactions: N, excluded_files: [...]}`가 들어 있으며, `--print-sent`는 모델을 호출하지 않고 정리된 시스템 텍스트와 사용자 텍스트를 `{sent: [{system, user}], privacy, dry_run: true}`로 출력합니다(`ai.enabled = true`가 필요하며 키와 네트워크는 필요 없음).

**한계.** 작업 폴더가 저장소인 로컬 에이전트(`workdir = repository`, 또는 리뷰의 *저장소에서 에이전트 실행*)는 파일을 직접 읽을 수 있습니다. 정리는 GitPoulpi가 보내는 내용에만 적용되며 에이전트가 스스로 여는 파일에는 적용되지 않습니다. 에이전트를 저장소 밖에 두려면 `dedicated` 작업 폴더를 사용하세요.

## 문제 해결

| 증상 | 해결 방법 |
|---|---|
| `✦`가 어디에도 없음 | AI가 꺼져 있습니다. *설정 > AI > AI 사용*. |
| `✦`가 회색임 | 스테이징된 것이 없습니다(commit 메시지). |
| *연결 테스트*: 명령을 찾을 수 없음 | 로컬 에이전트의 **명령**이 GitPoulpi가 보는 `PATH`에 없습니다. `claude --version`이 동작하는 곳에서 GitPoulpi를 시작하거나 전체 경로를 지정하세요. |
| 로컬 에이전트가 멈추거나 대화형 화면을 표시함 | *헤드리스* 실행 모드에서는 **인자**에 헤드리스 플래그(Claude Code는 `-p`)를 추가하거나, **에이전트 종류**를 다시 골라 헤드리스 호출을 복원하세요. 대화형 화면은 *대화형 (가상 터미널)* 실행 모드가 쓰라고 있는 것입니다. |
| "Use "Open the agent"..." | 에이전트가 처음 실행할 때의 질문(폴더 신뢰, 로그인)을 했습니다. 프로필의 **에이전트 열기...**를 사용해 답하고, 에이전트를 닫은 뒤 다시 시도하세요. |
| 가상 터미널 요청이 시간 초과됨 | 메시지 끝에 에이전트 화면의 마지막 줄이 붙으며, 권한 요청, 로그인, 업데이트 질문이 거기에 나타납니다. **에이전트 열기...**로 답하거나 **제한 시간**을 늘리세요. |
| `실패:` 401 | 키가 잘못되었거나 다른 제공자의 키입니다. 다시 입력하세요. |
| `실패:` 404 | 해당 제공자에 **모델**이 없습니다. 비워서 기본값을 사용하세요. |
| `실패:` 연결 오류 (Ollama, LM Studio) | 서버가 실행 중이 아니거나 **기본 URL**의 포트가 틀렸거나 `/v1`이 없습니다. |
| 키를 입력한 뒤 `(설정 안 됨)`으로 표시됨 | 자격 증명 도우미가 없습니다. 하나를 구성하고(`git config --global credential.helper ...`) 다시 입력하세요. |
| *AI 한도 초과* | 요청의 입력 하나가 `[ai.limits]`의 한도를 넘었습니다. *모두 보내기*, *잘라서 보내기*, *설정 열기*, *취소* 중에서 고르세요([입력 한도](#입력-한도) 참고). |
| "충돌이 한도보다 큽니다" | 충돌이 `ai.limits.conflict_bytes`(기본값 40000)를 넘었습니다. *그래도 보내기*는 한 번만 보내고, *설정 열기*는 설정 > AI > 한도의 해당 항목으로 이동합니다. |
| 언어나 스타일이 맞지 않음 | 지침을 추가하세요. 편집기의 빠른 삽입 칩을 쓰면 빠릅니다. |
| 작성기가 계획이 유효하지 않다고 함 | 모델이 파일을 빠뜨렸거나 반복했습니다. 다시 시도하거나 더 강력한 모델을 사용하세요. |

## 이전 구성 파일

`[[ai.presets]]`와 `[ai.defaults]`가 있는 이전 `config.toml`도 계속 로드됩니다.

- 각 동작의 기본 프리셋은 해당 `[ai.actions.<action>]`이 됩니다(`system_prompt`는 `instructions`가 됩니다).
- 이전 프리셋은 모두 `[[ai.legacy_presets]]`에 보관됩니다. 설정 > AI는 이를 *이전 프리셋* 아래에 *보관본 삭제*와 함께 표시합니다.
- 저장소의 이전 `[preferences.ai_presets]`는 저장소 재정의가 됩니다.

내장 프롬프트는 이제 항상 맨 앞에 옵니다. 이전 프롬프트가 내장 프롬프트를 복사한 것이었다면 복사한 부분을 지우고 추가하려는 내용만 남기세요.
