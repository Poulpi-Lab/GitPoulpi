# CLI 참조

하위 명령 없이 `gitpoulpi`를 실행하면 창이 열리고, 하위 명령을 주면 스크립트로 쓸 수 있는 git 클라이언트가 됩니다. 모든 명령은 창과 같은 백그라운드 데몬을 거치므로, 스크립트에서 한 변경이 열려 있는 GitPoulpi에 실시간으로 나타납니다. 에이전트가 받는 MCP 도구는 이 같은 명령에서 생성됩니다([MCP와 에이전트](mcp-and-agents.md)). `gitpoulpi <command> --help`에 모든 플래그가 있습니다.

## 전역 플래그

| 플래그 | 효과 |
|---|---|
| `--json` | 결과를 JSON으로 출력합니다. 오류도 JSON입니다. stdout에 `{"error": "..."}`를 출력하고 종료 코드는 1입니다. 실패한 git 작업에는 `"detail": {"operation", "command", "exit_code", "stderr"}`가 추가됩니다(실행된 git 명령(비밀 정보는 가려짐), 종료 코드, stderr의 끝부분. 내장 git 라이브러리는 `"git2": {"class", "code", "message"}`). 데몬이 이름을 붙일 수 있었던 실패에는 `"context": {"operation", "label", "args", "repo", "frontend", "request", "job"}`가 추가됩니다(작업, 사람이 부르는 이름, 비밀 정보를 가린 주요 인수, 저장소, 요청한 쪽, 요청 id, 그리고 fetch나 push라면 작업 번호). MCP 도구도 같은 객체를 반환합니다. `--json` 없이는 이 줄들이 stderr로 나갑니다. |
| `--repo <path>` | 대상 저장소(기본값: git처럼 현재 디렉터리를 둘러싼 저장소). |
| `-s, --session <name>` | 통신할 세션(데몬). 기본값: 저장소 루트에서 도출되므로, 한 저장소 안에서 연 모든 것이 하나의 데몬을 공유하고 저장소 두 개는 데몬 두 개를 갖습니다. |
| `--backend git2\|system` | 이 명령이 시작하는 데몬의 백엔드(이미 실행 중인 데몬은 자기 백엔드를 유지합니다). |
| `--cwd-file <file>` | 창이 종료될 때 활성 탭의 폴더를 기록할 위치(`shell-init`이 사용). |
| `-a, --add [path]`, `--no-raise` | 새 GitPoulpi를 시작하는 대신, 이미 실행 중인 GitPoulpi에 폴더를 새 탭으로 엽니다. [열린 창에 폴더 추가](#열린-창에-폴더-추가)를 참고하세요. 하위 명령은 받지 않습니다. |
| `-l, --lang <lang>` | `--help` 텍스트에만 적용되는 언어: `en`, `fr`, `es`, `pt-BR`, `pt-PT`, `it`, `de`, `zh-CN`, `ja`, `ko`, `ru`, `uk`, `pl`, `cs`, `nl`, `sv`, `tr`. [번역된 도움말](#번역된-도움말)을 참고하세요. |

### 열린 창에 폴더 추가

`gitpoulpi --add [path]`(`-a`. `gp -a`와 `gpa` 명령 별칭도 같은 코드를 실행합니다)는 `path`(기본값: 현재 디렉터리이며 그것을 포함하는 저장소로 확인됨)를 이미 실행 중인 GitPoulpi의 새 탭으로 엽니다. 터미널에서 `cd`로 이동한 폴더 때문에 두 번째 창이 시작되지 않습니다.

- *실행 중인 세션*은 데몬이 응답하고 GitPoulpi 창이 연결된 세션입니다. 사용자가 **AI 에이전트의 화면 제어 허용**을 끈 창은 스스로를 알리지 않으므로 찾지 못합니다(`gitpoulpi launch`와 같은 제한).
- 실행 중인 세션이 하나: 그 세션이 탭을 받고(해당 저장소가 이미 열려 있으면 그 탭을 보여 주고), 데스크톱이 허용하면 창이 앞으로 나옵니다(Windows, WezTerm, Hyprland. `--no-raise`로 건너뜀). 어느 세션이 받았는지 한 줄로 알려 줍니다.
- 여러 개: 번호, 탭 수, 저장소 이름과 함께 목록으로 보여 줍니다. 번호를 입력하고 Enter를 누르십시오(빈 줄을 입력하거나 Esc 후 Enter를 누르면 취소하며 종료 코드 130). stdin에 터미널이 없으면 명령이 실패하고 `--session NAME`을 지정하라고 안내합니다. `-s NAME`을 쓰면 질문을 건너뜁니다.
- 없음(또는 `-s NAME`이 실행 중이 아닌 세션을 가리킴): `gp [path]`와 똑같이 이 터미널에서 그 폴더로 GitPoulpi를 평소처럼 시작합니다.
- 창은 이를 사용자 본인의 선택으로 즉시 적용합니다(확인 칩 없음, 에이전트 표시 없음). 단, 그 창에서 폼에 입력 중이면 창이 상태 표시줄 칩으로 탭을 제안하며 종료 코드는 3입니다. 저장소 안에 있지 않은 폴더는 거부됩니다(종료 코드 1).

`--json`은 객체 하나를 출력합니다. `{"action": "joined", "session", "repo", "already_open", "raised", "outcome": {...}}`(`outcome`은 `ui show`와 같은 창의 응답) 또는 `{"action": "cancelled"}`이며, 오류는 `{"error": "..."}`입니다. 종료 코드: 0 탭이 열림, 3 칩으로 제안됨, 1 거부되었거나 실패, 130 취소됨. 이에 해당하는 MCP 도구는 없습니다. 사용자에게 저장소를 보여 주려는 에이전트는 `ui show tab`을 사용합니다.

### 번역된 도움말

`gitpoulpi --help`는 영어입니다. `-l`을 붙이면 다른 언어로 설명을 읽을 수 있습니다. `gitpoulpi -l fr --help`, `gitpoulpi -l de commit --help`처럼 사용합니다. 설명과 섹션 제목만 번역됩니다. 명령 이름, 플래그, 값 이름, 가능한 값은 바뀌지 않으므로 스크립트와 에이전트는 같은 인터페이스를 봅니다. 도움말 언어는 환경에서 읽지 않으며, `-l`을 줄 때만 출력이 바뀝니다. MCP 도구 설명은 항상 영어입니다.

리비전(revision)은 git이 받아들이는 모든 것을 받습니다(`HEAD~2`, 브랜치, tag, 짧은 sha). hunk와 줄 번호는 `gitpoulpi --json diff`가 매기는 방식을 따릅니다.

## 명령

**조회**

| 명령 | 동작 |
|---|---|
| `status` | 스테이징된 파일, 스테이징되지 않은 파일, 추적되지 않는 파일, 충돌한 파일. |
| `log [--graph] [--limit N] [--skip N] [--path P] [--count]` | 기록. `--skip` + `--limit`로 페이지를 나누고, `--path`는 파일 기록입니다. `--count`는 `{"total": N}`만 출력합니다. 순회가 가진 commit 수이며(`--limit`/`--skip`은 무시), TUI 상태 표시줄의 슬래시 뒤 숫자(`500 / 2500 commits`)와 같습니다. |
| `log --format mermaid [--detail structure\|refs\|subjects\|full] [--orientation lr\|tb] [--fence] [--range A..B] [--limit N] [--subject-width N]` | 커밋을 Mermaid `gitGraph` 스크립트로 출력합니다. Log의 [Mermaid gitGraph로 복사](log-and-history.md#commit을-mermaid-gitgraph로-복사하기) 팝업이 만드는 것과 같습니다. `--range A..B`는 `git log A..B`이며(`A`만 쓰면 `A..HEAD`), 없으면 처음 `--limit`개의 커밋(기본값 30)입니다. 상세 수준, 방향, 펜스의 기본값은 `ui.mermaid_*`입니다. `--json`과 함께 쓰면 `{format, detail, commits, text}`이고, 일반 출력은 스크립트 자체입니다. |
| `diff [--staged] [--path P] [--name-only]` | 작업 트리(또는 스테이징된) diff를 hunk와 줄로 보여 줍니다. `--name-only`는 변경된 파일과 상태만 나열합니다. |
| `diff --from <rev> [--to <rev\|worktree>] [--name-only]` | 두 리비전, 또는 리비전과 작업 트리를 비교합니다(`--to`의 기본값은 `worktree`: 추적 중인 파일의 스테이징된 변경과 스테이징되지 않은 변경). Log의 [비교](log-and-history.md#commit-비교하기)와 같은 목록입니다. |
| `show <path> [--at REV \| --staged \| --worktree] [--raw [--output FILE]]` | 리비전, 인덱스 또는 디스크에 있는 파일의 내용. 이미지는 `--json`에서 `image: {format, width, height}`를 가집니다(헤더에서 읽음). `--raw`는 정확한 바이트를 stdout 또는 `--output FILE`에 씁니다(LFS 포인터는 로컬 객체를 줍니다). MCP로는 사용할 수 없습니다. |
| `blame <path> [--at REV]` | 각 행을 누가 바꿨는지. 파일 전체의 이름 변경을 따라갑니다. 각 행에는 commit, 작성자와 committer 시각, `orig_path`(그 commit에서의 파일 이름), `previous`(`[부모, 경로]`: 그 commit 이전의 행을 보려면 blame을 다시 할 위치. 루트 commit이나 부모에 파일이 없는 commit에서 생긴 행에는 없음)가 붙습니다. |
| `file-history <path> [--at REV] [--skip N] [--limit N]` | 파일을 바꾼 commit을 최신순으로, **이름 변경을 따라** 반환합니다(`git log --follow`). 각 항목에는 commit, 부모, 작성자, 작성자와 committer 시각, 요약, 그 commit에서의 파일 `path`, `change`(`Added`, `Modified`, `Deleted`, `{Renamed: {from}}`), 행 수 `added`/`removed`(바이너리는 null)가 있습니다. `--limit` 기본값은 100이고, `more`는 더 오래된 항목이 있는지 알려 주며, `--skip` + `--limit`로 페이지를 넘깁니다. merge는 모든 부모와 다를 때만 나열되고 수치는 첫 번째 부모 기준입니다. `log --path`와 달리 이름 변경이 기록을 끝내지 않습니다. |
| `conflicts list [--names-only]` | 세 쪽의 텍스트가 포함된 충돌 파일. `--names-only`는 가벼운 목록입니다(경로, 종류, stage oid). |
| `conflicts show <path> [--conflict N]` | 충돌한 파일 하나: 창 레이블, 세 쪽, 번호가 매겨진 A/B 충돌 영역(`--json`은 전체 문서). |
| `conflicts resolve <path> --side ours\|theirs\|base` | 한쪽으로 파일을 해결합니다(`--ours` / `--theirs`는 축약형). |
| `conflicts resolve <path> --both [--theirs-first]` | 모든 충돌의 양쪽을 유지합니다(A 다음 B, 또는 B 다음 A). |
| `conflicts resolve <path> --pick 1=a,2=ba [--default a\|b]` | 충돌마다 선택: `a` ours, `b` theirs, `ab`, `ba`, `none`. 모든 충돌에 선택이 있거나 `--default`가 주어지지 않으면 `pick_incomplete`로 거부됩니다. |
| `conflicts resolve <path> --content-file F\|- [--encoding L]` | 주어진 최종 텍스트를 씁니다(UTF-8, 또는 `L`로 인코딩). |
| `conflicts resolve <path> --delete` | 삭제를 수락합니다(delete/modify 충돌): `git rm`. |
| `conflicts resolve ... [--no-stage] [--expect base,ours,theirs]` | `--no-stage`는 해결됨으로 표시하지 않고 저장합니다. `--expect`는 오래됨 방지 장치입니다(stage oid, 없으면 `-`). |
| `conflicts unresolve <path>` | 이번 작업 중에 해결한 파일을 다시 충돌 상태로 되돌립니다. |
| `conflicts check` | 현재 브랜치가 갈라져 나온 브랜치로 HEAD를 merge하면 충돌할까요? `{"status": "conflicts"\|"clean"\|"no-base"\|"disabled", "head", "base_ref", "base", "base_source": "globs"\|"pull-request", "files": [...]}`. 메모리 안에서 하는 merge이므로 작업 트리, 인덱스, ref는 바뀌지 않습니다(시스템 백엔드의 git 2.38 이상, 아니면 `disabled`). 읽기 전용이며 MCP 도구 `conflicts_check`도 같습니다. [merge 충돌 해결](merge-conflicts.md#충돌-방지)을 참조하세요. |
| `conflicts state` | 진행 중인 merge, rebase, cherry-pick 또는 revert(없으면 `null`). |
| `conflicts abort` | 그 작업을 중단합니다(파괴적: 그 사이에 한 해결을 버립니다). |
| `conflicts skip` | 진행 중인 cherry-pick 또는 revert(또는 rebase가 멈춘 commit)를 건너뜁니다. HEAD, 인덱스, 작업 트리가 HEAD로 돌아갑니다. 빈 commit에서 벗어나는 방법이며, merge에는 건너뛸 것이 없습니다(파괴적, 실행 취소 불가). |
| `conflicts am-continue` | 패치의 파일을 해결하고 스테이징한 뒤 진행 중인 `git am`을 계속합니다(`{"outcome":"Completed"}` 또는 `"Stopped"`). |
| `conflicts am-skip` | `git am`이 멈춘 패치를 건너뜁니다. |
| `conflicts am-abort` | `git am`을 중단합니다(파괴적: 브랜치가 `am` 이전으로 돌아갑니다). |
| `job list` | 데몬의 백그라운드 작업을 오래된 순으로 나열합니다. 모든 fetch, push, pull, clone, LFS 전송이 요청을 받은 순간부터 하나의 작업입니다(대기 중, 실행 중, 또는 최근 30초 안에 끝남). JSON: id, kind, state, phase, progress, `not_cancellable`, `error`. |
| `job cancel <id>` | 작업을 중지합니다. 안전하게 멈출 수 있는 시점을 지났으면 거부되며(종료 코드 1, 아무것도 바뀌지 않음) 작업을 시작한 명령에서 Ctrl+C를 누르면 그 작업이 취소됩니다. |
| `job wait <id> [--timeout S]` | 작업이 끝날 때까지 기다린 뒤 최종 상태를 출력합니다. `Done`이면 종료 코드 0, 실패, 취소 또는 시간 초과면 1입니다. |
| `index-lock show` | 저장소의 `index.lock`(없으면 `null`): 경로, 경과 초, `stale`(10초보다 오래됨). |
| `index-lock remove` | 오래된 `index.lock`을 삭제합니다. 10초보다 어리거나 없으면 거부됩니다. |
| `rebase-plan [<upstream>] [--root]` | 대화형 rebase가 다시 적용할 commit, 오래된 것부터. |

**스테이징과 commit**

| 명령 | 동작 |
|---|---|
| `stage --file F \| --folder D \| --all [--hunk N [--lines a,b]] [--allow-sensitive]` | 파일, 폴더, 전체, hunk 또는 일부 줄을 스테이징합니다. 민감한 파일(개인 키, `.env`, 인식된 토큰: [설정 참조](config-reference.md#privacy-민감한-파일)의 `[privacy]`)을 추가하게 될 파일, 폴더 또는 `--all` 스테이징은 종료 코드 2와 `{error: "sensitive_files", files: [{path, reason}]}`(규칙과 가려진 미리 보기이며 값은 절대 표시하지 않음)와 함께 거부되고 아무것도 스테이징되지 않습니다. `--allow-sensitive`는 그래도 스테이징합니다. |
| `unstage` (같은 플래그) | 그 반대. |
| `discard --file F [--hunk N [--lines a,b]]` | 스테이징되지 않은 변경 사항을 버립니다(파일 전체: 모든 변경, 추적되지 않는 파일은 삭제하고, 그 결과 비게 되는 폴더도 삭제). 실행 취소 가능. |

| `apply-commit <rev>` | 커밋 하나가 만든 변경 사항(잃어버린 커밋도 가능)을 작업 트리에만 적용합니다. 인덱스와 HEAD는 그대로입니다. 전부 아니면 전무입니다: 파일 하나라도 깔끔하게 적용되지 않으면 아무것도 바뀌지 않고 명령이 실패합니다(그래도 변경 사항을 보관하려면 `stash from-commit` 사용). merge 커밋은 거부됩니다. 바이너리 파일과 줄 끝은 커밋에 있던 그대로 나옵니다. `{files}`를 출력하며, `undo` 한 번으로 파일을 되돌립니다. |
| `undo-forget [--dry-run] [--redo] [--expect ID] [--yes]` | 막힌 최신 저널 항목(중단되었거나 저장소가 앞서 나간 것)을 버려 그 아래 항목을 실행 취소할 수 있게 합니다. 저장소는 건드리지 않습니다. `--yes`가 없으면 종료 코드 3. |
| `undo [--dry-run] [--list [--all]] [--expect ID] [--yes]`, `redo [--dry-run] [--expect ID] [--yes]` | 마지막 작업을 되돌림 / 복원. 종료 코드 2는 거부, 3은 `--yes` 필요. `undo --list`는 항목마다 "이것만 복원"으로 되돌릴 수 있는 것과 누가 했는지도 알려 줍니다(`"source": "gitpoulpi"`, 또는 셸이나 AI 에이전트가 일반 git으로 한 변경이면 `"outside"`. 데몬이 git이 남긴 이유와 committer와 함께 기록합니다). [실행 취소와 다시 실행](undo-redo.md)을 참고하세요. |
| `mailmap list [--all-local\|--ref R...] [--mapped\|--unmapped]`, `mailmap check IDENTITY...`, `mailmap add --canonical IDENTITY --from IDENTITY... [--file F]` | `.mailmap`: 여러 이름으로 commit한 사람에게 대표 이름과 이메일을 하나 정해 줍니다. `IDENTITY`는 `Name <email>`(또는 `<email>`)입니다. `list`는 `{identities: [{name, email, as_author, as_committer, mapped_to}], commits, has_mailmap}`을 출력합니다. 범위(현재 브랜치, `--all-local`, `--ref`)의 모든 이름과 이메일을 작성자로서, 커미터로서의 commit 수와 함께 commit이 많은 순으로 보여 주고, `.mailmap`이 이미 매핑한 작성자 정보(`mapped_to`, 없으면 생략)도 보여 줍니다. `--mapped` / `--unmapped`로 거릅니다. `check`는 `{identities: [{identity, shown_as, mapped}]}`를 출력합니다. 각 작성자 정보가 `.mailmap`(과 `mailmap.file`)을 거치면 어떻게 보이는지이며 `git check-mailmap`의 답입니다. `add`는 `--from`마다 `.mailmap`에 한 줄을 덧붙이고(`Canonical Name <canonical@email> Old Name <old@email>`. 파일이 없으면 생성. 이미 있는 줄은 반복하지 않음) `{mailmap: {added, file}}`를 출력합니다. 파일만 편집하고 아무것도 commit하지 않으니 직접 commit하세요. 실행 취소 항목 하나입니다(`undo`가 이전 파일을 되돌려 놓음). `log.use_mailmap`이 켜져 있는 동안(기본값) `log`, `blame`, `file-history`는 대표 작성자 정보를 바로 보여 주며, 저장된 commit은 바뀌지 않아 force push가 필요 없습니다. commit 자체를 다시 쓰려면 `rewrite preview --mailmap`을 쓰세요(`mailmap` 규칙: 작성자와 커미터가 `git log --use-mailmap`이 보여 주는 이름이 됨. `--who`로 대상을 고르고 `--mailmap-file F`는 다른 파일을 적용). |
| `undo-restore <id> [--name N] [--dry-run]` (`undo restore <id>`도 가능) | "이것만 복원": 이전 항목 하나가 제거한 것(삭제한 브랜치나 tag, 버린 stash, 버리거나 삭제한 파일, 제거한 리모트, ignore 줄)을 그 뒤의 항목을 실행 취소하지 않고 되돌립니다. 덮어쓰지 않습니다: 바뀐 파일은 옆에 `<name>.restored`로 생기고, reset, amend, rebase는 이전 끝에 새 브랜치로 돌아옵니다. 저널 항목이 새로 하나 생기므로 `undo`로 되돌릴 수 있습니다. 종료 코드 2는 거부(이름이 이미 사용 중, 복원할 것이 없음...). |
| `reflog [<ref>] [--skip N] [--limit N]` | `HEAD`(기본값) 또는 브랜치의 reflog 한 페이지를 최신순으로, git이 기록한 이유와 함께 보여 줍니다. 셸에서 한 이동도 나타납니다. 삭제한 브랜치에는 없습니다. |
| `reflog-restore <ref> <oid> [--mode keep\|soft\|mixed\|hard] [--dry-run]` (`reflog restore ...`도 가능) | 브랜치나 `HEAD`를 reflog의 한 위치로 옮깁니다. commit하지 않은 변경 사항이 있는 체크아웃된 브랜치는 `--mode`가 필요합니다. 저널 항목이 하나 생기므로 `undo`로 되돌릴 수 있습니다. 종료 코드 2는 거부. |
| `lost-commits [--skip N] [--limit N] [--no-deep] [--budget-ms MS]` | 어떤 브랜치, tag, 리모트, stash에서도 닿지 않는 commit(삭제한 브랜치의 commit, 오래된 undo 핀, dangling 객체)을 최신순으로 보여 줍니다. 검색은 시간 예산에서 멈추고 `partial`이라고 알립니다. |

**브랜치와 기록**

| 명령 | 동작 |
|---|---|
| `branch list`, `branch create <name> [at]`, `branch delete <name>`, `branch rename <old> <new>` | 로컬 브랜치. |
| `branch track <remote/branch> [--name N]` | 리모트 브랜치를 추적하는 로컬 브랜치를 만들고 체크아웃합니다. |
| `branch delete-remote <name> [--remote R]` | 리모트의 브랜치를 삭제하고 로컬 브랜치는 유지합니다. `undo --yes`가 원래대로 다시 push합니다([실행 취소](undo-redo.md#리모트의-브랜치나-tag-삭제)). |
| `branch set-upstream <branch> <remote/branch>`, `branch unset-upstream <branch>` | 업스트림. |
| `branch upstream list [--branch B]`, `remote-group status [--branch B]` | 브랜치의 리모트(기본값: 현재 브랜치): 기본 업스트림, 추가 push 대상, pull 소스를 `{remotes: {branch, primary, push_to, pull_from, missing}, targets: [{remote, branch, role, pull, tracking, relation, missing}]}` 형태로 보여 줍니다. `relation`은 `up_to_date`, `{local_ahead: n}`, `{remote_ahead: n}`, `{diverged: {ahead, behind}}`, `absent` 또는 `unrelated`이며 원격 추적 ref를 있는 그대로 읽습니다(네트워크 없음: 먼저 fetch하세요). |
| `branch upstream add <remote>[:<dst>] [--pull] [--branch B]`, `branch upstream remove <remote> [--branch B]` | 추가 push 대상을 추가하거나 뺍니다(`<dst>`는 해당 리모트의 브랜치 이름이며 기본값은 같은 이름, `--pull`은 pull 소스로도 지정). `remove`는 그 리모트를 가리키는 모든 대상과 소스를 뺍니다. 새 상태를 출력합니다. 되돌릴 수 있는 항목 하나(`undo`가 구성을 복원). 종료 코드 2는 거부: 그 리모트가 이미 기본 업스트림이거나, 대상이 아니거나, `--branch` 없이 HEAD가 분리됨. |
| `branch upstream pull <remote>[:<dst>] --on\|--off [--branch B]` | 리모트 하나를 pull 소스로 켜거나 끕니다(켜면 일반 pull이 이것도 통합). 새 상태를 출력합니다. 종료 코드는 같습니다. |
| `branch upstream primary <remote/branch> [--branch B]` | 기본 업스트림: `branch set-upstream`과 같은 요청입니다. |
| `branch fast-forward <branch> [target]` | fast-forward일 때만 브랜치를 앞으로 옮깁니다. |
| `checkout <target> [--autostash]` | 브랜치를 전환하거나 commit에서 분리(detach)합니다. |
| `merge <ref> [--ff \| --no-ff \| --ff-only \| --squash] [--autostash]` | 현재 브랜치로 merge합니다. 플래그가 없으면 fast-forward 설정이 정합니다(저장소 자체의 선택, 없으면 `git.merge_fast_forward`이며 기본값은 `never`: fast-forward가 가능해도 merge commit을 만듭니다). `--ff`는 가능하면 fast-forward하고(git 기본값), `--no-ff`는 항상 merge commit을 만들고, `--ff-only`는 fast-forward하거나 *cannot fast-forward*로 실패하며 아무것도 바꾸지 않습니다. 이 플래그들은 서로 함께 쓸 수 없습니다. JSON이 어느 쪽이었는지 알려 줍니다: `{"FastForwarded": oid}`, `{"Merged": oid}`(merge commit), `"UpToDate"` 또는 `{"Conflicted": [paths]}`. `--squash`는 브랜치의 변경 사항을 스테이징만 하고 commit은 만들지 않습니다(`merge --squash`). 이어서 `commit`을 실행합니다. ref가 움직이지 않으므로 실행 취소할 수 없습니다. merge commit이나 fast-forward는 실행 취소 항목 하나입니다. |
| `rebase [onto] [--autostash]` | Rebase. 진행 중에는 `--continue`, `--skip`, `--abort`, `--status`. |
| `rebase <upstream> --interactive --plan <file\|->` | JSON 계획(`[{"commit", "action", "message"}]`, 동작은 `pick`, `reword`, `squash`, `fixup`, `drop`, `edit`, 또는 한 글자 형태 `p`, `r`, `s`, `f`, `d`, `e`. rebase todo 목록처럼 대소문자 무관)으로 하는 비대화형 "대화형" rebase. `--root`, `--onto-commit`, `--autosquash`. `rebase-plan`으로 만듭니다. |
| `cherry-pick <commits>...` 또는 `cherry-pick --plan <file\|->` | commit을 순서대로 적용합니다(계획: `pick` / `drop` 단계). |
| `revert <commit> [-m <parent>]` | commit을 revert합니다. merge commit에는 `--mainline <parent>`(`-m`)가 필요합니다. 남길 부모의 번호(1부터)이며, `1`은 merge를 만든 브랜치입니다. |
| `reset <target> --mode soft\|mixed\|hard` | 브랜치를 옮깁니다. |
| `tag list [--unpushed]`, `tag create <name> [at] [-m M]`, `tag annotate <name> -m M` | Tag. `tag list`는 각 tag를 그 위치와 함께 출력합니다. 마지막 fetch나 tag push에서 알게 된 정보이며 네트워크를 쓰지 않습니다. `local`(여기에 있음), `remote`(그 tag를 가진 리모트), `differs_on`(다른 commit에 그 tag를 가진 리모트), 그리고 `where`: `local`, `remote`(리모트에는 있지만 이 저장소에는 없음), `both`, `differs`. |
| `tag delete <name> [--local \| --remote R \| --both [--remote R]]` | tag를 삭제합니다. 로컬(기본값), 리모트에서만(`git push R --delete`. 외부에 영향을 주며 실행 취소할 수 없음), 또는 여기와 그 tag를 가진 리모트 양쪽에서 삭제합니다. 응답에는 `scope`(`local`, `remote`, `both`)가 들어 있고, 리모트에 아직 있는 tag를 로컬에서만 삭제했을 때는 `still_on`(다음 `fetch`가 되살림)도 들어 있습니다. 양쪽 삭제는 리모트를 먼저 지우며, 이후 `undo`는 로컬 tag만 복원하고 `tag push`가 다시 올립니다. |
| `tag fetch <name> [--remote R]` | 리모트(기본값은 그 tag를 가진 리모트)에서 tag 하나를 fetch합니다. 예: `where: remote`인 tag. 다른 commit을 가리키는 로컬 tag는 절대 덮어쓰지 않습니다. |
| `tag push [names...] [--remote R]`, `tag delete-remote <name> [--remote R]` | 리모트의 tag(이름이 없으면 어느 리모트에도 없는 모든 tag). 리모트에서의 삭제는 실행 취소할 수 있습니다(`undo --yes`). |
| `worktree list`, `worktree add <path> <start> [-b BRANCH]` | 연결된 worktree. |
| `submodule list`, `submodule init [paths]`, `submodule update [paths] [--init] [--recursive]` | 서브모듈([서브모듈](submodules.md)). |

`--autostash`는 작업을 막는 로컬 변경 사항을 stash하고, 작업을 실행한 뒤 stash를 pop합니다. `general.auto_stash` 설정과 무관하게 동작합니다([자동 stash](log-and-history.md#자동-stash)).

| 명령 | 동작 |
|---|---|
| `autostash start-over [--dry-run] [--yes]` | 보류 중인 자동 stash가 있을 때: stash된 파일의 변경 사항을 버리고(복사본은 `refs/gitpoulpi-backup/` 아래에 보관), 자동 stash를 일으킨 작업을 실행 취소하고, 원래 commit에서 stash를 pop합니다. 단계가 실패하면 stash를 그대로 둔 채 멈춥니다. `--yes`가 없으면 종료 코드 3이며, 거부는 이유가 붙은 오류(종료 코드 1)입니다. |

**리모트**

| 명령 | 동작 |
|---|---|
| `fetch [--remote R \| --all] [--prune] [--prune-tags]` | 기본 리모트, 리모트 하나 또는 모든 리모트를 fetch합니다. 리모트가 삭제한 리모트 추적 브랜치는 `general.auto_prune`이 false가 아닌 한 정리되며, `--prune`은 이를 강제합니다. 모든 fetch는 각 리모트가 가진 tag(`tag list`의 `remote`) 기록도 갱신하며, `--prune`이 없어도 그 기록은 정리합니다. `--prune-tags`(설정: tag 자동 정리)는 리모트가 삭제한 로컬 tag도 삭제합니다. 리모트에 있었던 tag만 대상이며 push한 적 없는 tag는 절대 삭제하지 않고, 삭제한 것은 응답의 `pruned_tags`에 나열됩니다 (git 2.41 이상). |
| `pull [--remote R] [--mode merge\|ff-only\|rebase] [--autostash]` | Pull. 모드는 항상 git에 명시적으로 전달됩니다. |
| `push [--remote R] [--branch B] [-u] [--force-with-lease]` | Push. 단순 force는 없고 `--force-with-lease`만 있습니다. |
| `push --all-targets\|--to <remote>[:<dst>]... [--branch B] [--resolve REMOTE=push\|ff\|merge\|rebase\|force\|skip]... [--no-preflight] [--tags] [--yes]` | 브랜치를 기본 업스트림과 모든 추가 push 대상(`--all-targets`)으로, 또는 `--to`가 지정한 리모트로만(반복 가능, 이번 push에만 적용: 구성은 바뀌지 않음) push합니다. 먼저 계획을 세웁니다(리모트에 묻습니다. `remote-group plan` 참고). 모든 리모트가 일반 push이거나, 최신이거나, 앞선 리모트의 쌍둥이이면 실행하고, 아니면 `{"needs_resolution": {"plan": ...}}`로 응답하며 종료 코드 3, 변경 없음입니다. `--resolve`로 답합니다(리모트는 `name` 또는 `name:branch`, 계획이 그 리모트에 허용한 동작만). `force`는 명시적 lease를 쓰는 push이며 `--yes`가 필요하고, 없으면 `{"needs_confirmation": {...}}`, 종료 코드 3입니다. 결과는 `{run_id, branch, mode, status, local_tip, targets: [{remote, branch, action, status, detail, replaced, recovery}], pending, stopped, conflicts, message}`입니다. `replaced`는 강제 push가 덮어쓴 커밋, `recovery`는 그것을 되돌리는 명령입니다. 해결이 요구하는 merge와 rebase가 먼저 실행되고, 그다음 push가 리모트를 하나씩 나가며, 리모트 전체의 원자성은 없습니다. 종료 코드 0은 모든 리모트가 push됨, 최신 또는 건너뜀. 4는 리모트가 실패했거나, 거부했거나, 알 수 없거나, 시도되지 않았거나, merge나 rebase가 충돌로 멈춤(`stopped`). 2는 거부(`remote_group_pending`: 저장된 실행이 대기 중, `detached_head`, `checked_out_elsewhere`, `bad_resolve`, `action_not_allowed`). `git.pull_mode`가 rebase이면 갈라진 리모트의 기본값은 merge 대신 rebase입니다. 이 플래그가 없으면 `push`는 달라지지 않습니다. |
| `pull --all-sources [--branch B] [--mode merge\|ff-only\|rebase] [--resolve REMOTE=ff\|merge\|rebase\|skip]... [--autostash] [--no-preflight]` | 기본 업스트림과 모든 pull 소스(`branch upstream pull`)에서 pull하며, 각각 `--mode`로 통합합니다. 계획, `--resolve`, 결과, 종료 코드는 `push --all-targets`와 같습니다(fast-forward나 해당 모드의 통합보다 많은 것이 필요한 소스, 또는 `--mode ff-only`의 모든 소스는 `--resolve`를 요구). 로컬 부분은 되돌리기 항목 하나입니다. |

| `ai [--print-sent] [--send-all] <command>` | 모든 `ai` 명령의 `--send-all`(별칭 `--no-truncate`)은 모든 입력을 `ai.limits.*` 한도를 넘더라도 통째로 보냅니다. 이 옵션이 없으면 한도를 넘은 입력은 잘리고(충돌은 거부됨) 무언가 잘렸을 때 응답에 `truncated: [{part, detail?, bytes, limit, setting}]`가 들어 있습니다([AI > 입력 한도](ai.md#입력-한도)). 모든 `ai` 명령의 `--print-sent`는 전송될 내용(정리된 시스템 텍스트와 사용자 텍스트, `{sent: [{system, user}], privacy, dry_run: true}`)을 출력하고 모델을 호출하지 않습니다. `ai.enabled = true`가 필요하며 키와 네트워크는 필요 없습니다. 모든 `ai` 응답에는 `privacy: {redactions: N, excluded_files: [...]}`가 들어 있습니다: 비밀 정보가 몇 개 대체되었고 어떤 민감한 파일이 제외되었는지([AI > 개인정보](ai.md#개인정보)). |
| `ai commit-message` | 스테이징된 변경 사항(스테이징된 것이 없으면 모든 변경 사항)에 대해 AI가 제안하는 메시지를 출력합니다. 아무것도 commit하지 않습니다. |
| `ai explain [rev] [--wip]` | commit(기본값 `HEAD`) 또는 작업 변경 사항을 설명합니다. |
| `ai split-plan <rev>` | commit을 나누기 위해 AI가 제안하는 계획을 `{commit, parts, applied: false}` 형식으로 출력합니다. `parts`는 `split-commit --plan`이 받는 형식입니다. 아무것도 적용하지 않습니다. `ai.enabled = true`가 필요합니다. |
| `ai rewrite-script <instruction> [--sample N]` | 입력한 지시로 AI가 기록 다시 쓰기용 Lua 스크립트를 작성해 `{script, check, retried, sample, applied: false}`로 출력합니다. `check`는 그 스크립트에 대한 `rewrite script check`의 결과입니다(컴파일되지 않으면 모델에게 한 번 더 요청하며, 그래도 안 되면 종료 코드 2). 지시문만 보내며, `--sample`을 주면 가장 최근 `N`개(최대 50) commit의 작성자, 날짜, 제목도 보냅니다. 파일 내용은 절대 보내지 않습니다. 아무것도 실행하지 않습니다. `ai.enabled = true`가 필요합니다. |
| `ai rewrite-rules <description> [--context]` | 설명을 바탕으로 AI가 기록 다시 쓰기에 제안하는 규칙과 설정을 `{recipe, problems, notes, retried, context, applied: false}`로 출력합니다. `recipe`는 `rewrite preview --recipe-json`이 읽는 형식이고, `problems`는 제외한 항목을 이유와 함께 나열합니다(하나라도 있으면 종료 코드 2. 유효한 규칙은 유지됨). 설명만 보내며, `--context`를 주면 현재 브랜치, 브랜치와 tag 이름, 최신 commit 200개의 작성자도 보냅니다. 파일 내용은 절대 보내지 않습니다. 아무것도 미리 보거나 적용하지 않습니다. `ai.enabled = true`가 필요합니다. |
| `ai resolve-conflict <path> [--conflict N]` | 충돌한 파일의 충돌 하나에 대해 AI가 제안하는 해결 방법을 출력합니다(`N`은 1부터 시작하며 파일에 충돌이 하나면 생략 가능). 출력만 합니다. 아무것도 쓰거나 스테이징하지 않습니다(`conflicts resolve`가 결과를 적용합니다). |
| `ai prompt --action <a>` | AI 동작이 이 저장소에서 보내는 시스템 프롬프트를 단계별(`base`, `global`, `workspace`, `repository`, `task`)로, 그리고 최종 `system_prompt`로 출력합니다. 모델을 호출하지 않으며 AI가 꺼져 있어도 동작합니다. 워크스페이스는 저장소를 포함하면 `GITPOULPI_WORKSPACE`의 것이고, 아니면 포함하는 첫 번째입니다. `code_review`에는 `review_context` 항목(단계가 아니라 diff 앞에서 요청에 합쳐집니다)이 있어, diff 외에 리뷰에 무엇이 전달되는지를 실제 적용 값과 함께 알려 줍니다. |
| `ai review-context [--repo PATH \| --project HOST/PROJECT] [--run-in-repo profile\|yes\|no] [--claude-md on\|off] [--agents-md on\|off] [--context-file PATH\|URL] [--no-context-file] [--no-extra-file [on\|off]] [--reset]` | 코드 리뷰 초안에 diff 외에 무엇을 줄지 표시하거나 설정합니다(`[ai.review]`, [AI > 리뷰 컨텍스트](ai.md#리뷰-컨텍스트) 참고). `--repo`도 `--project`도 없으면 전역 기본값이고, `--repo`(전역 플래그)는 클론 하나의 고유 값, `--project github.com/owner/name`은 클론되지 않은 저장소의 값(`remote-reviews.toml`)입니다. 설정 플래그가 없으면 표시만, 있으면 저장하고 출력합니다. JSON: `scope`(`global`, `repository`, `project`), `target`, `global`, `own`(저장소 또는 프로젝트가 설정한 필드만), `effective`(리뷰에 적용되는 값), `changed`. `--reset`은 저장소 또는 프로젝트의 고유 값을 지웁니다. `--run-in-repo`는 `--project`에 적용되지 않습니다. `--no-extra-file`(단독 또는 `on`)은 전역 값과 관계없이 저장소 또는 프로젝트에 추가 파일을 주지 않으며, `off`는 다시 전역 파일을 따르게 합니다. `--repo` 또는 `--project`가 필요하고 `--context-file`과 함께 쓸 수 없으며, 이때 `own`에 `"no_extra_file": true`가 나타납니다. 모델이 필요 없으며 AI를 꺼도 동작합니다. |
| `ai trust <profile> [--accept-origin URL] [--accept-certificate SHA256] [--allow-insecure-http on\|off]` | 프로필의 API 키를 저장된 주소에 묶습니다([AI > 키가 가는 곳](ai.md#키가-가는-곳) 참고). 옵션이 없으면 `{profile, current_origin, trusted}`를 출력합니다. `--accept-origin`은 바뀐 뒤의 프로필 현재 기본 URL을 수락하고(거부 메시지가 출력한 철자 그대로), `--accept-certificate`는 자체 호스팅 서버의 인증서를 SHA-256 키 지문으로 고정하며, `--allow-insecure-http`는 이 컴퓨터가 아닌 곳의 일반 `http://` 기본 URL을 허용합니다. 사람만 실행합니다: MCP 도구가 아닙니다. AI가 꺼져 있어도 동작합니다. |

여기에 `commit --ai [--send-all]`와 `stash push --ai [--send-all]`가 더해집니다(`ai`와 같은 `--send-all`과 `truncated`이며, `hosting review suggest`도 `--send-all`을 받습니다). 모델은 `gitpoulpi` 프로세스에서 호출되므로 API 키는 데몬이나 MCP 클라이언트로 넘어가지 않습니다.

**저장소, 세션, 데몬, 설정**

| 명령 | 동작 |
|---|---|
| `repo discover [path]`, `repo init <path> [--initial-branch B] [--bare]`, `repo open <path>`, `repo close <path>`, `repo list`, `repo recent [--prune] [--forget P]` | 저장소와 이 세션의 탭. |
| `refs hide <names>...`, `refs show <names>...`, `refs solo <names>...` (각각 `--clear` 지원) | Log의 ref 필터: 숨기기, 다시 표시, 이것들만 표시(열려 있는 창에 실시간 반영). 숨긴 ref는 탐색에서도 빠집니다. 그 ref만 닿는 commit은 Log에서 사라집니다(체크아웃된 commit은 항상 남습니다). |
| `refs hide --remote <name>...`, `refs show --remote <name>...` | 리모트 전체를 숨기거나 표시합니다. 모든 브랜치가 대상이며 나중에 fetch하는 것도 포함합니다. 숨기려면 이름이 저장소의 리모트여야 합니다. `show`는 하나씩 숨겨 둔 그 리모트의 브랜치도 함께 표시하고, `--clear`는 숨긴 리모트도 비웁니다. |
| `session list`, `session new <name>`, `session rename <old> <new>`, `session delete <name>` | 이름 있는 세션(데몬이 실행 중이면 rename / delete는 거부됩니다). |
| `daemon run`, `daemon start`, `daemon stop [--all]`, `daemon restart`, `daemon status` | 세션의 백그라운드 프로세스(별칭 `server`). 실행 중인 데몬이 없으면 각 명령이 자기 수명 동안 쓸 내장 데몬을 시작합니다. `daemon start`는 느린 컴퓨터를 위해 새 데몬이 포트를 게시할 때까지 최대 20초 기다립니다(실패를 알리기 전에 한 번 더 확인합니다). |
| `config path`, `config get <key>`, `config set <key> <value>` | 설정([설정 참조](config-reference.md)). `config set ui.theme`과 `ui.graph_color_theme`은 이름을 레지스트리와 대조합니다. |
| `licenses` | 프로그램에 내장된 서드파티 라이선스 고지와 크레딧(정보 > 라이선스의 텍스트). 읽기 전용, 데몬 없음. |
| `theme list`, `theme export <slug>` | 색상 테마: JSON 목록(slug, label, source, light, lane palette)과 stdout의 완전한 테마 파일([테마](themes.md)). 읽기 전용, 데몬 없음. |
| `desktop shortcut status` | `ui.launch_terminal`이 가리키는 터미널에서 GitPoulpi를 시작하는 런처 바로 가기(설정 > 런처도 같은 일을 합니다): 각 바로 가기의 상태(`not_installed`, `installed`, `outdated`, `foreign`)와 사용 중인 터미널을 출력합니다. 데몬 없이 동작하며 MCP 도구가 아닙니다. |
| `desktop shortcut install [--where launcher\|desktop\|startmenu]` | 바로 가기를 만들거나 갱신합니다: Linux에서는 `.desktop` 항목과 아이콘, Windows에서는 시작 메뉴나 바탕 화면의 `.lnk`, macOS에서는 `~/Applications/GitPoulpi.app`. 기본값은 OS 런처입니다. |
| `desktop shortcut remove [--where ...]` | GitPoulpi가 만든 바로 가기를 제거합니다(기본값: 전부). GitPoulpi의 것이 아닌 파일은 절대 건드리지 않습니다. |
| `desktop folder-menu status`, `desktop folder-menu install`, `desktop folder-menu remove` | 파일 관리자 오른쪽 클릭 메뉴의 **GitPoulpi에서 열기** 항목(설정 > 런처 > 파일 관리자 메뉴): Windows는 파일 탐색기, Linux는 GNOME Files, Dolphin, Nemo, Thunar, Caja, PCManFM, macOS는 Finder. `status`는 JSON `{os, entries:[{manager, detected, state}], unavailable, error}`를 출력합니다(`state`: `not_installed`, `installed`, `outdated`, `foreign`. `unavailable`: GitPoulpi 옆에 실행 도우미가 없음). `install`은 발견된 모든 파일 관리자에 항목을 씁니다(GitPoulpi의 것이 아닌 파일 위에는 쓰지 않음). `remove`는 `install`이 쓴 것만 제거합니다. 데몬 없음, MCP 도구가 아닙니다. |
| `alias status`, `alias create <name> [--add]`, `alias remove [name]` | 명령 별칭(`gp` 또는 임의의 이름)과, `--add`를 쓰면 추가용 변형(`gpa`. `gitpoulpi --add`를 실행하며, Linux와 macOS에서는 표시된 `/bin/sh` 스크립트, Windows에서는 `.cmd`). GitPoulpi가 만든 각 별칭의 상태(`installed`, `outdated`, `foreign`)와 `kind`(`open` 또는 `add`), bin 폴더, 대상을 JSON으로 보여 줍니다. `create`는 경고(이름이 이미 PATH에서 무언가를 실행함, PowerShell 자체 별칭)와 bin 폴더가 PATH에 있는지도 알려 주며, GitPoulpi의 것이 아닌 파일은 거부합니다. 이름 없는 `remove`는 GitPoulpi가 만든 모든 별칭을 제거합니다. 데몬 없음, 설치 프로그램이 호출합니다. |
| `path status`, `path add`, `path remove` | 새 터미널을 위해 사용자 PATH에 넣는 GitPoulpi: 셸 시작 파일의 표시된 블록(Linux, macOS) 또는 `HKCU\Environment`(Windows). `status`는 `not_added`, `added`, `outdated`, `on_path`(이미 있으나 GitPoulpi가 넣은 것이 아님) 중 하나입니다. `remove`는 `add`가 넣은 것만 제거합니다. |
| `uninstall [--keep-files]` | GitPoulpi가 만든 명령 별칭, PATH 항목, 바로 가기, 파일 관리자 메뉴 항목을 제거하고, 릴리스 설치라면 프로그램 파일도 제거합니다(`install.sh --uninstall`과 Windows 제거 프로그램이 실행하는 것). `.gitpoulpi-dist` 표시가 없는 빌드(cargo 빌드)는 거부합니다. MCP 에이전트는 사용할 수 없습니다. |
| `launch [--new-window] [-- COMMAND...]`, `launch [--new-window] --folder DIR` | GitPoulpi 바로 가기가 실행하는 것: 이미 열려 있는 GitPoulpi의 창을 보여 주고(`ui.reuse_window`), 없으면 COMMAND(터미널 명령)를 시작합니다. `--new-window`는 항상 COMMAND를 시작합니다(reason `new_window`). Windows에서는 바로 가기나 작업 표시줄 아이콘을 클릭할 때 Shift를 누르고 있어도 같습니다. JSON: `{"action":"raised"}` 또는 `{"action":"started","reason":...}`. `--folder DIR`은 파일 관리자의 **GitPoulpi에서 열기** 항목이 실행하는 것입니다. `ui.reuse_window`가 켜져 있고 열린 창이 있으면 DIR이 속한 저장소가 가장 최근에 포커스된 창의 탭이 되고(`{"action":"joined",...}`), 아니면 `ui.launch_terminal`의 터미널이 DIR에서 GitPoulpi를 시작합니다. 데몬은 시작하지 않으며 MCP 도구가 아닙니다. |
| `mcp serve --stdio \| --http [ADDR] [--allow-remote] [--ui-control auto\|ask\|off]` | MCP 서버([MCP와 에이전트](mcp-and-agents.md)). `ADDR`이 없으면 `--http`는 `[mcp] bind`(기본값 `127.0.0.1:8808`)를 사용합니다. `--http`는 `[mcp] http_auth`가 꺼져 있지 않으면 bearer 토큰이 필요합니다. `--allow-remote`는 인증이 켜져 있고 트래픽이 암호화되어 있지 않으면(`[mcp] tls` 또는 `behind_proxy`) 거부됩니다. |
| `mcp token [--show] [--copy] [--rotate]` | MCP HTTP 엔드포인트의 bearer 토큰을 JSON `{token_hint, path, rotated}`로 보여 줍니다(토큰은 처음 사용할 때 생성). `--show`는 클라이언트의 `Authorization: Bearer` 헤더에 붙여 넣을 전체 `token`을 추가하고, `--copy`는 출력하지 않고 터미널(OSC 52)을 통해 클립보드에 넣고, `--rotate`는 새 토큰으로 교체하며 이전 토큰은 즉시 동작하지 않습니다. MCP 도구가 아닙니다: 에이전트는 자신의 서버를 지키는 키를 읽거나 교체할 수 없습니다. [MCP와 에이전트](mcp-and-agents.md#다른-컴퓨터에서-엔드포인트에-접근하기)를 참고하세요. |
| `completions bash\|zsh\|fish\|powershell\|elvish` | 셸 자동 완성 스크립트를 stdout에 출력합니다. |
| `shell-init bash\|zsh\|fish\|pwsh [--name gp]` | *종료 후 cd*로 종료할 때 활성 탭의 폴더로 `cd`하는 래퍼 함수(`gp`): `eval "$(gitpoulpi shell-init bash)"`. [탭 폴더 따라가기](following-the-tab-folder.md)를 참고하세요. |

### 워크스페이스와 검색

**워크스페이스**는 이름이 붙은 저장소 묶음으로, 기본 commit 프로필을 둘 수 있습니다.
`config.toml` 옆의 `workspaces.toml`에 있으며 모든 세션과 창이 공유하므로
`workspace` 명령은 데몬을 시작하지 않습니다(저장소마다 `origin` URL을 얻기 위해
`add`와 `create --add`만 데몬에 묻습니다). 저장소는 여러 워크스페이스에 속할 수
있습니다. 경로는 즐겨찾기와 최근 목록처럼 비교됩니다.

| 명령 | 동작 |
|---|---|
| `workspace list`, `workspace show <id>` | `{workspaces: [...]}` / `{workspace}`: `id`(slug. 이름을 바꿔도 그대로), `name`, `color`, `description`, `profile`, `profile_exists`, `repos: [{path, exists, remote}]`(`remote`는 저장소를 추가할 때 기록한 `origin` URL이며 자격 증명은 제거됩니다). |
| `workspace create <name> [--add PATH]... [--profile ID] [--color C] [--description T]` | 워크스페이스를 만들고 출력합니다. 두 워크스페이스가 같은 이름을 가질 수 없습니다. `--add`는 반복할 수 있으며, 명령을 실행할 저장소를 고르는 `--repo`와 다릅니다. |
| `workspace rename <id> <name>`, `workspace delete <id>` | 이름을 바꿔도 id는 유지됩니다. 삭제는 저장소를 절대 건드리지 않습니다. |
| `workspace add <id> <path>...`, `workspace remove <id> <path>...` | `add`는 각 저장소의 루트와 `origin` URL을 기록합니다(존재하지 않거나 저장소 안에 있지 않은 경로는 메시지와 함께 거부되며 아무것도 저장되지 않습니다. 나중에 사라진 저장소만 누락으로 표시된 채 목록에 남습니다). `remove`는 디스크에서 사라진 저장소의 경로도 받습니다. |
| `workspace set-profile <id> <profile>` / `--none` | 워크스페이스의 저장소에서 commit할 때 쓰는 `[[profiles]]` id입니다. 어떤 프로필도 가리키지 않는 id는 저장되며(`profile_exists: false`) 적용되지 않습니다. |
| `workspace set-ai-instructions <id> [--action <a>] [--mode append\|replace] (--text T \| --clear)` | 워크스페이스의 AI 지침으로, 모든 동작 또는 하나(`commit_message`, `code_review`, ...)에 대해 설정합니다. `append`는 전역 지침 뒤에 붙이고, `replace`는 대신 사용합니다. 워크스페이스의 모든 저장소에 적용되며 저장소 자체 지침보다 앞에 옵니다. `workspace show`는 이를 `ai_instructions`로 출력합니다. |
| `commit -m M [--workspace ID]` | 저장소가 워크스페이스에 속하고 프로필이 존재하면 워크스페이스의 프로필로 commit하며, 아니면 `general.active_profile`, 그것도 없으면 저장소 자체의 신원을 사용합니다. `--workspace`(또는 `GITPOULPI_WORKSPACE`)가 없으면 아무것도 바뀌지 않습니다. 저장소가 여러 워크스페이스에 속할 수 있으므로 commit은 소속만으로 워크스페이스를 추측하지 않습니다. 알 수 없는 id는 오류입니다. |
| `search <query> [--workspace ID] [--kind K]... [--limit N]` | 현재 저장소 또는 워크스페이스의 모든 저장소(`GITPOULPI_WORKSPACE`가 플래그를 대신함)의 브랜치(로컬과 리모트), tag, worktree, stash, commit 메시지, 그리고 호스팅 캐시의 pull/merge request와 이슈를 퍼지 검색합니다. 창에서의 버전은 [검색](search.md)입니다. |

`search`는 `{query, workspace, hits, partial, repos}`로 응답합니다. 각 결과는
`{kind, label, detail, target, score, positions, repo}`입니다. `kind`는 `branch`,
`tag`, `commit`, `stash`, `worktree`, `repo`, `pull_request`, `issue` 중 하나이고,
`positions`는 강조 표시할 `label`의 일치한 문자이며, `target`은 이동할 곳을
알려 줍니다(전체 ref 이름을 가진 `{type: "ref", name}`, `{type: "commit", id}`,
`{type: "stash", index, id}`, `{type: "worktree", path}`, `{type: "repo", path}`,
`{type: "pull_request", number}`, `{type: "issue", number}`). 결과는 저장소를
가로질러 `score` 기준으로 합쳐지며 가장 좋은 것이 먼저 옵니다. 일치 방식은 명령
팔레트와 같습니다: 쿼리 그대로, 그다음 어디든 그대로 포함, 그다음 문자가 순서대로
(앞에 있고 짧을수록 우선). commit 본문은 제목이 일치하지 않고 쿼리가 세 글자 이상일
때만 검색합니다. 접두사는 검색 범위를 좁히며 텍스트의 일부가 아닙니다: `b:` 브랜치,
`t:` tag, `c:` commit, `s:` stash, `w:` worktree, `r:` 저장소(워크스페이스에서만),
`pr:`(또는 `mr:`) pull/merge request, `i:` 이슈, `#`은 그 둘 모두입니다. `--kind`도
(반복 가능, 같은 이름) 필터링합니다. `partial`은 저장소의 commit이
[`search.commit_limit`](config-reference.md#search-워크스페이스-검색)에서 잘렸을 때
true입니다. `repos`는 저장소마다 검색되었는지 알려 줍니다(검색되지 않았으면
`reason`. 디스크에서 사라진 경로는 보고되며 치명적이지 않습니다). 일회성 명령은 먼저
각 저장소의 인덱스를 만들고, 같은 세션에 창이 열려 있으면 데몬이 이미 데워 둔
인덱스를 사용합니다. pull/merge request와 이슈는 각 저장소의 호스팅 캐시(창이
`.gitpoulpi/hosting-cache.json`에 보관하는 파일)에서 읽으며 호스트에서는 절대 읽지
않습니다. 창이 한 번도 불러오지 않은 저장소에는 찾을 것이 없고, 없거나 반쯤 쓰인
캐시는 그냥 결과가 없는 것입니다.

**열려 있는 창에 표시하기**(`ui`. 모든 명령은 `--viewer <id>`와 `--launch`도 받습니다)

| 명령 | 동작 |
|---|---|
| `ui viewers [--all-sessions]`, `ui state [--text]` | 열려 있는 창, 그리고 창이 보여 주는 내용. |
| `ui show commit <rev> [--also R] [--files] [--focus refs\|log\|status]`, `ui show ref <name>`, `ui show pr <n>`, `ui show issue <n>`, `ui show wip [path] [--staged] [--composer]` | 무언가를 선택합니다. |
| `ui show diff <path> [--rev R \| --unstaged \| --staged] [--line N] [--side old\|new] [--split \| --inline] [--whole-file \| --hunks] [--highlight A-B]` | 특정 줄에서 diff를 엽니다. |
| `ui show file <path> [--rev R \| --worktree \| --index] [--blame \| --history] [--line N] [--column C] [--highlight A-B]` | 파일, 그 blame 또는 기록을 엽니다. |
| `ui show tab [path]`, `ui show home [--filter F]`, `ui show search <query>`, `ui show palette [query]`, `ui show keys [topic]`, `ui show settings [page] [--setting KEY]` | 탭, Home, 찾기 표시줄, 팔레트, 도움말, 설정 페이지로 이동합니다. `gitpoulpi ui show settings --help`가 페이지 이름을 나열합니다. |
| `ui highlight <A[:C]-B[:C]> [--no-scroll]`, `ui notify <message>`, `ui back` | 줄에 색을 입힙니다. 토스트 표시. 마지막 보기 변경을 되돌립니다. |
| `ui show conflict <path> [--conflict N]` | 충돌한 파일의 충돌 N에서 merge 편집기를 엽니다(아무것도 선택하거나 저장하지 않음). |
| `ui propose reword <rev> -m M`, `ui propose commit-message <summary> [--body B]`, `ui propose branch <name> [--start-point R]`, `ui propose tag <name> [--target R] [-m M]` | 미리 채워진 대화상자를 열어 사용자가 확인합니다(`[mcp] allow_ui_propose = true` 필요). |
| `ui propose split <rev> --plan <file\|->` | commit 위에 분할 편집기를 열고 계획(`split-commit --plan` JSON)을 채워 사용자가 검토, 편집, 적용하게 합니다. 사용자가 적용하기 전에는 아무것도 분할되지 않습니다. 다른 제안과 같은 제한이 적용됩니다. |
| `ui propose rewrite --recipe <file\|->` | 레시피(`rewrite preview --recipe`와 같은 TOML 또는 JSON)가 이미 들어 있는 기록 다시 쓰기 워크벤치를 열어 사용자가 미리 보고 적용하게 합니다. 사용자가 하기 전에는 아무것도 다시 쓰거나, 영구 삭제하거나, push하지 않습니다. 제안에는 규칙이 50개 이하이고, 스크립트(미리볼 때 실행되므로)와 비밀 값이 없어야 합니다. 다른 제안과 같은 허용 설정을 씁니다. |
| `ui propose resolution <path> (--pick 1=a,2=ba,... [--default a\|b] \| --content-file F)` | 해결 방법이 이미 선택된(또는 파일 전체가 텍스트로 채워진) merge 편집기를 열어 사용자가 검토하게 합니다. 사용자의 저장 및 해결됨으로 표시가 유일한 확인입니다. 다른 제안과 같은 제한이 적용됩니다. |

종료 코드: 0은 적용됨, 3은 사용자에게 위임됨, 그 밖에는 1입니다. 자세한 내용과 창이 따르는 규칙은 [MCP와 에이전트](mcp-and-agents.md#사용자에게-보여-주기)를 참고하세요.

## 참고

- **세션.** `gitpoulpi session list`는 각 세션을 `live` / `stale`과 함께 보여 줍니다(포트에 연결해 보고 판단). 도출된 이름은 `<folder>-<hash of the path>`입니다.
- **대화형 프롬프트 없음.** 아무것도 질문하지 않습니다. 위험한 작업은 플래그(`--yes`, `--force-with-lease`)가 필요하거나 이유와 함께 거부됩니다.
- **CLI에 없음**: `checkout --file`(파일 하나 복원)은 창에서만 제공됩니다.
