# Diff 보기와 파일 보기의 그림

이미지인 바이너리 파일은 "(no textual changes - binary content...)" 안내 대신 그림으로 표시됩니다. Diff 보기는 **이전**과 **이후**를 보여 주고, 파일 보기는 파일을 있는 그대로 보여 주며, merge 편집기는 충돌한 그림의 각 쪽을 보여 줍니다. 여기 있는 모든 것은 읽기 전용입니다: 그림을 보는 것은 저장소를 절대 바꾸지 않으므로 취소할 것이 없습니다.

**설정 > 이미지 > 이미지 미리 보기**(`ui.image_view`)로 끌 수 있습니다: 일반 바이너리 안내로 돌아갑니다. `image-view` 기능이 없는 사용자 지정 빌드에는 뷰어가 전혀 없고, 이미지 페이지에는 편집기 목록만 남습니다([사용자 지정 빌드](custom-builds.md) 참고).

## 어떤 파일

PNG와 JPEG는 항상, GIF, WebP(첫 프레임), BMP, ICO/CUR는 빌드에 `image-view`가 있을 때 지원합니다. TIFF, AVIF, HEIC, PSD, RAW는 인식하지만 디코딩하지 않습니다: 정보 카드가 형식, 크기, 치수를 알려 줍니다. SVG는 텍스트이므로 텍스트 diff를 유지합니다. **미리 보기 최대 크기 (MiB)**(기본 32 MiB)를 넘거나 64메가픽셀을 넘는 이미지는 대신 정보 카드를 표시합니다. Git LFS로 저장된 파일은 그 객체가 로컬 저장소에 있으면 표시되고, 없으면 카드가 먼저 `LFS > Pull`을 하라고 알려 줍니다. 투명한 부분은 체커보드 위에 그려집니다.

## 그려지는 방식

이미지 프로토콜이 있는 터미널(Kitty와 Ghostty, WezTerm과 iTerm2, Rio, mintty, 그리고 sixel 터미널인 Windows Terminal, foot, Tabby)에서는 그림이 진짜 이미지입니다. 그 밖의 곳(일반 Windows 콘솔, zellij, GitPoulpi가 모르는 터미널)에서는 색이 있는 반블록 문자로 그려지며, 세로 해상도는 절반이지만 어디서든 알아볼 수 있습니다. **이미지 프로토콜이 없을 때**를 *정보 카드만*으로 설정할 수 있습니다. **로그 및 그래프** 페이지의 **이미지 프로토콜**로 하나를 강제할 수 있습니다.

## Diff 보기

이미지 파일의 diff를 여세요(commit의 diff, 또는 WIP의 스테이징 안 된 쪽이나 스테이징된 쪽). 헤더에 두 파일이 표시되고(`PNG 512x512 . 34 KiB -> PNG 640x480 . 41 KiB`), 이어서 확대 버튼, **맞춤**, **1:1**, **편집 프로그램**이 나옵니다.

- 헤더 오른쪽의 **분할 | 인라인**, 또는 `m`: 나란히 보기, 또는 한 번에 그림 하나. **Tab**이나 *이전 | 이후* 클릭으로 인라인 보기에서 다른 쪽을 표시합니다. 두 창을 나누기에 너무 좁은 분할은 설정(`ui.diff_layout`)을 바꾸지 않고 인라인으로 그려집니다.
- 분할의 **구분선**은 드래그하거나 `Alt+Right` / `Alt+Left`(이전 창이 공간을 가져가거나 내줌)로 옮기고, 더블 클릭이나 `Alt+0`으로 가운데로 돌아옵니다. 비율은 세션 동안 기억됩니다.
- 새 파일은 *새 파일*이라는 캡션이 붙은 창 하나를 보여 주고, 삭제된 파일은 *삭제된 파일*을 보여 주며, 둘 다 전환 버튼을 숨깁니다. 작업 중인 변경 사항에서 선택한 추적되지 않는 그림은 새 파일로 미리 보입니다.
- 이전 쪽은 부모 commit(commit diff), `HEAD`(스테이징됨), 인덱스(스테이징 안 됨)이고, 이후 쪽은 commit, 인덱스, 디스크의 파일입니다. diff를 연 동안 디스크의 파일이 바뀌면(편집기에서 저장했거나 도구가 다시 썼을 때) 그림이 약 0.5초 안에 따라갑니다.

## 파일 보기

파일의 메뉴나 diff 막대에서 **파일 보기**로 그림을 여세요: 창 하나에 해당 리비전의 파일(작업 중인 변경 사항이면 디스크의 파일)이 표시됩니다.

## 확대와 스크롤

| | |
|---|---|
| `+` / `-`(또는 `=`) | 창의 중심을 기준으로 확대 / 축소 |
| `0` | **맞춤**(기본값): 그림 전체. 창이나 구분선의 크기를 바꿔도 맞춤이 유지됩니다 |
| `1` | 실제 크기(1:1) |
| 화살표, `h j k l` | 창의 10분의 1만큼 스크롤. `Shift`와 함께면 창 하나만큼. `PageUp`/`PageDown`, `Home`/`End` |
| 휠 | 세로 스크롤. `Shift`+휠은 가로. `Ctrl`+휠은 포인터를 기준으로 확대 |
| 드래그 | 그림을 잡고 움직입니다. 양옆의 스크롤바는 다른 곳과 똑같이 동작합니다 |

확대한 보기는 창 크기가 바뀌어도 배율과 중심점을 유지하고, 맞춤은 맞춤으로 유지됩니다. Diff 보기에서는 두 창이 확대와 스크롤 위치를 공유하므로(**이전/이후 확대와 스크롤 동기화**, 기본적으로 켜짐) 두 그림의 같은 부분이 보입니다. 크기가 다르면 확대는 각각에 상대적으로 유지됩니다. **픽셀 확대 시작 배율**(기본 2x)부터는 그림이 부드럽게 처리되지 않고 네모난 픽셀로 확대되며, 아이콘과 픽셀 아트에 알맞습니다.

## 편집 프로그램

헤더의 **편집 프로그램** 버튼은 이 컴퓨터에서 찾은 이미지 편집기(GIMP, Krita, Inkscape, Photoshop, Paint.NET, Preview, ... 그리고 시스템 기본 앱)를 나열합니다. `o`는 기본 편집기를 실행하고 `Shift+O`는 목록을 엽니다. 파일 목록에서 이미지를 오른쪽 클릭한 메뉴와 명령 팔레트(*이미지: 편집 프로그램...*)에도 있습니다. 목록과 기본값은 **설정 > 이미지**에서 정하며, [열기 위치](open-in.md)와 같은 방식으로 동작합니다.

디스크의 파일(작업 중인 변경 사항 쪽)을 편집하는 것은 직접적입니다: 편집기가 그 자리에 저장하고 그림이 새로 고쳐집니다. 그 밖의 버전(commit의 것, 인덱스, 삭제된 파일)은 상태 표시줄에 안내가 표시되는 **읽기 전용 임시 사본**으로 쓰이므로, 편집기가 저장소를 바꿀 수 없습니다.

시스템이 이미지 형식에 등록한 앱(그 *연결 프로그램* 목록)은 목록의 편집기 뒤에 오며, 이미 있는 프로그램은 반복하지 않습니다. 이미지가 아닌 다른 바이너리 파일도 같은 목록을 사용합니다. [열기](open-in.md)를 참고하세요.

## merge 편집기에서

충돌한 그림은 카드에 **A**, **B**, 그리고 (있다면) **Base** 그림을 상자 안에 나란히 보여 주며, 각각 상자에 맞춰지고 읽기 전용입니다(거기서는 확대 불가. 그림은 고르는 데 도움을 줄 뿐입니다). 버튼과 키는 그대로입니다: **A 유지**(`a`), **B 선택**(`b`), **Base 선택**(`o`), **merge 도구로 열기**(`m`). 미리 보기에는 충분히 넓은 창(약 70열)과 여유 행이 필요합니다. 더 좁으면 카드는 일반 텍스트 카드가 됩니다. [merge 충돌 해결](merge-conflicts.md)을 참고하세요.

## 키와 설정

키는 [단축키](keybindings.md#이미지-보기)에 있습니다. 모든 키를 다시 지정할 수 있고 팔레트(`Ctrl+P`, *이미지* 입력)에서 닿을 수 있습니다. 옵션은 [설정](settings.md#이미지)의 **이미지** 페이지와 [설정 참조](config-reference.md)(`ui.image_view*`, `ui.image_editors`)에 있습니다.
