# 인터페이스 둘러보기

이 페이지는 GitPoulpi 창의 모든 영역을 위에서 아래로 차례로 소개합니다. 다른
페이지도 같은 이름을 사용합니다. 그림에는 가상의 작성자가 있는 작은 데모
저장소를 사용했습니다.

![영역이 표시된 메인 창: 탭 표시줄, 도구 모음, Refs 사이드바, Log, 작업 변경 창, commit 양식, 상태 표시줄](../images/hero.png)

## 프레임

### 제목 표시줄

창의 맨 위 가장자리에는 `🐙 GitPoulpi vX.Y.Z -- <repository path>`가 표시됩니다(세션 이름은 맨 아래 상태 표시줄에 있습니다).

- **🐙**는 **정보** 창을 엽니다. 버전, 빌드 기능, 라이선스, 링크, 서드파티 크레이트가 나옵니다. 이미지를 그릴 수 있는 터미널에서는 문어가 픽셀 로고이며 로고 색으로 표시됩니다(그 밖에는 이모지 그대로입니다). 팔레트: `도움말: GitPoulpi 정보`, 키: `Ctrl+N` 다음 `A`. 정보 창에서는 문어의 눈동자가 마우스 포인터를 따라갑니다. 로고를 클릭하거나 `Space`를 누르면 로고가 회전하며 다음 색으로 바뀝니다. 로고를 오른쪽 클릭하거나 `c`를 누르면 색 목록이 나옵니다. 선택한 색은 GitPoulpi가 `ui.logo_color`에 저장합니다. 링크는 클릭하거나 접근 키(`s` 소스 코드, `d` 문서, `i` 라이선스)로 열고, `l`은 서드파티 크레이트를 버전과 라이선스와 함께 나열합니다(스크롤 가능한 목록, `Esc` 또는 `l`로, 또는 제목을 클릭해서 돌아갑니다). 목록의 각 크레이트에는 해당 페이지로 가는 링크(저장소, 없으면 crates.io 페이지)가 있습니다. 행을 클릭하거나 `↑` `↓`로 고르고 `Enter`를 누르면 브라우저에서 열립니다. `t`(또는 팔레트 명령 `도움말: 라이선스 및 크레딧`)를 누르면 프로그램에 포함된 모든 것의 라이선스 고지와 크레딧을 스크롤되는 텍스트로 볼 수 있습니다(`Up` / `Down`, `PgUp` / `PgDn`, `Home` / `End`, 돌아가려면 `Esc` 또는 `t`). 스크립트에서는 `gitpoulpi licenses`가 같은 텍스트를 출력합니다.
- 이름과 경로 사이의 **버전**(`v1.0.0`, 더 새로운 릴리스가 있으면 `vX.Y.Z 사용 가능`)은 사이에 있으며, 클릭하면 더 새로운 릴리스가 있을 때는 업데이트 패널이, 그렇지 않으면 **릴리스 노트** 탭이 열립니다. [업데이트](updates.md)를 참고하세요.
- 경로 바로 뒤의 **열기 위치 ▾**는 탭의 폴더를 터미널, 편집기, 멀티플렉서, 파일
  관리자에서 엽니다(`Alt+O`). [열기 위치](open-in.md)를 참고하세요.
- 톱니바퀴 바로 왼쪽의 **⌕ 전체 검색**(돋보기와 레이블)은 [전체 검색](search.md)(`Ctrl+Alt+F`)을 엽니다. 제목 표시줄이 너무 좁으면 가장 먼저 줄어듭니다. 레이블이 먼저 사라지고(돋보기는 남습니다), 그다음 버튼이 사라집니다.
- **×** 바로 왼쪽의 **톱니바퀴**(`⚙`)는 **설정**(`Ctrl+,`)을 엽니다.
- 오른쪽 끝의 **×**는 `q`와 마찬가지로 종료합니다.

### 상태 표시줄

상태 표시줄은 기본적으로 창의 마지막 줄입니다(**설정 > 모양 > 상태 표시줄 위치**로 저장소 탭 위의 맨 위로 옮길 수 있습니다). 현재 브랜치, 불러온 commit 수(더 오래된 기록을 아직 불러오는 중에는 `commit 500 / 48213개`, 총수를 세는 동안은 총수 자리에 `...`, 전부 불러오면 `commit 2500개`만), `dirty` 또는 `clean`, 세션 이름, 스파스 체크아웃에서는 `스파스` 배지, 그리고 가장 유용한 키가 표시됩니다. `?` 도움말, `Ctrl+G` git 동작, `Ctrl+N` 탐색, `Ctrl+P` 명령, `Shift+F10` 메뉴, `q` 종료입니다. 창이 좁으면 덜 유용한 키부터 생략됩니다. 상태 표시줄에는 상태 메시지와 진행 상황도 표시됩니다. 표시되는 키는 항상 실제로 적용 중인 키이며, 직접 바꾼 키도 포함됩니다([설정](settings.md#키보드-및-마우스) 참고). 총수를 세는 방법은 설정입니다(**전체 commit 수를 세는 방법**, [설정](settings.md#로그-및-그래프) 참고).

오른쪽 끝의 **활동** 버튼은 활동 로그를 엽니다. Git 작업 탭(작업과 걸린 시간, 메시지, 오류), 애플리케이션 탭(수준 상자와 **로그 지우기** 버튼이 있는 애플리케이션 로그), 그리고 두 탭을 이 저장소, 워크스페이스, 모든 저장소로 좁히는 **범위** 상자가 있습니다. 버튼의 숫자는 아직 확인하지 않은 오류의 수입니다. 그 왼쪽의 작업 표시기는 실행 중인 백그라운드 작업과 이를 취소하는 `[x]`를 보여 줍니다. **홈** 탭에도 같은 상태 표시줄이 있으며, 오른쪽 아래의 **활동** 버튼은 *모든 저장소*로 열립니다. 작업이 실패하면 상태 표시줄이 빨간색으로 알려 주고, 활동 로그의 해당 항목에 이유, 다음 단계, 세부 정보, AI용 복사가 있습니다. 둘 다 [무언가 실패했을 때](troubleshooting.md#무언가-실패했을-때)에서 설명합니다.

### 오버레이

명령 팔레트, 도움말, 컨텍스트 메뉴, 대화상자, 팝업, 설정은 창 위에 열립니다.
각각 테두리 오른쪽 위에 `✕`가 있으며, `Esc`나 `✕` 클릭으로 닫습니다. 대화상자, 팝업, 패널은 바깥을 클릭해도 닫힙니다([창과 대화상자 닫기](mouse-and-gestures.md#창과-대화상자-닫기) 참고).

### 창이 작을 때

창이 좁아져도 아무것도 소리 없이 사라지지 않습니다. 버튼은 먼저 긴 레이블을 잃고(`...`로 잘림), 그다음 두 번째 줄로 넘어가거나 그 행의 `⋯` 메뉴 뒤로 들어가며, 키와 팔레트 항목은 내내 계속 동작합니다. 창에 비해 너무 큰 대화 상자는 아무것도 그리지 않는 대신 제목, `✕`, **창이 너무 작음: 넓히세요**라는 줄이 있는 작은 프레임을 그립니다. `Esc`와 `✕`로 닫을 수 있고, 창을 넓히면 온전한 모습으로 돌아옵니다.

## 탭 표시줄

**홈** 탭(집 아이콘)이 왼쪽 끝에 있고, 그 뒤에 [워크스페이스 칩](workspaces.md)(워크스페이스가 생긴 뒤), 고정된 **Radar** 탭(다른 탭처럼 닫을 수 있습니다. [Radar](radar.md) 참고), 그리고 한 번 연 뒤의 **워크스페이스** 탭(`Alt+J`, 다른 탭처럼 닫을 수 있습니다)이 옵니다. 그다음에 열린 저장소마다 탭이 하나씩 있습니다. 탭을 닫는 `x`는 현재 탭과 포인터 아래의 탭에만 표시됩니다. 탭 표시줄에는 탭만 있습니다([전체 검색](search.md) 버튼은 제목 표시줄에 있습니다).

저장소 탭이 다 들어가지 않으면 탭이 줄어드는 대신 줄이 스크롤됩니다. 탭은 두 화살표 버튼 사이에 놓이며, 왼쪽이 `‹`, 오른쪽이 `›`입니다. 그쪽에 숨은 탭이 없으면 화살표는 흐리게 표시됩니다. 화살표를 클릭하면 그쪽으로 탭이 하나 더 보이고(누르고 있으면 계속 스크롤), 줄 위에서 휠을 써도 됩니다(위 또는 왼쪽이 앞쪽 탭). 현재 탭이 바뀔 때마다(키보드, 탭 선택기, 팔레트로 탭을 전환하거나 탭을 열고 닫거나 창 크기를 바꿀 때) 줄은 그 탭이 온전히 보일 만큼만 스크롤합니다. 공간이 있으면 오른쪽 화살표 뒤의 `…` 버튼이 탭 선택기를 엽니다. 탭을 화살표 위로 끌어 그대로 두면 줄이 스크롤되므로, 화면에 보이는 탭 너머에 놓을 수 있습니다. `Ctrl+N`을 누르면 동작하는 각 화살표에 배지가 표시됩니다.

**설정 > 모양 > 탭 표시줄 위치**는 이 줄을 창 아래쪽(상태 표시줄 아래)으로 옮기거나 왼쪽 가장자리의 열로 바꿉니다. 한 줄에 탭 하나씩, 맨 앞이 홈, 그다음 워크스페이스 칩, 레이더, 워크스페이스 탭, 각 탭(긴 이름은 `…`로 끝남), 그리고 `+`가 놓입니다. 탭이 줄 수보다 많으면 `…` 줄이 위(`▲`)와 아래(`▼`)에 숨은 개수를 보여 주고 탭 목록을 엽니다. 휠로 열을 스크롤합니다. 세로 도구 모음 옆에서도 탭이 가장 바깥에 놓입니다. 80열 미만의 창은 탭을 위에 둡니다. 클릭, 닫기 ×, 가운데 클릭, 오른쪽 클릭 메뉴, 끌어서 순서 바꾸기, 키보드는 어느 위치에서든 똑같이 동작합니다.

- 마지막 탭 바로 뒤의 **+**는 작은 메뉴를 엽니다. 메뉴에는 **새 탭**(`Alt+T`, 팔레트의 **탭: 새 탭**)이 있고, 해당 탭이 닫혀 있는 동안에는 그 탭을 여는 **Radar**와 **워크스페이스**(`Alt+J`)도 있습니다. 팔레트의 **탭: 새로 만들기...**도 같은 메뉴를 엽니다. **새 탭**은
  검색 필드가 준비된 홈 보기이므로 입력하면 바로 저장소가 필터링됩니다.
  저장소(또는 찾아보기, 클론, 초기화)를 고르면 그 탭이 표시줄 끝에 나타나고, 이미
  열려 있는 저장소는 그 탭으로 전환만 합니다. 빈 검색에서의 `Esc`, `Ctrl+W`, 탭의
  `x`, 가운데 클릭은 새 탭을 닫고 이전에 보던 탭으로 돌아갑니다. 세션에는 절대
  저장되지 않습니다.

  ![새 탭: 검색 필드가 준비된 홈 보기와 그 뒤의 열린 탭](../images/new-tab.png)
- 탭을 오른쪽 클릭하거나 `Ctrl+T`를 누르면 탭 메뉴가 나옵니다. **새 탭**, **탭 닫기**,
  **다른 탭 닫기...**, **오른쪽 탭 닫기...**, **즐겨찾기에 추가**(또는
  **즐겨찾기에서 제거**), **워크스페이스에 추가**(워크스페이스가 있을 때는 **워크스페이스에서
  제거**), **경로 복사**, **열기 위치 ›**, **SSH 키...**, **스파스 체크아웃...**입니다.
- `Ctrl+PageUp`과 `Ctrl+PageDown`은 탭을 전환합니다. `Ctrl+W`는 현재 탭을
  닫습니다. 탭을 가운데 클릭해도 닫힙니다(같은 확인 질문이 나옵니다).
- `t`(또는 `Ctrl+N t`)는 열린 탭을 검색할 수 있는 목록인 탭 선택기를 엽니다.
- **탭 순서 바꾸기:** 저장소 탭을 눌러 옆으로 끌면(탭의 고스트가 포인터를 따라가고 막대가 놓일 위치를 보여 줍니다. `Esc`로 취소) 되고, 탭 선택기의 행을 끌거나, 선택기에서 강조된 행에서 `Alt+Up` / `Alt+Down`을 누르거나, 팔레트의 **탭: 왼쪽으로 이동** / **탭: 오른쪽으로 이동**을 실행해도 됩니다. 순서는 세션과 함께 저장됩니다. 움직임 없이 클릭만 하면 그대로 탭이 선택됩니다. 집, 워크스페이스 칩, `+`는 움직이지 않습니다.
- `gp` 셸 래퍼로 GitPoulpi를 시작했고 현재 탭이 시작한 폴더가 아니면 탭 오른쪽에
  **종료 후 cd**가 나타납니다. [활성 탭의 폴더 따라가기](following-the-tab-folder.md)를
  참고하세요.
- 집 바로 뒤의 **워크스페이스 칩**(색 점과 이름, 또는 "워크스페이스 없음")은
  [워크스페이스](workspaces.md)를 전환합니다. 클릭하거나 `Alt+W`를 누르세요.
  워크스페이스가 하나 생기면 나타납니다.

![열린 저장소를 나열한 탭 선택기](../images/tab-picker.png)

**탭 기억**이 켜져 있으면(기본값) 다음 실행 때 탭이 복원됩니다. 워크트리는 자체
탭에서 열리며, 워크트리를 제거하면 그 탭도 닫힙니다.

worktree 탭은 해당 저장소 탭 바로 뒤에 놓이고, 끌어서 떼어 낸 worktree 탭은 다시 그 옆으로 돌아옵니다(설정 > 일반의 **worktree 탭 함께 묶기**, 기본값은 켜짐).

### 홈

홈 탭은 저장소 관리자입니다. **열린 저장소**, **즐겨찾기**, **최근 저장소**, **모든
저장소**의 네 섹션이 있습니다. 각 행에는 브랜치, ahead 및 behind 개수, 변경 수가
표시되고, 공간이 있으면 이어서 폴더 경로가 나옵니다. 경로는 `~`로 줄이고 좁으면 가운데를 잘라 내며, 이름, 소유자, 브랜치를
밀어내는 일은 없습니다. 각 행에는 별(즐겨찾기), **열기** 또는 **전환**, **닫기** 또는 **제거**,
`⋮` 메뉴가 있습니다.

맨 위에는 **찾아보기**, **클론**, **초기화**, 검색 상자, **모두 접기**, **모두
펼치기**가 있습니다. 더 이상 존재하지 않는 폴더는 *최근*과 *모든 저장소*에서 저절로
사라집니다. 없어진 즐겨찾기는 **제거** 버튼과 함께 남습니다. **제거**는 디스크의
어떤 것도 삭제하지 않습니다.

키: `Enter` 열기, `f` 즐겨찾기, `x` 닫기 또는 제거, `y` 경로 복사, `o` 기본 위치에서 열기(`⋮` 메뉴의 **열기 위치**에서 다른 것을 고를 수 있음), `.` 메뉴, `/` 검색, `Space`
섹션 접기, `Esc` 내 탭으로 돌아가기.
`Ctrl+N`을 누르면 검색 상자, 각 섹션, 각 버튼에 배지가 표시됩니다. 배지의 문자를 누르면 그 항목에 포커스하거나 그 버튼을 누릅니다([배지](keybindings.md#배지) 참고).

검색 상자 하나가 그 아래의 모든 것(즐겨찾기 포함)을 걸러 냅니다. 이름, 브랜치, 경로 중 하나가 입력한 텍스트를 포함하면 저장소가 남습니다. 워크스페이스는 홈의 페이지가 아니라 별도의 탭입니다. `+` 메뉴, `Alt+J` 또는 명령 팔레트에서 열고 `x`로 닫습니다. [워크스페이스](workspaces.md)를 참고하세요.

**클론**은 연결된 프로필(GitHub, GitLab, Gitea, Forgejo, Azure DevOps, Bitbucket, Gerrit)마다 접근할 수 있는 저장소를 소유자별 섹션으로 나열합니다. 먼저 내 저장소, 그다음 조직 또는 그룹별로(알파벳 순) 각각 머리글 아래에 나옵니다. 자물쇠 표시는 비공개 저장소입니다. 검색 상자는 모든 섹션에 걸쳐 필터링하며, 일치하는 것이 없는 섹션은 사라집니다. `Up`과 `Down`은 머리글을 건너뛰고, `Home`, `End`, `PgUp`, `PgDn`도 목록에서 동작합니다.

![홈 탭: 열린 저장소, 즐겨찾기, 최근 저장소와 찾아보기, 클론, 초기화 버튼](../images/home.png)

## 도구 모음

기본값은 창 아래, 상태 표시줄 위의 한 줄입니다. **설정 > 모양 > 도구 모음 위치**로 위(탭 아래), 아래, 또는 창 왼쪽이나 오른쪽의 세로 열에 둘 수 있습니다(80열 미만의 창에서는 열을 아래의 한 줄로 그립니다). 버튼은 줄이나 열의 시작에 놓이며, **설정 > 모양 > 도구 모음 버튼 정렬**로 가운데나 끝으로 옮길 수 있습니다. 버튼마다 아이콘 색이 다르며 테마가 정합니다([테마](themes.md) 참고). 모두 들어가지 않으면 덜 중요한 버튼부터 `⋯` 뒤로 옮겨집니다. 열에서는 버튼마다 한 줄을 쓰고 `▾`가 줄 끝에 있으며 메뉴는 열 옆에 열립니다. 아래쪽 도구 모음의 메뉴는 위로 열립니다.

| 버튼 | 동작 |
|---|---|
| **실행 취소**, **다시 실행** | 마지막 작업을 되돌리거나 복원합니다(`Ctrl+Z`, `Ctrl+Y`). 실행 취소가 꺼져 있으면 숨겨집니다. [실행 취소와 다시 실행](undo-redo.md)을 참고하세요. |
| **Pull** `▾` | **설정 > Git 및 인코딩 > Pull 버튼**이 정한 방식으로 pull합니다. `▾` 목록에는 **Fetch All**, **Pull (가능하면 fast-forward)**, **Pull (fast-forward만)**, **Pull (rebase)**가 있습니다. 목록 항목은 한 번만 실행되며 버튼을 바꾸지 않습니다. |
| **Push** `▾` | 체크아웃된 브랜치를 push합니다. `▾` 목록에서는 고른 리모트로 한 번만 push합니다. |
| **브랜치** | 체크아웃된 commit에 브랜치를 만듭니다. |
| **Tag** | 체크아웃된 commit에 tag를 만듭니다. |
| **Stash**, **Pop** | 모든 변경 사항을 stash합니다. 가장 최근 stash를 pop합니다. |
| **LFS** `▾` | Git LFS 동작: fetch, checkout, pull, push, prune(`Ctrl+G l`). Git LFS가 꺼져 있으면 숨겨집니다. [Git LFS](lfs.md)를 참고하세요. |
| **Flow** `▾` | 브랜치 워크플로 메뉴(시작, 완료, 동기화, 승격. `Ctrl+G Shift+W`). 워크플로가 있는 저장소에서만 나타납니다. [브랜치 워크플로](branching-workflows.md)를 참고하세요. |
| **검색** | Log 위에 commit 검색 막대를 엽니다(`f`). |

끝(줄에서는 오른쪽, 열에서는 아래)에는 저장소가 호스트에 연결되어 있을 때 체크아웃된 브랜치의 pull request를 보여 주는 **칩**(예: `GH #12` 또는 `GL !53`) 또는 흐린 `+ PR`이 나타납니다. **설정 > 모양 > pull request 버튼을 끝에 고정**(기본값 켜짐)이 칩을 끝에 고정하며, 끄면 다른 버튼과 함께 배치되고 같은 정렬을 따릅니다. [호스팅 및 이슈 트래커 연동](hosting-integration.md)을 참고하세요. 열에서는 프로필 콤보박스가 마지막 줄을 차지합니다.

[프로필](settings.md#프로필)이 둘 이상이면 오른쪽 끝의 **프로필 콤보박스**가 이
저장소의 commit 신원을 고릅니다. 첫 번째 행인 *기본값*은 **설정 > 프로필**을
따릅니다. 프로필을 고르면 GitPoulpi가 그 이름과 이메일을 저장소의 git 설정
(`user.name`, `user.email`)에도 기록할지 묻습니다. **git 설정에 기록**을 누르면
기록합니다. `Esc`는 선택을 GitPoulpi에만 유지합니다. 팔레트:
`저장소: 프로필 변경...`.

모든 버튼에는 팔레트 명령과 단축키가 있습니다.

## 배너

Log 위의 띠는 저장소가 특별한 상태일 때 알려 줍니다. 앞으로 나아갈 방법을 위한
버튼이 있으며, 각 버튼은 팔레트 명령이기도 합니다.

| 배너 | 버튼 |
|---|---|
| merge, cherry-pick, revert가 충돌로 멈춤 | **충돌 해결...**, **Merge Commit** 또는 **계속**, **중단** |
| rebase 진행 중 | **충돌 해결...**, **계속**, **건너뛰기**, **중단** |
| **패치 적용 중(git am)** | **충돌 해결...**, **계속**, **건너뛰기**, **중단** |
| 남아 있는 `index.lock`이 모든 변경을 막음 | **index.lock 삭제**(먼저 확인함) |
| 자동 stash가 복원되지 않음 | **Pop now**, **stash 보기**, **처음부터 다시**, **Drop**(상태에 따라 선택지가 다름) |

[merge 충돌 해결](merge-conflicts.md)과 [문제 해결과 FAQ](troubleshooting.md)을
참고하세요.

## Refs 사이드바 (왼쪽)

commit을 가리키는 모든 이름의 트리입니다. 각 섹션의 제목에는 개수가 있고, 접기용
쉐브론과 자체 스크롤 위치가 있습니다. 두 섹션 사이의 경계를 드래그하면 크기를
바꿀 수 있습니다.

- 맨 위의 **필터** 상자(`/`): 모든 섹션을 이름으로 필터링합니다.
- **로컬**: 내 브랜치이며 `/`로 나뉜 폴더(`feature/`, `fix/`)에 들어 있습니다.
  체크 표시가 체크아웃된 브랜치를 나타냅니다. 폴더는 설정에서 끌 수 있습니다.
- **리모트**: 각 리모트와 그 아래의 브랜치.
- **워크트리**: 연결된 워크트리(있는 경우, 또는 섹션을 표시하도록 한 경우). 머리글의 **+**로 만들고, 워크트리를 더블 클릭하면 자체 탭에서 열리며, 오른쪽 클릭하면 열기 위치, merge, 제거가 나옵니다. [워크트리](worktrees.md)를 참고하세요.
- **STASHES**: 내 stash. 오른쪽 클릭하면 **Pop**, **Apply**, **Drop**이 나옵니다.
- **TAGS**: 내 tag. 브랜치처럼 `/`로 나뉜 폴더(`releases/`, `backups/`)로 묶입니다. 화살표는 그 tag가 리모트에도 있다는 뜻입니다.
- **PULL REQUESTS**와 **이슈**: 호스팅 계정을 연결하고 저장소를 연결한 뒤에
  나타납니다.
- **서브모듈**: 서브모듈과 그 상태(있는 경우). [서브모듈](submodules.md)을
  참고하세요.

**섹션 표시 또는 숨기기:** 섹션 머리글이나 패널의 빈 부분을 오른쪽 클릭하면 섹션 체크리스트가 열립니다(마지막으로 보이는 섹션은 남습니다). 선택은 저장소별로, 다시 시작해도 유지됩니다. [왼쪽 패널 섹션](mouse-and-gestures.md#왼쪽-창-섹션)을 참고하세요.

행에 마우스를 올리면 버튼이 나타납니다. Log에서 그 ref를 숨기거나 표시하는 버튼과
**솔로**(그 ref의 commit만 표시)입니다. 로컬 브랜치나 tag를 더블 클릭하면 체크아웃합니다.
행을 오른쪽 클릭하면 메뉴가 나옵니다. 사이드바 제목의 `‹`는 사이드바를
접습니다(`Ctrl+N h`).

두 측면 창(Refs 사이드바 `Ctrl+N h`와 오른쪽 창 `Ctrl+N l`)은 Log에 속합니다.
diff, 파일 보기 또는 편집기가 열려 있는 동안 둘 중 하나를 표시하거나 접으면 그
보기에만 적용됩니다. diff나 파일 보기는 내용을 넓게 보여 주기 위해 Refs 사이드바도
저절로 접습니다. Log로 돌아오면 두 창 모두 Log에서 두었던 상태 그대로이며, 다음
실행을 위해 저장되는 것도 그 상태입니다.

## Log (가운데)

![Log: 열 머리글 줄, 맨 위의 작업 변경 행, stash 행, 그래프 왼쪽의 ref 필](../images/log-graph.png)

commit마다 한 행이며 최신 commit이 맨 위에 옵니다. 머리글을 오른쪽 클릭하면 열을
표시하거나 숨길 수 있습니다. 두 머리글 사이의 경계를 드래그하면 열 너비가 바뀝니다.
머리글을 드래그하면 열이 이동합니다. 너비는 저장소에 속합니다: 저장소와 함께 저장되어 다시 열면 돌아오며, 처음 여는 저장소는 모든 열이 Log가 보여 주는
내용에 맞춰집니다(**모든 열을 내용에 맞추기**를 누르면 다시 맞추고, **열 너비 초기화**는 자동 너비로 되돌리며 그 상태가 유지됩니다).

이 패널에는 제목이 없으며, 열 머리글이 무엇인지 알려 줍니다. ref가 없는 commit은 마우스를 올린 행에 소속 브랜치의 이름이 흐린 알약 모양으로 나타납니다. 그 브랜치가 삭제되었다면, 그것을 병합한 merge commit에서 읽은 이름이 취소선 알약으로 나타납니다. tag는 있는 자리에 그려지며 가상 표시는 절대 되지 않습니다(설정 > 로그 및 그래프의 **마우스를 올린 commit에 가상 브랜치 표시**로 끌 수 있습니다).

| 열 | 표시 내용 |
|---|---|
| **Ref** | commit에 있는 브랜치와 tag의 색 필: 로컬은 노트북 아이콘, 리모트는 지구본, tag는 tag 아이콘, 더 많은 ref가 가리키면 `+N`. |
| **그래프** | 브랜치 레인, merge, 브랜치 분기점. kitty, Ghostty, WezTerm, Rio, iTerm2, sixel을 쓰는 Windows Terminal, foot, Tabby에서는 그림으로, 다른 터미널에서는 문자로 그려집니다. 레인 색은 테마 또는 직접 고른 팔레트에서 옵니다([테마](themes.md) 참고). 가장 좁은 너비(commit 점 하나)에서는 열이 간결해집니다. 모든 commit이 한 레인에 놓이고 브랜치 선도 merge 선도 없습니다. |
| **메시지** | commit 요약. |
| **작성자** | 작성자와 선택 사항인 아바타. |
| **날짜** | 선택한 형식의 작성 날짜. |
| **변경** | 선택 사항: 변경된 파일과 `+추가 -삭제` 줄 수. |
| **SHA** | 짧은 해시. |

![Log 머리글의 열 메뉴: Ref, 그래프, 메시지, 작성자, 날짜, 변경, SHA 체크박스](../images/log-columns-menu.png)

특별한 행:

- 맨 위의 **작업 변경 행**(WIP 행): 점선 원, `// WIP` 또는 초안 메시지, 수정 및
  추가된 파일 수. 클릭하면 오른쪽 창에서 스테이징하고 commit할 수 있습니다.
- **stash 행**: 레인 위의 작은 사각형이며, stash를 만든 commit 옆에 있습니다.
- 검색하는 동안 일치하지 않는 행은 흐리게 표시됩니다.

셀에 마우스를 올리면 전체 텍스트가 툴팁으로 나옵니다. 행을 오른쪽 클릭하면
[commit 메뉴](log-and-history.md#commit-메뉴)가 나옵니다.

![commit의 오른쪽 클릭 메뉴: cherry-pick, revert, reset, 메시지 편집, 설명, rebase, 브랜치, tag, checkout, 워크트리, 패치, 복사 동작](../images/context-menu.png)

## 오른쪽 창

오른쪽 창은 Log에서 선택한 항목을 따라갑니다.

**작업 변경**(WIP 행이 선택됨):

- `main의 파일 변경 4개` 같은 제목. 충돌이 있는 merge 중에는 충돌한 파일 수가
  덧붙습니다. 왼쪽의 빨간 `✗`는 모든 변경 사항을 버립니다(먼저 확인함). AI가
  켜져 있으면 오른쪽의 `✦`가 변경 사항을 설명합니다.
- **경로** 또는 **트리**(평면 목록 또는 폴더, `m`), **모두 접기**, **모든 파일
  보기**(`a`).
- **스테이징 안 된 파일**과 **스테이징된 파일**. 각각 개수와 **모두 스테이징** 또는
  **모두 스테이징 해제** 버튼이 있습니다. 행에 마우스를 올리면 **파일 스테이징**
  또는 **파일 스테이징 해제** 버튼이 나타납니다.
- 맨 아래의 **commit 양식**: **이전 commit 수정 (Amend)**, **AI로 commit 구성**(AI가
  켜져 있을 때), 글자 수 카운터와 `✦` 버튼이 있는 **요약**, **설명**,
  **변경 파일 N개 Commit** 버튼.

**Commit 상세**(commit이 선택됨), 위에서 아래로: 전체 해시, 아바타와 날짜가 있는
작성자, 부모 해시와 변경 수, 그다음 메시지(요약과 설명. 아래 테두리를 드래그해 크기
조절). 그 아래의 **변경된 파일** 창은 자체 컨트롤로 시작합니다. 정렬 전환, **경로** /
**트리**, **모든 파일 보기**, **파일 필터** 상자가 목록 위에 고정되어 있고, 스크롤되는
것은 목록뿐입니다. 파일을 클릭하면 diff가 열립니다. 창이 낮으면 메시지가 먼저(한
줄까지) 줄어들고, 그다음 목록이 줄어듭니다. 작업 변경 보기에서는 **경로** / **트리** /
**모든 파일 보기** 줄이 파일 목록 맨 위, 스테이징 안 된 파일과 스테이징된 파일 목록
위에 그대로 있습니다.

**메시지 속 링크.** 메시지에 적힌 웹 주소(`https://...` 또는 마크다운 `[텍스트](https://...)`의 대상)에는 밑줄이 그어지고 손 모양 포인터가 표시되며, 클릭하면 아무것도 열리기 전에 주소 전체와 함께 **이 링크를 여시겠습니까?**라고 묻습니다. 메시지 텍스트는 신뢰할 수 없기 때문입니다. **열기**(`O`)는 브라우저를 실행하고, **취소**(`C`, `Esc`, 닫기 표시)는 아무것도 하지 않습니다. `http`와 `https` 주소만 제시됩니다. 키보드 대응은 팔레트 명령 `commit 상세: 메시지의 링크 열기...`로, 메시지의 첫 번째 주소를 묻고 **다음**(`N`)으로 나머지를 차례로 보여 줍니다. 일부 터미널은 포인터 아래의 주소에 자체 밑줄을 그리고 수정 키를 누른 클릭(대개 Shift+클릭)으로 직접 엽니다. 이는 GitPoulpi가 아니라 터미널의 기능입니다.

모든 파일 목록에는 파일, 폴더, 빈 부분의 메뉴가 있고 여러 파일을 한 번에 선택할 수 있습니다(**Ctrl+클릭**, **Shift+클릭**). [스테이징과 commit](staging-and-committing.md)을 참고하세요.

## Commit 열

commit의 파일이 diff, 파일 보기 또는 Blame으로 열려 있을 때, 그 왼쪽에 열 하나를 둘 수 있습니다(작업 사본을 편집하는 내장 편집기 옆에는 두지 않습니다. 편집기가 열리면 열은 사라지고, 편집기를 닫아 diff로 돌아오면 다시 나타납니다). 열은 세 가지 상태를 가집니다.

- **파일**: 그 한 파일의 commit을 두 줄씩 나열합니다([파일 기록](log-and-history.md#파일-기록)). 오른쪽에는 선택한 commit 시점의 파일이 나옵니다.
- **전체**: 로그의 commit을 그래프와 함께 간결하게 나열한 목록이며, 아래에서 설명합니다.
- **숨김**: 보기 왼쪽의 얇은 `›` 띠를 누르면 열이 다시 나타납니다(띠의 툴팁에 키가 표시됩니다).

보기의 버튼 막대는 항상 열 위로 전체 너비에 걸쳐 있으므로, 열이 열리거나 닫히거나 목록이 바뀌어도 버튼은 움직이지 않습니다. 막대의 **`파일 │ 전체`** 선택기(한 컨트롤의 두 부분이며 너비는 항상 같습니다)가 목록을 고릅니다. 한 부분을 클릭하면 그 목록이 표시되고, 열이 숨겨져 있었다면 열립니다. 열이 표시된 상태에서 이미 선택된 부분을 클릭하면 열이 숨겨집니다. 화면에 있는 목록의 부분이 밝게 표시되고, 열이 숨겨져 있는 동안에는 다시 열릴 때의 목록에 밑줄이 그어지며 목록은 그대로 유지됩니다. 선택기의 툴팁에 클릭, 선택된 부분 다시 클릭, `Alt+C`가 나옵니다. 파일 기록은 예전부터 열던 곳(파일 메뉴, 팔레트의 `파일 기록: ...`)에서도 열립니다.

![전체 상태의 commit 열이 commit의 파일 diff 옆에 있고, 머리글은 Ref, 그래프, 메시지, 작성자, 날짜이며 Ref 부분에 브랜치와 tag 레이블이 표시됨](../images/commit-column-all.png)

- **표시 또는 숨기기**: `Alt+C`(팔레트의 `보기: Commit 열 전환`), 선택기에서 선택된 부분 클릭, 열의 ✕, 또는 `›` 띠. 팔레트의 `보기: Commit 열: 숨기기`, `... : 파일 기록`, `... : 모든 Commits`가 상태를 고릅니다. 선택은 그때의 목록과 함께 열의 다른 설정과 같이 기억됩니다. 선택이 없으면 전체 목록은 터미널 너비가 정하며, 140열 이상에서 표시됩니다. 옆의 보기가 30열 미만으로 남게 되면 열은 그려지지 않고, 작업 트리의 diff나 비교에서는 전체 목록의 그래프가 그려지지 않습니다(파일 기록은 commit이 필요 없으므로 표시됩니다).
- **너비**: 오른쪽 테두리를 드래그하거나(밝아진 테두리가 포인터를 따라갑니다) `보기: Commit 열 넓히기`와 `보기: Commit 열 좁히기`를 사용합니다. 가운데 열의 70%까지 차지할 수 있습니다(나머지는 보기의 몫이며, 보기는 30열 미만으로 줄어들지 않습니다). 다른 크기와 함께 기억됩니다.
- **commit 고르기**: 클릭하거나, 열에 키보드를 넘기고(`Ctrl+N` 다음 열의 배지, 또는 `보기: Commit 열에 포커스`) `위` / `아래`, `PageUp` / `PageDown`, `Home` / `End`를 씁니다. `Enter` 또는 `오른쪽`은 그 commit의 파일 목록으로 넘어가고, `Esc`는 키보드를 보기에 돌려줍니다. 오른쪽 창은 선택을 따라가며 commit 상세와 변경된 파일을 보여주므로, 그 commit의 다른 파일도 열 수 있습니다.
- **보기의 동작**: 열려 있는 파일은 그대로 열려 있습니다. 고른 commit이 파일을 변경했다면 그 commit에서의 diff를 보여줍니다. 변경하지 않았다면 그 시점의 파일을 제목에 "이 commit에서 변경 없음"과 함께 보여줍니다. 그 commit에 그 파일이 없으면 보기가 그렇게 알리고 계속 쓸 수 있습니다. Blame은 Blame으로 남으며 고른 commit 시점의 것이 됩니다.

전체 목록은 머리글(로그의 열 이름) 아래에 놓입니다. 한 줄에 commit 하나: 그래프 레인, 제목(메시지), 작성자 이름, 짧은 날짜이고, 켜면 브랜치와 태그 레이블도 나옵니다. 로그 자체의 목록이므로 같은 commit이 같은 순서로 나오고, 스크롤하면 오래된 것을 더 불러옵니다. 레인은 로그의 그래프 열과 같은 방식으로 그려집니다. 그림을 표시하는 터미널([터미널 고르기](terminals.md) 참고)에서는 둥근 마커로 이어진 레인으로, 아바타 설정이 그래프이면 원 안에 작성자의 사진까지 그려지고, 그 밖의 터미널에서는 문자로 그려집니다. 기본적으로 레인은 필요한 만큼 공간을 차지하고 제목에는 항상 몇 단어가 남습니다. 열이 좁으면 레인이 잘리기 전에 작성자가 먼저, 그다음 날짜가 사라집니다. 가장 좁은 너비인 commit 점 하나까지 줄이면 그래프 부분은 로그처럼 간결해집니다. 모든 commit이 한 레인에 놓이고 브랜치 선도 merge 선도 없습니다. 창에 잘린 부분(옆으로 스크롤된 행, 또는 공간보다 넓은 그래프 부분)은 그림과 아바타를 유지하며 가장자리에서 잘립니다. 휠은 포인터 아래의 목록을 스크롤합니다.

- **마우스 올리기와 메뉴**: 행에 포인터를 올려 두면 포인터 아래 부분에 대한 로그의 툴팁이 나옵니다(제목에는 메시지 전체, 작성자에는 이름과 이메일, 날짜에는 전체 날짜). 행을 오른쪽 클릭하면(열에 키보드가 있을 때는 메뉴 키나 `Shift+F10`, 팔레트에서는 `보기: Commit 열: 선택한 행의 메뉴`) 그 행의 메뉴가 열립니다. *Log에서 보기*, 그 commit에서의 파일 diff, 그 commit 시점의 파일, 그 commit에서의 파일 Blame, 그다음 그 commit에 대한 로그 자체의 메뉴(복사, cherry-pick, 브랜치, 그리고 구분선 아래에 revert처럼 무언가를 다시 쓰는 행)가 나옵니다. 앞의 네 행에는 팔레트 항목도 있습니다(`보기: Commit 열: ... 보기` 등). 파일 목록에서는 행에 파일 기록 자체의 메뉴와 같은 툴팁이 있습니다.
- **부분 크기 조절과 옆으로 스크롤**: 머리글의 경계를 드래그하면 그 왼쪽 부분(레인, 메시지, 작성자, 날짜, Ref, 변경, SHA)의 크기가 바뀝니다. 마지막 부분에도 경계가 있습니다. 바로 뒤의 칸(행이 공간을 가득 채우면 열 자체의 테두리)이며, 같은 방식으로 밝아지고 그 마지막 부분의 크기를 정합니다. 로그(`ui.column_resize`)와 마찬가지로 경계는 기본적으로 두 부분 사이의 구분 칸이며, 그래프의 행 색조가 끝나는 곳입니다(색조가 그 칸을 지나므로 그 칸과 다음 부분 사이에 평범한 칸은 없습니다). 머리글에서는 그 칸에 눈금이 놓이고, 포인터가 올라가 있거나 드래그하는 동안 열을 따라 가는 선이 그려지며, 선의 어느 지점에서든 드래그하면 크기가 바뀝니다. `header`에서는 다음 이름의 첫 글자이며 포인터가 올라가 있는 동안 밝아집니다(선은 그려지지 않고, 머리글만 드래그를 시작할 수 있는 곳입니다). 아무것도 크기를 정하지 않으면 메시지가 나머지 공간을 차지합니다. 첫 드래그는 메시지를 포함한 모든 부분을 현재 너비로 고정하므로, 한 부분의 크기를 바꾸면 그 뒤의 부분들이 움직이고 다른 너비는 바뀌지 않습니다. 크기를 정한 부분은 공간이 모자라도 줄어들지 않고 유지됩니다. 그래서 행이 열보다 넓어지면 Shift+휠, 가로 휠, 또는 열에 키보드가 있을 때 `Shift+Left` / `Shift+Right`로 옆으로 스크롤되며, 아래 테두리의 스크롤바가 위치를 보여 줍니다. 키보드에서는 `Tab`이 (표시된 부분 중에서) 부분을 고르고, `]`가 넓히고, `[`가 좁히며, `0`이 모든 부분을 자동으로 되돌립니다(팔레트에는 `보기: Commit 열: 다음 부분 선택`, `... 부분 넓히기`, `... 부분 좁히기`, `... 부분 너비 초기화`, `... 왼쪽으로 스크롤`, `... 오른쪽으로 스크롤`이 있습니다). 너비는 기억됩니다. 스크롤로 레인이 잘린 동안에는 그림을 표시하는 터미널에서도 레인이 문자로 그려집니다.
- **표시할 부분 고르기**: 머리글을 오른쪽 클릭하면 부분마다 체크 박스가 있는 메뉴가 열립니다. 로그가 제공하는 모든 열, 즉 Ref, 그래프, 메시지, 작성자, 날짜, 변경, SHA입니다. 메시지는 항상 표시됩니다. **Ref**, **변경**, **SHA**는 기본값이 꺼짐이며, 켜면 Ref는 그 commit의 브랜치와 태그 레이블을, 변경은 파일 수와 `+추가 -삭제` 줄 수를, SHA는 짧은 해시를 보여 주며 모두 로그 자체의 열과 같습니다. Ref처럼 변경과 SHA도 공간이 모자라도 줄어들지 않고, 대신 행이 옆으로 스크롤됩니다. 키보드에서는 `보기: Commit 열: 표시할 열 선택`이 같은 메뉴를 열고(화살표와 `Enter`로 행을 고릅니다) `보기: Commit 열: Ref 열 표시 전환`, `... 그래프 열 표시 전환`, `... 작성자 열 표시 전환`, `... 날짜 열 표시 전환`, `... 변경 열 표시 전환`, `... SHA 열 표시 전환`이 부분을 바로 켜고 끕니다. 표시할 부분, 그 순서와 너비는 이 열에만 속합니다. `config.toml`에 저장되며(`ui.commit_column_columns_visible`, `ui.commit_column_columns_order`, `ui.commit_column_columns_widths`), 로그 자체의 열은 이에 따라 바뀌지 않고, 그 반대도 마찬가지입니다.
- **부분 옮기기**: 머리글의 이름을 다른 이름 위로 드래그하면 그 부분이 그 자리로 옮겨집니다. 로그와 같습니다(행이 포인터를 따라가며, `ui.column_resize = "header"`에서는 이름의 첫 글자가 크기 조절 경계이므로 이름의 나머지 부분을 누르세요). 레인과 Ref 레이블을 포함해 어떤 부분이든 어디로든 갈 수 있습니다. 키보드에서는 `Tab`이 부분을 고르고 `<` / `>`가 표시된 부분 사이에서 한 칸 왼쪽이나 오른쪽으로 옮깁니다(팔레트에는 `보기: Commit 열: 부분을 왼쪽으로 이동`과 `... 부분을 오른쪽으로 이동`이 있습니다). 순서는 기억됩니다.

  ![commit 열 머리글의 오른쪽 클릭 메뉴: Ref, 그래프, 메시지(항상 표시), 작성자, 날짜, 변경, SHA 체크 박스](../images/commit-column-menu.png)

마우스 동작은 [마우스와 제스처](mouse-and-gestures.md#commit-열-전체-목록)에도 나와 있습니다.

## 크기는 기억됩니다

GitPoulpi는 드래그해서 바꾼 모든 크기를 탭을 전환하거나 재시작해도 기억합니다.
크기는 모든 저장소에서 같습니다. 대상은 Refs 사이드바, Log, 오른쪽 창 사이의 구분선,
각 Refs 섹션의 높이, commit 메시지 블록, Log 열 너비, merge 편집기 창, 폴더 선택기
구분선입니다. 크기는 창에 대한 비율로 저장되므로, 넓은 터미널에서 만든 레이아웃이
좁은 터미널에도 맞습니다.

모든 크기를 초기화하려면 팔레트 명령 `탐색: 레이아웃 초기화`를 실행하세요. 일부
크기는 별도의 초기화도 있습니다. `탐색: Refs 섹션 크기 초기화`,
`Commit 상세: 메시지 크기 초기화`, 그리고 merge 편집기에서는 구분선 더블 클릭 또는
`Alt+0`입니다.

## 오버레이와 특수 화면

- **명령 팔레트**(`Ctrl+P`): 모든 명령에 대한 필터 상자. 각 행에 단축키가
  표시됩니다. 지금 실행할 수 없는 명령은 회색이며 이유가 맨 아래에 표시됩니다.
  명령에는 `Git:`, `Refs:`, `탐색:`, `Diff:`, `작업 변경:`, `commit:`, `보기:`,
  `저장소:`, `탭:`, `LFS:`, `Pull request:`, `이슈:`, `AI:` 같은 그룹 접두사가
  있습니다. 접두사를 입력하면 해당 그룹이 나타납니다.
- **선택기**: 일부 팔레트 명령은 두 번째 목록을 엽니다. 예를 들어
  `앱: 테마 변경...`, `앱: 언어 변경...`, `앱: 그래프 색상 테마 변경...`입니다.
  목록을 이동하는 동안 창에 각 선택지가 바로 적용되어 보입니다. `Enter`는 선택을
  유지하고 `Esc`는 이전 선택으로 되돌립니다. 테마 목록에는 **전체**, **다크**,
  **라이트**, **컬러** 필터가 있습니다. [테마](themes.md)를 참고하세요.
- **도움말**(`?`): 탭으로 나뉩니다. **키** 탭은 모든 키와 제스처를 나열하고, 나머지
  탭(시작, Log, 변경, Refs, 호스팅, 설정, AI/CLI)은 각 동작과 그 실행 방법을 짧게
  안내합니다. `Tab` / `Shift+Tab`, `Left` / `Right`, `Alt+1`..`Alt+8` 또는 클릭으로
  탭을 바꿉니다. 입력하면 현재 탭이 필터링됩니다. `Ctrl+D` 또는 맨 아래 링크를 클릭하면
  현재 탭에 해당하는 문서 페이지가 열립니다.

  ![도움말의 호스팅 탭: 각 동작과 그 실행 방법을 담은 짧은 안내](../images/help-hosting.png)

  ![도움말 오버레이: Ctrl+P, Ctrl+N, Ctrl+G, ?와 이동 키를 나열한 전역 섹션, 그다음 마우스 기본 섹션](../images/help.png)
- **검색 막대**(`f`): Log의 오른쪽 위. 일치 항목을 `n of N`으로 표시합니다.
- **컨텍스트 메뉴**: 오른쪽 클릭, 또는 선택한 행에서 `.`. `›`가 있는 행은 하위
  메뉴를 엽니다.
- **대화상자**: 확인, 브랜치 또는 tag 이름, 클론, 초기화, Pull request 만들기,
  거부된 push 후의 선택지 등. `Enter`는 수락하고 `Esc`는 취소합니다.
- **대화형 rebase**와 **commit 작성기**는 Log를 검토 화면으로 바꿉니다.
  [Log 다루기](log-and-history.md#대화형-rebase)와
  [스테이징과 commit](staging-and-committing.md#commit-작성기-변경-사항을-여러-commit으로-나누기)을
  참고하세요.

  ![commit 4개 제안을 각 파일과 함께 검토하는 commit 작성기와 초기화, 취소, commits 4개 만들기 버튼](../images/composer.png)

- **설정**(`Ctrl+,` 또는 톱니바퀴): 왼쪽의 페이지 목록과 오른쪽의 해당 페이지
  옵션. [설정](settings.md)을 참고하세요.

  ![설정: 검색 상자가 위에 있는 왼쪽의 페이지 목록과 오른쪽의 일반 페이지](../images/settings.png)

- 긴 답변을 위한 **팝업**. 예를 들어 AI **변경 사항 설명** 팝업이 있습니다(`↑` `↓`
  스크롤, `c` 복사, `Esc` 닫기).

  ![AI 설명과 다시 확인할 항목 목록이 있는 작업 변경 설명 팝업](../images/ai-explain.png)

팝업의 모든 목록은 같은 방식으로 작동합니다. [키보드 단축키](keybindings.md)와
[마우스와 제스처](mouse-and-gestures.md)를 참고하세요.

## 이 문서에서 쓰는 용어

| 용어 | 의미 |
|---|---|
| 창(Pane) | 세 열 중 하나: Refs 사이드바, Log(또는 열린 파일), 오른쪽 창. |
| 필(Pill) | Ref 열의 브랜치 또는 tag 레이블. |
| WIP 행 | Log 맨 위의 작업 변경 행. |
| Hunk | diff에서 변경된 줄의 한 덩어리. |
| 작성기(Composer) | commit 양식, 그리고 변경 사항을 commit으로 나누는 AI 검토. |
| 코드(Chord) | `Ctrl+G` 다음 `s`처럼 키 뒤에 이어지는 키. |
| 접두사(Prefix) | `Ctrl+G`(git 동작) 또는 `Ctrl+N`(탐색). |
| 배지(Badge) | `Ctrl+N`이 컨트롤 옆에 표시하는 글자. 누르면 그 컨트롤로 포커스가 이동합니다. |
