# Radar

Radar는 홈 바로 뒤에 있는 별도의 탭으로, **여러 저장소**에 걸쳐 나를 기다리는 것을 하나의 목록으로 보여 줍니다. 내가 쓴
pull(또는 merge) request, 내 리뷰를 요청한 것, 나에게 할당되었거나 내가 만든 이슈, 그리고
작업 중인 변경을 남겨 둔 저장소입니다. 홈 창 위에 Radar 보기를 얹은 것이므로 아래의 어떤 것도
클릭이나 키를 가로채지 못합니다.

코드 호스트 프로필([호스팅과 이슈 트래커](hosting-integration.md) 참고. 저장소 하나의 목록은 [pull request와 이슈](pull-requests-and-issues.md)에 있고, 행의 토론은 [대화](conversations.md)로 열립니다)과 그 프로필에 연결된 저장소가 필요하며,
또는 계정 전체 목록을 켠 프로필이 필요합니다(아래 "범위 너머: 계정 전체 행" 참고).
연결되지 않은 저장소에는 요청하지 않으며, 대신 **연결...** 줄이 표시됩니다(아래 "할 말이 있는 저장소" 참고).

![두 저장소 위의 Radar: 고정된 요청 하나, 그다음 내 리뷰 대기 중, 내 pull request, 나에게 할당됨, 이슈, 진행 중인 작업](../images/radar.png)

pull 또는 merge request 행의 **리뷰...**(또는 `e`)는 저장소를 열고 그 요청의 앱 내 리뷰를 엽니다
([pull request 리뷰](review.md)).

## 열기

- 어디서든 **`Alt+R`**(다시 할당 가능: `global.radar`).
- 팔레트: `Radar: 열기`.
- 탭 표시줄에서 홈 바로 뒤에 있는 **Radar** 탭.
- 탭이 닫혀 있을 때 **`+`** 메뉴의 **Radar** 행.

저장소 탭에서 열면 Radar가 열린 홈 창으로 이동합니다. `Esc` 또는 **뒤로**는 저장소
목록으로 돌아가며, `⌂`도 같은 일을 합니다.

## 탭 닫기 또는 Radar 끄기

탭은 저장소 탭처럼 닫습니다. 탭의 **x**, 가운데 클릭, 표시 중일 때 `Ctrl+W`, 또는 팔레트의 `Radar: 탭 닫기`입니다.
홈은 닫을 수 없는 유일한 탭입니다. 닫은 탭은 다시 Radar를 열 때까지(`Alt+R`, `Radar: 열기`, 또는 `+` 메뉴) 재시작을
거쳐도 그 세션에서 닫힌 채로 있으며, 다시 열면 홈 바로 뒤에 돌아옵니다. 닫아도 설정은 바뀌지 않습니다.

전혀 쓰지 않는다면 **설정 > 일반 > Radar 사용**(`general.radar_enabled`, [설정 참조](config-reference.md) 참고)에서
끄세요. 끄면 탭, 팔레트 명령, `Alt+R`이 사라지고 GitPoulpi는 Radar를 위해 아무것도 가져오지 않습니다. 재시작 없이
즉시 적용됩니다.
## 대상: 범위

**범위** 콤보박스는 어떤 저장소에 요청할지 고릅니다.

- 이름으로 고른 **워크스페이스**(열린 탭이 없는 저장소도 포함한 그 저장소들),
- **열린 탭**: 이 세션의 탭으로 열려 있는 저장소.
- **기본 클론 폴더**와 **기본 찾아보기 폴더**: [설정](config-reference.md)에 지정한 폴더(`repos.clone_root`, `repos.browse_root`)에서 찾은 모든 저장소. 탭이 열려 있는지는 상관없습니다.

여기서 마지막으로 고른 범위(`radar.toml`에 보관됨)가 아직 있으면 그것으로 열립니다. 처음 고르기 전이거나 그
워크스페이스가 삭제되었으면 세션의 활성 워크스페이스로, 그것도 없으면 열린 탭으로 열립니다. 선택은 이 보기에만
적용되며 창의 활성 워크스페이스를 바꾸지 않습니다. 두 저장소의 폴더 이름이 같으면 구분할 수 있도록 칩에 상위 폴더가 덧붙습니다.

### 폴더 범위 둘

폴더 범위는 저장소를 **두 단계 깊이**까지 찾습니다. 폴더 바로 아래의 폴더와, 그중 저장소가 아닌 폴더 안의
폴더입니다 (`~/src/work/app`). 숨김 폴더는 건너뛰고, 저장소 안으로는 들어가지 않으며, 최대 200개의 저장소를
나열합니다. 검색은 백그라운드에서 실행되고 화면을 그리는 스레드에서는 절대 실행되지 않으며, 결과는 새로 고칠
때까지 유지됩니다. 새로 고침 버튼, `r`, `F5`(창의 새로 고침 키, 다시 지정 가능), `Radar: 새로 고침`이 폴더를 다시 검색합니다 (그 사이에 클론한 저장소가
나타남).

호스팅은 저장소마다 선택하는 것으로 유지됩니다. 폴더 안의 저장소 중 호스트에 **연결되지 않은** 것에는 절대
요청하지 않습니다. 작업 중인 변경 사항 행만 보여 주고, 저장소 아래에 **연결...**이 있는 `연결되지 않음` 줄이
나오며 (그 저장소의 pull request 섹션이 열려 공급자와 프로젝트를 고를 수 있음), 상태 표시줄이 그 개수를 셉니다
(`연결되지 않은 저장소 3개 (작업 중인 변경 사항만)`).

지정하지 않은 폴더는 목록에서 회색입니다 (`기본 찾아보기 폴더 (설정에서 지정)`). 고르면 그 설정 행(설정 > 일반)이
열리고 범위는 그대로 유지됩니다. 클론 폴더는 OS별 기본값(클론 대화상자가 시작하는 폴더)이 있는 한, 그 폴더가
존재하면 지정된 것으로 칩니다. 찾아보기 폴더에는 기본값이 없습니다. 범위 목록은 열 때마다 설정에서 읽으므로
그곳에서 바꾼 내용이 바로 적용됩니다.

## 목록

| 묶음 | 담는 것 |
|---|---|
| 고정됨 | 종류와 관계없이 고정한 모든 것, 고정한 순서대로 |
| 내 리뷰 대기 중 | 내 리뷰를 요청한(내가 쓰지 않은) 요청 |
| 내 pull request | 내가 쓴 요청. 초안이면 칩에 `초안`이라고 표시됩니다 |
| 나에게 할당됨 | 나에게 할당된 요청 |
| 나를 언급함 | 나를 언급하면서 위의 어떤 묶음에도 아직 들어 있지 않은 열린 요청과 이슈(나에게 할당되지도, 내가 만들지도 않은 이슈는 나를 언급할 때만 여기에 표시됩니다) |
| 기타 pull request | 나머지 열린 요청 |
| 나에게 할당된 이슈 | 나에게 할당된 열린 이슈 |
| 내가 만든 이슈 | 내가 만든 열린 이슈 |
| 진행 중인 작업 | 범위 안의 저장소 중 커밋하지 않은 변경이나 push하지 않은 commit이 있는 곳 |
| 미룬 항목 | 잠시 숨긴 항목. 열기 전까지 접혀 있습니다 |
| 저장소 | 할 말이 있는 저장소(오프라인, 갱신할 토큰, 연결되지 않음) |

"pull request"와 "merge request"라는 말은 평소의 용어 설정과 호스트를 따릅니다.

각 행에는 항목의 종류(`⇄` 요청, `●` 이슈, `✎` 진행 중인 작업), 저장소 칩(워크스페이스의
색), 번호, 제목, 작성자, 경과 시간, 그리고 자리가 있으면 레이블이 표시됩니다. 진행 중인
작업 행에는 브랜치와 거기 대기 중인 것이 표시됩니다. `✎` 변경된 파일, `+` 새 파일, `↑`
push할 commit, `↓` pull할 commit입니다.

개수는 각 머리글에 있습니다. 묶음 안에서는 가장 최근에 갱신된 항목이 먼저 옵니다.

호스트가 잠시보다 오래 응답하지 않으면 필터 아래 상태 표시줄에 스피너가 표시됩니다.
캐시된 목록(사이드바가 쓰는 것과 같은 캐시)은 즉시 표시되고 응답이 도착하는 대로
교체됩니다.

### 열

저장소 칩, `#`(번호와 체크 표시), 작성자, 경과 시간은 **크기를 조절할 수 있는 열**입니다. 자동으로 두면 저장소 열은 화면에서 가장 긴 이름만큼 넓어지므로(최대 40칸, 창의 3분의 1 이하), 일반 터미널에서 `owner/name`과 계정 목록의 `group/sub/project`가 잘리지 않습니다. 제목은 나머지를 차지합니다. 들어가지 않는 이름은 줄임표로 끝나며(`group/sub...`), 다음과 같이 할 수 있습니다.

- 잘린 저장소, 제목, 작성자 또는 레이블 목록에 **포인터를 올려 두면** 툴팁이 전체 텍스트를 보여 줍니다. 행을 선택하면 필터 아래 상태 표시줄도 전체 프로젝트와 제목을 알려 주므로 키보드로도 같은 것을 볼 수 있습니다.
- **구분선을 끌어**(저장소 이름 바로 뒤, `#` 뒤, 또는 작성자나 경과 시간 바로 앞의 칸) 열 크기를 조절하고, **더블 클릭**하면 열을 다시 맞춥니다. 목록에는 **머리글 행**(저장소, `#`, 제목, 작성자, 경과)이 있고 구분선은 Log처럼 `ui.column_resize`를 따릅니다. `line`(기본값)에서는 머리글 행의 구분 칸에 흐린 `│`가 놓이고, 포인터가 구분선 위(머리글 또는 목록의 어느 행이든)에 있거나, 키로 열을 골랐거나, 드래그하는 동안 목록 전체에 걸쳐 가는 강조선이 그려지며, 그 선의 어느 지점에서든 드래그하면 크기가 바뀝니다. 놓으면 선은 사라집니다. 포인터가 아직 구분선 위에 있으면 포인터와 함께 사라집니다. 마우스 드래그는 열을 고른 상태로 남기지 않습니다. `header`에서는 눈금도 선도 없고, 구분선 뒤 머리글 행의 첫 셀이 밝아지며 그곳이 유일하게 드래그를 시작할 수 있는 곳입니다. 지원하는 터미널에서는 구분선 위에서 포인터가 크기 조절 포인터로 바뀝니다. 상태 칩은 너비가 고정이고 경과 시간도 그렇습니다(크기를 정하기 전에는 표시되는 가장 넓은 경과 시간. 좁은 열에서 잘린 경과 시간은 툴팁에 전체 날짜를 보여 줍니다). 그래서 작성자는 모든 행에서 같은 칸에서 시작합니다.
- 또는 키를 씁니다. **`C`**는 열을 고르고(다시 누르거나 `Tab`이면 다음 열), **`]`**는 두 칸 넓히고, **`[`**는 좁히고, **`0`**은 모든 열을 자동으로 되돌리며, `Esc`로 나갑니다. 팔레트에도 같은 것이 있습니다. `Radar: 열 선택`, `Radar: 열 넓히기`, `Radar: 열 좁히기`, `Radar: 열 너비 초기화`.

너비는 `radar.toml`(`[columns]`, `repo`, `number`, `author`, `age`, 칸 단위)에 보관되며 재시작 후에도 유지됩니다. Log 열과 같은 크기 조절 동작입니다.

### 검사와 충돌

호스트가 무언가를 알려 주면 요청 행의 번호 뒤에 작은 표시가 최대 두 개 붙습니다:

| 표시 | 의미 |
|---|---|
| `✓` | head 커밋의 검사가 통과했습니다 |
| `✗` | 검사가 실패했습니다 |
| `●` | 검사가 대기 중이거나 실행 중입니다 |
| `!` (옆에) | 요청이 대상 브랜치와 충돌합니다 |

표시 위에 포인터를 올리면 툴팁이 말로 알려 줍니다("검사 실패", "main과(와) 충돌"). 행을 선택하면 필터 아래의 상태 표시줄이
같은 내용을 알려 주므로 키보드로도 볼 수 있습니다. 표시가 없는 요청은 호스트가 아무 말도 하지 않은 것입니다(CI가 구성되지 않았거나 요청하지 않음).

- **GitLab**은 merge request 목록과 함께 파이프라인 상태와 충돌 플래그를 보내므로 모든 행에 표시가 있습니다.
- **GitHub**는 그렇지 않아 목록에 둘 다 없습니다. GitPoulpi는 요청마다 따로 물어봅니다(병합 상태는 요청 자체에, head 커밋의 통합 상태와 검사 실행은
  각각: 호출 세 번). 저장소당 최대 **열린 요청 15개**이며 내 것이 먼저입니다. 그 호출 중 하나를 GitHub가 거부하면(속도 제한) 나머지는 다음 새로 고침까지
  표시 없이 남습니다. 응답은 호스팅 캐시와 함께 저장됩니다.

- **Gitea와 Forgejo**는 GitHub처럼 읽습니다: 목록에 충돌 플래그(`mergeable`)가 담겨 있고, 커밋 상태는 요청별로
  요청하며(저장소당 최대 15개, 내 것이 먼저), 이슈는 같은 묶음입니다. 언급은 서버의 검색(`mentioned_by`)을 씁니다.

### 언급

**나를 언급함**과 **표시: 나를 언급함** 필터는 호스트가 언급에 대해 아는 것을 사용합니다. GitHub는 검색(`mentions:`)으로, GitLab은 내 할 일 목록으로
묻습니다: 거기서 아직 **대기 중**인 언급만 세므로, 완료로 표시한 할 일은 묶음에서 빠집니다.

닫히거나 병합된 요청과 닫힌 이슈는 나열되지 않습니다.

## 보기와 필터

콤보박스 세 개와 텍스트 필드 하나가 목록을 좁힙니다. 모든 선택은 드롭다운이며, 클릭하거나
그 키를 사용합니다.

- **보기**(`v`): 전체, 요청, 이슈, WIP(진행 중인 작업), 미룬 항목.
- **표시**(`f`): 모두, 내 것(내가 쓴 요청, 내가 만든 이슈), 나에게 할당됨, 리뷰 요청됨, 나를 언급함.
- **범위**(`w`): 위를 참고하세요.
- **필터 텍스트**(`/` 또는 `Ctrl+F`): 저장소, 번호, 제목, 작성자, 브랜치, 레이블을 퍼지
  일치로 찾습니다. `Enter`는 키를 목록에 돌려주고 텍스트는 유지하며, `Esc`는 텍스트를
  지웁니다.

`Ctrl+N`을 누르면 필터, 각 콤보박스, **새로 고침**과 **뒤로** 버튼, 화면의 각 섹션 제목에 배지가 표시됩니다. 배지의 문자를 누르면 필터가 키보드를 받고, 콤보박스가 열리고, 버튼이 실행되고, 제목이 선택됩니다(이어서 `Enter`나 `Space`를 누르면 접힙니다). `Esc`는 취소합니다. [배지](keybindings.md#배지)를 참고하세요.

## 동작

행을 선택하고 그 메뉴(오른쪽 클릭, 행 끝의 `⋮`, `.` 또는 `Menu`), 키, 또는 팔레트
(`Radar: ...`)를 사용합니다. 마우스 동작에는 항상 키와 팔레트의 짝이 있습니다.

| 동작 | 키 | 팔레트 |
|---|---|---|
| 저장소 열기(그 탭이 열리거나 전환됩니다) | `Enter` / 더블 클릭 | `Radar: 저장소 열기` |
| 리뷰...(요청. 클론되지 않은 요청은 방법을 묻습니다) | `e` | `Radar: 요청 리뷰...` |
| 호스트 API로 요청 리뷰(클론 없이) | 질문에서 `a` | `Radar: API로 리뷰` |
| 저장소를 클론한 뒤 요청 리뷰 | 질문에서 `c` | `Radar: 클론 후 리뷰...` |
| 브라우저에서 열기 | `o` | `Radar: 브라우저에서 열기` |
| 브랜치 체크아웃(요청) | `c` | `Radar: 브랜치 체크아웃` |
| worktree 만들기...(요청) | `t` | `Radar: worktree 만들기...` |
| 저장소에서 표시(그 목록) | `s` | `Radar: 저장소에서 표시` |
| 이슈 작업 시작...(이슈) | `n` | `Radar: 이슈 작업 시작...` |
| 맨 위에 고정, 또는 고정 해제 | `p` / `★` 클릭 | `Radar: 고정 또는 해제` |
| 담당자... / 리뷰어... / 레이블... 편집, 마일스톤 설정...(GitHub, GitLab) | 행 메뉴 | `Radar: 담당자 편집...`, `Radar: 리뷰어 편집...`, `Radar: 레이블 편집...`, `Radar: 마일스톤 설정...` |
| 미루기... | `z` | `Radar: 미루기...` |
| 미루기 해제 | `u` | |
| 클론하지 않은 저장소의 요청 표시 또는 숨김 | `a` | `Radar: 클론하지 않은 요청 표시` |
| 계정 전체 행의 초안 표시 또는 숨김 | `d` | `Radar: 초안 표시` |
| 호스트의 계정 전체 리뷰 요청 켜기 | `T` / 안내 줄에서 `Enter` / **켜기** | `Radar: 계정 전체 리뷰 요청 켜기...` |
| 새로 고침 | `r`, `F5` | `Radar: 새로 고침` |
| 행 메뉴 | `.` | `Radar: 행 메뉴...` |
| 홈으로 돌아가기 | `Esc` | `Radar: 홈으로 돌아가기` |

저장소 자체의 창이 필요한 동작(체크아웃, worktree, 표시, 작업 시작, 연결, 메타데이터 선택기)은 먼저 그
탭으로 전환하고, 불러오기가 끝나면 거기서 실행합니다.

- **체크아웃**은 사이드바 자체의 체크아웃을 사용합니다. 브랜치가 로컬에 있으면 그
  브랜치를, 그렇지 않으면(예: fork의 요청) 요청의 head를 로컬 브랜치로 fetch합니다.
- **worktree 만들기...**는 요청의 브랜치에 대해 worktree 만들기 대화상자를 엽니다.
- **저장소에서 표시**는 PULL REQUESTS 또는 ISSUES 목록에서 그 항목을 선택합니다.
- **이슈 작업 시작**은 이슈로 만든 이름(`12-fix-the-thing`)으로 새 브랜치 프롬프트를
  엽니다.

### 고정과 미루기

**고정**은 항목을 맨 위에 둡니다. **미루기**는 항목을 **1시간**, **4시간**, **내일까지**(내일 아침 08:00, 현지 시간 기준이며 지금이 아직 08:00 전이어도 마찬가지)
또는 **변경될 때까지**(호스트가 항목의 갱신을 알리거나, 진행 중인 작업 행이면 그 카운터가
움직일 때까지) 숨깁니다. 둘 다 설정 폴더의 `radar.toml`에 호스트, 저장소, 종류,
번호를 키로 하여 보관되며 이 컴퓨터의 모든 세션이 공유합니다.

### 할 말이 있는 저장소

문제가 있는 저장소는 목록 끝에 자기 줄이 생기고, 캐시된 항목은 화면에 그대로 남습니다.

- **오프라인, 5m 전 데이터**: 호스트에 연결할 수 없었습니다.
- **다시 연결**: 토큰이 없거나 거부되었습니다. 이 버튼은 설정 > 연동을 엽니다.
- **이번 주기에는 일시 중지됨**: 호스트가 속도를 늦추라고 했으므로(또는 토큰을 거부했으므로)
  GitPoulpi는 이번 주기에 다른 저장소에 대해서도 다시 요청하지 않았습니다.
- **연결되지 않음, GitHub 제안됨**: 저장소의 리모트가 프로필과 일치하지만 호스팅은 저장소별로
  직접 켜는 방식이므로, 연결하기 전에는 아무것도 요청하지 않습니다. **연결...**을 누르면 그
  저장소의 PULL REQUESTS 섹션으로 이동하며, 거기서 제공자와 프로젝트를 고릅니다.

동시에 요청하는 저장소는 최대 네 개이며, 화면을 그리는 스레드에서는 절대 요청하지 않습니다.

## 범위 너머: 계정 전체 행

범위는 내가 클론한 저장소를 다룹니다. 한 번도 클론하지 않은 저장소에서 내 리뷰를 기다리는 요청은 거기서 보이지 않습니다. **계정 전체 행**은 프로필마다 한 번 호스트에 직접 묻고, 범위와 관계없이 목록에 합쳐집니다. 폴더가 아니라 나에 대한 것이기 때문입니다.

이 행은 **기본값이 꺼짐**입니다(호스트의 검색은 API 할당량을 소모합니다). 연결된 코드 호스트에서 어떤 목록도 켜져 있지 않으면 목록 맨 위에 그 호스트의 줄이 표시됩니다.

`GitHub: 클론하지 않은 저장소를 포함해, 내 리뷰를 기다리는 요청 나열  [켜기]`

**켜기**를 클릭하거나, 그 줄에서 `Enter`를 누르거나, `T`를 누르거나, `Radar: 계정 전체 리뷰 요청 켜기...`를 실행하면 `config.toml`의 해당 프로필에 `integrations.radar.review_requests = true`를 쓰고 곧바로 호스트에 묻습니다. 다른 목록(내 네임스페이스의 열린 요청 전부, 나에게 할당된 이슈, 초안, 네임스페이스)은 `gitpoulpi hosting integrations radar`나 프로필 설정에서 지정합니다. [설정 참조](config-reference.md)와 [CLI 참조](cli-reference.md)를 참고하세요. GitHub, GitLab, Gitea, Forgejo, Azure DevOps, Bitbucket Data Center, Gerrit이 응답하며, Bitbucket Cloud에는 계정 전체 엔드포인트가 없어 그 요청은 범위의 연결된 저장소에서만 표시됩니다.

프로필의 **네임스페이스**는 그 프로필의 모든 목록을 일부 저장소로 제한합니다(설정 > 연동 > Radar: 한 줄에 항목 하나인 텍스트 영역과 **정규 표현식** 체크박스). 한 줄은 저장소의 전체 경로와 같거나 `/`에서 끝나는 경로 접두사이면 일치합니다. `orbit`은 `orbit/products/x`를 유지하고 `orbitx/y`와 `training/y`는 제외합니다. 체크박스를 켜면 각 줄이 전체 경로에 쓴 그대로 적용되는 정규 표현식이 됩니다(`^orbit/(products|infra)/`). 유효하지 않은 줄은 필드 아래에 표시되고 저장되지 않습니다. 비어 있으면 제한 없음입니다.

행이 놓이는 방식:

- 범위가 이미 나열한 행(같은 호스트, 프로젝트, 종류, 번호)은 한 번만 나타납니다: **범위의 행이 우선**합니다.
- 프로젝트를 어딘가에 클론한 행(최근 저장소, 워크스페이스, 폴더 범위가 찾은 폴더. 리모트 URL로 대조)은 그 클론을 가지며, **Enter**, 체크아웃, worktree 등은 다른 행처럼 그 클론을 엽니다.
- 그 밖의 행은 **클론되지 않음**입니다: 저장소 칩이 흐리게 프로젝트(`acme/app`)를 표시하고, 선택하면 상태 표시줄에 `클론 안 됨`이라고 나옵니다. **브라우저에서 열기**는 동작하고, **리뷰**는 리뷰 방법을 묻고(아래), 체크아웃, worktree, 저장소에서 표시, 작업 시작은 `먼저 저장소를 클론하세요`라고 알려 줍니다.

### 요청 리뷰

범위 자체의 저장소에 있는 요청에서 **리뷰**(`e`)는 그 저장소의 탭을 열고 리뷰를 보여 줍니다. 계정 전체 행의 요청에서는 클론을 알고 있는지, 그리고 프로필의 **클론하지 않은 저장소의 요청** 설정(설정 > 연동, [설정 참조](config-reference.md)의 `review_mode`)에 따라 달라집니다.

| 설정 | 클론을 알고 있음 | 클론을 모름 |
|---|---|---|
| 묻기(기본값) | 묻습니다: **로컬 클론 열기**(`l`) 또는 **API로 리뷰**(`a`) | 묻습니다: **클론한 뒤 리뷰**(`c`) 또는 **API로 리뷰**(`a`) |
| 클론하기 | 클론을 엽니다 | 클론 대화상자를 엽니다 |
| API로 리뷰 | API로 리뷰합니다 | API로 리뷰합니다 |

질문은 작은 대화상자입니다. 글자 키로 고르고, **Enter**는 강조된 행을 고르며, `Esc`, **취소**, `✕`, 바깥 클릭으로 닫습니다. **GitHub에 기억하기**(`r`)는 프로필의 설정을 써서 다시 묻지 않게 합니다(설정의 행이 이를 되돌립니다). `Ctrl+N`은 컨트롤에 배지를 표시합니다.

- **API로 리뷰**는 코드를 호스트에서 가져와 홈 창의 Radar 위에 리뷰를 엽니다([클론 없이 리뷰](review.md#클론-없이-리뷰) 참고). `Esc`나 `✕`로 Radar로 돌아가며, 팔레트의 *리뷰: ...* 행이 이 리뷰에서 동작합니다.
- **클론한 뒤 리뷰**는 행이 나온 연결된 계정의 클론 대화상자(같은 저장소 목록, 소유자별로 묶임)를 요청의 저장소를 선택하고 기본 클론 폴더를 채운 채 엽니다. 둘 중 무엇이든 바꾼 뒤 클론하며, 그 계정에서 하는 다른 클론과 같은 로그인을 씁니다. 저장소가 계정 목록에 없으면(구성원이 아님) 목록이 열린 채 이름으로 검색이 되어 있고 메모가 그렇게 알려 주며, 저장소를 나열할 수 없는 호스트라면 대화상자가 주소가 채워진 **URL로 클론**에서 열립니다. 클론이 끝나면 새 저장소가 호스트에 연결되고(PULL REQUESTS 소스, 그리고 호스트에 이슈가 있고 소스가 지정되지 않았다면 ISSUES 소스), 그 탭이 열리며 그 요청의 리뷰가 거기서 열려 있습니다. 대화상자를 취소하거나 클론이 실패하면 아무것도 연결되지 않습니다.
- Azure DevOps와 Bitbucket 요청에는 앱 내 리뷰가 없습니다: **리뷰**는 요청의 페이지를 브라우저에서 열고 상태 표시줄에 그렇게 알립니다.

팔레트의 *Radar: API로 리뷰*와 *Radar: 클론 후 리뷰...* 행은 질문을 건너뜁니다.

필터 옆의 확인란 둘(계정 전체 목록을 요청하는 중일 때 나타남)은 `radar.toml`에 보관됩니다.

| 확인란 | 키 | 기본값 | 효과 |
|---|---|---|---|
| `[x] 클론 안 됨` | `a` | 켜짐 | 알려진 클론이 없는 저장소의 행을 나열합니다. 끄면 알려진 클론의 행만 남습니다. |
| `[ ] 초안` | `d` | 꺼짐 | 계정 전체 행의 초안 요청을 나열합니다. 범위 자체 저장소의 초안은 항상 나열됩니다. |

둘 다 `Ctrl+N` 배지와 팔레트(`Radar: 클론하지 않은 요청 표시`, `Radar: 초안 표시`)에 있습니다.

프로필의 응답은 **5분** 동안 `radar-account.json`에 보관됩니다: 그 안에 Radar를 다시 열면 호스트에 묻지 않고 행을 보여 줍니다. **새로 고침**(`r` 또는 `F5`)은 항상 묻습니다. 마지막 응답이 얼마나 오래됐든 모든 저장소와 모든 계정 전체 목록을 묻습니다. 속도를 늦추라고 했거나 토큰을 거부한 호스트는 같은 주기에 다시 묻지 않습니다. 프로필과 종류당 최대 300행을 보관하며, **Repositories** 아래의 한 줄이 더 있었던 개수나 프로필을 읽을 수 없던 이유를 알려 줍니다(**다시 연결**은 설정 > 연동을 엽니다).

## 한계

- 계정 전체 행은 GitHub, GitLab(자체 호스팅 포함), Gitea, Forgejo, Azure DevOps, Bitbucket Data Center, Gerrit 프로필에서 가져옵니다(Bitbucket Cloud 제외). 나에게 할당된 이슈는 처음 다섯 개에서 가져오며, Bitbucket과 Gerrit에는 이슈가 없습니다.
- 저장소별 목록은 GitHub, GitLab(자체 호스팅 포함), Gitea, Forgejo, Azure DevOps, Bitbucket, Gerrit 프로필을 사용하며, 검사, 충돌, 언급은 처음 네 개에서만 읽습니다.
- GitLab의 언급은 대기 중인 할 일에서만 가져오고, GitHub, Gitea, Forgejo의 검사는 저장소당 요청 15개에 대해서만 요청합니다.
