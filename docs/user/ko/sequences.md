# 시퀀스

**시퀀스**는 차례로 실행되는 명령의 이름 있는 목록입니다. 예를 들어 *모든 변경 사항 스테이징*,
*AI: commit 메시지 생성*, *Commit*, *Push*를 하나의 **백업** 키로 묶을 수 있습니다. 각 단계는
[명령 팔레트](keybindings.md)의 명령 하나이며, 시퀀스는 그 자체로 팔레트 행(`시퀀스: <이름>`)이 되고,
키에 바인딩할 수 있으며, **설정 > 시퀀스**나 `config.toml`에서 편집합니다.

## 시퀀스 페이지

**설정 > 시퀀스**는 [목록 페이지](settings.md#목록)입니다: 왼쪽에 시퀀스 목록, 오른쪽에 선택한 시퀀스의 행이 있습니다.
모든 변경은 즉시 적용되고 기록되며, 팔레트와 키맵은 재시작 없이 따라옵니다.

```
 시퀀스
+- 시퀀스 ----------------+  시퀀스 편집 중 1/2
| 이 설치                 |  이름         백업
| > 백업          Alt+B   |  ID           backup
|   워크트리와 에이전트   |  설명         모두 스테이징, ...
| 이 저장소               |  범위         이 설치
|   릴리스                |  단축키       [ Alt+B ] [ 지우기 ]
+-------------------------+  단계         모두 스테이징 > AI: ... > Commit > Push
| [+ 추가 v] [복제] [제거]|              [ 단계 편집 (4) ] [ 지금 실행 ]
| [↑] [↓]                 |
+-------------------------+
```

* **+ 추가**는 **빈 시퀀스**와 프리셋 세 개, **프리셋에서 ▸ 백업**, **작성 후 push**, **워크트리와 에이전트**를
  제공합니다. 프리셋은 출발점일 뿐입니다: 추가하기 전에는 아무것도 활성화되지 않으며, 추가한 것은 편집할 수 있는
  복사본입니다. 프리셋의 이름은 추가할 때 인터페이스 언어로 정해집니다.
* **복제**, **제거**(먼저 묻습니다), **↑** / **↓** 또는 드래그로 목록의 순서를 바꿉니다(`Insert`, `Ctrl+D`,
  `Delete`, `Alt+Up`, `Alt+Down`). 목록의 순서는 `config.toml`의 순서입니다.
* 문제가 있는 행은 빨간색으로 표시되고 이유를 알려 줍니다(단계가 없음, 이 버전이 모르는 단계, 필요한 옵션이 없는
  `안 함` 일시 중지). 문제가 있는 시퀀스도 **저장할 수 있고** 알 수 없는 미래의 단계는 그대로 유지되지만, 고칠 때까지
  팔레트 행은 회색으로 유지됩니다.

### 시퀀스의 행

| 행 | 하는 일 |
|---|---|
| **이름** | 팔레트에 표시되는 것: `시퀀스: <이름>`. |
| **ID** | `config.toml`, 명령줄, 단축키의 키에 쓰는 짧은 이름(`a-z`, `0-9`, `_`, `-`). 이름을 바꾸면 같은 기록에서 단축키도 함께 옮겨집니다. |
| **설명** | 선택 사항, 본인용입니다. |
| **범위** | 아래를 참고하세요. |
| **단축키** | 키를 보여 주는 버튼. `Enter`나 클릭은 **키보드 및 마우스**와 같은 키 입력 대기를 엽니다: 누르는 동안 충돌과 터미널 경고가 표시되며, 다른 동작이 쓰는 키는 똑같이 거부됩니다. **지우기**는 키를 제거합니다. 키는 `[keybindings.sequence] <id>`로 저장됩니다. |
| **단계** | 순서대로 나열된 단계. **단계 편집**이 엽니다. |
| **지금 실행** | 현재 창에서 시퀀스를 실행합니다. |

### 범위

시퀀스마다 범위가 있으며 시퀀스와 함께 저장됩니다.

| 범위 | 저장되는 곳 | 보는 사람 |
|---|---|---|
| **이 설치**(기본값) | `config.toml`의 `[[sequences]]`, 이 설치가 소유자 | 이 GitPoulpi 설치만. |
| **이 컴퓨터의 모든 설치** | `config.toml`의 `[[sequences]]`, 소유자 없음 | 그 파일을 공유하는 모든 설치. |
| **이 저장소만** | 현재 저장소의 `.gitpoulpi/sequences.toml` | 저장소를 가진 모든 사람. 신뢰해야만 적용됩니다(아래 참고). |

범위를 바꾸면 정의가 옮겨집니다: **이 저장소만**을 고르면 저장소의 파일에 기록되고 `config.toml`에서는 제거되며, 반대도
마찬가지입니다. 저장소 범위에는 열려 있는 저장소가 필요합니다.

### 저장소 시퀀스와 신뢰

`.gitpoulpi/sequences.toml` 파일은 커밋될 수 있으므로 다른 사람에게서 올 수 있고, 시퀀스는 내 컴퓨터에서 명령을 실행합니다.
그래서 저장소의 시퀀스는 커밋된 워크플로 파일의 명령처럼 **신뢰하기 전에는 제공되지 않습니다**.

아직 아무도 신뢰하지 않은 이런 파일이 저장소에 있으면 Log 위에 알림이 나타납니다: *이 저장소에 시퀀스 2개가 정의되어 있습니다*와
**검토**, **신뢰**, **무시**. 아무것도 막지 않습니다.

- **검토**는 모든 시퀀스를 모든 단계, 일시 중지, 옵션과 함께 읽기 전용으로 나열합니다. 거기서 **신뢰**는 나열된 것을
  신뢰하고, **닫기**(또는 `Esc`)는 아무것도 신뢰하지 않습니다. 목록이 창보다 길면 거기서는 신뢰가 제공되지 않습니다(창을
  넓히세요): 읽을 수 없었던 것을 신뢰하는 일은 없습니다.
- **신뢰**(버튼, 또는 팔레트의 *시퀀스: 이 저장소의 시퀀스 신뢰*)는 파일을 지금 그대로 신뢰합니다.
- **무시**는 파일이 바뀔 때까지 알림을 숨깁니다.
- 키보드에서: 팔레트에 *시퀀스: 이 저장소의 시퀀스 검토 / 신뢰 / 무시*가 있습니다.

기록되는 것은 ID, 명령, 일시 중지, 옵션의 다이제스트이며 저장소의 로컬 상태(저장소 안이 아님)에 보관됩니다. 그중 하나라도 바뀌면
(예: pull 이후) 알림이 *이 저장소의 시퀀스가 변경되었습니다*로 돌아오고, 다시 신뢰할 때까지 팔레트와 키에서 빠집니다. 시퀀스의
이름을 바꾸거나 설명을 편집해도 아무것도 바뀌지 않습니다. 설정에서 직접 작성한 시퀀스는 편집하기 전에 파일이 이미 신뢰되어 있었다면(또는
비어 있었다면) 신뢰된 채로 남습니다.

신뢰한 뒤에는 저장소 시퀀스가 내 것처럼 팔레트에 `시퀀스: <이름>`으로 나타나며 설정에서 단축키를 줄 수 있습니다. 내 시퀀스와
ID가 같은 시퀀스는 충돌입니다: 내 것이 우선하고 다른 것은 중복으로 보고됩니다.

명령줄에서: `gitpoulpi sequence list`는 파일의 시퀀스를 `trusted`와 `repo_trust` 상태(`untrusted`, `changed`, `trusted`)와 함께
보여 줍니다. `gitpoulpi sequence trust`(와 `untrust`, 다른 저장소는 `--repo PATH`)는 `sequence show`를 읽은 뒤 사람이 실행하는
것입니다. `sequence run`은 신뢰되지 않은 저장소 시퀀스를 거부합니다. AI 에이전트는 신뢰할 수 없습니다: MCP 도구가 없습니다.

## 단계

**단계 편집**은 목록을 시퀀스의 단계로(제목은 **<이름>의 단계**) 바꾸고, 행을 선택한 단계의 행으로 바꿉니다.
**뒤로**(행 맨 위의 ✕)나 `Esc`는 시퀀스로 돌아갑니다.

* **+ 추가**는 **단계 추가**를 엽니다: 시퀀스가 실행할 수 있는 모든 명령이 팔레트 이름으로(AI 명령에는 반짝이 표시)
  나열되며, 입력하는 대로 팔레트의 일치 방식으로 필터됩니다. 이 버전이 실행할 수 없는 단계는 이유와 함께 회색으로 표시됩니다.
  `Enter`나 클릭은 맨 끝에 추가하고, `Esc`나 ✕는 팝업을 닫습니다.
* **복제**, **제거**, **↑** / **↓**와 드래그는 시퀀스와 같이 동작합니다.
* 위험한 명령(브랜치 삭제, 변경 사항 버리기...)은 제공되지 않습니다: 시퀀스는 그런 명령을 실행할 수 없습니다.

### 일시 중지

각 단계에는 **일시 중지**가 있습니다.

| 일시 중지 | 의미 |
|---|---|
| **기본값** | 단계는 응답이 필요할 때만, 평소 대화상자에서 멈춥니다(브랜치 이름, 아직 비어 있는 commit 메시지...). |
| **항상** | 이 단계 전에 멈추고 계속할지 묻습니다. |
| **안 함** | 절대 멈추지 않습니다. 단계의 옵션이 필요한 모든 것을 제공해야 하므로, 이름을 묻는 단계에는 **이름** 옵션이 채워져 있어야 합니다. |

실행 전에 항상 묻는 단계(강제 push)는 **안 함**을 제공하지 않으며, 행이 이유를 알려 줍니다. AI 메시지 단계의 **안 함**은 명시적인 선택으로
허용됩니다.

### 옵션

**일시 중지** 아래의 행은 단계의 옵션입니다: **이름**이나 **메시지** 텍스트, **브랜치**, **새 탭에서 열기** 같은 확인란, 또는 설정에서
채워지는 드롭다운(**리모트**, **AI 프로필**, **열기 위치** 항목). 텍스트는 `${branch}`, `${date}`, `${time}`, `${n}`(이름을 고유하게
만드는 숫자) 변수를 받습니다. 텍스트를 지우면 옵션이 제거됩니다.

## AI로 만들기와 편집

[AI를 켠](ai.md#시퀀스-초안) 상태(설정 > AI)에서는 항목 두 개가 나타납니다: **추가 > AI로 만들기...**(팔레트 행
`시퀀스: AI로 만들기...`도 같으며, 이 페이지에서 대화상자와 함께 설정을 엽니다)와 선택한 시퀀스의 **지금 실행** 옆의
**AI로 편집...**입니다. AI가 꺼져 있는 동안에는 둘 다 없습니다.

```
+- AI로 시퀀스 만들기 ------------------------------------- x -+
| 원하는 시퀀스를 설명하세요                                    |
| +-----------------------------------------------------------+ |
| | stage everything, write the commit message with the AI,   | |
| | commit, then push                                         | |
| +-----------------------------------------------------------+ |
| Enter는 줄 추가. Ctrl+Enter는 보내기. Esc는 닫기.             |
| [ ] 컨텍스트 보내기 (리모트 이름, AI 프로필, 열기 위치 레이블)|
|    꺼짐: 설명만 전송됩니다.                                   |
| AI는 제안만 합니다. 수락하기 전에는 아무것도 저장되지 않으며...|
| [ 보내기 ] [ 취소 ]                                           |
+---------------------------------------------------------------+
```

원하는 내용을 자기 말로 쓰고, **보내기**(또는 `Ctrl+Enter`, `Ctrl+S`)는 다른 모든 AI 동작과 같은 프로필, 작업 표시기, `Esc`(그리고 같은
"전송되는 내용" 질문)로 모델에 요청합니다. 답은 아무 일이 일어나기 전에 읽어 보는 **제안**입니다.

* 이름, ID, 설명, 그리고 일시 중지와 옵션이 있는 단계.
* **AI로 편집**에서는 현재 시퀀스와의 차이: `+`는 추가된 단계, `-`는 삭제된 단계, `~`는 일시 중지나 옵션이 바뀐 단계, 필드는
  `~ 이름: "a" -> "b"`.
* **제외됨**: 모델이 제안했지만 허용되지 않는 단계(알 수 없음, 위험함, 시퀀스 안의 시퀀스, 불가능한 일시 중지)와 이유. 유효한 단계는
  유지됩니다.
* 모델의 **메모**와, 표시만 되는 **제안된 단축키**(그 키가 이미 사용 중인지 여부 포함). 바인딩되지는 않습니다: 나중에
  **단축키** 버튼을 사용하세요.

```
+- 제안된 변경 --------------------------------------------- x -+
| + 추가   - 삭제   ~ 변경                                      |
| ~ 이름: "Daily" -> "Daily 2"                                  |
| 단계 (3)                                                      |
| + 1. Git: Fetch All Remotes                                   |
|   2. Git: Stage All Changes                                   |
| - Git: Commit...                                              |
| ~ 3. Git: Push: 기본값 -> 일시 중지: 항상                     |
| 제외됨                                                        |
| 4단계 `reset_hard`: 위험한 단계는 허용되지 않습니다           |
| [ 수락 ] [ 저장 전에 편집 ] [ 거부 ] [ 뒤로 ]                 |
+---------------------------------------------------------------+
```

* **수락**은 한 번의 저장으로 기록하고(새 시퀀스, 또는 편집한 시퀀스의 대체이며 ID, 범위, 키를 유지) 목록에서 선택합니다.
* **저장 전에 편집**은 같은 일을 하면서 단계를 열어 행을 다듬을 수 있게 합니다(이 페이지는 모든 편집을 즉시 저장하므로
  시퀀스는 이미 저장된 상태입니다).
* **거부**는 아무것도 기록하지 않습니다. **뒤로**는 설명으로 돌아가 다시 보냅니다.
* **수락**은 수락할 것이 없을 때는 사용할 수 없습니다: 사용할 수 있는 단계가 없음, 페이지가 표시할 문제, 아무것도 바꾸지 않는 편집.

**수락**하기 전에는 아무것도 기록되지 않으며, 여기서 시퀀스가 실행되는 일은 없습니다. 설명을 입력했거나 제안이 열려 있는 동안
대화상자를 닫으면(✕, `Esc`, 바깥 클릭) "변경 사항을 버리시겠습니까?"라고 묻고, 설정을 닫을 때도 묻습니다.

## config.toml

```toml
[[sequences]]
id = "backup"
name = "Backup"
scope = "installation"
owner = "<this installation's id>"

[[sequences.steps]]
run = "stage_all"

[[sequences.steps]]
run = "ai_generate_commit_message"
pause = "always"

[[sequences.steps]]
run = "commit"

[[sequences.steps]]
run = "push"

[keybindings.sequence]
backup = "Alt+B"
```

이 버전이 모르는 키와 단계는 페이지가 저장할 때 그대로 유지됩니다.

## 시퀀스 실행

시퀀스는 단계의 이름 있는 목록이며, 각 단계는 팔레트의 명령 하나입니다(모두 스테이징, AI로 commit 메시지 작성, commit, push...). 팔레트
(`시퀀스: <이름>`), 설정 > 키보드 및 마우스에서 지정한 키(`tui.toml`의 `[keybindings.sequence]`), 또는 명령줄(`gitpoulpi sequence run`)로
실행합니다.

실행 중에는 Log 위쪽의 띠가 `<이름> k/n`, 단계, 기다리는 것을 보여 줍니다. 실행은 작업 패널에도 `시퀀스 <이름> k/n: <단계>`로
나타납니다. 한 번에 하나의 시퀀스만 실행되며, 두 번째를 시작하면 어느 것이 실행 중인지 알려 줍니다.

**질문하려고 멈추는 곳.** 각 단계에는 `pause` 설정(`default`, `always`, `never`)이 있습니다.

| 단계 | 기본값 | `pause = "never"` |
|---|---|---|
| AI commit 메시지 | 메시지가 메시지 필드에 들어가고, 띠에 "메시지를 검토한 뒤 계속"이 표시됩니다 | 바로 이어집니다 |
| Commit | 빈 메시지는 항상 멈춥니다: 필드가 키보드를 받고, 내가 commit하거나 계속하면 이어집니다 | commit할 메시지가 없으면 사용할 수 없습니다 |
| AI commit 구성 | 검토가 열리고, 적용하면 이어지며 닫으면 취소됩니다 | 제안을 그대로 적용합니다 |
| 워크트리 만들기 | 이름이 채워진 대화상자가 열립니다 | 대화상자 없이 `options.name`으로 만듭니다 |
| Push | `git.push_behavior = ask`이면 "Push to..." 선택기가 열립니다 | `options.remote`로 push합니다 |
| lease를 사용한 강제 push, 비밀로 보이는 파일 스테이징 | 항상 묻습니다 | 허용되지 않습니다 |

어떤 단계든 `pause = "always"`이면 실행 전에 **계속**과 **취소**와 함께 "다음: <단계>"가 표시됩니다. 브랜치가 갈라져 push가 거부되면 평소
대화상자가 열리고 띠에 "push 거부됨: 대화상자에서 선택하세요"가 표시됩니다. pull한 뒤 push하거나(또는 lease를 사용한 강제 push) 하면 실행이 이어지고,
대화상자를 닫으면 취소됩니다.

**계속**은 띠의 버튼, 팔레트의 `시퀀스: 계속`, 또는 `sequence.continue`에 바인딩한 키입니다. **취소**는 띠의 닫기 ✕, `시퀀스: 취소`(`sequence.cancel`),
작업 패널, 또는 다른 것이 쓰지 않을 때의 `Esc`입니다(열린 대화상자가 먼저 닫히며, 그것도 취소입니다). 취소하면 이미 실행된 단계는 유지되며 그렇게
알려 줍니다: "<이름>을(를) k/n단계(<단계>) 이후 취소했습니다. 이전 단계는 유지됩니다".

**단계가 실패하면** 실행이 거기서 멈춥니다: 상태 표시줄이 시퀀스, 단계, 오류를 알려 주고, 띠가 빨간색이 되며 **자세히**(단계의 옵션을 나열하는 활동 로그
항목)와 닫기 ✕가 나타나고, 이전 단계는 완료된 채로 남습니다.

**워크트리.** `open_tab = true`인 워크트리 만들기 단계는 실행을 새 워크트리의 탭으로 옮깁니다: 다음 단계(`tab_dir_terminal`,
`tab_open_agent_here`, `tab_open_in`)가 거기서 동작합니다. 다른 탭이 화면에 있으면 띠에 "탭 <이름>을(를) 기다리는 중"과 **이동**이 표시됩니다. 그 탭을
닫으면 실행이 취소됩니다. 실행은 GitPoulpi를 종료하면 이어지지 않습니다.

### 에이전트의 실행 제안

*AI 에이전트가 확인용 변경을 제안하도록 허용*이 켜져 있으면(`[mcp] allow_ui_propose`) 에이전트가 내 창에 시퀀스 실행을 요청할 수 있습니다
(`gitpoulpi ui sequence run <id>`, MCP `ui_sequence_run`). 배너가 나타납니다:
*✦ <agent>의 제안: 시퀀스 <이름> 실행*과 **실행**, **닫기**. 실행을 누르기 전에는 아무것도 실행되지 않습니다(클릭하거나 `Ctrl+N` 다음 `Enter`).
닫기, `Esc`(다른 것이 쓰지 않을 때), 팔레트의 *에이전트: 대기 중인 보기 닫기*는 제안을 버립니다. 이후 실행은 내가 시작한 것과 똑같이 시퀀스가
정한 곳에서 멈추며 진행됩니다. 시퀀스가 없거나, 올바르지 않거나, 신뢰하지 않은 저장소 시퀀스이면 제안은 거부됩니다.

## 실행 취소

저장소를 바꾸는 모든 단계(스테이징, commit, tag, 브랜치, stash, 워크트리...)는 실행의 태그가 붙은 **자기만의 일반 실행 취소 항목**을 남기므로,
`Ctrl+Z`는 여전히 한 번에 한 단계씩 취소하며 [실행 취소 기록](undo-redo.md#실행-취소-기록)에는 그 항목들에 `⟳ <이름>`이 표시됩니다. 실행 전체를
되돌리는 것이 **시퀀스 전체 실행 취소**입니다: 실행 취소 기록의 버튼(`x`), 팔레트 행 `편집: 시퀀스 전체 실행 취소`, 또는 `gitpoulpi undo --sequence`.
실행의 항목을 최신 것부터 각각 자기 검사와 질문(이미 push한 commit은 먼저 묻습니다)과 함께 취소하고, 첫 거부에서 단계를 짚으며 멈추고,
더 오래된 항목은 저널에 남깁니다. AI 메시지와 push는 항목을 남기지 않습니다: push는 절대 실행 취소되지 않습니다. 현재 저장소의 저널만
건드립니다. 워크트리에서 한 단계는 그 저장소에서 실행 취소합니다. 다시 실행은 항목별로 유지됩니다. 자세한 내용: [시퀀스 실행](undo-redo.md#시퀀스-실행).
