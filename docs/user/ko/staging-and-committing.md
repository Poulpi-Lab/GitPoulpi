# 스테이징과 commit

무엇을 변경했는지 확인하고, commit에 들어갈 내용을 정확히 고르고, commit을 작성하고, 파일을 더 깊이 살펴보는 방법(blame, 파일 기록, 내장 편집기)을 설명합니다. *WIP 행*과 *hunk* 같은 용어는 [인터페이스 둘러보기](interface-tour.md)에서 설명합니다.

## 작업 변경 사항

아직 commit하지 않은 작업은 **Log의 첫 번째 행**입니다(점선 원, `// WIP`, 수정된 파일 수 `✎ n`과 추가된 파일 수 `+ n` 카운터가 함께 표시됨). 이 행을 선택하면 오른쪽 창에 작업 변경 사항이 나타납니다.

![작업 변경 사항: 오른쪽에 스테이징 안 된 파일과 스테이징된 파일, 아래에 commit 양식](../images/hero.png)

- **스테이징 안 된 파일**: 다음 commit에 아직 들어가지 않은, 수정되거나 추가되거나(추적되지 않음) 삭제된 파일.
- **스테이징된 파일**: 다음 commit에 들어갈 내용.
- **경로** 또는 **트리**(`m`)는 파일을 평면 목록 또는 폴더별로 나열합니다. **모두 접기**(`z`)는 폴더를 접습니다. **모든 파일 보기**(`a`)는 변경된 파일만이 아니라 전체 트리를 보여 줍니다. 목록의 빈 곳을 오른쪽 클릭하면 **모두 펼치기** / **모두 접기**가, 폴더 행에서는 **하위 폴더 모두 펼치기** / **하위 폴더 모두 접기**가 나옵니다. 키는 `=`, `-`, `*`, `_`입니다([마우스와 제스처](mouse-and-gestures.md) 참고).
- 제목에는 어느 브랜치에서 파일 몇 개가 변경되었는지 표시됩니다.

### 스테이징, 스테이징 해제, 버리기

| 작업 | 방법 |
|---|---|
| 파일 스테이징 | 행에 마우스를 올리고 **파일 스테이징**을 클릭하거나, 행을 선택하고 `Ctrl+Space` 또는 `Ctrl+G s`를 누릅니다 |
| 폴더 스테이징 | 폴더 행의 **폴더 스테이징** |
| 모두 스테이징 | 섹션 제목의 **모든 변경 사항 스테이징** 또는 `Ctrl+G a` |
| 스테이징 해제 | 스테이징된 섹션에서 같은 버튼과 키(`Ctrl+G u`) |
| 파일의 변경 사항 버리기 | 파일을 마우스 오른쪽 버튼으로 클릭 > **변경 사항 버리기...**(먼저 확인하며, `Ctrl+Z`로 변경 사항을 되돌릴 수 있음) |

### 민감한 파일

파일, 폴더 또는 전체를 스테이징하면 먼저 무엇이 추가되는지 확인합니다. 이름이 `[privacy] sensitive_patterns`(`.example`, `.sample`, `.template` 파일을 제외한 `.env`와 `.env.*`, `*.pem`, `*.key`, SSH 개인 키, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `*.crt`, `*.cer`, `*.der`, `*.kdbx`)에 일치하거나, 텍스트에 스캐너가 인식하는 비밀 정보가 들어 있는 파일은 스테이징되지 않습니다. **민감한 파일** 질문은 각 파일을 이유(패턴, 또는 비밀 정보의 종류와 가려진 미리 보기이며 값은 절대 표시하지 않음)와 함께 나열하고 **1. 그래도 스테이징** 또는 **2. 취소, 스테이징하지 않음**을 제공합니다. 화살표 키나 숫자를 누르기 전에는 어떤 답도 강조되지 않으므로 실수로 누른 Enter는 아무것도 답하지 않습니다. `Esc`, 닫기 표시, 바깥 클릭은 취소합니다. 키보드, 버튼, 메뉴, 팔레트, 드래그 앤 드롭 모두 같은 요청을 보내므로 같은 질문이 나옵니다. 취소하면 같은 스테이징의 일반 파일도 포함해 아무것도 스테이징하지 않습니다.

텍스트 파일은 각각 최대 1 MiB, 전체 32 MiB까지 읽으며, 더 큰 파일과 바이너리 파일은 이름으로만 판단합니다. `[privacy] staging_guard = false`는 검사를 끕니다. hunk 하나나 일부 줄을 스테이징하는 것은 검사하지 않습니다. 이미 그 파일을 작업 중이기 때문입니다.

파일을 마우스 오른쪽 버튼으로 클릭하면 메뉴가 나옵니다. 스테이징 또는 스테이징 해제, 버리기, 경로 복사, 파일 기록과 blame, 외부 편집기·diff 도구·파일 관리자에서 열기([설정 > Diff 및 편집기](settings.md#diff-및-편집기)에서 지정), 그 밖의 기능이 있습니다.

## 파일 무시하기, 바이너리 또는 텍스트로 처리하기

파일을 마우스 오른쪽 버튼으로 클릭 > **무시**로 파일이나 확장자를 무시하고, 폴더 행에서는 **폴더의 모든 파일 무시**를 고릅니다. GitPoulpi는 먼저 규칙을 어느 파일에 쓸지 묻습니다. 저장소 루트의 `.gitignore`(기본값), 파일이 있는 폴더까지 각 폴더의 `.gitignore`, 또는 `.git/info/exclude`(이 클론에만 적용, commit되지 않음)입니다. 아직 없는 파일은 *새 파일*로 표시되고 확인하면 만들어집니다. 줄은 선택한 파일 기준 상대 경로로 기록되어, `src/a/b.txt`는 `src/.gitignore`에서 `/a/b.txt`가 됩니다. 화살표 키로 이동하고, 입력으로 목록을 좁히고, `Enter`로 기록하고, `Esc`로 취소합니다. `.gitignore`에 쓴 내용은 `Ctrl+Z`로 되돌릴 수 있고, `.git/info/exclude`는 작업 트리 밖에 있어 되돌릴 수 없습니다.

![무시 규칙을 어느 파일에 쓸지 묻는 목록: 저장소의 .gitignore, 파일 폴더의 .gitignore 또는 .git/info/exclude, 각각 기록될 줄과 함께 표시](../images/ignore-picker.png)

파일을 마우스 오른쪽 버튼으로 클릭 > **바이너리로 처리**(git이 이미 바이너리로 처리하면 **텍스트로 처리**)는 `.gitattributes` 규칙(`binary` 또는 `text diff`)을 기록합니다. 파일 자체 또는 같은 확장자의 모든 파일을 고른 다음, 위와 같은 목록에서 기록할 `.gitattributes`를 고릅니다(이 클론에만 적용하려면 `.git/info/attributes`). 같은 패턴에 이미 쓰인 규칙은 모순 없이 교체됩니다. 파일의 diff는 바로 갱신되고, 상태 표시줄에는 무엇을 어디에 썼는지가 표시됩니다(다른 규칙이 여전히 우선하면 경고도 합니다). 폴더 행에는 **폴더의 파일을 다음으로 처리** > **바이너리** / **텍스트**가 있습니다. 명령 팔레트(**작업 변경: 선택한 파일을 바이너리로 처리...**)와 명령줄(`gitpoulpi treat binary|text <경로>`)에도 같은 기능이 있습니다. 파일 보기도 이 규칙을 따릅니다. 텍스트로 처리한 파일은 NUL 바이트가 있어도 줄을 보여 줍니다.

## 파일 목록의 메뉴, 다중 선택, 변환

오른쪽 창의 파일 목록(스테이징 안 된 파일, 스테이징된 파일, commit의 변경된 파일, **모든 파일 보기**)은 같은 메뉴와 동작을 공유합니다. 파일, 폴더 행 또는 목록의 빈 부분을 오른쪽 클릭하거나, 포커스된 행에서 `.`(`Shift+F10`, 메뉴 키)을 누르거나, 팔레트에서 **파일: 행 또는 선택 항목의 메뉴 열기**를 실행합니다.

- **commit의 파일**(그리고 **모든 파일 보기**의 파일): **Diff 열기**, **파일 열기**, **파일 기록**, **파일 Blame**, 편집기, 기본 프로그램 또는 **연결 프로그램...**으로 열기, **폴더에서 보기**, **파일 편집**, **파일 경로 복사**, **파일 전체 경로 복사**, **무시**, **바이너리로 처리** 또는 **텍스트로 처리**, **변환**, **이 commit에서 파일 복원**(먼저 묻습니다. `git checkout <commit> -- <파일>`처럼 파일도 스테이징되며, `Ctrl+Z`로 이전 파일이 돌아옵니다), **파일 삭제...**. 파일이 작업 트리에 없으면 작업 사본에 관한 행은 이유와 함께 회색으로 표시됩니다. **작업 디렉터리와의 Diff**는 commit의 버전과 디스크의 파일 사이의 diff를 엽니다. **파일 변경 사항에서 패치 만들기...**는 그 commit에서 해당 파일의 변경 패치를 씁니다(선택 항목과 폴더 행에도 있으며, 작업 변경 사항의 **모든 파일 보기**에서는 파일의 작업 트리 변경을 패치로 만듭니다).
- **폴더 행**: **폴더 열기**, **파일 경로 복사**, **폴더의 모든 파일 무시**, **폴더의 파일을 다음으로 처리**, **변환**, **이 폴더에 파일 만들기**.
- **목록의 빈 부분**: **파일 만들기**와 **저장소 폴더 열기**. 스테이징 안 된 파일 목록에는 **모두 스테이징**과 **모든 변경 사항 버리기...**가, 스테이징된 파일 목록에는 **모두 스테이징 해제**가 추가됩니다.

![commit의 파일을 마우스 오른쪽 버튼으로 클릭한 메뉴: diff, 파일 기록, blame 열기, 편집기나 기본 프로그램으로 열기, 경로 복사, 무시, 변환, commit에서 복원, 삭제](../images/commit-file-menu.png)

### 여러 파일 선택

동작은 Log와 같습니다. **Ctrl+클릭**은 행을 선택에 추가하거나 제거합니다. **Shift+클릭**(터미널이 Shift+클릭을 쓰는 경우 **Alt+클릭**)은 기준점부터의 범위를 선택합니다. 일반 클릭은 처음부터 다시 시작하며 이전처럼 diff를 엽니다. `Esc`는 선택을 해제합니다. 키보드에서는 `Space` 또는 `Insert`가 모든 목록에서 현재 행을 전환하고(스테이징 안 된 파일과 스테이징된 파일에서는 `Ctrl+Space`가 선택 항목 또는 현재 행을 스테이징합니다) `Shift+Up` / `Shift+Down`가 범위를 넓힙니다. 폴더 행은 접혀 있어도 그 아래의 모든 파일을 선택합니다. 선택된 행은 강조 표시되고 상태 표시줄에 개수가 표시됩니다. `Ctrl+A`는 포커스된 목록의 모든 행을 선택합니다.

선택된 행을 오른쪽 클릭(또는 `.`)하면 **파일 N개**라는 제목의 선택 전체 메뉴가 열립니다: 스테이징 또는 스테이징 해제, 버리기, 무시, 바이너리 또는 텍스트로 처리, 변환, 경로 복사, commit에서 복원, 삭제. 스테이징, 스테이징 해제, 복원은 각각 한 번의 동작이며, 버리기와 삭제는 먼저 묻고 파일 수를 알려 줍니다. 선택 밖의 행을 오른쪽 클릭하면 그 행으로 선택을 다시 시작합니다.

![스테이징 안 된 파일 목록에서 파일 4개를 선택하고 "파일 4개" 제목의 메뉴를 연 모습: 스테이징, 버리기, 무시, 바이너리/텍스트로 처리, 변환, 경로 복사, 삭제](../images/file-pane-multiselect.png)

### 인코딩, 줄 끝, 들여쓰기 변환

**변환**은 파일, 폴더 또는 선택의 메뉴에 있습니다. 명령줄의 `gitpoulpi convert`도 같은 일을 합니다.

- **인코딩**: UTF-8, UTF-8 BOM, UTF-16 LE/BE, Windows-1252, ISO-8859-1, ISO-8859-15, Windows-1250, Windows-1251, KOI8-R, Shift_JIS, EUC-JP, GBK, Big5, EUC-KR.
- **줄 끝**: LF, CRLF 또는 CR.
- **들여쓰기**: 줄 앞의 공백을 스페이스 또는 탭으로 바꿉니다(탭 너비 지정).

작업 트리의 파일은 편집기의 상태 표시줄과 같은 함수로 백그라운드에서 다시 쓰입니다. 올바른 UTF-8이 아니고 바이트 순서 표시도 없는 파일은 편집기처럼 Windows-1252로 읽습니다. 바이너리 파일, 없는 파일, 대상 인코딩으로 표현할 수 없는 파일은 건너뛰고 보고하며(*파일 12개 변환, 3개 건너뜀 (바이너리 3)*) 손상시키지 않습니다. 쓸 수 없는 파일은 실패 알림을 띄웁니다. 전체 일괄 처리가 실행 취소 기록의 항목 하나이므로 `Ctrl+Z` 한 번으로 모든 파일이 돌아옵니다. 편집기에서 열려 있는 파일은 닫을 때까지 변환이 차단됩니다.

## diff 읽기

파일 이름을 클릭하거나(또는 그 위에서 `d`를 누르면) 가운데에 있던 Log 대신 그 파일의 diff가 나타납니다. `Esc` 또는 `q`를 누르면 Log로 돌아옵니다.

![hunk 두 개가 있는 diff. 각 hunk에 버리기와 스테이징 버튼이 있음](../images/diff.png)

위쪽 바에서 보기를 전환합니다.

- **인라인**은 통합 diff를 보여 주고, **분할**은 변경 전과 후를 나란히 놓습니다(`m`으로 레이아웃을 순환).
- **Hunk**(`Shift+H`)는 변경된 hunk만 앞뒤 한 줄의 문맥과 함께 보여 줍니다. 끄면 파일 전체가 보입니다.
- **WS**(`s`)는 공백만 다른 변경을 숨깁니다.
- **줄바꿈**(`w`)은 긴 줄을 자르지 않고 줄바꿈합니다.
- **맵**(`Shift+M`)은 스크롤바 옆에 파일 전체의 미니맵을 표시합니다. 클릭하면 그 위치로 이동합니다. 선택한 단어의 다른 출현은 색이 입혀지고 스크롤바에도 표시됩니다.
- `n`과 `p`(또는 바의 화살표)로 hunk 사이를 이동합니다.
- **자동**(마지막 버튼, `Shift+C`)은 파일을 읽는 인코딩입니다. 클릭하거나(또는 `Shift+C`를 누르거나, 팔레트에서 *Diff: 인코딩 선택...*을 실행하여)
  목록에서 하나를 고릅니다: 먼저 **자동 감지**, 이어서 UTF-8, UTF-8 BOM, UTF-16 LE와 BE, Windows-1252, ISO-8859-1, ISO-8859-15, Windows-1250,
  Windows-1251, KOI8-R, Shift_JIS, EUC-JP, GBK, Big5, EUC-KR(입력하여 목록 검색). 파일의 양쪽이 그 인코딩으로 정확한 바이트 그대로 다시 읽히므로,
  Latin-1 파일은 악센트가 보이고 UTF-16 파일(git은 이를 바이너리로 봅니다)은 줄이 보입니다. 선택은 종료할 때까지 그 파일의 경로에 대해 기억되며, 이 보기와
  [리뷰](review.md)에 모두 적용됩니다. 인코딩을 고른 동안의 hunk는 이 보기 자체의 것이므로 스테이징과 버리기는 꺼집니다(다시 스테이징하려면 **자동 감지**를
  고르세요). 느린 읽기는 잠시 후 제목에 *...(으)로 읽는 중*이라고 표시합니다.

![분할 레이아웃으로 본 같은 diff. 변경 전과 후가 나란히 있음](../images/diff-split.png)

마우스로 텍스트를 선택(드래그 또는 단어 더블 클릭)하고 `y` 또는 `Ctrl+C`로 복사할 수 있습니다. 파일 텍스트만 복사되며 줄 번호나 `+`, `-` 표시는 복사되지 않습니다.

### hunk 또는 한 줄 스테이징

작업 트리 diff에서 각 hunk 머리글에는 **Hunk 스테이징**과 **Hunk 버리기**가 있습니다(스테이징된 쪽에는 **Hunk 스테이징 해제**).

- `Space`는 커서가 있는 hunk를 스테이징합니다.
- 몇 줄만 스테이징하려면 `v`로 선택을 시작하고 `j`/`k`로 이동한 뒤 `Enter`를 누릅니다. *변경된* 줄만 대상이 됩니다.
- `x`는 hunk를, `Shift+X`는 선택한 줄을 버립니다. 둘 다 먼저 확인하며 `Ctrl+Z`로 되돌릴 수 있습니다.
- hunk에서 마우스 오른쪽 버튼(또는 `.`)을 누르면 메뉴가 나옵니다. 스테이징, 스테이징 해제, 버리기, 파일 기록, blame, 복사가 있습니다.

commit의 diff는 읽기 전용입니다. 변경된 그림은 그림으로 표시됩니다. [그림](image-view.md)을 참고하세요.

## commit 작성

commit 양식은 오른쪽 창의 아래쪽에 있으며, 그 **요약**은 Log의 작업 변경 사항 행에 있는 필드이기도 합니다. 한쪽에 입력하면 다른 쪽에도 나타납니다.

![AI가 작성한 메시지로 채운 commit 양식: 글자 수 카운터가 있는 요약, 설명, 초록색 commit 버튼](../images/ai-commit-message.png)

- **요약**(카운터는 72자 중 남은 글자 수를 표시)과 **설명**. 요약에서 `Enter`를 누르면 설명으로 이동하고, 설명에서 `Enter`를 누르면 줄이 추가됩니다.
- **변경 파일 N개 Commit**(초록색 버튼) 또는 `Ctrl+Enter`로 스테이징된 변경 사항을 commit합니다. 스테이징된 것이 없으면 버튼이 그렇게 알려 주고 아무 일도 하지 않습니다.
- **이전 commit 수정 (Amend)**(`Shift+A`)는 스테이징된 변경 사항과 새 메시지를 마지막 commit에 합칩니다. 이미 push한 commit이라면 이후 force push(lease 포함)가 필요합니다.
- **훅 건너뛰기**(`Shift+H`, 또는 팔레트의 **Commit: 훅 건너뛰기 전환**)는 저장소의 `pre-commit`과 `commit-msg` 훅을 실행하지 않고 commit합니다. commit마다 따로 정하며, **설정 > 저장소별 설정 > Commit**에서 선택된 채로 시작하게 만들 수 있습니다. 행에 공간이 있을 때 표시됩니다.
- Status 창에서 `c`를 누르면 커서가 양식으로 이동합니다. `Esc`로 벗어납니다.
- `Ctrl+G c`와 `Ctrl+G Enter`(팔레트의 **Git: Commit...**과 **Git: 스테이징된 변경 사항 지금 Commit**)는 하나의 명령이며, 어디에서든 쓸 수 있는 commit 버튼입니다. 양식에 요약이 있고 스테이징된 것이 있으면 포커스를 옮기지 않고 바로 commit하며, **이전 commit 수정 (Amend)**과 **훅 건너뛰기**를 따릅니다. 그렇지 않으면 아무것도 commit하지 않고 양식의 요약으로 커서를 옮기며(창이 숨겨져 있거나 접혀 있으면 먼저 표시합니다), 상태 표시줄이 commit하는 단축키(기본값 `Ctrl+Enter`)를 알려 줍니다. 스테이징된 것이 없으면 그렇게 알립니다. 상태 표시줄에는 아무것도 입력되지 않습니다. AI 요청이 아직 진행 중이면 아무것도 commit하지 않고 그렇게 알립니다(`Esc`로 요청을 취소합니다). `Ctrl+Z`는 다른 commit처럼 이 commit을 되돌립니다.
- 저장소별로 [설정](settings.md#저장소별-commit)에서 **commit할 때마다 push**하게 하거나, 양식을 **commit 템플릿**으로 시작하게 하거나(메시지에서 `#` 주석을 제거하도록도 설정 가능), merge를 **squash**로 만들 수 있습니다. 이때 양식은 git의 squash 메시지로 열립니다.
- 호스팅 연동이 연결되어 있으면 양식에서 `Alt+R`로 이슈 참조를 삽입합니다. [호스팅과 이슈 트래커](hosting-integration.md)를 참고하세요.

[AI](ai.md)를 켜면 요약 오른쪽의 **`✦`** 버튼이 스테이징된 변경 사항으로 메시지를 작성하고(`Ctrl+G i`), **AI로 commit 구성**은 아래 설명처럼 작업을 여러 commit으로 나눕니다. 텍스트는 양식에 들어가 직접 편집할 수 있으며, commit 버튼을 누르기 전에는 아무것도 commit되지 않습니다.

## commit 작성기: 변경 사항을 여러 commit으로 나누기

*(AI를 켜야 합니다. [AI 지원](ai.md) 참고.)* **AI로 commit 구성**을 누릅니다(또는 `Ctrl+G C`, 혹은 작업 변경 사항 행을 마우스 오른쪽 버튼으로 클릭). 모델이 파일을 포함한 여러 commit을 제안합니다. 변경된 모든 파일은 정확히 하나의 commit에 들어가며, 유효하지 않은 계획은 모델에 한 번 되돌려 보냅니다. 제안은 아직 아무것도 commit되지 않은 검토 화면으로 열립니다.

![commit 작성기: 제안된 commit 네 개, 각각 파일로 펼칠 수 있고 위, 아래, 편집, 삭제 컨트롤과 초기화, 취소, commit 4개 만들기 버튼이 있음](../images/composer.png)

| 작업 | 방법 |
|---|---|
| commit 펼치기 또는 접기 | `Left` / `Right` 또는 쐐기 표시 클릭. `*`는 전체 전환 |
| commit을 위나 아래로 이동 | 행의 `▲` `▼` 또는 `Alt+Up` / `Alt+Down`(`K` / `J`) |
| 파일을 다른 commit으로 이동 | commit 위로 끌어다 놓기(목록에서, 또는 오른쪽의 작업 변경 사항 목록에서). 또는 파일에서 `m`을 누르고 드롭다운에서 commit 선택. 또는 파일에서 `Alt+Up` / `Alt+Down` |
| 파일을 별도 commit으로 | 파일에서 `n` 또는 `+ 별도 commit` 버튼 |
| commit 메시지 수정 | 연필 아이콘, `e`, `Enter` 또는 더블 클릭: 메시지를 편집하고 `Enter`로 유지, `Esc`로 취소 |
| commit 제외 | `drop`(`d` 또는 `Delete`). 해당 파일은 commit되지 않은 채 남습니다. `복원`으로 되돌립니다 |
| 처음부터 다시 | **초기화**(`r`)는 모델의 계획으로 돌아갑니다 |
| 만들기 | **commit N개 만들기**(`Ctrl+S`, `Ctrl+Enter` 또는 `a`) |
| 나가기 | **취소** 또는 `Esc`: 아무것도 하지 않음 |

commit을 만들 때는 먼저 모든 것을 스테이징 해제하고, 각 commit마다 해당 파일을 스테이징한 뒤 commit하므로 작업 트리는 건드리지 않습니다. 중간 단계가 실패하면 중단하고 commit이 몇 개 만들어졌는지 알려 줍니다. 파일 전체가 스테이징되므로, 일부만 스테이징했던 파일도 전체가 commit됩니다. 작성기가 사용할 프로필과 지침은 *설정 > AI*에서 고릅니다. [AI 지원](ai.md#commit-작성기)을 참고하세요.

## 파일 보기, Blame, 파일 기록

보기 바에는 **파일 보기**(파일의 내용), **Diff 보기**, **Blame**, 그리고 [commit 열](interface-tour.md#commit-열)의 `파일 │ 전체` 선택기(`파일` 목록이 파일 기록)가 있으며, 파일의 마우스 오른쪽 버튼 메뉴에도 같은 항목이 있습니다. 이 보기들은 진입한 commit 시점의 파일을, 작업 변경 사항에서 열었다면 commit되지 않은 상태(`@ WIP`)의 파일을 보여 줍니다.

- **Blame**과 **파일 기록**은 각각 완전한 보기입니다. *Log 다루기*의 [Blame](log-and-history.md#blame)과 [파일 기록](log-and-history.md#파일-기록)을 참고하세요. blame hunk나 파일 기록 행에서 `Enter`를 누르면 Log의 해당 commit으로 이동합니다.
- `y` 또는 `Ctrl+C`는 선택한 텍스트를 복사합니다(Blame에서는 코드만).
- `Shift+G`는 마지막 줄로 이동합니다. `q`는 보기를 닫습니다.

## 내장 편집기

**편집**(`e`)은 파일의 *작업 디렉터리 사본*을 가운데 창 위에 뜨는 작은 편집기에서 엽니다. 구문 색상, 줄 번호, 실행 취소와 다시 실행, 찾기, 상태 표시줄(위치, 줄 끝, 들여쓰기, 언어)이 있습니다. 오래된 commit의 diff에서 열었더라도 항상 작업 사본을 편집합니다.

![Rust 파일을 구문 강조와 줄 번호로 보여 주는 편집기. 도구 모음에 저장, 실행 취소, 다시, 찾기가 있음](../images/editor.png)

| 키 | 동작 |
|---|---|
| `Ctrl+S` | 저장(파일을 임시 파일에 쓴 뒤 이름을 바꾸므로 절반만 쓰인 상태가 되지 않으며, 줄 끝, BOM, 마지막 줄바꿈은 유지됨) |
| `Ctrl+Z`, `Ctrl+Y` | 실행 취소, 다시 실행 |
| `Ctrl+F`, `F3` | 찾기, 다음 찾기 |
| `Tab`, `Shift+Tab` | 들여쓰기, 내어쓰기(파일 자체의 스타일을 따름) |
| `Ctrl+A`, `Ctrl+C`, `Ctrl+X`, `Ctrl+V` | 모두 선택, 복사, 잘라내기, 붙여넣기 |
| `Esc` | 닫기. 저장하지 않은 변경 사항이 있으면 **저장**(`s`), **버리기**(`d`), **취소**(`c`)를 묻습니다 |

바이너리 파일은 열 수 없습니다. 탭 크기, 줄 끝, 구문 강조, 줄 번호, 자동 줄바꿈은 *설정 > Diff 및 편집기*에 있습니다. [설정](settings.md#diff-및-편집기)을 참고하세요.

**선택 따라가기**를 선택하면(편집기 막대의 상자, 팔레트의 *편집기: 선택 따라가기 전환*, *설정 > Diff 및 편집기*), 편집기가 열려 있는 동안 오른쪽 창에서 다른 파일을 선택했을 때 그 파일의 diff나 파일 보기 대신 작업 사본이 편집기에서 열립니다. 저장하지 않은 변경 사항이 있으면 먼저 **저장**, **버리기**, **취소**를 묻고, 취소하면 현재 파일에 그대로 머뭅니다. 편집할 수 없는 파일(바이너리, 너무 큰 파일, 삭제된 파일)은 기본 보기로 열리고 상태 표시줄에 이유가 표시됩니다. 편집기를 닫으면 선택된 파일의 보기로 이동합니다. 기본적으로 선택되어 있습니다. 이는 작업 중인 변경에 대한 것입니다. 편집 중에 commit의 파일을 고르면 편집기를 떠나(먼저 저장할지 묻습니다) 그 commit에서의 파일 diff를 보여주며, 편집기에는 없는 commit 열도 함께 돌아옵니다.

오른쪽의 상태 표시줄에는 파일의 **인코딩**, **줄바꿈**, **들여쓰기**가 표시되고, 이어서 커서 위치와 구문이 표시됩니다.
처음 세 가지는 버튼이며, 각각 드롭다운을 엽니다(화살표 또는 휠, 입력하여 필터링, `Enter`로 선택, `Esc`로 닫기).
팔레트(`Ctrl+P`)에서도 같은 메뉴를 열 수 있습니다: *편집기: 인코딩 변경*, *편집기: 인코딩으로 다시 열기*, *편집기: 인코딩으로 변환*, *편집기: 줄바꿈 변환*, *편집기: 들여쓰기 변경*.

![막대의 UTF-8 칩 아래에 열린 편집기의 인코딩 메뉴: 다른 인코딩으로 파일을 다시 열거나 변환합니다](../images/editor-encoding-menu.png)

![LF 칩 아래에 열린 편집기의 줄 끝 메뉴: 파일을 LF, CRLF 또는 CR로 변환합니다](../images/editor-eol-menu.png)

- **인코딩.** 파일은 스스로 알리는 인코딩(BOM: UTF-8 또는 UTF-16)으로 열리고, 없으면 UTF-8, 그것도 아니면
  Windows-1252로 열리며, 상태 표시줄에 어느 것인지 표시됩니다. **인코딩으로 다시 열기**는 파일의 바이트를 다른
  인코딩으로 다시 읽습니다(저장하지 않은 변경 사항이 있으면 먼저 묻습니다). 감지가 틀렸을 때 사용하세요.
  **인코딩으로 변환**은 텍스트는 그대로 두고 파일이 저장되는 인코딩을 바꿉니다(UTF-8, UTF-8 BOM, UTF-16 LE와 BE,
  Windows-1252, ISO-8859-1과 -15, Windows-1250, Windows-1251, KOI8-R, Shift_JIS, EUC-JP, GBK, Big5, EUC-KR).
  저장하기 전에는 아무것도 기록되지 않으며, 실행 취소로 되돌릴 수 있습니다. 대상 인코딩이 표현할 수 없는 문자가
  있으면 상태 표시줄에 그 개수와 첫 위치가 표시되고 변환되지 않습니다. 저장도 같은 방식으로 거부되며 `?`를 쓰지 않습니다.
- **줄바꿈.** `LF`, `CRLF`, `CR`를 표시하고, 파일에 여러 종류가 섞여 있으면 `혼합`으로 표시합니다. 메뉴는 파일의 모든
  줄바꿈을 LF, CRLF 또는 CR로 한 번의 실행 취소 단계로 변환합니다. 새로 입력하는 줄은 파일 자체의 줄바꿈을 따릅니다.
  선택한 값이 *줄바꿈* 설정보다 우선합니다.
- **들여쓰기.** `공백: 4` 또는 `탭: 4`를 표시합니다. 메뉴에서 `Tab`과 자동 들여쓰기가 넣을 것(공백 또는 탭),
  크기(1~8: 들여쓰기 단계와 이 파일에서 탭의 너비)를 정하고, 각 줄 앞의 공백을 공백 또는 탭으로 한 번의 실행 취소
  단계로 변환할 수 있습니다.

## Stash, 패치, Git LFS

- **Stash**와 **Pop**은 도구 모음에 있습니다. [Log 다루기](log-and-history.md#브랜치-tag-refs-사이드바)를 참고하세요.
- **패치 만들기**와 **패치 적용**은 commit 메뉴와 ref 메뉴에 있으며, CLI에는 `gitpoulpi patch`가 있습니다.
- Git LFS로 저장된 큰 파일은 내용을 pull하기 전까지 작은 포인터 파일로 표시됩니다. [Git LFS](lfs.md)를 참고하세요.

## 명령줄에서

이 페이지의 모든 기능은 스크립트로 실행할 수 있습니다.

```
gitpoulpi --json status
gitpoulpi stage --file src/lib.rs
gitpoulpi stage --all --allow-sensitive   # after the refusal below
gitpoulpi --json diff
gitpoulpi commit -m "feat: add the helper"
gitpoulpi discard --file src/lib.rs --hunk 1
```

`gitpoulpi stage`도 민감한 파일을 같은 방식으로 거부합니다. 아무것도 스테이징되지 않고 종료 코드는 2이며 `--json`은 `{error: "sensitive_files", files: [{path, reason}]}`(규칙과 가려진 미리 보기이며 값은 절대 표시하지 않음)를 출력합니다. 다시 시도하려면 `--allow-sensitive`를 쓰세요. MCP 에이전트도 같은 응답으로 거부되며 `[mcp] allow_sensitive_staging = true`가 아니면 `allow_sensitive`를 전달할 수 없습니다. 에이전트는 사용자에게 물어보라는 안내를 받습니다.

[CLI 참조](cli-reference.md)를 참고하세요.
