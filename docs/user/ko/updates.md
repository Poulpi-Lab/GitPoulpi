# 업데이트

GitPoulpi는 새 릴리스가 있는지 확인하고, 설치된 방법에 따라 자신의 파일을 직접 교체하거나 설치한 프로그램에 업데이트를 넘깁니다. 사용자가 직접 하지 않으면 아무것도 교체되거나 재시작되지 않습니다.

## 칩과 패널

제목 표시줄에는 앱 이름과 저장소 경로 사이에 실행 중인 버전(`v1.0.0`)이 표시됩니다. 새 릴리스가 알려지면 칩이 강조색의 `v0.2.0 사용 가능`으로 바뀝니다.

`Ctrl+N` 다음 `u`를 누르거나, 명령 팔레트(`Ctrl+P`)에서 **업데이트: 업데이트 패널 보기**를 실행하거나, 칩에 `사용 가능`이 표시되는 동안(또는 업데이트가 진행 중인 동안) 칩을 클릭하면 업데이트 패널이 열립니다. 더 새로운 릴리스가 없을 때 칩을 클릭하면 대신 릴리스 노트 탭이 열립니다. 앱 위에 뜨는 창이며 `Esc`, `q`, 닫기 표시 또는 바깥 클릭으로 닫습니다. 패널에는 다음이 표시됩니다.

- 실행 중인 버전과 **설치 방법**: GitPoulpi가 이 컴퓨터에 설치된 방법입니다(아래의 모든 동작이 이에 따라 정해집니다).
- 업데이트 진행 상태(확인 중, 퍼센트와 함께 다운로드 중, 준비 완료, 실패).
- 이 설치 방법의 절차에 해당하는 버튼, 그리고 명령이 있으면 정확한 명령.
- 관리자가 설정했다면 관리자의 메시지 한 줄.

모든 버튼에는 키(패널의 힌트 줄에 표시됨)와 팔레트 명령이 있으므로 패널은 마우스 없이도 사용할 수 있습니다.

| 버튼 | 키 | 팔레트 명령 |
|---|---|---|
| **업데이트 후 재시작** (또는 **업데이트 실행**) | `u` | 업데이트: 지금 업데이트 |
| **명령 복사** | `c` | 업데이트: 업데이트 명령 복사 |
| **터미널에서 열기** | `t` | 업데이트: 터미널에서 업데이트 명령 실행 |
| **되돌리기** | `v` | 업데이트: 이전 버전으로 되돌리기 |
| **릴리스 노트** | `n` | 도움말: 릴리스 노트 |
| **이 버전 건너뛰기** | `s` | 업데이트: 이 버전 건너뛰기 |
| **공지 열기** (보안 공지가 있을 때만) | `a` | 업데이트: 보안 공지 열기 |
| **지금 확인** | `r` | 업데이트: 지금 업데이트 확인 |
| **닫기** | `Esc` | |

이 설치 방법에 해당하지 않는 명령은 팔레트에서 이유와 함께 회색으로 표시됩니다(예: "이 설치본은 다른 방법으로 업데이트합니다: "업데이트: 업데이트 패널 보기" 참조").

## 설치 방법별 동작

| 설치 방법 | 확인 대상 | 패널의 동작 | 되돌리기 |
|---|---|---|---|
| 릴리스 아카이브 또는 `install.sh` | GitHub 릴리스 | **업데이트 후 재시작**: GitPoulpi가 아카이브를 다운로드해 검증하고, 종료한 뒤 파일을 교체하고 같은 터미널에서 다시 엽니다. | **되돌리기**는 이전 파일로 다시 교체합니다. |
| Windows 설치 프로그램, 나 혼자 사용 | GitHub 릴리스 | 같지만 확인 창이 없습니다. Windows에서는 새 창에서 다시 열립니다. | **되돌리기**로 다시 교체합니다. |
| Windows 설치 프로그램, 모든 사용자 | GitHub 릴리스 | 같지만 Windows가 관리자 승인을 요청합니다. 이 컴퓨터에서 다른 사용자가 실행 중인 GitPoulpi 세션은 종료되며 저장하지 않은 입력은 사라집니다. 거절하면 아무것도 바뀌지 않습니다. | **되돌리기**로 다시 교체하며 같은 확인 창이 뜹니다. |
| Chocolatey | Chocolatey 커뮤니티 피드 | **업데이트 실행**은 `choco upgrade gitpoulpi -y`를 실행합니다(Windows가 관리자 승인을 요청). | 패널에 `choco install gitpoulpi --version <previous> --allow-downgrade -y`가 표시됩니다. |
| Chocolatey, 사내 피드 | 조직의 피드 | **업데이트 실행**은 `choco upgrade gitpoulpi -y --source=<feed>`를 실행합니다. 패키지 매개변수는 다시 보내지 않으므로 배포된 구성은 그대로 유지됩니다. | 피드를 붙인 같은 `choco install` 줄. |
| winget | GitHub 릴리스 | **업데이트 실행**은 약관에 동의한 상태로 `winget upgrade --id GitPoulpi.GitPoulpi --exact --silent`를 실행합니다. 설치가 컴퓨터 전체 범위이면 winget이 직접 관리자 승인을 요청합니다. | 패널에 `winget install --id GitPoulpi.GitPoulpi --version <previous>`가 표시됩니다. |
| Scoop | GitHub 릴리스 | **업데이트 실행**은 GitPoulpi가 완전히 종료된 뒤 `scoop update gitpoulpi`를 실행합니다. | **되돌리기**는 `scoop reset gitpoulpi@<previous>`를 실행합니다. |
| Homebrew | GitHub 릴리스 | **업데이트 실행**은 이 터미널에서 `brew upgrade gitpoulpi`를 실행합니다. | 패널에 `brew install gitpoulpi@<previous>`가 표시됩니다. |
| apt | GitHub 릴리스 | 패널에 `sudo apt update && sudo apt install --only-upgrade gitpoulpi`가 **명령 복사**와 **터미널에서 열기**와 함께 표시됩니다. GitPoulpi는 `sudo`를 대신 실행하지 않습니다. 이 컴퓨터에 GitPoulpi apt 저장소가 없으면 대신 새 `.deb`를 다운로드하라고 안내합니다. | 패널에 `sudo apt install gitpoulpi=<previous>`가 표시됩니다. |
| MSI 패키지 | GitHub 릴리스 또는 관리자의 소스 | 실행할 것이 없습니다. 설치본은 관리자가 관리하며 패널에 관리자의 메시지가 표시됩니다. | 제공되지 않습니다. |
| AUR | GitHub 릴리스 | 패널에 `yay -S gitpoulpi-bin`이 표시됩니다(`paru`도 가능하며 먼저 찾은 쪽을 사용합니다. 도우미가 없으면 `git clone`과 `makepkg -si` 단계). | 제공되지 않습니다. |
| cargo | GitHub 릴리스 | `cargo-binstall`이 설치되어 있으면 `cargo binstall gitpoulpi-cli`, 아니면 `cargo install --locked --git https://github.com/Poulpi-Lab/GitPoulpi --tag releases/v<version> gitpoulpi-cli`가 표시됩니다. | 이전 태그로 같은 명령. |
| Docker 이미지 | GitHub 릴리스 | 실행할 것이 없습니다. 이미지는 통째로 교체됩니다. 패널에 `docker pull poulpilab/gitpoulpi:<version>`과 `:latest`가 표시됩니다. [Docker에서 실행하기](docker.md)를 참고하세요. | 패널에 `docker pull poulpilab/gitpoulpi:<previous>`가 표시됩니다. |
| 쓸 수 없는 폴더에 있는 릴리스 아카이브 | GitHub 릴리스 | 그 위치에서는 GitPoulpi가 스스로 교체할 수 없다고 알리고 **다운로드**를 안내합니다. | 제공되지 않습니다. |
| 개발 빌드(`cargo build`) | 없음 | 업데이트하지 않습니다. 칩은 버전만 표시하고, 패널은 설치 기록이 없다고 알립니다. | 제공되지 않습니다. |

"표시" 행은 스스로 아무것도 실행하지 않습니다. **터미널에서 열기**는 명령이 입력된 터미널을 열고, `Enter`는 사용자가 누릅니다.

관리자가 확인 대상을 다른 곳(사내 피드, 미러, `latest.json`)으로 지정하지 않는 한 릴리스는 항상 프로젝트의 GitHub 저장소에서 옵니다. [엔터프라이즈 배포](enterprise-distribution.md)를 참고하세요. 릴리스 노트는 릴리스 또는 GitPoulpi에 내장된 변경 로그 중 접근할 수 있는 쪽에서 가져옵니다.

## 알림과 자동

`updates.mode`([설정 > 동기화](settings.md#동기화)):

- **알림**(기본값): 하루에 한 번 백그라운드에서 확인하고 칩을 표시합니다. 사용자가 버튼을 누르기 전에는 아무것도 다운로드하지 않습니다.
- **자동**: GitPoulpi가 자신의 파일을 직접 교체하는 경우(릴리스 아카이브, Windows 설치 프로그램) 업데이트를 발견하는 즉시 백그라운드에서 다운로드하고 검증합니다. 그러면 칩에 **재시작하여 업데이트**가 표시되며, 재시작은 여전히 사용자가 선택합니다. 패키지 관리자가 업데이트를 맡는 경우 **자동**은 **알림**처럼 동작합니다.
- **끔**: 요청을 전혀 보내지 않으며 칩에는 버전만 표시됩니다.

**업데이트 채널** 설정(`updates.channel`)은 **안정**과 **시험판**(릴리스 후보 포함) 중에서 고릅니다. **지금 확인**으로 시작한 확인은 하루 한 번 제한을 무시합니다. 네트워크 연결이 없거나, 저장소가 비공개이고 github.com 토큰이 저장되어 있지 않으면 백그라운드 확인은 조용히 실패하며 애플리케이션 로그에 한 줄이 남습니다.

## 재시작과 이후 표시

**업데이트 후 재시작** 또는 **업데이트 실행**을 누르면 세션을 저장하고 창을 닫습니다. 별도의 작은 프로그램 `gitpoulpi-updater`가 작업을 수행하므로, GitPoulpi 자신의 파일이 교체되는 동안 사용 중이지 않고 기다리는 부모 프로세스가 패키지 관리자를 막지도 않습니다. 먼저 GitPoulpi의 백그라운드 데몬을 중지하고(사용자의 다른 창과 MCP 서버도 닫힙니다), 업데이트를 수행하고, 새 `gitpoulpi --version`이 예상한 버전을 출력하는지 확인한 뒤 GitPoulpi를 다시 시작합니다. Linux와 macOS에서는 같은 터미널에서, Windows에서는 새 창에서 시작합니다. 확인에 실패하면 이전 파일을 되돌려 놓습니다.

다음 시작 때 상태 표시줄에 한 줄이 표시됩니다.

- `v1.4.2(으)로 업데이트했습니다`
- `업데이트 실패: <reason>. 이전 버전이 그대로 설치되어 있습니다.`
- `업데이트를 취소했습니다: 관리자 승인이 거부되었습니다. 변경된 것은 없습니다.`

업데이트는 한 번에 하나만 실행됩니다. GitPoulpi의 데이터 폴더에 있는 잠금 파일(쓸 수 있으면 설치 폴더에도 하나)이 두 번째 업데이트를 막으며, 10분이 지난 잠금은 무시하므로 중단된 업데이트가 GitPoulpi를 영구히 잠그지 않습니다. 새 잠금이 있는 동안에는 CLI와 데몬이 시작되지 않습니다.

## 되돌리기

GitPoulpi가 자신의 파일을 직접 교체하는 경우 **되돌리기**는 이전 파일로 다시 교체하고 재시작합니다. 이전 파일은 새 버전이 시작된 뒤 1분 동안 `<name>.old`로 남아 있다가 삭제되므로, 되돌리기는 업데이트 후 첫 실행을 위한 것입니다. 패키지 관리자가 설치를 맡는 경우 되돌리기는 표에 있는 명령이며 패널이 이를 표시하거나 실행합니다. 되돌리기는 저장소가 아니라 GitPoulpi 자신의 파일을 바꾸므로 git 실행 취소 기록에 포함되지 않습니다.

## 검사하고 거부하는 것

무엇이든 교체하기 전에 GitPoulpi는 아카이브, `.minisig` 서명, `.sha256`을 다운로드합니다. 먼저 GitPoulpi에 내장된 프로젝트 릴리스 키로 서명을 검사하며, 서명의 신뢰된 주석에는 이 아카이브와 이 버전이 명시되어 있어야 합니다. 그다음 해시를 검사합니다. 다음은 거부합니다. `.minisig`가 없는 릴리스(릴리스에 서명하기 전에 공개된 이전 릴리스는 업데이터로 설치할 수 없으며, 버전 고정이나 이전 버전으로 돌아가기도 포함됩니다), 다른 키의 서명, 다른 파일이나 다른 버전에 대한 서명, `.sha256`이 없는 릴리스, 일치하지 않는 해시, 이 플랫폼용 이름(`gitpoulpi-<version>-<target>.<zip|tar.gz>`)이 아닌 아카이브, 표식이 다른 버전이나 플랫폼을 가리키는 아카이브, 그리고 GitHub 릴리스 호스트(모든 리디렉션 단계를 검사) 또는 관리자가 설정한 미러 밖의 다운로드 링크. 교체는 전부 아니면 전무입니다. 다른 프로그램이 실행 파일 하나를 붙잡고 있으면 GitPoulpi는 그 파일의 이름을 알리고, 아무것도 바꾸지 않으며, 다음 시도를 위해 다운로드를 남겨 둡니다. Windows에서 모든 사용자용 업데이트는 권한 상승 단계가 다시 검증합니다. 이 단계가 `.minisig`와 `.sha256`을 직접 다운로드해 둘 다 다시 검사하므로, 그 사이에 사용자의 다운로드 폴더에서 바뀐 파일은 거부됩니다. 패키지 관리자(Chocolatey, winget, Scoop, Homebrew, apt, AUR)는 자체 패키지를 직접 검증하므로 그 경우 GitPoulpi는 아무것도 다운로드하지 않습니다.

## 보안 공지

프로젝트는 각 릴리스와 함께 `security.json`을 게시합니다. 보안 공지 목록으로, 식별자, 심각도, `>=1.2.0, <1.4.3` 같은 범위로 나타낸 영향받는 버전, 수정된 버전, 링크, 한 문장 요약이 들어 있습니다. 새 버전을 찾는 매일의 확인이 릴리스와 같은 곳에서 이 파일도 가져옵니다. GitHub는 저장소의 릴리스 페이지, 미러는 `latest.json`이 있는 폴더, 공개 Chocolatey 피드는 GitHub입니다. 공지는 `security.json.minisig`가 프로젝트 키로 검증될 때만 사용됩니다. 서명이 없거나 잘못된 파일은 표시되지 않습니다(무시했다는 한 줄이 활동 로그에 남습니다).

공지가 실행 중인 버전을 명시하면 칩이 빨간색으로 바뀌고 **보안 공지: 이 버전이 영향을 받습니다**가 표시됩니다. 패키지 관리자가 설치를 맡는 경우를 포함해 모든 설치 방법에서 같습니다. 그러면 업데이트 패널이 각 공지를 심각도, 요약, 수정된 버전, 링크와 함께 나열합니다. **공지 열기**(`a`, 또는 팔레트의 **업데이트: 보안 공지 열기**)는 가장 심각한 공지의 링크를 브라우저에서 엽니다. 패키지 관리자가 설치를 맡는 경우 패널에 "패키지 관리자로 업데이트하세요."가 추가됩니다.

업데이트 확인을 끈 경우(`updates.mode = "off"`), `check`가 `none`인 관리자 정책이 있는 경우, `cargo build`로 만든 빌드에서는 아무것도 가져오지 않으며 공지도 표시되지 않습니다. 조직 자체의 NuGet 피드를 사용한다고 해서 GitPoulpi가 GitHub에 접속하지는 않습니다. 그 경우 공지는 정책의 `download_base` 미러에서만 옵니다.

## 관리자가 잠근 설정

관리자는 컴퓨터 전체 정책에서 업데이트 모드, 채널, 고정된 버전, 확인할 위치, GitPoulpi가 스스로 업데이트할 수 있는지 여부를 정할 수 있습니다. 설정에서 해당 행에는 **관리자가 설정함**이 표시되고, 패널에는 관리자의 메시지가 표시되며, 자체 업데이트가 꺼져 있으면 패널은 파일을 교체하는 버튼 대신 명령이나 안내 문구를 제공합니다. 읽을 수 없는 정책 파일은 안전하게 거부 방향으로 처리됩니다. 알림만 제공하고 자체 업데이트는 하지 않습니다. 관리자 쪽 내용은 [엔터프라이즈 배포](enterprise-distribution.md#정책-파일과-레지스트리)에 있습니다.
