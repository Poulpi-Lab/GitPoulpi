# 워크트리

워크트리는 저장소를 체크아웃한 두 번째 사본입니다. 다른 폴더에서 다른 브랜치를
열지만 같은 기록을 공유합니다. Refs 창의 **워크트리** 섹션에 목록이 나오며,
메인 워크트리에는 `(main)`이 붙습니다.

![워크트리가 둘 연결된 저장소의 Refs 창: WORKTREES 섹션에 main (main), hotfix/axis-labels, feature/legend이 나열되고 그 아래에 SUBMODULES 섹션이 있음](../images/worktrees.png)

## 섹션 표시하기

연결된 워크트리가 아직 없는 저장소에서는 이 섹션이 숨겨져 있습니다. 그래도 보려면
(그러면 "워크트리 없음: +로 만들기"라고 표시됩니다) 팔레트 명령
**왼쪽 창: 워크트리 섹션 표시**를 쓰거나, 왼쪽 창의 표시/숨기기 목록(섹션 머리글을
오른쪽 클릭)에서 **워크트리**를 선택하거나, 아래의 만들기 명령 중 하나를 실행하세요.
GitPoulpi는 이 선택을 그 저장소에 대해 기억합니다([설정](settings.md)의
**왼쪽 창 섹션** 참고). 워크트리가 없는 다른 저장소는 여전히 섹션이 숨겨진 채
시작합니다.

## 워크트리 만들기

워크트리 머리글의 **+**(키보드: 섹션에서 `+`, 팔레트: **Refs: 워크트리 만들기...**)가
메뉴를 엽니다.

- **현재 브랜치에서**: 그 브랜치는 메인 폴더에 체크아웃되어 있으므로 대화상자가
  그 위에 새 브랜치(`worktree-<id>`)를 제안합니다.
- **선택한 commit에서**: Log에서 commit을 선택하기 전까지는 회색입니다. 대화상자가
  거기서 시작하는 새 브랜치 `worktree-<id>`를 제안하며, 분리된 워크트리를 원하면 브랜치
  필드를 비웁니다.
- **브랜치 선택...**: 대화상자가 **워크트리 브랜치** 목록이 열린 채로 나타나며, 이미
  있는 브랜치를 열 때 씁니다.

팔레트에도 같은 세 가지가 있습니다(**Refs: 현재 브랜치에서 워크트리 만들기**,
**Git: 선택한 Commit에 워크트리 만들기...**, **Refs: 브랜치를 골라 워크트리 만들기**).
이전 항목도 계속 동작합니다: 브랜치, tag, commit 메뉴의 **워크트리 만들기...**.

![워크트리 만들기 대화상자: 이름, 폴더, Ref, 워크트리 브랜치 필드, "new branch from main" 줄, 새 워크트리를 탭으로 열기 상자, 취소와 만들기 버튼](../images/worktree-create.png)

대화상자는 모든 값을 제안하며 바꿀 수 있습니다. **이름**과 새 브랜치는 둘 다 `worktree-<id>`로
시작하며, `<id>`는 무작위 16진수 8자리(둘이 같음)라서 두 워크트리가 충돌하지 않습니다.

| 필드 | 의미 |
|---|---|
| **이름** | 폴더 이름이 이것을 따릅니다. **브랜치 이름 따르기**(`Alt+N`)는 이름을 `worktree-<branch>`로 설정합니다: 슬래시는 `-`가 되고 단어를 겹쳐 쓰지 않습니다(`worktree-foo`와 `feature/worktree-x`는 그대로 두고, `feature/login`은 `worktree-feature-login`이 됩니다). |
| **폴더** | 저장소와 같은 위치의 `<repository>-<name>`. 폴더 필드에 직접 입력하기 전까지는 이름을 따라갑니다. **찾아보기**로 위치를 고릅니다. |
| **Ref** | *새* 브랜치가 시작하는 곳: 브랜치 또는 commit(목록이며, 입력해서 검색). 기존 브랜치를 고른 동안에는 사용되지 않으며 그렇게 표시됩니다. |
| **워크트리 브랜치** | 하나의 필드에 두 가지 의미가 있으며 아래에 표시됩니다. 로컬 브랜치가 아닌 이름은 Ref에서 새 브랜치를 만듭니다(**main에서 새 브랜치**). 다른 곳에 체크아웃되지 않은 로컬 브랜치(목록에서 고르거나 이름을 입력)는 그대로 거기서 체크아웃합니다(**이 브랜치를 체크아웃**). 목록의 첫 행 또는 빈 필드는 Ref의 브랜치를 체크아웃하며(commit이면 분리), 그 브랜치가 이미 체크아웃되어 있으면 거부됩니다. |
| **다시 생성** | `Alt+R`. 새 `<id>`를 뽑아 이름과 브랜치를 바꿉니다. 직접 입력한 것(직접 쓴 이름이나 브랜치)과 기존 브랜치는 바꾸지 않습니다. **브랜치 이름 따르기**나 AI가 만든 이름은 생성된 것으로 취급합니다. |
| **AI로 이름 짓기** | AI가 켜져 있을 때만 표시됩니다(아래 참고). |
| **새 워크트리를 탭으로 열기** | 기본적으로 켜져 있습니다. |

비어 있지 않은 폴더, 올바르지 않은 이름, git이 거부하는 브랜치 이름, 다른 워크트리가 쓰는
브랜치는 대화상자의 자체 줄에 표시되며 **만들기**는 회색인 채로 남습니다.

### AI로 이름 짓기

[AI](ai.md)가 켜져 있으면 **AI로 이름 짓기**(`Alt+A`)가 대화상자 안에 상자를 엽니다:
*기능, 버그 또는 작업을 설명하세요*. **이름 짓기**는 모델에게 짧은 워크트리 이름과
저장소 자체의 브랜치 이름(`feature/`, `fix/`, 소문자 kebab-case)을 따르는 브랜치 이름을
요청합니다. 결과는 이름(`worktree-<name>`)과 브랜치 필드에 들어가며 계속 편집할 수
있습니다. 이미 있는 브랜치 이름에는 `-2` 접미사가 붙어서 답이 아무것도 모르게
체크아웃하는 일이 없습니다. 상자는 진행 상태를 보여 주고 **중지**(또는 `Esc`)로
취소하며, 실패는 대화상자 안에 표시됩니다. 설명과 로컬 브랜치 이름만 전송됩니다.

## 행 메뉴

워크트리를 오른쪽 클릭하거나(선택한 뒤 메뉴 키, `Shift+F10` 또는 `.`):

- **새 탭에서 열기**: 더블 클릭이나 `Enter`와 같습니다.
- **열기 위치**: **워크트리 열기 가능** 상자가 선택된 [열기 위치](open-in.md)
  항목(설정 > 열기 위치, 모든 항목이 기본적으로 선택됨). 워크트리 폴더를 `${cwd}`로
  하여 실행됩니다.
- **<branch>을(를) 다음으로 merge...**: merge할 대상 브랜치를 고릅니다(기본값은
  메인 워크트리의 브랜치). 일반 merge가 그 브랜치가 체크아웃된 워크트리에서
  사용자의 merge 옵션으로 실행되며, 충돌은 거기서 평소의 충돌 흐름으로
  해결합니다. 어디에도 체크아웃되지 않은 브랜치는 이유와 함께 거부됩니다.
  분리된 워크트리에는 표시되지 않습니다.
- **워크트리 제거...**: 메인 워크트리는 제거할 수 없습니다.

![워크트리 행의 오른쪽 클릭 메뉴: 새 탭에서 열기, 열기 위치, hotfix/axis-labels을(를) 다음으로 merge..., 워크트리 제거...](../images/worktree-menu.png)

**새 탭에서 열기**(또는 더블 클릭, `Enter`)는 워크트리의 폴더를 자체 Log, 상태, 브랜치를 가진 별도의 탭으로 엽니다.

![hotfix/axis-labels 워크트리가 메인 탭 옆의 별도 탭으로 열려 그 commit과 변경된 파일이 보임](../images/worktree-tab.png)

팔레트에도 선택한 행에 대한 같은 동작이 있습니다(**Refs: 워크트리를 열 위치...**,
**Refs: 워크트리 브랜치를 다른 브랜치로 merge...**, **Refs: 워크트리 제거...**,
**Refs: 워크트리를 탭으로 열기**).

## 워크트리 제거하기

깨끗한 워크트리는 간단한 확인만 거칩니다. 그 브랜치가 이미 merge되었다면(upstream,
메인 워크트리의 브랜치 또는 `main` / `master`에) **브랜치 <b>도 삭제** 상자가 기본적으로
선택되어 있고, merge되지 않은 브랜치는 유지된다고 표시됩니다.
**Merge 후 제거...**는 먼저 merge하고, 충돌 없이 merge가 끝난 뒤에만 제거합니다.

commit하지 않은 변경 사항(추적 대상 또는 추적되지 않는 파일)이 있으면 대화상자가
개수와 함께 목록(스크롤 가능)을 보여 주고 다음을 제공합니다.

- **Commit 후 제거**: 대화상자의 메시지 필드를 쓰며, 모든 변경 사항이 스테이징되어
  (`.gitignore` 존중) 워크트리의 브랜치에 commit된 뒤 워크트리가 제거됩니다. 분리된
  워크트리는 같은 대화상자에서 그 commit에 쓸 브랜치 이름을 입력합니다.
- **Stash 후 제거**: 추적되지 않는 파일을 포함한 모든 변경 사항이 수정할 수 있는
  메시지(기본값 "WIP on <folder>")와 함께 stash된 뒤 워크트리가 제거됩니다.
  stash 목록은 모든 워크트리가 공유하므로, 이후 그 stash는 메인 저장소의
  STASHES에 있어 바로 꺼낼 수 있습니다.
- **열어서 commit하기**: commit 메시지에 포커스를 둔 채 워크트리를 탭에서 엽니다.
  아무것도 제거되지 않습니다.
- **그래도 제거**: 두 번째의 명시적 확인을 거친 뒤 변경 사항을 버립니다.

## 실행 취소

워크트리 제거는 실행 취소할 수 없습니다. 폴더가 사라지기 때문입니다. 먼저 저장한
것은 남습니다. commit은 그 브랜치에, stash는 목록에 있습니다. **브랜치 <b>도 삭제**가
추가하는 브랜치 삭제는 저널에 기록되는 일반 삭제이며, **실행 취소**하면 브랜치가
돌아옵니다(폴더는 아닙니다). 워크트리 만들기도 기록에 포함되지 않습니다.

## 스크립트나 에이전트에서

`gitpoulpi worktree changes <path>`는 워크트리의 commit하지 않은 변경 사항을
나열합니다. `gitpoulpi worktree remove <path> [--force] [--commit-message M
[--commit-branch B]] [--stash-message M] [--delete-branch]`는 워크트리를 제거합니다.
MCP 도구는 `worktree_changes`와 `worktree_remove`입니다. `gitpoulpi ai
worktree-name --describe "<task>"`는 AI가 제안하는 워크트리와 브랜치 이름
(`{ name, worktree, branch }`)을 출력하며 아무것도 만들지 않습니다. MCP 도구는
`ai_worktree_name`입니다. [CLI 참조](cli-reference.md)를 참고하세요.
