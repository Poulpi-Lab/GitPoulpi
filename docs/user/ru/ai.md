# Помощь ИИ

GitPoulpi никогда не требует учётной записи, а **ИИ по умолчанию выключен**. Когда
ИИ включён, он может писать сообщения commit'ов и stash'ей, объяснять изменения,
писать описания pull request'ов, предлагать разрешения конфликтов слияния и
разбивать ваши рабочие изменения на несколько commit'ов. Модель ваша: собственный
API-ключ, локальный сервер или уже установленный CLI агента (например, `claude -p`).

Каждый элемент ИИ отмечен фиолетовым `✦`. Пока ИИ выключен:

- Ничего никуда не отправляется.
- Ни один элемент ИИ не показывается: нет кнопки `✦`, команд палитры `ИИ:`,
  пунктов меню ИИ и подсказок клавиш ИИ. Клавиши ИИ ничего не делают.
- Страница ИИ репозитория показывает только «ИИ выключен (Настройки > ИИ)».
- MCP-сервер не перечисляет инструменты `ai_*`. Команды CLI `gitpoulpi ai ...`
  отказывают с тем же сообщением.

**Включить ИИ** действует сразу. Перезапуск не нужен.

С GitPoulpi ИИ можно использовать двумя способами:

| | Встроенный ИИ (эта страница) | Внешний агент |
|---|---|---|
| Что это | GitPoulpi просит у модели сообщение commit'а, объяснение, ... | Claude Code, Cursor, Codex... управляют GitPoulpi как инструментом |
| Где настраивается | Настройки > ИИ (`[ai]`) | в MCP-конфигурации агента, ограничения в `[mcp]` |
| Руководство | ниже | [MCP и агенты](mcp-and-agents.md) |

## Настройка ИИ

1. `Ctrl+,` > **ИИ** > отметьте **Включить ИИ**.
2. Профили - это список вкладки **Профили (подключения)** слева на странице (в узком терминале он стоит сверху):
   выберите профиль, чтобы править его справа (`Enter` переходит к его строкам;
   команда палитры `✦ ИИ: изменить профиль...` переходит к списку). **+ Добавить**
   создаёт ещё один, **Дублировать** копирует выбранный (без его ключа), а
   **Удалить** сначала спрашивает. Выберите **Провайдер** и заполните его поля:

   | Провайдер | Поля | По умолчанию |
   |---|---|---|
   | **Локальный агент** (без ключа, без собственной учётной записи) | **Тип агента** (что это за агент), **Команда** (точная программа: в вашем `PATH`, псевдоним или скрипт-обёртка, либо полный путь), **Аргументы**, делающие его неинтерактивным, и необязательные **переменные окружения**. Запрос передаётся на его stdin, ответ читается из stdout. | Claude Code: `claude`, `-p --model haiku` |
   | **Anthropic** | **Ключ API**, необязательные **Модель** и **Базовый URL** | `claude-sonnet-5`, `https://api.anthropic.com/v1` |
   | **OpenAI** | **Ключ API**, Модель, Базовый URL | `gpt-5`, `https://api.openai.com/v1` |
   | **OpenRouter** | **Ключ API**, Модель, Базовый URL | `openai/gpt-5`, `https://openrouter.ai/api/v1` |
   | **Совместимый с OpenAI** (Ollama, LM Studio, vLLM, корпоративный шлюз) | **Базовый URL** (`.../v1`), **Модель**, необязательный ключ | `http://localhost:11434/v1` (Ollama; у LM Studio `http://localhost:1234/v1`), `llama3` |

   **Пресеты** (всегда можно ввести другое значение):

   ![Выпадающий список «Тип агента» профиля локального агента: Claude Code, OpenAI Codex CLI, Gemini CLI, opencode и другие CLI агентов](../images/settings-ai-presets.png)

   - **Локальный агент > Тип агента** - выпадающий список распространённых CLI
     агентов, самые используемые первыми: Claude Code, OpenAI Codex CLI, Gemini CLI,
     opencode, Cursor Agent, GitHub Copilot CLI, Pi, Qwen Code, Aider, Goose, Crush,
     Amp или *Другой (без подсказок)*. Тип **отделён от команды**: он лишь выбирает,
     какие подсказки вы получите. Выбор типа заполняет **Команду** (пока она ещё
     равна значению по умолчанию предыдущего типа) и **Аргументы** безынтерфейсным
     вызовом (`claude -p`, `codex exec -`, `gemini -p ...`, ...). **Команда** - это
     свободный текст: напишите `/opt/bin/work-claude`, скрипт-обёртку или цель
     псевдонима, и тип с его параметрами, списком моделей и переменными останется.
     Если **Тип агента** пуст, GitPoulpi определяет его по команде.
   - **Параметры аргументов** добавляет или убирает параметры, подходящие для
     однократного использования GitPoulpi, каждый с однострочной причиной: без
     инструментов, без сохранённой сессии, ответ простым текстом, мало рассуждений,
     режим только чтения, без запросов разрешений, без проверки обновлений и
     статистики. Список различается у разных агентов, потому что различаются сами
     агенты (только некоторые умеют отключать инструменты из командной строки; у
     opencode для этого есть переменная окружения). **Модель** перечисляет модели
     этого агента и записывает нужный флаг (`--model haiku` для Claude Code,
     `-m gpt-6-luna` для Codex, `--model provider/model` для opencode); *(по
     умолчанию - без флага)* убирает его. У Amp нет флага модели. `aider` читает
     запрос из `/dev/stdin`, поэтому работает только в Linux и macOS.
   - **Переменные окружения** задаются только для процесса этого агента, никогда
     для GitPoulpi или других профилей. **Добавить переменную окружения**
     предлагает документированные переменные, важные для этого агента, каждую с
     пояснением (отключить телеметрию и проверку обновлений, уровень рассуждений,
     папка конфигурации, ключ API, базовый URL или локальный хост, ...); можно
     также ввести `NAME` или `NAME=value`. После этого у каждой переменной есть
     своя строка **Env NAME**: её значение показано кнопкой (нажмите её, чтобы
     ввести новое; оно сохраняется, когда вы покидаете поле) и кнопка **[x]**,
     которая удаляет переменную. Значением может быть
     `${env:NAME}`, чтобы взять одну из собственных переменных GitPoulpi (удобно
     для ключей API, чтобы они не попадали в `config.toml`). Значения, похожие на
     секреты (имена, оканчивающиеся на `_KEY`, `_TOKEN`, `_SECRET`, ... или
     известные префиксы ключей), показываются точками и вводятся заново. Значения
     никогда не логируются.
   - **HTTP-провайдеры > Пресет провайдера** заполняет базовый URL и модель для
     OpenAI, Anthropic, OpenRouter, Google Gemini, xAI, DeepSeek, Mistral, Groq,
     Together, Fireworks, Cerebras, Perplexity, Moonshot, Qwen (DashScope), Zhipu
     (GLM) и локальных серверов Ollama, LM Studio, llama.cpp, vLLM, Jan и
     LocalAI. **Модель** - выпадающий список моделей этого провайдера, допускается
     свободный текст.

3. Нажмите **Проверить подключение**: *Последняя проверка* покажет
   `подключено: модель ответила` или `сбой: <причина>`.
4. При нескольких профилях выберите **Профиль по умолчанию** внизу; каждое
   действие по-прежнему может указать свой.

![Нижняя часть блока «Профили» страницы ИИ для локального агента: Режим запуска, Аргументы, Модель, Рабочая папка, Тайм-аут (секунды), две строки Env, «Добавить переменную окружения» и «Проверить подключение»](../images/settings-ai-agent.png)

**Ключи API** вводятся клавишей `Enter` на строке **Ключ API** и хранятся в
системном хранилище учётных данных (Git Credential Manager, libsecret / `pass`,
Keychain) под именем `ai:<profile id>`, никогда не в `config.toml`. Без такого
хранилища GitPoulpi так и скажет, а не будет делать вид, что хранит ключ.
**Настройки > SSH и учётные данные > Забыть все имена пользователей и пароли**
удаляет их.

То же в `config.toml` (всё остальное - в [справочнике по
конфигурации](config-reference.md#ai-встроенный-ии-по-умолчанию-выключен)):

```toml
[ai]
enabled = true
default_profile = "claude-code"

[[ai.profiles]]
id = "claude-code"
name = "Claude Code"
kind = "local_agent"      # open_ai | anthropic | open_router | open_ai_compatible | local_agent
command = "claude"        # свободный текст: псевдоним, скрипт-обёртка, абсолютный путь
harness = "claude"        # что это за агент; пусто = определяется по `command`
args = ["-p", "--model", "haiku"]

[ai.profiles.env]         # только для процесса этого агента; ${env:NAME} берёт наши
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC = "1"
ANTHROPIC_API_KEY = "${env:ANTHROPIC_API_KEY}"
```

## Режим запуска: безынтерфейсный или виртуальный терминал

Профиль локального агента запускает своего агента одним из двух способов, по
выбору в строке **Режим запуска** (показывается для Claude Code, OpenAI Codex
CLI и Gemini CLI):

- **Безынтерфейсный (неинтерактивный)**, по умолчанию: однократный режим агента
  (`claude -p`), запрос на stdin, ответ на stdout.
- **Интерактивный (виртуальный терминал)**: GitPoulpi запускает собственный
  экран агента в скрытом терминале, вводит запрос так, как это сделал бы
  человек, ждёт ответа и закрывает агента. Некоторые агенты тарифицируют или
  ограничивают свой безынтерфейсный режим иначе, чем интерактивный; что
  применимо к вам и что условия провайдера говорят о каждом из режимов -
  решает провайдер, так что уточните их у него.

У каждого режима свои **Аргументы**, **Параметры аргументов** и **Модель**:
при переключении режимов ничего не теряется, а интерактивный режим
предлагает только параметры, имеющие смысл без безынтерфейсного флага. Ещё две
строки действуют в обоих режимах:

- **Рабочая папка**: *Выделенная папка* - пустая папка, которой владеет
  GitPoulpi, так что агент не видит проекта и один раз просит довериться ей.
  *Текущий репозиторий* даёт агенту собственный контекст проекта (например, его
  `CLAUDE.md`), и доверие запрашивается один раз для каждого репозитория.
  *По умолчанию* - это выделенная папка в интерактивном режиме, а в
  безынтерфейсном - папка, в которой запущен GitPoulpi, как и раньше.
- **Тайм-аут (секунды)**: сколько агент может работать, прежде чем GitPoulpi
  сдастся и остановит его. Пусто - 120 секунд в безынтерфейсном режиме и 180 в
  интерактивном.

**На вопросы первого запуска отвечаете вы.** Агент, ни разу не запускавшийся в
папке, сначала что-то спрашивает (довериться этой папке, войти в учётную запись,
выбрать тему). GitPoulpi никогда не отвечает за вас: запрос останавливается с
сообщением, а **Открыть агента...** (в профиле или *ИИ: открыть агента* в
палитре команд) один раз открывает агента в видимом терминале, в той рабочей
папке, которую он будет использовать. Ответьте на вопрос, закройте агента и
повторите попытку; ответ запоминает сам агент.

### Открыть агента в папке вкладки

Команда палитры `Вкладка: открыть ИИ-агента здесь` (переназначается как
`palette.tab_open_agent_here`, клавиши по умолчанию нет) открывает ваш терминал в папке
активной вкладки и запускает в нём агента локального профиля агента, чтобы работать с ним
там вручную. Это тот же терминал, что и **Терминал здесь**, и та же команда, что
**Открыть агента...**, но в папке вкладки, а не в собственной рабочей папке профиля. При
одном локальном профиле агента он открывается сразу; при нескольких список под панелью
вкладок спрашивает, какой выбрать. Запрос не отправляется и обращение к ИИ не
начинается: действие - это сам запуск агента, а то, что вы в нём вводите, - ваше.

У строки есть искра ИИ, она скрыта, пока ИИ выключен (**Настройки > ИИ**), и серая
(«локальный ИИ-агент не настроен»), если ни один профиль не является локальным агентом.
В последовательности шаг `tab_open_agent_here` берёт `id` профиля ИИ из параметра
`profile` (пусто: профиль по умолчанию, иначе первый локальный агент). Команду агента
нельзя передать собственному шаблону терминала: терминал открывается в папке, а строка
состояния говорит, какую команду запустить.

Ответ читается из транскрипта сеанса агента для Claude Code (его точный текст,
после чего транскрипт удаляется) и с экрана между двумя строками-маркерами,
которые запрашивает запрос, для Codex и Gemini. Одновременно выполняется не
более двух запусков в виртуальном терминале, а нажатие Esc во время запроса
останавливает агента.

```toml
[[ai.profiles]]
id = "claude-terminal"
kind = "local_agent"
command = "claude"
harness = "claude"
args = ["-p"]                       # безынтерфейсный набор, сохраняется
run_mode = "terminal"               # headless (по умолчанию) | terminal
terminal_args = ["--effort", "low"] # интерактивный набор
workdir = "dedicated"               # default | dedicated | repository
timeout_secs = 180                  # 0 или нет: 120 headless, 180 terminal
```

## Инструкции

Текст, который вы добавляете к тому, что сообщается модели. Встроенный запрос
каждого действия (он задаёт формат ответа) всегда идёт первым и не редактируется;
затем четыре уровня, от самого общего к самому конкретному, каждый только если не
пуст:

1. **Общие инструкции** (каждое действие). Чипы *Быстрой вставки* в редакторе
   вставляют типовые фразы: *Отвечать на `<языке>`*, *Отвечать кратко*,
   *Повелительное наклонение*, *Технический тон*, *Неформальный тон*.
2. **Инструкции рабочего пространства** (каждое действие, каждый репозиторий
   [рабочего пространства](workspaces.md#инструкции-ии-рабочего-пространства)):
   для всех действий и, при желании, для каждого отдельно. Правятся в форме
   «Изменить» рабочего пространства.
3. **Инструкции репозитория** (каждое действие, только этот репозиторий) с
   параметром *Сочетать с общими*: **Дополнить общие** (после них) или
   **Заменить общие** (вместо них).
4. **Инструкции для действия** (*Создание сообщения commit'а*, *Объяснение
   изменений*, *Создание сообщения stash'а*, *Pull Request*, *Композитор commit'ов*,
   *Разрешение конфликтов*, *Код-ревью*), каждый
   блок со своими чипами в своём редакторе (например, *Формат conventional
   commits*, *Лимит 50 символов*) и своим выпадающим списком **Профиль** (`По умолчанию (<имя>)`
   следует профилю по умолчанию).

`Enter` на строке *Свои инструкции* открывает многострочный редактор (`Ctrl+S`
сохраняет, `Esc` отменяет). Над текстом строка *Быстрая вставка* содержит чипы
этого раздела: щёлкните один, чтобы вставить его фразу в позицию курсора. С
клавиатуры `Tab` переходит на строку, `Left`/`Right` выбирают чип, `Enter` или
`Space` вставляет его и возвращает в текст (`Tab` или `Esc` возвращают без
вставки). Чип, фраза которого уже есть в инструкциях, затемнён, и повторная
вставка ничего не делает. Текст - полноценный редактор: щелчок ставит курсор,
перетаскивание или `Shift`+стрелки выделяют, `Ctrl+A` выделяет всё, `Ctrl+C` /
`Ctrl+X` копируют и вырезают выделенное, `Ctrl`+стрелки прыгают по словам,
`Home` / `End`, `PageUp` / `PageDown` и колесо мыши перемещают по длинному
тексту. Сама страница показывает только предпросмотр каждой инструкции.

![Страница ИИ: общие инструкции, затем блоки «Создание сообщения: commit» и «Объяснение изменений» с выпадающим списком профиля и своими инструкциями](../images/settings-ai.png)

**Для репозитория**: **Настройки > Настройки репозитория > ИИ** (пока открыт
репозиторий) содержит инструкции репозитория и для каждого действия профиль и
инструкции, переопределяющие общие. Пустое поле использует общую настройку (она
показана в нём серым); **Сбросить к общим** снимает переопределение. Сохраняется
в `.gitpoulpi/repo-state.toml` репозитория и учитывается также в CLI.

![Страница ИИ репозитория: Инструкции репозитория с выпадающим списком «Сочетать с общими», затем профиль и инструкции для каждого действия](../images/settings-repo-ai.png)

### Как сочетаются уровни

Запрос отправляется в таком порядке: встроенный запрос, **общие**, **рабочего
пространства**, **репозитория**, затем инструкции самого действия. Режим уровня
решает, что происходит с вышестоящими:

- **Дополнить** (по умолчанию): текст уровня добавляется после более общих.
- **Заменить**: текст уровня используется *вместо* всех более общих уровней
  (общего и рабочего пространства, когда заменяет репозиторий). Уровень без
  текста ничего не заменяет.

Инструкции действия следуют той же идее: общие для этого действия, затем
инструкции рабочего пространства для него (добавленные после них или заменяющие
их), а собственное переопределение репозитория для действия побеждает оба.
Используется активное рабочее пространство окна, если оно содержит репозиторий,
иначе первое рабочее пространство, которое его содержит; в командной строке это
рабочее пространство из `GITPOULPI_WORKSPACE`, иначе первое.

Чтобы увидеть, что именно отправляется, уровень за уровнем, выполните
`gitpoulpi ai prompt --action <действие> --repo .` (`base`, `global`,
`workspace`, `repository`, `task` и итоговый `system_prompt`). Команда не
обращается к модели и работает при выключенном ИИ. Задать инструкции
рабочего пространства из скрипта можно командой
`gitpoulpi workspace set-ai-instructions <id> [--action <a>] [--mode
append|replace] --text ...` (или `--clear`).

### Переменные запроса

Любой текст инструкций (общих, рабочего пространства, репозитория, действия) может содержать переменные
`${name}`. Они заменяются своим значением непосредственно перед отправкой запроса
(в сохранённом тексте остаётся `${...}`). Имя, которого нет в таблице, отправляется
как написано, а редактор предупреждает об этом; для буквального `${` пишите `$${`.

| Переменная | Заменяется на | Пример |
|---|---|---|
| `${uilang}` | Язык интерфейса, его английское название | `French` |
| `${repo}` | Имя папки репозитория | `gitpoulpi` |
| `${branch}` | Текущая ветка | `main` |
| `${ref}` / `${commit}` | Короткий sha commit'а, о котором действие (*Объяснение*), иначе HEAD | `4c0443d` |
| `${commit_subject}` | Заголовок этого commit'а | `feat: add search` |
| `${date}` | Локальная дата, ISO | `2026-10-03` |
| `${time}` | Локальное время, `HH:MM` | `14:05` |
| `${datetime}` | Локальные дата и время | `2026-10-03 14:05` |
| `${user}` / `${email}` | `git config user.name` / `user.email` | `Ada Lovelace` |
| `${remote}` | Remote по умолчанию (`origin`, иначе первый) | `origin` |
| `${host}` | `github`, `gitlab`, `other` (другой хостинг) или `none` | `github` |
| `${files}` | Число файлов в diff действия | `3` |
| `${action}` | Выполняемое действие | `commit_message` |

В редакторе инструкций: введите `${`, и всплывающий список покажет подходящие
переменные (`Up`/`Down` выбирают, `Enter` или `Tab` вставляет, `Esc` закрывает);
либо используйте выпадающий список **Переменные** внизу слева (`Ctrl+T` или
`✦ ИИ: вставить переменную запроса` в палитре команд), который вставляет в позицию
курсора. У каждого пункта есть описание, оно показывается в выпадающем списке и в
строке над кнопками, пока вы наводите на него курсор или выделяете его.

|---|---|---|

Модель читает diff запроса, описание и существующие комментарии (и по умолчанию `CLAUDE.md` и `AGENTS.md` проекта: см. | **Скрипт переписывания истории** | В [окне переписывания истории](history-rewrite.md#скрипт-от-ии): кнопка `✦ Написать с ИИ...` в редакторе скрипта или команда палитры `Переписывание: написать скрипт с помощью ИИ...`. | **Правила переписывания истории** | В [окне переписывания истории](history-rewrite.md#правила-от-ии): кнопка `✦ Создать правила с ИИ...`, `Alt+I` или команда палитры `Переписывание: создать правила с помощью ИИ...`. Многострочный диалог показывает, что именно будет отправлено; правила и настройки попадают в окно переписывания, и ничего не запускается в предпросмотр и не применяется за вас. | `ai rewrite-rules "<description>" [--context]` (выводит) |
| **Черновик последовательности** | Опишите [последовательность действий](#черновик-последовательности), которую нужно создать, или как изменить существующую (Настройки > Последовательности, следующий срез окна). | `ai sequence-draft "<description>" [--edit <id>] [--context]` (выводит) |
| **Имя worktree** | В [диалоге создания worktree](worktrees.md#имя-от-ии): кнопка `✦ Имя от ИИ` или `Alt+A` открывает поле, где вы описываете функцию, ошибку или задачу; модель называет worktree и его ветку по принятому в репозитории именованию, и оба имени попадают в поля диалога для правки. Отправляются только ваше описание и названия локальных веток, поэтому диалога «что отправляется» нет. | `ai worktree-name --describe "<task>"` (выводит) |
| **Ответ на хостинге** и **Описание задачи** | Кнопка **Написать с ИИ** (`Alt+E`) в каждом редакторе Markdown, текст которого уходит на хостинг: комментарий, ответ или правка в беседе, комментарий или резюме ревью, описание новой задачи. Черновик попадает в поле; ничего не публикуется. См. [Помощь в написании на хостинге](#помощь-в-написании-на-хостинге). | `ai hosting-reply` (выводит черновик) |
| **Композитор commit'ов** | Меню строки WIP *Составить commit'ы (ИИ)...*, `Ctrl+G C`, команда палитры `✦ ИИ: составить commit'ы из рабочих изменений...` | |

`Esc` отменяет идущий запрос (процесс локального агента убивается).

### Разрешение конфликта слияния

Модель получает путь и язык файла, базовый, текущий (A) и входящий (B) блоки
конфликта с подписями, которые показывает редактор, до 20 строк уже слитого текста
до и после него, а также ваши инструкции (общие, репозитория и *Разрешение
конфликтов* в **Настройки > ИИ**). Она отвечает разрешённым текстом этого одного
конфликта в блоке кода; ответ с маркерами конфликта или болтовнёй вместо кода
возвращается один раз, затем отклоняется. Конфликт больше 40 КБ
(`ai.limits.conflict_bytes`, *Настройки > ИИ > Лимиты*) задерживается за
предупреждением, в котором указаны его размер и лимит, с кнопками *Всё равно
отправить* (только этот запрос, проверки конфиденциальности всё равно
применяются), *Открыть настройку* и *Отмена*; лимит - собственная защита
GitPoulpi, поэтому увеличьте его, если у вашей модели хватает места. Элементы
управления скрыты, пока ИИ выключен, а предложение никогда
ничего не сохраняет, не добавляет в индекс и не разрешает: проверьте результат,
отредактируйте и сохраните как обычно.

### Композитор commit'ов

Модель разбивает рабочие изменения на несколько commit'ов (каждый изменённый файл
ровно в одном; некорректный план возвращается один раз, затем отклоняется). Пока в файлах
остаются конфликты, ничего не запрашивается: диалог перечисляет их и открывает
режим разрешения конфликтов, потому что композитору нужно дерево без
конфликтов. Вы проверяете план, прежде чем будет создан хотя бы один commit:

![Обзор композитора: четыре предложенных commit'а с файлами и кнопки Сброс, Отмена и Создать 4 commit'а](../images/composer.png)

| Клавиша | Мышь | Действие |
|---|---|---|
| `Up` / `Down` (`k` / `j`) | щелчок по строке | перемещение по commit'ам и файлам |
| `Alt+Up` / `Alt+Down` (`K` / `J`), `m` | стрелки, drag and drop | переместить commit; переместить файл в другой commit |
| `Right` / `Left`, `*` | стрелка строки | развернуть / свернуть commit, все сразу (`ui.composer_files` задаёт начальное состояние) |
| `e` / `Enter` | карандаш | изменить сообщение |
| `d` / `Delete` | `drop` / `вернуть` | пропустить commit (его файлы остаются незафиксированными) |
| `n` | `+ свой commit` | вынести файл в отдельный commit |
| `r` | `Сброс` | вернуться к плану модели |
| `Ctrl+S` / `a` | `Создать N commit'ов` | создать их по порядку |
| `Esc` | `Отмена` | выйти, ничего не сделано |

Создание добавляет в индекс файлы каждого commit'а и по очереди делает commit;
рабочее дерево не затрагивается. Файл, лишь частично добавленный в индекс,
попадает в commit целиком. Если шаг не удаётся, процесс останавливается и сообщает, сколько
commit'ов создано.

### Разделение commit'а

Модель читает изменения commit'а, пронумерованные так же, как их нумерует [редактор
разделения](log-and-history.md#разделение-commitа), и предлагает несколько commit'ов с
сообщением для каждого; она умеет группировать hunk'и и отдельные строки. Ответ,
в котором пропущено изменение, одно изменение назначено дважды или названо
несуществующее, отклоняется. В любом случае открывается редактор разделения: либо
с готовым предложением, либо, если модель не справилась, с причиной в заметке, чтобы
вы разделили commit вручную. Пока вы не нажмёте **Разделить** (`Ctrl+S`), ничего не
разделяется; если группировка не подходит, сначала переместите изменения, переименуйте
commit'ы или добавьте ещё один. Профиль и инструкции - те, что называются
*Разделение commit'а* в Настройки > ИИ.

### Скрипт переписывания истории

Вы описываете, что должно сделать переписывание («перенести каждый commit, сделанный
ночью, на следующее утро», «заменить мой старый email новым, только до 2024 года»), а
модель пишет [Lua-скрипт](history-rewrite.md#lua-скрипты) для правила «Скрипт»: с
заголовком, функцией `rewrite_commit(c, ctx)` и помощниками песочницы. Демон
компилирует ответ; если он не компилируется, ошибка один раз возвращается модели. То,
что получилось, показывается в редакторе: прочитайте, проверьте, затем делайте
предпросмотр. Подробности и диалог - в разделе
[Переписывание истории](history-rewrite.md#скрипт-от-ии). Профиль и инструкции - те,
что называются *Скрипт переписывания истории* в Настройки > ИИ.

### Правила переписывания истории

Вы своими словами описываете, как нужно переписать историю («заменить мой старый
адрес a@b.org на c@d.org», «убрать secrets.txt из всей истории»), а модель
предлагает область, некоторые настройки и список
[правил переписывания](history-rewrite.md#правила-от-ии) на языке самого окна
переписывания. **Она только готовит**: ответ заполняет окно переписывания, ничего
не запускается в предпросмотр и не применяется, а запись, которую нельзя
использовать, выводится с причиной, при этом допустимые сохраняются. Правило
«Скрипт» так никогда не создаётся. По желанию вместе с описанием отправляются
область, названия веток и tag'ов и авторы последних commit'ов (флажок, по
умолчанию выключен, показан в панели «Что отправляется»). Профиль и инструкции -
те, что называются *Правила переписывания истории* в Настройки > ИИ.

### Черновик последовательности

Вы своими словами описываете последовательность действий («добавить всё в индекс,
написать сообщение с ИИ, commit и push» или, для существующей, «сначала добавить fetch»),
а модель предлагает название, id, шаги и, если хочет, сочетание клавиш. **Она только
предлагает**: пока вы не примете, ничего не сохраняется и ничего не запускается. Модель
знает только команды, которые может содержать последовательность (список, который ей
дают, строится из той же таблицы, что проверяет последовательность, поэтому расхождений
нет); каждый шаг проверяется отдельно, а неизвестный, разрушительный шаг, шаг, запускающий
другую последовательность, или шаг с невозможной паузой отбрасывается и выводится с
причиной, при этом допустимые остаются. По желанию вместе с описанием уходят имена remote,
id профилей ИИ и названия записей «Открыть в» (по умолчанию выключено; флаг CLI -
`--context`). В терминале `gitpoulpi ai sequence-draft` выводит предложение как JSON (с
`toml`, который читает `gitpoulpi sequence add --file`) и ничего не сохраняет. Профиль и
инструкции - те, что называются *Черновик последовательности* в Настройки > ИИ.

В терминальном интерфейсе то же задание - пункт **Создать с ИИ...** в Настройки >
Последовательности > **Добавить** (палитра: `Последовательность: создать с ИИ...`) и
кнопка **Изменить с ИИ...** у последовательности: диалог, где вы пишете, что нужно, с
флажком контекста (по умолчанию выключен) и вопросом «Что отправляется», затем
предложение, которое можно **Принять**, **Изменить перед сохранением**, **Отклонить** или
отправить заново через **Назад**. Изменение показывает diff с текущей последовательностью
(`+` добавлено, `-` удалено, `~` изменено), а предложенное сочетание сверяется с вашей
раскладкой, но никогда не назначается. Пока вы не примете, ничего не сохраняется (см.
[Последовательности](sequences.md#создание-и-изменение-с-ии)).

### Помощь в написании на хостинге

*Ответ на хостинге* составляет черновик комментария, ответа в обсуждении, комментария к строке кода или
резюме ревью; *Описание задачи* составляет черновик описания новой задачи. **ИИ только пишет черновик.** Текст
попадает в поле ввода (или выводится CLI), чтобы вы прочитали, поправили и отправили его сами. От этой функции
нет пути к записи на хостинг: она не может ничего опубликовать, изменить, разрешить или удалить, ответ CLI и MCP
содержит `"posted": false`, а локальный агент работает только на чтение (см. ниже). Текст покидает GitPoulpi
только через собственную кнопку поля **Отправить** (`Ctrl+Enter`) или **Комментировать**.

**В редакторе Markdown.** Когда ИИ включён, в каждом поле, текст которого уходит на хостинг (комментарий, ответ или
правка в [окне беседы](conversations.md), комментарий ревью, резюме при завершении ревью,
описание новой задачи и описание pull request'а), справа в строке режимов есть кнопка **Написать с ИИ**
(`Alt+E`, во всех полях одна и та же клавиша). Она открывает панель под строкой:

- поле *Что должно быть в этом ответе*, которое заполняется в момент использования (`Enter` пишет
  черновик). В подсказке поля дан пример такого рода («согласиться и попросить падающий тест»). Список
  **Недавние** хранит прежние инструкции (щёлкните по одной или нажмите `Вверх` / `Вниз` в поле; хранятся в
  `ai-hints.toml`);
- *Улучшить мой черновик*: отмечено, если в поле уже есть текст: ИИ исходит из него, а не пишет новый;
- *Разрешить ИИ читать репозиторий*: **каждый раз не отмечено**, если вы не включили отметку по умолчанию (см.
  ниже);
- **Черновик**, **Стоп** (также `Esc`) и **Закрыть**, а также одна строка для хода работы или ошибки.

Обычный диалог «Что отправляется» (`[ai.sent_preview] hosting_reply`, `issue_body`, `pull_request_description`)
показывает запрос до отправки. Помимо системного и пользовательского текста он показывает список **Контекст
репозитория**, когда репозиторий читается: каждую часть с её размером, общий размер относительно предела
(*31.2 KB из 48 KB*), что сокращено, чтобы уместиться, что исключено как чувствительное и какие части взяты
повторно. Для локального агента он сообщает, что агент сам читает репозиторий инструментами только для
чтения, называет их, указывает рабочую папку и то, новая сессия агента или продолженная; каждый диалог
заканчивается строкой *ИИ пишет только черновик. Ничего не публикуется, пока вы сами не отправите.*
Черновик заменяет текст одним шагом отмены, а поле переключается на просмотр, чтобы вы прочитали его до
отправки; `Ctrl+Z` возвращает ваш текст. Описание pull request'а пишется по commit'ам и diff ветки и принимает ту же
инструкцию; пункт о репозитории там неактивен («не для этого текста»).

Что получает модель: заголовок, состояние и описание элемента, обсуждение, на которое вы отвечаете, последние
комментарии (сначала новые, в пределах `ai.limits.hosting_reply_context_bytes`, по умолчанию 49152), разметка,
которую принимает хостинг (поэтому ответ для Jira возвращается как Markdown, который GitPoulpi преобразует),
то, что вы хотите видеть в этом ответе, и, чтобы улучшить ваш текст, ваш черновик. Всё, что написали другие
люди, помечается в запросе как недоверенные данные, поэтому инструкция, спрятанная в комментарии, не
выполняется. При превышении предела ничего не обрезается молча: вас спрашивают, а самые старые комментарии
отбрасываются первыми (обсуждение, на которое вы отвечаете, сохраняется, до половины бюджета); CLI сообщает об
обрезке в `truncated`, а `--send-all` снимает предел.

**Ваш собственный базовый промпт.** Инструкции, с которых начинаются оба действия, можно править: *Настройки > ИИ >
Ответы на хостинге > Базовый промпт* (`ai.hosting_reply.base_prompt`). Если пусто, берётся встроенный промпт: он
просит только текст, в разметке хостинга и на языке беседы, если подсказка не говорит иного. Ваши общие
инструкции, инструкции рабочей области и репозитория по-прежнему идут после него, а текст других людей остаётся
помеченным как недоверенный, что бы вы там ни написали. `ai prompt --action hosting_reply` выводит уровни.

#### Доступ к репозиторию

**По умолчанию выключен и отмечается для каждого случая.** Чтение репозитория даёт заметно лучшие ответы на вопрос
«этот сбой происходит в нашем коде?», но отправляет больше, поэтому вы решаете это каждый раз: *Разрешить ИИ читать
репозиторий* в каждом поле начинается неотмеченным. `ai.hosting_reply.read_repository` (*Разрешать ИИ читать
репозиторий по умолчанию*, выкл.) лишь делает так, что пункт сразу отмечен; `--read-repo` - отметка в CLI. Пункт
неактивен (причина показывается при его активации) в трёх случаях: репозиторий **не клонирован** (беседа другого
репозитория из Radar: читать нечего), у выбранного локального агента **нет режима только для чтения**, которому
доверяет GitPoulpi, или текст **пишется не по репозиторию** (описание pull request'а). Включает его только ваша
собственная отметка.

Что происходит дальше, зависит от профиля:

| Профиль | Что читает репозиторий | Что отправляется |
|---|---|---|
| **API** (совместимый с OpenAI, Anthropic) | GitPoulpi через демон, только чтение | Контекст, который он строит и передаёт модели: карта репозитория (дерево верхнего уровня и пути вокруг найденных файлов), файлы, названные в беседе (весь файл или окно из 40 строк вокруг строки или символа), результаты поиска идентификаторов и сообщений об ошибках из беседы, а для pull request'а его diff. В пределах `ai.limits.hosting_reply_*` (контекст 49152, файл 8192, карта 6144, 20 результатов на запрос, 8 запросов); сокращение идёт в порядке diff, файлы, результаты поиска, карта, и о нём сообщается. Файлы, которые выглядят чувствительными, исключаются, а секреты в остальных сначала маскируются (см. [Конфиденциальность](#конфиденциальность)). |
| **Локальный агент** (Claude Code, Codex), безынтерфейсный | Сам агент, в папке репозитория | Ничего не строится: агент запускается в репозитории с **инструментами только для чтения** и читает то, что ему нужно. Claude Code получает `Read`, `Grep` и `Glob`, а `Bash`, `Edit`, `Write`, `NotebookEdit`, `WebFetch` и `WebSearch` ему запрещены, ни один MCP-сервер не загружается (собственный сервер проекта мог бы публиковать); Codex работает в своей песочнице только для чтения. Учётные данные хостинга из вашего окружения (`GH_TOKEN`, `GITHUB_TOKEN`, `GITLAB_TOKEN`, переменные Jira, Linear, Azure DevOps и Bitbucket, `GIT_ASKPASS`, `SSH_AUTH_SOCK`) удаляются из его среды, поэтому даже неверно настроенный агент не сможет ничего опубликовать или отправить. |

Агента, для которого у GitPoulpi нет подтверждённого режима только для чтения (и любого агента в режиме запуска в
интерактивном терминале), допустить нельзя: пункт остаётся неактивным с пояснением *У этого агента нет режима
только для чтения, которому доверяет GitPoulpi.*

**Кэширование и «Обновить контекст».** Собранное используется повторно, чтобы следующий ответ был быстрым и дешёвым:

- Построенный контекст профиля API хранится для каждого репозитория `ai.hosting_reply.context_ttl_minutes` минут
  (*Хранить контекст репозитория*, по умолчанию 30). Ключ - репозиторий, его `HEAD`, выбор и пределы, а части
  хранятся по отдельности, поэтому для следующей задачи того же репозитория перестраиваются только те части,
  которые у неё не общие. В окне кэши живут в памяти (последние 8 контекстов); CLI хранит их в файлах в своей
  закрытой папке состояния, поэтому второй `ai hosting-reply --read-repo` использует то, что построил первый.
- Новый commit в текущей ветке (`HEAD` сдвигается), смена пределов или истечение времени начинают всё заново.
  То же делает **Обновить контекст**: кнопка в панели, когда репозиторий читается, или `--refresh-context` в CLI. Строка под полем сообщает, что сделал последний черновик: *Контекст собран: частей 5,
  31.2 KB, HEAD a1b2c3d*, *Контекст использован повторно (4 из 5 частей, HEAD a1b2c3d)*, *Кэш провайдера: повторно 12k токенов*,
  *Агент прочитал репозиторий (HEAD a1b2c3d)*, *Сессия агента начата* или *Сессия агента продолжена*.
- **Кэш промптов Anthropic.** Для профиля Anthropic запрос отправляется с базовым промптом и инструкциями как
  одним кэшируемым блоком и контекстом репозитория как вторым, а ваши беседа, подсказка и черновик идут после них,
  поэтому второй ответ на том же контексте читается из кэша провайдера и стоит малую долю (повторные просьбы
  кэшируют также сообщение беседы и самый новый черновик, см. ниже). Счётчики кэша из
  ответа - это то, что показывает *Кэш провайдера: повторно N токенов*. Серверы, совместимые с OpenAI,
  получают тот же устойчивый порядок запроса, чем пользуется их автоматическое кэширование префиксов; GitPoulpi
  не отправляет ничего лишнего.
- **Агент сохраняет свою сессию.** При включённом **Сохранять сессию агента между ответами**
  (`ai.hosting_reply.reuse_agent_session`, по умолчанию включено) и отмеченном *Разрешить ИИ читать репозиторий*
  локальный агент, который это умеет (сейчас Claude Code), запускается с id сессии, а затем возобновляется по
  нему, поэтому прочитанное из репозитория остаётся в его собственной истории, и следующий ответ начинается быстрее.
  Остальные агенты работают в одноразовом режиме. Сессия относится к репозиторию, `HEAD` и действию; новый commit
  или **Обновить контекст** начинает новую; при выключенной опции или неотмеченном пункте каждый ответ - это
  одноразовый запуск, который ничего не сохраняет. Сессия живёт в собственном хранилище агента, GitPoulpi хранит
  только её id (в памяти в окне, в файле только для пользователя для CLI).

**Повторные просьбы: короче, другая инструкция.** Новая просьба в том же редакторе («сделай короче», «добавь
благодарность») - это один обмен. Возобновлённая сессия Claude Code помнит его сама. Для всего остального
(профиль API, Codex и любой другой агент) GitPoulpi возвращает его: запрос несёт сообщение беседы из первого
запроса, затем каждую прежнюю инструкцию и черновик, который на неё ответил, как настоящие реплики чата
(для агента, читающего один документ, это стенограмма в промпте), и в конце только новое: вашу инструкцию и, если
отмечено *Улучшить мой черновик*, текст, который сейчас в поле, с вашими правками. Так повторная просьба никогда
не начинается с нуля, и из репозитория ничего не читается заново. «Что отправляется» показывает всё это. Обмен
ограничен `ai.limits.hosting_reply_context_bytes`, как и беседа: сначала отбрасываются самые старые повторные
просьбы, сообщение беседы и ваш самый новый черновик остаются всегда (в ответе CLI их считает
`context.history_omitted`). В пределах обмена контекст репозитория остаётся контекстом его первого запроса,
поэтому он используется повторно и кэш провайдера работает: для профиля Anthropic кэшируются базовый промпт,
контекст репозитория, сообщение беседы и самый новый черновик, а сервер, совместимый с OpenAI, получает тот же
порядок сообщений для кэширования префиксов. Codex можно было бы возобновлять командой `codex exec resume <id>`,
но id сессии он выбирает сам и лишь печатает его среди своих событий JSON (а `--last` подхватил бы ваши
собственные сессии), поэтому GitPoulpi оставляет его одноразовым и заново передаёт историю. Обмен живёт вместе
с редактором: он заканчивается, когда редактор закрывается или текст отправлен, и **Обновить контекст** тоже
сбрасывает его (следующий запрос становится первым). В обмен попадает только запрос, на который пришёл ответ;
неудавшийся или остановленный не попадает. У описания pull request'а, которое пишется по diff, обмена нет.

В CLI каждый вызов отдельный, поэтому `--continue` подхватывает обмен снова: он продолжает последний
`ai hosting-reply` для той же цели в этом репозитории (те же `--item`, `--reply-to`, `--path`/`--line` или
`--issue-title`) из небольшого файла в закрытой папке состояния. Без `--continue` начинается новый обмен и
заменяет сохранённый. `--continue`, когда для цели ничего не сохранено, - ошибка. В `context` ответа есть
`history_turns` (и `history_omitted`), когда вместе с запросом ушли прежние реплики.

```
gitpoulpi ai hosting-reply --conversation conversation.json --hint "say I will look tomorrow"
gitpoulpi ai hosting-reply --conversation conversation.json --hint "shorter" --continue
gitpoulpi ai hosting-reply --conversation conversation.json --reply-to <thread id> --draft "thx will do"
gitpoulpi ai hosting-reply --conversation conversation.json --read-repo --hint "is this our bug?"
gitpoulpi ai hosting-reply --issue-title "Crash on empty config" --hint "steps to reproduce"
```

`--conversation` принимает файл, `-` для стандартного ввода или сам JSON: тот JSON, который выводят
`hosting issue comments --json` или `hosting review conversation --json` (принимается и прежняя страница с
`header` и `entries`), поэтому работает
`gitpoulpi hosting issue comments 7 --json | gitpoulpi ai hosting-reply --conversation -`; `--item <ref>`
сам запрашивает беседу (`7` или `#7` - задача, `!7` - pull request). С `--read-repo` флаги `--pr-base REV
--pr-head REV` помещают в контекст diff pull request'а; поле `context` ответа сообщает, какие части были прочитаны,
использовались ли они повторно, токены кэша провайдера и сессию агента. Инструмент MCP `ai_hosting_reply` - та же
команда, только для чтения.

## Куда уходит ключ

Ключ API (OpenAI, Anthropic, OpenRouter, сервер, совместимый с OpenAI) привязан к адресу, для которого он был сохранён: к origin базового URL профиля, записанному в `trust.toml` в закрытой папке данных, доступной только пользователю. Если базовый URL позже указывает на другое место, запрос отклоняется до отправки чего-либо, и ключ остаётся там, где был. Выполните `gitpoulpi ai trust <profile> --accept-origin <url>` (или примите это в приложении), чтобы намеренно перенести ключ на новый адрес.

- Обычный `http://` разрешён на этой машине (Ollama, LM Studio на `localhost`); в остальных случаях нужен `gitpoulpi ai trust <profile> --allow-insecure-http on`.
- Самостоятельно размещённый сервер, сертификат которого не ведёт цепочкой к известному центру, принимается только для отпечатка ключа, который вы закрепили через `--accept-certificate <sha256>`; рукопожатие TLS по-прежнему доказывает, что сервер владеет этим ключом.
- Профиль, у которого уже был ключ до появления этой проверки, молча записывается по своему текущему базовому URL при первом использовании.
- У локального агента (`claude -p` и подобных) нет ни ключа, ни HTTP, так что привязывать нечего.

## Контекст ревью

Черновик код-ревью (`✦` или `hosting review suggest`) читает diff запроса, заголовок, описание и
существующие комментарии. Ему можно передать и собственные соглашения проекта в блоке **Project
conventions** перед diff, а локальный агент может работать внутри репозитория. Значения по умолчанию:

| Настройка | По умолчанию | Значение |
|---|---|---|
| `run_in_repository` | `profile` | `profile`: решает *Рабочая папка* профиля ИИ. `yes`: локальный агент запускается в репозитории на время ревью, что бы ни говорил профиль. `no`: не там (профиль с *Репозиторием* использует выделенную папку). У HTTP-профилей нет рабочей папки, поэтому для них это ничего не меняет. |
| `include_claude_md` | вкл. | Передавать модели `CLAUDE.md` репозитория. |
| `include_agents_md` | вкл. | Передавать модели `AGENTS.md` репозитория. |
| `extra_file` | нет | Ещё один файл: путь относительно корня репозитория, абсолютный путь или ссылка. |

Они накладываются слоями, как инструкции, и побеждает самый конкретный слой, поле за полем: глобальная
таблица `[ai.review]`, затем собственные значения репозитория (неустановленное поле наследуется), затем выбор
одного запуска. Репозиторий, который не клонирован, хранит свои значения по `host/project` в
`remote-reviews.toml`, рядом с черновиками его ревью.

Репозиторий может и выключить глобальный дополнительный файл: его `no_extra_file = true` (флажок **Без дополнительного файла** в *Настройках репозитория > ИИ*, в диалоге ✦ «Параметры ревью» и флаг `--no-extra-file` команды `ai review-context`) означает «без дополнительного файла для этого репозитория», что бы ни называл `[ai.review]`. **Пустое** поле **Дополнительный файл** - это другое: оно наследует глобальный файл. Файл репозитория и переключатель исключают друг друга (задание одного сбрасывает другое), а если в файле, правленном вручную, есть оба, побеждает переключатель. Прежний `extra_file = ""` репозитория по-прежнему означает «нет».

Откуда берутся файлы:

- `CLAUDE.md`, `AGENTS.md` и относительный дополнительный файл читаются из **корня** репозитория в ветке,
  на которую нацелен запрос, и никогда из рабочего дерева (оно может быть на другой ветке или с локальными
  правками). При наличии клона - из базового коммита запроса; без него - через API хостинга.
- Абсолютный путь читается с этого компьютера.
- Ссылка на файл на хостинге кода (GitHub `.../blob/<branch>/<path>`, GitLab `.../-/blob/<branch>/<path>`,
  Gitea и Forgejo `.../src/branch/<branch>/<path>` или raw-ссылка) читается через профиль интеграции,
  хост которого совпадает, поэтому приватный репозиторий работает с уже введённым токеном. Ссылка, которой
  не соответствует ни один профиль, и любой другой адрес загружаются анонимно. Имя ветки со слэшем нельзя
  прочитать из ссылки: используйте путь или ссылку на ветку без слэша.
- Отсутствующие `CLAUDE.md` или `AGENTS.md` молча пропускаются; отсутствующий дополнительный файл
  отмечается (`context.problems` в JSON командной строки).
- Каждый файл обрезается на **8 КБ**, а все файлы вместе - на **16 КБ**, с заметной пометкой
  `[CLAUDE.md cut: showing ... of ... bytes]` в том, что читает модель.

Когда локальный агент работает в репозитории, запрос сообщает ему, что файлы в рабочей копии могут не
совпадать с head запроса и что авторитетен diff.

В окне ревью `s` открывает диалог **✦ Параметры ревью** с этими значениями: репозитория поверх глобальных.
Измените их только для этого запуска или отметьте *Сохранить как значения по умолчанию для этого репозитория*,
чтобы сохранить (см. [Параметры ревью](review.md#параметры-ревью)). Значения по умолчанию можно править и в
*Настройки > ИИ* (блок *Код-ревью*, четыре строки), и для репозитория в *Настройки репозитория > ИИ*, где у каждой
строки есть вариант *Использовать общие*, а кнопка *Сбросить к общим* убирает собственные значения репозитория;
поиск по настройкам их находит (`Включать AGENTS.md`, `Дополнительный файл`). Всё, что не удалось передать
модели (отсутствующий дополнительный файл) или что было обрезано, показано на карточке черновика.

Из командной строки:

```sh
gitpoulpi ai review-context                      # глобальные значения по умолчанию и то, что получит ревью
gitpoulpi ai review-context --agents-md off      # сохранить глобальное значение
gitpoulpi --repo ~/work/app ai review-context --claude-md off --context-file docs/REVIEW.md
gitpoulpi ai review-context --project github.com/acme/app --context-file https://github.com/acme/rules/blob/main/review.md
gitpoulpi ai review-context --repo ~/work/app --reset   # снова следовать глобальным значениям
gitpoulpi hosting review suggest 12 --claude-md off --context-file docs/REVIEW.md --run-in-repo no
```

`ai review-context` не требует модели и работает при выключенном ИИ. `ai prompt --action code_review` выводит
действующий контекст как `review_context`. Те же четыре настройки - `ai.review.*` в
`config.toml` ([справочник](config-reference.md#ai-встроенный-ии-по-умолчанию-выключен)).

## Лимиты ввода

У каждого ввода, который GitPoulpi помещает в запрос, есть предел размера: настройка в
`[ai.limits]` (*Настройки > ИИ > Лимиты*). Пределы - собственная защита GitPoulpi (окно
контекста модели у каждой модели своё): увеличьте их, если у вашей модели хватает места,
уменьшите, чтобы запросы были небольшими.

| Настройка (`ai.limits.`) | По умолчанию | Что ограничивает |
|---|---|---|
| `conflict_bytes` | 40000 | Базовый, текущий и входящий блоки одного конфликта merge |
| `diff_bytes` | 60000 | diff для сообщения commit'а, объяснения, имени stash'а, описания pull request'а, плана commit'ов или разделения; весь diff код-ревью |
| `review_file_bytes` | 12000 | diff одного файла в код-ревью |
| `review_text_bytes` | 4000 | Описание проверяемого pull request'а |
| `review_threads_bytes` | 6000 | Уже существующие комментарии ревью |
| `review_context_file_bytes` | 8192 | Один файл контекста проекта в ревью (`CLAUDE.md`, `AGENTS.md`, дополнительный файл) |
| `review_context_bytes` | 16384 | Все файлы контекста ревью вместе |
| `hosting_reply_context_bytes` | 49152 | Элемент и беседа, передаваемые для черновика ответа |
| `hosting_reply_file_bytes` | 8192 | Один файл репозитория для черновика ответа (когда ИИ читает репозиторий) |
| `hosting_reply_map_bytes` | 6144 | Карта репозитория для черновика ответа |
| `hosting_reply_hits_per_term` | 20 | Результатов поиска на запрос (от 1 до 200) |
| `hosting_reply_terms` | 8 | Поисковых запросов (от 1 до 50) |

**Ничего не обрезается молча.** Когда ввод превышает предел, запрос ждёт, а окно
*Превышен лимит ИИ* перечисляет, что именно превышено: какая часть (diff, файл,
описание, файл контекста), её размер, предел и настройка. Ревью перечисляет все
превышенные части в одном окне. Кнопки, у каждой своя клавиша:

- *Отправить всё* (`в`): только этот запрос, ничего не обрезается. Он всё равно проходит
  проверки конфиденциальности (секреты заменяются, конфиденциальные файлы
  исключаются) и, если она включена, панель *Что отправляется*, которая идёт следом.
- *Отправить с обрезкой* (`с`): то, что превышает предел, обрезается, как и раньше;
  каждая строка окна говорит, что не включено (конец diff, последние блоки изменений,
  файлы, которые не поместились).
- *Открыть настройку* (`н`): отменяет запрос и открывает *Настройки > ИИ > Лимиты* на
  первом из перечисленных пределов. Фокус стоит здесь: Enter никогда ничего не отправляет.
- *Отмена* (`о`, `Esc`, крестик или щелчок снаружи): ничего не отправляет.

Конфликт - исключение: он никогда не обрезается. *Всё равно отправить* (`в`) отправляет
его целиком один раз; в окне конфликта *Открыть настройку* - `н`, *Отмена* - `о`.

Ничто не запускает запрос к ИИ само, поэтому нет фонового запуска, который мог бы
спросить: каждый запрос начали вы. Запуск, который не может спросить (CLI и MCP),
обрезает как раньше и сообщает об этом; см. ниже.

**В командной строке** на диалог некому ответить, поэтому ввод сверх предела обрезается
как раньше, а ответ сообщает, что обрезано:
`truncated: [{part, detail?, bytes, limit, setting}]` (есть, только если что-то
обрезано; `part` - одно из `diff`, `split_hunks`, `review_diff`, `review_file`,
`review_text`, `review_threads`, `context_file`, `context_total`). `--send-all`
(псевдоним `--no-truncate`) вместо этого отправляет всё целиком: у `ai` (все его
команды, включая `ai resolve-conflict`, где конфликт сверх предела иначе
отклоняется), у `commit --ai`, у `stash push --ai` и у `hosting review suggest`.
У инструментов MCP тот же аргумент `send_all` и то же поле `truncated`.

## Конфиденциальность

- Ничего не отправляется, пока вы не нажмёте кнопку или не запустите команду.
  Никакого фонового ИИ, никакой телеметрии, никакой учётной записи GitPoulpi.
- Что отправляется: запрос (встроенный, затем ваши инструкции) и diff, о котором
  вы спросили; для pull request'а также заголовки commit'ов ветки. diff
  больше 60 КБ (`ai.limits.diff_bytes`) никогда не обрезается молча: см.
  [Лимиты ввода](#лимиты-ввода).
- Запрос на скрипт переписывания истории отправляет вашу инструкцию и фиксированный
  контракт скрипта (API песочницы скриптов). Автор, дата и тема до 20 commit'ов уходят
  вместе с ним **только** если в диалоге отмечено *Отправить выборку* (по умолчанию
  выключено; в CLI нужен `--sample N`). Содержимое файлов и секретные значения не
  отправляются никогда.
- Это уходит только к профилю, выбранному для этого действия: на хост этого API
  или на stdin вашей команды локального агента (который затем делает то, что
  делает этот агент).
- Ключи API использует сам процесс `gitpoulpi`, и они никогда не попадают ни к
  демону, ни к другим клиентам окна, ни к MCP-клиенту.
- Сгенерированный текст никогда сам не попадает в commit, не отправляется и не применяется.

### Что вычищается из запроса

Каждый запрос, каким бы действием он ни отправлялся и какой бы провайдер его ни
получал (размещённый API или локальный агент), сначала проходит один и тот же шаг
очистки:

- **Секреты скрываются** (`[ai.privacy] redact_secrets`, по умолчанию включено).
  Токен с известным префиксом, блок закрытого ключа, JWT, пароль в URL и строка
  `password = value`, значение которой выглядит случайным, заменяются на
  `[REDACTED:<rule>]`. Список не исчерпывающий: находятся распространённые формы
  (тот же сканер, что в `rewrite scan-secrets`).
- **Конфиденциальные файлы исключаются** (`[ai.privacy] exclude_sensitive_files`,
  по умолчанию включено). Diff файла, подходящего под `[privacy] sensitive_patterns`
  (`.env` и `.env.*`, кроме файлов `.example`, `.sample` и `.template`, `*.pem`,
  `*.key`, закрытые ключи SSH, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `*.crt`,
  `*.cer`, `*.der`, `*.kdbx`), в запрос не входит. Часть разделения или список файлов
  композитора, называющие такой файл, вырезаются так же, поэтому план для него может
  быть отклонён как неполный: добавьте в индекс или разделите этот файл сами.

Отключение любого из них - ваш выбор, и Настройки > ИИ показывают под ним красную
строку, пока он выключен.

**Что отправляется, до отправки.** Прежде чем запрос уйдёт, TUI показывает диалог
**Что отправляется**: инструкции и запрос после очистки (та же панель, что в
диалогах переписывания истории, прокручиваемая, `Alt+W` показывает или скрывает её),
сколько секретов заменено и какие файлы исключены (правило и маскированный
фрагмент вроде `ghp_****abcd`, но никогда не значение), флажок **Больше не
показывать для «<действие>»** и кнопки **Отправить** / **Отмена** (`Esc`, крестик
закрытия и щелчок снаружи отменяют; ничего не уходит до «Отправить»). Флажок
записывает `[ai.sent_preview] <action> = false`; Настройки > ИИ > *Показывать, что
отправляется, перед...* содержат по переключателю на каждое действие и кнопку
**Показывать всё снова**. Два диалога переписывания истории уже показывают свой
запрос, поэтому переключателя у них нет.

**В командной строке** каждый ответ `ai ...` (и `hosting review suggest`) несёт
`privacy: {redactions: N, excluded_files: [...]}`, а `--print-sent` выводит
очищенные системный и пользовательский текст как `{sent: [{system, user}], privacy,
dry_run: true}`, не обращаясь к модели (нужен `ai.enabled = true`, ключ и сеть не
нужны).

**Ограничение.** Локальный агент, чья рабочая папка - репозиторий
(`workdir = repository` или *Запускать агента в репозитории* для ревью), может сам
читать файлы: очистка охватывает то, что GitPoulpi отправляет ему, но не то, что он
открывает самостоятельно. Используйте рабочую папку `dedicated`, чтобы не пускать его
в репозиторий.

## Устранение неполадок

| Симптом | Решение |
|---|---|
| Нигде нет `✦` | ИИ выключен: **Настройки > ИИ > Включить ИИ**. |
| `✦` серая | Ничего не добавлено в индекс (сообщение commit'а). |
| *Проверить подключение*: команда не найдена | **Команды** локального агента нет в `PATH`, который видит GitPoulpi: запустите GitPoulpi там, где работает `claude --version`, или укажите полный путь. |
| Локальный агент зависает или показывает интерактивный экран | В *безынтерфейсном* режиме запуска добавьте его безынтерфейсный флаг (`-p` для Claude Code) в **Аргументы** или выберите его **Тип агента** заново, чтобы восстановить безынтерфейсный вызов. Для интерактивного экрана и нужен режим запуска *Интерактивный (виртуальный терминал)*. |
| "Use "Open the agent"..." | Агент задал вопрос первого запуска (довериться папке, войти в учётную запись). Нажмите **Открыть агента...** в профиле, ответьте, закройте агента и повторите попытку. |
| Запрос в виртуальном терминале завершился по тайм-ауту | Сообщение заканчивается последними строками экрана агента: там видны запрос разрешения, вход в учётную запись или вопрос об обновлении. Ответьте на него через **Открыть агента...** или увеличьте **Тайм-аут**. |
| `сбой:` 401 | Неверный ключ или ключ другого провайдера: введите его заново. |
| `сбой:` 404 | Такой **Модели** там нет: очистите поле, чтобы использовать модель по умолчанию. |
| `сбой:` ошибка подключения (Ollama, LM Studio) | Сервер не запущен, либо в **Базовом URL** неверный порт или нет `/v1`. |
| Ключ показывает `(не задан)` после ввода | Нет хранилища учётных данных: настройте его (`git config --global credential.helper ...`) и введите ключ снова. |
| *Превышен лимит ИИ* | Ввод запроса превышает предел из `[ai.limits]`: выберите *Отправить всё*, *Отправить с обрезкой*, *Открыть настройку* или *Отмена* (см. [Лимиты ввода](#лимиты-ввода)). |
| «Конфликт слишком велик для отправки» | Конфликт превышает `ai.limits.conflict_bytes` (по умолчанию 40000). *Всё равно отправить* отправляет его один раз; *Открыть настройку* ведёт к пределу в Настройки > ИИ > Лимиты. |
| Неверный язык или стиль | Добавьте инструкции; чипы *Быстрой вставки* в редакторе делают это быстро. |
| Композитор говорит, что план некорректен | Модель пропустила или повторила файл: повторите или используйте модель посильнее. |

## Старые файлы конфигурации

Старый `config.toml` с `[[ai.presets]]` и `[ai.defaults]` по-прежнему загружается:

- Пресет по умолчанию каждого действия становится его `[ai.actions.<action>]`
  (`system_prompt` становится `instructions`).
- Каждый старый пресет сохраняется в `[[ai.legacy_presets]]`. **Настройки > ИИ**
  показывает их в разделе *Старые пресеты (до редизайна)* с пунктом *Удалить архив*.
- Прежний `[preferences.ai_presets]` репозитория становится переопределением
  репозитория.

Встроенный запрос теперь всегда идёт первым. Если старый запрос копировал
встроенный, удалите скопированную часть и оставьте только то, что хотите добавить.
