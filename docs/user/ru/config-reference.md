# Справочник по конфигурации

Каждый ключ `config.toml`, его значение по умолчанию и что он делает. Файл редко
приходится править вручную: [экран настроек](settings.md) (`Ctrl+,`) записывает его
по мере ваших изменений, как и `gitpoulpi config set`.

## Где он находится и как выбирается значение

| | |
|---|---|
| Файл | `%APPDATA%\GitPoulpi\config.toml` (Windows), `~/.config/gitpoulpi/config.toml` (Linux), `~/Library/Application Support/GitPoulpi/config.toml` (macOS). `gitpoulpi config path` выводит путь. |
| Другая папка | `GITPOULPI_CONFIG_DIR=<dir>` переносит всю папку конфигурации (файл, `sessions/`, файлы портов демона): переносимая установка, тест или агент, которого нужно держать подальше от ваших настроек. |
| Приоритет | встроенное значение по умолчанию, затем `config.toml`, затем переменная `GITPOULPI_*`, затем флаг командной строки. Побеждает самое позднее. Неверное значение (опечатка в варианте выбора в файле, неверная переменная) - это ошибка, а не молчаливый пропуск. |
| Переменные | Напишите ключ заглавными буквами и замените точки подчёркиваниями: `general.auto_prune` превращается в `GITPOULPI_GENERAL_AUTO_PRUNE`. Только для ключей, которые GitPoulpi действительно читает (не для помеченных ниже как *не используются* и не для списков вроде `ui.log_columns_hidden`). |
| Флаги | `--backend git2\|system` переопределяет `general.default_backend` для демона, который запускает эта команда. |
| Токены и ключи | Никогда не хранятся в этом файле. Токены хостингов и API-ключи ИИ попадают в системный помощник учётных данных (Git Credential Manager, libsecret / `pass`, Keychain); в файле лежит только ссылка (`token_ref`). Без помощника сохранение токена завершается ошибкой с сообщением, и токен живёт только до конца сеанса. |

```
gitpoulpi config path                          # файл и существует ли он уже
gitpoulpi config get general.auto_stash        # значение, слой, откуда оно взято (default/file/env/flag), и читает ли его что-нибудь
gitpoulpi --json config get ui                 # целый раздел
gitpoulpi config set general.auto_stash always # проверяется по схеме, затем записывается
```

`config set` держит файл разреженным (только ключи, которые кто-то задавал) и сохраняет
ключи, о которых речи не шло, но удаляет комментарии. Он отказывается принимать списки и
целые таблицы, кроме `keybindings.*` (несколько последовательностей клавиш через пробел;
пустое значение снимает привязку). `[[profiles]]`, `[[integrations]]` и `[[ai.profiles]]`
правьте в настройках или вручную.

В таблицах **Перезапуск** означает, что значение читается при запуске; всё остальное
применяется сразу (или при следующем обновлении, загрузке или закрытии настроек).

## `[general]`

| Ключ | По умолчанию | Значения и действие |
|---|---|---|
| `general.default_backend` | `"git2"` | `git2` (libgit2 с откатом на программу `git` для индексации, слияния, rebase, stash и сети) или `system` (только установленный `git`). Работающий демон сохраняет свой бэкенд: **перезапустите** его (`gitpoulpi daemon restart`). |
| `general.auto_stash` | `"ask"` | Когда локальные изменения мешают checkout, pull, merge или rebase: `ask` (диалог в TUI; CLI и MCP завершаются ошибкой и называют `--autostash`), `always` (stash, выполнить, pop) или `never` (отказать). См. [Auto-stash](log-and-history.md#auto-stash). |
| `general.include_untracked_in_autostash` | `false` | Auto-stash берёт и неотслеживаемые файлы. |
| `general.initial_commits_in_graph` | `5000` | Сколько commit'ов Log загружает сначала (не меньше 500). Большее значение стоит памяти и времени отрисовки на огромных репозиториях. |
| `general.lazy_load_commits_in_graph` | `true` | Подгружает более старые commit'ы, когда вы прокручиваете к концу. Выкл.: Log останавливается на начальном числе. |
| `general.commits_per_lazy_page` | `1000` | Commit'ов на одну фоновую страницу (не меньше 50). |
| `general.max_commits_in_graph` | `100000` | Предел, на котором останавливается ленивая загрузка (около 300 байт на commit); `0` = без предела. |
| `general.auto_fetch_interval_minutes` | `5` | Фоновый Fetch All каждые N минут, от 0 до 60; `0` = выкл. **Перезапуск.** |
| `general.auto_fetch_interval_unit` | `"auto"` | Единица, в которой Настройки показывают интервал: `minutes`, `hours` или `auto`. Только отображение: интервал всегда равен `auto_fetch_interval_minutes` минут. `auto` (и конфигурация без этого ключа) выбирает наибольшую единицу, на которую минуты делятся нацело (60 читается как «1 час», 45 - как «45 минут»); неподходящая единица игнорируется. Настройки записывают оба ключа; старый GitPoulpi игнорирует единицу и по-прежнему читает минуты. |
| `general.fetch_on_tab_open` | `true` | Fetch All при открытии вкладки (пропускается, если GitPoulpi загружал этот репозиторий меньше 60 с назад). |
| `general.auto_prune` | `true` | Загрузки также удаляют (prune) исчезнувшие ветки удалённого отслеживания. |
| `general.auto_prune_tags` | `false` | Fetch также удаляет локальные tag'и, удалённые на remote (только те, что там были; tag, который вы не отправляли, остаётся). Git 2.41+. |
| `general.hosting_refresh_minutes` | `5` | Обновление списков pull request / задач и значка на панели инструментов, от 0 до 120; `0` = только по запросу и по событиям. |
| `general.hosting_refresh_unit` | `"auto"` | Единица, в которой Настройки показывают период обновления: `minutes`, `hours` или `auto`, читается так же, как `general.auto_fetch_interval_unit`. Только отображение. |
| `general.hosting_post_as` | `""` | Имя, от которого публикуются сообщения на хостинге, когда токен репозитория принадлежит боту (токен GitHub App), например `my-app[bot]`: показывается в каждом поле ввода и по нему опознаются ваши комментарии. Пусто: имя запрашивается у хостинга, иначе узнаётся по первой публикации. Репозиторий может переопределить его (Настройки, SSH и учётные данные репозитория). |
| `general.keep_submodules_up_to_date` | `false` | После checkout или pull выполняет `git submodule update --init --recursive`, если подмодуль перестал соответствовать. См. [Подмодули](submodules.md). |
| `general.default_branch_name` | `"main"` | Первая ветка репозитория, созданного через Init; пусто - решает git. Ничего не переименовывает. |
| `general.delete_orig_files_after_merge` | `false` | После успешного слияния удаляет резервные файлы `*.orig`. |
| `general.remember_tabs` | `true` | Снова открывает вкладки прошлого сеанса. Если выключено, запуск внутри репозитория открывает только этот репозиторий, а запуск вне репозитория - только Главную. **Перезапуск.** |
| `general.radar_enabled` | `true` | [Radar](radar.md): его вкладка, команды палитры, `Alt+R` и фоновая загрузка данных. Выкл. скрывает всё это, и для него ничего не загружается. Применяется сразу; в сборке без функции `radar` не показывается. |
| `general.startup_tab_in_repo` | `"current-repo"` | Вкладка, на которой открывается запуск, если папка, из которой он выполнен, находится внутри репозитория: `"current-repo"` (вкладка этого репозитория, при необходимости открытая), `"last"` (вкладка, активная при последнем выходе), `"home"` или `"radar"`. Репозиторий, заданный через `--repo`, всегда открывает собственную вкладку. `"last"` открывает «Главная» при выключенном `remember_tabs` или если ничего не запомнено; `"radar"` открывает «Главная», если Radar выключен или отсутствует в сборке. Читается один раз при запуске; нужен перезапуск. |
| `general.startup_tab_outside_repo` | `"home"` | Вкладка, на которой открывается запуск, если папка, из которой он выполнен, не является репозиторием (например, папка пользователя): `"home"`, `"last"` или `"radar"`. `"last"` открывает «Главная» при выключенном `remember_tabs` или если ничего не запомнено; `"radar"` открывает «Главная», если Radar выключен или отсутствует в сборке. Читается один раз при запуске; нужен перезапуск. |
| `general.startup_tab_launcher` | `"last"` | Вкладка, на которой открывается запуск, если GitPoulpi запущен созданным им ярлыком на рабочем столе или в меню «Пуск» (он передаёт `--launcher`), независимо от папки: `"home"`, `"last"` или `"radar"`. Приоритетнее двух настроек выше. `"last"` открывает «Главная» при выключенном `remember_tabs` или если ничего не запомнено; `"radar"` открывает «Главная», если Radar выключен или отсутствует в сборке. Читается один раз при запуске; нужен перезапуск. |
| `general.group_worktree_tabs` | `true` | Держит вкладки связанных рабочих деревьев репозитория сразу после его вкладки: когда рабочее дерево открывается, когда его вкладку оттащили в сторону (она возвращается к своей группе; вкладка репозитория возглавляет группу, а её рабочие деревья идут следом) и когда настройка включается. Выкл.: вкладки остаются там, куда вы их поставили. |
| `general.undo_depth` | `100` | Сколько операций может откатить отмена; `0` = без ограничения. |
| `general.conflict_detection` | `true` | Проактивное обнаружение конфликтов: значок в Log, если merge текущей ветки в ветку, от которой она ответвилась, привёл бы к конфликту; считается в фоне (слияние в памяти: файлы, индекс и ссылки не меняются). Репозиторий может отключить его для себя (`[preferences] conflict_detection`). У базовых веток, с которыми идёт сравнение, есть собственные списки: [`[conflict_prevention]`](#conflict_prevention-списки-базовых-веток). См. [Разрешение конфликтов слияния](merge-conflicts.md#предотвращение-конфликтов). |
| `general.dev_mode` | отсутствует (автоматически) | Для тех, кто собирает GitPoulpi из клона репозитория; в Настройках никогда не показывается. Отсутствует: включён, когда запущенный exe лежит в `<checkout>/target/<profile>/` (`Cargo.toml` и `crates/gitpoulpi-tui` рядом с `target`). `true` / `false` задаёт его принудительно. Режим разработчика открывает только `ui.launcher_build`. |
| `general.journal_outside` | `true` | Записывать то, что оболочка или ИИ-агент делают с ветками, tag'ами, stash'ами и HEAD, как записи истории отмен с пометкой «внешнее», чтобы `Ctrl+Z` мог это откатить. Правки файлов не фиксируются. Нужна `undo_enabled`. См. [Отмена и повтор](undo-redo.md#изменения-сделанные-вне-gitpoulpi). |
| `general.undo_enabled` | `true` | `false`: учёт для отмены не ведётся (самый быстрый режим), история отмены стирается, кнопки Undo/Redo исчезают. См. [Отмена и повтор](undo-redo.md). |
| `general.active_profile` | `""` | Идентификатор профиля `[[profiles]]`, от имени которого создаются commit'ы. Пусто или профиль с пустым именем либо email: `user.name` / `user.email` из git. |
| `general.external_editor` | `""` | Команда пункта *Открыть во внешнем редакторе* для файла, например `code -r {file}`. Пусто: VS Code, если он установлен, иначе значение системы по умолчанию. |
| `general.external_diff_tool` | `""` | Команда для *Открыть во внешнем diff-инструменте*: `{local}` (версия из commit'а / HEAD), `{remote}` (версия рабочего дерева / индекса). Пусто: `git difftool --no-prompt`. |
| `general.external_merge_tool` | `""` | Команда для *Открыть во внешнем инструменте merge* на карточке конфликта (двоичный, LFS или слишком большой файл): `{base}`, `{local}` (A, текущее), `{remote}` (B, входящее) и `{merged}` (файл, в который инструмент записывает результат; GitPoulpi добавляет его в индекс, если инструмент завершился успешно). Пусто: `git mergetool --no-prompt`. |
| `general.file_explorer` | зависит от ОС | Команда для *Показать в папке*: `{path}` (файл), `{dir}` (его папка). По умолчанию: `explorer.exe /select,"{path}"`, `open -R "{path}"`, `xdg-open "{dir}"`. |

Три шаблона команд сначала разбиваются на аргументы (`"..."` объединяет слово), и
только потом подставляются плейсхолдеры, поэтому пути с пробелами остаются одним аргументом.
Оболочка не участвует.

```toml
[[profiles]]                # профили идентичности для commit'ов (Настройки > Профили)
id = "work"
name = "Work"
author_name = "Jane Doe"
author_email = "jane@work.example"
```

## `[ui]`

**Log и граф**

| Ключ | По умолчанию | Значения и действие |
|---|---|---|
| `ui.graph_renderer` | `"auto"` | `auto` (изображение там, где терминал умеет его рисовать, иначе символы), `image`, `text`. **Перезапуск.** |
| `ui.image_protocol` | `"auto"` | Как картинки (граф, аватары) попадают в терминал: `auto`, `kitty`, `iterm2`, `sixel`, `none`. `auto` = протокол Kitty в kitty, Ghostty, iTerm2 3.7.7 и новее и herdr с `kitty_graphics = true`; протокол iTerm2 в WezTerm и Rio (с прозрачностью), более старом iTerm2 и mintty (с непрозрачной подложкой); sixel (колонка графа и аватары) в Windows Terminal, foot, Tabby, Konsole, mlterm, в tmux, если терминал за ним понимает sixel, и в любом терминале, чей ответ при запуске называет sixel (xterm, запущенный с `-ti vt340`, терминал VS Code с включёнными картинками); символы в zellij, screen и неизвестных терминалах. В tmux картинки kitty требуют здесь `kitty` и `allow-passthrough on` ([Мультиплексоры](multiplexers.md)). Если псевдоконсоль терминала теряет картинки или смещает их (WezTerm 20240203, Rio и mintty в Windows), используйте `ui.graph_renderer = "text"` ([Выбор терминала](terminals.md#windows)). **Перезапуск.** |
| `ui.theme` | `"system"` | Цветовая тема: встроенный slug (`gitpoulpi theme list` выводит их все), slug файла в `<config>/themes/` или `system` (следует светлому или тёмному фону терминала, определяемому при запуске; прежнее значение `default` означает то же). `config set` отвергает неизвестные имена. См. [Темы](themes.md). |
| `ui.graph_color_theme` | `"theme"` | Палитра полос: `theme` (как в теме) или любое имя палитры полос: `gitpoulpi`, `light`, `material`, `serie` и палитры остальных тем. |
| `ui.graph_lane_background` | `"off"` | `off` или `row_tint` (слабая полоса цвета полосы за графом плюс планка у его края). **Приложение: переключить подсветку строк графа** (`Ctrl+N Shift+T`) переключает его; **Приложение: сменить цветовую тему графа...** (`Ctrl+N Shift+Y`) выбирает `ui.graph_color_theme`. |
| `ui.graph_row_tint_strength` | `"medium"` | `strong`, `medium`, `subtle` (только с `row_tint`). |
| `ui.toolbar_position` | `"bottom"` | `top`, `bottom`, `left`, `right`. `left` и `right` рисуют колонку; окно меньше 80 столбцов возвращается к `bottom`. |
| `ui.dialog_geometry` | `"session"` | `session`, `saved`, `never`: сохраняет ли диалог, который вы переместили или изменили в размере (перетащите заголовок или границы, либо `Ctrl+N m`), своё место. Один параметр для всех диалогов (каждый хранит своё положение и размер): до закрытия GitPoulpi (по умолчанию), на диске до следующего запуска (все диалоги в одном файле `dialog_geometry.txt` в папке данных) или нет (каждый диалог открывается на стандартном месте и в стандартном размере). |
| `ui.toolbar_align` | `"start"` | `start`, `center`, `end`: где кнопки стоят вдоль панели (слева, по центру, справа в строке; сверху, по центру, снизу в колонке). |
| `ui.toolbar_pr_pinned` | `true` | Кнопка pull request закреплена на дальнем конце панели инструментов; `false` оставляет её среди остальных кнопок. |
| `ui.statusbar_position` | `"bottom"` | `top` (над вкладками репозиториев) или `bottom`. |
| `ui.tabs_position` | `"top"` | `top`, `bottom` (последняя строка окна, под строкой состояния) или `left` (колонка у левого края; при ширине меньше 80 столбцов остаётся сверху). |
| `ui.graph_show_stashes` | `true` | Строка на каждый stash в Log. |
| `ui.ref_connector` | `true` | Тонкая линия от плашки ссылки к её commit'у. |
| `ui.column_resize` | `"line"` | Как захватывается граница колонки в Log, Radar и колонке commit'ов видов diff, файла и blame. `line`: каждая граница - промежуток в одну ячейку с небольшой меткой в заголовке; пока указатель на границе, в заголовке или в любом месте таблицы, поверх всей высоты рисуется тонкая линия акцентного цвета, и перетаскивание из любой её точки меняет размер. `header`: без промежутка и метки; подсвечивается первый символ ячейки заголовка после границы, и перетаскивание от него меняет размер (только из заголовка). Клавиши изменения размера и строки палитры одинаковы в обоих режимах. |
| `ui.ref_tree` | `true` | Группирует ветки и tag'и по `/` в папки на боковой панели Refs (`y` переключает). |
| `ui.graph_ghost_ref` | `true` | Столбец Ref графа Log показывает бледную пилюлю с названием ветки (иначе удалённой ветки), к которой относится наведённый commit, если у commit'а нет собственной ссылки и в столбце хватает места; никогда не tag. Удалённая ветка выводится из темы merge-commit'а, который её влил, и рисуется зачёркнутой. При наведении на пилюлю видно её тип. |

**Команды `ui.open_in`** сначала разбиваются на аргументы (пробелы, `'...'`, `"..."`), потом внутри каждого аргумента подставляются переменные, поэтому папка с пробелами остаётся одним аргументом; оболочка не участвует, если команда сама её не запускает (`sh -c '... "$GITPOULPI_CWD"'`). Переменные: `${cwd}` (папка вкладки), `${repo}` (корень репозитория), `${name}` (имя папки), `${branch}` (пусто при detached HEAD), `${web_url}` (веб-страница remote `origin`, если это проект GitHub или GitLab, иначе пусто; запись с ней отказывается запускаться, когда значение пусто), `${env:NAME}` (пусто, если не задана). Прежний `{repo}` по-прежнему означает `${cwd}`. Любая другая `${...}` - ошибка с её названием. Пример:

```toml
[ui]
open_in_default = "Herdr: new tab"

[[ui.open_in]]
label = "Herdr: new tab"
command = "herdr tab create --workspace ${env:HERDR_WORKSPACE_ID} --cwd ${cwd} --focus"

[[ui.open_in]]
label = "VS Code"
command = "code ${cwd}"
```

Устарело: `ui.terminal_launch` и `ui.terminal_launch_command` по-прежнему читаются (они наполняют список, пока `ui.open_in` отсутствует: `custom` становится «Terminal (custom)» с `{repo}`, переписанным в `${cwd}`, идентификатор шаблона становится этим шаблоном), но вытеснены `ui.open_in`.

**Команды `ui.image_editors`** сначала разбиваются на аргументы (пробелы, `'...'`, `"..."`), потом внутри каждого аргумента подставляются переменные, поэтому путь с пробелами остаётся одним аргументом; оболочка не участвует. Переменные: `${file}` (абсолютный путь к изображению), `${dir}` (его папка), `${name}` (имя файла), `${repo}` (корень репозитория, пусто для временной копии), `${env:NAME}` (пусто, если не задана). Любая другая `${...}` - ошибка с её названием. Изображение, которое не является файлом рабочего дерева (версия из commit'а, индекс, удалённый файл), открывается как **временная копия только для чтения**, поэтому редактор не может тронуть репозиторий. Редакторов без командной строки (Affinity Photo из Microsoft Store, некоторые установки Photoshop) нет среди шаблонов: напишите свою запись. Пример:

```toml
[ui]
image_editor_default = "GIMP"

[[ui.image_editors]]
label = "GIMP"
command = "gimp ${file}"

[[ui.image_editors]]
label = "Paint.NET"
command = "\"C:\\Program Files\\paint.net\\paintdotnet.exe\" ${file}"
```

**Пока не используются** (принимаются, сохраняются, но ничего их не читает):
`ui.graph_colorization` (убраны из настроек;
при загрузке всё ещё принимаются), `ui.date_word_format` (убран из настроек; при
загрузке всё ещё принимается). Прежний `ui.diff_view_mode`
один раз читается как `diff_layout` / `diff_hunks_only`.

## `[[integrations]]` (хостинги и трекеры задач)

Записывается в **Настройки > Интеграции** или через `gitpoulpi hosting integrations add`. У каждого
вида есть клиент (только персональные токены, без OAuth).

```toml
[[integrations]]
id = "corp"                         # то, что принимает --id; токен хранится под integration:corp
kind = "gitlab_self_managed"        # github | github_enterprise | gitlab | gitlab_self_managed | ...
url = "https://gitlab.example.com"  # корень API выводится из него
token_ref = "integration:corp"      # ссылка, но никогда сам токен
name = "Corp GitLab"                # необязательное отображаемое имя
account = "me@example.com"          # необязательно, см. ниже
enabled = true                      # false: не учитывается при сопоставлении хоста
```

Собственный сервер может работать по обычному http: `url = "http://localhost:3000"`
сохраняется как введено (схема и порт попадают в каждый запрос, а remote на этом
хосте сопоставляется с профилем). Токен, отправленный по обычному http, передаётся
без шифрования, поэтому используйте http только в локальной или доверенной сети.

`kind` также принимает `azure_devops`, `azure_devops_server`, `bitbucket`,
`bitbucket_data_center`, `jira_cloud`, `jira_data_center`, `trello`, `gitea`, `forgejo`, `linear`, `youtrack`, `redmine` и `gerrit`
(Gitea и Forgejo используют один клиент; профиль Forgejo по умолчанию указывает на `https://codeberg.org`). Jira,
Trello, Linear, YouTrack и Redmine - только трекеры задач; Gerrit - только ревью (его изменения и есть pull request,
задач в нём нет). У Bitbucket Cloud нет трекера задач.

`account` - несекретная идентичность рядом с токеном; для большинства видов пуста и
не пишется: email аккаунта Atlassian для `jira_cloud` и `bitbucket` (пустой аккаунт
Bitbucket означает токен доступа рабочей области или репозитория, отправляемый как
Bearer), ключ API для `trello`, имя пользователя для `gerrit` (токен - его пароль HTTP,
отправляется как HTTP basic). Единственным секретом остаётся сам токен. Для
`azure_devops` `url` - это `https://dev.azure.com/<organization>`; URL вида
`https://<organization>.visualstudio.com` читается как та же организация.
Для `azure_devops_server` это корень коллекции, например
`https://tfs.example.com/tfs/DefaultCollection`.

`user` (подключённый аккаунт) и `ssh` (выбор ключа профиля) записываются за вас.
Токен берётся из `GITPOULPI_TOKEN_<ID>` (идентификатор заглавными буквами,
не-алфавитно-цифровые символы как `_`), иначе из сохранённого токена, иначе из вашего помощника
учётных данных для этого хоста, если его использует только один профиль (только профили
GitHub и GitLab: остальные виды помощника учётных данных никогда не читают). Подробности: [Интеграции с хостингами
и трекерами задач](hosting-integration.md). Прежняя таблица `[[hosting]]` *не используется*.

Для `local_markdown` (папка заметок Markdown как источник задач) `url` - это папка, относительно каждого
репозитория или абсолютная, а токена нет. Его необязательная таблица `[integrations.local]` задаёт `statuses`
(порядок колонок доски, по умолчанию `todo`, `doing`, `done`), `done_status` (по умолчанию `done`),
`reference_prefix` (`LOC` показывает `LOC-12`) и `me` (что означает «назначены мне»).
См. [Локальные задачи и Obsidian](local-issues.md).

### `[integrations.radar]` (списки по всему аккаунту)

Необязательная таблица профиля хостинга кода (GitHub, GitLab, Gitea, Forgejo, Azure DevOps, Bitbucket Data Center, Gerrit; не Bitbucket Cloud). Если её нет,
все ключи выключены. Записывается командой `gitpoulpi hosting integrations radar`; читается
`gitpoulpi hosting radar` и Radar, правится в Настройки > Интеграции (блок Radar подключённого профиля).

```toml
[integrations.radar]
review_requests = true    # запросы, ждущие моего ревью, все репозитории
open_requests = false     # все открытые запросы моих пространств имён
include_drafts = false    # оставлять запросы-черновики в этих списках
assigned_issues = true    # открытые задачи, назначенные мне, все репозитории
namespaces = ["acme", "ptm/produits"]  # по одной записи в строке в настройках; пусто = без ограничений
namespaces_regex = false  # true: каждая запись - регулярное выражение для полного пути репозитория
review_mode = "ask"       # ask | clone | api
```

| Ключ | По умолчанию | Значение |
|---|---|---|
| `review_requests` | `false` | Открытые запросы, где просят вашего ревью, клонирован репозиторий или нет |
| `open_requests` | `false` | Все открытые запросы вашего собственного пространства имён и каждой организации или группы, где вы состоите (или из `namespaces`), но никогда не «всё, что видит токен» |
| `include_drafts` | `false` | Запросы-черновики не попадают в эти списки, пока это не включено |
| `assigned_issues` | `false` | Открытые задачи, назначенные вам, все репозитории |
| `namespaces` | `[]` | Какие репозитории оставляет каждый список (запросы на ревью, назначенные задачи, открытые запросы); пусто означает без ограничений, и тогда `open_requests` ищет в вашем собственном пространстве имён и всех, где вы состоите (GitHub: ищется не более 12, GitLab: 10 групп и 10 собственных проектов, Gitea, Forgejo и Gerrit: 10). Запись соответствует полному пути репозитория (`group/sub/project`, в Azure DevOps `Project/repo`, в Bitbucket Data Center `KEY/repo`), если равна ему или является префиксом пути, оканчивающимся на `/`: `ptm` оставляет `ptm/produits/x`, но не `ptmx/y`; регистр не учитывается. В настройках одна запись на строку; старый файл может содержать одну строку через запятую (`"ptm, formation"`): она по-прежнему загружается и сохраняется обратно списком |
| `namespaces_regex` | `false` | Читать каждую запись `namespaces` как регулярное выражение, сопоставляемое с полным путём репозитория в том виде, как вы его пишете (поэтому `^ptm/(produits\|infra)/` привязано к началу; без `^` и `$` оно совпадает в любом месте пути; добавьте `(?i)`, чтобы не учитывать регистр). `open_requests` тогда ищет в ваших членствах, а выражения фильтруют строки. Недопустимое выражение показывается под полем в настройках и не сохраняется; в файле, правленном вручную, оно оставляет списки пустыми с примечанием |
| `review_mode` | `"ask"` | Что делает ревью запроса, репозиторий которого не клонирован: `ask`, `clone` (клонировать, затем ревью) или `api` (ревью через API хостинга) |

Ответы кэшируются для каждого профиля в `radar-account.json` рядом с
`config.toml` на пять минут; файл - это кэш, его можно удалять.

### Хранилище доверия (не в `config.toml`)

Чему доверяли каждой интеграции и профилю ИИ с ключом API (её адрес, id учётной
записи, закреплённый ключ сертификата, разрешён ли обычный http) хранится в
`trust.toml` в закрытой папке данных, доступной только пользователю
(`<data>/private/trust.toml`: `%APPDATA%\GitPoulpi\private\` в Windows,
`~/.local/share/gitpoulpi/private/` в Linux). Оно намеренно не входит в `config.toml`:
тот, кто может править конфигурацию, не должен иметь возможности расширить доверие
правкой. Меняйте его командами `gitpoulpi hosting integrations trust` и
`gitpoulpi ai trust` (см. [проверку безопасности](hosting-integration.md#проверка-безопасности));
файл перезаписывает GitPoulpi, а не вы вручную.

## `[mcp]` (что разрешено ИИ-агентам)

| Ключ | По умолчанию | Значения и действие |
|---|---|---|
| `mcp.allow_mutations` | `false` | Выкл.: инструменты MCP, что-либо меняющие, отклоняются; чтение, `ui_*` и предложения продолжают работать. `true` позволяет агентам менять репозиторий. |
| `mcp.mutation_allowlist` | `[]` | Не пусто: менять что-либо могут только эти инструменты (`["stage", "commit"]`). |
| `mcp.allow_ui` | `true` | `false`: отклонять инструменты `ui_*`, двигающие ваше окно (кроме `ui_state` / `ui_viewers`). |
| `mcp.ui_control` | `"ask"` | `ask` (окно показывает значок, который вы подтверждаете), `auto` (применяется, если вы не заняты), `off`. `--ui-control` в команде сервера переопределяет его для отдельного агента. Действует и на `gitpoulpi ui show`. |
| `mcp.allow_ui_propose` | `false` | Разрешить `ui_propose_*` / `gitpoulpi ui propose`: заполненные диалоги, которые вы подтверждаете сами. |
| `mcp.allow_history_purge` | `false` | Только в `config.toml` (строки в Настройках нет). `true` показывает агентам инструмент `rewrite_purge` (ему по-прежнему нужен `allow_mutations`). Если выключено, агент этот инструмент вообще не видит: очистка навсегда удаляет старую историю переписывания, её отмену и её reflog. CLI и TUI этот параметр не ограничивает. |
| `mcp.enabled` | `true` | `false`: `gitpoulpi mcp serve` и `gitpoulpi-mcp` отказываются запускаться с сообщением, называющим этот ключ. Настройки > Агенты и MCP > *Сервер MCP*. Читается, когда агент запускает сервер. |
| `mcp.bind` | `"127.0.0.1:8808"` | Адрес, который слушает `--http`, если вы его не указали (`--http ADDR` / `--bind` главнее). Только loopback, если нет `--allow-remote`. Пусто или прежнее `"stdio"` означают значение по умолчанию. Настройки > Агенты и MCP > *Порт сервера MCP* меняет порт и сохраняет хост. |
| `mcp.http_auth` | `true` | `--http` отвечает только на запрос с `Authorization: Bearer <token>` (токен из `gitpoulpi mcp token`). `false` убирает проверку; сервер тогда предупреждает в stderr, а `--allow-remote` отклоняется. Настройки > Агенты и MCP > *Аутентификация HTTP*. |
| `mcp.tls` | `"off"` | `off`, `self_signed` (сертификат, один раз созданный в закрытой папке данных; его отпечаток SHA-256 выводится при запуске) или `files` (`tls_cert` и `tls_key`). При включённом TLS сервер сам завершает TLS, и обычного слушателя нет. Настройки > Агенты и MCP > *TLS*. |
| `mcp.tls_cert` | `""` | Цепочка сертификатов PEM, используемая с `tls = "files"`. |
| `mcp.tls_key` | `""` | Закрытый ключ PEM, используемый с `tls = "files"`. |
| `mcp.behind_proxy` | `false` | Вы заявляете, что шифрование обеспечивает туннель или обратный прокси перед эндпоинтом. Изнутри сервера это проверить нельзя, поэтому для `--allow-remote` без TLS параметр должен быть включён. Участок между прокси и сервером передаётся открытым текстом по этой сети. Настройки > Агенты и MCP > *За туннелем или обратным прокси*. |
| `mcp.allow_sensitive_staging` | `false` | Только в `config.toml`. Выключено: инструменты MCP для добавления в индекс не предлагают `allow_sensitive`, а добавление, которое внесло бы помеченный файл (см. `[privacy]`), отклоняется с сообщением, что агенту нужно спросить вас. Включено: агент может передать `allow_sensitive`. CLI и TUI этим не ограничены: они спрашивают вас. |

`allow_mutations`, `mutation_allowlist` и `allow_ui` ограничивают только сервер MCP;
CLI - это ваша собственная оболочка, и они на неё не действуют. См. [MCP и
агенты](mcp-and-agents.md#разрешения).

## `[ai]` (встроенный ИИ, по умолчанию выключен)

| Ключ | По умолчанию | Значения и действие |
|---|---|---|

Собственная таблица репозитория `[preferences.ai_review]` (в его `repo-state.toml` или запись неклонированного репозитория в `remote-reviews.toml`) принимает те же ключи, все необязательные, плюс `no_extra_file = true`: без дополнительного файла для этого репозитория, что бы ни говорил `ai.review.extra_file`. Незаданный ключ, незаданный `extra_file` и отсутствующий `no_extra_file` наследуют глобальное значение; задание `extra_file` файлом сбрасывает переключатель, и наоборот.

```toml
[[ai.profiles]]
id = "default"
name = "Default"
kind = "open_ai"        # open_ai | anthropic | open_router | open_ai_compatible | local_agent
model = "gpt-5"         # пусто = значение вида по умолчанию
base_url = ""           # пусто = значение вида по умолчанию (Ollama: http://localhost:11434/v1)
token_ref = "ai:default"  # где хранится ключ API; сам ключ никогда
command = ""            # только local_agent: точная программа ("claude", псевдоним, обёртка, путь)
harness = ""            # только local_agent: claude | codex | gemini | opencode | cursor-agent | copilot | pi | qwen | aider | goose | crush | amp | other; empty = inferred from `command`
args = []               # только local_agent, например ["-p", "--model", "haiku"]
run_mode = "headless"   # только local_agent: headless (по умолчанию) | terminal (интерактивный экран агента в виртуальном терминале)
terminal_args = []      # только local_agent: аргументы режима terminal (args сохраняет безынтерфейсный набор)
workdir = "default"     # только local_agent: default | dedicated | repository (default = выделенная папка в режиме terminal, папка GitPoulpi в режиме headless)
timeout_secs = 0        # только local_agent: секунд до остановки агента; 0 = 120 headless, 180 terminal

[ai.profiles.env]       # только local_agent, необязательно: переменные только для этого процесса
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC = "1"
ANTHROPIC_API_KEY = "${env:ANTHROPIC_API_KEY}"   # ${env:NAME} = one of GitPoulpi's own variables
```

`harness` выбирает подсказки, которые предлагает Настройки > ИИ (аргументы без интерфейса,
параметры, флаг и список моделей, переменные окружения) независимо от
`command`; оба ключа не пишутся в файл, когда пусты. Значения окружения
никогда не попадают в журнал и скрываются в настройках, если похожи на секреты.

Настройки > ИИ предлагает шаблоны для `harness`/`command`/`args`/`env` (распространённые CLI агентов с
их флагами для работы без интерфейса, флагом модели и полезными переменными окружения) и для `kind`/`base_url`/`model` (облачные
и локальные HTTP-провайдеры); см. [ИИ > Настройка](ai.md#настройка-ии).

Профиль с названием *Default* создаётся, если профилей нет. Старые файлы с `[[ai.presets]]` /
`[ai.defaults]` переносятся при загрузке и сохраняются в `[[ai.legacy_presets]]`.
Всё остальное: [ИИ-помощь](ai.md).

## `[log]` (журнал приложения)

То, что показывает вкладка «Приложение» Журнала активности и что цитирует «Копировать диагностику». Подробности: [Когда что-то не удаётся](troubleshooting.md#когда-что-то-не-удаётся).

| Ключ | По умолчанию | Значения и действие |
|---|---|---|
| `log.level` | `"info"` | Самая подробная из записываемых строк: `error`, `warn`, `info`, `debug` или `trace`. Поле уровня в Журнале активности меняет её (и сохраняет здесь). |
| `log.retention_days` | `7` | Сколько дней хранятся файлы журнала, считая сегодняшний: от 1 до 3650, то есть десять лет (значение вне диапазона приводится к границе). Всегда число дней, в какой бы единице его ни показывали Настройки. Более старые файлы удаляются при запуске GitPoulpi. Файл за день ограничен ещё и `log.max_file_mb`, поэтому в худшем случае это около `2 x max_file_mb x retention_days`. |
| `log.retention_unit` | `"auto"` | Единица, в которой Настройки показывают `log.retention_days`: `days`, `weeks`, `months`, `years` или `auto`. Только отображение, на срок хранения файлов не влияет. Неделя - 7 дней, месяц - 30 дней (не календарный месяц, так что число дней одно и то же в любой момент применения), год - 365 дней. `auto` и конфигурация, записанная до появления этого ключа, выбирают наибольшую единицу, на которую дни делятся нацело (14 дней читаются как «2 недели», 45 дней - как «45 дней»). Единица, на которую дни не делятся (`retention_days = 10` с `weeks`), игнорируется, и показываются дни. Настройки записывают оба ключа; старый GitPoulpi игнорирует единицу и по-прежнему читает дни. |
| `log.max_file_mb` | `5` | Файл за день при таком размере ротируется в одну резервную копию `.old`, так что день никогда не занимает больше чем вдвое. |
| `log.max_file_unit` | `"auto"` | Единица, в которой Настройки показывают размер: `mib`, `gib` (1024 МиБ) или `auto`. Только отображение: размер всегда равен `max_file_mb` МиБ, от 1 до 1024. |
| `log.timings` | `true` | Вкладка «Операции git» Журнала активности показывает, сколько длилась каждая операция (`Push - 123 ms`: открытие репозитория, обновление, fetch, pull, push, commit, checkout, merge, rebase, stash, clone). Длительность измеряет окно, от запроса до ответа демона, так что она включает путь IPC туда и обратно. Выключено - длительности и записи об успешных операциях скрыты. Сбои всегда перечислены. |
| `log.extended` | `false` | «Расширенное ведение журнала»: вкладка «Операции git» перечисляет также фоновые операции (периодическое обновление, опрашивающее статус, auto-fetch) с их длительностью. В журнал приложения они всегда пишутся на уровне `debug`. |
| `log.commit_count` | `"system-git"` | Как строка состояния узнаёт итог в `загружено / всего`. `"system-git"` запускает `git rev-list --count` (один процесс, на обычной машине быстрее всего: git читает файл commit-graph). `"libgit2"` считает внутри процесса обходом libgit2 и ничего не запускает: выбирайте, если любой процесс командной строки стартует медленно, обычно потому что антивирус с проверкой в реальном времени осматривает каждый; на 50 000 commit'ов это занимает около 200 мс в фоне вместо 12 мс, зато процесс не запускается. `"off"` не считает вовсе: строка показывает только загруженные commit'ы. Применяется сразу. Подсчёт с фильтром по пути всегда идёт через системный git. |
| `log.use_mailmap` | `true` | Показывать каждого автора так, как его называет `.mailmap` репозитория (и `mailmap.file`): в Log, в blame и в истории файла. Демон спрашивает у git `%aN`/`%aE` (системный бэкенд) или сам применяет те же файлы (бэкенд libgit2), поэтому ответ одинаков. Сохранённые commit'ы не меняются, ничего не переписывается. Поиск в Log по автору сопоставляется с именами в том виде, как они показаны. Применяется сразу; Log перечитывает данные в пределах своего опроса раз в 2 с. |

Файлы называются `gitpoulpi-YYYY-MM-DD.log` и лежат в папке состояния ОС (`~/.local/state/gitpoulpi/logs` в Linux; `<cache>\logs` в Windows и macOS; `<config>/cache/logs` при `GITPOULPI_CONFIG_DIR`). Токены, пароли и заголовки `Authorization` маскируются до того, как что-либо записывается.

| Ключ | По умолчанию | Значения и действие |
|---|---|---|
| `rewrite.protected_branches` | `["main", "master", "develop", "release/*"]` | Ветки (имена или шаблоны, где `*` совпадает с любым текстом), которые переписывание не трогает, если они уже отправлены, пока запуск не перечислит их (`--include-protected BRANCH`; `--include-all-protected` для push; флажок у каждой ветки в окне переписывания). Добавляются к базам, которые `workflow.toml` репозитория помечает как `protected`. Отправка переписанного пропускает их так же. Это собственная защита GitPoulpi: принимать ли force push, всё равно решает защита веток на хосте. Читается на лету: следующий предпросмотр учтёт изменение. |
| `rewrite.external_scripts` | `["shell"]` | Какие языки внешних скриптов может использовать правило «Скрипт»: любые из `"shell"` (bash или sh; pwsh или powershell для скриптов PowerShell), `"python"`, `"lua"` (установленный Lua; встроенный Lua включён всегда и записи не требует). **Внешний скрипт не в песочнице: он работает с вашими правами.** Язык, которого нет в списке, в окне переписывания серый, а CLI, MCP и демон отказывают (`scripts_disabled`). Даже если язык в списке, внешний скрипт из репозитория или общего рецепта запускается только после того, как вы ему доверились (`gitpoulpi rewrite script trust FILE` или вопрос в окне переписывания); доверие привязано к хэшу содержимого скрипта, поэтому изменённый скрипт спросит снова. Включите Python, отредактировав `config.toml` (список нельзя задать через `config set`): `[rewrite]`, затем `external_scripts = ["shell", "python"]`. Читается на лету. |
| `rewrite.script_timeout_ms` | `5000` | Сколько времени внешнему скрипту дано на ответ по одному commit'у. При тайм-ауте убивается всё дерево процессов, а переписывание завершается ошибкой (`script_failed` с указанием commit'а); ничего не сдвинуто. `0` читается как значение по умолчанию. Читается на лету. |
| `rewrite.script_timeout_unit` | `"auto"` | Единица, в которой Настройки показывают лимит времени: `milliseconds`, `seconds` или `auto`. Только отображение: лимит всегда равен `script_timeout_ms` миллисекунд. Настройки принимают от 1 до 600000 (десять минут); `0` по-прежнему читается как значение по умолчанию. Читается на лету. |
| `rewrite.script_total_timeout_s` | `3600` | Сколько всего может занять один проход внешнего скрипта. `0` читается как значение по умолчанию. Читается на лету. |
| `rewrite.script_total_timeout_unit` | `"auto"` | Единица, в которой Настройки показывают лимит времени: `seconds`, `minutes`, `hours` или `auto`. Только отображение: лимит всегда равен `script_total_timeout_s` секунд. Настройки принимают от 1 до 86400 (сутки); `0` по-прежнему читается как значение по умолчанию. Читается на лету. |

## `[updates]` (поиск новой версии)

Что делает чип версии в строке заголовка, когда есть новый выпуск. Подробности: [Обновления](updates.md).

| Ключ | По умолчанию | Значения и действие |
|---|---|---|
| `updates.mode` | `"notify"` | `"notify"` раз в сутки в фоне спрашивает GitHub, есть ли новый выпуск, и превращает чип версии в `vX.Y.Z доступна`. `"auto"` дополнительно сам скачивает и подготавливает обновление, если сборка получена из архива выпуска (перед перезапуском всё равно спрашивает); для любой другой сборки ведёт себя как `"notify"`. `"off"` никогда не делает запросов. Применяется сразу. |
| `updates.channel` | `"stable"` | `"stable"` учитывает только полноценные выпуски; `"prerelease"` предлагает и релиз-кандидаты (`-rc.1`). Применяется сразу. |
| `updates.repo` | `"Poulpi-Lab/GitPoulpi"` | `owner/name` на github.com, чьи выпуски проверяются. Пока этот репозиторий закрытый, GitHub отвечает 404, если для github.com не сохранён токен (Настройки > Интеграции); без него проверка тихо не удаётся и пишет одну строку в журнал приложения. |

Администратор может задать `mode`, `channel` (как `release_channel`) и `repo`, а также ещё несколько параметров обновления в файле политики для всего компьютера или в реестре Windows. Ключ, заданный политикой, главнее `config.toml` и отображается в настройках как **Задано администратором**. `mode` в политике - потолок: вы можете выбрать меньшее значение, но не большее. См. [Корпоративное распространение](enterprise-distribution.md#файл-политики-и-реестр).

## `[privacy]` (конфиденциальные файлы)

| Ключ | По умолчанию | Значения и действие |
|---|---|---|
| `privacy.sensitive_patterns` | `[".env", ".env.*", "!.env.example", "!.env.sample", "!.env.template", "*.pem", "*.key", "id_rsa*", "id_ed25519*", "id_ecdsa*", "*.p12", "*.pfx", "*.jks", "*.keystore", "*.crt", "*.cer", "*.der", "*.kdbx"]` | Шаблоны путей в стиле gitignore. Шаблон без `/` подходит под имя файла на любой глубине, с `/` - под весь путь (начальный `/` привязывает его к корню); `*` и `?` остаются внутри одной папки, `**` пересекает папки; `!` снова разрешает то, что подошло под более ранний шаблон, и побеждает последнее совпадение; регистр игнорируется. Используется защитой индекса и `ai.privacy.exclude_sensitive_files`. |
| `privacy.staging_guard` | `true` | Добавление в индекс файла, подходящего под шаблон или содержащего распознанный секрет, сначала спрашивает (TUI), отклоняется, если не задан `--allow-sensitive` (CLI) или `mcp.allow_sensitive_staging` не позволяет агенту передать `allow_sensitive` (MCP). Читаются текстовые файлы до 1 МиБ каждый и 32 МиБ в сумме; двоичные файлы сопоставляются только по имени. См. [Индекс и commit'ы](staging-and-committing.md#конфиденциальные-файлы). |

## `[conflict_prevention]` (списки базовых веток)

Какие ветки проактивное обнаружение конфликтов может считать базой текущей ветки, задаётся списком шаблонов (см. [Разрешение конфликтов слияния](merge-conflicts.md#предотвращение-конфликтов)). Списки могут быть именованными и общими; их правит Настройки > Общие > Предотвращение конфликтов.

| Ключ | По умолчанию | Значения и действие |
|---|---|---|
| `conflict_prevention.default_list` | `""` | Имя списка, который использует репозиторий без собственного списка. Пусто или имя, которого нет среди списков, означает встроенный `**` (все ветки). Читается заново при каждой проверке, поэтому изменение действует на открытые репозитории без перезапуска. |
| `conflict_prevention.lists` | нет | Именованные списки, по одной таблице на список: `[conflict_prevention.lists.release]` с `patterns = ["origin/release/**", "!origin/release/old"]`. Пустой `patterns` разрешает все ветки. Правка списка действует на каждый репозиторий, который ему следует. |

Какому списку следует репозиторий, записано в его `repo-state.toml` (ниже). Приоритет: собственные шаблоны репозитория, затем именованный список, которому он следует, затем `default_list`, затем `**`.

## `[keybindings]`

Переназначает сочетания клавиш TUI; правится в Настройки > Клавиатура и мышь.

```toml
[keybindings.global]
git_prefix = "Ctrl+B"            # по умолчанию Ctrl+G
nav_prefix = "Alt+n"             # по умолчанию Ctrl+N
settings   = ["Ctrl+,", "F2"]    # список = альтернативы
tab_menu   = []                  # не назначено

[keybindings.git_prefix]         # клавиша после префикса git
stage_file = "z"
```

`[keybindings.<context>] <action> = "<chord>"`; значение заменяет умолчания этого
действия, удаление строки их восстанавливает. Сочетания: `Ctrl+Shift+N`, `Alt+n`,
`F2`, `PageDown`, `Space`, `,`, `P` (= `Shift+p`). Неверная запись ничего не
блокирует: TUI игнорирует её, оставляет значение по умолчанию и сообщает об этом в строке состояния.
Контексты, идентификаторы действий, умолчания и правила конфликтов: [Сочетания клавиш](keybindings.md).

## Настройки репозитория: `.gitpoulpi/repo-state.toml`

Хранится внутри репозитория; папка игнорирует саму себя (`.gitignore` со строкой `*`),
поэтому никогда не показывается как изменение. Записывается TUI и CLI; править её
вручную приходится редко.

| Ключ | Что это | Чем задаётся |
|---|---|---|
| `[preferences] encoding` | Переопределяет `git.default_encoding` здесь | Настройки > Git и кодировка |
| `[preferences] lfs_enabled` | Переопределяет `git.lfs_enabled` здесь | Настройки > Git и кодировка |
| `[preferences] profile` | Идентификатор `[[profiles]]`, от имени которого здесь создаются commit'ы; отсутствие означает `general.active_profile` | выпадающий список профилей на панели инструментов, **Репозиторий: сменить профиль...** |
| `[preferences] autocrlf`, `eol` | *Пока не используются* | Настройки > Git и кодировка |
| `[preferences] push_after_commit` | Делать push ветки в её upstream после каждого commit'а (выкл., если нет) | Настройки > Настройки репозитория > Commit |
| `[preferences] skip_hooks_by_default` | «Пропустить хуки» в форме commit'а начинается отмеченным (выкл., если нет) | Настройки > Настройки репозитория > Commit |
| `[preferences] squash_merge` | Слияние локальной ветки делает squash: добавляет в индекс, без merge-commit'а (выкл., если нет) | Настройки > Настройки репозитория > Настройки merge |
| `[preferences] template_apply`, `template_strip_comments` | Заполнять пустую форму commit'а шаблоном; убирать строки комментариев `#` при создании commit'а (оба выкл., если нет) | Настройки > Настройки репозитория > Шаблон сообщения |
| `[preferences] conflict_detection` | Проактивное обнаружение конфликтов для этого репозитория; если нет, действует `general.conflict_detection` | Настройки > Настройки репозитория > Предотвращение конфликтов |
| `[preferences] conflict_base_branches` | Собственные шаблоны базовых веток репозитория, по одному в строке (используются как **Собственный список**) | Настройки > Настройки репозитория > Предотвращение конфликтов |
| `[preferences] conflict_base_source` | Откуда берутся базовые ветки: `default` (глобальный список по умолчанию), `list` (`conflict_base_list`) или `own` (`conflict_base_branches`). Если нет: собственные шаблоны, когда они есть, иначе список по умолчанию | Настройки > Настройки репозитория > Предотвращение конфликтов |
| `[preferences] conflict_base_list` | `[conflict_prevention.lists.<name>]`, которому репозиторий следует при источнике `list`; удалённый список заменяется списком по умолчанию | Настройки > Настройки репозитория > Предотвращение конфликтов |
| `commit-template.txt` (файл рядом с `repo-state.toml`) | Шаблон commit'а; на него указывает `commit.template` git | Настройки > Настройки репозитория > Шаблон сообщения |
| `[preferences.ai_instructions]` | `text`, `mode = "add" \| "replace"`: инструкции ИИ для этого репозитория | Настройки > Настройки репозитория > ИИ |
| `[preferences.ai_overrides.<action>]` | `profile`, `instructions` для одного действия здесь | Настройки > Настройки репозитория > ИИ |
| `default_remote` | Remote, который используют Push/Pull/Fetch в один щелчок | меню remote, `gitpoulpi remote default <name>` |
| `hosting_integration` | Закреплённый здесь профиль `[[integrations]]` | `gitpoulpi hosting use --id` |
| `pulls_source`, `issues_source` | Проект провайдера, который читают списки PR / задач, в виде `{ integration, project, filter }`. `filter` необязателен: дополнительное условие провайдера (фрагмент Jira JQL, условие Azure WIQL, названия списков Trello), присоединяемое через AND к запросу списка; GitHub и GitLab его игнорируют. | разделы боковой панели, `gitpoulpi hosting link` |
| `ref_visibility` | Скрытые / выделенные (solo) ссылки | боковая панель Refs, `gitpoulpi refs hide\|show\|solo` |
| `hidden_remotes` | Remote, скрытые из графа целиком (каждая ветка, в том числе полученные позже) | ⊙ и меню remote, `gitpoulpi refs hide --remote` |
| `folds`, `collapsed_*_ref_folders` | Свёрнутые разделы боковой панели и папки веток и tag'ов. `[folds]` также хранит `status_folders` (свёрнутые папки деревьев файлов Unstaged / Staged) и `commit_folders` (свёрнутые папки дерева изменённых файлов commit'а, одинаковые для каждого commit'а), каждое ограничено 500 путями, самые старые отбрасываются первыми | боковая панель, деревья файлов |
| `pending_auto_stash` | Stash, который создал GitPoulpi и ещё не вернул | записывается демоном; см. [Auto-stash](log-and-history.md#auto-stash) |

## Прочие переменные окружения

| Переменная | Действие |
|---|---|
| `GITPOULPI_CONFIG_DIR` | Папка конфигурации (см. выше). |
| `GITPOULPI_TOKEN_<ID>` | Токен хостинга для профиля `<ID>`, главнее сохранённого (CI, разовое использование). |
| `GITPOULPI_GIT` | Исполняемый файл `git` (по умолчанию: `git` из `PATH`; в Windows - настоящий `mingw64\bin\git.exe` за заглушкой `cmd\git.exe` из Git for Windows, что экономит процесс на каждый вызов). |
| `GITPOULPI_LANG=fr` | Язык интерфейса, главнее `ui.language` (любое значение `ui.language`; `qps` - псевдолокаль для переводчиков). Неизвестное или пустое значение игнорируется. |

| `GITPOULPI_NO_EXIT_PAUSE=1` | Не ждать Enter после выхода из TUI с ошибкой. |
