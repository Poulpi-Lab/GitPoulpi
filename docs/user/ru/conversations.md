# Беседы

Окно беседы задачи, рабочего элемента, карточки или pull / merge request'а. Нужны учётная запись и связанный репозиторий: см. [Интеграции с хостингами и трекерами задач](hosting-integration.md); списки, из которых оно открывается, описаны в [Pull request'ах и задачах](pull-requests-and-issues.md); ревью кода - в [Ревью pull request'а](review.md).

**Беседа** - это всё, что сказано об одной задаче, рабочем элементе, карточке, изменении или pull / merge request:
описание, комментарии, ревью, обсуждения кода и события (метки, назначения, смены состояния, push'и). GitPoulpi
читает её с хостинга, показывает отформатированной и позволяет отвечать, не выходя из окна.

### Как открыть беседу

| Откуда | Как |
|---|---|
| Строка ЗАДАЧИ | `Enter` или двойной щелчок; пункт меню строки **Открыть беседу**; палитра *Хостинг: открыть беседу задачи...* (список задач на экране). Пункт меню строки **Открыть в браузере** по-прежнему открывает браузер. |
| Строка PULL REQUESTS в Azure DevOps или Bitbucket | `Enter` или **Открыть беседу**. В GitHub, GitLab, Gitea, Forgejo и Gerrit строка открывает [ревью](review.md), чья страница обзора и есть эта же беседа (лента, клавиши и поле комментария под ней). |
| Карточка [доски задач](pull-requests-and-issues.md#доска-задач) | `Enter` или двойной щелчок. |
| [Radar](radar.md) | `i` на строке задачи или запроса, пункт меню строки **Открыть беседу** или *Radar: открыть беседу задачи*. |
| Ссылка в другой беседе | Щёлкните по ней (или `l`, затем выберите): `#7`, `!12`, `ABC-12` связанного источника открываются в приложении и кладутся в стек возврата. |
| Агент | `gitpoulpi ui show issue <n> --view conversation` (также `ui show pr`), см. [справочник по CLI](cli-reference.md). |

**Неклонированные репозитории.** Строка Radar репозитория, клона которого у вас нет, тоже открывает свою беседу:
окну нужны только профиль интеграции и проект, поэтому Radar показывает её поверх своего окна, а `Esc` возвращает
Radar. То, для чего нужен клон, исключено: ссылка на commit открывается на хостинге, а не в Log, а
*Разрешить ИИ читать репозиторий* неактивно с указанием причины (см. [главу об ИИ](ai.md#помощь-в-написании-на-хостинге)).
У запроса клонированного репозитория вместо этого есть ревью (`e`), а **Открыть беседу** в Radar для него сообщает,
что читать здесь нечего; задача клонированного репозитория открывает беседу во вкладке этого репозитория.

Задача на хостинге, где читать нечего (в Bitbucket и Gerrit нет задач), по-прежнему открывает браузер, и то же
делает сборка без функции `conversation` везде ([пользовательские сборки](custom-builds.md)).

### Окно беседы

Окно на весь экран: заголовок (состояние, кто и когда открыл, метки, число комментариев, **Показывать события**,
**Назад**, **Обновить**, **Открыть в браузере**), строка **Публикация как**, лента и под ней поле комментария.

![Беседа задачи #7: описание со ссылкой на #9, два комментария, событие метки, показанное кнопкой «Показывать события», и пустое поле «Новый комментарий» с режимами «Ввод», «Просмотр» и «Рядом»](../images/issue-conversation.png)

![Страница обзора merge request'а !58: описание, нерешённое и решённое обсуждения кода со ссылками на файл и строку, комментарии, «Ответить» и «Цитата» на выбранном обсуждении и поле комментария](../images/pr-conversation.png)

- Лента читается от старых записей к новым и начинается с самого нового окна (не больше 300 записей). **Загрузить
  старые** вверху ленты (`m`, палитра *Беседа: загрузить старые записи*) читает предыдущее окно, с указанием числа
  оставшихся, если хостинг его сообщает.
- Комментарий показывает автора, дату, метку `изменено`, метку `бот` для ботов, `внутренняя` для закрытых заметок и
  кнопки **Ответить**, **Цитата**, **Изменить**, **Удалить** и **Ссылки**, которые допускает выбранная запись.
  Обсуждение кода показывает `путь:строка`, `разрешено` или `не разрешено`, `устарело` и свои комментарии. Ревью
  показывает своё решение.
- События - по одной приглушённой строке (*carol добавил(а) метку lfs*). **Показывать события** (`v`) скрывает их;
  выбор хранится для каждого репозитория. У хостингов без истории событий (YouTrack, рабочие элементы Azure DevOps,
  локальные заметки) такого флажка нет.
- Текст отрисовывается как Markdown: заголовки, вложенные списки и списки задач, цитаты, блоки-примечания в стиле
  GitHub, код с подсветкой, таблицы, ссылки, изображения как `[image: alt]`. Текст, пришедший в собственной разметке
  хостинга, сначала преобразуется (см. [Преобразование разметки](#преобразование-разметки)). Блок кода `mermaid`
  получает кнопку **Открыть диаграмму**, которая показывает исходник диаграммы в прокручиваемом окне (`Enter`
  копирует его); в палитре есть *Беседа: открыть диаграмму записи*. Для этого нужна сборка с `conversation` и
  `mermaid`.
- В Обзоре ревью `путь:строка` обсуждения кода служит ссылкой на код (**`G`**, *Беседа: открыть код обсуждения*;
  см. [Ревью](review.md)); в беседе, открытой отдельно (задача, строка Радара), страницы с кодом нет.
- Окно перечитывается каждые 60 секунд и по `F5` (**Обновить**).

**Клавиши.** У каждой есть кнопка, пункт меню или строка палитры (*Беседа: ...*), а `Ctrl+N` отмечает кнопки значками.

| Клавиша | Действие |
|---|---|
| `Up`, `Down`, `Ctrl+J`, `Ctrl+K`, `j`, `k` | Предыдущая / следующая запись |
| `PageUp`, `PageDown`, `Home`, `End`, колесо, полоса прокрутки | Прокрутка |
| `Tab`, `Shift+Tab` | Лента, поле комментария, затем кнопки заголовка |
| `r` | Ответить: в обсуждение выбранной записи или с цитатой её текста там, где у хостинга нет обсуждений |
| `Q` | Процитировать выбранную запись в новом комментарии |
| `c` | Новый комментарий |
| `e`, `d` | Изменить, удалить один из ваших комментариев (перед удалением задаётся вопрос) |
| `l`, `Enter` | Ссылки записи: `Enter` переходит по единственной или открывает их меню |
| `y`, `o` | Скопировать адрес записи, открыть её в браузере |
| `n` | Следующая непрочитанная запись |
| `v`, `m`, `F5` | Показать или скрыть события, загрузить старые, обновить |
| `Alt+Left`, `Backspace` | Назад по стеку возврата |
| `q`, `Esc` | Закрыть (если в поле есть текст, сначала спросит) |

### Написание

**Новый комментарий** (`c` или `Tab` к полю), **Ответить** (`r`), **Цитата** (`Q`) и **Изменить** (`e`) используют один
редактор Markdown: **Ввод**, **Просмотр** и **Рядом** (`Alt+P` переключает ввод и просмотр, `Alt+L` включает режим
«Рядом», для него нужно окно шириной 100 столбцов). `Ctrl+Enter` (также `Ctrl+S` и `Alt+Enter`) или **Отправить**
публикует, **Отмена** убирает поле, а `Alt+E` открывает **Написать с ИИ**, где ИИ включён ([глава об
ИИ](ai.md#помощь-в-написании-на-хостинге)). Просмотр строится тем же отрисовщиком, что и лента, с теми же ссылками.
Если хостинг не принимает Markdown, внизу указана разметка, в которой отправляется текст (*Отправляется как вики-разметка
Jira*, *Отправляется как Textile*).

![Ответ на задачу в режиме «Рядом»: черновик Markdown слева, его отрисованный просмотр справа и «Отправить»](../images/issue-reply-composer.png)

- Комментарий сразу добавляется в ленту и занимает своё место, когда отвечает хостинг. Если хостинг отказывает,
  запись исчезает, а поле открывается снова с вашим текстом и причиной.
- Неотправленный текст хранится для каждого элемента (`remote-conversations.toml` в папке конфигурации) и оказывается
  на месте при следующем открытии этого поля; отправка или отказ удаляют его. Закрытие поля с текстом сначала
  спрашивает.
- **Ответить** в обсуждении (обсуждение ревью, дискуссия GitLab, комментарий Linear, обсуждение Bitbucket или Azure
  DevOps) публикует в это обсуждение. Там, где у хостинга только плоский список, **Ответить** начинает новый
  комментарий с цитатой выбранной записи (`> **автор**`), так же как **Цитата**.
- **Внутренняя заметка** (флажок, `Alt+I`): в GitLab и Redmine комментарий виден только участникам проекта. Он
  показывается только на хостингах, у которых такие заметки есть, и только в новом комментарии.
- Публикация - внешнее действие: ничего не журналируется и **из GitPoulpi ничего нельзя отменить**. Без соединения
  поле остаётся, **Отправить** неактивна с указанием причины, а заголовок сообщает, что показана сохранённая копия.

**Кто может изменять и удалять.** Только у ваших комментариев есть **Изменить** и **Удалить**. Первым слово собственно
хостинга, если он его даёт (`viewerCanUpdate` и `viewerCanDelete` в GitHub, `can_edit` в остальных), затем ваш логин
сравнивается с автором комментария без учёта регистра; комментарии бота App должны ещё и принадлежать учётной записи
бота. Пока логин бота GitHub App неизвестен, учитываются только комментарии, опубликованные этой установкой
(репозиторий хранит их id): по имени ничего не угадывается. В обсуждении **Изменить** и **Удалить** действуют на
последний ваш комментарий в нём. Хостинг, который не умеет изменять или удалять (см. [таблицу](#чего-не-может-каждый-хостинг)),
показывает кнопки неактивными с указанием причины.

### Публикация от имени

Строка под заголовком сообщает, от чьего имени публикуются ваши сообщения, и та же строка есть в каждом поле:

| Строка | Значение |
|---|---|
| *Публикация как ann (личный токен)* | Токен профиля: ваш собственный логин (`GET /user`). |
| *Публикация как ci-bot (команда токена репозитория)* | Для API хостинга используется [команда токена](hosting-integration.md#8-работа-от-имени-бота-github-app) репозитория. |
| *Публикация как my-app[bot] (бот GitHub App)* | Токен установки. Имя берётся из **Публиковать как**, иначе у хостинга. |
| *Публикация как бот GitHub App (его имя пока неизвестно: задайте «Публиковать как» в настройках)* | Имя не задано и ещё не узнано. |
| *Публикация как ... (бот проекта)* | Токен доступа проекта или группы GitLab. |
| *Запись как kai (локальная заметка)* | Папка заметок Markdown: `local.me` профиля, иначе подключённый пользователь. |
| *Пока неизвестно, от чьего имени публиковать. Задайте «Публиковать как» в настройках.* | Ничего не удалось узнать. |

**Публиковать как** - это имя: для GitHub App это `my-app[bot]`. Задайте его для всех репозиториев в **Настройки >
Интеграции > Публиковать как** (`general.hosting_post_as`) или для одного репозитория в **Настройки > Настройки
репозитория > SSH и учётные данные > Хостинг**, где оно имеет приоритет. Если оно пусто, GitPoulpi спрашивает GitHub
(GraphQL `viewer { login }`, на что токен установки может ответить, а может и нет), а если не вышло, узнаёт имя по
автору первого опубликованного им комментария и хранит его вместе с репозиторием. Личному токену оно никогда не
нужно. См. [Работа от имени бота GitHub App](hosting-integration.md#8-работа-от-имени-бота-github-app).

### Перекрёстные ссылки

Ссылки в беседе подчёркнуты и доступны для щелчка. Сначала сопоставляются связанные источники ЗАДАЧ и PULL REQUESTS
репозитория, поэтому `ABC-12` связанного проекта Jira открывается в приложении даже внутри комментария GitHub; то,
что добавляет собственная грамматика хостинга, открывает его страницу после подтверждения ссылки. Id commit'а
открывается в Log, если репозиторий клонирован и в id не меньше 7 символов, иначе на хостинге. Ничто внутри
фрагмента кода, блока кода, ссылки Markdown, адреса электронной почты или URL ссылкой не считается, как и `C#1`,
`UTF-8`, `SHA-256` и `ISO-8601`.

| Хостинг | Распознаётся |
|---|---|
| GitHub | `#7`, `GH-7`, `owner/repo#7`, `owner/repo@sha`, `@login`, id commit'ов |
| GitLab | `#7`, `!7`, `group/project#7`, `group/project!7`, `project#7` (соседний проект), `@user`, `~label` и `%milestone` как плашки, id commit'ов |
| Gitea, Forgejo | `#7`, `!7`, `owner/repo#7`, `owner/repo@sha`, `@user`, id commit'ов |
| Azure DevOps | `#7`, `!7`, `AB#7`, `@user` |
| Bitbucket | упоминания `@user`, `{uuid}`, id commit'ов |
| Gerrit | значения `Change-Id` (`I` и 40 шестнадцатеричных цифр), id commit'ов |
| Redmine | `#7`, ревизии `r123`, `commit:abc1234` |
| Jira, Linear, YouTrack | `ABC-12`, только для проекта или команды связанного источника |
| Trello | адреса карточек (`trello.com/c/...`) |
| Локальные заметки | `[[note]]`, `[[note\|alias]]` и относительные ссылки `.md` на другую заметку папки |

`gitpoulpi hosting markdown --body T --id I` выводит, что приложение делает из текста, включая ссылки.

### Преобразование разметки

Хостинги, не знающие Markdown, преобразуются в обе стороны, поэтому везде вы читаете и пишете Markdown. То, чего
преобразователь не понимает, остаётся читаемым текстом.

- **Jira** (Cloud и Data Center) хранит комментарии как вики-разметку по API v2. Прочитанное преобразуется в Markdown;
  написанное преобразуется в вики-разметку, а внизу сказано *Отправляется как вики-разметка Jira*.
- **Redmine** оформляет текст как Textile или Markdown, чего API не сообщает: об этом GitPoulpi говорит строка профиля
  **Формат текста сервера** (Настройки > Интеграции, `markup`, по умолчанию Textile). Textile преобразуется в Markdown
  для чтения и обратно в Textile для записи.
- **Azure DevOps Server** возвращает комментарии рабочих элементов как HTML и принимает их как HTML: они показываются
  как Markdown, преобразованный из него, и записываются как HTML. Azure DevOps Services и обсуждения pull request'ов
  принимают Markdown.
- **Gerrit** - простой текст: он не отрисовывается как Markdown, а написанное отправляется как набрано.
- Каждый импортёр сначала удаляет управляющие и escape-последовательности, поэтому комментарий не может управлять
  терминалом.

### Сохранённая копия, «Загрузить старые», непрочитанное

- Каждая открытая беседа сохраняется (`<state dir>/conversations/<integration>/<project>/<kind>-<n>.json`, только
  для пользователя, без токена, не больше 2 МБ на файл, хранятся 50 последних файлов). Она рисуется сразу при
  открытии элемента и обновляется позади. Когда хостинг недоступен, сохранённая копия остаётся на экране под строкой
  *Офлайн: показана копия, сохранённая 3 мин назад (причина)*, а «Отправить» неактивна.
- **Непрочитанное:** то, что вы видели последним, запоминается для каждой беседы (хранятся последние 200). Записи
  других людей, которые новее, получают цветную полосу и метку `новое`, а `n` переходит к следующей. В беседе,
  открытой впервые, нового нет.

### Чего не может каждый хостинг

Каждое «нет» ниже - настоящее ограничение: элемент управления скрыт или неактивен с указанием причины, а CLI отвечает
ошибкой с названием хостинга до отправки чего-либо.

| Хостинг | Элементы | Ответ в обсуждении | Изменение и удаление своих | Разрешение обсуждения | События | Внутренние заметки | Пишется как |
|---|---|---|---|---|---|---|---|
| GitHub | задачи, pull request'ы | pull request'ы | оба | pull request'ы | да | нет | GitHub Markdown |
| GitLab | задачи, merge request'ы | да (дискуссии) | оба | merge request'ы | да | да | GitLab Markdown |
| Gitea | задачи, pull request'ы | pull request'ы | оба | pull request'ы | да | нет | Markdown |
| Forgejo | задачи, pull request'ы | pull request'ы | оба | нет (у хостинга нет конечной точки) | да | нет | Markdown |
| Azure DevOps | рабочие элементы, pull request'ы | pull request'ы | оба | нет (статус показывается, но не меняется) | только pull request'ы | нет | Markdown (HTML у рабочих элементов Server) |
| Bitbucket (Cloud, Data Center) | только pull request'ы | да | оба | нет (показывается, но не меняется) | да | нет | Markdown |
| Gerrit | только изменения | да | нет (ни то, ни другое нельзя изменить или удалить) | да | да | нет | простой текст |
| Jira | задачи | нет (плоский список) | оба | нет | да (журнал изменений) | нет (нужна роль в проекте) | вики-разметка |
| Linear | задачи | да (ответы на комментарий) | оба | нет | да | нет | Markdown |
| YouTrack | задачи | нет | оба | нет | нет | нет | Markdown |
| Redmine | задачи | нет | только изменение (Redmine 5 и новее), удаления нет | нет | да (журналы) | да (закрытые заметки) | Markdown или Textile |

Кроме того: ни один хостинг не позволяет начать из беседы новое обсуждение у строки (делайте это в ревью), а реакции
показываются только в GitHub. Текст длиннее, чем принимает хостинг, отклоняется (GitHub 65 536 символов, GitLab
1 000 000, Azure DevOps 150 000, Jira 32 767, Trello 16 384): CLI проверяет заранее, в приложении показывается
собственное сообщение хостинга, а ваш текст сохраняется. Локальная заметка хранит свои комментарии в последнем разделе
`## Comments` самого файла заметки, по одной записи `### автор - время`, поэтому их видят и Obsidian, и оболочка.

В командной строке те же беседы - это `gitpoulpi hosting issue comments`, `issue comment`, `comment-edit` и
`comment-delete`, а также `hosting review conversation` (см. [справочник по CLI](cli-reference.md)); для агентов это
инструменты MCP с теми же именами (см. [MCP и агенты](mcp-and-agents.md)).
