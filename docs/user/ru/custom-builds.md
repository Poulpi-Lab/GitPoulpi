# Пользовательские сборки

Для тех, кому нужен исполняемый файл поменьше: интерактивный скрипт спрашивает,
какие языки, интеграции с хостингами, темы, цвета логотипа и функции включить,
и собирает только их с оптимизированным профилем. Обычная сборка и официальный
релиз не меняются (всё включено).

```
./build-custom.sh                # Linux / macOS (scripts/build-custom.sh)
build-custom                     # Windows, cmd или PowerShell (scripts/build-custom.ps1)
```

Результат попадает в `target/custom/`, никогда не поверх официального
`target/dist/`. Скрипт выводит размер каждого исполняемого файла и разницу с
`target/dist/`, если та сборка существует. Рядом с исполняемыми файлами он
записывает и `BUILD-FEATURES.txt`.

## Что вы выбираете

| Выбор | Если отключить |
|---|---|
| Языки | Только английский (собирается всегда) плюс отмеченные вами. В списке выбора в Настройках только собранные языки. |
| Темы | GitPoulpi Dark, GitPoulpi Light и Terminal собираются всегда (`system` требует Dark и Light). Все остальные темы выбираются по семействам (`catppuccin`, `gruvbox`, `nightfox`, ...; `--list-themes` выводит их). Невыбранные темы не компилируются: их нет ни в выпадающем списке Настроек, ни в `gitpoulpi theme list`, а конфигурация с такой темой обрабатывается как с неизвестной, с обычным предупреждением. |
| Цвета логотипа | Пиксельный осьминог в окне «О программе» существует в 20 цветовом варианте (`--list-logo-colors`). Выберите те, что компилировать (минимум один), вариант по умолчанию (его первым показывает «О программе»; к нему же возвращается сохранённый `ui.logo_color`, которого нет в сборке; он должен входить в собранные; официальный по умолчанию: lavender) и цвет значка исполняемого файла Windows (любой вариант, по умолчанию: вариант логотипа по умолчанию). С единственным вариантом логотип по-прежнему вращается по щелчку, но остаётся этого цвета, а список цветов (`c`, правый щелчок) не предлагается. |
| Интеграции (GitHub, GitLab, Gitea, Forgejo, Azure DevOps, Bitbucket, Gerrit, Jira, Trello, Linear, YouTrack, Redmine) | Без них: только клонирование по URL; никаких задач, pull/merge request. |
| ИИ | Нет кнопок ИИ, команд и инструментов `ai` в CLI/MCP. |
| MCP | Нет исполняемого файла `gitpoulpi-mcp` и команды `gitpoulpi mcp`. Команды агентов `ui` остаются. |
| LFS, Worktree, подмодули | Соответствующие экраны управления и команды исчезают; возвращается типизированный ответ «not built into this binary». |
| Загрузка аватаров | Только значки с инициалами, без обращения к сети. |
| Просмотр изображений | Файлы изображений показываются обычным уведомлением о двоичном файле; **Править в** по-прежнему работает. |
| Radar | Нет вкладки Radar, `Alt+R` и команды палитры; Radar не открывается. Нужна интеграция (без неё он и так бездействует). |
| Mermaid | Нет «Копировать как Mermaid gitGraph» (меню Log, `Shift+Y`, палитра) и нет `log --format mermaid` в CLI/MCP. Также нет кнопки **Открыть диаграмму** под блоком `mermaid` в [беседе](hosting-integration.md#5c-беседы) (блок остаётся кодом) и нет строки палитры *Беседа: открыть диаграмму записи*. |
| Доска | Нет канбан-доски (кнопка в заголовке ЗАДАЧИ, палитра) и нет команды `hosting board`. Нужна интеграция. |
| Беседа | Нет встроенного окна [беседы](hosting-integration.md#5c-беседы) задачи или запроса: `Enter` на строке задачи, карточке доски или строке Radar по-прежнему открывает браузер, нет пункта *Открыть беседу* и команд палитры *Беседа: ...*, а в беседе нет **Написать с ИИ** (поля ревью, формы задачи и формы pull request'а сохраняют свои). Команды беседы в CLI и MCP (`hosting issue comments`, `comment`, `comment-edit`, `comment-delete`, `hosting review conversation`) и `ai hosting-reply` остаются. Нужна интеграция. |
| Ревью | Страница обзора ревью - это вид беседы, поэтому сборка с Ревью содержит и вид беседы, что бы ни говорила строка *Беседа*. Нет встроенного вида код-ревью (меню строки, Enter на строке pull request, палитра, `Ревью` в Radar) и нет помощи ИИ в ревью. Команды CLI/MCP `hosting review` остаются (их используют Gerrit и агенты). Нужна интеграция. |
| Окно переписывания (расширенная перезапись истории: авторы, даты, сообщения, содержимое) | Нет окна переписывания: нет команд палитры `Переписывание:`, сочетания для окна, клавиш и раздела справки, нет строк «Переписать историю» в меню Log, нет кнопки «Изменить историю глубже...» в диалоге Amend, нет «Создать правила с ИИ» и ИИ для скриптов, нет ограничений скриптов на странице настроек Синхронизации и нет блоков ИИ для перезаписи истории в настройках ИИ. Команды `rewrite` в CLI/MCP, `ai rewrite-script`, `ai rewrite-rules` и `ui propose rewrite` исчезают из дерева команд. Идентичности `.mailmap` (`mailmap`, `log.use_mailmap`) сюда не входят и остаются. |
| Глобальный поиск | Нет кнопки «Глобальный поиск» в строке заголовка, нет `Ctrl+Alt+F`, нет команды палитры `Поиск: рабочее пространство...` и нет команды `gitpoulpi search` в CLI/MCP. Строка поиска в Log (`ui show search`) - другая функция и остаётся. |
| Рабочие пространства | Окно работает с единственным списком вкладок по умолчанию («Нет рабочего пространства»): нет метки рабочего пространства, вкладки «Рабочие пространства», `Alt+W` / `Alt+J`, команд палитры `Рабочее пространство:`, строк «Добавить в рабочее пространство» у вкладок, команд `gitpoulpi workspace` в CLI/MCP и флага `--workspace` у `commit` и `search`. Вкладки и сеансы работают как обычно. Файл `workspaces.toml`, записанный другой сборкой, не читается и не меняется; профиль по умолчанию и инструкции ИИ рабочего пространства не применяются. Radar и глобальный поиск охватывают открытые вкладки. |
| Скрипты перезаписи (встроенный Lua) | Правила Script при перезаписи истории отклоняются типизированным ответом «не встроено в этот бинарный файл», и Lua не линкуется. Само окно переписывания остаётся (у него свой выбор). Не имеет смысла, с предупреждением, если окно переписывания отключено. |

Ваши файлы конфигурации общие для всех сборок: настройка того, чего нет в
сборке, сохраняется и игнорируется.

## Интерактивный режим

Скрипт Bash использует списки флажков `whiptail` или `dialog` (три экрана,
затем сводка) либо нумерованные вопросы, если их нет. Скрипт PowerShell
использует `Out-GridView`, если он доступен, иначе вопросы. Ваш предыдущий выбор
отмечен заранее.

## Неинтерактивный режим

Любой аргумент пропускает вопросы и сразу запускает
`cargo run -p xtask -- build-custom`:

```
./build-custom.sh --langs fr,de --integrations github --no-ai --no-mcp
./build-custom.sh --last --dry-run         # прежний выбор, только вывести команду cargo
.\build-custom -Langs fr -Integrations none -NoAi -NoLfs -NoWorktree -NoSubmodules
```

| Параметр | Значение |
|---|---|
| `--langs fr,de` / `all` / `en` | Языки, кроме английского. Коды - имена файлов локалей (`pt-br`, `zh-cn`...). |
| `--integrations github,gitlab,azure-devops,bitbucket,jira,trello,gitea,linear,youtrack,redmine,gerrit,local-issues` / `all` / `none` | Провайдеры: GitHub, GitLab (включая self-managed), Azure DevOps (Services и Server), Bitbucket (Cloud и Data Center) (хостинги), Gitea и Forgejo, включая Codeberg (`gitea`) (хостинги), Jira, Trello, Linear, YouTrack (Cloud и Server), Redmine (трекеры задач), Gerrit Code Review (`gerrit`, только ревью), локальные задачи Markdown (`local-issues`, папка или хранилище Obsidian). Каждый из `azure-devops`, `bitbucket`, `gerrit`, `gitea`, `jira`, `linear`, `local-issues`, `redmine`, `trello`, `youtrack` - отдельная функция cargo; размеры в [binary-size](../../developer/binary-size.md). |
| `--themes all` / `none` / `nord,catppuccin` | Семейства тем для компиляции (по умолчанию `all`). `--list-themes` выводит семейства. |
| `--logo-colors all` / `violet,teal` | Цветовые варианты логотипа для компиляции (по умолчанию `all`, в порядке таблицы, а это порядок вращения). `--list-logo-colors` выводит их (`*` = официальный по умолчанию). |
| `--logo-default teal` | Вариант по умолчанию; должен входить в собранные (по умолчанию: lavender, иначе первый из собранных). |
| `--icon-color sun` | Цвет значка исполняемого файла Windows (по умолчанию: вариант логотипа по умолчанию). |
| `--[no-]ai`, `--[no-]mcp`, `--[no-]lfs`, `--[no-]worktree`, `--[no-]submodules`, `--[no-]avatar-fetch`, `--[no-]image-view`, `--[no-]radar`, `--[no-]mermaid`, `--[no-]board`, `--[no-]review`, `--[no-]conversation` | Каждый по умолчанию включён. |
| `--[no-]history-rewrite` | Окно переписывания (расширенная перезапись истории: авторы, даты, сообщения, содержимое). По умолчанию включено. |
| `--[no-]global-search` | Глобальный поиск (кнопка в строке заголовка, `Ctrl+Alt+F`, `gitpoulpi search`). По умолчанию включён. |
| `--[no-]workspaces` | Рабочие пространства (именованные группы репозиториев). По умолчанию включены; выключенные оставляют только список вкладок по умолчанию. |
| `--[no-]rewrite-scripts` | Встроенный Lua для правил Script при перезаписи. По умолчанию включён; игнорируется с предупреждением, если окно переписывания отключено. |
| `--save <name\|file>` | Сохраняет определённый выбор как сохранённый набор (имя или путь к файлу). |
| `--preset <name\|file>` | Начинает с сохранённого набора (имя или путь к файлу); остальные параметры переопределяют его, где бы они ни стояли в строке. |
| `--list-presets`, `--delete-preset <name>` | Выводит сохранённые наборы и их папку / удаляет один по имени. |
| `--last` | Использовать `target/custom-build/last-choices.env`; другие параметры его переопределяют. |
| `--full` | Вообще без выбора (всё включено). |
| `--profile custom\|dist\|release` | По умолчанию `custom` (настройки `dist`, отдельный каталог результата). |
| `--dry-run` | Вывести точную команду cargo и остановиться. |
| `-- <cargo args>` | Передаётся в cargo, например `--target x86_64-unknown-linux-musl`. |

Имена в PowerShell: `-Langs -Integrations -Themes -LogoColors -LogoDefault -IconColor -NoAi -NoMcp -NoLfs -NoWorktree
-NoSubmodules -NoAvatarFetch -NoImageView -NoRadar -NoMermaid -NoBoard -NoReview -NoHistoryRewrite -NoGlobalSearch -NoWorkspaces -NoRewriteScripts -Last -Preset -Save -ListPresets -DeletePreset -Full -DryRun -Profile -CargoArgs`.

Выбор тем попадает в сборку через переменную окружения
`GITPOULPI_THEMES` (`all`, `none` или список семейств через запятую), которую
читает скрипт сборки `gitpoulpi-config`; он отбрасывает остальные палитры во
время компиляции; при желании задайте её сами для обычного `cargo build`. `gitpoulpi
--version` выводит строку `themes:` с набором, который был собран.

Выбор логотипа - это переменные окружения `GITPOULPI_LOGO_COLORS`
(`all` или список слагов через запятую), `GITPOULPI_LOGO_DEFAULT` и
`GITPOULPI_ICON_COLOR`, которые читают скрипты сборки `gitpoulpi-tui` (он
фильтрует `assets/logo/colourways.json` в таблицу, встраиваемую в окно «О
программе») и трёх крейтов с исполняемыми файлами (значок). Источник цветов остаётся
`assets/logo/colourways.json`.

### Значок исполняемого файла Windows

Когда целевая платформа - Windows, исполняемые файлы `gitpoulpi`, `gitpoulpi-tui`
и `gitpoulpi-mcp` получают в качестве значка осьминога, который создаётся при
сборке (Python и ImageMagick не нужны) выбранного цвета, размеры от 16 до 128 px.
Он встраивается крейтом `winresource` и требует системного компилятора ресурсов
(`rc.exe` из Windows SDK для MSVC, `windres` для GNU). Если его нет, сборка лишь
выводит предупреждение, а исполняемый файл сохраняет значок по умолчанию. В
наборе инструментов GNU значок несёт только `gitpoulpi` (иначе ресурс был бы скомпонован
дважды). Сборки для Linux и macOS игнорируют всё это, кроме таблицы цветов.

## Сохранённые наборы

Чтобы собрать новую версию, не повторяя весь выбор заново, сохраните его под именем и позже начните с него. Параметры, указанные вместе с `--preset`, по-прежнему переопределяют сохранённые значения.

```
./build-custom.sh --no-ai --no-rewrite-scripts --save no-ai    # keep these choices as "no-ai"
./build-custom.sh --preset no-ai --dry-run                     # start from them later
./build-custom.sh --preset ~/dotfiles/gitpoulpi.env --langs fr # a file path works too
./build-custom.sh --list-presets
./build-custom.sh --delete-preset no-ai
.\build-custom -Preset no-ai -Save no-ai-v2                    # PowerShell
```

Сохранённые наборы - это обычные файлы `КЛЮЧ=значение` (формат `last-choices.env`, читаемый из оболочки). Они лежат в папке `custom-builds` каталога конфигурации GitPoulpi, вне `target/`, поэтому `cargo clean` их не удаляет:

- Linux: `$XDG_CONFIG_HOME/gitpoulpi/custom-builds/` (`~/.config/gitpoulpi/custom-builds/` по умолчанию)
- Windows: `%APPDATA%\GitPoulpi\config\custom-builds\`
- macOS: `~/Library/Application Support/GitPoulpi/custom-builds/`

`GITPOULPI_CONFIG_DIR` переносит эту папку вместе с конфигурацией. `--preset` и `--save` принимают и путь к файлу (значение с `/` или `\` либо оканчивающееся на `.env`), чтобы хранить выбор в репозитории dotfiles.

Выбор, записанный другой версией GitPoulpi, всё равно загружается. Неизвестный ключ, а также язык, интеграция, тема или цвет, которых больше нет, игнорируются с предупреждением. Ключ, которого нет в файле (функция, добавленная позже), получает значение по умолчанию, а добавленная позже интеграция включается; об обоих случаях сообщается в стандартный поток ошибок.

Если есть сохранённый набор, интерактивный режим сначала предлагает «Начать с» (прежние варианты, сохранённый набор или всё включено), а в конце спрашивает, сохранить ли текущий выбор под именем.

## Примечания

- Пользовательская сборка медленная, как любая сборка `dist` (fat LTO, несколько минут).
- Она работает без sccache, как `build-opti`.
- Коды языков проверяются по поставляемым локалям; неизвестный код
  отклоняется с выводом списка допустимых.
