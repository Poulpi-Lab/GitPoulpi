# Запуск в Docker

Образ `poulpilab/gitpoulpi` содержит официальные исполняемые файлы выпуска (`gitpoulpi`, а также прокладки `gitpoulpi-tui` и `gitpoulpi-mcp`) на `debian:bookworm-slim`, а также `git`, `git-lfs`, `openssh-client`, `less` и `tini`. Он работает на `linux/amd64` и `linux/arm64`. Образ лежит на Docker Hub.

## Запуск интерфейса

```
docker run -it --rm \
  --user "$(id -u):$(id -g)" \
  -v "$PWD":/work \
  -v gitpoulpi-config:/config \
  poulpilab/gitpoulpi
```

- `-it` даёт интерфейсу терминал. Без него программе негде рисовать.
- `-v "$PWD":/work` монтирует текущую папку как рабочую (`/work`). Откройте репозиторий оттуда или смонтируйте несколько репозиториев в `/work`.
- `-v gitpoulpi-config:/config` - именованный том, который сохраняет ваши настройки и сеансы между запусками.
- `--user "$(id -u):$(id -g)"` запускает программу от вашего имени, поэтому файлы, которые GitPoulpi создаёт в ваших репозиториях, сохраняют владельца с хоста, а не `root`. Каждая папка, в которую пишет образ, доступна для записи всем, так что подойдёт любой id пользователя.

## Тома и пути

| Путь | Что содержит |
|---|---|
| `/work` | Рабочая папка. Смонтируйте сюда свои репозитории. |
| `/config` | Настройки (`config.toml`), сеансы и, во вложенных папках, данные и кэш (`GITPOULPI_CONFIG_DIR=/config`). Чтобы сохранять их, используйте именованный том или bind-монтирование. |
| `/data`, `/cache` | Тоже объявлены как тома, для инструментов, следующих переменным XDG (`XDG_DATA_HOME=/data`, `XDG_CACHE_HOME=/cache`). |
| `/home/gitpoulpi` | `HOME`. Это не том: для каждого контейнера создаётся новая папка. |

Без тома для `/config` каждый запуск с `--rm` начинается с настроек по умолчанию. Чтобы начать со своего `config.toml`, смонтируйте его: `-v "$PWD/config.toml":/config/config.toml:ro` (только для чтения означает, что настройки не смогут сохраняться).

## Репозитории другого владельца

Git отказывается работать с репозиторием, владелец которого отличается от запускающего пользователя («dubious ownership»). С `--user`, как выше, владелец совпадает. Когда не совпадает (bind-монтирование из другой учётной записи, общая папка Docker Desktop), доверьте все каталоги так:

```
docker run -it --rm -e GITPOULPI_SAFE_DIRECTORY='*' -v "$PWD":/work poulpilab/gitpoulpi
```

Тогда точка входа выполняет `git config --global --add safe.directory '*'` перед запуском интерфейса. Используйте это только для папок, которым вы доверяете, ведь так снимается защита git для всего контейнера.

## SSH

Пробросьте свой агент SSH вместо копирования ключей в контейнер.

Linux:

```
docker run -it --rm \
  -v "$SSH_AUTH_SOCK":/ssh-agent -e SSH_AUTH_SOCK=/ssh-agent \
  -v "$PWD":/work poulpilab/gitpoulpi
```

Docker Desktop (macOS, Windows) выставляет агент хоста по фиксированному пути внутри своей виртуальной машины:

```
docker run -it --rm \
  -v /run/host-services/ssh-auth.sock:/ssh-agent -e SSH_AUTH_SOCK=/ssh-agent \
  -v "$PWD":/work poulpilab/gitpoulpi
```

С `--user` сокет должен быть доступен для чтения вашему id пользователя, и это так, когда он принадлежит вам. В контейнере нет `known_hosts`: при первом подключении к хосту вас попросят принять его ключ, либо смонтируйте свой файл: `-v ~/.ssh/known_hosts:/home/gitpoulpi/.ssh/known_hosts:ro`.

## Личность git и учётные данные

- **Личность и настройки:** смонтируйте свою конфигурацию Git только для чтения: `-v ~/.gitconfig:/home/gitpoulpi/.gitconfig:ro`. Либо задайте личность автора коммитов в профиле GitPoulpi (Настройки > Профили), который хранится в `/config`.
- **Учётные данные HTTPS:** в образе нет помощника учётных данных вроде связки ключей. Либо смонтируйте хранилище учётных данных (`-v ~/.git-credentials:/home/gitpoulpi/.git-credentials:ro`, с `credential.helper = store` в смонтированном `.gitconfig`), либо используйте SSH-remote с проброшенным агентом.
- **Токены хостингов** (pull request'ы, задачи): без помощника учётных данных GitPoulpi хранит токен только в памяти на время сеанса. Для постоянной настройки передайте его через окружение: `-e GITPOULPI_TOKEN_<ID>=...`, где `<ID>` - id интеграции в верхнем регистре, с небуквенно-цифровыми символами, заменёнными на `_` (см. [Интеграции с хостингами и трекерами задач](hosting-integration.md)). Сами интеграции находятся в `config.toml` в `/config`.

## Терминал, цвета и мышь

Цвета и поддержку мыши даёт ваш эмулятор терминала. Docker передаёт `TERM` из `-t`; добавьте `-e TERM -e COLORTERM`, если цвета или тема true-color выглядят неправильно, например `-e COLORTERM=truecolor`. Щелчки мыши, перетаскивание и колесо приходят через терминал как обычно. Граф коммитов рисуется символами; изображения (kitty, iTerm2, sixel) передаются не через каждый терминал и мультиплексор, см. [Выбор терминала](terminals.md). Изменение размера окна терминала меняет размер интерфейса: контейнер получает изменение размера.

## CLI и MCP

Точка входа запускает интерфейс. Остальные программы доступны, если переопределить её:

```
# скриптовый CLI (добавьте --json для скриптов)
docker run --rm --entrypoint gitpoulpi -v "$PWD":/work poulpilab/gitpoulpi status

# сервер MCP через стандартный ввод и вывод, для агента, который его запускает
docker run -i --rm --entrypoint gitpoulpi -v "$PWD":/work poulpilab/gitpoulpi mcp serve
```

Каждый `docker run` - это отдельный контейнер со своим фоновым демоном GitPoulpi, поэтому изменения, сделанные через CLI, не видны вживую в интерфейсе, запущенном в другом контейнере. Чтобы управлять одним интерфейсом из CLI, запустите оба в одном контейнере: запустите интерфейс с `--name gp` и используйте `docker exec gp gitpoulpi ...`. Для агента зарегистрируйте `docker run -i --rm --entrypoint gitpoulpi ... mcp serve` как команду сервера MCP, см. [MCP и агенты](mcp-and-agents.md); переключатели разрешений MCP в смонтированном `config.toml` действуют как обычно.

## Теги и обновление

| Тег | Значение |
|---|---|
| `X.Y.Z` | Один точный выпуск. |
| `X.Y` | Последний патч этой минорной версии (только стабильные выпуски). |
| `latest` | Последний стабильный выпуск. |

Предварительный выпуск получает только свой точный тег `X.Y.Z-...`.

Образ заменяется, а не обновляется на месте. GitPoulpi внутри контейнера это знает (его запись об установке гласит «образ Docker»): [панель обновлений](updates.md) показывает версию и команды и ничего не заменяет. Чтобы обновить:

```
docker pull poulpilab/gitpoulpi
```

Затем запустите новый контейнер. Ваши настройки остаются в томе `/config`. Чтобы вернуться назад, запустите более старый тег: `docker pull poulpilab/gitpoulpi:<предыдущая>`. Чтобы закрепить версию в скриптах, используйте точный тег вместо `latest`. Организация может сделать зеркало образа в собственном реестре, см. [Корпоративное распространение](enterprise-distribution.md#зеркало-реестра-docker).
