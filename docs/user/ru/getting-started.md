# Начало работы

Эта страница проведёт вас от свежей установки до первого commit'а.
[Обзор интерфейса](interface-tour.md) называет каждую область окна.
В [Настройках](settings.md) перечислены все параметры.

## 1. Установка и запуск

Следуйте разделу [Установка](installation.md). Затем откройте терминал в
Git-репозитории и выполните:

```
gitpoulpi-tui
```

`gitpoulpi` без подкоманды делает то же самое. GitPoulpi открывает репозиторий,
содержащий текущую папку. Вне репозитория он открывает вкладку **Главная**, где
можно просматривать и клонировать репозитории или инициализировать новый (см.
[шаг 7](#7-открытие-клонирование-и-инициализация-репозиториев)).

Для значков нужен шрифт Nerd Font или шрифт с эмодзи. Если вы видите
квадратики, см. [Устранение неполадок](troubleshooting.md).

![Главное окно: боковая панель Refs слева, граф Log посередине, рабочие изменения с формой commit'а справа](../images/hero.png)

## 2. Три клавиши, с которых начинается всё остальное

| Клавиша | Открывает |
|---|---|
| `?` | **Справку**: каждая клавиша и жест мыши. Введите текст, чтобы отфильтровать. `Ctrl+D` открывает эту документацию в браузере. |
| `Ctrl+P` | **Палитру команд**: введите, чтобы найти команду, `Enter` запускает её. В каждой строке указано её сочетание клавиш. |
| `Ctrl+,` | **Настройки**. Шестерёнка в строке заголовка, левее ×, тоже открывает их. |

Всё можно делать с клавиатуры или мышью. Палитра охватывает каждую команду. См.
[Сочетания клавиш](keybindings.md) и
[Мышь и жесты](mouse-and-gestures.md).

![Палитра команд, отфильтрованная по слову stage, со списком команд индекса и их сочетаниями клавиш](../images/palette.png)

## 3. Просмотр истории

Середина окна - это **Log**: одна строка на commit, новые сверху. Он показывает
ветки и tag'и цветными плашками, граф, сообщение, автора, дату и короткий хеш.

- Щёлкните commit. Справа появятся его сведения и изменённые файлы.
- Щёлкните изменённый файл. Его diff откроется посередине. `Esc` закрывает его.
- `j` / `k` или стрелки двигают выделение. `f` ищет по commit'ам.
- Щёлкните commit правой кнопкой, чтобы увидеть его меню.

![Log с выбранным commit'ом слияния: его сообщение, автор и два добавленных им файла справа](../images/log-graph.png)

## 4. Внесите изменение и добавьте его в индекс

Отредактируйте файл в своём редакторе. **Верхняя строка Log** теперь показывает
рабочие изменения: пунктирная строка с числом изменённых файлов. Щёлкните её.
Правая панель покажет **Файлы unstaged** и **Файлы staged**.

- Наведите курсор на файл и нажмите его кнопку **Stage**. Или нажмите
  **Stage всё**.
- Щёлкните имя файла, чтобы открыть его diff. Там можно добавить в индекс один
  **hunk** (**Stage hunk**) или одну **строку**.

См. [Индекс и commit'ы](staging-and-committing.md).

![Diff изменённого файла с кнопками Stage Hunk и Discard Hunk над каждым блоком](../images/diff.png)

## 5. Commit

Введите заголовок и, при желании, описание в форме commit'а справа внизу. Затем
нажмите зелёную кнопку **Commit изменений в N файлах** или `Ctrl+Enter` (либо `Ctrl+G Enter`, откуда угодно). Отметьте
**Amend предыдущего commit'а**, чтобы добавить изменения в последний commit, а
не создавать новый.

Если вы включили [ИИ](ai.md), кнопка `✦` рядом с заголовком пишет
сообщение по изменениям в индексе. GitPoulpi никогда не делает commit,
пока вы не нажмёте кнопку commit'а.

## 6. Поделитесь своей работой

На панели инструментов есть кнопки **Pull** и **Push**, у каждой со списком `▾`.
С клавиатуры нажмите `Ctrl+G`, затем букву: `Ctrl+G p` делает pull,
`Ctrl+G Shift+P` делает push. После `Ctrl+G` строка состояния перечисляет буквы.

GitPoulpi использует аутентификацию, которую уже использует ваш `git`
(credential helper, ssh-agent). Собственная учётная запись ему не нужна. Чтобы
видеть и создавать pull request, один раз подключите аккаунт хостинга. См.
[Хостинги и трекеры задач](hosting-integration.md).

## 7. Открытие, клонирование и инициализация репозиториев

Щёлкните значок домика на левом конце строки вкладок или нажмите `Ctrl+O`.
Вкладка **Главная** перечисляет ваши открытые, избранные и недавние репозитории с
кнопками **Обзор**, **Клонировать** и **Init**. Каждый репозиторий открывается в
отдельной вкладке. `Ctrl+W` закрывает текущую вкладку.

![Вкладка «Главная» со списком открытых и недавних репозиториев и кнопками Обзор, Клонировать и Init](../images/home.png)

**Клонировать** запрашивает URL и папку либо позволяет выбрать репозиторий из подключённой учётной записи (GitHub, GitLab, Gitea, Forgejo, Azure DevOps, Bitbucket, Gerrit; см. [Клонирование из подключённой учётной записи](hosting-integration.md#клонирование-из-подключённой-учётной-записи)). **Init** превращает папку в новый репозиторий.
Во всех трёх диалогах (и в окне выбора папки, которое они открывают) `Ctrl+N` показывает значок у каждого поля и кнопки: нажмите этот символ, чтобы поставить курсор в поле или нажать кнопку.

| ![Диалог «Клонировать репозиторий»: куда клонировать, URL, имя папки и кнопки «Отмена» и «Клонировать»](../images/clone.png) | ![Диалог «Инициализировать репозиторий»: папка, имя и начальная ветка](../images/init.png) |
|---|---|

### Частичный checkout

Большой репозиторий не обязан целиком попадать на диск. В диалоге «Клонировать репозиторий» отметьте **Частичный checkout (только некоторые каталоги)** и введите нужные каталоги через пробел или запятую (`src docs/guide`). Checkout делается только для этих каталогов и файлов в корне репозитория; вся история всё равно скачивается, поэтому Log, blame и ветки работают как обычно. Пока флажок отмечен, нужен хотя бы один каталог.

![Окно «Частичный checkout» с двумя введёнными каталогами и кнопками «Отмена», «Выключить» и «Применить»](../images/sparse-checkout.png)

Любой репозиторий можно переключить позже: откройте палитру команд (`Ctrl+P`) и выполните **Репозиторий: Частичный checkout...** или воспользуйтесь **Частичный checkout...** в меню вкладки репозитория. Окно перечисляет каталоги, для которых сейчас сделан checkout, в одном поле: добавьте или удалите имена и нажмите **Применить** (`Enter`) либо **Выключить (полный checkout)**, чтобы вернуть каждый файл. Пока рабочее дерево частичное, в строке состояния виден маленький значок `частичный`. Те же элементы управления есть и на странице *Настройки > Частичный checkout* (список путей по одному в строке и кнопки **Начать**, **Остановить** и **Обновить**).

Примечания:

- Это режим cone в git (каталоги, а не шаблоны); `*`, `..` и абсолютные пути отклоняются.
- Изменение набора не записывается в Отмену: ничего не теряется, а **Выключить** восстанавливает каждый файл. Git может отказаться убрать каталог с незафиксированными изменениями (ошибка появится в строке состояния); сначала сделайте commit или stash.
- То же из скриптов и от агентов: `gitpoulpi clone <url> --sparse src docs` и `gitpoulpi sparse-checkout status | set | add | disable` (см. [справочник CLI](cli-reference.md)); у сервера MCP те же инструменты.
