# Изображения в виде Diff и в просмотре файла

Двоичный файл, являющийся изображением, показывается как картинка, а не как
сообщение «(нет текстовых изменений - двоичное содержимое...)». Вид Diff показывает
**до** и **после**; просмотр файла показывает файл как есть; редактор слияния
показывает стороны конфликтной картинки. Здесь всё только для чтения: просмотр
картинки никогда не меняет репозиторий, поэтому отменять нечего.

Отключается через **Настройки > Изображения > Показывать изображения**
(`ui.image_view`): возвращается обычное сообщение о двоичном файле. В
пользовательской сборке без функции `image-view` просмотра нет вообще, а
страница «Изображения» сохраняет только список редакторов (см.
[Пользовательские сборки](custom-builds.md)).

## Какие файлы

PNG и JPEG всегда; GIF, WebP (их первый кадр), BMP и ICO/CUR, когда в сборке есть
`image-view`. TIFF, AVIF, HEIC, PSD и RAW распознаются, но не декодируются:
информационная карточка показывает формат, размер и габариты. SVG - это текст и
сохраняет текстовый diff. Изображение больше **Макс. размер просмотра (МиБ)** (по
умолчанию 32 МиБ) или больше 64 мегапикселей показывается информационной
карточкой. Файл, хранящийся в Git LFS, показывается, если его объект есть в
локальном хранилище; иначе карточка предлагает сначала выполнить `LFS > Pull`.
Прозрачность рисуется поверх шахматной сетки.

## Как это рисуется

В терминале с протоколом изображений (Kitty и Ghostty, WezTerm и iTerm2, Rio,
mintty) картинка настоящая. В любом другом (обычный Windows Terminal, tmux,
незнакомый GitPoulpi терминал) она рисуется цветными символами полублоков:
вертикальное разрешение вдвое ниже, зато читается везде; параметр **Без протокола
изображений** можно установить в *Только карточка*. **Протокол изображений** на
странице **Журнал и граф** принудительно выбирает протокол.

## Вид Diff

Откройте diff файла-изображения (commit'а либо части WIP: вне индекса или в индексе). Заголовок называет оба файла (`PNG 512x512 . 34 KiB -> PNG 640x480 . 41 KiB`),
затем кнопки масштаба, **Вписать**, **1:1** и **Править в**.

- **Рядом | Единый** справа в заголовке или `m`: бок о бок или по одной
  картинке. **Tab** или щелчок по *До | После* показывает другую в виде «Единый».
  Если окно слишком узкое для двух панелей, раскладка «Рядом» рисуется как
  «Единый», не меняя вашу настройку (`ui.diff_layout`).
- **Разделитель** меняет положение перетаскиванием, `Alt+Right` /
  `Alt+Left` (панель «до» занимает / отдаёт место) и возвращается на середину
  двойным щелчком или `Alt+0`. Доля запоминается на время сеанса.
- Новый файл показывает одну панель с подписью *Новый файл*, удалённый -
  *Удалённый файл*; обе скрывают переключатель. Неотслеживаемая картинка,
  выбранная в рабочих изменениях, показывается как новый файл.
- Сторона «до» - родительский commit (diff commit'а), `HEAD` (в индексе) или
  индекс (вне индекса); сторона «после» - commit, индекс или файл на диске.
  Если файл на диске меняется при открытом diff (вы сохранили его из редактора,
  его переписал инструмент), картинка обновляется примерно за полсекунды.

## Просмотр файла

Откройте картинку через **Файл** в меню файла или на панели diff: одна панель,
файл в ревизии (или на диске для рабочих изменений).

## Масштаб и прокрутка

| | |
|---|---|
| `+` / `-` (или `=`) | Увеличить / уменьшить вокруг центра панели |
| `0` | **Вписать** (по умолчанию): вся картинка; она остаётся вписанной при изменении размера окна или разделителя |
| `1` | Реальный размер (1:1) |
| Стрелки, `h j k l` | Прокрутка на десятую часть панели; с `Shift` на панель целиком; `PageUp`/`PageDown`, `Home`/`End` |
| Колесо | Прокрутка по вертикали; `Shift`+колесо по горизонтали; `Ctrl`+колесо масштабирует вокруг указателя |
| Перетаскивание | Схватить картинку и двигать; полосы прокрутки по бокам работают как везде |

Увеличенный вид сохраняет масштаб и точку в центре при изменении размера
панели; «Вписать» остаётся «Вписать». В виде Diff две панели используют один
масштаб и одну позицию прокрутки (**Синхронизировать масштаб и прокрутку
до/после**, включено по умолчанию), так что в поле зрения одна и та же часть
обеих картинок; если их размеры различаются, масштаб сохраняется относительно
каждой. Начиная с **Пиксельное увеличение с** (по умолчанию 2x) картинка
увеличивается квадратными пикселями, а не сглаживается, что подходит для
значков и пиксель-арта.

## Править в

Кнопка **Править в** в заголовке перечисляет редакторы изображений, найденные
на этом компьютере (GIMP, Krita, Inkscape, Photoshop, Paint.NET, Preview, ... и
программа системы по умолчанию); `o` запускает программу по умолчанию, а
`Shift+O` открывает список. Она также есть в контекстном меню изображения в
списках файлов и в палитре команд (*Изображение: править в...*). Список и
значение по умолчанию настраиваются в **Настройки > Изображения**, так же как
работает [Открыть в](open-in.md).

Правка файла на диске (сторона рабочих изменений) прямая: редактор сохраняет на
месте, и картинка обновляется. Любая другая версия (commit'а, индекса,
удалённого файла) записывается во **временную копию только для чтения** с
уведомлением в строке состояния, так что редактор не может изменить репозиторий.

Приложения, которые система регистрирует для типа изображения (её список «Открыть с помощью...»), идут после ваших редакторов в списке и не повторяют уже имеющуюся программу. У остальных двоичных файлов такой же список, см. [Открыть в](open-in.md).

## В редакторе слияния

Конфликтная картинка показывает свою карточку с изображениями **A**, **B** и (если
есть) **База** в полях рядом, каждое вписано в своё поле и только для чтения
(масштаба там нет; картинки лишь помогают выбрать). Кнопки и клавиши не меняются:
**Оставить A** (`a`), **Взять B** (`b`), **Взять базу** (`o`), **Открыть во внешнем merge-инструменте** (`m`). Для просмотра нужно достаточно широкое окно (около 70 столбцов) и
немного свободных строк; при меньшем размере карточка текстовая. См.
[Разрешение конфликтов слияния](merge-conflicts.md).

## Клавиши и настройки

Клавиши описаны в разделе [Сочетания клавиш](keybindings.md#просмотр-изображений);
каждую можно переназначить, и все доступны из палитры (`Ctrl+P`, введите
*Изображение*). Настройки находятся на странице **Изображения** в
[Настройках](settings.md#изображения) и в
[справочнике по конфигурации](config-reference.md) (`ui.image_view*`, `ui.image_editors`).
