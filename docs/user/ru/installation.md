# Установка

У GitPoulpi три исполняемых файла:

| Исполняемый файл | Что это |
|---|---|
| `gitpoulpi-tui` | Терминальный интерфейс. |
| `gitpoulpi` | Интерфейс командной строки (`--json` для скриптов). Без подкоманды открывает интерфейс. |
| `gitpoulpi-mcp` | MCP-сервер для ИИ-агентов. См. [MCP и агенты](mcp-and-agents.md). |

Рядом с ними в архиве лежит `gitpoulpi-launch`, крошечная программа, которую запускают ярлыки, чтобы показать уже открытое окно GitPoulpi (`gitpoulpi launch`). В Windows у неё нет окна консоли, поэтому щелчок никогда не вызывает его мигания. Она устанавливается, обновляется и удаляется вместе с остальными.

## Что вам нужно

- **Системный `git`** в вашем `PATH`. GitPoulpi использует libgit2 для большинства
  операций, а ваш `git` для остальных.
  Нужна версия **2.34 или новее**. В macOS подходит `git` из Apple Command Line Tools, а также из Homebrew.
- **Терминал** с поддержкой мыши. kitty, Ghostty, WezTerm и iTerm2 (а также Windows Terminal и foot через sixel) рисуют граф
  commit'ов как изображения. Другие терминалы (консоль Windows, tmux и
  большинство остальных) показывают символьный граф. См.
  [Выбор терминала](terminals.md).
- Шрифт **Nerd Font** или шрифт с эмодзи для значков на панели инструментов и в
  боковой панели.
- По желанию: **`git-lfs`** 3.0 или новее для репозиториев Git LFS. Без него
  файлы LFS показываются как небольшие файлы-указатели, и GitPoulpi объясняет
  почему. Как его установить, см. в [Git LFS](lfs.md).
- По желанию: **credential helper** (Git Credential Manager, libsecret, `pass`,
  Keychain) для хранения токенов хостингов и ключей API ИИ. См.
  [Хостинги и трекеры задач](hosting-integration.md).

## Из архива релиза

Архив релиза называется `gitpoulpi-<version>-<target>.zip` (Windows) или
`.tar.gz` (Linux, macOS), рядом с ним лежит файл `.sha256`. Сверьте архив с
файлом `.sha256`, распакуйте его и поместите три исполняемых файла в папку из
вашего `PATH`. `INSTALL.txt` в архиве описывает те же шаги.

## С установщиком

К каждому выпуску прилагается установщик для каждой ОС. Оба делают одни и те же
выборы (ярлыки, PATH, псевдоним команды вроде `gp`), вызывая сам установленный
`gitpoulpi` - тот же код, что стоит за Настройки > Общие > Лаунчер, поэтому то,
что настроил установщик, и то, что показывают Настройки, всегда совпадает.

### Windows: `gitpoulpi-<version>-x86_64-pc-windows-msvc-setup.exe`

Он ставится для текущего пользователя, без запроса прав администратора, в
`%LOCALAPPDATA%\Programs\GitPoulpi` (в первом диалоге можно выбрать установку
для всех пользователей и папку установки). Флажки: ярлык в меню «Пуск», ярлык на
рабочем столе, добавление в PATH. На отдельной странице спрашивается **псевдоним
команды**: по умолчанию `gp`, можно любое имя, пусто - без псевдонима. В
PowerShell `gp` уже занят командой `Get-ItemProperty`, поэтому там выберите
другое имя или пользуйтесь `gitpoulpi`.

Установщик копирует три исполняемых файла и маркер `.gitpoulpi-dist`, так что
[«Обновить сейчас»](#обновление-на-месте) работает точно так же, как для zip.
Установка для одного пользователя доступна для записи, поэтому может обновлять
себя; установка для всех пользователей в Program Files требует повышения прав
для замены, поэтому её переустанавливают новым установщиком. Удаляйте через
Параметры Windows > Приложения: запускается `gitpoulpi uninstall` (псевдоним,
записи PATH, ярлыки), затем файлы удаляются, включая остатки `.old` от
обновления. Ваши настройки и репозитории остаются.

### Linux и macOS: `install.sh`

```
curl -fsSL https://github.com/Poulpi-Lab/GitPoulpi/releases/latest/download/install.sh | sh
```

Скрипт выбирает архив для вашей ОС и процессора, сверяет его `.sha256`, ставит в
`~/.local/opt/gitpoulpi` и связывает `gitpoulpi` и `gitpoulpi-mcp` ссылками в
`~/.local/bin`. Root не нужен, за пределами домашней папки ничего не
затрагивается. Без `--yes` он спрашивает про псевдоним (по умолчанию `gp`), PATH
и ярлыки.

| Флаг | Действие |
|---|---|
| `--prefix DIR` | Поставить файлы программы в `DIR` (абсолютный путь). |
| `--version X.Y.Z` | Поставить этот выпуск вместо последнего. |
| `--archive FILE` | Взять локальный архив; рядом должен лежать `FILE.sha256` (`--no-verify` это пропускает). Сеть не используется. |
| `--alias NAME` / `--no-alias` | Сделать так, чтобы `NAME` запускал GitPoulpi (`gitpoulpi alias create`), либо без псевдонима. |
| `--no-path` | Не добавлять GitPoulpi в PATH новых оболочек (иначе выполняется `gitpoulpi path add`). |
| `--desktop` | Создать также ярлыки в меню приложений и на рабочем столе. |
| `--yes` | Ничего не спрашивать: действуют флаги и значения по умолчанию (псевдоним `gp`, PATH да, ярлыки нет). |
| `--uninstall` | Выполнить `gitpoulpi uninstall`, затем удалить ссылки и папку. |

Для поиска последнего выпуска репозиторий должен быть открытым; для закрытого
скачайте архив в браузере и используйте `--archive`.

## Из исходников

Нужен свежий стабильный набор инструментов Rust (<https://rustup.rs>).

```
git clone https://github.com/Poulpi-Lab/GitPoulpi.git
cd GitPoulpi
cargo build --release
```

Исполняемые файлы окажутся в `target/release/`. Профиль `release` собирается
быстро. Для самых маленьких и быстрых исполняемых файлов используйте профиль
`dist`. Он собирается дольше:

```
cargo build --profile dist
```

Скрипты `build-opti` в корне репозитория запускают эту сборку для трёх
исполняемых файлов и выводят их размеры:

```
./build-opti.sh                  # Linux, macOS
build-opti                       # Windows (cmd или PowerShell)
```

Чтобы собрать только нужные вам языки и функции, см.
[Пользовательские сборки](custom-builds.md).

## Собрать архив релиза самостоятельно

```
cargo run -p xtask -- dist
```

Это собирает профиль `dist` и записывает
`target/dist/gitpoulpi-<version>-<target>.zip` (Windows) или `.tar.gz` (другие
системы). В архиве три исполняемых файла, `INSTALL.txt`, `README.md`, `LICENSE`
и `CHANGELOG.md`. Рядом записывается файл `.sha256`.

## Обновления

Строка заголовка показывает запущенную версию (`v1.0.0`) между названием приложения
и путём к репозиторию. Щёлкните по ней или выполните из палитры команд (`Ctrl+P`)
**Справка: заметки о выпуске**: откроется вкладка «Заметки о выпуске» со списком
изменений, прокрученным до запущенной версии.

Раз в сутки в фоне GitPoulpi спрашивает GitHub, есть ли новый выпуск
(`updates.mode`, [Настройки > Синхронизация](settings.md#синхронизация)). Если
есть, чип показывает `доступна v0.2.0` акцентным цветом, а щелчок по нему
открывает вкладку «Заметки о выпуске» с заметками этого выпуска сверху. На вкладке
три кнопки, у каждой своя клавиша и команда палитры:

- **Скачать** (`d`, *Обновления: скачать*) открывает страницу выпуска в браузере.
- **Пропустить версию** (`s`, *Обновления: пропустить эту версию*) скрывает
  уведомление, пока не появится более новый выпуск.
- **Проверить** (`r`, *Обновления: проверить наличие сейчас*) спрашивает ещё раз
  немедленно.

`updates.mode = "off"` вообще не делает запросов. Без сети или пока репозиторий
закрытый и токена github.com нет, проверка тихо не удаётся (одна строка в журнале
приложения, в интерфейсе ничего).
`GITPOULPI_UPDATE_API` направляет проверку на другой корень API (нужно тестам).

### Обновление на месте

Сборка, установленная из архива выпуска, может заменить себя сама. В архиве рядом
с исполняемыми файлами лежит небольшой файл `.gitpoulpi-dist`; запущенная сборка
«обновляема» только тогда, когда этот файл лежит рядом с её исполняемым файлом (и
называет её платформу). Сборка через `cargo`, своя сборка, скопированная в другое
место, или пакет, потерявший файл, сама никогда не обновляется: вкладка «Заметки
о выпуске» говорит об этом и предлагает только **Скачать**.

Для обновляемой сборки на вкладке добавляются:

- **Обновить сейчас** (`u`, *Обновления: обновить сейчас*) скачивает в фоне архив
  и его `.sha256` (задача в индикаторе строки состояния, с процентами, отменяется
  как любая задача), проверяет хэш, распаковывает архив и кладёт каждый новый файл
  рядом со старым как `<name>.new`. Ничего работающего не затрагивается. В режиме
  `auto` то же происходит само, как только проверка находит новый выпуск.
- **Перезапустить для обновления** (`R`, *Обновления: перезапустить для
  обновления*; чип говорит то же, когда скачанное подготовлено) - всегда ваше
  действие, никогда не автоматическое. Оно останавливает отдельный демон сеанса
  (встроенный уходит вместе с окном), подменяет файлы и запускает новую версию с
  теми же аргументами и сеансом.
- **Вернуться к предыдущей версии** (`v`, *Обновления: вернуться к предыдущей версии*)
  возвращает прежние файлы и перезапускает. Файлы предыдущей версии лежат как
  `<name>.old`, пока новая версия не проработает минуту, затем удаляются, так что
  кнопка нужна на первый запуск. Это не часть журнала отмены git: меняются
  собственные файлы GitPoulpi, а не репозиторий.

Как заменяются файлы: в Linux и macOS каждый новый файл переименовывается поверх
старого (атомарно; работающая программа держит свою старую копию, пока не
завершится). В Windows работающий `.exe` перезаписать нельзя, поэтому старый
переименовывается в `<name>.old`, а новый переносится на его место; `.old`,
который ещё запущен, удаляется при одном из следующих запусков. Замена - всё или
ничего: если какая-то другая программа держит один из исполняемых файлов (клиент
MCP с запущенным `gitpoulpi-mcp`, например), GitPoulpi называет файл, ничего не
меняет и оставляет скачанное подготовленным для новой попытки.

Что отклоняется, каждый раз с сообщением: выпуск без файла `.sha256`, несовпавший
хэш, файл архива с именем не для этой платформы
(`gitpoulpi-<version>-<target>.<zip|tar.gz>`), архив с маркером, называющим другую
версию или платформу, и любая ссылка для скачивания вне этих хостов:
`github.com`, `api.github.com`, `objects.githubusercontent.com`,
`release-assets.githubusercontent.com` и `github-releases.githubusercontent.com`
(первый запрос и каждый переход по перенаправлению; перенаправление в любое другое
место останавливает загрузку). Архивам закрытого репозитория нужен сеанс браузера,
поэтому там скачивание не удаётся, пока репозиторий не станет открытым.

## Проверка работоспособности

```
gitpoulpi --version
cd path/to/a/git/repository
gitpoulpi-tui
```

`--version` выводит версию и commit, из которого сделана сборка. Затем
следуйте разделу [Начало работы](getting-started.md).

## Удаление

`gitpoulpi uninstall` (его запускают оба установщика) удаляет псевдонимы команд,
записи PATH и ярлыки, созданные GitPoulpi, а затем файлы программы при установке
из выпуска; он отказывается работать в сборке без маркера `.gitpoulpi-dist`
(сборка через cargo), а `--keep-files` оставляет файлы программы. Агентам MCP он
недоступен. Без установщика удалите три исполняемых файла. GitPoulpi также хранит
следующие файлы:

| Что | Где |
|---|---|
| Настройки (`config.toml`) и сеансы | Папка конфигурации вашей ОС. Её меняет `GITPOULPI_CONFIG_DIR`. |
| Состояние каждого репозитория | По умолчанию `gitpoulpi/` внутри каталога `.git` репозитория (см. `session.per_repo_state_dir` в [Справочнике по конфигурации](config-reference.md)). |
| Кэши (аватары) | Папка кэша вашей ОС. |
| Токены и ключи API | Ваш credential helper. **Настройки > SSH и учётные данные > Забыть все имена пользователей и пароли** удаляет их. |

Точные пути см. в [Справочнике по конфигурации](config-reference.md).
