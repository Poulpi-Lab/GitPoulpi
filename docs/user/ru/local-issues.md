# Локальные задачи и Obsidian

Храните задачи как папку заметок Markdown: без учётной записи, без токена, без сети. Папка может лежать внутри
репозитория (`docs/issues/`, с commit'ом вместе с кодом) или где угодно на диске, например в подпапке
[Obsidian](https://obsidian.md)-хранилища. GitPoulpi читает и пишет заметки. Obsidian, любой редактор или оболочка
могут править их одновременно, и списки это подхватывают.

![Локальные задачи Markdown на боковой панели с меню строки одной заметки: открыть заметку, закрыть её, изменить её метки или этап](../images/local-issues.png)

## Настройка

1. **Настройки > Интеграции > Трекеры задач > Local Markdown > Добавить профиль.** Введите папку или нажмите
   **Обзор...** и выберите её. Относительная папка (`docs/issues`) читается относительно каждого репозитория, к
   которому она привязана; абсолютная (`/home/me/Vault/Projects/Issues`) одинакова везде. Токен вводить не нужно.
   - CLI: `gitpoulpi hosting integrations add --kind local_markdown --path docs/issues`.
2. В репозитории откройте раздел **ЗАДАЧИ** боковой панели и выберите провайдера **Local Markdown - <имя>** (папка
   выбирается вместе с ним; список репозиториев показывает папку и её прямые подпапки, если нужна другая).
   - CLI: `gitpoulpi hosting link issues --id <профиль>` (папка профиля - это `--project` по умолчанию).

Само по себе ничего не привязывается: как и любой источник задач, он включается для каждого репозитория отдельно.

## Комментарии к заметке

`Enter` на строке заметки в разделе ЗАДАЧИ или на её карточке открывает её беседу: текст заметки, затем комментарии.
Комментарии хранятся в самом файле заметки, в последнем разделе `## Comments`, по одной записи `### <автор> - <время UTC>`
(у изменённой добавляется `(edited <время>)`). Всё, что выше этого заголовка, никогда не затрагивается, поэтому Obsidian
и оболочка читают и правят один и тот же файл. Можно писать, править и удалять комментарии локального автора
(`local.me` профиля, иначе подключённого пользователя, под этим именем работает *Назначенные мне*); чужие - нельзя.
Поле - обычный редактор Markdown с просмотром, а *Запись как <имя> (локальная заметка)* называет автора. Ничего не
уходит по сети. Заголовок `## Comments`, написанный вами вручную, читается как раздел комментариев.

## Заметки

Одна заметка на задачу с именем `<id>-<slug>.md` (`12-crash-on-empty-name.md`) и блоком frontmatter:

```yaml
---
id: 12
title: Crash on empty name
status: todo
assignees: [kai]
labels: [bug]
milestone: v0.1
created: 2026-10-14
updated: 2026-10-14T09:30:00
---
Свободный Markdown. GitPoulpi никогда не переписывает тело.
```

- Новые задачи получают `max(id) + 1`.
- GitPoulpi пишет только свои свойства (`title`, `status`, `assignees`, `labels`, `milestone`, `updated`).
  **Все остальные свойства, тело, окончания строк и порядок ключей сохраняются байт в байт.** Запись атомарна
  (временный файл, затем переименование).
- Чтение снисходительно: у заметки без `id` он берётся из имени файла, у заметки без `status` статус `todo`, у
  заметки без frontmatter название берётся из первого `# заголовка`. Файл, который не задача (`readme.md`),
  игнорируется.
- Статус - произвольный текст. **Открыта** значит «не статус "готово"».

### Комментарии в заметке

Комментарий к заметке записывается в саму заметку, в последний раздел `## Comments` (без сети, и в Obsidian он
читается нормально):

```markdown
(текст заметки)

## Comments

### kai - 2026-11-15T10:00:00Z
Первый комментарий, **любой Markdown**.

### ann - 2026-11-15T11:30:00Z (edited 2026-11-15T12:00:00Z)
Второй.
```

- Запись начинается со строки, которая в точности равна `### <автор> - <время UTC>`, с ` (edited <время UTC>)` после
  правки; её текст идёт до следующей записи. Раздел - это последний заголовок `## Comments` вне блока кода, он идёт
  до конца файла, поэтому после него ничего не пишите.
- Строка комментария, которая читалась бы как запись или как заголовок, хранится с обратной косой чертой в начале
  (`\### ...`, Markdown показывает тот же текст) и читается обратно без неё.
- Публикация добавляет в конец и оставляет всё выше байт в байт (включая окончания строк); правка или удаление
  переписывает только раздел. Публикация также сдвигает `updated` заметки (заметке без frontmatter он не
  присваивается).
- Автор - локальный автор профиля («я» в настройках локальных задач). Править и удалять можно только свои
  комментарии; id комментария - его время и автор, а две публикации в одну секунду различаются сдвигом второй на
  секунду.
- У заметки нет ответов, внутренних комментариев и истории событий.

## Что можно делать

| В разделе ЗАДАЧИ | Клавиатура / палитра |
|---|---|
| Новая задача (`+` или `n`): название, описание, статус, исполнители, метки, этап | `Хостинг: новая задача...` |
| Изменить исполнителей / метки / этап из меню строки. Выберите из того, что папка уже использует, или **введите новую метку или логин** и возьмите строку `Добавить «...»` | `Хостинг: изменить метки...` и остальные |
| **Закрыть задачу** / **Открыть задачу снова** (задаёт статус «готово» или первый другой) | `Локальные задачи: закрыть задачу...` / `открыть задачу снова...` |
| **Открыть заметку** (ваша программа по умолчанию для `.md`) | `Integrations: Open Issue...` |
| **Открыть в Obsidian** (только когда папка внутри хранилища, то есть выше есть папка `.obsidian/`) | `Локальные задачи: открыть в Obsidian...` |
| Фильтры: Открытые / Закрытые / Все, «Назначены мне» | выпадающий список фильтра |

«Назначены мне» сопоставляется с настройкой профиля `me`, иначе с именем подключения, иначе с именем профиля.

Ветки и commit'ы работают как для GitHub: «Создать ветку из задачи» даёт `12-crash-on-empty-name`, а `#12` в
сообщении commit'а или `12-...` в имени ветки распознаются.

Изменения, сделанные вне GitPoulpi (Obsidian, оболочка, `git pull`), появляются примерно за секунду: имена файлов
папки и время их изменения проверяются в фоновом потоке, никогда не в потоке отрисовки.

## Файл конфигурации

В `config.toml`, рядом с профилем (все ключи необязательны):

```toml
[[integrations]]
id = "vault"
kind = "local_markdown"
url = "/home/me/Vault/Projects/Issues"
token_ref = "integration:vault"

[integrations.local]
statuses = ["todo", "doing", "review", "done"]   # порядок колонок доски
done_status = "done"                            # закрывает задачу
reference_prefix = "LOC"                         # показывается как LOC-12 вместо #12
me = "kai"                                       # что значит «назначены мне»
```

Статусы, которые используют заметки, но которых нет в `statuses`, идут после перечисленных. `statuses` - это порядок
колонок [доски](#доска-канбан) (`gitpoulpi hosting issue options` выводит его).

## Доска (канбан)

![Доска папки заметок: по колонке на статус, карточки с исполнителями, метками и этапом](../images/issue-board.png)

Если вы работаете один или в команде, которая хранит задачи рядом с кодом, папка заодно служит канбан-доской.
**Заголовок ЗАДАЧИ > Доска** или `Задачи: открыть доску` в палитре открывает её поверх окна; `Esc` закрывает.

- **Колонки** - это статусы: сначала перечисленные в `statuses`, в этом порядке, затем любой другой статус, который
  использует заметка. Пустая колонка всё равно показывается. В заголовке каждой - число карточек.
- **Карточки** показывают номер задачи, название (две строки), исполнителей инициалами, метки и этап. Когда колонки
  не помещаются, доска прокручивается вбок (полоса под ней, колесо с `Shift` или стрелки).
- **Перенести карточку** можно перетаскиванием в другую колонку (колонка подсвечивается под указателем), клавишами
  `Shift+←` / `Shift+→` или командой `Доска: перенести карточку в...` (`m`), выпадающим списком колонок. Карточка
  переносится сразу; `status` заметки переписывается, как в [разделе о заметках](#заметки), ничего больше в файле. Если
  запись не удалась, карточка возвращается, а ошибка видна в строке состояния.
- **Открыть** карточку можно `Enter` или двойным щелчком: в окне открывается [беседа](conversations.md) заметки с её текстом и комментариями (пункт меню карточки **Открыть заметку** открывает файл в вашей программе по умолчанию для
  `.md`). `e` меняет её исполнителей, метки или этап, `.` или правый щелчок открывает меню карточки, `n` начинает новую
  задачу в выбранной колонке (форма после закрытия возвращает к доске).
- **Фильтр** по исполнителю (`a`), метке (`l`), этапу (`M`) или тексту (`/`); `x` сбрасывает их. Фильтры - выпадающие
  списки: введите текст, чтобы сузить, `Enter` выбирает.
- **Живая**: заметка, изменённая из Obsidian или оболочки, переносит свою карточку за секунду.

У каждого жеста мыши есть клавиша и команда палитры (`Доска: ...`, перечислены на странице
[сочетаний клавиш](keybindings.md)).

## Obsidian Bases

**Палитра: `Локальные задачи: создать Obsidian Base`** (CLI: `gitpoulpi hosting issue base`) один раз записывает
`issues.base` рядом с заметками: вид *таблица* и вид *канбан* с группировкой по `status` в порядке `statuses`. Откройте
его в Obsidian, чтобы увидеть те же задачи как доску и там. GitPoulpi никогда не правит существующий файл `.base`
(ваш или прежний): он отказывается и говорит об этом. Формат следует синтаксису Bases от Obsidian
(<https://obsidian.md/help/bases/syntax>); для канбан-вида нужен недавний Obsidian.

## CLI и MCP

Работают те же команды, что и для любого источника задач: `hosting issues`, `hosting issue create [--list <статус>]`,
`hosting issue edit <n> --add-label ...`, `hosting open issue <n>`, `hosting refs`. Ещё четыре предназначены для
заметок: `hosting issue close <n>`, `hosting issue reopen <n>`, `hosting issue move <n> --status <s>` и
`hosting issue base`. См. [Справочник по CLI](cli-reference.md).

## Ограничения

- Новый **этап** нельзя ввести в выборщике (выберите уже используемый папкой), но `milestone:` в заметке может быть
  любым и появляется, как только заметка сохранена.
- Задачами считаются только заметки прямо в папке (не в подпапках).
- Удаления нет: удалите заметку в файловом менеджере или Obsidian (его корзина - ваша).
