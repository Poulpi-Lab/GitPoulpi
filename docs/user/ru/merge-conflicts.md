# Разрешение конфликтов слияния

Когда merge, cherry-pick, revert или rebase останавливается на конфликтах, Log
показывает баннер (*Идёт merge · feature в main · 2 файла с конфликтами*), а
файлы с конфликтами появляются в панели Status с красным `!`. Откройте любой из
них в **редакторе слияния**: A (текущая сторона) и B (входящая сторона)
рядом, а под ними **Результат**, то есть файл, который вы пишете. Эта страница
краткая; полный список клавиш находится в разделе [Сочетания клавиш](keybindings.md).

## Как открыть

- `Enter` или двойной щелчок по строке `!` в панели Status; первый пункт её
  контекстного меню (правая кнопка) - **Открыть в редакторе merge**.
- Кнопка **Разрешить конфликты...** на баннере (она открывает первый файл с
  конфликтом).
- Вид Diff файла с конфликтом: кнопка **Редактор merge** (`Shift+E`).
- Палитра: `Конфликты: открыть редактор merge`.

Само ничего не открывается: остановленная операция лишь показывает баннер и
строки `!`.

![Log репозитория, остановившегося на конфликтном слиянии: баннер «Идёт merge» с кнопками Разрешить конфликты и Прервать merge и два файла с конфликтами, помеченные красным !](../images/conflict-banner.png)

Редактор занимает всю ширину окна: боковая панель Refs и
правая панель скрыты, пока он открыт, и возвращаются при его закрытии (`F9`
показывает или скрывает их в это время). A и B стоят рядом, когда редактор
шириной не менее `merge.side_by_side_min_width` столбцов (по умолчанию 100,
**Настройки > Diff и редактор**; `0` означает «всегда»); при меньшей ширине видна одна
сторона за раз, со вкладками. Длинные строки прокручиваются вбок, A и B
вместе (`Shift+←` / `Shift+→`, Shift+колесо или горизонтальное колесо), они
никогда не переносятся.

![Редактор слияния: A (текущая) и B (входящая) рядом над Результатом, конфликт 1 взят из A, конфликт 2 из B, конфликт 3 ещё предстоит выбрать](../images/merge-editor.png)

## Выбор

Каждый конфликт - это блок в рамке в A и в B, с флажком в заголовке и
значком `+` / `✓` перед каждой строкой.

| Чтобы... | Клавиша | Мышь |
|---|---|---|
| взять строку под курсором (в активной стороне) | `Space` | щёлкнуть по строке |
| взять весь блок активной стороны | `Enter` | щёлкнуть по `[ ]` в его заголовке |
| взять только A / только B для этого конфликта | `a` / `b` | правый щелчок по блоку |
| взять обе стороны: A, затем B / B, затем A | `c` / `Shift+C` | правый щелчок по блоку |
| ничего не брать | `x` | правый щелчок по блоку |
| поменять порядок двух выбранных сторон | `s` | щёлкнуть по метке `1-й` / `2-й` |
| взять всё из A / всё из B (все конфликты) | `Shift+A` / `Shift+B` | панель инструментов |
| снять выбор с этого конфликта (вернуть как неразрешённый) | `u` в A / B, `Alt+U` везде | правый щелчок по блоку, **Снять выбор (вернуть как неразрешённый)** |
| сбросить весь файл к исходным конфликтам (спрашивает, если вы вводили текст в Результат; `Ctrl+Z` вернёт) | `Shift+U` в A / B, `Alt+R` везде | **Сброс** рядом с «Взять всё» |
| следующий / предыдущий конфликт | `F7` / `Shift+F7`, `Alt+Down` / `Alt+Up` (`n` / `Shift+N` в A / B) | `▼` / `▲` или щелчок по метке на полосе прокрутки |
| число перед командой повторяет движение | `3j`, `2k`, `2n`, `3N` (в A / B) | |
| следующий / предыдущий файл с конфликтом | `Alt+PageDown` / `Alt+PageUp` | `›` / `‹` в заголовке |
| показать или скрыть панель База (общий предок) | `Alt+D` (`d` в A / B) | `База` |
| показать весь файл в A и B (**Файл целиком**) | `Alt+F` (`f` в A / B) | `Файл целиком` |
| дать A или B больше ширины / вернуть равную ширину | `Alt+Right` / `Alt+Left`, `Alt+0` | перетащить разделитель; двойной щелчок по нему |
| прокрутить A / B / базу вбок | `Shift+←` / `Shift+→` (`Shift+H` / `Shift+L`) | Shift+колесо, горизонтальное колесо |
| показать или скрыть панели Refs и Status | `F9` | |
| перейти к A, B, Результату | `F6` / `Shift+F6` | щелчок |
| перейти к панели на том конфликте, где вы находитесь | `Alt+1` A, `Alt+2` B, `Alt+3` Результат, `Alt+4` База; или `Ctrl+N`, затем `1` / `2` / `3` | |
| перейти к соседней панели (A, База, B, Результат), тот же конфликт | `h` / `l` или `←` / `→` в A / B | |
| переключить высоту Результата по кругу | `z` | перетащить его заголовок |
| отменить / повторить (выбор и ввод, один общий стек) | `Ctrl+Z` / `Ctrl+Y` | |
| записать файл, оставив его конфликтным | `Alt+S` | **Сохранить** |
| записать файл и пометить как разрешённый | `Ctrl+S` | **Сохранить и разрешить** |
| закрыть | `Esc` | `✕` |

На каждой полосе прокрутки (A / B / База и Результат) есть по метке на
конфликт: оранжевая, пока нужен выбор, зелёная, когда конфликт обработан, синяя
для текущего. Щелчок по метке переходит к этому конфликту (метка под ползунком
полосы прокрутки уже на экране, поэтому щелчок там перетаскивает ползунок).

**Файл целиком** показывает весь файл в A и B с подсветкой каждого различия, а не только конфликтов:

![Режим «Файл целиком»: весь файл в A и B, изменения подсвечены цветом](../images/merge-editor-full-file.png)

Результат - настоящий редактор: щёлкните в нём и печатайте, выделяйте,
вырезайте и вставляйте, ищите по `Ctrl+F`. Выбор для конфликта, который вы
правили вручную, заменяет вашу правку (`Ctrl+Z` вернёт её). Если сохранять
файл, когда в конфликте ничего не выбрано или осталась строка, похожая на
маркер конфликта, сначала будет вопрос.

### ✦ Предложить решение (ИИ)

Когда ИИ включён (Настройки > ИИ; см. [Помощь ИИ](ai.md)), на панели
инструментов есть кнопка **✦ Предложить**, в контекстном меню конфликта -
*Предложить решение (ИИ)*, а `Alt+I` и палитра (`✦ ИИ: предложить решение конфликта merge`) делают то же самое. Оно работает только с текущим конфликтом и
запускается только по вашей просьбе. Ответ заменяет часть Результата для этого
конфликта одной правкой, помеченной как изменённая (`✎`), так что `Ctrl+Z`
возвращает конфликт как был. Он никогда не сохраняется и не добавляется в индекс
за вас. Пока запрос идёт, в строке подсказок показано затраченное время; `Esc`
отменяет, а ошибка тоже показывается там. При выключенном ИИ этих элементов нет.

После **Сохранить и разрешить** файл добавляется в индекс, и снова виден список
файлов с конфликтами; следующий файл откройте сами. `Ctrl+Z`
(или кнопка «Отменить») отменяет последнюю пометку «разрешён». Когда файлов не
осталось, баннер предлагает **Commit merge** (или **Продолжить** для
cherry-pick, revert и rebase) и **Прервать merge**, который сначала спрашивает
подтверждение: он возвращает HEAD, индекс и рабочее дерево в прежнее состояние.

Слияние, результат которого равен HEAD (вы везде взяли нашу сторону), не имеет
ничего в индексе и изменённых файлов, но его всё равно можно завершить:
**Commit merge** открывает ввод commit'а с сообщением слияния, и у commit'а оба
родителя. Точно так же кнопка Commit в композиторе доступна при пустом индексе,
пока слияние остановлено.

Пустой cherry-pick или revert (изменение уже применено) нельзя превратить в commit:
git отказывает, и **Продолжить** сообщает об этом и указывает на **Пропустить**.
**Пропустить** (кнопка баннера, пункт палитры *Git: пропустить cherry-pick или
revert*, CLI `conflicts skip`) сначала спрашивает подтверждение, затем
завершает операцию, ничего для неё не записывая; HEAD, индекс и рабочее дерево
возвращаются к HEAD. «Пропустить» нельзя отменить (ничего не теряется, от чего
вы не отказались намеренно); у слияния пропускать нечего.

## Конфликты, не являющиеся текстом

У двоичного файла, указателя Git LFS, файла больше 8 МиБ, файла, удалённого на
одной стороне, остатка переименования, символической ссылки, смены режима или
подмодуля нет строк для выбора. Редактор показывает **карточку** с тем, что
содержит каждая сторона, и по кнопке на каждый вариант; выбор сразу разрешает
конфликт и добавляет файл в индекс.

| Карточка | Варианты |
|---|---|
| Двоичный файл, указатель LFS, слишком большой | **Оставить A** (`a`), **Взять B** (`b`), **Взять базу** (`o`, если она есть), **Открыть во внешнем merge-инструменте** (`m`) |
| Удалён на одной стороне, изменён на другой | **Оставить файл** (`k`), **Принять удаление** (`Shift+D`) |
| Остаток переименования (путь есть только на одной стороне) | **Оставить файл** (`k`), **Удалить файл** (`Shift+D`) |
| Символическая ссылка, подмодуль, режим файла | **Оставить A**, **Взять B**, **Взять базу** |

Если файл - изображение (PNG, JPEG, GIF, WebP, BMP, ICO), в полях также видны
изображения A, B и База, вписанные и только для чтения, в окне достаточной
ширины; см. [Изображения](image-view.md#в-редакторе-слияния).

![Карточка двоичного конфликта: что содержат A, B и база, и кнопки Оставить A, Взять B, Взять базу и «Открыть во внешнем merge-инструменте»](../images/merge-editor-card.png)

`Esc` закрывает карточку без выбора. Внешний инструмент слияния задаётся
параметром `general.external_merge_tool` в **Настройки > Diff и редактор > Внешний инструмент merge** (`{base}`,
`{local}` = A, `{remote}` = B, `{merged}`; пусто означает `git mergetool`);
файл добавляется в индекс, когда инструмент завершается успешно.

## Предотвращение конфликтов

GitPoulpi может сообщить о конфликте *до* слияния. Если ветка, на которой вы
находитесь, конфликтовала бы с веткой, от которой она ответвилась (её
**базой**), в верхней граничной строке Log появляется полоса: **Конфликты с
origin/main в 2 файлах** и кнопка **Показать файлы**. Она занимает следующую
свободную граничную строку после баннеров идущих операций, поэтому, пока виден
один из них, ей может не хватать места. Ничего не сливается: демон выполняет
слияние двух commit'ов в памяти (libgit2 или `git merge-tree --write-tree` с git
2.38 и новее; при более старом git функция отключается с одной строкой в
журнале), поэтому ваши файлы, индекс и ссылки не затрагиваются.

- **База** - целевая ветка pull request'а этой ветки, если GitPoulpi уже знает
  её (кэш раздела «Pull requests»; сетевых вызовов для этого нет), иначе ветка
  из шаблонов **Базовых веток** (Настройки > Предотвращение конфликтов), от
  которой прошло меньше всего commit'ов с момента ответвления. Если таких
  несколько, выигрывает ветка, чья вершина ближе к месту ответвления, затем
  удалённая ветка перед локальной, затем имя. Сама ветка и её собственная копия
  на remote базой не бывают.
- **Окно** (щелчок по полосе или команда палитры **Конфликты: показать
  предсказанные конфликты**, работающая с клавиатуры) перечисляет файлы и
  предлагает **Открыть предпросмотр merge** и **Rebase на базовую ветку**. Это
  собственные пункты меню базовой ветки (*Merge <база> в <ветка>*, *Rebase
  <ветка> на <база>*), выполненные за вас: они попадают в журнал, поэтому `Ctrl+Z`
  их отменяет, а merge, который всё же конфликтует, останавливается в редакторе
  merge, как любой другой. Влево и Вправо переходят между кнопками, Enter нажимает
  кнопку, Esc закрывает.
- **Когда это работает**: в фоне, примерно через 2 секунды после того, как
  репозиторий затих (commit, checkout, fetch, сдвинувший ветку, rebase), один раз
  для каждой пары `(HEAD, база)`. Полоса скрывается, как только HEAD сдвигается, и
  возвращается или нет - в зависимости от нового ответа. Отсоединённый HEAD не
  проверяется.
- **Списки базовых веток**: откуда репозиторий берёт базовые ветки, выбирается на его странице **Предотвращение конфликтов**. **По умолчанию** следует глобальному значению (встроенный `**`, то есть все ветки, пока вы не выберете другой список в Настройки > Предотвращение конфликтов); **Список: <имя>** следует одному из ваших именованных списков; **Собственный список** принадлежит только этому репозиторию. Списки общие: правка списка действует на каждый репозиторий, который ему следует, при следующей проверке, без перезапуска. **Сохранить как список...** превращает собственные шаблоны репозитория в именованный список, **Вернуть по умолчанию** отбрасывает выбор репозитория. Удаление списка, которому следует репозиторий, заставляет его использовать список по умолчанию.
- **Выключение**: **Включить проактивное обнаружение конфликтов** в Настройки >
  Предотвращение конфликтов, а для одного репозитория - на его странице **Предотвращение
  конфликтов**. Из скрипта `gitpoulpi conflicts check` выводит тот же ответ в
  JSON ([справочник по CLI](cli-reference.md)).

## Агенты

Агент может показать вам конфликт (`gitpoulpi ui show conflict <path> [--conflict
N]`: редактор открывается на нём, ничего не выбрано) или **предложить** решение
(`gitpoulpi ui propose resolution <path> --pick 1=a,2=ba` или `--content-file F`;
нужен параметр **Разрешить ИИ-агентам предлагать изменения для моего подтверждения**).
Предложение открывает редактор с уже внесёнными в Результат выборами (или всем
текстом) и фиолетовым баннером *✦ Предложено: claude-code*. Просмотрите его,
измените что хотите и нажмите **Ctrl+S**: только это что-то записывает или
добавляет в индекс. Закрытие редактора отклоняет предложение. См. [MCP и агенты](mcp-and-agents.md).

Из скрипта те же операции доступны как `gitpoulpi conflicts list | show | resolve |
unresolve | state | abort` ([Справочник по CLI](cli-reference.md)); `conflicts check` предсказывает их до слияния.
