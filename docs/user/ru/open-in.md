# Открыть в

Кнопка **Открыть в ▾** в строке заголовка, рядом с путём репозитория, открывает
папку активной вкладки в другом месте: в вашем терминале, новой вкладке или
панели мультиплексора, редакторе, файловом менеджере. Список выбираете вы.
Ничего не зашито жёстко: каждая запись - это название и команда.

## Как пользоваться

- **Щёлкните «Открыть в ▾»**: раскроется список. Щёлкните запись, чтобы
  запустить её. Запись по умолчанию отмечена `•`; последняя строка,
  **Настроить...**, открывает [Настройки](settings.md#открыть-в) на странице «Открыть в».

  ![Список «Открыть в»: Terminal, два редактора, инструмент Git и файловый менеджер, запись по умолчанию отмечена точкой, в конце «Настроить»](../images/open-in-menu.png)

- **Клавиатура**: `Alt+O` открывает тот же список (`Up`/`Down`, `Enter`, `Esc`;
  если записей больше семи, вводите текст для поиска). `Ctrl+Alt+O` сразу
  запускает запись по умолчанию. Палитра (`Ctrl+P`): `Вкладка: открыть в...` и
  `Вкладка: открыть в записи по умолчанию`. Команды палитры работают, даже если
  в строке заголовка нет места для кнопки. Обе клавиши можно переназначить; см.
  [Сочетания клавиш](keybindings.md).
- **По названию**: шаг [последовательности](config-reference.md#sequences) `tab_open_in` запускает запись,
  чьё **название** вы указали (`label = "VS Code"`), поэтому перестановка списка никогда не меняет то, что
  запускается. Неизвестное название останавливает шаг сообщением «нет записи «Открыть в» с названием ...».
  `Вкладка: терминал здесь` (палитра) открывает ваш терминал в папке, это прежняя кнопка «Терминал здесь»
  панели вкладок.
- **ИИ-агент в папке**: `Вкладка: открыть ИИ-агента здесь` открывает ваш терминал в папке вкладки и
  запускает в нём локального ИИ-агента; см. [ИИ](ai.md#открыть-агента-в-папке-вкладки).
- **Правый щелчок по вкладке репозитория**: в меню вкладки есть подменю
  **Открыть в** с теми же записями.
- Список начинается с записи, которой вы пользовались последней в этом сеансе.
- Строка состояния сразу пишет «открытие в ...». Если программа завершается
  с ошибкой примерно за 1,5 секунды (например, tmux без сервера или неверный
  флаг), в строке состояния появляется первая строка её вывода ошибок.
  Неустановленная программа называется сразу.

Пока вы не сохранили собственный список, запись по умолчанию выбирается по
тому, что обнаружено: внутри herdr - «Herdr: new tab»; в Omarchy - новое окно
kitty (kitty - его терминал); иначе - файловый менеджер.

Кнопка показывается на каждой вкладке репозитория, включая папку, в которой
запущен GitPoulpi, и в режиме `ui.tab_dir_follow = "auto"`. В режиме `auto`
запись по умолчанию также запускается сама при открытии новой вкладки (не для
вкладок, восстановленных при запуске). См. [Следование папке активной
вкладки](following-the-tab-folder.md).

## Как выглядит запись

В `config.toml` - одна таблица `[[ui.open_in]]` на запись:

```toml
[ui]
open_in_default = "Herdr: new tab"   # название; пусто означает первую запись

[[ui.open_in]]
label = "Herdr: new tab"
command = "herdr tab create --workspace ${env:HERDR_WORKSPACE_ID} --cwd ${cwd} --focus"

[[ui.open_in]]
label = "VS Code"
command = "code ${cwd}"
```

Вручную это пишут редко: список правит страница настроек. Все ключи описаны в
[справочнике по конфигурации](config-reference.md).

### Команды и переменные

Сначала команда делится на аргументы (пробелы, `'...'` и `"..."` объединяют
слова), затем внутри каждого аргумента подставляются переменные. Поэтому папка с
пробелом в имени остаётся одним аргументом. **Оболочка не используется**, если
её не запускает ваша команда.

| Переменная | Заменяется на |
|---|---|
| `${cwd}` | Папка вкладки. |
| `${repo}` | Корень репозитория (для вкладки worktree отличается от `${cwd}`). |
| `${name}` | Базовое имя папки. |
| `${branch}` | Текущая ветка; пусто при отсоединённом HEAD. |
| `${web_url}` | Веб-страница remote origin, если это GitHub или GitLab; иначе пусто. |
| `${env:NAME}` | Переменная окружения `NAME`; пусто, если не задана. |

Старая запись `{repo}` по-прежнему работает и означает `${cwd}`. Любая другая
`${...}` - ошибка с названием переменной.

Программа запускается с папкой вкладки как рабочей и получает три переменные
окружения, удобные для фрагмента shell:

| Переменная | Значение |
|---|---|
| `GITPOULPI_CWD` | Папка вкладки. |
| `GITPOULPI_REPO` | Корень репозитория. |
| `GITPOULPI_BRANCH` | Ветка или пусто. |

```toml
[[ui.open_in]]
label = "Terminal here, then status"
command = "sh -c 'cd \"$GITPOULPI_CWD\" && git status; exec $SHELL'"
```

В Windows программа ищется через `PATH` и `PATHEXT`, поэтому `code` и `cursor`
(файлы `.cmd`) работают, а окно консоли не мелькает.

## Шаблоны

**Настройки > Открыть в > Добавить шаблон** перечисляет готовые записи только
для вашей операционной системы (шаблоны Windows никогда не показываются в
Linux и так далее) по категориям: строка начинается с категории, `Проводник: ...`,
`Мультиплексор: ...`, `Терминал: ...`, `Редактор: ...`, `Инструмент Git: ...`,
`ИИ-агент: ...`, `Веб: ...`. Вверху **Найдено** - записи вычисленного списка по
умолчанию. Внутри каждой категории первыми идут шаблоны, которыми можно
пользоваться сразу (вы работаете внутри этого мультиплексора или терминала, а
программа есть в `PATH`), затем установленные, затем остальные. Введите текст в
поле выбора для поиска, например `lazygit` или `Инструмент Git:`. **Проверить
на текущей вкладке** пробует запись, прежде чем вы будете на неё полагаться.

![Список «+ Добавить» на странице «Открыть в»: сначала найденные записи, затем Проводник, Мультиплексор и другие категории, у каждого шаблона префикс категории](../images/settings-open-in-presets.png)

Шаблоны «запустить инструмент в панели» (`lazygit in Herdr tab`,
`yazi in tmux window`, `Claude Code in Herdr split`...) предлагаются, только
если установлены и хост (herdr, tmux, zellij, WezTerm, kitty,
`xdg-terminal-exec`, Windows Terminal), и сам инструмент. `$EDITOR in ...`
запускает редактор, указанный в вашей переменной `EDITOR` (в herdr при её
отсутствии - `vi`), в herdr или tmux.

Шаблоны инструментов herdr создают вкладку или разделение, затем вводят
команду в её оболочке, поэтому инструмент запускается в папке, а панель остаётся
открытой после его завершения. Шаблоны категории «ИИ-агент» используют
`herdr agent start`, поэтому herdr отслеживает состояние агента.

| Категория | Шаблоны (`V` = проверено запуском или по справке установленной программы) |
|---|---|
| Проводник | Windows `explorer.exe` (V), macOS Finder (V), Linux `xdg-open` (V), Nautilus, Dolphin, Thunar, Nemo, PCManFM; yazi, superfile, nnn, lf, ranger в панели/вкладке/терминале |
| Мультиплексор | herdr tab, workspace, split right/down (V); tmux window, split right/down, detached session (V); zellij pane, tab, floating; WezTerm tab, split, new window; kitty tab, split window, OS window (V: флаги из справки; нужен `allow_remote_control`); screen; cmux; psmux |
| Терминал | `xdg-terminal-exec` (V), kitty (V), foot (V), Alacritty (+ `alacritty msg`), WezTerm, Ghostty (Linux, macOS), GNOME Terminal, Ptyxis, Konsole, Xfce Terminal, Tilix, Terminator, MATE Terminal, iTerm2, Terminal.app, Warp; Windows: Windows Terminal (окно, вкладка, разделение и по вкладке для PowerShell 7, Windows PowerShell, Command Prompt, WSL), окна PowerShell 7 / Windows PowerShell / Command Prompt / WSL, Git Bash |
| Редактор | VS Code (V), VSCodium, Cursor, Windsurf, Zed, Sublime Text, Emacs, IntelliJ IDEA, RustRover, PyCharm, WebStorm, CLion, GoLand, Rider, PhpStorm, Android Studio, Visual Studio (Windows); Neovim, Vim, Helix, `$EDITOR` в панели/вкладке/терминале |
| Инструмент Git | gitk, `git gui`, gitg, Sublime Merge, GitKraken, GitHub Desktop; lazygit, tig, gitui в панели/вкладке/терминале (у herdr, tmux, kitty и `xdg-terminal-exec` - V) |
| ИИ-агент | Claude Code, Codex, Gemini CLI, opencode во вкладке/разделении herdr (V, с Claude), tmux, zellij, WezTerm, kitty, новый терминал |
| Веб | `Repository page on the web` (`${web_url}`), `gh repo view --web` (V), `glab repo view --web` |

WSL в Windows: `wsl.exe --cd ${cwd}` принимает путь Windows как есть, а
вкладка `wsl.exe` в Windows Terminal стартует в папке, которую WSL отображает
под `/mnt/`.

Проводник, Windows Terminal, PowerShell, `cmd`, WSL, Warp, psmux, Visual Studio
и Zed (Zed только для Unix) появляются только там, где существуют; tmux,
zellij, cmux, screen, удалённое управление kitty и шаблоны herdr на основе `sh`
только для Unix; herdr (простые шаблоны), WezTerm, Alacritty, VS Code, Cursor и
IDE JetBrains предлагаются везде.

### Переменная `${web_url}`

Веб-страница remote `origin` репозитория, если это проект GitHub или GitLab
(github.com, gitlab.com или self-managed хост, у которого есть запись в
`[[integrations]]`); иначе пусто, и тогда запись, которая её использует,
останавливается с сообщением вместо открытия пустого адреса. Она необязательна:
ни одному шаблону она не нужна, кроме `Repository page on the web`.

## Страница настроек

**Настройки > Открыть в** редактирует список. Записи - это [список](settings.md#списки)
слева (запись по умолчанию отмечена `★`), поля выбранной записи - справа; список
меняют кнопки `+ Добавить`, `Дублировать`, `Удалить`, `↑` / `↓` и перетаскивание строки.

| Строка | Что делает |
|---|---|
| **Запись по умолчанию** | Запись, которую запускает «Открыть в записи по умолчанию». Отмечена `•` в списке «Открыть в». |
| **Название** | Имя, показываемое в списке. Уникальное, не пустое. |
| **Команда** | Команда с кнопками переменных (`${cwd}`, `${repo}`, `${branch}`, `${name}`, `${web_url}`) для вставки. |
| **Проверить на текущей вкладке** | Сейчас запускает запись для папки активной вкладки. |
| **+ Добавить ▾** | Добавляет готовую запись (найденные первыми) или **Свою** - пустую запись, команду которой нужно ввести следом. |
| **Восстановить найденные значения** | Заменяет список тем, что найдено на этом компьютере, и сбрасывает запись по умолчанию. |

Правки сохраняются по мере внесения. Первая правка записывает весь массив
`[[ui.open_in]]` в `config.toml`; до этого список вычисляется (см. [Старые
ключи](#старые-ключи)), а в файле нет ключа `open_in`. Поиск по настройкам
находит и эту страницу.

## Двоичные файлы: Открыть в

У двоичного файла (PDF, документа Word, таблицы, архива...) нет текста, который можно показать в виде Diff или в просмотре файла. Если операционная система знает приложение для его типа, рядом с обычным уведомлением появляется кнопка **Открыть в**. В её списке первым идёт приложение, которым система открывает этот тип (оно отмечено точкой), затем все остальные приложения, зарегистрированные в системе для него (собственный список системы «Открыть с помощью»). В Linux это MIME-тип по имени файла, `mimeapps.list` для приложения по умолчанию и файлы `.desktop` для остальных; в Windows реестр (выбор пользователя и программы, зарегистрированные для расширения); в macOS только приложение по умолчанию.

`o` запускает приложение по умолчанию, а `Shift+O` открывает список. Оба действия есть в палитре команд (*Файл: открыть в приложении по умолчанию*, *Файл: открыть с помощью...*), а **Открыть с помощью...** есть в контекстном меню файла в панели Status и в списке файлов commit'а. Поиск идёт в фоне, один раз для каждого расширения: пока он идёт, вид показывает «поиск приложений...». Тип, для которого система не знает ни одного приложения, и простой текст сохраняют обычное уведомление и не получают кнопки.

![PDF в просмотре файла со списком «Открыть в»: сначала приложение по умолчанию, отмеченное точкой, затем остальные приложения, которые система связывает с этим типом](../images/open-with.png)

Файл рабочего дерева передаётся приложению как есть. Версия из commit'а (или из индекса) записывается во **временную копию только для чтения**, с уведомлением в строке состояния, чтобы приложение не могло изменить репозиторий. Ни то, ни другое не меняет репозиторий: записи в журнале нет, отмена не затрагивается.

Список меню открывается рядом с меню, на уровне строки **Открыть с помощью...**, как подменю (слева, если справа нет места), и мышью, и с клавиатуры. Список редакторов изображений (**Править в...**), открытый из меню файла, ведёт себя так же.

### Файлы Git LFS

Карточка объекта Git LFS (см. [Git LFS](lfs.md)) несёт под текстом те же два действия: **Открыть в программе по умолчанию** и **Открыть в**, с теми же клавишами (`o`, `Shift+O`) и строками палитры. Они открывают настоящий файл, а не указатель: файл рабочего дерева как есть или временную копию объекта из локального хранилища LFS только для чтения для версии из commit'а или индекса. У ещё не загруженного объекта на карточке нет кнопок, а строка состояния сообщает, что содержимое ещё не загружено. Тот же отказ действует для файла рабочего дерева, в котором пока лежит только указатель: **Открыть в программе по умолчанию**, **Открыть в** и **Править в** из карточки или любого меню файла сообщают, что содержимое не загружено, вместо открытия текста указателя (загрузите его строками pull или checkout на панели LFS и повторите). Открытие только читает: записи в журнале нет, отменять нечего.

### Браузеры в Windows

Chrome и Edge регистрируют `--single-argument %1`, из-за чего всё после ключа читается как один адрес, вместе с кавычками. GitPoulpi передаёт путь такой программе как есть и без кавычек, как это делает Windows, поэтому файл с пробелами в пути открывается, а не падает с `http://"c/...`. Любая другая программа получает путь как один обычный аргумент.

## Старые ключи

Старые ключи `ui.terminal_launch` и `ui.terminal_launch_command` читаются, только
пока `ui.open_in` отсутствует. Тогда вычисляемый список такой:

1. ваш прежний выбор терминала, если это не `auto` (`custom` становится
   «Terminal (custom)» с `{repo}`, переписанным в `${cwd}`; id шаблона
   становится этим шаблоном). Значение `auto` становится первой записью,
   «Default terminal».
2. файловый проводник ОС,
3. мультиплексоры и терминалы, обнаруженные в окружении,
4. редакторы, найденные в `PATH`.

Когда вы сохраняете список в настройках, `ui.open_in` берёт управление на себя,
а старые ключи игнорируются. Команды палитры **Вкладка: открыть в терминале** и
**Вкладка: открыть в файловом менеджере** этот список не используют.

## Устранение неполадок

- *«program X was not found»*: программы нет в `PATH`, который видит GitPoulpi.
  Запустите GitPoulpi из оболочки, где она есть, или укажите полный путь.
- *Запись tmux/zellij/herdr сразу завершается ошибкой*: они обращаются к
  работающему серверу, поэтому работают, только когда GitPoulpi запущен внутри
  него.
- *Запись вкладки kitty завершается ошибкой*: ей нужен `allow_remote_control` в
  `kitty.conf`.
- *Проводник Windows*: `explorer.exe` завершается с кодом 1 даже при успехе;
  GitPoulpi считает это успехом.
