# Поиск

`Ctrl+Alt+F` (или `Ctrl+P`, затем `Поиск: рабочее пространство...`) открывает
нечёткий поиск по **всем репозиториям, в которых вы работаете**: по
репозиториям активного [рабочего пространства](workspaces.md), если оно есть,
иначе по открытым вкладкам. Его открывает и кнопка **Глобальный поиск** (лупа с подписью в строке
заголовка, сразу левее шестерёнки). Он находит:

- **репозитории** (по имени, затем по пути),
- **ветки** (локальные и удалённые) и **tag'и**,
- **worktree** (по папке, затем по пути и ветке),
- **stash'и** (по сообщению),
- **commit'ы** (по заголовку; тело commit'а ищется, только если не совпал его
  заголовок, а вы набрали три символа или больше),
- **pull или merge request** и **задачи** (по заголовку, `#номеру`, автору и
  ветке).

![Окно поиска над двумя открытыми репозиториями: ветки, stash и commit, совпавшие с «main», у каждого справа его репозиторий](../images/workspace-search.png)

Результаты сгруппированы по типам, внутри группы лучшее совпадение первым. У
каждой строки есть значок типа, подсвеченные совпавшие символы, тусклая деталь
(upstream ветки, автор и ветка запроса, позиция stash'а) и справа имя
репозитория, так что две ветки `main` в разных репозиториях никогда не
перепутаются. Когда репозиторий ещё индексирует свои commit'ы (первый поиск в
большом репозитории может занять время), в заголовке виден индикатор
загрузки; остальные типы есть сразу, а commit'ы присоединяются, как только
готовы.

## Переход к результату

| Клавиша | Что делает |
|---|---|
| `Up` / `Down`, `PageUp` / `PageDown`, `Home` / `End` | Перемещение по результатам (заголовки групп пропускаются). |
| `Enter` | Переходит к результату: открывается (или активируется) вкладка репозитория, затем показывается результат. |
| `Esc` | Закрывает поиск. |
| `Alt+1` .. `Alt+8` | Включает или выключает тип (значки над списком, в их порядке). `Alt+0` включает все. |

Что значит «перейти»:

| Результат | Enter |
|---|---|
| Ветка или tag | Выбирает его в панели Refs, а его commit - в Log. |
| Commit | Выбирает его в Log, сначала подгрузив Log дальше, если commit старше уже загруженного. |
| Stash | Выбирает его строку в разделе СТЭШИ. |
| Worktree | Открывает его во вкладке. |
| Pull/merge request, задача | Выбирает её строку в боковой панели (во вкладке этого репозитория). |
| Репозиторий | Переключается на его вкладку (открывая её, если она не открыта). |

`Ctrl+N Backspace` (или `Назад` в палитре) возвращает туда, где вы были, как
после любой смены вида, которую делает за вас агент. Переход никогда ничего не
переключает, не сливает и не меняет.

Мышью: щелчок по строке выбирает её, двойной щелчок переходит к ней, щелчок по
значку включает или выключает этот тип, колесо прокручивает, а щелчок снаружи
закрывает окно.

## Сужение префиксом

Начните запрос с префикса, чтобы искать только один тип, что бы ни говорили
значки:

| Префикс | Тип |
|---|---|
| `r:` | репозитории |
| `b:` | ветки |
| `t:` | tag'и |
| `w:` | worktree |
| `s:` | stash'и |
| `c:` | commit'ы |
| `pr:` (или `mr:`, `p:`) | pull или merge request |
| `i:` | задачи |
| `#` | pull/merge request и задачи (`#12` находит номер 12) |

`fix: login` - обычный запрос, а не префикс: считается только одна буква (или
`pr:` / `mr:`) с двоеточием либо `#` в начале.

## Как идёт сопоставление

Те же три уровня, что в палитре команд: ваш текст дословно, затем дословно где
угодно, затем его символы по порядку, но вразброс. Выигрывают более раннее
совпадение и более короткий текст. Регистр не важен.

## Pull request и задачи

Они берутся из того, что GitPoulpi уже загрузил для каждого репозитория
(списки разделов PULL REQUESTS и ЗАДАЧИ боковой панели), и хранятся в небольшом
файле кеша в папке `.gitpoulpi/` репозитория. Поиск **никогда не обращается к
GitHub или GitLab**: у репозитория, запросы которого ни разу не загружали в
окне, искать нечего, а то, что вы видите, так же свежо, как последнее
обновление боковой панели. Без привязанной учётной записи искать нечего и
ничего не нужно настраивать.

## Из командной строки

`gitpoulpi search <query> [--workspace ID] [--kind K]... [--limit N]` делает то
же самое и выводит JSON (см. [справочник по
CLI](cli-reference.md#рабочие-пространства-и-поиск)); у сервера MCP есть
инструмент `search`, так что агент находит то же, что и вы.
`search.commit_limit` в [настройках](config-reference.md#search-поиск-по-рабочему-пространству)
ограничивает, сколько commit'ов каждого репозитория индексируется (`0`
выключает поиск по commit'ам).

## Смена клавиши

`Поиск: рабочее пространство...` - команда палитры, а клавиша - действие
`global.workspace_search`: переназначьте её в Настройки > Клавиатура и мышь или в
таблице `[keybindings.global]` (`workspace_search = "Ctrl+Alt+F"`).
