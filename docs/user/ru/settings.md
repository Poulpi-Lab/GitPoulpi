# Настройки

Откройте Настройки с помощью `Ctrl+,`, `Ctrl+N`, затем `,`, значка шестерёнки в
строке заголовка (левее `×`) или `Ctrl+P` > *Настройки*. Экран настроек заменяет
окно, пока он открыт. Закрыть его можно значком `✕` справа вверху, `Esc` или
`q`. Он спрашивает подтверждение, только когда закрытие что-то потеряет (см.
[Закрытие настроек](#закрытие-настроек)).

Изменения сразу сохраняются в `config.toml`. [Справочник по конфигурации](config-reference.md)
описывает каждый ключ, его значение по умолчанию и переменную окружения. Эта
страница описывает экран настроек.

![Экран настроек: поле поиска и список разделов слева, раздел «Общие» справа](../images/settings.png)

## Работа с экраном настроек

| Чтобы | Сделайте |
|---|---|
| Перейти между списком страниц и настройками | `Tab` / `Shift+Tab` или щёлкните. |
| Перемещаться | `j` / `k` или стрелки. |
| Изменить настройку | `Enter` или `Space`, либо щелчок по её значению. См. ниже. |
| Закрыть | Щёлкните `✕` или нажмите `Esc` или `q`. Пока открыто поле, выпадающий список или подтверждение, `Esc` закрывает только их. |

Что делают `Enter` и `Space`, зависит от строки:

- Флажок переключается.
- Выпадающий список открывается. Стрелки выбирают, `Enter` принимает.
- Текстовое или числовое поле начинает правку. Работают стрелки, `Home`, `End`,
  `Backspace` и `Delete`, а щелчок ставит курсор. `Enter`, `Tab`, `Up`, `Down`
  или щелчок в другом месте сохраняет значение. `Esc` отменяет. Отклонённое
  значение остаётся в поле красным цветом, а строка состояния называет причину.
- Строка кнопок (**Создать**, **Удалить**, **Проверить**...) показывает только те кнопки,
  которые применимы сейчас. `Left` / `Right` выбирают кнопку, `Enter` нажимает её, либо
  щёлкните по ней. Кнопка, которая что-то удаляет, сначала спрашивает.

На каждой странице значения начинаются в одной колонке: подписи выровнены слева, поля -
справа. Текст или число показаны тонированной полосой, выбор - полосой с `▾` в конце,
флажок - `[x]`. Длинная подпись переносится, а не обрезается, а в узком окне значение
уходит под свою подпись.

Серая строка объясняет, почему она неактивна. Например, **Насыщенность подсветки
строки** серая, пока **Фон полос графа** - **Выкл.**

### Списки

Страницы, где правится несколько однотипных элементов (Профили, ИИ, Рабочий процесс,
Открыть в, Изображения), показывают их **списком слева, а поля выбранного элемента -
справа**. В узком окне список стоит над полями. Везде список устроен одинаково:

- Метка строки говорит о её состоянии: `●` активный профиль, `★` запись по умолчанию, `⚠`
  незавершённый элемент (профиль без email), причина показана там, где были бы сведения.
- Под списком: **+ Добавить**, **Дублировать**, **Удалить**, `↑` и `↓`. Кнопка, которая сейчас
  неприменима (`↑` на первой строке), приглушена. **+ Добавить ▾** открывает выпадающий
  список, если страница предлагает шаблоны или виды элементов.
- **Удалить** сначала спрашивает, кроме элемента, который вы только что добавили и не правили.
- Перетащите строку, чтобы переместить её; полоса показывает, куда она встанет, а `Esc`
  отменяет перетаскивание. Двойной щелчок переходит к полям элемента.

| Клавиша | Действие |
|---|---|
| `Up` / `Down`, `Home` / `End`, `PageUp` / `PageDown` | Выбрать элемент. |
| `Insert` | Добавить элемент (открывает выпадающий список, если он есть). |
| `Ctrl+D` | Дублировать элемент. |
| `Delete` | Удалить элемент после подтверждения. |
| `Alt+Up` / `Alt+Down` | Переместить элемент вверх или вниз. |
| `Enter` или `Right` | Перейти к полям элемента. |
| `Left` | Назад к списку страниц. |
| `Alt+Left` / `Alt+Right` | Переключает вкладки «Общие» и списка (в любом месте страницы). |

У каждой из этих страниц под заголовком есть две **вложенные вкладки**, чтобы настройку самой страницы никогда не путали со свойством выбранного элемента: **Общие** - собственные настройки страницы (активный профиль, запись по умолчанию, инструкции, которые получает каждое действие ИИ, шаблон рабочего процесса...) и вкладка, названная по элементам (**Профили**, **Профили (подключения)**, **Записи**, **Редакторы**, **Правила**), где находятся список и поля выбранного элемента. Страница открывается на вкладке **Общие**; настройки запоминают вкладку, на которой вы оставили каждую страницу, а также позицию прокрутки и выбранную строку каждой страницы (и вкладки), до выхода из приложения. Щёлкните вкладку или нажмите `Alt+Left` / `Alt+Right`. Поиск, строки настроек в палитре команд и ссылки «задайте в настройках» открывают вкладку, на которой находится настройка.

У раздела [Клавиатура и мышь](#клавиатура-и-мышь) те же две вкладки (**Общие**, **Сочетания клавиш**).

Клавиши можно переназначить в разделе **Клавиатура и мышь** (контекст *preferences*, см.
[Сочетания клавиш](keybindings.md)).

### Многострочные редакторы

Настройки из нескольких строк (например, пути частичного checkout, описание шаблона commit, базовые ветки предотвращения конфликтов и хуки рабочего процесса) открываются в небольшом редакторе по `Enter` или щелчку; `Ctrl+S` сохраняет текст, `Esc` отбрасывает. Мышь работает там как в любом текстовом поле:

- Щелчок ставит курсор в место щелчка.
- Перетаскивание выделяет текст; колесо прокручивает.
- Двойной щелчок выделяет слово под указателем.
- `Shift` + щелчок расширяет выделение от курсора до указателя.

То же доступно с клавиатуры: `Shift` со стрелками выделяет, `Ctrl` со стрелками переходит по словам, `Ctrl+A` выделяет всё, `Ctrl+C` и `Ctrl+X` копируют и вырезают.

### Закрытие настроек

`✕`, `Esc` и `q` делают одно и то же. Настройки применяют каждое изменение сразу, поэтому
чаще всего они просто закрываются. Вопрос **Закрыть настройки?** появляется, только если
что-то будет потеряно:

- на странице **Рабочий процесс** есть несохранённые изменения;
- в шаблоне сообщения commit'а есть несохранённые изменения;
- у профиля не указан email автора (созданные им commit'ы нельзя будет связать с вами).

В окне предлагаются **Перейти** (открывает эту страницу), **Отбросить и закрыть** или
**Всё равно закрыть**, а также **Отмена**. У небольших редакторов внутри Настроек (текст
инструкций ИИ, хук рабочего процесса, пути частичного checkout) свой `✕`, и они спрашивают
**Отбросить изменения?**, только если их текст был изменён.

### Всплывающие окна поверх настроек

В строке заголовка показаны осьминог и название приложения, как в главном окне.
Щелчок по осьминогу открывает «О программе».

Несколько общих для всего окна всплывающих окон открываются поверх настроек и
возвращают их в прежнем виде (страница, положение прокрутки и несохранённые изменения
рабочего процесса или шаблонов остаются):

- палитра команд (`Ctrl+P`),
- выбор темы (`Ctrl+N y`, **Приложение: сменить тему...**), который показывает каждую
  тему прямо на экране настроек; `Esc` возвращает прежнюю тему,
- выбор языка и цветов графа (`Ctrl+N`, затем те же буквы, что в главном окне),
- поиск по рабочему пространству (`Ctrl+Alt+F`),
- «О программе» (`Ctrl+N a`, осьминог или **Справка: о GitPoulpi**) и окно справки (`?`).

Каждое закрывается клавишей `Esc`, собственным `✕` или щелчком вне него. Команды,
которые действуют на то, что настройки закрывают (вкладка, ветка, diff...), есть в
палитре, но серые, с пометкой «сначала закройте настройки», а сочетания `Ctrl+N` для
них показывают эту строку на нижней границе настроек: закройте настройки и запустите
их.

`Ctrl+N` показывает значок на каждом элементе страницы: поле поиска, список страниц (один значок, на текущей странице), подвкладки, список и его кнопки, каждое поле на экране и крестик закрытия. Нажмите символ значка, и произойдёт то же, что при щелчке по этому элементу: текстовое поле открывается для редактирования, флажок переключается, выпадающий список раскрывается, кнопка выполняется. `Esc` отменяет. У поля, прокрученного за пределы экрана, значка нет. Пока вы вводите текст в поле или открыт выпадающий список, редактор или поиск, `Ctrl+N` принадлежит им. См. [Значки](keybindings.md#значки).

### Поле поиска

Поле над списком страниц ищет по названию и описанию каждой настройки на
каждой странице. Щёлкните по нему или нажмите `/` или `Ctrl+F` и вводите текст.
Раскрывается список совпадений. Каждое совпадение показывает настройку и её
страницу. `Up` / `Down` выбирают, `Enter` переходит к настройке, `Esc` закрывает
список.

![Поиск по настройкам «diff»: подходящие настройки со страниц «Журнал и граф», «Diff и редактор» и «Git и кодировка»](../images/settings-search.png)

## Настройки из палитры команд

Большинство настроек можно изменить, не открывая этот экран: введите `Настройки:` или `Settings:` в палитре команд (`Ctrl+P`). Строки создаются из полей самих страниц, поэтому новая настройка появляется в обоих местах.

- Флажок называется **Настройки: переключить ...**. Он переключается сразу, а строка показывает `[x]` или `[ ]`.
- Выпадающий список называется **Настройки: ...**. `Enter` сужает палитру до его значений, текущее помечено как `текущее`; `Enter` на значении выбирает его.
- Число или текст открывает строку ввода с текущим значением. Значение, которое отвергла бы страница (не число, вне диапазона), отвергается так же, и строка остаётся открытой.
- Настройка, которой нужна своя страница (список, комбобокс с вариантами, определяемыми при запуске), открывает Настройки на ней.

![Палитра команд, отфильтрованная по Settings: по одной строке на настройку и её текущее значение справа](../images/palette-settings.png)

Значение сохраняется в `config.toml` и применяется точно так же, как на странице. Английские слова ключа настройки (`remember tabs`) находят строку на любом языке.

## Разделы

В списке страниц две группы:

- **Настройки**: глобальные настройки.
- **Настройки репозитория**: настройки репозитория активной вкладки. Они
  показываются, только пока открыт репозиторий.

### Общие

![Выпадающий список «Язык» на странице «Общие»: «Авто» и семнадцать языков, с полем поиска](../images/settings-language.png)

| Настройка | Что делает |
|---|---|
| **Язык** | Язык интерфейса: **Авто** (язык вашей системы, иначе английский), English, Français, Español, Português (Brasil), Português (Portugal), Italiano, Deutsch, 简体中文, 日本語, 한국어, Русский, Українська, Polski, Čeština, Nederlands, Svenska, Türkçe. Применяется сразу, без перезапуска. Названия месяцев и даты в Log следуют ему. Переменная окружения `GITPOULPI_LANG` (например, `GITPOULPI_LANG=fr`) переопределяет этот выбор. Вывод CLI и MCP остаётся английским. |
| **Переводить термины git** | По умолчанию выкл.: commit, push, pull, stash, tag и другие термины git остаются английскими на любом языке. Вкл.: используется собственный git-словарь языка (русский: *коммит*, *отправить*, *подтянуть*, *стэш*, *тег*). Применяется сразу. |
| **Git-слова по-английски** | Только для японского, корейского и китайского: показывает *stage*, *unstage*, *staged* английскими словами вместо транскрипции. Не действует, пока включено **Переводить термины git**. |
| **Запоминать вкладки** | При запуске снова открывает вкладки прошлого сеанса. Если выключено, запуск внутри репозитория открывает только этот репозиторий, а запуск вне репозитория начинается с «Главной» без вкладок репозиториев. Нужен перезапуск. |
| **Включить Radar** | По умолчанию включено (`general.radar_enabled`). Выключено - вкладка Radar, его команды палитры и `Alt+R` скрыты, и для него ничего не загружается в фоне. Применяется сразу. См. [Radar](radar.md#закрыть-вкладку-или-выключить-radar). В сборке без Radar не показывается. |
| **Вкладка при запуске внутри репозитория** | Вкладка, на которой открывается запуск, если папка, из которой он выполнен, находится внутри репозитория (`general.startup_tab_in_repo`): **Текущий репозиторий** (по умолчанию, вкладка этого репозитория, при необходимости открытая), **Последняя вкладка** (вкладка, активная при последнем выходе), **Главная**, **Radar**. Репозиторий, заданный через `--repo`, всегда открывает собственную вкладку. **Последняя вкладка** открывает «Главная», если выключено **Запоминать вкладки** или ничего не запомнено; **Radar** открывает «Главная», если Radar выключен или отсутствует в сборке. Читается один раз при запуске; нужен перезапуск. |
| **Вкладка при запуске вне репозитория** | Вкладка, на которой открывается запуск, если папка, из которой он выполнен, не является репозиторием (например, папка пользователя) (`general.startup_tab_outside_repo`): **Главная** (по умолчанию), **Последняя вкладка**, **Radar**. **Последняя вкладка** открывает «Главная», если выключено **Запоминать вкладки** или ничего не запомнено; **Radar** открывает «Главная», если Radar выключен или отсутствует в сборке. Читается один раз при запуске; нужен перезапуск. |
| **Вкладка при запуске из лаунчера** | Вкладка, на которой открывается запуск, если GitPoulpi запущен созданным им ярлыком на рабочем столе или в меню «Пуск» (он передаёт `--launcher`), независимо от папки (`general.startup_tab_launcher`): **Последняя вкладка** (по умолчанию), **Главная**, **Radar**. Приоритетнее двух настроек выше. **Последняя вкладка** открывает «Главная», если выключено **Запоминать вкладки** или ничего не запомнено; **Radar** открывает «Главная», если Radar выключен или отсутствует в сборке. Ярлыки, созданные старой версией, получают этот параметр при следующем запуске. Читается один раз при запуске; нужен перезапуск. В Windows копия, закреплённая на панели задач, тоже переписывается при следующем запуске, а запуск без оболочки вокруг (двойной щелчок, сам закреплённый exe) считается запуском из лаунчера. |
| **Группировать вкладки рабочих деревьев** | По умолчанию включено (`general.group_worktree_tabs`). Вкладки связанных worktree репозитория стоят сразу за вкладкой репозитория, а оттащенная вкладка worktree возвращается на это место. Выключено - вкладки остаются там, где вы их положили. Включение заново группирует открытые вкладки. |
| **Папка клонирования по умолчанию** | С чего начинается диалог клонирования. Пусто: `%USERPROFILE%\source\repos` в Windows, `~/src` в остальных системах. |
| **Диалог клонирования открывается на** | Источник, на котором открывается диалог клонирования (`repos.clone_start_source`): **Последний использованный** (по умолчанию: источник, показанный при последнем закрытии, после клонирования или отмены), **Клонировать по URL** или одна из подключённых интеграций. Если источник больше недоступен, открывается «Клонировать по URL». Клонирование, начатое из Radar, сохраняет свой источник. |
| **Папка обзора по умолчанию** | Где открывается «Обзор». Пусто: последняя использованная папка, иначе ваша домашняя. |
| **Расположение данных репозитория** | Где GitPoulpi хранит данные каждого репозитория (`session.per_repo_state_dir`): **Внутри .git** (по умолчанию: в рабочем дереве ничего не появляется, все рабочие деревья делят данные), **В рабочем дереве** (папка `.gitpoulpi`; нужна, чтобы зафиксировать командный `workflow.toml`) или **В папке данных пользователя** (вне репозитория). Папка `.gitpoulpi`, оставшаяся от старой версии, переносится на новое место при первом обращении и удаляется, когда пустеет; файл, который отслеживает git (зафиксированный `workflow.toml`), никогда не переносится и не удаляется и остаётся доступным для чтения. |
| **Имя ветки по умолчанию** | Первая ветка репозитория, который вы создаёте через Init. Пусто: решает git. Существующие ветки не переименовываются. |
| **Включить проактивное обнаружение конфликтов** | По умолчанию включено (`general.conflict_detection`). Предупреждает в Log, что merge текущей ветки в ветку, от которой она ответвилась, привёл бы к конфликту, ещё до того, как вы попробуете. Репозиторий может отключить это для себя на странице **Предотвращение конфликтов**. См. [Разрешение конфликтов слияния](merge-conflicts.md#предотвращение-конфликтов). Применяется при закрытии настроек. |
| **Уровень журнала**, **Хранить файлы журнала**, **Максимальный размер файла журнала** | Журнал приложения за Журналом активности: самый подробный записываемый уровень (`log.level`), как долго хранятся файлы (целое число и единица, дни, недели, месяцы или годы, в одной строке: щёлкните число, чтобы ввести его, Вверх и Вниз меняют его, Tab переходит к единице, а Enter открывает её список; не больше 10 лет, по умолчанию 1 неделя, `log.retention_days` и `log.retention_unit`) и размер, при котором файл за день ротируется (число и МиБ или ГиБ, от 1 МиБ до 1 ГиБ, `log.max_file_mb` и `log.max_file_unit`). |
| **Показывать длительность операций**, **Расширенное ведение журнала** | Вкладка «Операции git» Журнала активности: длительность каждой операции (`log.timings`, по умолчанию включено) и фоновая работа тоже, обновление и auto-fetch (`log.extended`, по умолчанию выключено). См. [Когда что-то не удаётся](troubleshooting.md#журнал-активности). |
| **Отмена включена**, **Глубина истории отмены**, **Записывать изменения, сделанные вне GitPoulpi** | Группа **История отмен**. Включает или выключает отмену и задаёт, сколько операций она хранит (по умолчанию 100, `0` - без ограничения). Выключение отмены стирает историю отмены после подтверждения. Последняя настройка записывает ещё и то, что оболочка или агент делают с ветками, тегами, stash'ами и HEAD. См. [Отмена и повтор](undo-redo.md). |

#### Лаунчер (интеграция с рабочим столом)

Группа **Лаунчер**, последняя на странице «Общие», создаёт ярлык, который запускает GitPoulpi
из лаунчера системы в выбранном вами терминале.

| Строка | Что делает |
|---|---|
| **Терминал для ярлыков** | `ui.launch_terminal`: **Автоматически**, **По умолчанию в системе** или один из терминалов, найденных на этом компьютере (то же обнаружение, что и в **Открыть в**). Автоматически: Windows Terminal в Windows (иначе WezTerm, Alacritty, обычная консоль), `xdg-terminal-exec` в Linux (Omarchy; иначе первый найденный терминал), Terminal в macOS, если не установлен iTerm2, Ghostty, WezTerm или kitty. |
| **Открывать заново в этом терминале при двойном щелчке** | Только Windows (`ui.relaunch_in_terminal`). Двойной щелчок по exe открывает стандартную консоль, которая плохо рисует изображения: GitPoulpi открывается заново в выбранном терминале, а первое окно закрывается. Не происходит, если программа запущена из терминала. |
| **Показывать открытое окно по щелчку** | `ui.reuse_window` (включено по умолчанию). Щелчок по ярлыку GitPoulpi (`gitpoulpi launch`) показывает окно уже открытого GitPoulpi вместо запуска ещё одного. Новый терминал запускается, только если ни один не открыт, параметр выключен или окно не может выйти на передний план. На передний план оно выходит в Windows, в WezTerm и в Hyprland; на других рабочих столах Linux щелчок по-прежнему запускает новое окно. В macOS не используется (Dock уже это делает). Чтобы намеренно открыть ещё одно окно, удерживайте **Shift** при щелчке (Windows) или используйте действие лаунчера **New Window** (Linux); из скрипта это делает `gitpoulpi launch --new-window`. |
| **Псевдоним команды** | `ui.command_alias`: выпадающий список с вариантами **Нет** и `gp`, либо введите любое имя (буквы, цифры, `-`, `_`, `.`; без пробелов и разделителей пути). Встроенная кнопка **Создать** делает так, что это имя запускает GitPoulpi (когда псевдоним уже есть, она превращается в **Удалить** и удаляет все созданные GitPoulpi псевдонимы). Под строкой появляется предупреждение, если имя уже запускает что-то другое из вашего PATH, а в Windows - если у PowerShell есть встроенный псевдоним с таким именем (там `gp` - это `Get-ItemProperty`, и он главнее любого файла). Псевдоним или функцию оболочки отсюда не видно: oh-my-zsh сам определяет `gp`, и он главнее нашего. |
| **Псевдоним новой вкладки** | `ui.command_alias_add`: вторая команда, например `gpa`, которая открывает текущую папку новой вкладкой уже запущенного GitPoulpi (`gitpoulpi --add`) вместо запуска ещё одного; если ни один не запущен, она запускает GitPoulpi как обычно, а если запущено несколько, спрашивает, к какому присоединиться. Выпадающий список с вариантами **Нет**, `gpa` и имя псевдонима с добавленной `a`, либо введите любое имя (те же правила, что выше). Одна кнопка **Создать** делает обе команды, **Удалить** удаляет все созданные GitPoulpi команды; у каждой своя строка состояния. В Linux и macOS это скрипт из двух строк, в Windows - файл `.cmd`. См. [справочник CLI](cli-reference.md#добавление-папки-в-открытое-окно). |
| **Добавить GitPoulpi в PATH** | Добавляет в PATH для новых терминалов папку, из которой запускается GitPoulpi, и папку псевдонимов. Кнопка в строке называется **Добавить** или **Убрать**, и **Убрать** убирает ровно то, что было добавлено. Папки, которые уже есть в PATH, не трогаются (тогда в строке написано **уже в PATH**). |
| **Linux: Лаунчер приложений** | Записывает `~/.local/share/applications/gitpoulpi.desktop` (учитывает `XDG_DATA_HOME`) и значок в `~/.local/share/icons/hicolor/256x256/apps`. В Omarchy это та же запись, что создаёт `omarchy-tui-install` (`xdg-terminal-exec --app-id=TUI.tile -e <exe>`); для других терминалов - соответствующая команда (`kitty`, `wezterm start --`, `alacritty -e`, `ghostty -e`, `foot`, ...). |
| **Linux: Рабочий стол** | Та же запись в папке рабочего стола, если она у вас есть. |
| **Windows: Меню «Пуск»** | `GitPoulpi.lnk` в `%APPDATA%\Microsoft\Windows\Start Menu\Programs`. Копия, закреплённая на панели задач, сама следует за сменой значка и цвета; если её значок остался старым, открепите её и закрепите снова (правый клик по записи в меню «Пуск», затем **Закрепить на панели задач**). |
| **Windows: Рабочий стол** | `GitPoulpi.lnk` на вашем рабочем столе. |
| **macOS: Папка «Программы»** | `~/Applications/GitPoulpi.app` - небольшой пакет, который открывает терминал с запущенным GitPoulpi. |

Каждая строка показывает своё состояние: **не создан**, **создан**, **устарел, обновляется...** (exe
перемещён или выбран другой терминал; GitPoulpi сам перезаписывает ярлык в течение секунды, так что вы редко это видите) или «там лежит
файл, созданный не GitPoulpi» (файл с таким именем существует, но его создал не GitPoulpi,
поэтому он никогда не трогается). **Удалить** удаляет только файлы, созданные GitPoulpi
(у них есть метка `X-GitPoulpi=1`). Значок - осьминог цвета вашего логотипа (окно
«О программе», клавиша `c`); в Linux у каждого цвета своё имя значка, так что лаунчер, кэширующий значки, показывает новый цвет. Созданный ярлык сам остаётся актуальным: когда вы меняете цвет или терминал либо exe переезжает, GitPoulpi перезаписывает ярлыки, которые создал (никогда не чужие и никогда не создавая новых), при запуске и во время работы. Кнопки «Обновить» нет; есть только **Создать** (для ярлыка, которого ещё нет) и **Удалить**.

**Группировка на панели задач и в доке.** GitPoulpi работает в окне терминала, поэтому панель задач обычно показывает его под значком терминала, без точки «запущено» под закреплённым значком GitPoulpi. Windows: ярлыки несут AppUserModelID `GitPoulpi.GitPoulpi`, а GitPoulpi, запущенный из такого ярлыка, даёт окну своего терминала тот же ID и свой значок (он находит окно, на мгновение задавая ему уникальный заголовок, а затем возвращает заголовок), так что окно оказывается под закреплённым значком GitPoulpi. Окно терминала с несколькими вкладками перемещается целиком: все его вкладки группируются под значком GitPoulpi, пока в нём работает GitPoulpi. Ранее созданные ярлыки и закрепления на панели задач переписываются той же синхронизацией; если закрепление всё ещё показывает значок терминала, открепите его и закрепите заново. Linux: kitty, foot, Alacritty, WezTerm и Ghostty запускаются с классом окна `gitpoulpi`, и запись `.desktop` указывает его (`StartupWMClass`), поэтому док группирует окно под значком запуска; остальные терминалы сохраняют собственный значок. macOS: делать нечего, Dock группирует по приложению.

![Настройки > Общие, прокрученные до группы «Лаунчер»: терминал для ярлыков и строка лаунчера приложений](../images/settings-launcher.png)

##### Псевдоним команды и PATH по системам

| Система | Псевдоним | PATH |
|---|---|---|
| Linux, macOS | Символическая ссылка `~/.local/bin/<name>` на `gitpoulpi-tui`. Ссылка не может нести метку, поэтому она считается нашей, если её цель - файл с именем `gitpoulpi-tui`; обычный файл или ссылка на что-либо другое **не наши** и никогда не заменяются и не удаляются. | Блок между `# >>> GitPoulpi PATH (X-GitPoulpi=1) >>>` и `# <<< GitPoulpi PATH <<<` в `~/.bashrc` и `~/.zshrc` (в тех, что есть; если нет ни того ни другого, то `~/.zshrc` в macOS и `~/.bashrc` в остальных) и `~/.config/fish/conf.d/gitpoulpi-path.fish`, если настроен fish. Удаление убирает блок (или файл fish) и больше ничего. |
| Windows | `%LOCALAPPDATA%\Programs\GitPoulpi\bin\<name>.cmd` - прокладка из двух строк с `REM X-GitPoulpi=1`. | Пользовательский PATH в `HKCU\Environment`, записанный через PowerShell, затем рассылка `WM_SETTINGCHANGE`, чтобы новые программы его увидели. Значение `GitPoulpiPathAdded` запоминает, что добавлено, и удаление убирает только это. |

Изменение PATH видят новые терминалы, а не уже открытые. Ни то ни другое действие не попадает в журнал: отмены для них нет, обратный путь - **Удалить**.

В палитре есть те же действия (**Лаунчер: создать ярлык**, **Лаунчер: создать ярлык на рабочем столе**,
**Лаунчер: удалить ярлыки**, **Лаунчер: создать псевдоним команды**, **Лаунчер: удалить псевдоним команды**, **Лаунчер: добавить в PATH**, **Лаунчер: убрать из PATH**), а `gitpoulpi desktop shortcut
status|install|remove [--where launcher|desktop|startmenu]` делает то же из скрипта.

Команда палитры **Приложение: сменить язык...** (`Ctrl+N g`) открывает тот же
список языков. Там выделенный язык сразу показывается в предпросмотре; `Enter`
оставляет его, а `Esc` возвращает прежний.

### Синхронизация

Как GitPoulpi синхронизирует репозиторий с его remote и что делает с вашими
локальными изменениями в это время.

![Страница «Синхронизация»: интервал auto-fetch в виде числа и единицы (минуты) в одной строке, ниже остальные параметры](../images/settings-quantity.png)

| Настройка | Что делает |
|---|---|
| **Интервал auto-fetch** | С этим интервалом в фоне загружает все remote, число и единица (минуты или часы) в одной строке. По умолчанию 5 минут, максимум 60 минут (1 час), `0` отключает. `general.auto_fetch_interval_minutes` остаётся в минутах; `general.auto_fetch_interval_unit` лишь записывает, как это показывается. Нужен перезапуск. |
| **Делать fetch при открытии вкладки** | Запускает Fetch All в фоне при открытии вкладки репозитория. По умолчанию включено. Репозиторий, загруженный за последние 60 секунд, повторно не загружается. |
| **Автоочистка (prune)** | Загрузка также удаляет remote-tracking ветки, которых больше нет на remote. По умолчанию выкл. |
| **Автоочистка tag'ов** | Загрузка также удаляет локальные tag'и, которые удалены на remote. Затрагиваются только tag'и, которые там были: tag, который вы никогда не отправляли через push, остаётся. По умолчанию выкл., как в git. Нужен git 2.41 или новее. CLI: `gitpoulpi fetch --prune-tags`; ключ конфигурации `general.auto_prune_tags`. См. [Ветки, tag'и и боковая панель Refs](log-and-history.md#ветки-tagи-и-боковая-панель-refs). |
| **Обновлять подмодули** | После checkout или pull обновляет подмодули до commit'ов, записанных в репозитории. См. [Подмодули](submodules.md). |
| **Удалять файлы «.orig» после merge** | После завершения merge удаляет резервные файлы `*.orig`. По умолчанию выкл. |
| **Auto-stash перед checkout, pull, merge или rebase** | Что делать, когда локальные изменения блокируют одну из этих операций: **спрашивать** (диалог предлагает спрятать изменения в stash, выполнить операцию и вернуть stash), **всегда** (делать без вопросов) или **никогда** (отказ). |
| **Включать неотслеживаемые файлы в auto-stash** | Автоматический stash берёт и неотслеживаемые файлы. |

Там же, в группе **Обновления**:

| Настройка | Что делает |
|---|---|
| **Проверка обновлений** | Выпадающий список (`updates.mode`): **Уведомлять** (по умолчанию) раз в сутки проверяет в фоне и показывает в строке заголовка `доступна vX.Y.Z`; **Авто** дополнительно скачивает обновление в фоне, если GitPoulpi установлен из архива выпуска (когда перезапускать, выбираете вы); **Выкл.** никогда не делает запросов. Применяется сразу. См. [Обновления](installation.md#обновления). |
| **Канал обновлений** | Выпадающий список (`updates.channel`): **Стабильный** (по умолчанию) или **Предварительный** (также релиз-кандидаты). Применяется сразу. |

Там же, в группе **Переписывание истории**, лимиты времени внешних скриптов (см. [Переписывание истории](history-rewrite.md)):

| Настройка | Что делает |
|---|---|
| **Лимит времени ответа скрипта** | Сколько внешнему скрипту дано на ответ по одному commit'у, число и единица (миллисекунды или секунды) в одной строке. По умолчанию 5 секунд, от 1 миллисекунды до 10 минут (`rewrite.script_timeout_ms`, `rewrite.script_timeout_unit`). При тайм-ауте весь процесс останавливается, а переписывание завершается ошибкой, ничего не изменив. |
| **Лимит времени скрипта на проход** | Сколько может занять один полный проход внешнего скрипта, число и единица (секунды, минуты или часы). По умолчанию 1 час, не больше 24 часов (`rewrite.script_total_timeout_s`, `rewrite.script_total_timeout_unit`). |

### Профили

![Страница «Профили»](../images/settings-profiles.png)

Профили идентичности для commit'ов: имя и email, с которыми делаются commit'ы из
GitPoulpi. На вкладке **Общие** находится выпадающий список **Активный профиль**;
вкладка **Профили** - это [список](#списки) (добавление, дублирование, удаление,

При двух и более профилях на панели инструментов в правом конце появляется

этого репозитория. Команда палитры: **Репозиторий: сменить профиль...**.

Эти профили - не профили хостинга со страницы «Интеграции» и не профили ИИ со
страницы «ИИ».

### SSH и учётные данные

![Страница «SSH и учётные данные»](../images/settings-ssh.png)

SSH использует системный `ssh`, поэтому ваш ssh-agent и ваша конфигурация ssh
продолжают работать. GitPoulpi никогда не читает содержимое ключей.

| Настройка | Что делает |
|---|---|
| **Путь к закрытому ключу** | Если задан, fetch, pull, push и clone запускают git с `GIT_SSH_COMMAND=ssh -i "<key>" -o IdentitiesOnly=yes`, так что ssh предлагает только этот ключ. Пусто: агент и ваша конфигурация ssh действуют без изменений. |
| **Путь к открытому ключу** | Используется, только если путь к закрытому ключу пуст: ssh выбирает подходящий ключ из ssh-agent (или аппаратный ключ). |
| **Тип ключа** | Тип, который создаёт **Создать пару ключей**: `ed25519`, `rsa` (4096 бит) или `ecdsa` (NIST P-256). |
| **Учётные данные HTTPS** | Как fetch, pull, push и clone проходят аутентификацию по HTTPS: **credential_helper** (собственный помощник git, по умолчанию), **prompt** (игнорировать помощники; git спрашивает в терминале) или **none** (без учётных данных, только публичные remote). |
| **Забыть все имена пользователей и пароли** | Удаляет все токены, которые GitPoulpi сохранил в вашем credential helper. Сначала просит подтверждение. |
| **Создать пару ключей** | Создаёт пару ключей **Типа ключа** в `~/.ssh/gitpoulpi_<type>`, без парольной фразы, и записывает два её пути. Никогда не перезаписывает файл. |

Пути к ключам применяются при следующей передаче. Префикс `~/` означает вашу
домашнюю папку.

Настройка, заданная в другом месте, всегда главнее этих путей. Порядок, от
высшего приоритета:

1. `GIT_SSH_COMMAND` или `GIT_SSH` в окружении, в котором работает GitPoulpi.
2. `core.sshCommand` в git-конфигурации репозитория или в вашей глобальной
   git-конфигурации. Пункт **Ключ SSH...** меню вкладки записывает его для одного
   репозитория.
3. Два пути к ключам с этой страницы.
4. Собственные значения по умолчанию ssh и агент.

Ключ может также принадлежать аккаунту на хостинге; см.
[Интеграции с хостингами и трекерами задач](hosting-integration.md#ключ-ssh-для-профиля).

Что ИИ-агенты могут делать в этом окне и может ли работать сервер MCP. Две

|---|---|
| **Сервер MCP** | Включено (по умолчанию): агент может запустить сервер (`gitpoulpi mcp serve`). Выключено: он отказывается запускаться. Сохраняется как `mcp.enabled`. Изменение применяется при следующем запуске сервера агентом; уже работающий сервер сохраняет свои настройки. |

| **Разрешить ИИ-агентам управлять видом** | Позволяет агентам показывать вам в этом окне commit, файл или уведомление (`ui show`). Выкл.: ни один агент не достаёт до окна. |
| **Разрешить ИИ-агентам предлагать изменения для моего подтверждения** | Позволяет агентам открывать заполненные заранее диалоги изменения сообщения, commit'а, ветки или tag'а, которые вы подтверждаете. По умолчанию выкл. См. [MCP и агенты](mcp-and-agents.md#разрешения). |
| **Открывать окно для агентов**, **Команда запуска (custom)** | Может ли агент открыть окно GitPoulpi, когда ни одного не открыто, и с помощью какого терминала или мультиплексора. По умолчанию выкл. |

### Журнал и граф

Как рисуется граф commit'ов и сколько commit'ов загружает Log. Цвета графа
находятся на странице **Внешний вид**.

| Настройка | Что делает |
|---|---|

В столбце Ref наведённый commit без собственной ссылки показывает бледную пилюлю с названием ветки, к которой он относится (иначе удалённой ветки), выведенным из истории, если в столбце хватает места. Tag никогда не показывается как призрак. При наведении на пилюлю видно её тип. Щелчок по ней ничего особого не делает; ветку создаёт команда палитры `Git: создать ветку в выбранном commit'е...`. |

Тот же переключатель есть в списке колонок Log и в палитре. |

Клавиши изменения размера (`Shift+C` в Log, `C` в Radar, `Tab` в колонке commit'ов) в обоих режимах работают одинаково. |
| **Показывать счётчики WIP в сообщении, когда колонка «Изменения» скрыта** | Показывает счётчики изменений (`✎ 3  + 2  − 1`) в сообщении строки WIP. Когда колонка «Изменения» видна, счётчики показываются там. |
| **Дерево папок веток** | Группирует ветки и tag'и по `/` в папки на боковой панели. `y` на панели Refs переключает его. |
| **Разделы левой панели** | Чей выбор определяет, какие разделы левой панели показаны или скрыты: **по репозиториям** (по умолчанию; у каждого репозитория свой набор, за основу берётся глобальный) или **глобально** (один набор для всех репозиториев). При переключении туда и обратно сохраняются оба набора. См. [мышь и жесты](mouse-and-gestures.md). (`ui.sidebar_sections_scope`) |
| **Щелчок по ссылке показывает её в графе** | Одиночный щелчок по ссылке на панели Refs прокручивает Log туда, куда она указывает, и подсвечивает строку (выбор commit'а и правая панель остаются на месте). Выкл.: щелчок только выбирает строку боковой панели. **Показать в графе** работает в любом случае. |
| **Предложения композитора** | Открывается ли обзор ИИ-композитора commit'ов с файлами каждого предложения **развёрнутыми** или **свёрнутыми**. |
| **Начальное число commit'ов в графе** | Сколько commit'ов Log загружает при открытии репозитория. По умолчанию 5000, минимум 500. Большие значения замедляют работу с крупными репозиториями. |

| **Показывать авторов через .mailmap** | Log, blame и история файла показывают каждого автора так, как его называет `.mailmap` репозитория (`log.use_mailmap`, переключатель, по умолчанию включён, применяется сразу). Сохранённые commit'ы не меняются никогда. Выключено - имена показываются такими, какими были закоммичены. См. `history-rewrite.md`, *Вкладка «Авторы»*. |

### Изображения

Как показываются файлы изображений и какую программу использует **Править в**.
См. [Изображения](image-view.md). На вкладке **Общие** находятся параметры просмотра
ниже, **Запись по умолчанию** и **Восстановить найденные значения**; вкладка
**Редакторы** - это список редакторов изображений. В сборке без просмотра
изображений параметров просмотра нет.

| Настройка | Что делает |
|---|---|
| **Показывать изображения** | Показывает файл изображения как картинку в виде Diff и в просмотре файла. Выкл.: обычное сообщение о двоичном файле. По умолчанию включено. |
| **Без протокола изображений** | В терминале без встроенного протокола изображений: **Цвета полублоков** (по умолчанию) или **Только карточка**. |
| **Макс. размер просмотра** | Изображения больше этого размера не декодируются; вместо них показывается карточка. Число и МиБ или ГиБ, по умолчанию 32 МиБ, не больше 1 ГиБ (`ui.image_view_max_mib`, `ui.image_view_max_unit`). |
| **Пиксельное увеличение с** | `1x`, `2x` (по умолчанию) или `never`: начиная с этого масштаба картинка показывается квадратными пикселями вместо сглаженной. |
| **Синхронизировать масштаб и прокрутку до/после** | Две панели diff изображений используют один масштаб и одну позицию прокрутки. По умолчанию включено. |

Вкладка **Редакторы** - это [список](#списки), как и [Открыть в](open-in.md):
для каждого редактора **Название**, **Команда**,
плашки переменных `${file}` `${dir}` `${name}` `${repo}` и **Проверить на
тестовом изображении**; **+ Добавить ▾** предлагает шаблоны и пункт **Своя**, а
**Восстановить найденные значения** сбрасывает список. Пока вы его не
правите, в списке находятся редакторы, установленные на этом компьютере, и
приложение системы по умолчанию. Каждое изменение применяется сразу.

### Настройки репозитория: Частичный checkout

Те же элементы, что в окне частичного checkout (`Репозиторий: Частичный checkout...`), в виде страницы настроек этого репозитория
(`gitpoulpi ui show settings sparse-checkout`).

| Настройка | Что делает |
|---|---|
| **Состояние** | Является ли это рабочее дерево частичным checkout. |
| **Сохраняемые каталоги** | По одному каталогу в строке, относительно корня репозитория. `Enter` (или щелчок) открывает многострочный редактор: `Ctrl+S` сохраняет текст, `Esc` отбрасывает. Пока частичный checkout включён, в поле показаны текущие каталоги. Конусный режим git знает только каталоги (ни шаблонов, ни отдельных файлов), файлы в корне всегда извлекаются, а пустой список отклоняется. |
| **Начать частичный checkout** | Извлекает только перечисленные каталоги. Когда частичный checkout уже включён, та же кнопка называется **Применить список каталогов** и применяет изменённый список: каталог, выпавший из списка, удаляется из рабочего каталога. Недоступна, пока список пуст. |
| **Остановить частичный checkout** | Возврат к полному checkout: все файлы возвращаются (после подтверждения). Недоступна, пока частичный checkout выключен. |
| **Обновить частичный checkout** | Применяет текущий список ещё раз (например, после того как скрипт или другая программа извлекла файлы вне него). Отправляются текущие каталоги, а не неотправленный текст поля. Недоступна, пока частичный checkout выключен. |

Кнопки выполняются как обычные фоновые действия (пока одно идёт, страница пишет «применяется частичный checkout...»). Как и окно, они не входят в стек отмены: ничего не теряется, а **Выключить** возвращает каждый файл.

### Настройки репозитория: LFS

Состояние LFS этого репозитория (`gitpoulpi ui show settings lfs`; в сборке без LFS нет).

- **Не инициализирован:** «Git LFS не настроен в `<репозиторий>`» и кнопка **Настроить LFS здесь**,
  выполняющая `git lfs install --local` (фильтры и хуки этого репозитория, но не глобальная конфигурация; нужен
  `git-lfs`). Если `.gitattributes` репозитория уже направляет файлы через LFS, а его хуков нет, страница об этом
  говорит.
- **Инициализирован:** «Git LFS настроен в `<репозиторий>`» и шаблоны, отслеживаемые в `.gitattributes`
  (`filter=lfs`).

LFS считается **инициализированным**, когда у репозитория есть собственные хуки LFS (хук `pre-push` или `post-checkout`,
который записывает `git lfs install --local`). Одних фильтров недостаточно: `git lfs install` на уровне пользователя
задаёт их для каждого репозитория, и тогда любой репозиторий выглядел бы инициализированным.

Кнопка **`LFS ▾`** на панели инструментов следует тому же состоянию: она видна только в репозитории, где LFS
инициализирован или где `.gitattributes` уже его использует, и скрыта в обычном репозитории (а также пока не прошло
первое чтение LFS репозитория, поэтому она может появиться через мгновение после открытия). Инициализация с этой страницы
её показывает. Команды палитры `LFS:` доступны везде, включая **LFS: инициализировать для этого репозитория**.

### Настройки репозитория: Commit

Как ведёт себя commit в этом репозитории (`gitpoulpi ui show settings commit`). Оба переключателя по умолчанию
**выключены** и сохраняются только для этого репозитория (`[preferences]` в
[`repo-state.toml`](config-reference.md#настройки-репозитория-gitpoulpirepo-statetoml)).

| Настройка | Что делает |
|---|---|
| **Push при каждом commit'е** | После успешного commit'а делает push текущей ветки в её upstream, как обычный push (отслеживаемая передача с текстом «создание коммита, затем отправка...»). Ветка без upstream фиксируется, но не отправляется, и уведомление об этом говорит: первый push новой ветки остаётся за кнопкой **Push**, которая задаёт upstream. Отклонённый push открывает обычную карточку отказа; commit остаётся. |
| **По умолчанию обходить хуки git при каждом commit'е** | Флажок **Пропустить хуки** в форме commit'а (рядом с **Amend предыдущего commit'а**; `Shift+H` в панели Status или **Commit: переключить пропуск хуков** в палитре) начинается отмеченным, так что хуки `pre-commit` и `commit-msg` не запускаются (`git commit --no-verify`). Это остаётся выбором на каждый commit: после commit'а флажок возвращается к этому значению по умолчанию. |

Без этого значения хуки commit'а репозитория выполняются при каждом commit'е, какой бы бэкенд ни использовал GitPoulpi
(репозиторий с хуками commit'а фиксируется через системный `git`, потому что libgit2 их не запускает). Хук, который
завершился с ошибкой, показывает свой вывод в своей записи Журнала активности (строка состояния сообщает, что commit не удался), и ничего не фиксируется.

### Настройки репозитория: Настройки merge

Один переключатель, **Squash** (по умолчанию выключен). Когда он включён, слияние локальной ветки (меню ветки,
перетаскивание, `Merge` в палитре) добавляет изменения ветки в индекс, не создавая merge-commit (`git merge --squash`):
завершить commit предстоит вам. Форма commit'а открывается с squash-сообщением git (`SQUASH_MSG`, строки комментариев
убраны), один раз на каждый squash. Потом ничего не остаётся в процессе (нет `MERGE_HEAD`), так что **Прервать** не
применимо: чтобы отказаться, отбросьте добавленные в индекс изменения. Squash, остановившийся на конфликтах, оставляет
их в панели Status, как любое конфликтное слияние. Добавленные в индекс изменения - не запись отмены (ни одна ссылка не
сдвинулась, восстанавливать нечего); `gitpoulpi merge <branch> --squash` в CLI делает то же независимо от настройки.

### Настройки репозитория: Шаблон сообщения

Сообщение, с которого начинается форма commit'а (`gitpoulpi ui show settings commit-template`).

- **Заполнять пустую панель commit'а шаблоном**: *пустая* форма commit'а заполняется шаблоном, один раз на каждый
  commit (если вы очистили её вручную, это уважается до следующего commit'а).
- **Отбрасывать строки комментариев при создании commit'а**: при создании commit'а строки, начинающиеся с `#` (или с
  `core.commentChar` репозитория), удаляются из сообщения, как это сделал бы `git commit --cleanup=strip`. GitPoulpi
  делает commit с `-m`, а git такое сообщение не очищает, поэтому это делает он сам. При выключенном переключателе
  строка с `#` остаётся в commit'е.
- **Заголовок** (подпись считает оставшиеся из 72 столбцов и сколько превышено) и многострочное **Описание**
  (`Enter` или щелчок открывает редактор, `Ctrl+S` сохраняет).
- **Сохранить шаблон** записывает шаблон в `commit-template.txt` в папке данных репозитория (см.
  `session.per_repo_state_dir`) и задаёт `commit.template` этого репозитория на этот файл, так что `git commit` в
  командной строке и другие инструменты тоже его используют. Если `commit.template` уже указывает на другой файл,
  страница показывает путь к нему, правит *этот файл* и оставляет настройку как есть.

### Настройки репозитория: Предотвращение конфликтов

`gitpoulpi ui show settings conflict-prevention`. Страница проактивного обнаружения конфликтов этого репозитория
(см. [Разрешение конфликтов слияния](merge-conflicts.md#предотвращение-конфликтов)):

- **Включить проактивное обнаружение конфликтов с целевой веткой**: по умолчанию включено. Снятие флажка отключает
  обнаружение только для этого репозитория; глобальный переключатель - **Включить проактивное обнаружение
  конфликтов** на странице «Общие». Должны быть включены оба.
- **Базовые ветки** (по умолчанию `**`): ветки, от которых могла ответвиться текущая ветка, по одному шаблону в строке
  (`Enter` или щелчок открывает редактор, `Ctrl+S` сохраняет). Справочник - таблица шаблонов под ним:

  | Шаблон | Что подходит |
  |---|---|
  | `origin/main` | только эта ветка |
  | `origin/**` | все ветки remote `origin` |
  | `origin/feature/**` | ветки `origin`, имена которых начинаются с `feature/` |
  | `!origin/abc` | исключает эту ветку |

  Локальная ветка - просто её имя (`main`), удалённая имеет впереди свой remote (`origin/main`). `*` и `?` остаются
  внутри одного сегмента пути, `**` пересекает их. Пустые строки и комментарии `#` игнорируются; список из одних
  исключений означает «все ветки, кроме этих». Хранится в `repo-state.toml` и перечитывается при закрытии настроек.

### Настройки репозитория: Рабочий процесс

`gitpoulpi ui show settings workflow`. Рабочий процесс с ветками для этого репозитория (шаблон, определение, базовая ветка) описан в отдельном руководстве: [Рабочие процессы с ветками](branching-workflows.md#настройки--рабочий-процесс). Вкладка **Общие** содержит всё, что не является правилом (шаблон, определение, хуки, процесс задач, место сохранения); вкладка **Правила** - это [список](#списки) с группами (**Базовые ветки**, **Типы веток**, **Правила завершения**); **+ Добавить ▾** выбирает вид элемента, а элементы перемещаются внутри своей группы. В отличие от других страниц, здесь есть черновик (панель есть на обеих вкладках): панель, закреплённая внизу страницы, показывает **● Не сохранено** (или **Нет изменений**) и кнопки **Сохранить в общий файл**, **Только для меня** и **Отбросить изменения**, а закрытие настроек с несохранённым черновиком сначала спрашивает.

## Файлы, переменные окружения и CLI

- Файл настроек - `config.toml` в папке конфигурации вашей ОС.
  `gitpoulpi config path` печатает его расположение.
- Состояние отдельных репозиториев находится в `.gitpoulpi/repo-state.toml`
  внутри репозитория.
- `gitpoulpi config get <key>` и `gitpoulpi config set <key> <value>` читают и
  записывают каждую настройку.
- Переменные окружения и флаги командной строки переопределяют файл.

Подробности даёт [справочник по конфигурации](config-reference.md).
