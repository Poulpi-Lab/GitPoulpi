# Обновления

GitPoulpi проверяет наличие новых выпусков и, в зависимости от способа установки, либо заменяет собственные файлы, либо передаёт обновление программе, которая его установила. Ничто не заменяется и не перезапускается без вашего действия.

## Значок и панель

В строке заголовка между названием приложения и путём к репозиторию показана запущенная версия (`v1.0.0`). Когда известен более новый выпуск, значок меняется на `v0.2.0 доступна` цветом акцента.

Нажмите `Ctrl+N`, затем `u`, выполните **Обновления: показать обновление** в палитре команд (`Ctrl+P`) или щёлкните по значку, пока на нём написано `доступна` (или пока идёт обновление): откроется панель обновлений. Если нового выпуска нет, щелчок по значку открывает вкладку «Заметки о выпуске». Это окно поверх приложения: закрыть его можно клавишами `Esc`, `q`, крестиком или щелчком снаружи. Она показывает:

- запущенную версию и **Установлено через**: как GitPoulpi попал на этот компьютер (от этого зависит всё остальное ниже);
- состояние обновления (проверка, скачивание с процентами, готово, ошибка);
- кнопки процедуры для этой установки и точную команду, если она есть;
- строку от вашего администратора, если он её задал.

У каждой кнопки есть клавиша (она напечатана в строке подсказки панели) и команда палитры, так что панель работает без мыши:

| Кнопка | Клавиша | Команда палитры |
|---|---|---|
| **Обновить и перезапустить** (или **Запустить обновление**) | `u` | Обновления: обновить сейчас |
| **Копировать команду** | `c` | Обновления: копировать команду обновления |
| **Открыть в терминале** | `t` | Обновления: выполнить команду обновления в терминале |
| **Вернуться к ...** | `v` | Обновления: вернуться к предыдущей версии |
| **Заметки о выпуске** | `n` | Справка: заметки о выпуске |
| **Пропустить версию** | `s` | Обновления: пропустить эту версию |
| **Открыть уведомление** (только при уведомлении о безопасности) | `a` | Обновления: открыть уведомление о безопасности |
| **Проверить** | `r` | Обновления: проверить наличие сейчас |
| **Закрыть** | `Esc` | |

Команда, которая не подходит для этой установки, в палитре затемнена с указанием причины (например, «эта установка обновляется другим способом: см. «Обновления: показать обновление»»).

## Что происходит при каждом способе установки

| Установлено через | Где проверяется | Что делает панель | Возврат назад |
|---|---|---|---|
| Архив выпуска или `install.sh` | Выпуски GitHub | **Обновить и перезапустить**: GitPoulpi скачивает и проверяет архив, закрывается, заменяет свои файлы и снова открывается в том же терминале. | **Вернуться** возвращает прежние файлы. |
| Установщик Windows, только для меня | Выпуски GitHub | То же, без запроса. В Windows он открывается заново в новом окне. | **Вернуться** возвращает прежние файлы. |
| Установщик Windows, для всех пользователей | Выпуски GitHub | То же, но Windows запрашивает подтверждение администратора. Сеансы GitPoulpi других пользователей на компьютере закрываются, и их несохранённый ввод теряется. Если отказаться, ничего не изменится. | **Вернуться** возвращает прежние файлы, с тем же запросом. |
| Chocolatey | Общий репозиторий Chocolatey | **Запустить обновление** выполняет `choco upgrade gitpoulpi -y` (Windows запрашивает подтверждение администратора). | Панель показывает `choco install gitpoulpi --version <предыдущая> --allow-downgrade -y`. |
| Chocolatey, внутренний репозиторий | Репозиторий вашей организации | **Запустить обновление** выполняет `choco upgrade gitpoulpi -y --source=<feed>`. Параметры пакета повторно не передаются, поэтому развёрнутая конфигурация остаётся нетронутой. | Та же строка `choco install` с репозиторием. |
| winget | Выпуски GitHub | **Запустить обновление** выполняет `winget upgrade --id GitPoulpi.GitPoulpi --exact --silent` с принятыми соглашениями. Если установка общая для компьютера, winget сам запрашивает подтверждение администратора. | Панель показывает `winget install --id GitPoulpi.GitPoulpi --version <предыдущая>`. |
| Scoop | Выпуски GitHub | **Запустить обновление** выполняет `scoop update gitpoulpi` после полного закрытия GitPoulpi. | **Вернуться** выполняет `scoop reset gitpoulpi@<предыдущая>`. |
| Homebrew | Выпуски GitHub | **Запустить обновление** выполняет `brew upgrade gitpoulpi` в этом терминале. | Панель показывает `brew install gitpoulpi@<предыдущая>`. |
| apt | Выпуски GitHub | Панель показывает `sudo apt update && sudo apt install --only-upgrade gitpoulpi` с кнопками **Копировать команду** и **Открыть в терминале**. GitPoulpi никогда не выполняет `sudo` за вас. Если на этом компьютере нет репозитория apt GitPoulpi, она предлагает скачать новый пакет `.deb`. | Панель показывает `sudo apt install gitpoulpi=<предыдущая>`. |
| Пакет MSI | Выпуски GitHub или источник вашего администратора | Выполнять нечего: установкой управляет ваш администратор, и панель показывает его сообщение. | Не предлагается. |
| AUR | Выпуски GitHub | Панель показывает `yay -S gitpoulpi-bin` (или `paru`, что найдётся первым; без помощника шаги `git clone` и `makepkg -si`). | Не предлагается. |
| cargo | Выпуски GitHub | Панель показывает `cargo binstall gitpoulpi-cli`, если установлен `cargo-binstall`, иначе `cargo install --locked --git https://github.com/Poulpi-Lab/GitPoulpi --tag releases/v<версия> gitpoulpi-cli`. | Та же команда с предыдущим тегом. |
| Образ Docker | Выпуски GitHub | Выполнять нечего: образ заменяется. Панель показывает `docker pull poulpilab/gitpoulpi:<версия>` и `:latest`. См. [Запуск в Docker](docker.md). | Панель показывает `docker pull poulpilab/gitpoulpi:<предыдущая>`. |
| Архив выпуска в папке, в которую нельзя писать | Выпуски GitHub | Панель сообщает, что GitPoulpi не может там заменить себя, и указывает на **Скачать**. | Не предлагается. |
| Сборка для разработки (`cargo build`) | нет | Никогда не обновляется. Значок показывает версию и ничего больше; панель сообщает, что записи об установке нет. | Не предлагается. |

Строки «показать» сами ничего не выполняют. **Открыть в терминале** открывает ваш терминал с уже набранной командой, а Enter нажимаете вы.

Выпуски всегда берутся из репозитория проекта на GitHub, если только администратор не направил проверку в другое место (внутренний репозиторий, зеркало или `latest.json`), см. [Корпоративное распространение](enterprise-distribution.md). Заметки о выпуске берутся из самого выпуска или из журнала изменений, встроенного в GitPoulpi, смотря что доступно.

## Уведомлять и авто

`updates.mode` ([Настройки > Синхронизация](settings.md#синхронизация)):

- **Уведомлять** (по умолчанию): раз в сутки GitPoulpi проверяет обновления в фоне и показывает значок. Ничего не скачивается, пока вы не нажмёте кнопку.
- **Авто**: там, где GitPoulpi заменяет собственные файлы (архив выпуска, установщик Windows), он также скачивает и проверяет обновление в фоне, как только находит его. Тогда значок гласит **Перезапустить для обновления**, а сам перезапуск остаётся за вами. Там, где обновлением владеет менеджер пакетов, **Авто** работает как **Уведомлять**.
- **Выкл.**: запросы не выполняются вообще, а значок показывает только версию.

Настройка **Канал обновлений** (`updates.channel`) выбирает между **Стабильный** и **Предварительный** (включая релиз-кандидаты). Проверка, запущенная кнопкой **Проверить**, игнорирует ограничение «раз в сутки». Без подключения к сети, а также пока репозиторий закрыт и токен github.com не сохранён, фоновая проверка тихо завершается ошибкой с одной строкой в журнале приложения.

## Перезапуск и что вы увидите потом

Нажатие **Обновить и перезапустить** или **Запустить обновление** сохраняет ваш сеанс и закрывает окно. Работу выполняет отдельная небольшая программа `gitpoulpi-updater`, поэтому собственные файлы GitPoulpi не используются во время замены, а менеджер пакетов не блокируется ожидающим родителем. Сначала она останавливает фоновые демоны GitPoulpi (другие окна и серверы MCP вашего пользователя тоже закрываются), выполняет обновление, проверяет, что новый `gitpoulpi --version` выводит ожидаемую версию, и снова запускает GitPoulpi: в том же терминале в Linux и macOS, в новом окне в Windows. Если проверка не пройдена, она возвращает старые файлы.

При следующем запуске в строке состояния появится одна строка:

- `Обновлено до v1.4.2`
- `Не удалось обновить: <причина>. Предыдущая версия по-прежнему установлена.`
- `Обновление отменено: подтверждение администратора отклонено. Ничего не изменилось.`

Одновременно выполняется только одно обновление; файл блокировки в папке данных GitPoulpi (и ещё один в папке установки, если в неё можно писать) не пускает второе, а блокировка старше десяти минут игнорируется, так что аварийно завершившееся обновление никогда не заблокирует GitPoulpi навсегда. Пока существует свежая блокировка, CLI и демон не запускаются.

## Возврат к предыдущей версии

Там, где GitPoulpi заменяет собственные файлы, **Вернуться** возвращает прежние файлы и перезапускает программу. Они остаются как `<name>.old` ещё минуту после запуска новой версии, затем удаляются, так что возврат рассчитан на первый запуск после обновления. Там, где установкой владеет менеджер пакетов, возврат - это команда из таблицы: панель показывает или выполняет её. Возврат меняет собственные файлы GitPoulpi, а не репозиторий, поэтому не входит в журнал отмены git.

## Что проверяется и что отклоняется

Прежде чем что-либо заменить, GitPoulpi скачивает архив, его подпись `.minisig` и файл `.sha256`. Сначала он проверяет подпись по ключу выпусков проекта, встроенному в GitPoulpi, причём доверенный комментарий подписи должен называть этот архив и эту версию. Затем проверяется хэш. Отклоняется: выпуск без `.minisig` (более старый выпуск, опубликованный до подписи выпусков, нельзя установить через программу обновления, в том числе закрепив версию или вернувшись к ней), подпись другим ключом, подпись для другого файла или другой версии, выпуск без `.sha256`, несовпадающий хэш, архив, имя которого не соответствует этой платформе (`gitpoulpi-<версия>-<target>.<zip|tar.gz>`), архив, маркер которого называет другую версию или платформу, и ссылка для скачивания вне хостов выпусков GitHub (проверяется каждый переход по перенаправлению) или зеркала, настроенного администратором. Замена проходит по принципу «всё или ничего»: если другая программа удерживает один из исполняемых файлов, GitPoulpi называет этот файл, ничего не меняет и оставляет скачанное для другой попытки. В Windows обновление для всех пользователей повторно проверяется шагом с повышенными правами: он сам скачивает `.minisig` и `.sha256` и проверяет оба ещё раз, поэтому файл, подменённый в папке загрузок пользователя за это время, отклоняется. Менеджеры пакетов (Chocolatey, winget, Scoop, Homebrew, apt, AUR) проверяют свои пакеты сами: GitPoulpi там ничего не скачивает.

## Уведомления о безопасности

Рядом с каждым выпуском проект публикует `security.json`: список уведомлений о безопасности (идентификатор, серьёзность, затронутые версии в виде диапазона вроде `>=1.2.0, <1.4.3`, исправленная версия, ссылка и краткое описание в одно предложение). Та же ежедневная проверка, которая ищет новую версию, получает и его, из того же места, что и выпуск: страница выпуска репозитория для GitHub, папка `latest.json` для зеркала, GitHub для общего репозитория Chocolatey. Уведомление используется, только если `security.json.minisig` проверяется по ключу проекта; файл без подписи или с неверной подписью никогда не показывается (в журнале активности остаётся одна строка о том, что он проигнорирован).

Когда уведомление называет запущенную версию, значок становится красным и гласит **Уведомление о безопасности: эта версия затронута**, при любом способе установки, включая управляемые менеджером пакетов. Панель обновлений тогда перечисляет каждое уведомление с его серьёзностью, описанием, исправленной версией и ссылкой; **Открыть уведомление** (`a` или **Обновления: открыть уведомление о безопасности** в палитре) открывает в браузере ссылку самого серьёзного из них. Там, где установкой владеет менеджер пакетов, панель добавляет «Обновите через менеджер пакетов.»

При выключенной проверке обновлений (`updates.mode = "off"`), при политике администратора с `check` равным `none` и для сборки, выполненной через `cargo build`, ничего не загружается и уведомления не показываются. Собственный репозиторий NuGet организации не заставляет GitPoulpi обращаться к GitHub: его уведомления берутся только из зеркала `download_base` политики.

## Настройки, заблокированные администратором

Администратор может задать в общей для компьютера политике режим обновлений, канал, закреплённую версию, место проверки и то, может ли GitPoulpi вообще обновлять себя. В настройках эти строки показывают **Задано администратором**, панель показывает его сообщение, а когда самообновление отключено, панель предлагает команды или примечание вместо кнопок, заменяющих файлы. Нечитаемые файлы политики приводят к безопасному отказу: только уведомления, без самообновления. Сторона администратора описана в [Корпоративное распространение](enterprise-distribution.md#файл-политики-и-реестр).
