# Worktree

Worktree - это вторая рабочая копия репозитория: другая папка, другая ветка, но
та же история. Раздел WORKTREES панели Refs перечисляет их; основной помечен
`(main)`.

## Показ раздела

В репозитории, где ещё нет связанных worktree, раздел скрыт. Чтобы всё равно
увидеть его (тогда в нём написано «Worktree пока нет: + создаёт новый»),
используйте команду палитры **Левая панель: показать раздел Worktrees**, отметьте
**WORKTREES** в списке показа и скрытия разделов боковой панели (правый щелчок по
заголовку раздела) или выполните любую из команд создания ниже. GitPoulpi
запоминает это для данного репозитория (см. **Разделы левой панели** в
[Настройках](settings.md)); другой репозиторий без worktree по-прежнему
начинается со скрытым разделом.

## Создание worktree

**+** в заголовке WORKTREES (клавиатура: `+` в разделе; палитра:
**Refs: создать worktree...**) открывает меню:

- **Из текущей ветки**: ветка уже активна в основной папке, поэтому диалог
  предлагает новую ветку на её основе (`<ветка>-wt`).
- **Из выбранного commit**: недоступно, пока в Log не выбран commit. Worktree
  начинается там с отсоединённого HEAD, если вы не задали новую ветку.
- **Выбрать ветку...**: диалог открывается на своём списке **Ссылка**.

В палитре есть те же три команды (**Refs: создать worktree из текущей ветки**,
**Git: создать worktree в выбранном commit'е...**, **Refs: создать worktree с
выбором ветки**). Прежние пункты тоже работают: **Создать worktree из...** в меню
ветки, tag'а или commit.

Диалог всё предлагает сам и позволяет это изменить:

| Поле | Значение |
|---|---|
| **Имя** | По нему строится имя папки. Предлагается по ветке или короткому id. |
| **Папка** | Соседняя с репозиторием папка `<репозиторий>-<имя>`. Следует за полем «Имя», пока вы не начнёте печатать в поле «Папка»; **Обзор** выбирает место. |
| **Ссылка** | Ветка или commit, с которых начинается worktree (список; печатайте для поиска). При смене предлагается новое имя. |
| **Новая ветка** | Пусто: там делается checkout ветки из поля «Ссылка» (или отсоединяется HEAD на commit). Обязательно, если ветка уже активна. |
| **Открыть новый worktree во вкладке** | По умолчанию включено. |

Непустая папка, недопустимое имя или уже существующая ветка сообщаются в
собственной строке диалога, а кнопка **Создать** остаётся недоступной.

## Меню строки

Правый щелчок по worktree (или выберите его и нажмите клавишу меню, `Shift+F10`
или `.`):

- **Открыть в новой вкладке**: как двойной щелчок или `Enter`.
- **Открыть в**: записи [Открыть в](open-in.md), у которых отмечено поле **Можно
  открыть worktree** (Настройки > Открыть в; по умолчанию отмечены все записи).
  Они запускаются с папкой worktree в качестве `${cwd}`.
- **Merge <ветка> в...**: выберите ветку, в которую выполнить merge (по умолчанию
  ветка основного worktree). Обычный merge выполняется в том worktree, где эта
  ветка активна, с вашими параметрами merge; конфликт решается там же обычным
  порядком разрешения конфликтов. Ветка, не активная нигде, отклоняется с
  объяснением причины. Для отсоединённого worktree не предлагается.
- **Удалить worktree...**: основной удалить нельзя.

В палитре те же действия доступны для выбранной строки (**Refs: открыть worktree
в...**, **Refs: merge ветки worktree в...**, **Refs: удалить worktree...**).

## Удаление worktree

Для чистого worktree показывается простое подтверждение. Если его ветка уже
влита (в её upstream, в ветку основного worktree или в `main` / `master`), поле
**Также удалить ветку <b>** по умолчанию отмечено; о невлитой ветке сказано, что
она останется. **Merge в... и удалить** сначала выполняет merge и удаляет worktree
только после того, как merge прошёл без конфликтов.

Если есть незафиксированные изменения (отслеживаемые или неотслеживаемые),
диалог перечисляет их (число, с прокруткой) и предлагает:

- **Commit и удалить**: в диалоге есть поле для сообщения; все изменения
  добавляются в индекс (с учётом `.gitignore`) и фиксируются на ветке worktree,
  затем worktree удаляется. Для отсоединённого worktree в том же диалоге
  называется ветка для commit.
- **Stash и удалить**: все изменения, включая неотслеживаемые файлы, убираются в
  stash с редактируемым сообщением (по умолчанию «WIP на <папка>»), затем worktree
  удаляется. Список stash общий для всех worktree: после этого stash лежит в
  STASHES основного репозитория, готовый к pop.
- **Открыть для commit**: открывает worktree во вкладке с фокусом на сообщении
  commit; ничего не удаляется.
- **Всё равно удалить**: отбрасывает изменения после второго явного
  подтверждения.

## Отмена

Удаление worktree отменить нельзя: папки больше нет. То, что было сохранено
заранее, остаётся: commit лежит на своей ветке, stash - в списке. Удаление ветки,
которое добавляет **Также удалить ветку**, обычное, с записью в журнал:
**Отменить** возвращает ветку (но не папку). Создание worktree в историю тоже не
входит.

## Из скрипта или от агента

`gitpoulpi worktree changes <path>` перечисляет незафиксированные изменения
worktree. `gitpoulpi worktree remove <path> [--force] [--commit-message M
[--commit-branch B]] [--stash-message M] [--delete-branch]` удаляет его;
инструменты MCP - `worktree_changes` и `worktree_remove`. См.
[справочник CLI](cli-reference.md).
