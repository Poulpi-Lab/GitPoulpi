# Документація користувача GitPoulpi

<p align="center"><img src="../../../assets/logo/gitpoulpi-512.png" alt="Восьминіг GitPoulpi" width="128"></p>

GitPoulpi - це клієнт Git для термінала з графом commit'ів, по якому можна клацати,
палітрою команд, інтеграцією з хостингами та трекерами issues, необов'язковою
ШІ-допомогою, а також CLI і сервером MCP, які роблять усе, що й інтерфейс.
Сторінки розташовано в порядку читання: почніть згори й переходьте до
довідкових сторінок, коли вони потрібні.

![Головне вікно GitPoulpi](../images/hero.png)

## З чого почати

1. **[Встановлення](installation.md)**: що потрібно, архіви релізів,
   менеджери пакунків, збірка з вихідного коду. Менший виконуваний файл
   дивіться в розділі **[Власні збірки](custom-builds.md)**. Як GitPoulpi
   підтримує себе актуальним (чип версії, панель оновлення, повернення):
   **[Оновлення](updates.md)**. Щоб запустити його в контейнері:
   **[Запуск у Docker](docker.md)**. Для адміністраторів, внутрішніх стрічок,
   дзеркал і політики оновлення:
   **[Корпоративне розповсюдження](enterprise-distribution.md)**.
2. **[Початок роботи](getting-started.md)**: ваші перші п'ять хвилин, від
   запуску до першого commit'у.
3. **[Огляд інтерфейсу](interface-tour.md)**: назва кожної ділянки вікна, з
   малюнками.

## Знайти функцію

| Я хочу... | Сторінка | Як дістатися в застосунку |
|---|---|---|
| Працювати над двома гілками одночасно | [Worktrees](worktrees.md) | Розділ **WORKTREES** бічної панелі Refs (`+` створює; сховано, доки не з'явиться перший: палітра **Ліва панель: показати розділ Worktrees**); палітра **Refs: створити worktree...** |
| Працювати з вкладеними репозиторіями | [Підмодулі](submodules.md) | Розділ **SUBMODULES** бічної панелі Refs; палітра **Git: оновити всі підмодулі**, **Refs: оновити підмодуль (вибраний)** |
| Вирішити конфлікт merge | [Вирішення конфліктів merge](merge-conflicts.md) | `Enter` на рядку з `!` панелі Status, кнопка банера **Вирішити конфлікти...** або `Shift+E` у поданні Diff; палітра **Конфлікти: відкрити редактор merge** |
| Переглянути pull або merge request | [Рев'ю pull або merge request](review.md) | `Enter` на рядку розділу **PULL REQUESTS**, `e` на рядку Radar, `Alt+R` у пошуку по робочому простору; палітра **Хостинг: рев'ю запиту...** |
| Переглядати, створювати й вести pull requests та issues | [Pull requests та issues](pull-requests-and-issues.md) | Розділи **PULL REQUESTS** і **ISSUES** бічної панелі Refs (`n` створює); палітра **Pull requests: створити pull request...**, **Хостинг: нове issue...**. Спершу підключіть обліковий запис: [Хостинги й трекери issues](hosting-integration.md) |
| Читати й відповідати в обговоренні issue чи запиту | [Бесіди](conversations.md) | `Enter` на рядку issue, картці дошки чи рядку Radar; палітра **Хостинг: відкрити бесіду issue...** |
| Бачити свої issues як дошку | [Дошка issues](pull-requests-and-issues.md#дошка-issues) | Кнопка **Дошка** в заголовку ISSUES; палітра **Issues: відкрити дошку** |
| Вести issues як нотатки Markdown, без токена | [Локальні issues і Obsidian](local-issues.md) | Розділ ISSUES, провайдер `Local Markdown - <назва>`; палітра **Локальні issues: відкрити в Obsidian...** |
| Переписати авторів, дати, повідомлення чи файли в багатьох commit'ах | [Переписування історії](history-rewrite.md) | `Ctrl+G Shift+H`; палітра **Переписування: майстерня історії** |
| Скасувати (або повторити) операцію | [Скасування й повторення](undo-redo.md) | `Ctrl+Z` / `Ctrl+Y`; `Alt+Z` відкриває історію скасувань; палітра **Правка: скасувати** |
| Відстежувати великі файли через Git LFS | [Git LFS](lfs.md) | Палітра **LFS: відстежувати шаблон...**, **LFS: ініціалізувати для цього репозиторію** |
| Знайти гілку, commit, pull request чи issue в усіх репозиторіях | [Пошук](search.md) | `Ctrl+Alt+F` або кнопка Глобального пошуку в рядку заголовка; `f` шукає в графі commit'ів поточного репозиторію |
| Бачити в одному списку все, що потребує моєї уваги | [Radar](radar.md) | `Alt+R`; палітра **Radar: відкрити** |
| Згрупувати репозиторії та робити fetch чи pull разом | [Робочі простори](workspaces.md) | `Alt+W` перемикає, `Alt+J` відкриває вкладку «Робочі простори»; палітра **Робочий простір: керування...** |
| Отримати допомогу ШІ (повідомлення commit'ів, пояснення, описи) | [Допомога ШІ](ai.md) | `Ctrl+,` > **ШІ** > **Увімкнути ШІ**, потім `Ctrl+G i` пише повідомлення commit'у; палітра **ШІ: ...** |
| Знайти будь-яку команду чи клавішу | [Скорочення клавіатури](keybindings.md) | `?` у застосунку перелічує клавіші, `Ctrl+P` знаходить будь-яку команду |

## Щоденна робота

4. **[Робота з Log](log-and-history.md)**: читання графа, пошук,
   гілки, tag'и, stash, перетягування ref, rebase, cherry-pick,
   reword і amend, банери, pull і push, auto-stash.
5. **[Stage і commit'и](staging-and-committing.md)**: робочі зміни,
   diff, індексація hunk і окремих рядків, написання commit'ів, форма commit'у,
   blame, історія файлу та вбудований редактор.
6. **[Зображення](image-view.md)**: зображення в поданні Diff і в Перегляді файлу, до й після,
   масштаб, «Редагувати в».
7. **[Вирішення конфліктів merge](merge-conflicts.md)**: редактор merge (A і B
   поруч над Результатом), вибір рядків і блоків, картки для конфліктів
   двійкових файлів, LFS, видалення, символічних посилань і підмодулів та те,
   як агент пропонує вирішення.
8. **[Worktrees](worktrees.md)**: друга папка з checkout іншої гілки:
   розділ WORKTREES, створення, відкриття, merge і видалення пов'язаних
   worktree.
9. **[Підмодулі](submodules.md)**: розділ SUBMODULES, їх оновлення та
   синхронізація з checkout і pull.
10. **[Скасування й повторення](undo-redo.md)**: `Ctrl+Z` / `Ctrl+Y`, що можна й
    чого не можна скасувати, коли воно відмовляє чи питає, як далеко назад
    сягає, як його вимкнути.
11. **[Git LFS](lfs.md)**: великі файли, відстеження, блокування і що
    відбувається без встановленого `git-lfs`.
12. **[Теми](themes.md)**: вбудовані теми, будь-яка тема з будь-якою палітрою
    ліній, перегляд наживо, ваші власні файли тем, `gitpoulpi theme`.
13. **[Робочі простори](workspaces.md)**: іменовані групи репозиторіїв зі своїми
    вкладками й необов'язковим типовим профілем commit'ів, чип на панелі вкладок,
    вкладка «Робочі простори», Fetch все, Pull все,
    Клонувати відсутні.
14. **[Пошук](search.md)**: єдиний нечіткий пошук (`Ctrl+Alt+F`) по гілках,
    tag'ах, worktrees, stash'ах, commit'ах, запитах на злиття та issues усіх
    репозиторіїв робочого простору чи відкритих вкладок.
15. **[Radar](radar.md)**: запити на злиття, issues і робота в процесі
    робочого простору (або ваших відкритих вкладок) в одному списку: фільтри,
    закріплення, відкладання і що вміє кожен рядок.
16. **[Pull requests та issues](pull-requests-and-issues.md)**: розділи PULL
    REQUESTS і ISSUES бічної панелі, дошка issues, створення pull request чи
    issue, чип на панелі інструментів, посилання в повідомленнях commit'ів.
17. **[Бесіди](conversations.md)**: читання й відповіді в обговоренні issue чи
    запиту у вікні, публікація від імені, чого не вміє кожен хостинг.
18. **[Рев'ю pull або merge request](review.md)**: подання рев'ю з обговореннями
    коду, незавершеним рев'ю та Схвалити / Вимагати змін.
19. **[Відкрити в](open-in.md)**: список у рядку заголовка, що відкриває папку
    активної вкладки в терміналі, мультиплексорі, редакторі чи файловому
    менеджері.
20. **[Стеження за папкою активної вкладки](following-the-tab-folder.md)**:
    «Вийти й cd сюди» та обгортка `gitpoulpi shell-init` (`gp`) для bash,
    zsh, fish і PowerShell.
    Який термінал найкраще показує GitPoulpi: **[Вибір термінала](terminals.md)**.
    Що проходить через tmux, zellij, screen, herdr і панелі терміналів:
    **[Мультиплексори](multiplexers.md)**.

Також: **[Кілька remote для однієї гілки](multiple-remotes.md)**: цілі push і джерела
pull, діалог Remote, Push на всі або вибрані remote, розбір remote, що пішов уперед,
«Продовжити» після конфлікту, CLI і псевдонім на звичайному git.

**[Робочі процеси гілок](branching-workflows.md)**: шаблони Git Flow, GitHub
Flow, GitLab Flow і Trunk-based або ваші власні базові гілки, шаблони назв гілок і
типи гілок (`gitpoulpi flow ...`).

**[Переписування історії](history-rewrite.md)**: майстерня (`Ctrl+G Shift+H`), яка
переписує авторів, дати, повідомлення та вміст файлів у багатьох commit'ах, з переглядом,
скриптами Lua і одним скасуванням.

## Знімки екрана

Кожне зображення на цих сторінках - справжній знімок релізної збірки на
невеликому демонстраційному репозиторії з вигаданими авторами. Зображення
лежать у [`images/`](../images/). `scripts/docs-screenshots.sh` збирає
демонстраційні репозиторії та робить знімки заново. Знімки зроблено в
терміналі `kitty`, який малює граф commit'ів і аватари авторів як зображення.
Термінали без графічного протоколу показують натомість символьний граф.
