# Допомога ШІ

GitPoulpi ніколи не потребує облікового запису, а **ШІ типово вимкнено**. Коли ШІ
увімкнено, він може писати повідомлення commit'ів і stash'ів, пояснювати зміни,
писати описи pull request'ів, пропонувати вирішення конфліктів merge і розбивати
ваші робочі зміни на кілька commit'ів. Модель ваша: ключ API, що належить вам, локальний
сервер або вже встановлений CLI-агент (наприклад `claude -p`).

Кожен елемент керування ШІ має фіолетовий `✦`. Поки ШІ вимкнено:

- Нічого нікуди не надсилається.
- Жодного елемента ШІ не показано: ні кнопки `✦`, ні команди палітри `ШІ:`, ні
  пункту меню ШІ, ні підказки клавіш ШІ. Клавіші ШІ нічого не роблять.
- Сторінка ШІ репозиторію показує лише «ШІ вимкнено (Налаштування > ШІ)».
- Сервер MCP не перелічує інструменти `ai_*`. Команди CLI `gitpoulpi ai ...`
  відмовляють із тим самим повідомленням.

**Увімкнути ШІ** діє одразу. Перезапускати не потрібно.

Є два способи користуватися ШІ з GitPoulpi:

| | Вбудований ШІ (ця сторінка) | Зовнішній агент |
|---|---|---|
| Що це | GitPoulpi просить модель про повідомлення commit'у, пояснення, ... | Claude Code, Cursor, Codex... керують GitPoulpi як інструментом |
| Налаштовується в | Налаштування > ШІ (`[ai]`) | конфігурації MCP агента, обмеження в `[mcp]` |
| Посібник | нижче | [MCP та агенти](mcp-and-agents.md) |

## Налаштування ШІ

1. `Ctrl+,` > **ШІ** > позначте **Увімкнути ШІ**.
2. Профілі - це список вкладки **Профілі (підключення)**, ліворуч на сторінці (на
   вузькому терміналі він стоїть зверху): виберіть профіль, щоб змінити його праворуч (`Enter` переходить до
   його рядків; команда палітри **ШІ: змінити профіль...** веде до списку).
   **+ Додати** створює ще один, **Дублювати** копіює вибраний (без його ключа),
   а **Видалити** спершу питає. Виберіть **Провайдер** і заповніть його поля:

   | Провайдер | Поля | Типові значення |
   |---|---|---|
   | **Локальний агент** (без ключа, без власного облікового запису) | **Тип агента** (що це за агент), **Команда** (точна програма: у вашому `PATH`, псевдонім чи скрипт-обгортка, або повний шлях), **Аргументи**, що роблять його неінтерактивним, і необов'язкові **змінні середовища**. Запит надходить на його stdin, відповідь читається зі stdout. | Claude Code: `claude`, `-p --model haiku` |
   | **Anthropic** | **Ключ API**, необов'язково **Модель** і **Базовий URL** | `claude-sonnet-5`, `https://api.anthropic.com/v1` |
   | **OpenAI** | **Ключ API**, Модель, Базовий URL | `gpt-5`, `https://api.openai.com/v1` |
   | **OpenRouter** | **Ключ API**, Модель, Базовий URL | `openai/gpt-5`, `https://openrouter.ai/api/v1` |
   | **Сумісний з OpenAI** (Ollama, LM Studio, vLLM, корпоративний шлюз) | **Базовий URL** (`.../v1`), **Модель**, необов'язковий ключ | `http://localhost:11434/v1` (Ollama; LM Studio - `http://localhost:1234/v1`), `llama3` |

   **Пресети** (завжди можна ввести інше значення):

   ![Випадаючий список «Тип агента» профілю локального агента: Claude Code, OpenAI Codex CLI, Gemini CLI, opencode та інші CLI-агенти](../images/settings-ai-presets.png)

   - **Локальний агент > Тип агента** - випадаючий список поширених CLI-агентів,
     найуживаніші першими: Claude Code, OpenAI Codex CLI, Gemini CLI, opencode,
     Cursor Agent, GitHub Copilot CLI, Pi, Qwen Code, Aider, Goose, Crush, Amp, або
     *Інший (без підказок)*. Тип **окремий від команди**: він лише визначає, які
     підказки ви отримаєте. Вибір типу заповнює **Команду** (поки вона ще є типовою
     для попереднього типу) та **Аргументи** headless-викликом (`claude -p`,
     `codex exec -`, `gemini -p ...`, ...). **Команда** - вільний текст: напишіть
     `/opt/bin/work-claude`, скрипт-обгортку чи ціль псевдоніма, і тип разом зі своїми
     параметрами, переліком моделей і змінними залишиться. Коли **Тип агента** порожній,
     GitPoulpi визначає його за командою.
   - **Параметри аргументів** додає або прибирає параметри, що пасують до
     одноразового використання GitPoulpi, кожен з однорядковим поясненням: без
     інструментів, без збереженої сесії, відповідь простим текстом, низький рівень міркувань,
     режим лише читання, без запитів дозволу, без перевірки оновлень і статистики.
     Перелік різниться для кожного агента, бо агенти різні (лише деякі можуть вимкнути
     інструменти з командного рядка; для opencode це змінна середовища). **Модель**
     перелічує моделі цього агента й записує правильний прапорець (`--model haiku`
     для Claude Code, `-m gpt-6-luna` для Codex, `--model provider/model` для
     opencode); *(типово - без прапора)* прибирає його. В Amp немає прапорця моделі.
     `aider` читає запит із `/dev/stdin`, тож працює лише на Linux і macOS.
   - **Змінні середовища** задаються лише для процесу цього агента, ніколи для
     GitPoulpi чи інших профілів. **Додати змінну середовища** пропонує задокументовані
     змінні, важливі для цього агента, кожну з описом, що вона робить (вимкнути
     телеметрію й перевірки оновлень, рівень зусиль, папка конфігурації, ключ API,
     base URL чи локальний хост, ...); також можна ввести `NAME` або `NAME=value`.
     Далі кожна змінна має свій рядок **Env NAME**: її значення у вигляді кнопки
     (натисніть її, щоб ввести нове; воно зберігається, коли ви виходите з поля) і
     кнопка **[x]**, що видаляє змінну. Значенням
     може бути `${env:NAME}`, щоб запозичити одну зі змінних самого GitPoulpi (зручно
     для ключів API, щоб вони не потрапляли в `config.toml`). Значення, схожі на
     секрети (імена, що закінчуються на `_KEY`, `_TOKEN`, `_SECRET`, ... або відомі
     префікси ключів), показуються крапками й вводяться з нуля. Значення ніколи не
     записуються в журнал.
   - **HTTP-провайдери > Пресет провайдера** заповнює base URL і модель для OpenAI,
     Anthropic, OpenRouter, Google Gemini, xAI, DeepSeek, Mistral, Groq, Together,
     Fireworks, Cerebras, Perplexity, Moonshot, Qwen (DashScope), Zhipu (GLM) і
     локальних серверів Ollama, LM Studio, llama.cpp, vLLM, Jan та LocalAI.
     **Модель** - випадаючий список моделей цього провайдера, вільний текст дозволено.

3. Натисніть **Перевірити підключення**: *Остання перевірка* показує
   `підключено: модель відповіла` або `помилка: <причина>`.
4. За кількох профілів виберіть **Типовий профіль** унизу; кожна дія все одно може
   назвати свій.

![Блок «Профілі» сторінки ШІ для локального агента: Тип агента (Claude Code), Команда, Аргументи, Модель, два рядки Env, «Додати» і «Видалити змінну середовища», «Перевірити підключення» і «Типовий профіль»](../images/settings-ai-agent.png)

**Ключі API** вводяться через `Enter` на рядку **Ключ API** і зберігаються в
системному сховищі облікових даних (Git Credential Manager, libsecret / `pass`,
Keychain) під `ai:<profile id>`, ніколи в `config.toml`. Без сховища GitPoulpi про це
каже, а не вдає, що тримає ключ. *Налаштування > SSH і облікові дані > Забути всі
імена користувачів і паролі* видаляє їх.

Те саме в `config.toml` (усе інше в [довіднику
конфігурації](config-reference.md#ai-вбудований-ші-типово-вимкнений)):

```toml
[ai]
enabled = true
default_profile = "claude-code"

[[ai.profiles]]
id = "claude-code"
name = "Claude Code"
kind = "local_agent"      # open_ai | anthropic | open_router | open_ai_compatible | local_agent
command = "claude"        # free: an alias, a wrapper script, an absolute path
harness = "claude"        # which agent it is; empty = inferred from `command`
args = ["-p", "--model", "haiku"]

[ai.profiles.env]         # this agent's process only; ${env:NAME} borrows ours
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC = "1"
ANTHROPIC_API_KEY = "${env:ANTHROPIC_API_KEY}"
```

## Режим запуску: headless або віртуальний термінал

Профіль локального агента запускає свого агента одним із двох способів, які
обирає **Режим запуску** (показується для Claude Code, OpenAI Codex CLI і
Gemini CLI):

- **Headless (неінтерактивний)**, типово: одноразовий режим агента
  (`claude -p`), запит у stdin, відповідь у stdout.
- **Інтерактивний (віртуальний термінал)**: GitPoulpi запускає власний екран
  агента в прихованому терміналі, вводить запит так, як це зробила б людина,
  чекає на відповідь і закриває агента. Деякі агенти тарифікують або обмежують
  свій headless-режим інакше, ніж інтерактивний; що з цього стосується вас і
  що умови провайдера кажуть про кожен режим, залежить від провайдера, тож
  перевірте його правила.

Кожен режим має власні **Аргументи**, **Параметри аргументів** і **Модель**:
перемикання режимів нічого не губить, а інтерактивний режим пропонує лише
параметри, що мають сенс без headless-прапорця. Ще два рядки діють в обох
режимах:

- **Робоча папка**: *Окрема папка* - це порожня папка, якою володіє
  GitPoulpi, тож агент не бачить жодного проєкту й один раз просить вас
  довіритися їй. *Поточний репозиторій* дає агентові власний контекст проєкту
  (наприклад, його `CLAUDE.md`), і довіри він просить один раз для кожного
  репозиторію. *Типово* - це окрема папка в інтерактивному режимі, а в
  headless-режимі, як і раніше, папка, у якій працює GitPoulpi.
- **Тайм-аут (секунди)**: скільки часу може тривати робота агента, перш ніж
  GitPoulpi здасться й зупинить його. Порожнє значення означає 120 секунд для
  headless і 180 для інтерактивного режиму.

**На запитання першого запуску відповідаєте ви.** Агент, який ще ніколи не
запускався в папці, спершу про щось питає (довіряти цій папці, увійти в
обліковий запис, вибрати тему). GitPoulpi ніколи не відповідає за вас: запит
зупиняється з повідомленням, а **Відкрити агента...** (на профілі або *ШІ:
відкрити агента* в палітрі команд) один раз відкриває агента у видимому
терміналі, в робочій папці, яку він використовуватиме. Дайте відповідь на
запитання, закрийте агента й повторіть спробу; агент запам'ятовує відповідь.

Відповідь береться з транскрипту сесії агента для Claude Code (його точний
текст, після чого транскрипт видаляється) і з екрана між двома рядками-маркерами,
які просить виводити запит, для Codex і Gemini. Одночасно виконується щонайбільше
два запуски у віртуальному терміналі, а натискання Esc під час запиту зупиняє
агента.

```toml
[[ai.profiles]]
id = "claude-terminal"
kind = "local_agent"
command = "claude"
harness = "claude"
args = ["-p"]                       # the headless set, kept
run_mode = "terminal"               # headless (default) | terminal
terminal_args = ["--effort", "low"] # the interactive set
workdir = "dedicated"               # default | dedicated | repository
timeout_secs = 180                  # 0 or absent: 120 headless, 180 terminal
```

## Інструкції

Текст, який ви додаєте до того, що кажуть моделі. Вбудований запит кожної дії
(що фіксує формат відповіді) завжди йде першим і не редагується; далі
чотири рівні, від найзагальнішого до найконкретнішого, кожен лише коли не
порожній:

1. **Глобальні інструкції** (кожна дія). Чипи *Швидкої вставки* в редакторі
   вставляють поширені речення: *Відповідати мовою `<language>`*, *Стислі відповіді*, *Наказовий спосіб*,
   *Технічний тон*, *Невимушений тон*.
2. **Інструкції робочого простору** (кожна дія, кожен репозиторій
   [робочого простору](workspaces.md#інструкції-ші-робочого-простору)): для всіх дій
   і за бажанням для окремої дії. Редагуються у формі зміни робочого простору.
3. **Інструкції репозиторію** (кожна дія, лише цей репозиторій), з
   *Поєднати з глобальними*: **Додати до глобальних** (після них) або **Замінити
   глобальні** (замість них).
4. **Інструкції дії** (*Генерація повідомлення commit'у*, *Пояснення змін*,
   *Генерація повідомлення stash'у*, *Pull request*, *Композер commit'ів*,
   *Розділення commit'у*, *Вирішення конфліктів*, *Рев'ю коду*), кожен
   блок зі своїми чипами в редакторі (наприклад *Формат conventional commits*, *Ліміт 50
   символів*) і своїм випадаючим списком **Профіль** (`Типовий (<name>)` відповідає
   типовому профілю).

`Enter` на рядку *Власні інструкції* відкриває багаторядковий редактор (`Ctrl+S`
зберігає, `Esc` скасовує). Над текстом рядок *Швидка вставка* містить чипи цього
розділу: клацніть один, щоб вставити його речення в позицію курсора. З клавіатури
`Tab` переходить до рядка, `Left`/`Right` вибирають чип, `Enter` або `Space`
вставляє його й повертає до тексту (`Tab` або `Esc` повертають без вставки). Чип,
чиє речення вже є в інструкціях, затемнений, і повторна вставка нічого не робить.
Текст - повноцінний редактор: клацання ставить курсор, перетягування або
`Shift`+стрілки виділяють, `Ctrl+A` виділяє все, `Ctrl+C` / `Ctrl+X` копіюють і
вирізають виділене, `Ctrl`+стрілки переходять між словами, а `Home` / `End`,
`PageUp` / `PageDown` і колесо миші прокручують довгий текст. Сама сторінка
показує лише попередній перегляд кожної інструкції.

![Сторінка ШІ: глобальні інструкції, потім блоки «Генерація повідомлення commit'у» і «Пояснення змін» із випадаючим списком профілю та власними інструкціями](../images/settings-ai.png)

**Для репозиторію**: *Налаштування > Налаштування репозиторію > ШІ* (поки відкрито
репозиторій) містить інструкції репозиторію та, для кожної дії, профіль
та інструкції, що перевизначають глобальні. Порожнє поле використовує глобальне
налаштування (показане в ньому сірим); **Скинути до глобальних** прибирає
перевизначення. Зберігається в `.gitpoulpi/repo-state.toml` репозиторію, і CLI його теж враховує.

![Сторінка ШІ репозиторію: «Інструкції репозиторію» з випадаючим списком «Поєднати з глобальними», потім профіль та інструкції для кожної дії](../images/settings-repo-ai.png)

### Як рівні поєднуються

Порядок надсилання: вбудований запит, **глобальні**, **робочого простору**, **репозиторію**,
потім власні інструкції дії. Режим рівня вирішує, що станеться з рівнями вище
за нього:

- **Додати** (типово): текст рівня додається після загальніших.
- **Замінити**: текст рівня використовується *замість* кожного загальнішого рівня
  (глобального, а робочого простору - коли замінює репозиторій). Рівень без тексту
  ніколи нічого не замінює.

Власні інструкції дії слідують тій самій ідеї: глобальні для цієї дії,
потім робочого простору для цієї дії (додані після них або замість
них), а власне перевизначення репозиторію для дії перемагає обидва. Використовується
активний робочий простір вікна, коли він містить
репозиторій, інакше перший робочий простір, що його містить; у командному рядку
це той, що в `GITPOULPI_WORKSPACE`, інакше перший.

Щоб побачити, що саме надсилається, рівень за рівнем, виконайте
`gitpoulpi ai prompt --action <action> --repo .` (`base`, `global`, `workspace`,
`repository`, `task` і підсумковий `system_prompt`). Це не викликає модель і
працює з вимкненим ШІ. Задати інструкції робочого простору зі скрипта можна
`gitpoulpi workspace set-ai-instructions <id> [--action <a>] [--mode
append|replace] --text ...` (або `--clear`).

### Змінні запиту

Кожен текст інструкцій (глобальних, робочого простору, репозиторію, дії) може містити змінні
`${name}`. Їх замінюють значенням безпосередньо перед надсиланням запиту (збережений
текст залишає `${...}`). Назва, якої немає в таблиці, надсилається як написано, і
редактор про це попереджає; напишіть `$${`, щоб отримати буквальне `${`.

| Змінна | Розгортається в | Приклад |
|---|---|---|
| `${uilang}` | Мова інтерфейсу, її англійська назва | `French` |
| `${repo}` | Назва папки репозиторію | `gitpoulpi` |
| `${branch}` | Поточна гілка | `main` |
| `${ref}` / `${commit}` | Короткий sha commit'у, якого стосується дія (*Пояснити*), інакше HEAD | `4c0443d` |
| `${commit_subject}` | Тема цього commit'у | `feat: add search` |
| `${date}` | Місцева дата, ISO | `2026-10-03` |
| `${time}` | Місцевий час, `HH:MM` | `14:05` |
| `${datetime}` | Місцеві дата й час | `2026-10-03 14:05` |
| `${user}` / `${email}` | `git config user.name` / `user.email` | `Ada Lovelace` |
| `${remote}` | Типовий віддалений репозиторій (`origin`, інакше перший) | `origin` |
| `${host}` | `github`, `gitlab`, `other` (інший хост) або `none` | `github` |
| `${files}` | Кількість файлів у diff дії | `3` |
| `${action}` | Дія, що виконується | `commit_message` |

У редакторі інструкцій: введіть `${`, і спливне вікно перелічить відповідні змінні
(`Up`/`Down` вибирають, `Enter` або `Tab` вставляє, `Esc` закриває); або скористайтеся
випадаючим списком **Змінні** внизу ліворуч (`Ctrl+T` або *ШІ: вставити змінну запиту* в
палітрі команд), що вставляє в позиції курсора. Кожен запис має опис, який
показується в списку й у рядку над кнопками, поки ви наводите чи підсвічуєте його.

### Вирішення конфліктів merge

Модель отримує шлях і мову файлу, блоки основи, поточного (A) і вхідного (B) боку
конфлікту з підписами, які показує редактор, до 20 рядків уже об'єднаного тексту до та
після нього й ваші інструкції (глобальні, репозиторію та *Вирішення конфліктів* у
Налаштування > ШІ). Вона відповідає вирішеним текстом саме цього конфлікту в блоці
коду; відповідь із маркерами конфлікту чи зайвим текстом замість коду один раз
повертається назад, потім відхиляється. Конфлікт понад приблизно 40 КБ не
надсилається. Елементи керування приховані, поки ШІ вимкнено, а пропозиція ніколи
нічого не зберігає, не додає в індекс і не вирішує: перегляньте Результат,
відредагуйте його й збережіть як зазвичай.

### Композер commit'ів

Модель розбиває робочі зміни на кілька commit'ів (кожен змінений файл рівно в одному;
некоректний план один раз повертається назад, потім відхиляється). Ви переглядаєте
план, перш ніж щось буде закомічено:

![Перегляд композера: чотири запропоновані commit'и з файлами та кнопки «Скинути», «Скасувати» і «Створити 4 commit'и»](../images/composer.png)

| Клавіша | Миша | Дія |
|---|---|---|
| `Up` / `Down` (`k` / `j`) | клацання по рядку | рух по commit'ах і файлах |
| `Alt+Up` / `Alt+Down` (`K` / `J`), `m` | стрілки, перетягування | перемістити commit; перемістити файл в інший commit |
| `Right` / `Left`, `*` | стрілка рядка | розгорнути / згорнути commit, усі разом (`ui.composer_files` задає початковий стан) |
| `e` / `Enter` | олівець | змінити повідомлення |
| `d` / `Delete` | `drop` / `відновити` | не включати commit (його файли залишаються незакомічені) |
| `n` | `+ окремий commit` | перемістити файл в окремий commit |
| `r` | `Скинути` | назад до плану моделі |
| `Ctrl+S` / `a` | `Створити N commit'ів` | створити їх по порядку |
| `Esc` | `Скасувати` | вийти, нічого не зроблено |

Створення додає в індекс файли кожного commit'у й комітить їх по черзі; робоче дерево
ніколи не чіпається. Файл, доданий в індекс лише частково, комітиться цілком. Якщо
якийсь крок не вдається, процес зупиняється й повідомляє, скільки commit'ів
створено.

### Розділення commit'у

Модель читає зміни commit'у, пронумеровані так само, як у [редакторі розділення](log-and-history.md#розділення-commitу), і пропонує кілька commit'ів, кожен із повідомленням; вона вміє групувати hunk'и та окремі рядки. Відповідь, у якій якась зміна пропущена, призначена двічі або названо щось неіснуюче, відхиляється. У будь-якому разі відкривається редактор розділення: із заповненою пропозицією або, якщо модель не впоралася, із причиною в примітці, щоб ви розділили вручну. Нічого не розділяється, доки ви не натиснете **Розділити** (`Ctrl+S`); якщо групування не підходить, спершу перемістіть зміни, перейменуйте commit'и чи додайте ще один. Профіль та інструкції - це налаштування *Розділення commit'у* в Налаштування > ШІ.

### Скрипт переписування історії

Ви описуєте, що має зробити переписування («перенести кожен commit, зроблений уночі, на наступний ранок», «замінити мій старий email на новий, лише до 2024»), а модель пише [скрипт Lua](history-rewrite.md#скрипти-lua) для правила «Скрипт»: із заголовком, `rewrite_commit(c, ctx)` та допоміжними функціями пісочниці. Демон компілює відповідь; якщо вона не компілюється, помилку один раз повертають моделі. Те, що лишилося, показано в редакторі: прочитайте, протестуйте, потім зробіть Перегляд. Подробиці та діалог - у розділі [Переписування історії](history-rewrite.md#написати-скрипт-за-допомогою-ші). Профіль та інструкції - це налаштування *Скрипт переписування історії* в Налаштування > ШІ.

### Правила переписування історії

Ви своїми словами описуєте, як потрібно переписати історію («замінити мою стару адресу a@b.org на c@d.org», «прибрати secrets.txt з усієї історії»), а модель пропонує область, деякі налаштування й список [правил переписування](history-rewrite.md#створити-правила-за-допомогою-ші) у власному словнику майстерні. **Вона лише готує**: відповідь заповнює майстерню, нічого не переглядається й не застосовується, а непридатний пункт показано з причиною, тоді як чинні збережено. Правило «Скрипт» так ніколи не створюється. За бажанням разом ідуть область, назви гілок і tag'ів та автори найновіших commit'ів (прапорець, типово вимкнений, показаний на панелі «що надсилається»). Профіль та інструкції - це налаштування *Правила переписування історії* в Налаштування > ШІ.

## Контекст рев'ю

Чернетка рев'ю коду (`✦` або `hosting review suggest`) читає diff, назву, опис і наявні коментарі запиту.
Їй також можна передати власні угоди проєкту в блоці **Project conventions**, що стоїть перед diff,
а локальний агент може працювати всередині репозиторію. Типові значення такі:

| Налаштування | Типово | Значення |
|---|---|---|
| `run_in_repository` | `profile` | `profile`: вирішує *Робоча папка* профілю ШІ. `yes`: локальний агент запускається в репозиторії для рев'ю, що б не казав профіль. `no`: не там (профіль, заданий на *Репозиторій*, натомість використовує окрему папку). HTTP-профілі не мають робочої папки, тож для них це нічого не змінює. |
| `include_claude_md` | увімк. | Передати моделі `CLAUDE.md` репозиторію. |
| `include_agents_md` | увімк. | Передати моделі `AGENTS.md` репозиторію. |
| `extra_file` | немає | Ще один файл: шлях відносно кореня репозиторію, абсолютний шлях або посилання. |

Вони накладаються так само, як інструкції, і конкретніше перемагає поле за полем: глобальна таблиця `[ai.review]`,
потім власні значення репозиторію (незадане поле успадковується), потім вибір одного запуску.
Репозиторій, який не клоновано, зберігає власні значення за `host/project` у `remote-reviews.toml`, поруч
зі своїми чернетками рев'ю.

Репозиторій також може вимкнути глобальний додатковий файл: його `no_extra_file = true` (прапорець **Без додаткового
файлу** в *Налаштування репозиторію > ШІ*, у діалозі ✦ Параметри рев'ю та прапорець `--no-extra-file` команди
`ai review-context`) означає «жодного додаткового файлу для цього репозиторію», що б не вказував `[ai.review]`.
**Порожнє** поле **Додатковий файл** - це не те саме: воно успадковує глобальний файл. Файл репозиторію і перемикач
виключають один одного (задання одного очищає інший), а якщо вручну відредагований файл містить обидва, перемикач
виграє. Старіший `extra_file = ""` репозиторію, як і раніше, означає «жодного».

Звідки беруться файли:

- `CLAUDE.md`, `AGENTS.md` і відносний додатковий файл читаються з **кореня** репозиторію в гілці,
  на яку націлено запит, ніколи з робочого дерева (воно може бути на іншій гілці чи мати локальні
  правки). З клоном - з базового commit'у запиту; без нього - з API хостингу.
- Абсолютний шлях читається з цієї машини.
- Посилання на файл хостингу коду (GitHub `.../blob/<branch>/<path>`, GitLab `.../-/blob/<branch>/<path>`,
  Gitea і Forgejo `.../src/branch/<branch>/<path>` або raw-посилання) читається через профіль
  інтеграції, чий хост збігається, тож приватний репозиторій працює з токеном, який ви вже дали. Посилання,
  якому не відповідає жоден профіль, або будь-яка інша адреса завантажується анонімно. Назву гілки зі
  слешем неможливо прочитати з посилання: використайте шлях або посилання на гілку без нього.
- Відсутній `CLAUDE.md` чи `AGENTS.md` мовчки пропускається; відсутній додатковий файл повідомляється
  (`context.problems` у JSON CLI).
- Кожен файл обрізається на **8 КБ**, а всі файли разом на **16 КБ**, з помітною
  приміткою `[CLAUDE.md cut: showing ... of ... bytes]` у тому, що читає модель.

Коли локальний агент запускається в репозиторії, запит каже йому, що файли в checkout можуть не збігатися з
head запиту і що diff є визначальним.

У рев'ю `s` відкриває діалог **✦ Параметри рев'ю** із заповненими значеннями: репозиторію поверх
глобальних. Змініть їх лише для цього запуску або позначте *Зберегти як типові для цього репозиторію*, щоб
зберегти (див. [Параметри рев'ю](review.md#параметри-ревю)). Типові значення також можна змінити в *Налаштування > ШІ* (блок *Рев'ю коду*,
чотири рядки) і для окремого репозиторію в *Налаштування репозиторію > ШІ*, де кожен рядок може *використовувати глобальне значення*,
а кнопка *Скинути до глобальних* відкидає власні значення репозиторію; пошук у Налаштуваннях знаходить їх (`Include
AGENTS.md`, `Extra file`). Усе, чого моделі не вдалося передати (відсутній додатковий файл) або що було скорочено, щоб
вміститися, показано на картці чернетки.

З командного рядка:

```sh
gitpoulpi ai review-context                      # the global defaults and what a review gets
gitpoulpi ai review-context --agents-md off      # save a global default
gitpoulpi --repo ~/work/app ai review-context --claude-md off --context-file docs/REVIEW.md
gitpoulpi ai review-context --project github.com/acme/app --context-file https://github.com/acme/rules/blob/main/review.md
gitpoulpi ai review-context --repo ~/work/app --reset   # follow the global defaults again
gitpoulpi hosting review suggest 12 --claude-md off --context-file docs/REVIEW.md --run-in-repo no
```

`ai review-context` не потребує моделі й працює з вимкненим ШІ. `ai prompt --action code_review` друкує
чинний контекст як `review_context`. Ті самі чотири налаштування - це `ai.review.*` у
`config.toml` ([довідник](config-reference.md#ai-вбудований-ші-типово-вимкнений)).

## Приватність

- Нічого не надсилається, доки ви не натиснете кнопку чи не виконаєте команду. Жодного
  фонового ШІ, жодної телеметрії, жодного облікового запису GitPoulpi.
- Що надсилається: запит (спершу вбудований, потім ваші інструкції) і diff, про який
  ви просили, обрізаний приблизно до 60 КБ (із приміткою про це); для pull request
  також теми commit'ів гілки.
- Запит на скрипт переписування історії надсилає вашу вказівку та фіксований контракт скрипту
  (API пісочниці скриптів). Автор, дата й тема до 20 commit'ів ідуть разом із ним
  **лише** якщо ви позначили *Надіслати зразок* у діалозі (типово вимкнено; для CLI потрібен
  `--sample N`). Вміст файлів і значення секретів не надсилаються ніколи.
- Усе це йде лише до профілю, вибраного для цієї дії: на той хост API або на stdin вашої
  команди локального агента (який тоді робить усе, що робить цей агент).
- Ключі API використовує сам процес `gitpoulpi`, і вони ніколи не потрапляють до
  демона, інших клієнтів вікна чи клієнта MCP.
- Згенерований текст ніколи не комітиться, не надсилається й не застосовується сам.

## Усунення несправностей

| Симптом | Що робити |
|---|---|
| Ніде немає `✦` | ШІ вимкнено: *Налаштування > ШІ > Увімкнути ШІ*. |
| `✦` сірий | Нічого не додано в індекс (повідомлення commit'у). |
| *Перевірити підключення*: команду не знайдено | **Команди** локального агента немає в `PATH`, який бачить GitPoulpi: запустіть GitPoulpi там, де працює `claude --version`, або вкажіть повний шлях. |
| Локальний агент зависає або показує інтерактивний екран | У режимі запуску *Headless (неінтерактивний)* додайте його headless-прапорець (`-p` для Claude Code) в **Аргументи** або знову виберіть його **Тип агента**, щоб відновити headless-виклик. Інтерактивний екран - саме для того, щоб був режим запуску *Інтерактивний (віртуальний термінал)*. |
| "Use "Open the agent"..." | Агент поставив запитання першого запуску (довіра до папки, вхід в обліковий запис). Скористайтеся **Відкрити агента...** на профілі, дайте відповідь, закрийте агента й повторіть спробу. |
| Запит через віртуальний термінал завершується за тайм-аутом | Повідомлення закінчується останніми рядками екрана агента: там видно запит дозволу, вхід в обліковий запис або запитання про оновлення. Дайте відповідь через **Відкрити агента...** або збільште **Тайм-аут**. |
| `помилка:` 401 | Неправильний ключ або ключ іншого провайдера: введіть його заново. |
| `помилка:` 404 | Такої **Моделі** там немає: очистіть поле, щоб узяти типову. |
| `помилка:` помилка з'єднання (Ollama, LM Studio) | Сервер не запущено, або **Базовий URL** має неправильний порт чи не має `/v1`. |
| Ключ показує `(не задано)` після введення | Немає сховища облікових даних: налаштуйте його (`git config --global credential.helper ...`) і введіть ключ знову. |
| Неправильна мова чи стиль | Додайте інструкції; чипи «Швидкої вставки» в редакторі роблять це швидко. |
| Композер каже, що план некоректний | Модель пропустила або повторила файл: спробуйте ще раз або візьміть сильнішу модель. |

## Старіші файли конфігурації

Старіший `config.toml` із `[[ai.presets]]` і `[ai.defaults]` усе ще завантажується:

- Типовий пресет кожної дії стає її `[ai.actions.<action>]`
  (`system_prompt` стає `instructions`).
- Кожен старий пресет зберігається в `[[ai.legacy_presets]]`. Налаштування > ШІ показує
  їх під *Старі пресети (до редизайну)*, з *Видалити архів*.
- Старий `[preferences.ai_presets]` репозиторію стає перевизначенням репозиторію.

Вбудований запит тепер завжди йде першим. Якщо старий запит копіював вбудований,
приберіть скопійовану частину й залиште лише те, що хочете додати.
