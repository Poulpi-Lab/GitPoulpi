# Власні збірки

Для тих, кому потрібен менший виконуваний файл: інтерактивний скрипт питає, які
мови, інтеграції з хостингами, теми, кольори логотипа та функції включити, а
потім збирає лише їх з оптимізованим профілем. Звичайна збірка й офіційний
реліз не змінюються (усе ввімкнено).

```
./build-custom.sh                # Linux / macOS (scripts/build-custom.sh)
build-custom                     # Windows, cmd або PowerShell (scripts/build-custom.ps1)
```

Результат потрапляє в `target/custom/`, ніколи не поверх офіційного
`target/dist/`. Скрипт виводить розмір кожного виконуваного файлу та різницю з
`target/dist/`, коли така збірка існує. Він також записує `BUILD-FEATURES.txt`
поруч із виконуваними файлами.

## Що ви вибираєте

| Вибір | Якщо його вимкнути |
|---|---|
| Мови | Лише англійська (збирається завжди) плюс ті, що ви позначите. У списку вибору в Налаштуваннях лише зібрані мови. |
| Теми | GitPoulpi Dark, GitPoulpi Light і Terminal збираються завжди (`system` потребує Dark і Light). Кожну іншу тему вибирають за родиною (`catppuccin`, `gruvbox`, `nightfox`, ...; їх виводить `--list-themes`). Невибрані теми в двійковий файл не компілюються: їх немає в списку Налаштувань і в `gitpoulpi theme list`, а конфігурація з такою темою обробляється як невідома тема, зі звичайним попередженням. |
| Кольори логотипа | Піксельний восьминіг у вікні «Про програму» має 20 колірний варіант (`--list-logo-colors`). Виберіть ті, що компілювати (щонайменше один), типовий (показується першим у «Про програму»; до нього також відкочується збережений `ui.logo_color`, якого не скомпільовано; він має бути серед скомпільованих; офіційний типовий: лавандовий) і колір значка виконуваного файлу Windows (будь-який варіант, типово: типовий колір логотипа). З єдиним варіантом логотип усе ще обертається після клацання, але залишається цього кольору, а список кольорів (`c`, праве клацання) не пропонується. |
| Інтеграції (GitHub, GitLab, Gitea, Forgejo, Azure DevOps, Bitbucket, Gerrit, Jira, Trello, Linear, YouTrack, Redmine) | Без жодної: лише клонування за URL; немає issues, pull/merge requests. |
| ШІ | Немає кнопок ШІ, команд і `ai`-інструментів CLI/MCP. |
| MCP | Немає ретранслятора `gitpoulpi-mcp` і команди `gitpoulpi mcp`. Агентські команди `ui` залишаються. |
| LFS, worktree, підмодулі | Відповідних екранів керування й команд немає; повертається типізована відповідь «not built into this binary». |
| Завантаження аватарів | Лише значки з ініціалами, без звернень до мережі. |
| Перегляд зображень | Файли зображень показують звичайне повідомлення про двійковий файл; **Редагувати в** усе ще працює. |
| Radar | Немає вкладки Radar, `Alt+R` і команди палітри; Radar не відкривається. Потрібна інтеграція (без неї він і так бездіяльний). |
| Mermaid | Немає «Копіювати як Mermaid gitGraph» (меню Log, `Shift+Y`, палітра) і `log --format mermaid` у CLI/MCP. Також немає кнопки **Відкрити діаграму** під блоком `mermaid` у [бесіді](conversations.md) (блок лишається кодом) і рядка палітри *Бесіда: відкрити діаграму запису*. |
| Дошка | Немає вигляду дошки Kanban (кнопка в заголовку ISSUES, палітра) і команди `hosting board`. Потрібна інтеграція. |
| Бесіда | Немає вбудованого подання [бесіди](conversations.md) issue чи запиту: Enter на рядку issue, картці дошки чи рядку Radar відкриває браузер, як і раніше, немає рядка *Відкрити бесіду* чи команд палітри *Бесіда: ...* і немає **Написати зі ШІ** у бесіді (поля введення рев'ю, форми issue і форми pull request зберігають своє). Команди бесіди в CLI та MCP (`hosting issue comments`, `comment`, `comment-edit`, `comment-delete`, `hosting review conversation`) і `ai hosting-reply` лишаються. Потрібна інтеграція. |
| Рев'ю | Сторінка огляду рев'ю - це подання бесіди, тож збірка з Рев'ю містить і подання бесіди, що б не казав рядок *Бесіда*. Немає вбудованого перегляду рев'ю коду (меню рядка, Enter на рядку pull request, палітра, `Review` у Radar) і допомоги ШІ з рев'ю. Команди CLI/MCP `hosting review` лишаються (їх використовують Gerrit і агенти). Потрібна інтеграція. |
| Майстерня історії (розширене переписування історії: автори, дати, повідомлення, вміст) | Немає майстерні переписування історії: жодних команд палітри `Переписування:`, акорду, клавіш чи розділу довідки майстерні, жодних рядків «Переписати історію» в меню Log, жодної кнопки «Змінити історію глибше...» у діалозі Amend, жодних «Створити правила за допомогою ШІ» чи ШІ для скриптів, жодних обмежень скриптів на сторінці налаштувань Sync і жодних блоків ШІ для переписування історії в налаштуваннях ШІ. Команди CLI/MCP `rewrite`, `ai rewrite-script`, `ai rewrite-rules` і `ui propose rewrite` зникають з дерева команд. Ідентичності `.mailmap` (`mailmap`, `log.use_mailmap`) до неї не належать і лишаються. |
| Глобальний пошук | Немає кнопки «Глобальний пошук» у рядку заголовка, `Ctrl+Alt+F`, команди палітри `Пошук: робочий простір...` і команди CLI/MCP `gitpoulpi search`. Рядок пошуку в Log (`ui show search`) - це інша функція, і вона лишається. |
| Робочі простори | Вікно працює з єдиним типовим списком вкладок («Немає робочого простору»): немає чипа робочого простору, вкладки «Робочі простори», `Alt+W` / `Alt+J`, команд палітри `Робочий простір:`, рядків «Додати до робочого простору» у вкладках, команд CLI/MCP `gitpoulpi workspace` і прапорця `--workspace` у `commit` та `search`. Вкладки й сесії працюють як зазвичай. `workspaces.toml`, записаний іншою збіркою, не читається й не змінюється; типовий профіль робочого простору та його інструкції ШІ не застосовуються. Radar і глобальний пошук охоплюють відкриті вкладки. |
| Скрипти переписування (вбудований Lua) | Правила Script під час переписування історії відхиляються типізованою відповіддю «не вбудовано в цей двійковий файл», і Lua не лінкується. Сама майстерня історії лишається (вона має власний вибір). Не має сенсу, з попередженням, якщо майстерню історії вимкнено. |

Ваші файли конфігурації спільні для всіх збірок: налаштування того, що не
зібрано, зберігається й ігнорується.

## Інтерактивно

Скрипт Bash використовує списки `whiptail` або `dialog` (три екрани, потім
підсумок) або нумеровані запити, коли жодного з них немає. Скрипт PowerShell
використовує `Out-GridView`, коли він доступний, інакше запити. Ваш попередній
вибір позначено наперед.

## Неінтерактивно

Будь-який аргумент пропускає запитання й одразу виконує
`cargo run -p xtask -- build-custom`:

```
./build-custom.sh --langs fr,de --integrations github --no-ai --no-mcp
./build-custom.sh --last --dry-run         # previous choices, print the cargo command only
.\build-custom -Langs fr -Integrations none -NoAi -NoLfs -NoWorktree -NoSubmodules
```

| Параметр | Значення |
|---|---|
| `--langs fr,de` / `all` / `en` | Мови, окрім англійської. Коди - це назви файлів локалей (`pt-br`, `zh-cn`...). |
| `--integrations github,gitlab,azure-devops,bitbucket,jira,trello,gitea,linear,youtrack,redmine,gerrit,local-issues` / `all` / `none` | Провайдери: GitHub, GitLab (зокрема self-managed), Azure DevOps (Services і Server), Bitbucket (Cloud і Data Center) (хостинг), Gitea і Forgejo, зокрема Codeberg (`gitea`) (хостинг), Jira, Trello, Linear, YouTrack (Cloud і Server), Redmine (трекери issues), Gerrit Code Review (`gerrit`, лише рев'ю), локальні issues Markdown (`local-issues`, папка чи сховище Obsidian). Кожен із `azure-devops`, `bitbucket`, `gerrit`, `gitea`, `jira`, `linear`, `local-issues`, `redmine`, `trello`, `youtrack` - окрема функція (feature) cargo; розміри в [binary-size](../../developer/binary-size.md). |
| `--themes all` / `none` / `nord,catppuccin` | Родини тем, що компілювати (типово `all`). `--list-themes` виводить родини. |
| `--logo-colors all` / `violet,teal` | Колірні варіанти логотипа, що компілювати (типово `all`, у порядку таблиці, який і є порядком обертання). `--list-logo-colors` виводить їх (`*` = офіційний типовий). |
| `--logo-default teal` | Типовий колірний варіант; має бути серед скомпільованих (типово: лавандовий, інакше перший скомпільований). |
| `--icon-color sun` | Колір значка виконуваного файлу Windows (типово: типовий колір логотипа). |
| `--[no-]ai`, `--[no-]mcp`, `--[no-]lfs`, `--[no-]worktree`, `--[no-]submodules`, `--[no-]avatar-fetch`, `--[no-]image-view`, `--[no-]radar`, `--[no-]mermaid`, `--[no-]board`, `--[no-]review`, `--[no-]conversation` | Кожен типово ввімкнено. |
| `--[no-]history-rewrite` | Майстерня історії (розширене переписування історії: автори, дати, повідомлення, вміст). Типово ввімкнено. |
| `--[no-]global-search` | Глобальний пошук (кнопка в рядку заголовка, `Ctrl+Alt+F`, `gitpoulpi search`). Типово ввімкнено. |
| `--[no-]workspaces` | Робочі простори (іменовані групи репозиторіїв). Типово ввімкнено; вимкнено лишає лише типовий список вкладок. |
| `--[no-]rewrite-scripts` | Вбудований Lua для правил Script під час переписування. Типово ввімкнено; ігнорується з попередженням, якщо майстерню історії вимкнено. |
| `--save <name\|file>` | Зберігає визначений вибір як збережений вибір (назва або шлях до файлу). |
| `--preset <name\|file>` | Починає зі збереженого вибору (назва або шлях до файлу); інші параметри перевизначають його, де б вони не стояли в рядку. |
| `--list-presets`, `--delete-preset <name>` | Виводить збережені вибори та їхню теку / видаляє один за назвою. |
| `--last` | Повторно використати `target/custom-build/last-choices.env`; інші параметри його перевизначають. |
| `--full` | Без вибору взагалі (усе ввімкнено). |
| `--profile custom\|dist\|release` | Типово `custom` (параметри `dist`, окрема папка результату). |
| `--dry-run` | Вивести точну команду cargo й зупинитися. |
| `-- <cargo args>` | Передаються cargo, наприклад `--target x86_64-unknown-linux-musl`. |

Назви в PowerShell: `-Langs -Integrations -Themes -LogoColors -LogoDefault -IconColor -NoAi -NoMcp -NoLfs -NoWorktree
-NoSubmodules -NoAvatarFetch -NoImageView -NoRadar -NoMermaid -NoBoard -NoReview -NoHistoryRewrite -NoGlobalSearch -NoWorkspaces -NoRewriteScripts -Last -Preset -Save -ListPresets -DeletePreset -Full -DryRun -Profile -CargoArgs`.

Вибір тем потрапляє в збірку через змінну середовища `GITPOULPI_THEMES`
(`all`, `none` або список родин через кому), яку читає скрипт збірки
`gitpoulpi-config` і відкидає інші палітри під час компіляції; задайте її самі
для звичайного `cargo build`, якщо вважаєте за краще. `gitpoulpi --version` виводить рядок
`themes:` зі зібраним набором.

Вибір логотипа - це змінні середовища `GITPOULPI_LOGO_COLORS` (`all` або
список slug'ів через кому), `GITPOULPI_LOGO_DEFAULT` і `GITPOULPI_ICON_COLOR`,
які читають скрипти збірки `gitpoulpi-tui` (він фільтрує
`crates/gitpoulpi-logo-build/colourways.json` у таблицю, що її вбудовує вікно «Про програму») і
`gitpoulpi-cli` (значок). Джерелом кольорів залишається
`crates/gitpoulpi-logo-build/colourways.json`.

### Значок виконуваного файлу Windows

Коли цільова платформа - Windows, виконуваний файл `gitpoulpi`
отримує восьминога як значок, згенерований
під час збірки (Python чи ImageMagick не потрібні) обраним кольором значка, у
розмірах від 16 до 128 px. Він вбудовується крейтом `winresource` і потребує
компілятора ресурсів платформи (`rc.exe` із Windows SDK для MSVC, `windres` для
GNU). Якщо його немає, збірка лише виводить попередження, а виконуваний файл
залишає типовий значок. У тулчейні GNU значок має лише `gitpoulpi` (інакше ресурс
злінкувався б двічі). Збірки для Linux і macOS усе це ігнорують, окрім таблиці
кольорів.

## Збережені вибори

Щоб зібрати нову версію, не повторюючи весь вибір заново, збережіть його під назвою й пізніше почніть з нього. Параметри, указані разом із `--preset`, як і раніше, перевизначають збережені значення.

```
./build-custom.sh --no-ai --no-rewrite-scripts --save no-ai    # keep these choices as "no-ai"
./build-custom.sh --preset no-ai --dry-run                     # start from them later
./build-custom.sh --preset ~/dotfiles/gitpoulpi.env --langs fr # a file path works too
./build-custom.sh --list-presets
./build-custom.sh --delete-preset no-ai
.\build-custom -Preset no-ai -Save no-ai-v2                    # PowerShell
```

Збережені вибори - це звичайні файли `KEY=value` (формат `last-choices.env`, який читає оболонка). Вони лежать у теці `custom-builds` каталогу конфігурації GitPoulpi, поза `target/`, тому `cargo clean` їх не видаляє:

- Linux: `$XDG_CONFIG_HOME/gitpoulpi/custom-builds/` (`~/.config/gitpoulpi/custom-builds/` типово)
- Windows: `%APPDATA%\GitPoulpi\config\custom-builds\`
- macOS: `~/Library/Application Support/GitPoulpi/custom-builds/`

`GITPOULPI_CONFIG_DIR` переносить цю теку разом із конфігурацією. `--preset` і `--save` приймають також шлях до файлу (значення з `/` або `\` чи таке, що закінчується на `.env`), щоб зберігати вибір у репозиторії dotfiles.

Вибір, записаний іншою версією GitPoulpi, усе одно завантажується. Невідомий ключ, а також мова, інтеграція, тема чи колір, яких більше немає, ігноруються з попередженням. Ключ, якого немає у файлі (функція, додана пізніше), отримує типове значення, а пізніше додана інтеграція включається; про обидва випадки повідомляється у стандартний потік помилок.

Якщо є збережений вибір, інтерактивний режим спершу пропонує «Почати з» (попередні вибори, збережений вибір або все ввімкнено), а наприкінці питає, чи зберегти поточний вибір під назвою.

## Примітки

- Власна збірка повільна, як і будь-яка збірка `dist` (thin LTO, кілька хвилин).
- Вона працює без sccache, як `build-opti`.
- Коди мов перевіряються за вбудованими локалями; невідомий код відхиляється
  разом зі списком коректних.
