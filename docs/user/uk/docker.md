# Запуск у Docker

Образ `poulpilab/gitpoulpi` містить офіційні виконувані файли випуску (`gitpoulpi`, а також ретранслятори `gitpoulpi-tui` і `gitpoulpi-mcp`) на `debian:bookworm-slim`, із `git`, `git-lfs`, `openssh-client`, `less` і `tini`. Він працює на `linux/amd64` і `linux/arm64`. Він є на Docker Hub.

## Запуск інтерфейсу

```
docker run -it --rm \
  --user "$(id -u):$(id -g)" \
  -v "$PWD":/work \
  -v gitpoulpi-config:/config \
  poulpilab/gitpoulpi
```

- `-it` дає інтерфейсу термінал. Без нього програмі нема на чому малювати.
- `-v "$PWD":/work` монтує поточну теку як робочу (`/work`). Відкрийте звідти репозиторій або змонтуйте кілька репозиторіїв у `/work`.
- `-v gitpoulpi-config:/config` - іменований том, що зберігає ваші налаштування й сеанси між запусками.
- `--user "$(id -u):$(id -g)"` запускає від вашого імені, тож файли, які GitPoulpi створює у ваших репозиторіях, зберігають власника на хості замість `root`. Кожна тека, у яку пише образ, доступна для запису всім, тож працює будь-який id користувача.

## Томи та шляхи

| Шлях | Що містить |
|---|---|
| `/work` | Робоча тека. Змонтуйте сюди свої репозиторії (bind mount). |
| `/config` | Налаштування (`config.toml`, `tui.toml`), сеанси та, як підтеки, дані й кеш (`GITPOULPI_CONFIG_DIR=/config`). Використовуйте іменований том або bind mount, щоб їх зберегти. |
| `/data`, `/cache` | Також оголошені як томи, для інструментів, що слідують змінним XDG (`XDG_DATA_HOME=/data`, `XDG_CACHE_HOME=/cache`). |
| `/home/gitpoulpi` | `HOME`. Це не том: свіжий для кожного контейнера. |

Без тому для `/config` кожен запуск із `--rm` починається з типових налаштувань. Щоб почати зі свого `config.toml`, змонтуйте його: `-v "$PWD/config.toml":/config/config.toml:ro` (лише для читання означає, що Налаштування не можуть зберегтися). Налаштування інтерфейсу лежать у другому файлі, `tui.toml`, який монтується так само (`-v "$PWD/tui.toml":/config/tui.toml:ro`); див. [Довідник конфігурації](config-reference.md#два-файли-configtoml-і-tuitoml).

## Репозиторії, що належать іншому користувачеві

Git відмовляється працювати з репозиторієм, власник якого відрізняється від користувача, що його запускає («dubious ownership»). З `--user`, як вище, власник збігається. Коли не збігається (bind mount з іншого облікового запису, спільна тека Docker Desktop), довіряйте всім каталогам так:

```
docker run -it --rm -e GITPOULPI_SAFE_DIRECTORY='*' -v "$PWD":/work poulpilab/gitpoulpi
```

Тоді точка входу виконує `git config --global --add safe.directory '*'`, перш ніж запустити інтерфейс. Використовуйте це лише для тек, яким довіряєте, бо це знімає захист git для всього контейнера.

## SSH

Прокидайте свій агент SSH замість копіювання ключів у контейнер.

Linux:

```
docker run -it --rm \
  -v "$SSH_AUTH_SOCK":/ssh-agent -e SSH_AUTH_SOCK=/ssh-agent \
  -v "$PWD":/work poulpilab/gitpoulpi
```

Docker Desktop (macOS, Windows) показує агент хоста за фіксованим шляхом усередині своєї VM:

```
docker run -it --rm \
  -v /run/host-services/ssh-auth.sock:/ssh-agent -e SSH_AUTH_SOCK=/ssh-agent \
  -v "$PWD":/work poulpilab/gitpoulpi
```

З `--user` сокет має бути доступний для читання вашому id користувача, а так і є, коли він належить вам. У контейнері немає `known_hosts`: перше підключення до хоста просить прийняти його ключ, або змонтуйте власний файл через `-v ~/.ssh/known_hosts:/home/gitpoulpi/.ssh/known_hosts:ro`.

## Особа Git і облікові дані

- **Особа й налаштування:** змонтуйте свою конфігурацію Git лише для читання: `-v ~/.gitconfig:/home/gitpoulpi/.gitconfig:ro`. Або задайте особу commit'ів у профілі GitPoulpi (Налаштування > Профілі), що живе в `/config`.
- **Облікові дані HTTPS:** в образі немає помічника облікових даних на кшталт сховища ключів. Або змонтуйте сховище облікових даних (`-v ~/.git-credentials:/home/gitpoulpi/.git-credentials:ro`, з `credential.helper = store` у змонтованому `.gitconfig`), або використовуйте віддалений репозиторій SSH із прокинутим агентом.
- **Токени хостингів** (pull requests, issues): без помічника облікових даних GitPoulpi тримає токен лише в пам'яті на час сеансу. Для тривалого налаштування передайте його через середовище `-e GITPOULPI_TOKEN_<ID>=...`, де `<ID>` - id інтеграції великими літерами, з не буквено-цифровими символами як `_` (див. [Хостинги й трекери issues](hosting-integration.md)). Самі інтеграції лежать у `config.toml` у `/config`.

## Термінал, кольори й миша

Кольори й підтримка миші походять від вашого емулятора терміналу. Docker передає `TERM` далі з `-t`; додайте `-e TERM -e COLORTERM`, коли кольори чи тема true-color виглядають неправильно, наприклад `-e COLORTERM=truecolor`. Клацання миші, перетягування й колесо надходять через термінал як звичайно. Граф commit'ів малюється символами; зображення (kitty, iTerm2, sixel) передаються не через кожен термінал і мультиплексор, див. [Вибір термінала](terminals.md). Зміна розміру вікна терміналу змінює розмір інтерфейсу: контейнер отримує зміну розміру.

## CLI і MCP

Точка входу запускає інтерфейс. До інших програм можна дістатися, перевизначивши її:

```
# CLI для скриптів (додайте --json для скриптів)
docker run --rm --entrypoint gitpoulpi -v "$PWD":/work poulpilab/gitpoulpi status

# сервер MCP через стандартні ввід і вивід, для агента, що його запускає
docker run -i --rm --entrypoint gitpoulpi -v "$PWD":/work poulpilab/gitpoulpi mcp serve
```

Кожен `docker run` - це окремий контейнер із власним фоновим демоном GitPoulpi, тож зміни, зроблені через CLI, не з'являються наживо в інтерфейсі, що працює в іншому контейнері. Щоб керувати одним інтерфейсом із CLI, запустіть обидва в одному контейнері: запустіть інтерфейс з `--name gp` і використовуйте `docker exec gp gitpoulpi ...`. Для агента зареєструйте `docker run -i --rm --entrypoint gitpoulpi ... mcp serve` як команду сервера MCP, див. [MCP та агенти](mcp-and-agents.md); перемикачі дозволів MCP у змонтованому `config.toml` діють як завжди.

## Теги й оновлення

| Тег | Значення |
|---|---|
| `X.Y.Z` | Один точний випуск. |
| `X.Y` | Останній патч цієї мінорної версії (лише стабільні випуски). |
| `latest` | Останній стабільний випуск. |

Попередній випуск отримує лише свій точний тег `X.Y.Z-...`.

Образ замінюється, а не оновлюється на місці. GitPoulpi усередині контейнера це знає (його запис про встановлення каже «образ Docker»): [панель оновлення](updates.md) показує версію й команди й нічого не замінює. Щоб оновити:

```
docker pull poulpilab/gitpoulpi
```

Потім запустіть новий контейнер. Ваші налаштування лишаються в томі `/config`. Щоб повернутися, запустіть старіший тег: `docker pull poulpilab/gitpoulpi:<previous>`. Щоб закріпити версію в скриптах, використовуйте точний тег замість `latest`. Організація може дзеркалити образ у власному реєстрі, див. [Корпоративне розповсюдження](enterprise-distribution.md#дзеркало-реєстру-docker).
