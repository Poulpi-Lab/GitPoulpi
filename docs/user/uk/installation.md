# Встановлення

GitPoulpi має три виконувані файли:

| Виконуваний файл | Що це |
|---|---|
| `gitpoulpi-tui` | Інтерфейс користувача в терміналі. |
| `gitpoulpi` | Інтерфейс командного рядка (`--json` для скриптів). Без підкоманди відкриває інтерфейс. |
| `gitpoulpi-mcp` | Сервер MCP для ШІ-агентів. Див. [MCP та агенти](mcp-and-agents.md). |

Поряд із ними в архіві лежить `gitpoulpi-launch`, крихітна програма, яку запускають ярлики, щоб показати вже відкрите вікно GitPoulpi (`gitpoulpi launch`). У Windows вона не має вікна консолі, тож клацання ніколи не викликає його блимання. Вона встановлюється, оновлюється й видаляється разом з іншими.

## Що вам потрібно

- **Системний `git`** у вашому `PATH`. GitPoulpi використовує libgit2 для
  більшості операцій, а ваш `git` - для решти.
  Потрібна версія **2.34 або новіша**. У macOS підходить `git` з Apple Command Line Tools, а також з Homebrew.
- **Термінал** з підтримкою миші. kitty, Ghostty, WezTerm і iTerm2 (а також Windows Terminal і foot через sixel) малюють граф
  commit'ів як зображення. Інші термінали (консоль Windows, tmux і
  більшість решти) показують символьний граф. Див.
  [Вибір термінала](terminals.md).
- **Nerd Font** або шрифт з емодзі для значків на панелі інструментів і в
  бічній панелі.
- За бажання: **`git-lfs`** 3.0 чи новіший для репозиторіїв Git LFS. Без нього
  файли LFS показуються як маленькі файли-вказівники, а GitPoulpi пояснює
  чому. Як його встановити, див. [Git LFS](lfs.md).
- За бажання: **credential helper** (Git Credential Manager, libsecret, `pass`,
  Keychain) для зберігання токенів хостингів і API-ключів ШІ. Див.
  [Хостинги й трекери issues](hosting-integration.md).

## З архіву релізу

Архів релізу - це `gitpoulpi-<version>-<target>.zip` (Windows) або `.tar.gz`
(Linux, macOS), з файлом `.sha256` поруч. Звірте архів із файлом `.sha256`,
розпакуйте його й покладіть три виконувані файли в папку з вашого `PATH`.
`INSTALL.txt` в архіві дає ті самі кроки.

## З інсталятором

До кожного випуску додано інсталятор для кожної ОС. Обидва роблять однакові вибори
(ярлики, PATH, псевдонім команди на кшталт `gp`), викликаючи сам встановлений
`gitpoulpi` - той самий код, що стоїть за Налаштування > Загальні > Лаунчер, тож те,
що налаштував інсталятор, і те, що показують Налаштування, завжди збігаються.

### Windows: `gitpoulpi-<version>-x86_64-pc-windows-msvc-setup.exe`

Він встановлює для поточного користувача, без запиту прав адміністратора, в
`%LOCALAPPDATA%\Programs\GitPoulpi` (перший діалог пропонує встановлення для всіх
користувачів і вибір папки). Прапорці: ярлик у меню «Пуск», ярлик на робочому столі,
додавання до PATH. Окрема сторінка питає **псевдонім команди**: типово `gp`, можна
будь-яке ім'я, порожньо - без псевдоніма. У PowerShell `gp` уже означає
`Get-ItemProperty`, тож там оберіть інше ім'я або користуйтеся `gitpoulpi`.

Інсталятор копіює три виконувані файли та маркер `.gitpoulpi-dist`, тому
[«Оновити зараз»](#оновлення-на-місці) працює так само, як для zip. Встановлення для
одного користувача доступне для запису, тож може оновлювати себе саме; встановлення
для всіх користувачів у Program Files потребує підвищення прав для заміни, тому
перевстановіть його новим setup. Видалення - у Параметри Windows > Застосунки: воно
запускає `gitpoulpi uninstall` (псевдонім, записи PATH, ярлики) і видаляє файли, зокрема
залишки `.old` від оновлення. Ваші налаштування й репозиторії лишаються.

### Linux і macOS: `install.sh`

```
curl -fsSL https://github.com/Poulpi-Lab/GitPoulpi/releases/latest/download/install.sh | sh
```

Скрипт вибирає архів для вашої ОС і процесора, перевіряє його `.sha256`, встановлює в
`~/.local/opt/gitpoulpi` і лінкує `gitpoulpi` та `gitpoulpi-mcp` у `~/.local/bin`.
Права root не потрібні, і нічого поза вашою домашньою папкою не чіпається. Без `--yes`
він питає про псевдонім (типово `gp`), PATH і ярлики.

| Прапорець | Дія |
|---|---|
| `--prefix DIR` | Встановити файли програми в `DIR` (абсолютний шлях). |
| `--version X.Y.Z` | Встановити цей випуск замість останнього. |
| `--archive FILE` | Взяти локальний архів; поруч має лежати `FILE.sha256` (`--no-verify` пропускає перевірку). Мережа не використовується. |
| `--alias NAME` / `--no-alias` | Зробити так, щоб `NAME` запускало GitPoulpi (`gitpoulpi alias create`), або без псевдоніма. |
| `--no-path` | Не додавати GitPoulpi до PATH нових оболонок (інакше викликається `gitpoulpi path add`). |
| `--desktop` | Також створити ярлики в меню застосунків і на робочому столі. |
| `--yes` | Нічого не питати: діють прапорці та типові значення (псевдонім `gp`, PATH - так, ярлики - ні). |
| `--uninstall` | Виконати `gitpoulpi uninstall`, потім прибрати посилання й папку. |

Пошук останнього випуску вимагає, щоб репозиторій був публічним; для приватного
завантажте архів у браузері й скористайтеся `--archive`.

## З вихідного коду

Потрібен свіжий стабільний тулчейн Rust (<https://rustup.rs>).

```
git clone https://github.com/Poulpi-Lab/GitPoulpi.git
cd GitPoulpi
cargo build --release
```

Виконувані файли лежать у `target/release/`. Профіль `release` збирається
швидко. Для найменших і найшвидших виконуваних файлів використайте профіль
`dist`. Він збирається довше:

```
cargo build --profile dist
```

Скрипти `build-opti` у корені репозиторію виконують цю збірку для трьох
виконуваних файлів і виводять їхні розміри:

```
./build-opti.sh                  # Linux, macOS
build-opti                       # Windows (cmd or PowerShell)
```

Щоб зібрати лише потрібні вам мови та функції, див.
[Власні збірки](custom-builds.md).

## Власноручна збірка архіву релізу

```
cargo run -p xtask -- dist
```

Це збирає профіль `dist` і записує
`target/dist/gitpoulpi-<version>-<target>.zip` (Windows) або `.tar.gz` (інші
системи). В архіві три виконувані файли, `INSTALL.txt`, `README.md`, `LICENSE`
і `CHANGELOG.md`. Поруч записується файл `.sha256`.

## Оновлення

Рядок заголовка показує запущену версію (`v1.0.0`) між назвою застосунку та шляхом до репозиторію.
Клацніть по ній або виконайте в палітрі команд (`Ctrl+P`) **Довідка: нотатки до випуску**:
відкриється вкладка «Нотатки до випуску» зі списком змін, прокрученим до запущеної версії.

Раз на день у фоні GitPoulpi питає GitHub, чи є новіший випуск (`updates.mode`,
[Налаштування > Синхронізація](settings.md#синхронізація)). Коли є, чип набуває вигляду
`доступна v0.2.0` акцентним кольором, а клацання по ньому відкриває вкладку «Нотатки до випуску»
з нотатками цього випуску вгорі. На вкладці три кнопки, кожна з клавішею та командою палітри:

- **Завантажити** (`d`, *Оновлення: завантажити*) відкриває сторінку випуску в браузері.
- **Пропустити цю версію** (`s`, *Оновлення: пропустити цю версію*) ховає сповіщення,
  доки не з'явиться новіший випуск.
- **Перевірити зараз** (`r`, *Оновлення: перевірити зараз*) питає знову одразу.

`updates.mode = "off"` не робить жодного запиту. Без мережі, а також поки репозиторій
приватний і токена github.com не збережено, перевірка тихо не вдається (один рядок у
журналі застосунку, в інтерфейсі нічого). `GITPOULPI_UPDATE_API` спрямовує перевірку
на інший корінь API (його використовують тести).

### Оновлення на місці

Збірка, встановлена з архіву випуску, може замінити себе сама. Архів містить невеликий
файл `.gitpoulpi-dist` поруч із виконуваними файлами; запущена збірка «оновлювана»
лише тоді, коли цей файл лежить поруч із її виконуваним файлом (і називає її платформу).
Збірка від `cargo`, власна збірка, скопійована деінде, або пакет, що загубив файл, ніколи
не оновлює себе: її вкладка «Нотатки до випуску» каже про це й пропонує лише **Завантажити**.

Для оновлюваної збірки на вкладці додаються:

- **Оновити зараз** (`u`, *Оновлення: оновити зараз*) у фоні завантажує архів і його
  `.sha256` (завдання в індикаторі рядка стану, з відсотками, яке можна скасувати, як
  будь-яке завдання), перевіряє хеш, розпаковує архів і кладе кожен новий файл поруч зі
  старим як `<name>.new`. Нічого запущеного не чіпається. У режимі `auto` те саме відбувається
  саме, щойно перевірка знаходить новіший випуск.
- **Перезапустити й оновити** (`R`, *Оновлення: перезапустити й оновити*; чип говорить те саме,
  коли завантаження підготовлено) - завжди ваша дія, ніколи не автоматична. Вона зупиняє
  окремий демон сесії (вбудований іде разом із вікном), міняє файли й запускає нову версію з
  тими самими аргументами та сесією.
- **Повернути попередню версію** (`v`, *Оновлення: повернути попередню версію*) повертає попередні файли й
  перезапускає. Файли попередньої версії лишаються як `<name>.old`, доки нова версія не
  пропрацює хвилину, потім видаляються, тож кнопка потрібна для цього першого запуску. Вона
  не входить до журналу скасувань git: змінює власні файли GitPoulpi, а не репозиторій.

Як замінюються файли: у Linux і macOS кожен новий файл перейменовується поверх старого
(атомарно; запущена програма тримає стару копію до виходу). У Windows запущений `.exe` не
можна перезаписати, тому старий перейменовується на `<name>.old`, а новий переміщується на
його місце; `.old`, що ще працює, видаляє пізніший запуск. Заміна відбувається повністю або
зовсім ні: якщо інша програма тримає один із виконуваних файлів (наприклад, клієнт MCP, що
запустив `gitpoulpi-mcp`), GitPoulpi називає цей файл, нічого не змінює й лишає завантаження
підготовленим до наступної спроби.

Що відхиляється, кожного разу з повідомленням: випуск без файлу `.sha256`, хеш, що не збігається,
файл архіву, назва якого не відповідає цій платформі (`gitpoulpi-<version>-<target>.<zip|tar.gz>`),
архів, маркер якого називає іншу версію чи платформу, та будь-яке посилання для завантаження поза
цими хостами: `github.com`, `api.github.com`, `objects.githubusercontent.com`,
`release-assets.githubusercontent.com` і `github-releases.githubusercontent.com` (перший запит і
кожен перехід за перенаправленням; перенаправлення деінде зупиняє завантаження). Архіви
приватного репозиторію потребують сеансу браузера, тому завантаження там не вдається, доки
репозиторій не стане публічним.

## Перевірка роботи

```
gitpoulpi --version
cd path/to/a/git/repository
gitpoulpi-tui
```

`--version` виводить версію та commit, з якого зібрано. Далі див.
[Початок роботи](getting-started.md).

## Видалення програми

`gitpoulpi uninstall` (його запускають обидва інсталятори) прибирає псевдоніми команди, записи
PATH і ярлики, створені GitPoulpi, а для встановлення з випуску - ще й файли програми; він
відмовляється працювати зі збіркою без маркера `.gitpoulpi-dist` (збірка cargo), а `--keep-files`
лишає файли програми. Агентам MCP він недоступний. Без інсталятора видаліть три виконувані файли.
GitPoulpi також зберігає такі файли:

| Що | Де |
|---|---|
| Налаштування (`config.toml`) і сеанси | Папка конфігурації вашої ОС. `GITPOULPI_CONFIG_DIR` її змінює. |
| Стан окремих репозиторіїв | `.gitpoulpi/` усередині кожного репозиторію. |
| Кеші (аватари) | Папка кешу вашої ОС. |
| Токени й API-ключі | Ваш credential helper. **Налаштування > SSH і облікові дані > Забути всі імена користувачів і паролі** їх видаляє. |

Точні шляхи див. у [Довіднику конфігурації](config-reference.md).
