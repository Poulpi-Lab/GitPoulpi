# Мультиплексори й панелі

Мультиплексор стоїть між GitPoulpi і вашим терміналом: він сам перемальовує клітинки й
пересилає лише ті escape-послідовності, які розуміє. Тож те, що працює в самому терміналі
([Вибір термінала](terminals.md)), може не працювати всередині tmux, zellij, screen чи herdr.
Ця сторінка каже, що проходить, і яку конфігурацію додати. Результати походять із того самого
тестового проходу листопада 2026 року, що й таблиці терміналів: tmux 3.8 (MSYS2: 3.7c), zellij 0.45.1 і
0.46.0, GNU screen 5.0 (macOS постачає 4.00.03), herdr 0.9.5, psmux 3.4.0.

GitPoulpi виявляє мультиплексор за `TMUX`, `ZELLIJ`, `STY`, `TERM=screen*` чи `tmux*`
та `HERDR_*`. Усередині нього зображення типово замінюються символами, окрім випадків, коли таблиця нижче
каже, що GitPoulpi виявляє робочий шлях. `GITPOULPI_TERMINAL_IMAGE=off` вимикає всі
зображення, а `ui.image_protocol` примусово вибирає протокол.

## tmux

**Зображення.**

- **Sixel** малює сам tmux, перекодовуючи його для клієнта, що це підтримує. GitPoulpi
  питає tmux один раз під час запуску (`tmux display-message -p '#{client_termfeatures}'`,
  з обмеженням 400 мс) і використовує sixel, коли клієнт його вказує. Так є за foot,
  WezTerm, Rio і Tabby; не так за kitty і Ghostty (tmux тоді друкує
  текст «SIXEL IMAGE»). Потрібен tmux, зібраний із sixel (збірки Arch і Homebrew такі;
  перевірте через `tmux -V` і тест sixel). Без налаштування. Власна відповідь tmux на запит
  device attributes заявляє sixel незалежно від того, що за ним, тому GitPoulpi питає
  натомість про можливості клієнта.
- **iTerm2 за tmux** заявляє sixel, але зафарбовує незаданні пікселі непрозоро, тож здебільшого
  прозорий граф став би суцільним прямокутником. GitPoulpi розпізнає iTerm2
  (`LC_TERMINAL`, `ITERM_SESSION_ID`, тип клієнта) і малює символами.
- **Зображення kitty** проходять через DCS passthrough tmux (kitty, Ghostty; також бачили в
  iTerm2 і Rio у «сирій» пробі). Вони потребують `set -g allow-passthrough on` (tmux 3.3a або
  новіший) **і** `ui.image_protocol = "kitty"` у GitPoulpi, який тоді огортає завантаження
  і видалення. Без опції tmux обгортка відкидається, а граф лишається порожнім.
- Вбудовані зображення iTerm2 проходять через tmux, але tmux не може їх розмістити: GitPoulpi ніколи
  не користується ними там.

**Форма вказівника.** GitPoulpi огортає `OSC 22` для passthrough. Він доходить до вікна
в kitty і foot з `allow-passthrough on`. Ghostty не показує його в обгортці (стрілка
лишається). WezTerm, Rio, Alacritty, Tabby, iTerm2 не мають `OSC 22`, щоб його показати.

**Буфер обміну.** `set -g set-clipboard on`. GitPoulpi також надсилає форму в обгортці для passthrough
(вона працює з `allow-passthrough on`). За kitty, Ghostty, Alacritty і Tabby він
доходить; iTerm2 забороняє його, доки не ввімкнено його дозвіл на буфер обміну.

**Клавіші.** tmux не відповідає на запит клавіатури kitty, а `extended-keys` не
проводить `Ctrl+Enter` чи `Ctrl+,`: виміряно з tmux 3.8 усередині kitty, обидві доходять
як звичайні `Enter` і `,` з `extended-keys` off, on чи always. Комбінації з літерами, як-от
`Ctrl+Shift+Z`, доходять лише з `extended-keys` on чи always **і**
`extended-keys-format csi-u` (tmux 3.5 або новіший) **і** застосунком, що просить
розширені клавіші; GitPoulpi ніколи цього не робить, тож налаштування тут нічого не змінює. Користуйтеся
варіантами з `Alt` усередині tmux
([Скорочення клавіатури](keybindings.md#клавіші-яких-термінал-не-може-надіслати-і-протокол-клавіатури-kitty)).

**Конфігурація** (`~/.tmux.conf`):

```
set -g mouse on
set -as terminal-features ',*:RGB'     # truecolor
set -g set-clipboard on                # OSC 52
set -g allow-passthrough on            # tmux 3.3a or later: pointer shapes, forced kitty pictures
```

**tmux у WSL.** Не вимірювалося.

## zellij

Зображення: zellij приймає протокол kitty, але не його Unicode-заповнювачі, і не несе
sixel чи зображень iTerm2, тож GitPoulpi малює символами (свідоме вето). Форма вказівника:
ковтається, тож GitPoulpi її не надсилає. Буфер обміну: `OSC 52` пересилається (працює за
kitty, Ghostty, Alacritty, Tabby; iTerm2 і Terminal.app забороняють чи ігнорують його). Клавіші: zellij
відповідає на запит клавіатури kitty, тож повна клавіатура працює.

zellij 0.46 відкриває спливне вікно «Welcome to Zellij» на свіжому запуску: натисніть `Esc`. Сеанс, що
завершився, зберігає своє ім'я, а наступний запуск із тим самим ім'ям питає, що робити.
Конфігурація не потрібна.

## GNU screen

Нічого не проходить: зображення і `OSC 22` друкуються як символи чи відкидаються, `OSC 52`
ігнорується, а клавіатура застаріла. GitPoulpi малює символами. screen 4.00.03 (версія,
яку постачає macOS) також спотворює кольори й широкі гліфи в інтерфейсі; screen 5 тестували
лише в Linux. Для зручного сеансу користуйтеся tmux чи zellij.

## herdr

herdr вбудовує термінал, що повторно випромінює **зображення kitty**. GitPoulpi використовує їх, коли
`config.toml` herdr каже `kitty_graphics = true` (у `[terminal]`, а в старіших
версіях `[experimental]`), а термінал навколо herdr їх малює (kitty, Ghostty, WezTerm): виявляється,
без налаштування. Якщо конфігурація лежить деінде (наприклад під `HERDR_HOME`, який GitPoulpi
не читає), задайте `ui.image_protocol = "kitty"`. Через SSH (`herdr --remote`) GitPoulpi
не бачить локального клієнта, тож малює символами; див.
[Усунення несправностей](troubleshooting.md#граф-намальовано-символами-а-не-картинкою-herdr-tmux-інші-термінали).
`OSC 22` herdr 0.9.5 не пересилає, тож GitPoulpi його не надсилає. `OSC 52` доходить
за kitty, Ghostty, Alacritty і Tabby. У «сирій» пробі herdr малював зображення kitty в
kitty, Ghostty і iTerm2, також із типовою конфігурацією. Клавіші: не вимірювалося.

## psmux і MSYS2 tmux (Windows)

- **psmux** (Rust, ConPTY, командна мова tmux; `winget install psmux`) задає `TMUX`, тож
  GitPoulpi там малює символами за задумом. Усередині Windows Terminal він працює нормально,
  а копіювання працює через системний буфер обміну; вказівник не змінюється (у Windows
  Terminal немає `OSC 22`). Інші термінали-хости не вимірювалися.
- **tmux з MSYS2 чи Cygwin** також задає `TMUX` (символи за задумом), а в тесті
  екран був спотворений: застарілі кадри, намальовані один на одному, в mintty і в Windows Terminal
  (з `-u` і без; без нього рамки друкувалися як `qqqq`). Нативна програма Windows
  усередині псевдотермінала MSYS2 неправильно перемальовується tmux. Це не
  виправити в GitPoulpi: користуйтеся psmux, панелями Windows Terminal чи панелями WezTerm.
- zellij і screen не мають випуску для Windows. herdr 0.9.5 встановили, але не запускали.

## Панелі терміналів

Панелі, що належать самому терміналу, для GitPoulpi не є мультиплексорами:

- **Панелі WezTerm** (`wezterm cli split-pane`, `wezterm connect`, домени SSH): WezTerm малює
  все, тож зображення працюють (граф і аватари в панелі), а вказівник поводиться як у
  самому WezTerm (форми працюють у збірці з upstream WezTerm PR #8092; роздільник панелей
  дає вказівник зміни розміру). У Linux чи macOS не вимірювалося.
- **Панелі Windows Terminal** (`wt ; split-pane`): граф і аватари sixel працюють у панелі,
  копіювання працює, без форм вказівника.
- **Спліти kitty, Ghostty та iTerm2**: нативні, як термінал. У macOS не вимірювалося для
  kitty і Ghostty (їм потрібен GPU).

## iTerm2 `tmux -CC` (режим керування)

iTerm2 відкриває нативне вікно для кожного вікна tmux і тримає вікно-шлюз «[tmux bash]».
`TMUX` задано, тож GitPoulpi малює символами в нативному вікні. Зображення справді доходять до iTerm2
через з'єднання керування (вікно «Allow Terminal-Initiated Display?» з'явилося
для тесту `OSC 1337`), але GitPoulpi не користується ними там. Корисне навантаження kitty
примусового `ui.image_protocol = "kitty"` друкується у вікні-шлюзі, тож залиште `auto`.
`OSC 22` і `OSC 52` не доходять.

## Налаштування, які варто знати

| Налаштування | Для чого |
|---|---|
| `ui.image_protocol` | `kitty` примусово вмикає зображення kitty через мультиплексор, що їх пересилає (tmux з `allow-passthrough on`, herdr із конфігурацією, якої GitPoulpi не читає); `none` для символів. |
| `ui.graph_renderer` | `text` завжди правильний. |
| `ui.kitty_keyboard` | `off`, якщо мультиплексор хибно поводиться із запитом клавіатури. |

Про термінал за мультиплексором див. [Вибір термінала](terminals.md), а коли граф
малюється символами, - [Усунення несправностей](troubleshooting.md).
