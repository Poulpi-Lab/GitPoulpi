# Відкрити в

Кнопка **Відкрити в ▾** у рядку заголовка, поруч зі шляхом репозиторію, відкриває папку активної вкладки деінде: у вашому терміналі, новій вкладці чи панелі мультиплексора, редакторі, файловому менеджері. Ви самі вибираєте, що є у списку. Нічого не зашито: кожен запис - це назва й команда.

## Користування

- **Клацніть Відкрити в ▾**: випадає список. Клацніть запис, щоб його запустити. Запис за замовчуванням позначено `•`; останній рядок, **Налаштувати...**, відкриває [Налаштування](settings.md#відкрити-в) на сторінці «Відкрити в».

  ![Список «Відкрити в»: термінал, два редактори, інструмент Git і файловий менеджер, запис за замовчуванням позначено крапкою, а наприкінці Налаштувати](../images/open-in-menu.png)

- **Клавіатура**: `Alt+O` відкриває той самий список (`Up`/`Down`, `Enter`, `Esc`; якщо записів більше семи, вводьте текст для пошуку). `Ctrl+Alt+O` одразу запускає запис за замовчуванням. Палітра (`Ctrl+P`): `Вкладка: відкрити в...` і `Вкладка: відкрити в типовому`. Команди палітри працюють, навіть коли в рядку заголовка немає місця для кнопки. Обидві клавіші можна перепризначити; див. [Скорочення клавіатури](keybindings.md).
- **Праве клацання вкладки репозиторію**: меню вкладки має підменю **Відкрити в** з тими самими записами.
- Список починається із запису, яким ви скористалися останнім у цьому сеансі.
- Рядок стану одразу показує «відкриття в {label}...». Якщо програма завершується помилкою протягом приблизно 1,5 секунди (наприклад, tmux без сервера або хибний прапорець), у рядку стану з'являється перший рядок її виводу помилок. Програму, якої не встановлено, рядок стану називає одразу.

Доки ви не збережете власний список, запис за замовчуванням вибирається за виявленим: усередині herdr - «Herdr: new tab»; в Omarchy - нове вікно kitty (kitty є його терміналом); інакше - файловий менеджер.

Кнопка показується на кожній вкладці репозиторію, зокрема в папці, у якій запущено GitPoulpi, і в режимі `ui.tab_dir_follow = "auto"`. У режимі `auto` запис за замовчуванням також запускається сам, коли ви відкриваєте нову вкладку (не для вкладок, відновлених під час запуску). Див. [Стеження за папкою активної вкладки](following-the-tab-folder.md).

## Як виглядає запис

У `config.toml` - одна таблиця `[[ui.open_in]]` на запис:

```toml
[ui]
open_in_default = "Herdr: new tab"   # a label; empty means the first entry

[[ui.open_in]]
label = "Herdr: new tab"
command = "herdr tab create --workspace ${env:HERDR_WORKSPACE_ID} --cwd ${cwd} --focus"

[[ui.open_in]]
label = "VS Code"
command = "code ${cwd}"
```

Вручну це пишуть рідко: список редагує сторінка Налаштувань. Кожен ключ є в [довіднику конфігурації](config-reference.md).

### Команди й змінні

Команду спершу розбивають на аргументи (пробіли, `'...'` і `"..."` групують слова), а потім у кожному аргументі замінюють змінні. Папка з пробілом в імені тому залишається одним аргументом. **Оболонка не залучається**, якщо ваша команда сама її не запускає.

| Змінна | Замінюється на |
|---|---|
| `${cwd}` | Папка вкладки. |
| `${repo}` | Корінь репозиторію (для вкладки worktree відрізняється від `${cwd}`). |
| `${name}` | Назва папки без шляху. |
| `${branch}` | Поточна гілка; порожньо, коли HEAD відокремлено. |
| `${web_url}` | Веб-сторінка remote origin, коли це GitHub чи GitLab; інакше порожньо. |
| `${env:NAME}` | Змінна середовища `NAME`; порожньо, коли не задано. |

Старе `{repo}` досі працює й означає `${cwd}`. Будь-яке інше `${...}` - помилка, що називає змінну.

Програму запускають із папкою вкладки як робочою папкою, і вона отримує три змінні середовища, зручні для фрагмента оболонки:

| Змінна | Значення |
|---|---|
| `GITPOULPI_CWD` | Папка вкладки. |
| `GITPOULPI_REPO` | Корінь репозиторію. |
| `GITPOULPI_BRANCH` | Гілка або порожньо. |

```toml
[[ui.open_in]]
label = "Terminal here, then status"
command = "sh -c 'cd \"$GITPOULPI_CWD\" && git status; exec $SHELL'"
```

У Windows програму шукають через `PATH` і `PATHEXT`, тому `code` і `cursor` (файли `.cmd`) працюють, а вікно консолі не блимає.

## Шаблони

Налаштування > Відкрити в > **Додати шаблон** перелічує готові записи лише для вашої операційної системи (шаблони Windows ніколи не показуються в Linux тощо) за категоріями: рядок починається з категорії, `Провідник: ...`, `Мультиплексор: ...`, `Термінал: ...`, `Редактор: ...`, `Інструмент Git: ...`, `ШІ-агент: ...`, `Веб: ...`. Угорі **Знайдено** - записи обчисленого списку за замовчуванням. У кожній категорії першими йдуть шаблони, які можна використати одразу (ви працюєте всередині цього мультиплексора чи терміналу, а програма є в `PATH`), потім встановлені, потім решта. Вводьте текст у комбінованому списку, щоб шукати, наприклад `lazygit` або `Інструмент Git:`. **Перевірити на поточній вкладці** випробовує запис, перш ніж ви на нього покладетеся.

![Список «+ Додати» на сторінці «Відкрити в»: спершу знайдені записи, потім Провідник, Мультиплексор та інші категорії, кожен шаблон із префіксом своєї категорії](../images/settings-open-in-presets.png)

Шаблони «запуск інструмента в панелі» (`lazygit in Herdr tab`, `yazi in tmux window`, `Claude Code in Herdr split`...) пропонуються лише тоді, коли встановлено хост (herdr, tmux, zellij, WezTerm, kitty, `xdg-terminal-exec`, Windows Terminal) та інструмент. `$EDITOR in ...` запускає редактор, названий вашою змінною `EDITOR` (із запасним `vi` у herdr), у herdr або tmux.

Шаблони інструментів herdr створюють вкладку чи розділ, а потім вводять команду в її оболонці, тож інструмент стартує в папці, а панель залишається відкритою після його завершення. Шаблони `ШІ-агент` використовують `herdr agent start`, тож herdr відстежує стан агента.

| Категорія | Шаблони (`V` = перевірено запуском або за встановленою довідкою) |
|---|---|
| Провідник | Windows `explorer.exe` (V), macOS Finder (V), Linux `xdg-open` (V), Nautilus, Dolphin, Thunar, Nemo, PCManFM; yazi, superfile, nnn, lf, ranger у панелі/вкладці/терміналі |
| Мультиплексор | herdr tab, workspace, split right/down (V); tmux window, split right/down, detached session (V); zellij pane, tab, floating; WezTerm tab, split, new window; kitty tab, split window, OS window (V: прапорці з довідки; потрібен `allow_remote_control`); screen; cmux; psmux |
| Термінал | `xdg-terminal-exec` (V), kitty (V), foot (V), Alacritty (+ `alacritty msg`), WezTerm, Ghostty (Linux, macOS), GNOME Terminal, Ptyxis, Konsole, Xfce Terminal, Tilix, Terminator, MATE Terminal, iTerm2, Terminal.app, Warp; Windows: Windows Terminal (вікно, вкладка, розділ і по вкладці для PowerShell 7, Windows PowerShell, Command Prompt, WSL), вікна PowerShell 7 / Windows PowerShell / Command Prompt / WSL, Git Bash |
| Редактор | VS Code (V), VSCodium, Cursor, Windsurf, Zed, Sublime Text, Emacs, IntelliJ IDEA, RustRover, PyCharm, WebStorm, CLion, GoLand, Rider, PhpStorm, Android Studio, Visual Studio (Windows); Neovim, Vim, Helix, `$EDITOR` у панелі/вкладці/терміналі |
| Інструмент Git | gitk, `git gui`, gitg, Sublime Merge, GitKraken, GitHub Desktop; lazygit, tig, gitui у панелі/вкладці/терміналі (ті, що для herdr, tmux, kitty та `xdg-terminal-exec`, - V) |
| ШІ-агент | Claude Code, Codex, Gemini CLI, opencode у вкладці/розділі herdr (V, із Claude), tmux, zellij, WezTerm, kitty, новий термінал |
| Веб | `Repository page on the web` (`${web_url}`), `gh repo view --web` (V), `glab repo view --web` |

WSL у Windows: `wsl.exe --cd ${cwd}` приймає шлях Windows як є, а вкладка `wsl.exe` у Windows Terminal стартує в папці, яку WSL відображає під `/mnt/`.

Провідник, Windows Terminal, PowerShell, `cmd`, WSL, Warp, psmux, Visual Studio і Zed (Zed лише для Unix) з'являються тільки там, де існують; tmux, zellij, cmux, screen, віддалене керування kitty та шаблони herdr, що працюють через `sh`, лише для Unix; herdr (прості шаблони), WezTerm, Alacritty, VS Code, Cursor та IDE JetBrains пропонуються всюди.

### Змінна `${web_url}`

Веб-сторінка remote `origin` репозиторію, коли це проєкт GitHub чи GitLab (github.com, gitlab.com або власний хост, що має запис у `[[integrations]]`); інакше порожньо, і тоді запис, що її використовує, зупиняється з повідомленням замість відкривання порожньої адреси. Вона необов'язкова: жоден шаблон її не потребує, окрім `Repository page on the web`.

## Сторінка Налаштувань

Налаштування > **Відкрити в** редагує список. Записи - це [список](settings.md#списки)
ліворуч (типовий запис позначено `★`), а поля вибраного запису - праворуч; `+ Додати`,
`Дублювати`, `Видалити`, `↑` / `↓` і перетягування рядка керують списком.

| Рядок | Що він робить |
|---|---|
| **Типовий запис** | Запис, який запускає **Відкрити в типовому**. Він позначений `•` у списку «Відкрити в». |
| **Назва** | Назва, показана у списку. Унікальне, не порожнє. |
| **Команда** | Команда зі змінними-мітками (`${cwd}`, `${repo}`, `${branch}`, `${name}`, `${web_url}`) для вставки. |
| **Перевірити на поточній вкладці** | Запускає запис зараз для папки активної вкладки. |
| **+ Додати ▾** | Додає готовий запис (знайдені першими) або **Власний** - порожній запис, команду якого редагують далі. |
| **Відновити знайдені значення** | Замінює список тим, що знайдено на цьому комп'ютері, і скидає запис за замовчуванням. |

Зміни зберігаються в міру внесення. Перша зміна записує весь масив `[[ui.open_in]]` у `config.toml`; до того список обчислюється (див. [Застарілі ключі](#застарілі-ключі)), а файл не має ключа `open_in`. Пошук у Налаштуваннях також знаходить цю сторінку.

## Двійкові файли: Відкрити в

Двійковий файл (PDF, документ Word, таблиця, архів...) не має тексту, який можна показати в поданні Diff чи в Перегляді файлу. Якщо операційна система знає програму для його типу, поруч зі звичайним повідомленням з'являється кнопка **Відкрити в**. У її списку першою йде програма, якою система відкриває цей тип (позначена крапкою), потім усі інші програми, зареєстровані в системі для нього (власний список системи «Відкрити за допомогою»). У Linux це MIME-тип за назвою файлу, `mimeapps.list` для програми за замовчуванням і файли `.desktop` для решти; у Windows реєстр (вибір користувача та програми, зареєстровані для розширення); у macOS лише програма за замовчуванням.

`o` запускає програму за замовчуванням, а `Shift+O` відкриває список. Обидві дії є в палітрі команд (*Файл: відкрити у програмі за замовчуванням*, *Файл: відкрити за допомогою...*), а **Відкрити за допомогою...** є в контекстному меню файлу на панелі Status та в списку файлів commit'у. Пошук іде у фоні, один раз для кожного розширення: поки він триває, вигляд показує «пошук програм...». Тип, для якого система не знає жодної програми, і простий текст зберігають звичайне повідомлення та не мають кнопки.

![PDF у Перегляді файлу зі списком «Відкрити в»: спершу типова програма, позначена крапкою, далі інші програми, які система зв'язує з цим типом](../images/open-with.png)

Файл робочого дерева передається програмі як є. Версія з commit'у (або з індексу) записується у **тимчасову копію лише для читання**, з повідомленням у рядку стану, щоб програма не могла змінити репозиторій. Жодне з цього не змінює репозиторій: запису в журналі немає, Скасування не зачіпається.

Список меню відкривається поруч із меню, на рівні рядка **Відкрити за допомогою...**, як підменю (ліворуч, коли праворуч немає місця), і з миші, і з клавіатури. Список редакторів зображень (**Редагувати в...**), відкритий із меню файлу, робить те саме.

### Файли Git LFS

Картка об'єкта Git LFS (див. [Git LFS](lfs.md)) має під текстом ті самі дві дії: **Відкрити типовою програмою** і **Відкрити в**, з тими самими клавішами (`o`, `Shift+O`) і рядками палітри. Вони відкривають справжній файл, ніколи не покажчик: файл робочого дерева як є або тимчасову копію лише для читання об'єкта з локального сховища LFS для версії з commit'у чи з індексу. Для ще не завантаженого об'єкта на картці кнопок немає, а рядок стану каже, що вміст ще не завантажено. Та сама відмова діє для файлу робочого дерева, який досі містить лише покажчик: **Відкрити типовою програмою**, **Відкрити в** і **Редагувати в**, з картки чи з будь-якого меню файлу, кажуть, що вміст не завантажено, замість відкривати текст покажчика (завантажте його рядками pull чи checkout панелі LFS, тоді повторіть). Відкриття лише для читання: запису в журналі немає, скасовувати нічого.

### Браузери у Windows

Chrome і Edge реєструють `--single-argument %1`, через що читають усе після перемикача як одну адресу, разом із лапками. GitPoulpi передає такій програмі шлях дослівно й без лапок, як це робить Windows, тож файл із пробілами в шляху відкривається, а не завершується помилкою `http://"c/...`. Будь-яка інша програма отримує шлях як один звичайний аргумент.

## Застарілі ключі

Старі ключі `ui.terminal_launch` і `ui.terminal_launch_command` читаються лише доти, доки `ui.open_in` відсутній. Тоді обчислений список такий:

1. ваш старий вибір терміналу, якщо він не `auto` (`custom` стає «Terminal (custom)» із `{repo}`, переписаним на `${cwd}`; ідентифікатор шаблону стає цим шаблоном). Значення `auto` стає першим записом, «Default terminal».
2. файловий провідник ОС,
3. мультиплексори й термінали, виявлені за середовищем,
4. редактори, знайдені в `PATH`.

Коли ви зберігаєте список із Налаштувань, `ui.open_in` перебирає керування, а старі ключі ігноруються. Команди палітри **Вкладка: відкрити в терміналі** і **Вкладка: відкрити у файловому менеджері** цього списку не використовують.

## Усунення несправностей

- *«{label}: програму X не знайдено (PATH перевірено)»*: програми немає в `PATH`, який бачить GitPoulpi. Запустіть GitPoulpi з оболонки, що її має, або запишіть повний шлях.
- *запис tmux/zellij/herdr одразу завершується помилкою*: вони звертаються до запущеного сервера, тож працюють лише тоді, коли GitPoulpi запущено всередині нього.
- *запис вкладки kitty завершується помилкою*: потрібен `allow_remote_control` у `kitty.conf`.
- *Провідник Windows*: `explorer.exe` завершується з кодом 1 навіть за успіху; GitPoulpi вважає це успіхом.
