# Пошук

`Ctrl+Alt+F` (або `Ctrl+P`, а тоді `Пошук: робочий простір...`) відкриває нечіткий
пошук по **всіх репозиторіях, у яких ви працюєте**: репозиторіях активного
[робочого простору](workspaces.md), якщо він є, інакше - відкритих вкладок. Кнопка **Глобальний пошук** (лупа з підписом у рядку заголовка, одразу ліворуч від
шестірні) теж відкриває його. Він знаходить:

- **репозиторії** (за назвою, потім за шляхом),
- **гілки** (локальні й віддаленого відстеження) та **tag'и**,
- **worktrees** (за папкою, потім за шляхом і гілкою),
- **stash'і** (за повідомленням),
- **commit'и** (за темою; тіло commit'у шукається лише тоді, коли тема не
  збігається, а ви ввели три символи чи більше),
- **запити на злиття** (pull або merge request) та **issues** (за заголовком,
  `#номером`, автором і гілкою).

![Вікно пошуку над двома відкритими репозиторіями: гілки, stash і commit, що збігаються з «main», кожен зі своїм репозиторієм праворуч](../images/workspace-search.png)

Результати згруповано за типом, у кожній групі найкращі збіги першими. Кожен
рядок має піктограму типу, підсвічені символи, що збіглися, приглушену подробицю
(upstream гілки, автор і гілка запиту, позиція stash) та назву репозиторію
праворуч, тож два репозиторії з гілкою `main` ніколи не переплутаються. Коли
репозиторій ще індексує свої commit'и (перший пошук у великому репозиторії може
тривати мить), у заголовку крутиться індикатор; інші типи доступні одразу, а
commit'и з'являються, щойно готові.

## Перехід до результату

| Клавіша | Що робить |
|---|---|
| `Up` / `Down`, `PageUp` / `PageDown`, `Home` / `End` | Рух по результатах (заголовки груп пропускаються). |
| `Enter` | Переходить до результату: вкладка репозиторію відкривається (або на неї перемикається), потім результат показується. |
| `Esc` | Закриває пошук. |
| `Alt+1` .. `Alt+8` | Вмикає чи вимикає тип (чипи над списком, у їхньому порядку). `Alt+0` вмикає всі. |

Що означає «перейти»:

| Результат | Enter |
|---|---|
| Гілка або tag | Вибирає її на панелі Refs, а її commit - у Log. |
| Commit | Вибирає його в Log, перед цим довантажуючи Log, якщо commit старіший за завантажене. |
| Stash | Вибирає його рядок у розділі СХОВАНКИ. |
| Worktree | Відкриває його як вкладку. |
| Запит на злиття, issue | Вибирає його рядок на бічній панелі (у вкладці цього репозиторію). |
| Репозиторій | Перемикає на його вкладку (відкриваючи її, якщо вона не відкрита). |

`Ctrl+N Backspace` (або `Назад` у палітрі) повертає туди, де ви були, як і будь-яку
зміну вигляду, яку робить для вас агент. Перехід кудись нічого не checkout'ить, не
зливає й не змінює.

Мишею: клацання по рядку вибирає його, подвійне клацання переходить, клацання по
чипу вмикає чи вимикає цей тип, коліщатко прокручує, а клацання поза вікном
закриває його.

## Звуження префіксом

Почніть запит із префікса, щоб шукати лише один тип, що б не казали чипи:

| Префікс | Тип |
|---|---|
| `r:` | репозиторії |
| `b:` | гілки |
| `t:` | tag'и |
| `w:` | worktrees |
| `s:` | stash'і |
| `c:` | commit'и |
| `pr:` (або `mr:`, `p:`) | запити на злиття (pull або merge request) |
| `i:` | issues |
| `#` | запити на злиття та issues (`#12` знаходить номер 12) |

`fix: login` - це звичайний запит, а не префікс: рахується лише одна літера (або
`pr:` / `mr:`) із двокрапкою чи початковий `#`.

## Як відбувається збіг

Ті самі три рівні, що й у палітрі команд: ваш текст дослівно, потім дослівно будь-де,
потім його символи по порядку, але нарізно. Кращий збіг - раніший і коротший текст.
Великі й малі літери однакові.

## Запити на злиття та issues

Вони беруться з того, що GitPoulpi уже завантажив для кожного репозиторію (списки
за розділами бічної панелі PULL REQUESTS і ISSUES), і зберігаються в невеликому
файлі кешу в папці `.gitpoulpi/` репозиторію. Пошук **ніколи не звертається до GitHub
чи GitLab**: репозиторій, чиї запити ніколи не завантажувалися у вікні, не має що
знаходити, а побачене настільки свіже, наскільки свіже останнє оновлення бічної
панелі. Без прив'язаного облікового запису знаходити нічого, і налаштовувати
теж нічого.

## З командного рядка

`gitpoulpi search <query> [--workspace ID] [--kind K]... [--limit N]` робить те саме
й виводить JSON (див. [Довідник CLI](cli-reference.md#робочі-простори-та-пошук));
сервер MCP має інструмент `search`, тож агент знаходить те саме, що й ви.
`search.commit_limit` у [Налаштуваннях](config-reference.md#search-пошук-у-робочому-просторі)
обмежує, скільки commit'ів кожного репозиторію індексується (`0` вимикає пошук
commit'ів).

## Зміна клавіші

`Пошук: робочий простір...` - це команда палітри, а клавіша - це дія
`global.workspace_search`: перепризначте її в Налаштування > Клавіатура й миша або
в таблиці `[keybindings.global]` (`workspace_search = "Ctrl+Alt+F"`).
