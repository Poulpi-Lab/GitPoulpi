# Підмодулі

Підмодуль - це інший репозиторій, вкладений у ваш на фіксованому commit'і. GitPoulpi перелічує їх у бічній панелі Refs, оновлює з інтерфейсу, CLI чи палітри команд і може тримати їх у відповідності до commit'у, на якому ви зробили checkout.

## Розділ SUBMODULES

Коли репозиторій має `.gitmodules`, бічна панель Refs отримує розділ **SUBMODULES** (нижче за інші; його немає, коли підмодулів немає). Один рядок на підмодуль: позначка стану, його шлях і короткий commit.

| Позначка | Стан | Значення |
|---|---|---|
| `✓` | актуальний | checkout на commit'і, який записує репозиторій |
| `↑` | змінений | checkout на іншому commit'і (він просунувся далі, або ви перемкнули гілки, не оновивши його) |
| `○` | не клоновано | оголошено в `.gitmodules` і записано, але його папка порожня: оновіть його, щоб клонувати |
| `✗` | у конфлікті | у репозиторії є конфлікти merge на підмодулі |

| Дія | Миша | Клавіатура |
|---|---|---|
| Відкрити підмодуль окремою вкладкою | подвійне клацання по рядку | виберіть його, `Enter` (палітра: `Refs: відкрити підмодуль у вкладці`) |
| Меню: **Оновити (клонувати за потреби)**, **Ініціалізувати**, **Відкрити в новій вкладці** | праве клацання на рядку | виберіть його, клавіша контекстного меню (типово `.`) |
| Оновити вибраний підмодуль (за потреби спершу клонує його) | меню | `Ctrl+P`: `Refs: оновити підмодуль (вибраний)` |
| Зареєструвати його в `.git/config` без клонування | меню | `Ctrl+P`: `Refs: ініціалізувати підмодуль (вибраний)` |
| Оновити кожен підмодуль | | `Ctrl+P`: `Git: оновити всі підмодулі` |
| Перейти до розділу | клацання по його заголовку | `Ctrl+P`: `Навігація: фокус на Refs > Submodules` |

Оновлення може завантажувати з віддаленого репозиторію підмодуля, тож воно
підпорядковується **Налаштування > SSH і облікові дані > Облікові дані HTTPS**,
як і будь-яка інша передача. Для неклонованого підмодуля нічого відкривати як
вкладку; рядок стану каже про це й вказує на «Оновити».

## Тримати підмодулі актуальними

**Налаштування > Синхронізація > Тримати підмодулі актуальними**
(`general.keep_submodules_up_to_date`, типово вимкнено). Коли цей параметр увімкнено,
після успішного **checkout** чи **pull** виконується
`git submodule update --init --recursive`. Це відбувається лише тоді, коли
підмодуль не збігається з тим, що тепер записує репозиторій, тож репозиторій
без підмодулів не гальмується. Якщо це оновлення завершується помилкою, checkout чи
pull усе одно відбулися, і помилка про це повідомляє.

## З командного рядка

```
gitpoulpi submodule list                       # path, state, url (--json: the full list)
gitpoulpi submodule init [<path>...]           # register, do not clone
gitpoulpi submodule update [<path>...] [--init] [--recursive]
```

Без шляхів - це кожен підмодуль. Ті самі три є інструментами MCP
(`submodule_list` - читання; `init` і `update` змінюють репозиторій і підпорядковуються
`allow_mutations` з `[mcp]`).

## Примітки

- Перелічено лише верхній рівень; власні підмодулі підмодуля показуються, коли ви відкриваєте його як вкладку (або використайте `--recursive`, щоб оновити їх).
- Новіший git відмовляється клонувати підмодуль із *локальним шляхом* через транспорт `file`, якщо `protocol.file.allow` цього не дозволяє. Це важливо лише для підмодулів, URL яких - локальна папка; задайте це в глобальній конфігурації git, якщо ви їх використовуєте.
