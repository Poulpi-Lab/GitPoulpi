# 重写历史

重写历史会改动已经存在的 commit：谁写的、什么时候写的、消息、它们包含的文件、它们的签名。GitPoulpi 用一份**方案**（一个范围加一串按顺序执行的规则）来完成，整个过程分三步，而且绝不跳过中间那一步：

1. **预览**在不改动任何内容的情况下计算新的历史：数量、每条规则做了什么、会移动的分支和 tag，以及每个有改动的 commit 一行。
2. **应用**把你的本地分支和 tag 移到新历史上。它是[撤销历史](undo-redo.md)中的一条记录：**撤销**会把每个移动过的引用（以及检出的文件）恢复原状。
3. **推送**（带 lease 的 force push）和**清除**是各自独立、需要你刻意去做的步骤，因为它们无法撤销：见[推送结果](#推送结果)和[清除旧历史](#清除旧历史)。

工作台、命令面板、`gitpoulpi rewrite` 命令和 MCP 工具运行的是同一个引擎，所以在其中一处做出的预览，可以在另一处应用。[从命令行使用](#从命令行使用)列出了各个参数；[用 AI 创建规则](#用-ai-创建规则)根据一段描述填充工作台；[来自 AI 代理的提议](#来自-ai-代理的提议)说明了代理在这里可以做什么、不可以做什么。

**按改动对象划分的规则**

| 分组 | 规则 | 章节 |
|---|---|---|
| 作者 | 替换作者、匿名化作者、应用 .mailmap | [作者和 .mailmap](#作者和-mailmap) |

| 消息 | 在消息中查找替换、删除消息中的行、添加或删除尾部字段、修复消息编码 | [消息](#消息) |

**开始之前**

- 预览不会改动任何内容。应用只改动你的本地引用，从不 push。
- 被重写的 commit 会得到新的 id。所有持有旧历史的人都必须被告知：[推送结果](#推送结果)会替你写好通知。
- 已经 push 的机密就是已泄露。**请先吊销并更换它**，然后再重写、force push 并清除。
- 保持原样的 commit 会保留它们的 id 和签名。

## 工作台

`Ctrl+G Shift+H`（或命令面板中的**重写：历史工作台**）会在 Log 之上打开重写工作台。它没有工具栏按钮：高级操作放在命令面板里（每个 `重写：…` 行都会打开工作台，并已添加好对应的规则）、commit 菜单的**重写历史**子菜单里（*从此 commit 到 HEAD…*；同时选中多个 commit 时还有*选中的 commit…*；以及*打开工作台…*），还有就是这个组合键。

![改写历史工作台：范围栏、两条“替换作者”规则的列表及所选规则的字段，以及说明有多少个提交会改变的预览摘要](../images/history-rewrite.png)

`Ctrl+N` 会在工作台的每个控件（范围、规则、字段、标签页、按钮）上显示徽标；按下徽标的效果与点击该控件相同，`Esc` 会收起徽标（参见[徽标](keybindings.md#徽标)）。

- **范围栏：**哪些引用会移动（当前分支、所有本地分支、选定的分支和 tag、选中的 commit）、*Tags* 复选框；用*从此 commit 到 HEAD…*打开时，还有一个复选框，表示从该 commit 的父 commit 之后开始。
- **规则：**带编号的列表，按顺序依次应用。复选框启用或停用规则，箭头移动规则，叉号删除规则（*恢复已删除的规则*或 `Ctrl+Z` 可以找回）。*添加规则*按分组列出各种规则类型。需要某个你没有安装的程序的规则会显示为灰色，并附上原因。
- **规则设置：**点击文本字段即可编辑；点击有多个取值的字段会打开它的列表；复选框直接切换。

- **预览**（`F5`）会在不改动任何内容的情况下计算新的历史，并显示进度条。标签页：**摘要**（数量、每条规则做了什么、警告）、**Commits**（每个有改动的 commit 一行，由守护进程分页提供；筛选器可列出已更改、已移除或已 push 的）、**分支和 tags**（哪些会移动，以及已经 push 过的受保护分支，每个都有复选框）、**影响**（重写已 push 的历史意味着什么：带 lease 的 force push、协作者、签名），以及**机密**、**身份**和**大小**（见下文）。
- **commit 的文件：**在 Commits 行上按 `Enter`（或双击）会打开内容规则在该 commit 中改动过的文件，旁边是所选文件的 diff。叉号、`Esc` 或点击外部可关闭。机密规则删去的行会被隐藏。
- **应用**（`Ctrl+S` 或 `Ctrl+Enter`）在预览与规则一致之后才可用。没有默认答案的问题每次都会询问：已签名 commit 的签名如何处理，以及如何提取文件夹。结果面板提供**撤销**，会把每个移动过的引用恢复原状。
- **保存 / 加载**可以把方案保存在仓库中（共享）或仅为你自己保存；机密值绝不会被保存。

每个按钮都有对应的按键：列表见设置 > 键盘（上下文*重写*）和指南 `keybindings.md`。

### 作者和 .mailmap

- **替换作者**按姓名和/或邮箱（字面文本或正则表达式）匹配作者或提交者，并设置新的姓名和/或邮箱。*作用于*可选作者、提交者或两者；*同时包括 tag 的作者*会让重新创建的附注 tag 也随之改变。除非本次运行选了*我，现在*，否则原来的提交者保持不变。
- **匿名化作者**把每个身份替换为带编号的占位符（`Contributor 1`、`contributor-1@anonymous.invalid`；两种模式都可以自行修改，用 `{n}` 表示编号）。同一个人在一次运行中总是得到同一个编号；列为*保持原样*的身份不会被改动。

- **“身份”标签页**（命令面板中也有**重写：Merge 身份（.mailmap）…**）用来处理一个人用过多个姓名和邮箱提交的情况，而且**无需重写任何东西**。它列出范围栏上范围内的每个姓名和邮箱，以及各自作为作者和作为提交者写下的 commit 数，并标出仓库的 `.mailmap` 已经映射了哪些（`已映射到 Name <email>`）。勾选属于同一个人的身份（`Space` 或点击；*全选* / *全不选*），然后点击 **Merge 到…**（`m`）：对话框会询问保留其中哪一个（commit 最多的排在最前），并**为每个其他身份向 `.mailmap` 添加一行**（`Name <email> Old Name <old@email>`；已有的行不会重复，文件不存在时会创建）。不会提交任何东西：请自己提交 `.mailmap` 来共享它。Log、blame 和文件历史会立即显示规范姓名（设置 `log.use_mailmap`，默认开启；已存储的 commit 绝不会改变，所以无需 force push）。状态栏会说明写入了什么，并提供**撤销**（`u`），它会恢复之前的 `.mailmap`（和其他操作一样，它是撤销历史中的一条记录）。`r` 重新读取列表。
- **用 `.mailmap` 代替重写。**当作者规则要改动的 commit 已经在远程上时，摘要会显示*.mailmap 无需重写就能修正显示。改用 .mailmap？*，并带有一个**使用 .mailmap** 按钮（摘要上的快捷键是 `m`）。它会打开“身份”标签页，并勾选规则所匹配的身份；规则将要设置的那个身份会被作为要保留的身份提供，即使还没有任何 commit 使用它。
- **`.mailmap` 规则**（*重写：将 .mailmap 应用于历史…*，或 `rewrite preview --mailmap`）确实会重写：作者和提交者（由你选择）会变成工作树的 `.mailmap` 所指定的名字，即 `git log --use-mailmap` 显示的结果。当历史本身必须带有规范姓名时使用它，例如在公开历史之前；它和其他重写一样（预览、应用、force push）。

- **身份规则与尾部字段。**身份规则也可以改动尾部字段中出现的人：勾选**同时映射尾部字段**（`--map-trailers`）。每个值恰好是 `Name <email>`、且与规则的*邮箱为* / *姓名为*匹配的尾部字段，都会被设置为新的姓名和邮箱，无论规则对作者和提交者做了什么。它默认关闭：`Signed-off-by` 记录的是谁签署了它，所以改动它需要你单独决定。

### 日期

四条日期规则作用于作者日期、提交者日期或两者（在规则窗格的*日期*中选择）。

- **平移日期**把每个日期移动一个量（`+2h`、`-1d`、`90m`、`1d 2h`）。每个 commit 原本所用的时区保持不变。
- **更改时区**用另一个 UTC 偏移量写出日期。*保持*决定什么不变：**时刻**（同一个瞬间，钟面读数不同）或**时钟**（同样的本地时间，瞬间会变）。
- **限定在指定时段内**会把落在允许时段之外的每个 commit（例如 `Mon-Fri 18:00-23:30; Sat,Sun 10:00-20:00`）移到最近的允许时间，或只往前、只往后移（*移向*）。*不早于其父级*会保持历史的顺序；*种子*让小幅的随机扰动可以重现：同一段历史用同一个种子，得到的日期相同。
- **提交者日期 = 作者日期**把提交者（姓名、邮箱和日期）设置为作者的，这正是 `git commit --amend` 或 rebase 所抹掉的内容。

日期规则和其他规则一样：预览，在 **Commits** 标签页检查（每行显示旧日期和新日期），然后应用。一个 commit 的 id 取决于它的日期，所以日期规则会改变从第一个被改动的 commit 往后的每一个 commit。

### 消息

- **在消息中查找替换**和**删除消息中的行**接受字面文本或正则表达式（*正则表达式*、*区分大小写*）；替换内容留空即为删除。不是有效 UTF-8 的消息绝不会被它们改动：想编辑它，请先运行**修复消息编码**。
- **尾部字段。***添加或删除尾部字段*（命令面板中的*重写：添加或删除尾部字段…*，或 `--trailer-add`、`--trailer-remove`、`--trailer-map`）编辑消息末尾的 `Key: value` 行，也就是 `git interpret-trailers` 认得的那些（`Signed-off-by`、`Co-authored-by`、`Reviewed-by` 等）。**操作**下拉框可选*添加*（**尾部字段**的键、它的**值**，以及**已存在时**：*添加（相同则跳过）*、*替换已有的*或*保持该 commit 不变*）、*删除*（该键的所有尾部字段，或只删除值包含**值包含**所填内容的那些）或*更改值*（**在值中查找**会替换为**替换为**，例如把 `Signed-off-by` 中的旧邮箱换成新邮箱）。键的匹配不区分大小写。只有尾部字段行会改变，消息的其余部分保持原样；原本没有尾部字段的消息会多出一个空行和单独的一段。Commits 标签页会把每处改动显示为 `+Signed-off-by: ...` / `-Co-authored-by: ...`。消息的最后一段才是它的尾部字段块（标题绝不是），所以正文里形如 `Note: see the ticket` 的行，除非单独位于最后一段并与其他尾部字段在一起，否则不算尾部字段。
- **消息中的 commit id。****更新 commit id**（`--update-message-hashes`，默认关闭；位于会编辑消息的规则窗格末尾）会让消息中写出的 id 跟着重写走：一个 7 位或更多十六进制字符的缩写 id（`This reverts commit 1a2b3c4`、`see 1a2b3c4d5e`），只要恰好对应重写后历史中的一个 commit，就会被替换为该 commit 的新 id，并截成相同长度。对应多个 commit、对应不到任何 commit，或对应的 commit 是之后才由重写创建的，则保持原样；摘要会说明替换了多少个、保留了多少个。
- **修复消息编码**（*重写：修复消息编码…*，或 `--fix-message-encoding [--fix-name-encoding]`）把消息重新编码为 UTF-8，分两种情况：
  - 带 `encoding` 头的 commit（`ISO-8859-1`、`Windows-1252`、`Shift_JIS`，git 和编码表认得的任何一种）会被解码并写成 UTF-8，同时移除该头：文本在任何地方读起来都一样，无需再做转换。该 commit 的作者和提交者姓名用的是同一种编码，会随之解码，所以一个 commit 绝不会只转换了一半。
  - **乱码**（mojibake），即曾被当作 Latin-1 或 Windows-1252 读取的 UTF-8（把 `Réécriture` 显示成 `RÃ©Ã©criture`），**只有在往返转换完全一致时**才会修复：文本必须能编码回有效的 UTF-8 字节，并且把结果按同样方式弄乱后必须等于原文。仅仅是在真实字母旁边含有 `Ã©`，或含有旧字母表之外的字符的消息，通不过这个检查，会保持原样。

  *同时修复姓名*（`--fix-name-encoding`）用同样的办法修复已乱码的作者和提交者姓名。无法判断的情况（未知的编码名、不符合所声明编码的字节、既不是 UTF-8 又没有声明的消息、看上去乱码但无法证明的文本）会**保持原样并计入统计**：摘要会写*n 条消息保持原样：无法判断其编码*，数量在 `counts.encoding_left` 中。Commits 标签页会显示每处修复的旧消息和新消息，以及一行*编码*（`ISO-8859-1` 变为 `UTF-8`）。

### 文件和路径

- **文件内容规则**（*在文件中查找替换*、*从历史中删除文件*、*删除大文件*）：窗格会在你输入时检查每个值，并在字段下方给出原因（无法编译的模式、不合法的路径模式、小于一字节的大小）。大小可带单位（`500 KiB`、`5 MiB`、`1 GiB`）。不含斜杠的路径模式可匹配任意深度。*机密值*在遮蔽的字段中输入，只用于本次运行，绝不会被保存；预览会隐藏曾包含它们的行。*空 commit* 决定被规则改成空的 commit 是移除（默认）还是保留。二进制文件和超过大小上限的文件保持原样，并在摘要中计数。
- **移动路径。***移动或重命名路径*（命令面板中的*重写：移动或重命名路径…*）有三种方式，在**移动**下拉框中选择：
  - *重命名路径*（**从**、**到**；`--move-path FROM=TO`）：在每个有旧路径的 commit 中，同样的文件和文件夹会出现在新路径下；其他一切不变，每个文件都保留自己的 id。如果某个 commit 中新路径已经存在，它绝不会被覆盖：预览会被拒绝，并列出冲突的 commit 和路径（请选一个空闲的名字，或先移走已有的）。只接受精确路径，不支持通配符。
  - *把所有内容移入某个文件夹*（**文件夹**；`--into-subdir DIR`）：每个 commit 中的每条路径都会加上这个前缀。适合合并仓库而不产生重名冲突。
  - *将某个文件夹提取为根目录*（**文件夹**；`--extract DIR`）：该文件夹成为根目录，不涉及它的 commit 会被丢弃（创建它的那个 commit 没有父 commit），不再连接任何东西的合并会被简化，没有该文件夹任何内容的分支和 tag 会被删除。每次都会询问你**如何收尾**：
    - *提取到新的克隆中，并在新标签页打开*（`--extract-mode clone`）：在你选择的文件夹里创建本仓库的一份副本（新仓库会在其中得到一个以被提取文件夹命名的文件夹），在那里重写，并清理到只剩新的历史，以及每个含有该文件夹的本地分支和 tag。本仓库不会被改动。新仓库没有远程（原仓库不是它的 upstream）。
    - *原地提取：重写本仓库的历史*（`--extract-mode in-place`）：通常的重写流程：预览、应用、撤销。没有该文件夹的分支会被删除（撤销可以找回）；检出的分支必须含有它。
    - *作为本仓库的子模块*（`--extract-mode submodule`）：新仓库按克隆的方式创建，然后在当前分支上用**一个新 commit** 把该文件夹替换为指向它的子模块（`.gitmodules` 和链接），文件夹保留为已检出的子模块。本仓库的历史**不会**被重写：它的旧 commit 仍保留该文件夹的文件，所以指向它们的任何东西（tag、其他克隆）都不会失效。`.gitmodules` 中的 URL 是新仓库的本地路径：等它放到某个托管平台上之后，请修改它（`git config -f .gitmodules submodule.<folder>.url`）。文件夹中有已编辑或未跟踪的文件时会拒绝执行。撤销会把原来的普通文件夹放回去。

    摘要会说明预览显示的是新仓库的历史，以及它会放到哪个文件夹。排在提取之后的规则（重命名、删除）作用于提取出来的树；对于克隆或子模块，提取必须是第一条路径规则。路径规则在内容规则之后运行，所以删除用的通配符写的是路径原来的样子。

#### 换行符、可执行位和文件编码

这三条规则位于“添加”菜单的**内容**分组中（也可用命令面板中的*重写：转换换行符…*、*移除可执行位…*和*重写：转换文件编码…*）。三者都接受**文件**（通配符；不含斜杠的模式可匹配任意深度；留空表示每个文件）和**排除文件**。它们只改动通配符点名的文件，作用于范围内的每个 commit。二进制文件（前 8 KiB 中含有 NUL 字节）绝不会被改动：摘要会把它们计入*保持原样*。

- **转换换行符**（`--eol lf|crlf|cr --eol-paths GLOB... [--eol-exclude GLOB...]`）。*转换为*：LF（Linux、macOS）、CRLF（Windows）或 CR（经典 Mac）。匹配的文本文件中的每个换行符都会变成所选的那一种，所以换行符混用的文件也会变得一致；本来就正确的文件保持原版本不动。*遵循 .gitattributes*（默认关闭，`--eol-follow-attributes`）会读取每个 commit 根目录的 `.gitattributes`：标为 `-text` 或 `binary` 的文件会被跳过，标为 `eol=lf` 或 `eol=crlf` 的文件保持该换行符，而不是你选的那一种。
- **移除可执行位**（`--strip-exec GLOB... [--strip-exec-exclude GLOB...]`）。匹配的文件从模式 100755 变为 100644；内容不会改动。至少需要一个文件模式：移除所有可执行位会破坏你的脚本。
- **转换文件编码**（`--reencode TARGET [--from SOURCE] [--encoding-fallback ENC] --encoding-paths GLOB... [--encoding-exclude GLOB...]`）。*转换为*：UTF-8（默认）、UTF-8 带 BOM、UTF-16 LE 或 BE（写入字节顺序标记）、Windows-1252 或 ISO-8859-1。*文件编码为*：默认逐个检测每个文件的编码（字节顺序标记，否则是有效的 UTF-8，否则用*备选编码*，除非你修改，否则是 Windows-1252）；也可以指定一种编码来强制使用，但选错会得到错误的文本（把 UTF-8 当作 Latin-1 读取，每个重音字符都会变成两个）。源编码无法读取的文件，或含有目标编码无法存储的字符（ISO-8859-1 中的欧元符号）的文件，会原样保留并计入摘要。

规则按列表顺序在同一个文件上依次运行：先把文件转换为 UTF-16，再要求处理换行符，就不会改动它（它已经不是纯文本了）。应用在撤销列表中是一条记录，和其他重写一样。

### 查找机密


- **查找机密：**`gitpoulpi rewrite scan-secrets`（以及 MCP 工具 `rewrite_scan_secrets`）会读取一遍历史，列出令牌前缀（GitHub、GitLab、Slack、AWS、Stripe、npm、Google、OpenAI、Anthropic）、私钥、JWT、URL 中的密码，以及看上去随机的 `password = value` 行，每一项都附带文件、首个和最后一个 commit，以及形如 `ghp_****abcd` 的脱敏预览。扫描并不详尽，机密值也绝不会被显示、记录或保存。`--remove-finding ID` 会把一个发现项变成一条规则，从每个 commit 中删除它。已 push 的机密就是已泄露：请先吊销并更换它，然后再重写、force push 并清除。

- **“机密”标签页**在工作台里做同样的事，针对范围栏上的范围：**扫描机密**（`s`）把扫描作为后台任务运行（进度条标注为*正在扫描*，**取消**或 `Esc` 可停止）。每个发现项是一行，包含类型、脱敏预览、文件，以及还有多少其他文件包含它；列表下方是：它首次和最后一次出现的 commit，以及有多少个 commit 和文件版本包含它。标签页会说明有多少二进制文件和过大的文件没有被读取，也会说明扫描并不详尽。所有发现项一开始都是勾选的；**从历史中删除**（`r`）会把勾选的项变成一条按 id（绝不按值）指明它们的规则，你可以像其他规则一样预览并应用。重写或范围改变之后，发现项就过期了：标签页会提示，请重新扫描。工作台从不持有机密值，所以也无法显示它。

### 查找占空间的东西


- **找出占空间的东西：**`gitpoulpi rewrite analyze [--top N]`（以及 MCP 工具 `rewrite_analyze`）是大小分析，类似 `filter-repo --analyze`：最大的文件及其路径、大小、首个和最后一个 commit、是否仍在 HEAD 中，最大的文件夹，已从 HEAD 删除但历史仍保存着的文件，以及合计值。它只读取大小和路径，从不读取文件内容，也不会改动任何内容。

- **“大小”标签页**在工作台里做同样的事（`F7`，或命令面板中的*分析历史大小*，会打开它并立即运行）：**分析大小**（`s`）是一个后台任务（*正在分析*，**取消**或 `Esc` 可停止）。**显示**用来选列表（`v`）：*文件*（最大的不重复文件版本，各自标为*在 HEAD 中*、仍存在的文件的*旧版本*，或*已删除*）、*文件夹*（每个文件夹下曾存储过的全部内容）或*已删除*（已离开 HEAD 但历史仍保留的路径）。**排序**（`o`）可按大小、按路径，或已删除优先。勾选行（`Space`；`Alt+A` / `Alt+U` 全选 / 全不选）：标签页会说明它们占多少空间，并如实写成“最多约”，因为空间只有在重写、清除旧对象并运行 `gc` 之后才会回收。**从历史中删除**（`r`）会把勾选的路径变成路径规则（特殊字符会被转义，已在某条规则中的路径不会重复添加）；**删除所有超过…的文件**（`b`，在文件列表中）会写入一条大小规则，上限刚好略低于勾选的最小文件。像其他规则一样预览并应用它们。列表显示最大的 200 行；CLI 会说明还有多少行，`--top` 可以列出它们。重写或范围改变之后，行就过期了：请重新分析。

### 签名

- **签名：**被重写的 commit 无法保留它的签名（签名针对的是旧的字节），所以当已签名的 commit 被重写时，每次都会询问你：*移除签名*（会先显示数量）、*仅重新签名原本已签名的 commit*，或*重新签名每个被重写的 commit*。没有默认答案。保持原样的 commit 会保留它们的签名。重新签名使用你自己的设置，和创建已签名 commit 时一样：`gpg.format`（`openpgp`、`ssh` 或 `x509`）、`user.signingkey`，以及 `gpg.program` / `gpg.ssh.program` / `gpg.x509.program`。问题的第四项**检查签名**（`4`）会对一段测试数据签名一次并验证：它告诉你一个签名要多久，并按所询问的 commit 数估算整个运行的时间，或者告诉你为什么不能用（缺少密钥、代理已锁定、程序未安装，并附上安装方法）。预览在读取历史之前也会做同样的测试，失败时带着这个原因拒绝，所以有问题的设置绝不会留下签了一半的重写。这些 commit 是在**预览期间**签名的（它们的 id 包含签名），所以需要重新签名的预览会花上签名的时间，摘要会写*重新签名的 commit：n 个，用时 12.5 s*，这时可能会弹出口令输入：请先解锁你的代理（“检查签名”做的正是这件事）。**取消**会在两次签名之间停下，不留下任何东西。只有 commit 签名会被重新创建；已签名的 tag 仍会丢失签名。
- ***移除签名*规则**（“添加”菜单，*签名*分组；命令面板中的*重写：移除签名…*；`--remove-signatures`）会移除范围内每个 commit 的签名，即使没有其他改动也一样，并且不会问任何关于重新签名的问题。命令行里是：`rewrite check-signing` 和 `--signatures strip|resign-signed|resign-all`。

### 撤销重写

**撤销**（结果面板的按钮、Log 中工具栏的*撤销*及 `Ctrl+Z`，或 `gitpoulpi undo`）会借助重写固定下来的旧 commit，把每个移动过的分支、tag 和 note，连同检出的文件一起恢复原状。当某个被重写的分支已经在它的 upstream 上（在本地撤销并不会撤销一次 push），或你有未提交的更改时，它会先询问：这些更改会保留，而如果你改过的某个文件会被旧历史覆盖，撤销就会停下（文件的移动方式与 `reset --keep` 相同）。一旦你[清除](#清除旧历史)了某次重写的旧历史，它就无法再撤销；历史列表会把它标为*已清除*。

## 将文件迁入或迁出 Git LFS

“添加”菜单*LFS*分组中的两条规则会重写历史，让大文件从一开始就存放在 [Git LFS](lfs.md) 中（或离开它）。它们需要 `git-lfs` 程序：没有它时，规则显示为灰色并附上安装提示，预览也会被拒绝。它们是我们自己的引擎，而不是 `git lfs migrate`，所以你能得到和其他规则一样的预览、范围、撤销和 push 保护。

- **将文件迁移到 LFS**（*重写：将文件迁移到 LFS…*，或 `--lfs-import PATTERN` 加 `--lfs-min-size BYTES`）。每个匹配模式（`*.psd`、`assets/**`；不含斜杠的模式可匹配任意深度）、且至少有*仅限不小于*所填大小（留空：每个匹配项）的文件，在每个含有它的 commit 中都会变成 LFS 指针。应用时，它的内容会进入本地 LFS 存储（`.git/lfs/objects`，每份不同的内容只存一次），并且在每个含有指针的重写 commit 里，根目录的 `.gitattributes` 会得到 `<pattern> filter=lfs diff=lfs merge=lfs -text`（没有该文件时会创建，其他行不动，也不会重复）。已经是指针的文件保持不变。摘要会写*3 个文件（12 MiB）将迁移到 LFS。要写入的 LFS 对象：3。*，Commits 标签页会按 commit 列出*将 big.psd 迁移到 LFS*。
- **从 LFS 取回文件**（*重写：从 LFS 取回文件…*，或 `--lfs-export PATTERN`）。匹配的指针会还原为真实文件，这些模式在 `.gitattributes` 中的行会被移除。对象必须在本地 LFS 存储中：如果有缺失，预览会被拒绝，并列出缺失项，同时给出一个**下载 LFS 对象**按钮，从 `origin` 把它们取回来；之后请重新预览。对同样的模式先导入再导出，会得到完全相同的 commit。

应用之后，检出的文件是真实内容（不是指针），**撤销**会把旧历史放回来。结果面板有**发送 LFS 对象**（`l`）：等同于 `LFS: Push All Objects`，这样新历史就能 push，而不会让之后的 push 卡在缺失的对象上（对重写后的分支直接 push，也会通过应用时安装的 pre-push 钩子上传它们）。给协作者的通知会写明他们需要 git-lfs 和 `git lfs pull`。

值得了解：当仓库的 LFS 过滤器缺失时，应用会安装它们（`git lfs install --local`），因为 git 需要它们来比较真实文件和指针。只会写根目录的 `.gitattributes`，绝不会写嵌套的。*小于*最小大小、却匹配某个模式的文件仍是普通文件，但 git 在下次 add 时会想把它变成指针，所以在你提交之前，`git status` 会把它显示为已修改。导入时大文件按流处理，导出时一次只在内存中保留一个文件。


## 推送结果

应用重写从不会 push。曾在远程上的已重写分支和 tag 需要 force push，而这次 push 绝不会盲目强制：每个引用都带着 lease 发送，lease 针对的是预览时远程上的 id（而不是你的跟踪分支现在的值），所以同事在这期间的 push 会让该引用被拒绝，而不是被覆盖；服务器允许时，引用会放进一次要么全成功要么全失败的（`--atomic`）push。在 CLI 中：

```
gitpoulpi rewrite push --dry-run        # asks the remote, sends nothing
gitpoulpi rewrite push --yes            # sends it
gitpoulpi rewrite note                  # what the others must run
gitpoulpi rewrite maps --out ./maps     # commit-map and ref-map
```

已 push 的受保护分支（设置 `rewrite.protected_branches`，默认 `main`、`master`、`develop`、`release/*`）无论在重写时还是在 push 时都不会被动，除非你点名它们（`--include-protected main`）或全部包含。托管平台自己的分支保护仍然决定它是否接受 force push；它的拒绝会按引用显示。

在工作台里，应用之后的结果面板可以完成这一切：

- **把重写后的引用发送到远程仓库**列出重写所移动的、且某个远程上也有的引用，每个都有复选框（`Space`）。受保护分支一开始不勾选，旁边标有*受保护*：可逐个勾选，或用*全选* / *全不选*（`Alt+A` / `Alt+U`）。**Push 重写后的分支**（`p`）发送勾选的引用；结果是每个引用一行（*已推送*、*已是最新*、*已拒绝：预览之后远程仓库有变化*、*已拒绝：受托管平台保护*、*已跳过：受保护分支*、*未推送*）。被拒绝的行带有 **Fetch 并检查**（`f`）：工作台会关闭并获取各远程，于是 Log 会显示别人 push 了什么。不会覆盖任何内容：lease 保护了他们的工作，你需要再次预览，然后才能重试。
- **复制通知**（`c`）把给协作者的通知放进剪贴板，通知用界面语言书写，其中的 git 命令不翻译。
- **打开 commit 对照表**（`m`）会显示 commit 对照表和引用对照表所在的位置；点击路径（或按 `1` / `2`）即可复制。

push 无法撤销：如果你之后 `undo` 这次重写，只有你自己的仓库会改变，撤销在询问之前会这样告诉你。请把通知发给每个持有旧历史的人：它列出每个分支和 tag 的旧顶端和新顶端，以及要执行的命令（`git fetch`，然后 `git reset --hard origin/<branch>` 或 `git rebase --onto`）。两张对照表会随这次运行保留 24 小时；如果 GitLab 的仓库清理或某个脚本需要它们，请把它们复制出来。

## 当主机保护分支时

你的主机可能自行保护某个分支（GitHub 的分支保护和规则集、GitLab 的受保护分支、Azure DevOps 的分支策略、Bitbucket 的分支限制），并拒绝重写所需的 force push。当仓库已**关联**到它的主机（侧边栏的 pull request 区域，见[托管平台集成](hosting-integration.md)）时，工作台会用你自己的令牌向主机询问它保护了哪些分支：

- 这些分支**默认不参与重写**，和 `rewrite.protected_branches` 以及工作流中的受保护分支完全一样：Refs 标签页会逐个列出它们并带有复选框和*全选* / *全不选*按钮，并说明原因：*在 GitHub 上受保护*。
- 如果令牌读不到保护设置（缺少权限范围，或你不是管理员），工作台会提示*主机保护情况未知*，并且不会仅凭主机的说法把任何分支当作受保护。重写绝不会因此被挡住。没有关联的仓库永远不会被询问。

当受保护的分支挡了路（预览因所有分支都受保护而被拒绝，或主机拒绝了 push：*已拒绝：受托管平台保护*），**如何通过**按钮（`Alt+H`）会解释三条出路，并附上你所用平台和仓库的确切设置页面（选中一个链接后用 `c` 复制，或用 `o` 打开）。GitPoulpi 绝不会替你执行其中任何一条：

1. **临时解除保护**：在主机的设置中解除，push，然后恢复。
2. **以新的分支名 push 重写结果**，再把该分支设为默认分支（或重命名），并在没人再用旧分支后将其删除。
3. **最后手段：删除并重建远程仓库**，再把所有内容 push 上去。这会丢失 pull / merge request 及其评审、议题、fork 与旧历史的联系、星标和关注者、CI 设置、机密和变量，以及 webhook 和部署密钥。

在命令行里，同样的内容会以 `protected_by_host` 出现在 `rewrite preview` / `rewrite run` 的 JSON 中（当主机保护了范围内的某个分支时）、被拒绝的 `rewrite push` 中，以及 `rewrite note` 中：`provider`、`branches`、`ways`（各带它的 `steps` 和 `links`）、`recreate_loses`，以及完整的说明文字 `text`。


## 清除旧历史

重写之后，旧 commit 仍在你的仓库里：重写的撤销记录保留着它们（这正是它能撤销的原因），reflog 也一样。如果你重写是为了去掉某个机密，那么这个机密仍然留在 `.git` 文件夹里。清除会永久删除旧历史：

```
gitpoulpi rewrite purge                 # asks: lists what is deleted and lost (exit code 3)
gitpoulpi rewrite purge --yes           # does it
```

它会丢弃这次重写的撤销固定引用，使点名旧 commit 的 reflog 记录过期，运行 `git gc --prune=now`，然后检查每个旧 commit 和文件版本是否真的已经消失。确认对话框会事先说明你将失去什么：这次重写（以及任何撤销也需要旧 commit 的更早操作）**将无法再撤销**；它们仍会留在历史列表中，并标为已清除。清除一旦开始就无法中止，也无法撤销。它不会触及任何远程。

任何仍保留旧历史的东西都会阻止清除，此时不会改动任何内容。列表会点名每一项，并说明该怎么做：不属于这次重写的分支或 tag、基于旧历史的 stash（丢弃它，或保留它并接受旧历史留下）、HEAD 在旧历史上的另一个 worktree，以及仍指向旧历史的远程跟踪分支（先 push 重写后的分支，再 fetch）。你的 stash 列表和其他分支的 reflog 绝不会被碰。

已 push 的机密就是已泄露：**请先吊销并更换它**。清除之后，回答会按远程列出托管平台还需要做的事：GitHub 会在缓存视图和 pull request 引用中继续保留旧 commit（请联系 GitHub Support，或删除并重建仓库），GitLab 有一个接受 `commit-map`（`gitpoulpi rewrite maps --out DIR`）的仓库清理功能，外加例行维护，Azure DevOps 和 Bitbucket 需要提交支持请求或新建仓库，而每个拥有克隆或复刻的人手里仍有旧历史。

### 清除屏幕

在工作台里，重写的结果面板有一个**清除旧历史…**按钮（快捷键 `e`），命令面板里有**重写：清除旧历史…**（它针对最新一次尚未清除的重写，关闭工作台之后也可以使用）。屏幕会列出清除将删除什么、你将失去什么（撤销会随之消失的操作；标有*它的撤销也将失效*的并不是重写，但它们需要旧 commit），然后列出仍保留旧历史的东西，每项一行：

- 远程跟踪分支：**Fetch** 会从各远程更新它们；
- stash：**丢弃**会先询问，因为 stash 是你从未提交过的工作；
- 分支、tag、worktree 或其他引用：**复制名称**，然后到它所在的地方处理（重写或删除该分支，在 worktree 中检出一个重写后的分支）。

每次修复之后都会重新检查，**重新检查**（`r`）可以随时手动运行。只有在没有任何剩余项目时，**清除**（`p`）才可用。它会问最后一个问题，带编号且没有默认答案（`1` 永久清除，`2` 保持一切原样），然后开始运行；屏幕会显示它所处的步骤，并说明它无法中止。结果会告诉你旧历史已从这个克隆中消失，或者还有多少旧对象留在那里。下面是在各个远程上要采取的步骤（链接可以复制）。叉号、`Esc` 和点击外部都能关闭屏幕，清除运行期间除外。

通过 MCP 时，清除工具并不存在，除非你在 `config.toml` 的 `[mcp]` 表中设置 `allow_history_purge = true`。

## 脚本规则

*添加规则 > 脚本*（或命令面板中的**重写：运行脚本…**）会添加一条 Lua 脚本规则，并在工作台之上打开它的编辑器；在规则的*脚本*行上按 `Enter` 可以再次打开。编辑器从一个小模板开始。

- **语言**（规则窗格中的一行）：*Lua（内置）*、*Shell 脚本*、*Python* 或 *Lua（已安装）*。除内置 Lua 之外的任何一种都是[外部脚本](#外部脚本shellpythonlua)：没有沙箱隔离；在设置中已关闭、或缺少解释器的语言，会在列表中显示为灰色，原因写在旁边（选择它会告诉你该怎么做）。对还没写过的脚本更换语言，会同时换掉模板。
- **脚本**是带行号的文本编辑器。你输入的内容立刻就是规则，无需确认。
- 它下面的**检查**行会显示 `OK: rewrite_commit found`，或者列出各个问题及其行号（`script:3: ...`；边栏里的行号是红色）。它在你停止输入片刻之后运行，按住按键时不会运行。
- **参数**对应脚本头部的每一行 `--! param`，每行一个，标签在字段旁边：文本、数字，或表示真/假的复选框。你清空的值会回到头部的默认值；没有默认值的文本参数必须在预览之前填写。
- **文件**（仓库内的路径，起始为 `.gitpoulpi/rewrite/script.lua`），带有**从文件加载…**（替换文本）和**保存到文件…**。
- **在所选内容上测试**会在你于 Log 中选中的 commit 上运行脚本；没有选中时用最新的 20 个；它不会写入任何内容。表格列出每个 commit（短 id）、它会改变的每个字段（`old -> new`），以及脚本的 `log(...)` 输出行。**取消**会停止等待。脚本失败时，会显示出错的 commit 和原因。
- 叉号、点击编辑器外部和 `Esc` 都会关闭它；`Tab` 和 `Shift+Tab` 在编辑器、参数、文件、按钮和结果之间移动；`F5` 测试。

预览会拒绝无法编译的脚本：预览窗格会显示*脚本失败*及其行号（对于某个 commit 上的失败，则是它的短 id 和原因）。在不带脚本功能的构建中，这种类型仍留在“添加”菜单里，显示为灰色。

## 用 AI 编写脚本

开启 AI（[AI 辅助](ai.md)）后，脚本编辑器有一个 `✦ 用 AI 编写…` 按钮，命令面板里有 `✦ 重写：用 AI 编写脚本…`，它会在新建的脚本规则上打开工作台，并打开对话框。在你按下**发送**之前不会发送任何内容：对话框会在你输入时显示将要发出的确切文本。

- **脚本要做什么？** 用你自己的话：*把所有在夜间创建的 commit 移到第二天早上*，*把我的旧邮箱换成新邮箱，只限 2024 年之前*。
- **发送 N 个 commit 的样本**（默认关闭）：勾选后，“在所选内容上测试”会用到的那些 commit（你在 Log 中的选择，否则是最新的 20 个）的作者、日期和标题会一并发送，让模型看到你的数据长什么样。绝不包含文件内容或 commit 正文。取消勾选时，没有任何 commit 数据离开本机。
- **发送的内容**是一个只读窗格，背景略深，对话框打开时默认折叠（此时对话框较短）。点击它的标题、按 `Alt+W`，或用 `Tab` 移到它并按 `Enter` 即可展开：它列出指令（固定的脚本约定，然后是你的 AI 指令）和你的请求，并带有自己的滚动条（可拖动、在窗格上用滚轮，或在它拥有焦点时用方向键、`PageUp`、`PageDown`、`Home` 和 `End`）。接收它们的配置显示在上一行。对话框会随窗格增高，但不超出屏幕。
- **发送**（`Tab` 到它，`Enter`）。模型工作期间对话框会等待，`Esc` 取消请求。如果失败，对话框会保留并写明原因，方便你重试。

答案会经过与手写脚本相同的守护进程检查；编译错误会退回给模型一次。随后脚本会**替换编辑器中的文本**（当编辑器里不是初始模板时，对话框会这样提示），并且编辑器的标题会显示*✦ 由 AI 编写：预览前请先阅读*，直到你修改文本为止。它绝不会被替你测试、预览或应用：请阅读它，按**在所选内容上测试**，然后像其他脚本一样预览。脚本运行在与你自己写的脚本相同的沙箱中（没有文件、没有时钟、没有网络）。

在命令行中：`gitpoulpi ai rewrite-script "<instruction>" [--sample N]` 会以 JSON 输出脚本，以及对它运行 `rewrite script check` 的结果，并且不运行任何东西（仍无法编译时退出码为 2）。使用的是设置 > AI 中的*历史重写脚本*配置。

## 用 AI 创建规则

开启 AI（[AI 辅助](ai.md)）后，工作台在“保存”和“加载”旁边有一个 `✦ 用 AI 创建规则…` 按钮，按键是 `Alt+I`（设置 > 键盘与鼠标中的*用 AI 创建重写规则*，上下文为*重写*），命令面板里有 `✦ 重写：用 AI 创建规则…`。AI 关闭时，或在不含 AI 的构建中，按钮和命令面板中的这一行都不存在。你用自己的话描述历史应如何重写（*把我的旧邮箱 a@b.org 换成 c@d.org*，*从全部历史中移除 secrets.txt*，*把我的日期平移两小时*），模型就会提出规则和设置，并**填入工作台**。在你按下**发送**之前不会发送任何内容：对话框会在你输入时显示将要发出的确切文本。

- **历史应如何重写？** 一个多行字段：`Enter` 换行，`Ctrl+Enter` 或 `Ctrl+S` 发送，`Esc` 和叉号取消。
- **发送范围、分支和 tag 名称以及历史中的作者**（默认关闭）：勾选后，会一并发送范围栏上的范围、分支和 tag 名称，以及 Log 中显示的最新 commit（最多 20 个）里各不相同的作者（姓名和邮箱），让模型能准确写出你的邮箱（命令行的 `ai rewrite-rules --context` 则读取最新的 200 个 commit）。绝不包含文件内容或 commit 消息。取消勾选时，只有你的描述和固定的指令会离开本机。
- **替换当前规则**（仅当工作台中已有规则时显示；默认关闭）：默认情况下，新规则追加在你已有的规则之后；勾选后，新规则会替换它们（答案中给出的范围和设置无论如何都会应用）。
- **发送的内容**是一个只读窗格，背景略深，与上方的字段分开，对话框打开时默认**折叠**（此时对话框较短）。点击它的标题、按 `Alt+W`，或用 `Tab` 移到它并按 `Enter` 即可展开：它列出指令（规则词汇，然后是你的 AI 指令）和你的请求，并带有自己的滚动条（可拖动、在窗格上用滚轮，或在它拥有焦点时用方向键、`PageUp`、`PageDown`、`Home` 和 `End`）。接收它们的配置显示在上一行。对话框会随窗格增高，但不超出屏幕。文字超出描述字段时，该字段会有自己的滚动条。

模型可以使用本页的所有规则类型，但**脚本**除外（代码：*用 AI 编写脚本*会把脚本交给你审阅），*在文件中查找替换*的机密值形式也除外（机密值绝不会交给模型：请使用“机密”标签页）。它可以把范围设为当前分支、所有本地分支和 tag，或已存在的指定分支和 tag，并可设置 *Tags*、*committer*、*空 commit* 和*消息中的缩写 id* 这些选项。工作台无法表达的内容（例如*从三月起*这样的日期限制，或一个 commit 区间）不会被猜测：模型会在备注中说明。签名如何处理从不由模型决定：应用时会询问你。

**AI 只准备规则和设置。** 它从不预览、应用或运行任何东西：答案会像你加载的方案一样复制到工作台中，屏幕上的预览随之过期，预览和应用（以及它们的提问和确认）一如既往由你来做。每条规则都会由编辑器和引擎所用的同一套检查单独解析和检查；未通过的规则会被排除。如果有内容被排除，或者模型给出了备注，规则填入后会显示一个列表（*未采用（有效的规则已保留）*，每项带有位置、名称和原因），`Enter` 或 `Esc` 关闭它。请阅读并编辑这些规则，然后再预览。

在命令行中：`gitpoulpi ai rewrite-rules "<description>" [--context]` 会以 JSON 输出提议（`recipe`，即 `rewrite preview --recipe-json` 读取的内容，以及 `problems`、`notes` 和 `applied: false`），并且不运行任何东西（有内容被排除时退出码为 2）。对应的 MCP 工具是 `ai_rewrite_rules`。使用的是设置 > AI 中的*历史重写规则*配置。

## Lua 脚本

脚本规则会对每个 commit 运行你的函数。它是沙箱中的标准 Lua 5.4：没有文件、没有时钟、没有进程、没有模块、没有 `pcall`；同一份脚本在同一段历史上总是得到相同的结果，而一次调用如果超过 1000 万条指令、64 MiB 内存或 5 秒，就会中止，并给出指明 commit 的错误。

```lua
--! name: Replace an email
--! param old_email: text "Email to replace"
--! param new_email: text "New email"
function rewrite_commit(c, ctx)
  if c.author.email == ctx.params.old_email then
    return { author = { email = ctx.params.new_email } }
  end
end
```

`c` 包含 `id`、`parents`、`tree`、`author` 和 `committer`（`name`、`email`、`time`、`offset_minutes`）、`message` 以及 `signed`。`ctx` 包含 `index`、`total`、`params`、`state`（返回 `state = {...}` 即可把数据带给下一个 commit）以及 `window.before` / `window.after`（设置 `--! window: N`）。只返回有变化的部分：`author`、`committer`、`message`。辅助函数：`regex_replace`、`regex_match`、`stable_hash`、`rand`、`weekday`、`hour`、`log`，以及用于消息的 `trailers(message)`（`{key, value}` 的列表）、`set_trailer(message, key, value)`（替换该键的尾部字段；第四个参数 `"add"` 或 `"skip"` 可改变这一点）、`remove_trailer(message, key)`，还有 `at("2024-03-05 18:30", offset_minutes)`（把某个偏移量下的日期转成 Unix 时间）。

在命令行中：`gitpoulpi rewrite script check my.lua` 编译脚本，`gitpoulpi rewrite script test my.lua --commit HEAD --param old_email=a@b` 显示它会改动什么而不写入任何内容，`gitpoulpi rewrite preview --script my.lua --script-param old_email=a@b` 则规划整个重写。

## 外部脚本（shell、Python、Lua）

与 Lua 脚本相同的约定，但由你机器上的某个程序运行：*Shell 脚本*（bash 或 sh；Windows 上是 PowerShell，或任何 `.ps1`）、*Python* 和 *Lua（已安装）*（你自己的 `lua`，不是内置的那个；它没有 JSON 库，所以模板用模式匹配来读取这一行）。**它们没有沙箱隔离：外部脚本以你的权限运行**，可以读取或修改你能访问的一切。规则的窗格和编辑器的标题都会这样提示。

它们如何通信：GitPoulpi 每次运行只启动一次脚本，并通过标准输入给它发送每行一个的 JSON 请求（一个 commit 的各字段、`params`，以及上一次回答返回的 `state`）；它在标准输出上用一行 JSON 回答，字段与 Lua 脚本返回的相同（`author`、`committer`、`message`、`state`、`log`），或用 `{"error": "text"}` 表示放弃。诊断信息请打印到标准错误：它们会作为该 commit 的 `log` 行出现。头部行在 shell 和 Python 中以 `#!` 开头（`#! name: ...`、`#! param old: text "Old"`；shebang 行仍然是 shebang），在 Lua 中以 `--!` 开头。

```sh
#!/bin/sh
#! name: Uppercase author names
while IFS= read -r line; do
  name=$(printf '%s' "$line" | sed -n 's/.*"author":{[^}]*"name":"\([^"]*\)".*/\1/p' | tr 'a-z' 'A-Z')
  printf '{"author":{"name":"%s"}}\n' "$name"
done
```

**它得到什么。**除 `PATH`、`HOME` / `USERPROFILE`、`SYSTEMROOT`、`TEMP` / `TMP` 和 `LANG` 之外是空环境；一个全新的临时文件夹作为工作目录（里面是它自己的脚本副本）；不会告诉它仓库的路径。**时间限制：**每个回答 `rewrite.script_timeout_ms`（5000），整个遍历 `rewrite.script_total_timeout_s`（3600）。一旦超时、崩溃、输出了不是 JSON 的内容或任务被取消，GitPoulpi 就会终止这个脚本及其启动的一切，重写随即停止，并给出 commit 和原因；没有任何东西被移动。

**有哪些语言。**`config.toml` 中的 `rewrite.external_scripts` 列出它们：默认是 `["shell"]`；`"python"` 和 `"lua"` 需要你自己在 `config.toml` 中添加（`[rewrite]`，`external_scripts = ["shell", "python"]`；列表无法用 `gitpoulpi config set` 设置）。未列出的语言在工作台里显示为灰色，CLI 和 MCP 会拒绝它（`scripts_disabled`）；已列出但找不到解释器的语言，会显示为灰色并附上安装提示（`tool_missing`）。

**信任。**即使某种语言已启用，脚本也只有在你信任了它的确切文本之后才会运行。你在工作台里输入的脚本是你自己的，会立即运行；随共享方案或仓库中的文件而来的脚本则不然：预览和*在所选内容上测试*会停下来问*信任此脚本？*，给出两个带编号的答案，且没有预选项（`1` 信任并继续，`2` 不信任，`Esc` 先放着）。信任会针对这个仓库记住文本的 SHA-256，所以脚本一旦改动就会再次询问，克隆来的仓库也无法自行在你的机器上运行代码。在命令行中，先阅读文件，再 `gitpoulpi rewrite script trust FILE`（或在 `preview`、`run`、`script check` 和 `script test` 上加 `--trust`，它会先信任再继续）。通过 MCP 的代理无法信任任何东西：它只能运行你事先信任过的脚本。

**检查。**编辑器下方的检查行对未被信任的脚本显示*尚未信任*（没有启动任何东西）；对已信任的脚本，GitPoulpi 会用一个虚构的 commit（`"dry_run": true`）启动它一次，并检查回答是否符合约定。`gitpoulpi rewrite script check FILE` 做同样的事，并报告 `trust`、`hash` 和 `interpreter`。

## 从命令行使用

`gitpoulpi rewrite`（以及同名的 MCP 工具）运行同一个引擎，供脚本和代理使用。**方案**是一个 TOML 或 JSON 文件，就是工作台保存的那种（`--recipe FILE`，或用 `-` 表示标准输入），各个参数会在方案自己的规则之后继续添加规则。

```
gitpoulpi rewrite preview --recipe fix.toml --all     # plan, changes nothing
gitpoulpi rewrite apply --run ID --digest D           # run the plan you reviewed
gitpoulpi rewrite run --fix-message-encoding --signatures strip --yes
gitpoulpi undo                                        # puts everything back
```

- 用参数写规则：`--set-name` / `--set-email` 加 `--match-email`（身份）、`--mailmap`、`--shift-dates`、`--replace-message FIND=WITH`、`--trailer-add`、`--trailer-remove`、`--trailer-map`、`--fix-message-encoding`（`--fix-name-encoding`）、`--remove-path`、`--remove-blobs-over`、`--replace-content`、`--eol`（`--eol-paths`）、`--strip-exec`、`--reencode`（`--encoding-paths`）、`--move-path`、`--into-subdir`、`--extract`、`--lfs-import`、`--lfs-export`、`--script`、`--remove-signatures`、`--remove-finding`。范围是当前分支、`--all-local`，或 `--ref R`（可重复），再加上 `--since REV`。
- **没有默认答案的问题**也是参数：改动已签名的 commit 时用 `--signatures strip|resign-signed|resign-all`，提取时用 `--extract-mode`。没有它们时，得到的是拒绝或 `needs_choice`（退出码 3），绝不会替你猜。
- **退出码：**0 完成；1 出错（无法读取的方案、错误的参数）；2 被拒绝并给出原因（`stale`、`signature_choice_needed`、`dirty_paths_touched`、`empty_scope` 等）；3 有问题要回答，或已 push 的引用需要 `--yes`。
- `preview` 会把规划保存在仓库里，所以 `apply` 可以在之后的命令中、守护进程重启后或在另一个前端里执行；与摘要不再一致的规划是 `stale`。

[CLI 参考](cli-reference.md)列出了每个参数，[MCP 和代理](mcp-and-agents.md)说明了代理能得到哪些工具（清除工具除非你开启，否则并不存在；代理也无法信任脚本）。

## 来自 AI 代理的提议

代理可以**建议**一次重写，但绝不会执行。`gitpoulpi ui propose rewrite --recipe FILE|-`（MCP 工具 `ui_propose_rewrite`，在 `[mcp] allow_ui_propose = true` 之前不可用）会在你正在运行的窗口里打开工作台，列表中已经是方案的规则，上方还有一条紫色横幅：*✦ 由 <agent> 提出：一次历史重写（3 条规则）· Ctrl+Enter 接受 · Esc 拒绝*。

- **不会运行任何东西。**没有预览、没有应用、没有 push、没有清除：提议只是填好规则。你阅读它们，想改就改，点**预览**，再用你自己的按键应用。关闭工作台就是拒绝这个提议。
- **代理不能放进去的东西：**脚本（预览时它会运行）、超过 50 条规则、机密值（发送之前会从方案中移除）。这样的提议会被拒绝并给出原因。
- 代理可以在 `ui state` 中读到结果（按提议原样应用规则是 `accepted`，先改过再应用是 `accepted_edited`，关闭则是 `rejected`）。一次只能有一个提议；你有其他对话框打开时，它会被拒绝。


## 工具

历史重写的大部分功能除 Git 之外不需要任何东西：更改作者和提交者、应用 `.mailmap`、匿名化、平移日期或限定时段、重写消息和尾部字段、替换内容、删除路径或大文件以及移动路径，全都在 GitPoulpi 内部运行。

**Lua 脚本是内置的。**解释器已内置在 GitPoulpi 中，所以 Lua 脚本不需要任何工具，也无需任何设置。Shell、Python 和已安装 Lua 的脚本需要各自的解释器（见下表），详见[外部脚本](#外部脚本shellpythonlua)。

有些功能会用到外部程序。GitPoulpi 会检查它是否存在（在 `PATH` 中查找，Windows 上还会通过 `PATHEXT` 以及 Git for Windows 自带的 `usr/bin` 查找，并且它必须在 2 秒内响应 `--version`）；结果会缓存一分钟，点击“重新检查”会再次询问。需要缺失程序的规则会留在列表中并显示为灰色，附上原因和安装方法，而预览会在运行任何内容之前就拒绝。

| 功能 | 工具 | 说明 |
|---|---|---|
| 重新签名 commit | `gpg`（OpenPGP）、`ssh-keygen`（`gpg.format = ssh`）或 `gpgsm`（`gpg.format = x509`） | SSH 和 X.509 签名还需要 `user.signingkey`。`gpg.program`、`gpg.ssh.program` 和 `gpg.x509.program` 均受支持。 |
| LFS 迁移 | `git-lfs` 3.0 或更高版本 | 与 LFS 窗格的检查相同。 |
| Python 脚本 | `python` 3.8 或更高版本（Windows 上是 `py -3`） | 默认关闭：把 `"python"` 添加到 `rewrite.external_scripts`。 |
| Lua（已安装）脚本 | `lua5.4`、`lua54`、`lua` 或 `luajit` | 默认关闭：把 `"lua"` 添加到 `rewrite.external_scripts`。 |
| Shell 脚本 | `bash`、`pwsh`（PowerShell）或 `sh` | 默认开启（`"shell"`）。PowerShell 脚本（`.ps1` 文件、`pwsh` shebang，或 Windows 上的任何 shell 脚本）需要 `pwsh` 或 `powershell`；POSIX 脚本需要 `bash` 或 `sh`（在 Windows 上，Git for Windows 提供它们）。 |

安装提示，先说 Windows：

- Windows：Git for Windows 自带 `gpg`、`ssh-keygen`、`bash`、`sh` 和 Git LFS。否则可用 `winget install GnuPG.GnuPG`、设置 > 可选功能 > OpenSSH 客户端、`winget install GitHub.GitLFS`、`winget install Python.Python.3.12`、`winget install DEVCOM.Lua`、`winget install Microsoft.PowerShell`。
- Linux：发行版的软件包（`gnupg`、`openssh`、`git-lfs`、`python3`、`lua5.4`、`bash`、`powershell`）。
- macOS：`brew install gnupg git-lfs python lua powershell`；`ssh-keygen` 和 `sh` 是系统自带的。
