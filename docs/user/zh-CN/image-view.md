# Diff 视图和文件视图中的图像

属于图像的二进制文件会以图片显示，而不是显示“(no textual changes - binary content...)”提示。Diff 视图显示**修改前**和**修改后**；文件视图按原样显示文件；merge 编辑器显示有冲突图像的各个版本。这里的一切都是只读的：查看图像绝不会更改仓库，因此无需撤销。

可以通过**设置 > 图像 > 预览图像**（`ui.image_view`）将其关闭：这样会恢复为普通的二进制提示。没有 `image-view` 功能的自定义构建完全没有查看器，图像页面只保留编辑器列表（参见[自定义构建](custom-builds.md)）。

## 支持哪些文件

PNG 和 JPEG 始终支持；当构建包含 `image-view` 时还支持 GIF、WebP（取其第一帧）、BMP 和 ICO/CUR。TIFF、AVIF、HEIC、PSD 和 RAW 能被识别但不会被解码：信息卡会给出格式、大小和尺寸。SVG 是文本，保留文本 diff。超过**预览大小上限**（默认 32 MiB）或超过 64 百万像素的图像，会改为显示信息卡。以 Git LFS 存储的文件，在其对象位于本地存储中时会显示；否则卡片会提示先执行 `LFS > Pull`。透明部分绘制在棋盘格上。

## 如何绘制

在支持图像协议的终端上（Kitty 和 Ghostty、WezTerm 和 iTerm2、Rio、mintty，以及 sixel 终端 Windows Terminal、foot 和 Tabby），图片是真正的图像。在其他地方（普通的 Windows 控制台、zellij、GitPoulpi 不认识的终端），则用带颜色的半块字符绘制，垂直分辨率减半，但处处可辨；**无图像协议时**可以设为*仅信息卡*。**日志与图**页面上的**图像协议**可强制指定一种。

## Diff 视图

打开图像文件的 diff（某个 commit 的，或 WIP 的 unstaged 或 staged 部分）。标题会写出两个文件（`PNG 512x512 . 34 KiB -> PNG 640x480 . 41 KiB`），然后是缩放按钮、**适应**、**1:1** 和**编辑方式**。

- 标题右侧的**分栏 | 内联**，或按 `m`：并排显示，或一次显示一张图片。**Tab**，或点击*修改前 | 修改后*，可在内联视图中显示另一张。对于窄到容不下两个窗格的分栏，会以内联方式绘制，而不更改你的设置（`ui.diff_layout`）。
- 分栏的**分隔线**可通过拖动、`Alt+Right` / `Alt+Left`（修改前窗格获得 / 让出空间）来移动，双击或按 `Alt+0` 则回到中间。该比例在本次会话中会被记住。
- 新文件显示一个标注为*新文件*的窗格，已删除的文件则标注为*已删除的文件*；两者都会隐藏切换按钮。在工作更改中选中的未跟踪图像会按新文件预览。
- 修改前一侧是父 commit（commit diff）、`HEAD`（staged）或索引（unstaged）；修改后一侧是该 commit、索引或磁盘上的文件。如果打开 diff 时磁盘上的文件发生变化（你从编辑器保存了它，或某个工具重写了它），图像会在大约半秒内跟随更新。

## 文件视图

通过文件菜单或 diff 栏中的**文件视图**打开图像：一个窗格，显示该修订版本（工作更改则为磁盘上）的文件。

## 缩放与滚动

| | |
|---|---|
| `+` / `-`（或 `=`） | 以窗格中心为基准放大 / 缩小 |
| `0` | **适应**（默认）：显示整张图像，并且在窗口或分隔线调整大小时保持适应 |
| `1` | 实际大小（1:1） |
| 方向键、`h j k l` | 滚动窗格的十分之一；按住 `Shift` 滚动一整个窗格；`PageUp`/`PageDown`、`Home`/`End` |
| 滚轮 | 垂直滚动；`Shift`+滚轮水平滚动；`Ctrl`+滚轮以指针为中心缩放 |
| 拖动 | 抓住图像并移动；两侧的滚动条与别处一样可用 |

调整窗格大小时，已缩放的视图会保持其比例和位于中心的点；适应仍然是适应。在 Diff 视图中，两个窗格共用一个缩放和一个滚动位置（**同步前后缩放与滚动**，默认开启），因此两张图像的同一部分都在视野中；当它们大小不同时，缩放会按各自保持相对关系。从**从此缩放起使用像素化**（默认 2x）开始，图像会以方形像素放大，而不是平滑处理，这适合图标和像素画。

## 编辑方式

标题中的**编辑方式**按钮会列出本机上找到的图像编辑器（GIMP、Krita、Inkscape、Photoshop、Paint.NET、Preview 等，以及系统默认应用）；`o` 运行默认的那个，`Shift+O` 打开列表。它也在文件列表中图像的右键菜单里，以及命令面板中（*图片：编辑方式…*）。列表和默认项在**设置 > 图像**下设置，方式与[打开方式](open-in.md)相同。

编辑磁盘上的文件（工作更改一侧）是直接的：编辑器就地保存，图像随之刷新。任何其他版本（某个 commit 的、索引的、已删除的文件）都会被写入一个**只读的临时副本**，并在状态栏中给出提示，因此编辑器无法更改仓库。

系统为图片类型注册的应用（其“打开方式”列表）排在你的编辑器之后，不会重复列表中已有的程序。其他二进制文件使用同样的列表，见 [打开方式](open-in.md)。

## 在 merge 编辑器中

有冲突的图像会显示它的卡片，**A**、**B** 以及（若有）**基础**图像分别放在框中并排显示，每张都适应其框并且只读（那里不能缩放；这些图像只是帮助你选择）。按钮和按键保持不变：**保留 A**（`a`）、**采用 B**（`b`）、**采用基础版本**（`o`）、**在 merge 工具中打开**（`m`）。预览需要足够宽的窗口（约 70 列）和一些空闲行；更窄时，卡片就是纯文本的那种。参见[解决 merge 冲突](merge-conflicts.md)。

## 按键与设置

按键见[快捷键](keybindings.md#图片视图)；每一个都可以重新绑定，并且可以从面板访问（`Ctrl+P`，输入*图像*）。选项位于[设置](settings.md#图像)的**图像**页面和[配置参考](config-reference.md)中（`ui.image_view*`、`ui.image_editors`）。
