# Radar

Radar 是一个独立的标签页，紧跟在主页之后。它是一个列表，汇总**多个仓库**中正等着你处理的事项：你写的 pull（或 merge）request、请求你评审的那些、指派给你或由你创建的议题，以及你留下了进行中工作的仓库。它就是主页窗口，上面叠加着 Radar 视图，这样下面的任何内容都无法抢走点击或按键。

它需要一个代码托管平台配置（参见[托管平台与议题跟踪器](hosting-integration.md)；单个仓库的列表见 [Pull request 和议题](pull-requests-and-issues.md)，某一行的讨论会作为[对话](conversations.md)打开）以及关联到该配置的仓库，或者一个已开启账户范围列表的配置（参见下面的“范围之外”）。未关联的仓库不会被查询：它会显示一行**关联…**（参见下面的“有话要说的仓库”）。

![覆盖两个仓库的 Radar：一个已固定的请求，然后是等待我评审、我的 pull request、指派给我、议题和进行中的工作](../images/radar.png)

pull 或 merge request 行上的**评审…**（或 `e`）会打开该仓库，并打开该请求的应用内评审（[评审 pull request](review.md)）。

## 打开它

- **`Alt+R`**（可重新绑定：`global.radar`），在任何地方都可用。
- 命令面板：*Radar：打开*。
- **Radar** 标签页，位于标签栏中主页之后。
- 标签页已关闭时，**`+`** 菜单中的 **Radar** 项。

在仓库标签页中这样做会带你到打开了 Radar 的主页窗口；`Esc` 或**返回**会回到仓库列表，`⌂` 的作用相同。

## 关闭标签页，或关闭 Radar

这个标签页和仓库标签页一样可以关闭：点它的 **x**、中键点击、显示它时按 `Ctrl+W`，或用命令面板的 `Radar：关闭标签页`。主页是唯一不能关闭的标签页。关闭的标签页在本次会话中重启后仍保持关闭，直到你再次打开 Radar（`Alt+R`、`Radar：打开`，或 `+` 菜单）；它随后会回到主页之后。关闭它不会改变任何设置。

如果你从来不用它，可以在 **设置 > 常规 > 启用 Radar**（`general.radar_enabled`，参见[配置参考](config-reference.md)）中关闭。关闭后，标签页、它的命令面板命令和 `Alt+R` 都会消失，GitPoulpi 也不再为它获取任何数据。立即生效，无需重启。

## 它覆盖什么：范围

**范围**组合框决定查询哪些仓库：

- 按名称选择的**工作空间**（它的仓库，即使没有打开标签页）；
- **已打开的标签页**：此会话中以标签页打开的仓库。
- **默认克隆文件夹**和**默认浏览文件夹**：在[设置](config-reference.md)（`repos.clone_root`、`repos.browse_root`）中指定的文件夹里找到的每个仓库，无论有没有打开标签页。

它会在你上次在这里选择的范围上打开（保存在 `radar.toml` 中），只要它仍然存在；在你第一次选择之前，或该工作空间已被删除时，则在会话的当前工作空间上打开，否则在已打开的标签页上。这个选择只对当前视图有效：它不会改变窗口的当前工作空间。当两个仓库的文件夹名相同时，标签中会加上父文件夹，以便区分。

### 两种文件夹范围

文件夹范围会在**两层深度**内查找仓库：直接位于其中的文件夹，以及其中那些本身不是仓库的文件夹里面的文件夹（`~/src/work/app`）。隐藏文件夹会被跳过，不会进入仓库内部，最多列出 200 个仓库。查找在后台进行，绝不会占用绘制界面的线程，结果会保留到你刷新为止：刷新按钮、`r`、`F5`（窗口的刷新键，可重新绑定）或 `Radar：刷新` 会重新查找该文件夹（此后新克隆的仓库会因此出现）。

托管平台仍然按仓库逐个选择启用：文件夹里**没有关联**主机的仓库永远不会被询问。它只提供自己的进行中的工作一行，在“仓库”分组中有一行 `未关联`，带 **关联…**（它会打开该仓库的 pull request 区域，由你选择平台和项目），状态栏也会统计它们（`3 个未关联（仅显示进行中的工作）`）。

未设置的文件夹在列表中显示为灰色（`默认浏览文件夹（请在设置中指定）`）；选择它会打开对应的设置行（设置 > 常规），并保持范围不变。只要克隆文件夹各操作系统的默认位置（克隆对话框起始的文件夹）存在，它就算已设置；浏览文件夹没有默认值。范围列表每次打开时都会重新读取设置，所以那里的更改会立即生效。

## 列表

| 分组 | 内容 |
|---|---|
| 已固定 | 你固定的所有内容，不论类型，按固定的先后顺序 |
| 等待我评审 | 请求你评审（且不是你写的）的请求 |
| 我的请求 | 你写的请求；草稿的标签显示 `草稿` |
| 指派给我的 | 指派给你的请求 |
| 提到我的 | 提到你、且不在上面任何分组中的打开请求和议题（既不是指派给你、也不是你创建的议题，只有在提到你时才显示在这里） |
| 其他请求 | 其余打开的请求 |
| 指派给我的议题 | 指派给你的打开议题 |
| 我创建的议题 | 你创建的打开议题 |
| 进行中的工作 | 范围内有未提交更改或未推送 commit 的仓库 |
| 已延后 | 你暂时隐藏的事项；默认折叠，展开后查看 |
| 仓库 | 有话要说的仓库（离线、令牌需续期、未关联） |

“pull request”和“merge request”这两个词会跟随常规的术语设置和所属平台。

每一行显示事项类型（`⇄` 请求、`●` 议题、`✎` 进行中的工作）、仓库标签（使用工作空间的颜色）、编号、标题、作者、时长，以及空间足够时的标签。进行中工作的行显示分支和其中等待处理的内容：`✎` 已更改的文件，`+` 新文件，`↑` 待 push 的 commit，`↓` 待 pull 的 commit。

每个标题中都有数量。组内最近更新的事项排在最前。

当平台响应时间超过片刻，筛选框下方的状态栏会显示一个旋转图标。已缓存的列表（与侧栏使用的是同一个缓存）会立即显示，并在答复到达时被替换。

### 列

仓库标签、`#`（编号和检查标记）、作者和时长是**可调整大小的列**。保持自动时，仓库列与屏幕上最长的名称一样宽（最多 40 格，且至多为窗口的三分之一），因此在普通终端上 `owner/name` 和账户列表中的 `group/sub/project` 不会被截断。标题取用剩下的空间。放不下的名称以省略号结尾（`group/sub...`），并且：

- 把**指针停在**被截断的仓库、标题、作者或标签列表上，工具提示会显示完整文本。选中该行后，筛选框下方的状态栏也会写出完整的项目和标题，因此键盘用户看到的相同。
- **拖动分隔符**（仓库名之后、`#` 之后，或作者、时长之前的那一格）来调整列的大小；**双击**它可让该列重新适应内容。列表有一个**表头行**（仓库、`#`、标题、作者、时长），分隔符遵循 `ui.column_resize`，与 Log 相同：默认的 `line` 下，表头行的分隔符中停着一个暗色 `│`，当指针在分隔符上（在表头或列表的任意一行）、用按键选中该列或正在拖动时，整个列表会画出一条细的强调色线；从线上任意一点拖动都可调整宽度。松开后，这条线会消失，除非指针仍在分隔符上（那样它会随指针消失）：鼠标拖动绝不会让某一列保持被选中。设为 `header` 时没有刻度和线：分隔符之后表头行的第一个单元格会亮起，并且是唯一可以拖动的位置。在支持的终端中，指针在分隔符上会变成调整大小的指针。状态标签宽度固定，时长也是（显示的最宽时长，直到你调整它；被窄列截断的时长会在工具提示中显示完整日期），因此作者在每一行都从同一个单元格开始。
- 或使用按键：**`C`** 选择一列（再按一次，或按 `Tab`，选择下一列），**`]`** 把它加宽两格，**`[`** 把它收窄，**`0`** 让所有列恢复自动，`Esc` 退出。面板中有同样的命令：`Radar：选择列`、`Radar：加宽列`、`Radar：收窄列`、`Radar：重置列宽`。

列宽保存在 `radar.toml`（`[columns]`，`repo`、`number`、`author` 和 `age`，以格为单位），重启后依然有效。它们与 Log 的列使用相同的调整手势。

### 检查与冲突

当平台给出了信息时，请求行在其编号之后带有两个小标记：

| 标记 | 含义 |
|---|---|
| `✓` | head commit 的检查已通过 |
| `✗` | 有检查未通过 |
| `●` | 检查在排队或运行中 |
| `!`（紧随其后） | 该请求与其目标分支冲突 |

把指针停在标记上，提示会用文字说明（“检查未通过”“与 main 冲突”）；选中该行，筛选框下方的状态栏也会说同样的话，所以键盘用户同样能看到。没有标记的请求，是平台没有给出信息的请求（没有配置 CI，或没有查询）。

- **GitLab** 随 merge request 列表一起发送流水线状态和冲突标志：每一行都有标记。
- **GitHub** 不会：列表里两者都没有。GitPoulpi 按请求分别查询（请求本身用于合并状态，head commit 的综合状态及其检查运行：共三次调用），每个仓库最多查询 **15 个打开的请求**，你的请求优先。如果 GitHub 拒绝了其中某次调用（速率限制），其余的在下次刷新之前不会有标记。结果会随托管缓存一起保存。

- **Gitea 和 Forgejo** 与 GitHub 的读取方式相同：列表带有冲突标志（`mergeable`），提交状态按请求分别查询（每个仓库最多 15 个，你的请求优先），议题分组也相同。提及使用服务器的搜索（`mentioned_by`）。

### 提及

**提到我的**和**显示：提到我的**筛选使用平台所知道的提及信息。GitHub 通过它的搜索（`mentions:`）查询，GitLab 通过你的待办列表：只有在那里仍处于**待处理**的提及才算数，所以你标记为已完成的待办会离开该分组。

已关闭和已合并的请求以及已关闭的议题不会列出。

## 视图与筛选

三个组合框和一个文本字段用于缩小列表。每个选项都是下拉列表：点击它，或使用它的按键。

- **视图**（`v`）：全部、请求、议题、WIP（进行中的工作）、已延后。
- **显示**（`f`）：所有人、我的（你写的请求、你创建的议题）、指派给我、请求我评审、提到我的。
- **范围**（`w`）：见上文。
- **筛选文本**（`/` 或 `Ctrl+F`）：对仓库、编号、标题、作者、分支和标签做模糊匹配。`Enter` 把按键交还给列表并保留文本，`Esc` 清除它。

`Ctrl+N` 会在筛选框、每个下拉框、刷新和返回按钮，以及屏幕上的每个分区标题上显示徽标。按下徽标上的字符：筛选框获得键盘，下拉框打开，按钮被执行，标题获得选中状态（随后按 `Enter` 或 `Space` 即可折叠）。`Esc` 取消。参见[徽标](keybindings.md#徽标)。

## 操作

选中一行，使用它的菜单（右键、行尾的 `⋮`、`.` 或 `Menu`）、按键，或命令面板（*Radar：…*）。鼠标操作总有对应的按键和命令面板项。

| 操作 | 按键 | 命令面板 |
|---|---|---|
| 打开仓库（打开或切换到它的标签页） | `Enter` / 双击 | *Radar：打开仓库* |
| 评审…（请求；未克隆的请求会询问怎么做） | `e` | *Radar：评审请求…* |
| 通过托管平台的 API 评审请求（无需克隆） | 问题中的 `a` | *Radar：通过 API 评审* |
| 克隆仓库，然后评审请求 | 问题中的 `c` | *Radar：克隆并评审…* |
| 在浏览器中打开 | `o` | *Radar：在浏览器中打开* |
| 检出分支（请求） | `c` | *Radar：检出分支* |
| 创建 worktree…（请求） | `t` | *Radar：创建 worktree…* |
| 在仓库中显示（它的列表） | `s` | *Radar：在仓库中显示* |
| 开始处理此议题…（议题） | `n` | *Radar：开始处理议题…* |
| 固定到顶部，或取消固定 | `p` / 点击 `★` | *Radar：固定或取消固定* |
| 编辑指派人… / 评审者… / 标签…，设置里程碑…（GitHub、GitLab） | 行菜单 | *Radar：编辑指派人…*、*Radar：编辑评审者…*、*Radar：编辑标签…*、*Radar：设置里程碑…* |
| 延后… | `z` | *Radar：延后…* |
| 取消延后 | `u` | |
| 显示或隐藏未克隆仓库的请求 | `a` | *Radar：显示未克隆的请求* |
| 显示或隐藏账户范围行中的草稿 | `d` | *Radar：显示草稿* |
| 启用某个托管平台的账户范围评审请求 | `T` / 其提示行上的 `Enter` / **启用** | *Radar：启用账户范围的评审请求…* |
| 刷新 | `r`、`F5` | *Radar：刷新* |
| 行菜单 | `.` | *Radar：行菜单…* |
| 返回主页 | `Esc` | *Radar：返回主页* |

需要仓库自己窗口的操作（检出、worktree、显示、开始处理、关联、元数据选择器）会先切换到它的标签页，并在加载完成后在那里执行：

- **检出**使用侧栏自己的检出：分支在本地已知时直接检出，否则把请求的 head 抓取到一个本地分支（例如 fork 的）。
- **创建 worktree…** 会在该请求的分支上打开创建 worktree 对话框。
- **在仓库中显示**会在 PULL REQUESTS 或议题列表中选中该事项。
- **开始处理议题**会打开新建分支提示，其中的名称由该议题生成（`12-fix-the-thing`）。

### 固定与延后

**固定**会让事项保持在顶部。**延后**会把它隐藏 **1 小时**、**4 小时**、**到明天**（第二天早上 08:00，你的本地时间，即使现在还没到 08:00 也一样）或**直到有变化**（平台报告该事项有更新，或者对于进行中工作的行，它的计数发生变化）。两者都保存在你配置文件夹的 `radar.toml` 中，以平台、仓库、类型和编号为键，并由本机上的所有会话共享。

### 有话要说的仓库

有问题的仓库会在列表末尾获得自己的一行，它已缓存的事项仍留在屏幕上：

- **离线，数据来自 5m 前**：无法连接到平台；
- **重新连接**：令牌缺失或被拒绝；该按钮会打开“设置 > 集成”；
- **本轮已暂停**：平台要求放慢速度（或拒绝了令牌），所以 GitPoulpi 在这一轮中没有再为其他仓库查询它；
- **未关联，建议 GitHub**：仓库的远程与某个配置匹配，但托管集成按仓库选择启用，所以在你关联之前不会查询任何内容。**关联…** 会带你到该仓库的 PULL REQUESTS 分区，在那里选择平台和项目。

同时最多查询四个仓库，并且绝不在绘制屏幕的线程上进行。

## 范围之外：账户范围的行

范围涵盖你克隆过的仓库。位于你从未克隆过的仓库中、等着你评审的请求在那里是看不到的。**账户范围的行**会向托管平台本身询问，每个配置一次，
并且不论范围是什么都会加入列表：它们与你有关，而不是与某个文件夹有关。

它们**默认关闭**（托管平台的搜索会消耗 API 配额）。当某个已连接的代码托管平台没有开启任何列表时，列表顶部会显示一行它的提示：

`GitHub：列出等待你评审的请求，包括尚未克隆的仓库中的请求  [启用]`

点击**启用**、在该行上按 `Enter`、按 `T`，或运行 *Radar：启用账户范围的评审请求…*：它会在 `config.toml` 中为该配置写入
`integrations.radar.review_requests = true`，并立即向托管平台查询。其他列表（你的命名空间中所有未关闭的请求、指派给你的议题、草稿、命名空间）用
`gitpoulpi hosting integrations radar` 或在该配置的设置中设置；见[配置参考](config-reference.md)和 [CLI 参考](cli-reference.md)。
GitHub、GitLab、Gitea、Forgejo、Azure DevOps、Bitbucket Data Center 和 Gerrit 会应答；Bitbucket Cloud 没有账户范围的端点，所以它的请求只显示范围内已关联的仓库。

配置的**命名空间**会把它的所有列表限制在某些仓库内（设置 > 集成 > Radar：一个每行一项的文本区域，外加一个**正则表达式**复选框）。一行与仓库的完整路径相等，或是以 `/` 结尾的路径前缀时即匹配：`orbit` 保留 `orbit/products/x`，排除 `orbitx/y` 和 `training/y`。勾选该复选框后，每一行是一个正则表达式，按你输入的原样对完整路径匹配（`^orbit/(products|infra)/`）；无效的行会显示在字段下方且不会保存。留空表示不限制。

行的放置方式：

- 范围已经列出的行（同一托管平台、项目、类型和编号）只出现一次：**以范围中的行为准**。
- 其项目你已在某处克隆过的行（最近的仓库、工作空间、文件夹范围找到的文件夹；按远程 URL 匹配）会带着那个克隆：**Enter**、检出、worktree 等
  与其他行一样打开它。
- 其他任何行都是**未克隆**的：仓库标签变暗并显示项目（`acme/app`），选中它时状态栏显示*未克隆*。**在浏览器中打开**可用，**评审**会询问如何评审它（见下），
  而检出、worktree、在仓库中显示和开始处理都会提示*请先克隆该仓库*。

### 评审请求

范围自己的仓库中的请求上，**评审**（`e`）会打开该仓库的标签页并在其中显示评审。账户范围的行上的请求，做法取决于是否已知有克隆，以及该配置的
**未克隆仓库的请求**设置（设置 > 集成，[配置参考](config-reference.md)中的 `review_mode`）：

| 设置 | 已知有克隆 | 不知有克隆 |
|---|---|---|
| 询问（默认） | 询问：**打开本地克隆**（`l`）或**通过 API 评审**（`a`） | 询问：**克隆，然后评审**（`c`）或**通过 API 评审**（`a`） |
| 克隆 | 打开克隆 | 打开克隆对话框 |
| 通过 API 评审 | 通过 API 评审 | 通过 API 评审 |

这个问题是一个小对话框：按字母选择，**Enter** 选择高亮的行，`Esc`、**取消**、`✕` 和点击外部都会关闭它，**为 GitHub 记住**（`r`）会写入该配置的设置，
这样就不会再问（设置中的该行可改回来）。`Ctrl+N` 会为它的控件显示徽标。

- **通过 API 评审**会在主页窗口、盖在 Radar 之上打开评审，代码取自托管平台（见[无需克隆的评审](review.md#无需克隆的评审)）。
  `Esc` 或 `✕` 会把 Radar 还给你；面板的*评审：…*行可作用于它。
- **克隆，然后评审**会在该行所属的已连接账户上打开克隆对话框（同样的仓库列表，按所有者分组），选中该请求的仓库并填好默认克隆文件夹；改动任意一项，然后克隆，登录方式与该账户的任何克隆相同。如果仓库不在账户的列表中（你不是其成员），列表保持打开，搜索框中是它的名称，并有一条说明；对于无法列出仓库的托管平台，对话框会在**通过 URL 克隆**上打开，并填好地址。克隆完成后，新仓库会关联到托管平台
  （其 PULL REQUESTS 来源；托管平台有议题且未设置时，还有其 ISSUES 来源），其标签页打开，该请求的评审也在其中打开。取消对话框或克隆失败都不会关联任何东西。
- Azure DevOps 和 Bitbucket 的请求没有应用内评审：**评审**会在浏览器中打开该请求的页面，并在状态栏中说明。

面板行 *Radar：通过 API 评审* 和 *Radar：克隆并评审…* 会跳过这个问题。

筛选框旁边有两个复选框（一旦在查询账户范围的列表就会出现），保存在 `radar.toml` 中：

| 复选框 | 按键 | 默认 | 作用 |
|---|---|---|---|
| `[x] 未克隆` | `a` | 开 | 列出没有已知克隆的仓库的行。关闭后，只保留已知克隆的行。 |
| `[ ] 草稿` | `d` | 关 | 列出账户范围行中的草稿请求。范围自己仓库的草稿始终会列出。 |

两者都在 `Ctrl+N` 徽标和命令面板中（*Radar：显示未克隆的请求*、*Radar：显示草稿*）。

某个配置的答复会在 `radar-account.json` 中保留 **5 分钟**：在这段时间内再次打开 Radar，会直接显示这些行而不询问托管平台。**刷新**（`r` 或 `F5`）总是会询问：每个仓库和每个账户范围的列表，不论上次答复有多久。
在同一轮中，不会再次询问曾要求放慢速度或拒绝令牌的托管平台。每个配置每种类型最多保留 300 行，**仓库**下的一行会说明还有多少行，或者某个配置为何无法读取（**重新连接**会打开设置 > 集成）。

## 限制

- 账户范围的行来自 GitHub、GitLab（包括自托管）、Gitea、Forgejo、Azure DevOps、Bitbucket Data Center 和 Gerrit 配置（不含 Bitbucket Cloud）。
  指派给你的议题来自前五种；Bitbucket 和 Gerrit 没有议题。
- 每个仓库的列表使用 GitHub、GitLab（包括自托管）、Gitea、Forgejo、Azure DevOps、Bitbucket 和 Gerrit 配置；检查、冲突和提及只读取前四种。
- GitLab 的提及只来自待处理的待办；GitHub、Gitea 和 Forgejo 的检查每个仓库只查询 15 个请求。
