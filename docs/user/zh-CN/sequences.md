**序列**是一个具名的命令列表，其中的命令依次运行：例如 *Stage all changes*、*AI: Generate commit message*、*Commit*、*Push*，合起来绑在一个 **Backup** 键上。每一步都是[命令面板](keybindings.md)中的一个命令；序列本身就是命令面板里的一行（`序列：<名称>`），可以绑定按键，并在 **设置 > 序列** 或 `config.toml` 中编辑。

## 序列页面

**设置 > 序列** 是一个[列表页面](settings.md#列表)：左边是序列，右边是所选序列的各行。每次更改都会立即应用并写入，命令面板和键位映射无需重启即可跟随。

```
 序列
+- 序列 -------------------+  正在编辑第 1/2 个序列
| 此安装                    |  名称         Backup
| > Backup        Alt+B    |  Id           backup
|   Worktree 与代理         |  描述         Stage everything, ...
| 此仓库                    |  范围         此安装
|   Release                |  快捷键       [ Alt+B ] [ 清除 ]
+--------------------------+  步骤         Stage all > AI: ... > Commit > Push
| [+ 添加 v] [复制] [删除]  |              [ 编辑步骤（4） ] [ 立即运行 ]
| [上移] [下移]             |
+--------------------------+
```

* **+ 添加** 提供 **空序列** 和三个预设：**从预设 ▸ 备份**、**撰写并 push** 和 **Worktree 与代理**。预设只是起点：添加之前什么都不会生效，添加的是一份可以编辑的副本。预设在添加时按界面语言命名。
* **复制**、**删除**（会先询问）、**上移** / **下移** 或拖动，都可以调整列表顺序（`Insert`、`Ctrl+D`、`Delete`、`Alt+Up`、`Alt+Down`）。列表的顺序就是 `config.toml` 中的顺序。
* 有问题的行会标红并说明原因（没有步骤、此版本不认识的步骤、缺少所需选项的 `从不` 暂停）。有问题的序列**可以保存**，未来版本的未知步骤会原样保留，但它在命令面板中的行会保持灰色，直到修好。

### 序列的各行

| 行 | 作用 |
|---|---|
| **名称** | 命令面板显示的内容：`序列：<名称>`。 |
| **Id** | 在 `config.toml`、命令行中使用的短名称，也是快捷键的键名（`a-z`、`0-9`、`_`、`-`）。重命名时，快捷键会在同一次写入中随之移动。 |
| **描述** | 可选，写给你自己。 |
| **范围** | 见下文。 |
| **快捷键** | 显示按键的按钮。`Enter` 或点击会打开与 **键盘与鼠标** 相同的按键捕获：按键时会显示冲突和终端警告，其他操作已在使用的按键同样会被拒绝。**清除** 会移除它。按键保存为 `[keybindings.sequence] <id>`。 |
| **步骤** | 按顺序排列的步骤。**编辑步骤** 会打开它们。 |
| **立即运行** | 在当前窗口中运行该序列。 |

### 范围

每个序列都有一个范围，随序列一起保存：

| 范围 | 保存位置 | 谁能看到 |
|---|---|---|
| **此安装**（默认） | `config.toml` 中的 `[[sequences]]`，以此安装为所有者 | 只有此 GitPoulpi 安装。 |
| **这台电脑上的所有安装** | `config.toml` 中的 `[[sequences]]`，没有所有者 | 共用该文件的每个安装。 |
| **仅此仓库** | 当前仓库中的 `.gitpoulpi/sequences.toml` | 拥有该仓库的人。只有在你信任之后才算数（见下文）。 |

更改范围会移动定义：选择 **仅此仓库** 会把它写入仓库的文件并从 `config.toml` 中移除，反之亦然。仓库范围需要先打开一个仓库。

### 仓库序列与信任

文件 `.gitpoulpi/sequences.toml` 可以被提交，因此可能来自其他人，而序列会在你的电脑上运行命令。因此，仓库的序列**在你信任之前不会提供**，就像已提交的工作流文件中的命令一样。

当仓库中有尚无人信任的这类文件时，Log 上方会出现一条通知：*此仓库定义了 2 个序列*，带有 **查看**、**信任** 和 **忽略**。它从不阻塞任何操作。

- **查看** 以只读方式列出每个序列的每一步、它的暂停和选项。那里的 **信任** 会信任所列出的内容；**关闭**（或 `Esc`）不信任任何内容。如果列表比窗口长，那里不提供“信任”（请将窗口调大）：你绝不会信任自己没能读完的内容。
- **信任**（按钮，或命令面板的 *序列：信任此仓库的序列*）会按现在的样子信任该文件。
- **忽略** 会隐藏通知，直到该文件发生更改。
- 用键盘操作：命令面板有 *序列：查看 / 信任 / 忽略此仓库的序列*。

记录下来的是 id、命令、暂停和选项的摘要，保存在仓库的本地状态中（绝不保存在仓库里）。如果其中任何一项发生变化，例如在 pull 之后，通知会以 *此仓库的序列已更改* 的形式回来，这些序列会退出命令面板和按键，直到你再次信任。重命名序列或编辑描述不会改变任何东西。如果文件在你编辑之前已被信任（或为空），你在设置中自己写的序列会保持受信任。

一旦受信任，仓库序列就会像你自己的序列一样以 `序列：<名称>` 出现在命令面板中，并且可以在设置中为其指定快捷键。与你自己的某个序列 id 相同属于冲突：你的优先，另一个会被报告为重复。

在命令行中：`gitpoulpi sequence list` 会显示该文件的序列，带有 `trusted` 和 `repo_trust` 状态（`untrusted`、`changed`、`trusted`）；`gitpoulpi sequence trust`（以及 `untrust`，用 `--repo PATH` 指定另一个仓库）由人在读过 `sequence show` 之后运行。`sequence run` 会拒绝未受信任的仓库序列。AI 代理无法信任：没有对应的 MCP 工具。

## 步骤

**编辑步骤** 会把列表换成该序列的步骤（标题为 **<名称> 的步骤**），并把各行换成所选步骤的行。**返回**（行上方的叉号）或 `Esc` 回到序列列表。

* **+ 添加** 打开 **添加步骤**：序列可以运行的每个命令，使用其命令面板名称（AI 命令带星号标记），输入时用命令面板的匹配方式筛选。此版本无法运行的步骤会置灰并说明原因。`Enter` 或点击会把它添加到末尾；`Esc` 或叉号关闭弹出窗口。
* **复制**、**删除**、**上移** / **下移** 和拖动的用法与序列相同。
* 具有破坏性的命令（删除分支、丢弃更改等）从不提供：序列无法运行这类命令。

### 暂停

每个步骤都有一个 **暂停**：

| 暂停 | 含义 |
|---|---|
| **默认** | 该步骤只在需要回答时才停下，使用它通常的对话框（分支名称、仍为空的 commit 消息等）。 |
| **总是** | 在此步骤之前停下并询问是否继续。 |
| **从不** | 从不停下。步骤的选项必须提供它所需的一切，所以需要名称的步骤必须填好它的 **名称** 选项。 |

运行前总会询问的步骤（强制 push）不提供 **从不**：该行会说明原因。AI 消息步骤上的 **从不** 可以作为明确的选择。

### 选项

**暂停** 下面的各行是步骤的选项：**名称** 或 **消息** 文本、**分支**、像 **在新标签页中打开** 这样的复选框，或根据你的配置填充的下拉框（**远程**、**AI 配置**、**“打开方式”条目**）。文本可使用变量 `${branch}`、`${date}`、`${time}` 和 `${n}`（使名称唯一的数字）。清空文本会移除该选项。

## 用 AI 创建和编辑

[开启 AI](ai.md#序列草稿)（设置 > AI）后会出现两个入口：**添加 > 用 AI 创建…**（也是命令面板的 `序列：用 AI 创建…` 行，它会打开设置的此页面并弹出对话框），以及所选序列在 **立即运行** 旁的 **用 AI 编辑…**。AI 关闭时两者都不存在。

```
+- 用 AI 创建序列 ------------------------------------------- x -+
| 描述你想要的序列                                                |
| +-----------------------------------------------------------+ |
| | stage everything, write the commit message with the AI,   | |
| | commit, then push                                         | |
| +-----------------------------------------------------------+ |
| Enter 换行。Ctrl+Enter 发送。Esc 关闭。                         |
| [ ] 发送上下文（远程名称、AI 配置、“打开方式”标签）               |
|    关闭：只发送你的描述。                                       |
| AI 只提出建议。在你接受之前不会保存任何内容...                   |
| [ 发送 ] [ 取消 ]                                              |
+---------------------------------------------------------------+
```

你用自己的话写出想要的内容；**发送**（或 `Ctrl+Enter`、`Ctrl+S`）会通过与其他所有 AI 操作相同的配置、任务指示器和 `Esc`（以及同样的“发送了什么”问题）去询问模型。回答是一个**建议**，在任何事情发生之前由你阅读：

* 名称、id、描述，以及带暂停和选项的各个步骤；
* 对 **用 AI 编辑**，会给出与当前序列的差异：`+` 表示新增的步骤，`-` 表示删除的步骤，`~` 表示暂停或选项已更改的步骤，字段则显示为 `~ 名称："a" -> "b"`；
* **已舍弃**：模型提出的、不被允许的步骤（未知、具有破坏性、序列中套序列、不可能的暂停），并附原因；有效的步骤会保留；
* 模型的 **备注**，以及只供显示的 **建议快捷键**，并说明该键是否已被占用。它绝不会被绑定：之后请用 **快捷键** 按钮。

```
+- 建议的更改 ---------------------------------------------- x -+
| + 新增   - 删除   ~ 更改                                       |
| ~ 名称："Daily" -> "Daily 2"                                   |
| 步骤（3）                                                       |
| + 1. Git: Fetch All Remotes                                   |
|   2. Git: Stage All Changes                                   |
| - Git: Commit...                                              |
| ~ 3. Git: Push：默认值 -> 暂停：总是                             |
| 已舍弃                                                         |
| 第 4 步 `reset_hard`：不允许具有破坏性的步骤                     |
| [ 接受 ] [ 保存前编辑 ] [ 拒绝 ] [ 返回 ]                       |
+---------------------------------------------------------------+
```

* **接受** 会用一次保存写入它（新序列，或替换被编辑的那个，后者保留其 id、范围和按键），并在列表中选中它。
* **保存前编辑** 做同样的事，并打开它的步骤，以便你调整各行（此页面会立即保存每次编辑，所以序列其实已经保存了）。
* **拒绝** 不写入任何内容。**返回** 回到描述，以便重新发送。
* 没有可接受的内容时，**接受** 不可用：没有可用的步骤、页面会标出的问题，或没有任何改动的编辑。

在 **接受** 之前不会写入任何内容，也绝不会从这里运行序列。在输入了描述或打开了建议时，关闭对话框（叉号、`Esc`、点击外部）会询问“放弃更改？”；关闭设置时也会询问。

## config.toml

```toml
[[sequences]]
id = "backup"
name = "Backup"
scope = "installation"
owner = "<this installation's id>"

[[sequences.steps]]
run = "stage_all"

[[sequences.steps]]
run = "ai_generate_commit_message"
pause = "always"

[[sequences.steps]]
run = "commit"

[[sequences.steps]]
run = "push"

[keybindings.sequence]
backup = "Alt+B"
```

此版本不认识的键和步骤，在页面保存时会保留。

## 运行序列

序列是一个具名的步骤列表，每一步都是命令面板中的一个命令（stage 全部更改、用 AI 写 commit 消息、commit、push 等）。可以从命令面板运行（`序列：<名称>`），用你在 设置 > 键盘与鼠标 中给它的按键（`tui.toml` 中的 `[keybindings.sequence]`），或从命令行运行（`gitpoulpi sequence run`）。

运行时，Log 顶部会出现一条条带，显示 `<名称> k/n`、当前步骤以及它在等待什么。该运行也会在任务面板中显示为 `序列 <名称> k/n：<步骤>`。同一时间只运行一个序列；启动第二个时会告诉你哪一个正在运行。

**它在哪里停下来询问。** 每个步骤都有一个 `pause` 设置（`default`、`always`、`never`）：

| 步骤 | 默认 | `pause = "never"` |
|---|---|---|
| AI commit 消息 | 消息落入消息字段；条带显示“检查消息，然后继续” | 立即继续 |
| Commit | 空消息总会停下：键盘交给该字段，你的 commit（或继续）才会继续 | 没有可 commit 的消息时不可用 |
| AI 撰写 commits | 打开评审；应用会继续，关闭则取消 | 按原样应用建议 |
| 创建 worktree | 对话框打开，名称已填好 | 直接用 `options.name` 创建，不弹对话框 |
| Push | 当 `git.push_behavior = ask` 时，会打开“Push 到…”选择器 | push 到 `options.remote` |
| 带租约的强制 push、stage 看起来像密钥的文件 | 总是询问 | 不允许 |

任何步骤上的 `pause = "always"` 都会在它运行前显示“下一步：<步骤>”，并带有 **继续** 和 **取消**。如果 push 因分支已分叉而被拒绝，会打开常规对话框，条带显示“Push 被拒绝：请在对话框中选择”；先 pull 再 push（或带租约的强制 push）会继续该运行，关闭对话框则取消它。

**继续** 是条带的按钮、命令面板的 `序列：继续`，或绑定到 `sequence.continue` 的按键。**取消** 是条带的关闭叉号、`序列：取消`（`sequence.cancel`）、任务面板，或在没有其他东西需要 `Esc` 时按 `Esc`（已打开的对话框会先关闭，这也会取消）。取消会保留已运行的步骤并说明：“<名称> 在第 k/n 步（<步骤>）之后已取消；之前的步骤会保留”。

**某一步失败时**，运行会在那里停止：状态栏会写出序列、步骤和错误，条带变红，带有 **详情**（活动日志条目，其中列出该步骤的选项）和一个关闭叉号，之前的步骤保持已完成。

**Worktree。** 带有 `open_tab = true` 的创建 worktree 步骤会把运行移到新 worktree 的标签页：后续步骤（`tab_dir_terminal`、`tab_open_agent_here`、`tab_open_in`）会在那里执行。如果屏幕上是另一个标签页，条带会显示“正在等待标签页 <名称>”，并带有 **前往**。关闭该标签页会取消运行。运行不会在退出 GitPoulpi 后继续。

### 代理提议运行

开启 *允许 AI 代理提出更改供我确认*（`[mcp] allow_ui_propose`）后，代理可以请你的窗口运行一个序列（`gitpoulpi ui sequence run <id>`，MCP `ui_sequence_run`）。会出现一条横幅：*✦ <代理> 提议：运行序列 <名称>*，带有 **运行** 和 **忽略**。在你按下“运行”（点击它，或按 `Ctrl+N` 再按 `Enter`）之前不会运行任何内容；“忽略”、`Esc`（在没有其他东西需要它时）或命令面板的 *Agent: Dismiss Pending View* 会丢弃它。之后的运行与你自己启动完全一样，在序列指定处暂停。如果序列不存在、无效，或是你尚未信任的仓库序列，该提议会被拒绝。

## 撤销一次运行

每个更改仓库的步骤（stage、commit、tag、分支、stash、worktree 等）都会留下它**自己的普通撤销条目**，并标有该运行，所以 `Ctrl+Z` 仍然一次撤销一步，[撤销历史](undo-redo.md#撤销历史)会在这些条目上显示 `⟳ <名称>`。要撤回整个运行，有 **撤销整个序列**：撤销历史的按钮（`x`）、命令面板的 `编辑：撤销整个序列` 行，或 `gitpoulpi undo --sequence`。它会由新到旧撤销该运行的条目，每个都带有自己的检查和询问（已经 push 的 commit 会先询问），在第一次被拒绝时停下并指出是哪一步，较旧的条目留在日志中。AI 消息和 push 不留下条目：push 绝不会被撤销。只处理当前仓库的日志；在 worktree 中完成的步骤要从那个仓库撤销。重做仍按条目进行。详情：[序列运行](undo-redo.md#序列运行)。
